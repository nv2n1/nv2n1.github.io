<h2>NAME</h2>
<p> ncwa &#8211; netCDF Weighted Averager</p>
<h2>SYNTAX</h2>
<p> ncwa [-3] [-4] [-6] [-7] [-A] [-a <i>dim</i>[,&#8230;]] [-B <i>mask_cond]</i> [-b] [&#8211;bfr <i>sz</i>]<i>[-C]</i>[-c]<i>[&#8211;cnk_byt</i> <i>sz</i>]<i>[&#8211;cnk_dmn</i> <i>nm,sz</i>] [&#8211;cnk_map <i>map</i>] [&#8211;cnk_plc <i>plc</i>] [&#8211;cnk_scl <i>sz</i>]<i>[-D</i> <i>dbg_lvl</i>] [-d <i>dim</i>,[ <i>min</i>][,[ <i>max</i>]]] [&#8211;dbl|flt] [-F] [-G <i>gpe_dsc</i>] [-g <i>grp</i>[,&#8230;]] [-h] [&#8211;hdf] [&#8211;hdr_pad <i>sz</i>] [-I] [-L <i>dfl_lvl</i>]<i>[-l</i> <i>path</i>] [-M <i>val</i>] [-m <i>mask</i>] [-N] [&#8211;no_cll_mth] [&#8211;no_tmp_fl] [-O] [-o <i>output-file</i>] [-p <i>path</i>] [-R] [-r] [&#8211;ram_all] [-T <i>mask_comp</i>] [-t <i>thr_nbr</i>] [&#8211;unn] [-v <i>var</i>[,&#8230;]] [-w <i>weight</i>] [-x] [-y <i>op_typ</i>] <i>input-file</i> <i>output-file</i></p>
<h2>DESCRIPTION</h2>
<p> <code>ncwa</code> averages variables in a single file over arbitrary dimensions, with options to specify weights, masks, and normalization. The default behavior of <code>ncwa</code> is to arithmetically average every numerical variable over all dimensions and produce a scalar result. To average variables over only a subset of their dimensions, specify these dimensions in a comma-separated list following <code>-a</code>, e.g., <code>-a time,lat,lon</code>. As with all arithmetic operators, the operation may be restricted to an arbitrary hypserslab by employing the <code>-d</code> option <code>ncwa</code> also handles values matching the variable&#8217;s <code>_FillValue</code> attribute correctly. Moreover, <code>ncwa</code> understands how to manipulate user-specified weights, masks, and normalization options. With these options, <code>ncwa</code> can compute sophisticated averages (and integrals) from the command line. </p>
<p> <i>mask</i> and <i>weight</i>, if specified, are broadcast to conform to the variables being averaged. The rank of variables is reduced by the number of dimensions which they are averaged over. Thus arrays which are one dimensional in the <i>input-file</i> and are averaged by <code>ncwa</code> appear in the <i>output-file</i> as scalars. This allows the user to infer which dimensions may have been averaged. Note that that it is impossible for <code>ncwa</code> to make make a <i>weight</i> or <i>mask</i> of rank <i>W</i> conform to a <i>var</i> of rank <i>V</i> if <i>W &gt; V</i>. This situation often arises when coordinate variables (which, by definition, are one dimensional) are weighted and averaged. <code>ncwa</code> assumes you know this is impossible and so <code>ncwa</code> does not attempt to broadcast <i>weight</i> or <i>mask</i> to conform to <i>var</i> in this case, nor does <code>ncwa</code> print a warning message telling you this, because it is so common. Specifying <i>dbg &gt; 2</i> does cause <code>ncwa</code> to emit warnings in these situations, however. </p>
<p> Non-coordinate variables are always masked and weighted if specified. Coordinate variables, however, may be treated specially. By default, an averaged coordinate variable, e.g., <code>latitude</code>, appears in <i>output-file</i> averaged the same way as any other variable containing an averaged dimension. In other words, by default <code>ncwa</code> weights and masks coordinate variables like all other variables. This design decision was intended to be helpful but for some applications it may be preferable not to weight or mask coordinate variables just like all other variables. Consider the following arguments to <code>ncwa</code>: &#8220;-a latitude -w lat_wgt -d latitude,0.,90.&#8221; where <code>lat_wgt</code> is a weight in the <code>latitude</code> dimension. Since, by default <code>ncwa</code> weights coordinate variables, the value of <code>latitude</code> in the <i>output-file</i> depends on the weights in <i>lat_wgt</i> and is not likely to be 45.&#8212;the midpoint latitude of the hyperslab. Option <code>-I</code> overrides this default behavior and causes <code>ncwa</code> not to weight or mask coordinate variables. In the above case, this causes the value of <code>latitude</code> in the <i>output-file</i> to be 45.&#8212;which is a somewhat appealing result. Thus, <code>-I</code> specifies simple arithmetic averages for the coordinate variables. In the case of latitude, <code>-I</code> specifies that you prefer to archive the central latitude of the hyperslab over which variables were averaged rather than the area weighted centroid of the hyperslab. Note that the default behavior of ( <code>-I</code>) changed on 1998/12/01&#8212;before this date the default was not to weight or mask coordinate variables. The mathematical definition of operations involving rank reduction is given above. </p>
