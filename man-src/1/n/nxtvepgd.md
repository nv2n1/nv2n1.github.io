<h2>NAME</h2>
<p> nxtvepg &#8211; Receiving, Browsing and Analyzing Nextview EPG data</p>
<h2>SYNOPSIS</h2>
<p> <code>nxtvepg</code> [&nbsp;<wbr>options&nbsp;<wbr>] [&nbsp;<wbr>database&nbsp;<wbr>] </p>
<p> <code>nxtvepgd</code> [&nbsp;<wbr>daemon options&nbsp;<wbr>] [&nbsp;<wbr>database&nbsp;<wbr>]</p>
<h2>DESCRIPTION</h2>
<p> <code>nxtvepg</code> is an X11 and Win32 application to receive, analyze and browse <font SIZE="-1">TV</font> programme schedules transmitted on top of Teletext as defined by the European Telecommunications Standards Institute (<font SIZE="-1">ETSI</font>) in <font SIZE="-1">ETS</font> 300 707: &#8220;Protocol for a <font SIZE="-1">TV</font> Guide using electronic data transmission&#8221;. </p>
<p> <code>nxtvepgd</code> is a stripped-down version of nxtvepg which only performs data acquisition as a background daemon process. </p>
<p> The Nextview <font SIZE="-1">EPG</font> standard was developed for use in <font SIZE="-1">TV</font> sets, but the data can be received and used in a <font SIZE="-1">PC</font>, too &#8211; provided you have a Teletext capable <font SIZE="-1">TV</font> tuner card and are lucky enough to have a content provider in your country. </p>
<p> <code>nxtvepg</code> enables you to obtain free <font SIZE="-1">TV</font> programme listings for all of the major networks in Germany, Austria, France, Belgium and Switzerland. Currently Nextview <font SIZE="-1">EPG</font> is transmitted by the following <font SIZE="-1">TV</font> networks (note that each of these EPGs cover not only the provider&#8217;s programme but also that of many other networks):</p>
<dl>
<dt>*</p>
<dd> In Germany and Austria: Kabel1 (coverage: apx. 32 networks)</p>
<dt>*</p>
<dd> In Switzerland: <font SIZE="-1">SF1</font>, <font SIZE="-1">TSR1</font>, <font SIZE="-1">TSI1</font>, <font SIZE="-1">TV5</font> (coverage: apx. 37 networks)</p>
<dt>*</p>
<dd> In France: Canal+, M6, <font SIZE="-1">TV5</font> (coverage: 8 networks)</p>
<dt>*</p>
<dd> In Belgium: M6, <font SIZE="-1">TV5</font> (coverage: 32 networks)</p>
<dt>*</p>
<dd> In Turkey: <font SIZE="-1">TRT</font> family (coverage: apx. 17 networks)</dl>
<p> For up-to-date information check the nxtvepg homepage in the Internet (see the About popup in the Help menu). If you don&#8217;t receive any of the channels listed above, you can only use the demo mode as described with the <code>-demo</code> command line option. </p>
<p> Since version 2.8.0 nxtvepg also allows to extract <font SIZE="-1">EPG</font> data from teletext or import from external <font SIZE="-1">XMLTV</font> sources. Note when importing data you need to take care to respect copyright, same as when exporting data. In particular, the German law does not permit &#8220;Web scraping&#8221;, i.e. extraction of programme information from Internet sources without prior permission of the content provider.</p>
<h2>OPTIONS</h2>
<p> Summary of command line options:</p>
<dl>
<dt><code>-display</code> <i>display</i></p>
<dd> <font SIZE="-1">UNIX</font> only: The display on which the user interface will be placed, for example <code>localhost:0.0</code>. Default: taken from environment variable <i></i><font SIZE="-1"><i>DISPLAY</i></font><i></i>. For more info see the <i>X</i> manual page section <code>Display Names</code></p>
<dt><code>-tvdisplay</code> <i>display</i></p>
<dd> <font SIZE="-1">UNIX</font> only: The display on which the <font SIZE="-1">TV</font> application window is searched, e.g. on a remote host or different screen on a station with multiple monitors. Default: same as the main window&#8217;s display.</p>
<dt><code>-geometry</code> <i>geometry</i></p>
<dd> Specifies the position of the main window, e.g. <code>-geometry -0+0</code> to put the main window in the upper right corner of the visible screen. The size of the window cannot be changed.</p>
<dt><code>-iconic</code></p>
<dd> Start with the main window iconified (i.e. minimized). </p>
<p> For M$ Windows users this option may be esp. helpful when nxtvepg is started from inside the <i>Auto start</i> group and <i>Hide on minimize</i> is enabled: nxtvepg then will start almost invisibly in the background, only with an icon in the system tray of the task bar (see also &#8220;<font SIZE="-1">CONFIGURATION:</font> Show/Hide&#8221;).</p>
<dt><code>-rcfile</code> <i>path</i></p>
<dd> Specify an alternate configuration file. Default: on <font SIZE="-1">UNIX</font> <tt>$HOME</tt>/.nxtvepgrc, on Windows nxtvepg.ini in the current directory.</p>
<dt><code>-dbdir</code> <i>directory</i></p>
<dd> Specify an alternate directory for the databases. Default: On <font SIZE="-1">UNIX</font> <i>/usr/tmp/nxtvdb</i>, on Windows the current directory. Note that the database management is not equipped for concurrent writing, so if you have more than one <font SIZE="-1">TV</font> tuner card in your system or network, relocate the directory into the users&#8217; homes. </p>
<p> If you&#8217;re using an acquisition daemon, the browser must be configured to use the same directory as the daemon. If the daemon is running on a different host, you need to mount the remote directory, e.g. via <font SIZE="-1">NFS</font>.</p>
<dt><code>-card</code> <i>index</i></p>
<dd> Specify which <font SIZE="-1">TV</font> card hardware to use, if you have more than card. Default: index 0. On Linux the given index is appended to the device names, i.e. <i>/dev/vbi</i> and <i>/dev/video</i> (see also &#8220;<font SIZE="-1">FILES</font>&#8221;). On Windows index &#8220;n&#8221; means the n-th card found while scanning the <font SIZE="-1">PCI</font> bus for cards with a supported capture chip (e.g. Brooktree Bt878, Bt878A, Bt848, Bt849, Philips <font SIZE="-1">SAA7134</font>, Conexant 23881). If you have more than one <font SIZE="-1">TV</font> card with the same chip, the order between those is undefined, but still constant (i.e. the order is determined by the driver, not nxtvepg)</p>
<dt><code>-dvbpid</code> <i>number</i></p>
<dd> <font SIZE="-1">UNIX</font> only. Also only available when nxtvepg was configured at compile time (i.e. in the Makefile) to use the <i></i><font SIZE="-1"><i>ZVBI</i></font><i> library</i> (&lt;<a rel="nofollow" href="http://zapping.sourceforge.net/ZVBI/index.html">http://zapping.sourceforge.net/ZVBI/index.html</a>&gt;) for acquisition. </p>
<p> This option enables data acquisition from a <font SIZE="-1">DVB</font> device. The channel must be tuned with an external application. The <font SIZE="-1">PID</font> is the identifier of the data stream which contains Nextview <font SIZE="-1">EPG</font> data. The <font SIZE="-1">PID</font> also must be determined by external means. <font SIZE="-1">DVB</font> support is still <code>experimental</code> and not officially supported. In particular, the <font SIZE="-1">EPG</font> scan and acquisition modes which would require channel changing are not supported.</p>
<dt><code>-provider</code> <i></i><font SIZE="-1"><i>CNI</i></font><i></i></p>
<dd> Select a provider by its hexadecimal <font SIZE="-1">CNI</font> (Country and Network Identifier), e.g. <i>-provider d92</i> for <code>Kabel1</code>. You can find out the provider&#8217;s <font SIZE="-1">CNI</font> during a provider scan or from the database file names. Use keyword <i>merged</i> to dump a merged database (or use code <i></i><font SIZE="-1"><i>FF</i></font><i></i> as required by earlier versions of nxtvepg.) Note before you can use a merged database you have to configure it, see &#8220;<font SIZE="-1">MERGED</font> <font SIZE="-1">DATABASES</font>&#8221;. Default if this option is omitted: the last provider selected during the previous session.</p>
<dt><code>-noacq</code></p>
<dd> Start with acquisition disabled. The acquisition can still be started later from the Control menu (see &#8220;<font SIZE="-1">CONTROL:</font> Enable acquisition&#8221;).</p>
<dt><code>-daemon</code></p>
<dd> Start without graphical user interface and silently perform acquisition &#8220;in the background.&#8221; This option is implied when running <i>nxtvepgd</i>. (The daemon-only executable is slightly more efficient since it&#8217;s smaller and uses less libraries than the <font SIZE="-1">GUI</font> executable and hence needs less memory.) </p>
<p> If no other options are given the same provider and acquisition mode as configured with the <font SIZE="-1">GUI</font> will be used. If the -provider option is given acquisition will work for this provider only (note the difference to non-daemon mode, where that option selects the browser database). The -daemon option cannot be combined with the -noacq or -demo options. </p>
<p> The daemon always creates a named socket in the <i>/tmp</i> directory (<font SIZE="-1">UNIX</font> only) plus optionally a <font SIZE="-1">TCP/IP</font> socket to allow connects by browser processes. While connected, the browser receives updates for opened Nextview databases and reports about the acquisition progress; if left unconnected, the browser listing might be incomplete or outdated. </p>
<p> It&#8217;s important to note that the browser <code>must use</code> the same <i>-dbdir</i> directory, because the daemon forwards only deltas to the database files stored in that directory. For more details see &#8220;<font SIZE="-1">CONFIGURATION:</font> Client/Server&#8221;. </p>
<p> <font SIZE="-1">UNIX</font> warning: for security reasons it&#8217;s depreciated to run the daemon with root privileges, because nxtvepg has not been reviewed yet for possible exploits. If you want to start the daemon already during system startup, you should use <i><a href="/docs/linux/man/1-su/">su</a></i>(1). Also note that you&#8217;ll probably need to specify -rcfile because the <tt>$HOME</tt> environment variable might not be (correctly) defined. Example: </p>
<pre>
   su nobody -c &quot;/usr/local/bin/nxtvepg -daemon \
                 -rcfile /usr/local/etc/nxtvepgrc&quot;
</pre>
<p> For terminating the daemon process, see the -daemonstop option below. Alternatively you can stop the daemon via the graphical user interface by disabling <i>enable acquisition</i> in the control menu.</p>
<dt><code>-daemonstop</code></p>
<dd> With this option, a background acquisition process is searched and terminated if found; then the program exits. Note you need permission to send signals to the daemon process to be able to stop it (i.e. it must run with the same user <font SIZE="-1">ID</font>). This option is meant to allow controlling acquisition by scripts which start and stop acquisition automatically after a given time. </p>
<p> Note if the daemon is running on the same host and uid, it can also be stopped by deselecting <i>Enable acquisition</i> in the <i>Control</i> menu while being connected to the daemon. For more details see &#8220;<font SIZE="-1">CONTROL</font>&#8221; and &#8220;<font SIZE="-1">FILES</font>&#8221;.</p>
<dt><code>-nodetach</code></p>
<dd> <font SIZE="-1">UNIX</font> only: In daemon mode this option prevents the process actually making itself a daemon, i.e. it doesn&#8217;t fork and stays connected to the terminal. Also all log messages starting with level <i>warning</i> are sent to standard error out (e.g. configuration errors that lead to an immediate exit). This mode is intended for debugging purposes only.</p>
<dt><code>-acqpassive</code></p>
<dd> In daemon mode this option overrides the acquisition mode setting in the configuration file and forces acquisition into passive mode (see &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221;). The configuration file is not changed, so that you can use different acquisition strategies for daemon and <font SIZE="-1">GUI</font>.</p>
<dt><code>-acqonce</code> <i>phase</i></p>
<dd> In daemon mode this option will automatically stop acquisition and terminate the daemon after the given phase has been completed for all providers. Phases are the same as defined in &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221;, i.e. <i>now</i>, <i>near</i> and <i>full</i>. Note it&#8217;s not useful to use this option in acquisition mode <i>follow-ui</i> because acquisition restarts after each provider change. This option is only useful with a fixed list of providers. </p>
<p> If you want to run another program from inside a script after nxtvepg has finished, use the <i>-nodetach</i> option (<font SIZE="-1">UNIX</font> only) Then the shell which is processing the script will usually wait for nxtvepg to terminate before starting the next command. On Windows there&#8217;s no simple way to achieve this (because non-console applications are always run in the background), so you need to use a script language which supports instructions which wait until a running program (namely nxtvepg) has finished.</p>
<dt><code>-dump</code> <i>mode</i></p>
<dd> When started with this argument, nxtvepg will only export the entire programme database, then exit. This argument must be combined with <i>-provider</i> to specify which database shall be exported. </p>
<p> To export the database in <font SIZE="-1">XML</font> format, use keyword <i>xml</i> as mode. In this case the last mode (i.e. <font SIZE="-1">XMLTV</font> <font SIZE="-1">DTD</font> version) which was used via the main menu is used. To export the database in another mode, use <i>xml5</i>, <i>xml5ltz</i> or <i>xml6</i>. For more details see &#8220;<font SIZE="-1">CONTROL:</font> Export as <font SIZE="-1">XMLTV</font>&#8221;. </p>
<p> To export programme data into a <font SIZE="-1">HTML</font> document, use keyword <i>html</i> as mode. The same options as configured in the <font SIZE="-1">HTML</font> export dialog are applied (unless you are using the daemon executable <i>nxtvepgd</i> to perform the export.) For details see &#8220;<font SIZE="-1">CONTROL:</font> Export as <font SIZE="-1">HTML</font>&#8221;. The number of exported programmes can be limited by adding a number after the keyword, separated by a colon (e.g. <tt>&quot;-dump html:50&quot;</tt>.) However the format of the programme list is currently not configurable via command line options. </p>
<p> To export the database into a plain text file (e.g. for import into an <font SIZE="-1">SQL</font> database) three mode keywords are supported: <i>pi</i> to dump programmes (i.e. the complete <font SIZE="-1">TV</font> schedules), <i>ai</i> to dump the provider&#8217;s network table, <i>pdc</i> to dump the <font SIZE="-1">PDC</font> theme categories table. For more details see &#8220;<font SIZE="-1">CONTROL:</font> Export as text&#8221;. </p>
<p> For debugging purposes there&#8217;s also a mode <i>raw</i> which prints all data in the database in a format which is closely related to the internal data structures. This output should not be used for data export. For more details see &#8220;<font SIZE="-1">CONTROL:</font> Dump raw database&#8221;. </p>
<p> The output is written to <i>stdout</i> unless you redirect it into a file or pipe it into another program. See also option <i>-outfile</i></p>
<dt><code>-outfile</code> <i>path</i></p>
<dd> This option allows to redirect output from <i>-dump</i> or any other modes which print to <i>stdout</i> by default. It also works in normal operation modes, but the created file will be empty. nxtvepg will abort if the specified file already exists to avoid inadvertantly overwriting other files. If you&#8217;re using the option inside a script or batch file you should add a command to remove the target file before invoking nxtvepg. </p>
<p> This option is especially helpful for M$ Windows users, since output written to <i>stdout</i> is discarded by the operating system because nxtvepg is not a &#8220;console application&#8221;. This means for exmaple, if output of the above -dump mode is not to be discarded, you must either use this option or redirect output as explained below. </p>
<p> Note: instead of using this option you can also redirect output with the &#8220;&gt;&#8221; or &#8220;|&#8221; operators in <font SIZE="-1">UNIX</font> shells or under M$ Windows at the MS-DOS command prompt. For example you could use either of the following: </p>
<pre>
  nxtvepg -dump ai -prov d92 &gt; networks.txt
  nxtvepg -dump ai -prov d92 | more
</pre>
<p> to write the network table of provider <i>Kabel1</i> (<font SIZE="-1">CNI</font> <i>0xd92</i>) into a file named <i>networks.txt</i>, or pipe it to the paging program &#8220;more&#8221; respectively.</p>
<dt><code>-remctrl</code> <i>command</i></p>
<dd> This option can be used to remote control an other, previously started <font SIZE="-1">GUI</font> instance of nxtvepg, i.e. to send the given command to the other process and then exit. </p>
<p> The following commands are available: <i>quit</i> to terminate the other nxtvepg process; <i>iconify</i> to minimize the window; <i>deiconify</i> to undo a previous minimization; <i>raise</i> to deiconify the other window and to bring it to the top (in case it&#8217;s obscured by other windows); <i>acqon</i> to start acquisition; <i>acqoff</i> to stop acquisition.</p>
<dt><code>-clock</code> <i>mode</i></p>
<dd> When started with this argument, nxtvepg will acquire the current date and time from teletext and then terminate. To specify from which channel to acquire date and time use the <i>-prov</i> option option. (If you want to use a channel which is not an Nextview <font SIZE="-1">EPG</font> provider, you&#8217;d have to use an external application to tune the channel before you invoke nxtvepg; with the exception of Linux&#8217; <i>v4lctl setstation</i> command this mode is unsupported though and may not work, depending on the external application you&#8217;re using it with.) </p>
<p> <code>Important restriction</code>: nxtvepg is able to retrieve the clock only from channels where the so-called teletext <i>packet 8/30/1</i> is transmitted, which contains date, time and local time zone offset in a binary format. nxtvepg will never attempt to retrieve times from teletext header lines. All Nextview <font SIZE="-1">EPG</font> providers transmit packet 8/30/1, and a few other networks do too (e.g. <font SIZE="-1">ARD</font> and <font SIZE="-1">ZDF</font> in Germany.) </p>
<p> With mode <i>print</i> the date and time will be read and printed. The output is written to <i>stdout</i> unless you redirect it into a file or pipe it into another program. See option <i>-outfile</i> for details. </p>
<p> With mode <i>set</i> the time is set as system time, provided the calling user has the necessary priviliges (e.g. you&#8217;d need to be <i>root</i> on <font SIZE="-1">UNIX</font>; since it&#8217;s depreciated to run nxtvepg with root priviliges, it&#8217;s recommended to first print the time into a file and then pass it to date). </p>
<p> <font SIZE="-1">UNIX</font> users should also note that the <i>set</i> mode does not update the battery powered hardware clock (aka Real Time Clock <font SIZE="-1"><code>RTC</code></font>), so the correction will probably be lost with the next reboot. To update your <font SIZE="-1">RTC</font>, call <i>hwclock &#8211;systohc</i> or your operating system&#8217;s equivalent after nxtvepg. Some Linux distributions automatically take care of this during shutdown.</p>
<dt><code>-provscan</code> <i>country</i></p>
<dd> When started with this argument nxtvepg will start scanning all <font SIZE="-1">TV</font> channels in the given country&#8217;s frequency band for Nextview <font SIZE="-1">EPG</font> providers. Countries are specified by their top-level Internet domain names (e.g. de, at, ch, fr, be) When the scan is finished, nxtvepg updates the provider list stored in the configuration file and terminates itself. The scan is performed in the same way as described in &#8220;<font SIZE="-1">GETTING</font> <font SIZE="-1">STARTED:</font> Search for Nextview providers&#8221; and &#8220;<font SIZE="-1">CONFIGURATION:</font> Provider scan&#8221;, just without the graphical user interface. </p>
<p> During the scan nxtvepg reports progress to <i>stdout</i> unless you redirect it into a file or pipe it into another program. See option <i>-outfile</i> for details.</p>
<dt><code>-demo</code> <i>path</i></p>
<dd> Load database given by <i>path</i> and enter demo mode. In this mode all entries of the database are shifted into the presence, i.e. just far enough so that none are expired. Hence the entries&#8217; dates and times are not for real and acquisition or database reselection is not possible.</p>
<dt><code>-help</code></p>
<dd> List all available command line options.</dl>
<p> After the options you can add a database filename. If it&#8217;s a regular nxtvepg database, this is equivalent to specifying options <code>-dbdir</code> and <code>-provider</code> (if such options are provided, they are silently overridden in this case.) If it&#8217;s a nxtvepg database, but the file name does not have the format as defined in &#8220;<font SIZE="-1">FILES</font>&#8221;, it&#8217;s assumed to be a demo database and loaded just as with the <code>-demo</code> option. Last but not least, it&#8217;s also possible to name an <font SIZE="-1">XML</font> file with <font SIZE="-1">XMLTV</font> data. </p>
<p> This is particularily useful for users of graphical file managers (like the Windows Explorer) who can just drag and drop a database file onto the executable. When used on Windows systems the working directory is set to the one that contains the executable, because the Explorer seems to set it to the user&#8217;s desktop root, so that none of the DLLs and drivers are found. </p>
<p> Note to Windows users: all these options &#8211; unless otherwise noted &#8211; are available in the Win32 version too. You can supply the options either from a &#8220;<font SIZE="-1">MS-DOS</font>&#8221; command prompt or batch file, or by appending them to the executable in a shortcut definition.</p>
<h2>GETTING STARTED</h2>
<p> Before you can start reading in <font SIZE="-1">TV</font> programme schedules (called <i>acquisition</i> from here on), you have to do just a few configurations. Which ones depends on your setup and will be described in this chapter. As long as your browser window contains no data, there&#8217;s also a recommendation how to get to data in the browser window, highlighted by a yellow background. </p>
<p> This manual describes all features of nxtvepg in detail. You do not have to read all of it at once to operate the software. However it&#8217;s recommended to skim at least through &#8220;<font SIZE="-1">BASIC</font> <font SIZE="-1">BROWSING</font>&#8221;, &#8220;<font SIZE="-1">DATA</font> <font SIZE="-1">ACQUISITION</font>&#8221; and &#8220;<font SIZE="-1">FILTERING</font>&#8221;.</p>
<h2><font SIZE="-1">TV</font> card Setup on M$ Windows</h2>
<p> Windows users first have to configure the driver for their <font SIZE="-1">TV</font> card in the &#8220;<font SIZE="-1">TV</font> card input&#8221; dialog via the Configure menu (for additional information see also &#8220;<font SIZE="-1">CONFIGURATION:</font> <font SIZE="-1">TV</font> card input&#8221;). <font SIZE="-1">UNIX</font> users can skip this section. </p>
<p> First you need to decide which driver to use: For <font SIZE="-1">TV</font> cards with Brooktree Bt8x8 or Philips SAA713x capture chips, the <i>dsdrv</i> driver should be preferred. For <font SIZE="-1">TV</font> cards with Conexant CX2388x capture chips the <font SIZE="-1">WDM</font> drivers should be preferred. Generally, the internal driver is more reliable as it is optimized for teletext data acquisition while the vendors&#8217; <font SIZE="-1">WDM</font> drivers usually are optimized for video and sometimes don&#8217;t support teletext at all. On the other hand, the dsdrv driver doesn&#8217;t support all <font SIZE="-1">TV</font> cards and sometimes there are conflicts when a <font SIZE="-1">WDM</font> driver is installed for the same card (see also description of option &#8220;Stop conflicting <font SIZE="-1">WDM</font> drivers&#8230;&#8221;) </p>
<p> By default nxtvepg doesn&#8217;t include support for <font SIZE="-1">WDM</font>. The reason for this separation is that the use of <font SIZE="-1">WDM</font> is still experimental. Hence you need to obtain a separate package with an interface library (VBIAcqWDMDrv.dll) You should unpack the contents of this package into the same directory as the nxtvepg executable. If you don&#8217;t have the library you&#8217;ll see an error message stating &#8220;Failed to load <font SIZE="-1">WDM</font> interface library&#8221; when switching to a <font SIZE="-1">WDM</font> source. </p>
<p> If you chose to use a <font SIZE="-1">WDM</font> driver, you can skip the next chapter and continue with the video input configuration. </p>
<p> Note if both <font SIZE="-1">WDM</font> and dsdrv drivers fail to work with nxtvepg, a third option may be to run nxtvepg in parallel to K!TV. In this case the capturing is done inside of the <font SIZE="-1">TV</font> application and teletext data is simply forwarded via shared memory to nxtvepg.</p>
<h2>Dsdrv driver configuration on M$ Windows</h2>
<p> To start driver configuration, press the <i>Configure card</i> button in the middle of the &#8220;<font SIZE="-1">TV</font> card input&#8221; dialog window, which will open another dialog. If this button is disabled, this means no supported <font SIZE="-1">TV</font> capture chips were found in your system. (You&#8217;ll also see an error message popup stating <i>&#8220;</i><font SIZE="-1"><i>PCI</i></font><i> scan failed&#8221;</i>; see also the <font SIZE="-1">README</font> file for more details on driver error messages.) In this case your only option is to use the <font SIZE="-1">WDM</font> driver (see the previous chapter.) </p>
<p> First press the <i>Autodetect</i> button to the right of the dialog window; this will read certain parameter values from non-volatile memory on your card (<font SIZE="-1">EEPROM</font>) to determine the manufacturer and model. Optimally this will allow to derive all required parameters automatically. If this succeeds, all your card&#8217;s parameters will be set and you&#8217;re done and can close the configuration dialog with Ok. If you wish you can still override automatically derived values (e.g. tuner type) with the options described below. </p>
<p> If you get a message that says the card, but not the tuner, could be determined you can skip the next paragraphs and continue with the manual tuner selection. </p>
<p> If your card type could not be automatically determined, search and select your card type in the listbox at the left and then press the <i>Pick from list</i> button or double click on the listbox entry. Note: The card list is identical to the <code>DScaler</code> <font SIZE="-1">TV</font> application (also very similar to <code>K!TV</code>); the same is true for the tuner list. Hence if you&#8217;re unsure, the easiest way is to look up your configuration in DScaler and just copy it here. </p>
<p> For certain card types, the card is queried for the tuner type after manual card selection. If this fails, you&#8217;ll get a message and have to select the tuner manually. </p>
<p> To configure a tuner type, open the tuner selection popup menu by clicking on the <i>Configure</i> button and select one of the entries. For many cards the tuner type is printed on the outside of the retail packaging. Yet a better way is to read the tuner type from the metal shielding box on the card itself. </p>
<p> Some hints for figuring out your settings: For many cards the selected card type is not relevant to nxtvepg (i.e. only tuner and for Bt878 cards the <font SIZE="-1">PLL</font>). Hence if you don&#8217;t find your card in the list don&#8217;t worry, just use any <font SIZE="-1">PAL</font> or <font SIZE="-1">SECAM</font> card entry in the list and set the other parameters manually. To check your configuration start an <font SIZE="-1">EPG</font> scan. Before you do so you must leave the configuration sub-menu with <font SIZE="-1">OK</font> so that the changes are applied. For your convenience, you can open the card configuration dialog with a button in the <font SIZE="-1">EPG</font> scan dialog window. </p>
<p> Hints for tuner selection: If you live in Germany, Austria or Switzerland you probably have a <font SIZE="-1">PAL</font> tuner, in France it&#8217;s one of the <font SIZE="-1">SECAM</font> types. If you select the wrong tuner, you can have either no reception at all (the <font SIZE="-1">EPG</font> scan will just run through and suggest to check your antenna) all or no reception just on a few channels. </p>
<p> For cards built around a Brooktree chip (Bt878 et.al.) the type of <font SIZE="-1">PLL</font> initialization also needs to be set. This setting is directly tied to your card selection, hence usually you will not need to set it manually. Usually the correct value for <i></i><font SIZE="-1"><i>PLL</i></font><i> initialization</i> with <font SIZE="-1">PAL</font> and <font SIZE="-1">SECAM</font> cards is either <i>No init</i> or <i>28 MHz</i>. (If you select the wrong value you have no reception at all.)</p>
<h2>Video input configuration</h2>
<p> Before nxtvepg can start acquiring <font SIZE="-1">EPG</font> data, it must be told if the video feed is provided by your <font SIZE="-1">TV</font> card&#8217;s internal <font SIZE="-1">TV</font> tuner (if you&#8217;re connected to your city&#8217;s <font SIZE="-1">TV</font> cable network or a terrestrial antenna) or an external source (usually satellite receivers connected via Composite or S-Video cable). This can be configured in the <i></i><font SIZE="-1"><i>TV</i></font><i> card input</i> dialog in the Configure menu (for more in-depth information see also &#8220;<font SIZE="-1">CONFIGURATION:</font> <font SIZE="-1">TV</font> card input&#8221;). </p>
<p> By default nxtvepg assumes input via <font SIZE="-1">TV</font> tuner. This is the preferred mode of operation, since nxtvepg can change channels between multiple Nextview providers, while with an external source you have to switch channels manually (see also &#8220;<font SIZE="-1">DATA</font> <font SIZE="-1">ACQUISITION</font>&#8221;). If you&#8217;re living in France you should tell nxtvepg to use the French channel table (which implies using the Secam <font SIZE="-1">TV</font> norm instead of <font SIZE="-1">PAL</font> B/G/I); this information is required for the next step: the <font SIZE="-1">EPG</font> scan. </p>
<p> If you cannot use the <font SIZE="-1">TV</font> tuner but have instead connected a satellite receiver through the Composite or S-Video input, select the respective setting in the <i>video input</i> drop-down menu. Then close the dialog with Ok and open the aquisition mode configuration dialog from the same menu. There you should change to the <i>external</i> mode: in this mode nxtvepg will switch to the configured video input channel during startup of acquisition, but afterwards expect you to tune in a Nextview provider&#8217;s channel at the external video source. To load all provider&#8217;s inventories in the way the <font SIZE="-1">EPG</font> scan does, you have to tune in all provider channels (for a list see the intro of this manual or the Internet homepage) and wait until the status line changes from &#8220;starting up&#8221; to &#8220;working on&#8221;. </p>
<p> Note that you can also connect your satellite receiver via antenna cable. However this variant is highly depreciated, because the signal is often degraded so much that nxtvepg is not able to decode the <font SIZE="-1">EPG</font> data stream any more. But if you still want to go that route, you&#8217;d keep the tuner as input source and start an <font SIZE="-1">EPG</font> scan to find the channel your receiver is transmitting its signal on. Make sure to disable the <i>Use .xawtv</i> option in the provider scan dialog, unless your satellite receiver&#8217;s channel (i.e. the frequency onto which the satellite signal is modulated) is defined as an input channel in xawtv. Before you start the <font SIZE="-1">EPG</font> scan you need to tune in a Nextview provider&#8217;s channel. The scan will only find that one provider. If you want to load all providers you have to continue manually as described above. For an acquisition mode it&#8217;s recommended to stay with <i>Follow browser database</i>. Although nxtvepg will not be able to actually &#8220;follow&#8221; your provider selection with the acquisition since it can&#8217;t switch the <font SIZE="-1">TV</font> channel at your external input, this mode will tell nxtvepg to set the <font SIZE="-1">TV</font> tuner onto your receiver&#8217;s channel (see also &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221; for more details.)</p>
<h2>Search for Nextview providers (<font SIZE="-1">EPG</font> scan)</h2>
<p> This section only applies if you chose to use your <font SIZE="-1">TV</font> card&#8217;s internal tuner. In this case the next step to get started is to run a provider scan from the Configure menu. During the scan all <font SIZE="-1">TV</font> channels are checked for Nextview transmissions and a list of Nextview providers is built from the result. </p>
<p> You can speed up the scan by using a <font SIZE="-1">TV</font> application&#8217;s channel table; in this case the scan is limited to <font SIZE="-1">TV</font> frequencies defined in the <font SIZE="-1">TV</font> app&#8217;s channel table. This mode is enabled with the <i>Use </i><font SIZE="-1"><i>TV</i></font><i> app freq. table</i> checkbutton. This button will be disabled until you&#8217;ve selected a <font SIZE="-1">TV</font> application in the <i></i><font SIZE="-1"><i>TV</i></font><i> app. interaction</i> dialog described in the next chapter. You can open this dialog by pressing the button at the bottom of the <font SIZE="-1">EPG</font> scan dialog window. </p>
<p> At the end of the scan there&#8217;s a short summary which tells you how many providers have been found. If there were any, you can close the dialog window and open the provider selection dialog from the Configure menu and select you favorite one. Then wait a little while the provider&#8217;s <font SIZE="-1">TV</font> channel is tuned and data being loaded. </p>
<p> If the provider scan does not find any or not all Nextview provider channels (possibly due to weak reception &#8211; this is a very simple scan that does not attempt any fine-tuning) enable the <i>Slow</i> button and try again. If this does not help, you can still add the missing providers manually. set the acquisition mode to <i>external</i> or <i>passive</i> (<font SIZE="-1">UNIX</font> only). Then use an external application to tune the channel (Windows users have to stop acquisition first; then start the <font SIZE="-1">TV</font> application; then tune the channel; then quit the other application; finally start acquisition again). </p>
<p> In external mode nxtvepg will not touch the tuner and wait infinitly for Nextview reception on the current channel. On Windows (and Linux with bttv drivers version 0.7.50 and earlier) this method has the disadvantage that no channel number or frequency will be known for this provider so you have to tune the provider&#8217;s channel manually whenever you start acquisition. </p>
<p> Acquisition of a complete database takes about 20 minutes. However programmes that are nearer in the future are available much faster, since they are transmitted more often. The currently running and directly following programmes of all networks are usually available after about 2-3 minutes max.</p>
<h2>Configuring a <font SIZE="-1">TV</font> application</h2>
<p> nxtvepg can cooperate in the following ways with <font SIZE="-1">TV</font> applications:</p>
<dl>
<dt>*</p>
<dd> Loading the <font SIZE="-1">TV</font> application&#8217;s channel table: use of the <font SIZE="-1">TV</font> tuner frequencies can significantly speed up the <font SIZE="-1">EPG</font> scan (already mentioned above.) The <font SIZE="-1">TV</font> app&#8217;s channel names are used by the <i>Network name</i> dialog in the Configure menu (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Network names&#8221;) to synchronize network names between nxtvepg and the <font SIZE="-1">TV</font> application.</p>
<dt>*</p>
<dd> Interaction between nxtvepg and the <font SIZE="-1">TV</font> application, to provide you with convenience features like an on-screen display of the current programme title after channel changes, changing the channel from inside nxtvepg with the <i>TuneTV</i> button, and background Nextview data acquisition while you&#8217;re watching <font SIZE="-1">TV</font>.</dl>
<p> The first one is a passive feature, i.e. only nxtvepg needs to be adapted to the respective <font SIZE="-1">TV</font> applications. The second one however requires cooperation of both sides. For this reason the number of <font SIZE="-1">TV</font> applications for which the passive features are supported will always be much larger. On Windows the interaction features are currently only supported by K!TV. </p>
<p> On <font SIZE="-1">UNIX</font> <i>xawtv</i>, <i>xdtv</i> (former <i>xawdecode</i>), <i>zapping</i> and <i>tvtime</i> are supported currently. All the features listed above do work with any of them. </p>
<p> On Windows several freeware <font SIZE="-1">TV</font> applications are supported for the passive features; you must select which one you&#8217;re using. If you&#8217;ve loaded <font SIZE="-1">TV</font> card settings from a <font SIZE="-1">TV</font> app in the <i></i><font SIZE="-1"><i>TV</i></font><i> card input</i> dialog, then the <font SIZE="-1">TV</font> app type and path is already configured. Else, or if you want to use a different app as source for the channel table, open the <i></i><font SIZE="-1"><i>TV</i></font><i> app. interaction</i> dialog (see also &#8220;<font SIZE="-1">CONFIGURATION:</font> <font SIZE="-1">TV</font> application interaction&#8221;). </p>
<p> Regarding the second feature, i.e. the &#8220;active&#8221; one: You can check if nxtvepg is able to interact with a specific <font SIZE="-1">TV</font> application by starting both, and then opening the <font SIZE="-1">TV</font> application interaction dialog in the Configure menu. The connection status is indicated in the middle of the dialog window. On Windows nxtvepg should already display an error message when it&#8217;s started while an unsupported <font SIZE="-1">TV</font> application is running, complaining &#8220;Capturing is already enabled in the <font SIZE="-1">TV</font> card&#8221; or another driver error message. Only with cooperating <font SIZE="-1">TV</font> apps nxtvepg is able to automatically free the card when the <font SIZE="-1">TV</font> app is started (<font SIZE="-1">TV</font> viewing is always given priority over <font SIZE="-1">EPG</font> data acquisition.) </p>
<p> <code>Important</code>: On Windows you must not run nxtvepg with acquisition enabled at the same time as a <font SIZE="-1">TV</font> application. If you ever accidentially do that, immediately terminate both applications. When two applications access the <font SIZE="-1">TV</font> card hardware at the same time, the resulting conflicts can crash your system. </p>
<p> After setting up the <font SIZE="-1">TV</font> app type and path, you should open the <i>Network name</i> configuration dialog to synchronize network names between nxtvepg and the <font SIZE="-1">TV</font> app. Even if interaction is not possible, it may still be a good idea to have the same network names in both applications. See &#8220;<font SIZE="-1">CONFIGURATION:</font> Network names&#8221; for details.</p>
<h2>BASIC BROWSING</h2>
<p> The browser mainly consists of two windows: the upper one contains a list of programme titles, sorted by start time. All currently running programmes (or rather: all programmes that should be running according to their start time) are marked by a light blue background color. One line in the list is selected by a cursor; the lower window contains the attributes and description for this selected title. The amount of information available here depends entirely on the content provider. </p>
<p> The basic browsing of programme information works very straight-forward. You can either use the mouse or the keyboard cursor keys: </p>
<p> With the mouse, you can click on any title to select it and display its description in the lower window. Use the scrollbar to the left to scroll the listing forward to programmes farer in the future, or the weekday scale on the right to jump to a specific time and date. </p>
<p> With the keyboard, use the Cursor up/down keys to select any title. For fast scrolling use the page up/down keys. With the Home key you always get back to the first title. With <font SIZE="-1">TAB</font> and SHIFT-TAB you can move the keyboard input focus to other input elements, e.g. to the network and shortcut lists; to apply a selected theme or shortcut as filter press the <code>Space</code> key. The first 10 shortcuts can also be enabled directly from the main window with the digit keys 1-9 and 0. Control-C in the main window opens the context menu; Control-F opens the text search dialog; the Escape key is equivalent to the Reset button. The menus can be accessed by pressing the <font SIZE="-1">ALT</font> key together with the underlined character in the respective menu button. </p>
<p> You can restrict the programme selection in many ways to make it easier to find what interests you. For example, you can restrict the list to programmes of a certain network; or you can restrict the list to movies only. This process is called <i>filtering</i> and explained in detail below, see &#8220;<font SIZE="-1">FILTERING</font>&#8221;. For the most common filter options there&#8217;s a list of <i>Shortcuts</i> at the left of the main window. Note you can freely modify this list, see &#8220;<font SIZE="-1">FILTER</font> <font SIZE="-1">SHORTCUTS</font>&#8221;. </p>
<p> Since version 2.5.0 nxtvepg offers two different layouts for the <font SIZE="-1">TV</font> schedules: By default programmes of all channels are combined in a single list sorted by start time, i.e. one big table. Alternatively programmes can be separated so that each network has it&#8217;s own column. This format is very similar to most paper-based <font SIZE="-1">TV</font> magazines. In this layout you can scroll both vertically by start-time and horizontally by networks. </p>
<p> When you resize the main window vertically the difference in height will be added to the info text window at the bottom. You can adjust the proportions between program listbox and the info text with the &#8220;panning&#8221; button inbetween, i.e. by dragging the button you can resize the programme list. </p>
<p> nxtvepg can interact with <font SIZE="-1">TV</font> applications (e.g. <i>xawtv</i> on <font SIZE="-1">UNIX</font>; requires initial setup, see &#8220;<font SIZE="-1">GETTING</font> <font SIZE="-1">STARTED</font>&#8221;) to provide a connection in both directions: Firstly you&#8217;ll find a <i>Tune-TV</i> button in the main window below the clock. When you press it, the network of the currently selected programme will be tuned in the <font SIZE="-1">TV</font> application. This also works with a double-click on the programme or pressing the <i>Return</i> key. By clicking the right mouse button above the Tune-TV button you can also pop up a small menu which offers basic <font SIZE="-1">TV</font> controls. Secondly, when you change the channel in the <font SIZE="-1">TV</font> application, the cursor in the nxtvepg main window will automatically jump onto the programme currently running on that network. You can manually trigger this reaction by pressing &#8220;i&#8221; on your keyboard. For more details see &#8220;<font SIZE="-1">CONFIGURATION:</font> <font SIZE="-1">TV</font> application interaction&#8221; </p>
<p> At the bottom of the window there is a status line which informs you about the state of the browser database and background acquisition. It&#8217;s basically a very dense summary of the <code>Statistics</code> popups from the <code>Control</code> menu and is especially useful to warn you about the database age or stalled acquisition. </p>
<p> <i>Note:</i> For most providers it holds true that programme content descriptions (i.e. the texts in the lower nxtvepg window) are available only for currently running programmes and those whose start time is very close. This time span for full coverage can be as short as 2 hours, or 3 titles per network. As a consequence you should enable data acquisition as often as possible; consider running the acquisition daemon permanently in the background. For details on the acquisition process see the following chapter.</p>
<h2>DATA ACQUISITION</h2>
<p> As long as acquisition is enabled, programme titles are constantly being acquired or updated in the background. You will notice that all incoming programme information is instantly inserted to the programme listing. Every effort is taken to not alter the cursor position or title selection, except if the cursor is on the very first item &#8211; then the cursor stays on top. </p>
<p> By default, the acquisition always works for the provider whose database you have loaded into the browser. Therefore, upon program start or whenever you switch providers, the <font SIZE="-1">TV</font> tuner is set onto the frequency of the provider&#8217;s <font SIZE="-1">TV</font> channel. Please note that this mode is only possible after a provider scan, because that&#8217;s the only way to find out the frequencies. Check out &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221; for more sophisticated acquisition strategies. </p>
<p> If you do not choose the <font SIZE="-1">TV</font> tuner as input (e.g. if you choose an external source via the Composite or S-Video input sockets), or if the <font SIZE="-1">TV</font> tuner is kept busy by another application (<font SIZE="-1">UNIX</font> only, e.g. if you watch <font SIZE="-1">TV</font>) data is still being acquired, but it&#8217;s no longer possible to automatically change the <font SIZE="-1">TV</font> channel. Hence you are resposible for selecting the channel of the provider who&#8217;s database you want to load or refresh. If a transmission belonging to a different provider than the one selected in the browser is detected, a second database is automatically opened in the background to store the incoming data. </p>
<p> The transmitted database is constantly in change: Elapsed titles are removed, new titles appended, and the titles closest to the current time updated with an increased amount of description. (The reason that the complete description is not transmitted for all titles is simply that the size of the database has to be reduced &#8211; it shall be transmitted in 20 minutes maximum.) So you should start the acquisition as often as possible, about every 2-3 hours, at least a couple of minutes before you browse. </p>
<p> You can monitor the progress of acquisition with the timescale and database statistics windows from the Control menu. See &#8220;<font SIZE="-1">STATISTICS</font>&#8221; for details.</p>
<h2>ACQUISITION MODES</h2>
<p> The acquisition mode configuration dialog enables you to control for which providers data is collected, and in which order. It&#8217;s mainly intended for users who use more than one provider&#8217;s database, i.e. in a merged database, or want to optimize startup time. If you&#8217;re happy with a single provider or don&#8217;t want to browse immediately after program start, you should keep the default, which is loading data always for the provider selected in the browser.</p>
<dl>
<dt><code>Passive</code></p>
<dd> <font SIZE="-1">UNIX</font> only: In this mode the software never accesses the video device and never changes the input channel or tuner frequency. It&#8217;s useful if you want to set up the source with command line tools like <i>v4lctl</i>. If you&#8217;re using applications which keep the video device busy (e.g. a <font SIZE="-1">TV</font> application) you don&#8217;t need this mode, because when nxtvepg detects an unsolicited channel change, it automatically switches to the passive mode for as long as the video device remains busy. </p>
<p> Please note: when nxtvepg does not control the input channel, it can not automatically take care of updating your databases. Even if the browser database should be completely empty, no data will appear until you tune in the provider&#8217;s channel manually with an external application. Because of this, passive mode is depreciated.</p>
<dt><code>External</code></p>
<dd> This is the recommended mode for Composite or S-Video input sources. Only the input source will be set; the tuner is not touched. Hence the provider channel has to be selected either externally (e.g. in a satellite receiver connected to the Composite or S-Video input sockets) or by a different application (e.g. <font SIZE="-1">TV</font> application, <font SIZE="-1">UNIX</font> only), just like in passive mode. </p>
<p> On Windows systems this mode can be used if your tuner is not known to nxtvepg, i.e. if the <font SIZE="-1">EPG</font> scan does not find any channels with all of the available tuner types. In this case tune in the provider channel with a <font SIZE="-1">TV</font> application; then quit this application and start nxtvepg. When you view the acquisition statistics from the Control menu, the <font SIZE="-1">VPS/PDC</font> code of the tuned channel should appear in the lower half of the window.</p>
<dt><code>Follow-UI</code></p>
<dd> This is the default mode: the acquisition always works for the provider you have selected for the browser (i.e. user interface). If you change the provider in the browser window, acquisition follows by tuning the new channel. Of course this requires to have performed an <font SIZE="-1">EPG</font> scan at least once, so that the tuner frequencies of all providers are known. When you use a merged database in the browser, acquisition works on each of the merged providers, one after another, just like in the mode described next.</p>
<dt><code>Manually selected (Cyclic: All</code></p>
<dd> This mode enables you to manually select for which providers the acquisition should work. If you select more than one provider, they are loaded one after another, in your specified order. Warning: if you choose a provider for the browser that&#8217;s not on the list, no data will be loaded into the browser, even if it&#8217;s completely empty. </p>
<p> Since transmission errors have to be considered, it&#8217;s not attempted to load every single block of a provider before acquisitions switches to the next. Instead a statistical criterium was defined, that regards the variance in coverage of all networks contained in the database, and the slope of that variance.</p>
<dt><code>Cyclic: Now &#8211; Near &#8211; All</code></p>
<dd> Like the previous mode, this one enables you to specify a list of providers to load data for. However they are not just loaded completely one after another. Instead, a 3-staged round-robin is implemented. In the first stage, only <i>Now</i> data is loaded, i.e. the currently running and next 2-3 programmes. When this has been completed for all providers, the next stage begins, which loads <i>Near</i> data, i.e. all programmes running in the next 12-24 hours. When that was completed, the final stage loads the outstanding blocks for all providers. See below for an explanation what this mode is good for.</p>
<dt><code>Cyclic: Now &#8211; All</code></p>
<dd> This is the same as the previous mode, except that the <i>Near</i> stage is skipped.</p>
<dt><code>Cyclic: Near &#8211; All</code></p>
<dd> This is the same as the mode before the previous one, except that the <i>Now</i> stage is skipped.</dl>
<p> Which mode is best for you depends on how you use the browser. As said above, if you&#8217;re mainly using a single provider, stick with the Follow-UI mode. If you use a merged database, data is automatically loaded for all contained providers. However if you switch manually between multiple providers, you should choose one of the manual acquisition modes. </p>
<p> The Cyclic modes enables you to optimize startup time. While in standard manual mode, the first database is loaded completely before the next one is started, in Cyclic modes you can specify to load only Now data of all providers first. Hence already after a couple minutes you&#8217;ll have updated Now information for all providers. If you require more look-ahead than the next 2-3 programmes, e.g. the complete evening, use a Cyclic mode that starts with the Near stage. </p>
<p> If you use manual acquisition together with a merged browser database, make sure to put the same provider at top in both lists, i.e. acquisition should always start for the &#8220;master database&#8221; of the merge. </p>
<p> Please note that the time until all databases are complete is longer in the cyclic modes than in standard manual mode. In general, the time used for the Now and Next stages just adds to the time to complete the database. </p>
<p> Also note that the cyclic modes depend on the transmission cycles of the providers. Firstly this means that the time ranges covered by the cycle stages may differ between providers. Secondly, the cycle times may vary. In the worst case the Near cycle runs as long as the cycle for the complete database (e.g. the German provider <font SIZE="-1">RTL2</font>). In this case you don&#8217;t win anything by selecting a mode that contains a Near stage.</p>
<h2>STATISTICS</h2>
<p> There are currently three ways to obtain information about the state of the databases and the acquisition process: the first and most obvious is the status line at the bottom of the main window (only if enabled, see &#8220;<font SIZE="-1">CONFIGURATION</font>&#8221;). The second one are the timescale popup windows, which visualize for each <font SIZE="-1">TV</font> network the time ranges which are covered with <font SIZE="-1">TV</font> programme data. The third one are the database statistics popup windows which offer technical details about the database, e.g. which percentage of entries is already loaded etc., both in textual form and as charts. </p>
<p> The latter two windows are available separately for the browser and acquisition databases. (By default both are the same databases, but you can configure background acquisition on multiple databases, see &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221;). All types of statistics are regularily updated while acquisition is running. While connected to an acquisition daemon, all statistics output refers to the acquisition running in the daemon (see &#8220;<font SIZE="-1">CONTROL:</font> Connect to acq. daemon&#8221;)</p>
<h2>Status line</h2>
<p> The status line separately summarizes the state of the browser database (unless it&#8217;s a merged database) and the acquisition process. Since there&#8217;s not much room only the most relevant information is included there, i.e. the kind of information presented depends on the current state. </p>
<p> For the browser database you&#8217;ll normally just see the name of the content provider network and a percentage that describes how many of the blocks (i.e. <font SIZE="-1">TV</font> programmes) in the provider database already have been received. </p>
<p> If more than 10% of the blocks in the database lie in the past, you&#8217;ll additionally see a note about this percentage of expired blocks. Note that a 100% loaded database may appear completely empty when all blocks are expired. As soon as you start acquisition the fill percentage will drop to 0 because a new inventory will have been loaded which no longer contains the expired blocks. </p>
<p> When acquisition for the browser database stopped more than 60 minutes ago, a note is added to the status line. In this case it may be advisable to start acquisition for this database to load descriptions for programmes that are now included in the &#8220;Near&#8221; time range (see &#8220;<font SIZE="-1">DATA</font> <font SIZE="-1">ACQUISITION</font>&#8221;). </p>
<p> If acquisition is currently not active you&#8217;ll see a note about that, often together with a reason, e.g. &#8220;no reception&#8221; when you&#8217;ve manually tuned a station that doesn&#8217;t transmit Nextview. </p>
<p> Else you&#8217;ll see the name of the content provider network and a percentage that describes the progress of acquisition. Note that this percentage may be different from the overall fill percentage given with the browser database, as it also reflects blocks that have to be reloaded due to version changes. </p>
<p> Additionally there may be a note about the current mode of acquisition, like the current phase for cyclic acquisition modes or &#8220;forced passive&#8221; when nxtvepg is not able to change the channel, maybe due to a <font SIZE="-1">TV</font> application running in parallel. See &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221; for details.</p>
<h2>Timescale popup windows</h2>
<p> You can monitor the progress of acquisition with the timescale windows which can be opened from the Control menu. There&#8217;s one window for the browser database, and one for the acquisition database. The acquisition window is updated whenenever new <font SIZE="-1">EPG</font> blocks are received. </p>
<p> The timescale windows have one scale for each network covered by the selected provider. The left end of the scales refers to the start time of the oldest <font SIZE="-1">TV</font> programme in the database. Depending on how long ago the database was updated and the current expiry removal delay (see &#8220;<font SIZE="-1">FILTERING:</font> Expired Programmes Display&#8221;), some or all <font SIZE="-1">TV</font> programmes may lie in the past. The exact dates are printed in the date scale at the top of the window, the current time is additionally marked with a small arrow labeled &#8220;now&#8221;. </p>
<p> Ranges that are covered by programmes of the respective network in the database are marked in shades of red or blue, uncovered ranges are left black. The different colors reflect the <i>stream</i> in which the data was received, or an error status; the shades age and version. Stream numbers are directly connected with the cycle phases mentioned in &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221;; besides this the difference is not relevant during normal operation.</p>
<dl>
<dt><i>red:</i></p>
<dd> <font SIZE="-1">PI</font> blocks received in stream 1, i.e. cycle phase &#8216;Near&#8217;.</p>
<dt><i>blue:</i></p>
<dd> <font SIZE="-1">PI</font> blocks received in stream 2, i.e. cycle phase &#8216;All&#8217;.</p>
<dt><i>dark red or blue:</i></p>
<dd> <font SIZE="-1">PI</font> blocks from an earlier database version.</p>
<dt><i>orange:</i></p>
<dd> expired <font SIZE="-1">PI</font> blocks from stream 1 or an earlier database version.</p>
<dt><i>cyan:</i></p>
<dd> expired <font SIZE="-1">PI</font> blocks from stream 2 and the current database version.</p>
<dt><i>yellow:</i></p>
<dd> invalid <font SIZE="-1">PI</font> blocks (overlapping or zero run-time, block number not in the range given in inventory, etc.)</p>
<dt><i>gray:</i></p>
<dd> missing <font SIZE="-1">PI</font> blocks. Note that the range can only be roughly estimated, as the time range a block covers is not known until the actual block is available.</p>
<dt><i>black:</i></p>
<dd> time range which is not covered by the provider.</dl>
<p> Programmes for which description texts are currently available are additionally marked by an increased height of the scale in the covered time range. For short-info the area is extended towards the top, for long-info towards the bottom (the distinction between short and long info is only related to the Nextview transmission specification and does not neccessarily relate to the length of the description texts; also note that for the merged database there&#8217;s no distinction between short and long info because all texts are concatenated into one.) </p>
<p> In front of the scales there are 5 separate boxes, which refer to the first 5 programmes (<font SIZE="-1">PI</font> blocks) in the inventory (<font SIZE="-1">AI</font> block). They have two purposes: firstly, during acquisition you can see when the &#8216;Now&#8217; cycle phase is complete; secondly you can check if the data from the Now cycle is expired (marked orange). If all 5 are orange, it&#8217;s time to update the database.</p>
<h2>Database statistics</h2>
<p> There are two popup windows available from the Control menu which contain statistical information about the browser database and the acquisition database and progress. The window is horizontally divided in two parts: the upper part lists static information; the lower part lists dynamic info and is available only while acquisition is active. </p>
<p> The acquisition statistics are updated every time a new <font SIZE="-1">AI</font> block (inventory which lists all covered networks and block counts per network; usually transmitted every 10 seconds) is received.</p>
<dl>
<dt><i>Last </i><font SIZE="-1"><i>AI</i></font><i> update:</i></p>
<dd> The (local) time when the last inventory block was received. Since this block has to be transmitted on a regular basis it tells you when acquisition was active for this database.</p>
<dt><i>Database version:</i></p>
<dd> The version number is incremented by the provider every day or after content changes. A version change forces a complete reload of the database.</p>
<dt><i>Blocks in </i><font SIZE="-1"><i>AI:</i></font><i></i></p>
<dd> How many blocks are transmitted in total. This number is taken from the provider&#8217;s <font SIZE="-1">AI</font> block, i.e. the inventory. Additionally listed separately for stream 1 and 2 (swo).</p>
<dt><i>Block count db:</i></p>
<dd> How many blocks are in the local database. At maximum this can be the number of blocks given in the <font SIZE="-1">AI</font> block.</p>
<dt><i>Current version:</i></p>
<dd> How many blocks are in the local database and have the latest version.</p>
<dt><i>Filled:</i></p>
<dd> Percentage of blocks in the database in respect to the total given in the <font SIZE="-1">AI</font> block, i.e. &#8220;Block count db&#8221; divided by &#8220;Blocks in <font SIZE="-1">AI</font>&#8221;. The second percentage in the line only reflects blocks of the current version and hence the degree of completeness of acquisition.</p>
<dt><i>Expired stream:</i></p>
<dd> Number of programme blocks which have a stop time that&#8217;s in the past but are still registered in the provider&#8217;s inventory (<font SIZE="-1">AI</font>). When acquisition is stopped, this number can be large. During acquisition expired programmes are usually stripped by the provider with the start of every cycle, i.e. usually every 20-25 minutes. The percentage given here is in respect to the actual number of blocks in the local database (all versions), not the <font SIZE="-1">AI</font>.</p>
<dt><i>Expired total:</i></p>
<dd> Total number and percentage of expired blocks in the database. This value depends on the expire &#8220;cut-off time&#8221; configured by the user, i.e. on how long expired blocks are kept until they are removed from the database. Normally such blocks disappear from the programme list, but this can be changed with the expire time filter in the Filter menu (see also &#8220;<font SIZE="-1">FILTERING</font>&#8221;).</p>
<dt><i>Defective blocks:</i></p>
<dd> Number of blocks with invalid or overlapping start time. These blocks do not show up in the browser (as it would be impossible to handle if there is more than one &#8220;now&#8221; entry for a network). The percentage given here is in respect to the actual number of blocks in the local database (all versions), not the <font SIZE="-1">AI</font>.</dl>
<p> The pie chart on the left on the window visualizes these numbers. The circle represents 100% of the blocks listed in <font SIZE="-1">AI</font>. It&#8217;s divided in stream 1 (red) and stream 2 (blue). The shaded segments represent the blocks that are still missing in the local database. The yellow segments the percentage of expired and/or defective blocks. </p>
<p> When you interpret those values, please remember that blocks may be appended to the transmission cycle when programmes have expired (in a slight violation of the Nextview standard this is done even without changing the database version). So you might see from time to time that the fill percentages take a step back down during acquisition. Also note that expired <font SIZE="-1">PI</font> are not accessible from the user interface, however they are included in the database dump from the <i>Control</i> menu.</p>
<h2>Acquisition statistics</h2>
<dl>
<dt><i>Acq. runtime:</i></p>
<dd> How long the acquisition has been continuously running for this database. This timer is reset upon provider or database version changes or when an external channel change is detected.</p>
<dt><i>Channel </i><font SIZE="-1"><i>VPS/PDC:</i></font><i></i></p>
<dd> The <font SIZE="-1">VPS/PDC</font> code that has last been received on the currently tuned channel. Usually this will be the same as the provider <font SIZE="-1">CNI</font> given in the database statistics, but you might see different values here when you manually tune in a different channel with an external application. </p>
<p> If a valid <font SIZE="-1">VPS/PDC</font> code (Programme Identification Label, <font SIZE="-1">PIL</font>) was received together with the <font SIZE="-1">CNI</font> it is appended after the <font SIZE="-1">CNI</font> in decoded format (i.e. <font SIZE="-1">DD</font>.MM <font SIZE="-1">HH:MM</font> with day, month, hour and minute). Note: the <font SIZE="-1">VPS/PDC</font> codes are used to uniquely identify the current programme on a given network. You can display the codes for all programmes in the database (if you enable them in &#8220;<font SIZE="-1">CONFIGURATION:</font> Select attributes&#8221;) or pass them to external applications (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Context menu configuration&#8221;)</p>
<dt><i></i><font SIZE="-1"><i>TTX</i></font><i> data rate:</i></p>
<dd> The rate at which teletext data lines are received on the current channel in baud, i.e. bits per second. Each teletext line counts as 45 bytes.</p>
<dt><i></i><font SIZE="-1"><i>EPG</i></font><i> data rate:</i></p>
<dd> Same as <font SIZE="-1">TTX</font> data rate, however only teletext lines that belong to the page which transmits Nextview are counted.</p>
<dt><i></i><font SIZE="-1"><i>EPG</i></font><i> page rate:</i></p>
<dd> The per second average of received teletext pages with carry Nextview data. Many provider transmit one page per second during the day and up to 1.5 or 2 pages per second during the night.</p>
<dt><i></i><font SIZE="-1"><i>AI</i></font><i> recv. count:</i></p>
<dd> The number of <font SIZE="-1">AI</font> blocks received since acquisition start. As long as this counter remains at zero, no data is added to the database (because the <font SIZE="-1">AI</font> block is mandatory to identify the provider.)</p>
<dt><i></i><font SIZE="-1"><i>AI</i></font><i> min/avg/max:</i></p>
<dd> The minimum, average and maximum distance between reception of <font SIZE="-1">AI</font> blocks. The average should usually be 10 seconds. The maximum should not be much higher or else an <font SIZE="-1">EPG</font> scan might have a hard time finding this provider; also the acquisition start-up time would be higher because at first an <font SIZE="-1">AI</font> block must be awaited.</p>
<dt><i></i><font SIZE="-1"><i>PI</i></font><i> rx repetition:</i></p>
<dd> The average of the number of times each block in the <font SIZE="-1">AI</font> was received since start of the acquisition. Divided in Now, stream 1 and stream 2. This value is used by acquisition control in the termination criterium for acquisition phases, if the acquisition mode is cyclic.</p>
<dt><i>Decoder quality:</i></p>
<dd> Reception and loss statistics: Count of received <font SIZE="-1">EPG</font> teletext pages and count of complete <font SIZE="-1">EPG</font> pages missing in the sequence. Count of received teletext packets (usually 23 per page) and missing packets. Note: page and packet loss is usually caused by decoding errors in packet and page headers (which carry a 50% redundancy so this is a strong indication of weak signal quality) or when a <font SIZE="-1">TV</font> application running in parallel interferes with capture configuration (i.e. when not all required lines in <font SIZE="-1">VBI</font> can be received) </p>
<p> Next is the number of received and dropped blocks. Blocks are usually assembled from data received in several teletext packets and have to be dropped if packets or pages inbetween are missing. Blocks may also be dropped due to decoding or check-sum errors (above note regarding these errors applies here too) </p>
<p> The final line lists the number of decoded text characters (e.g. programme titles and descriptions) and how many decoding errors were detected. Forward error protection used for text is pretty weak, so you may see errors here even with relatively good signal quality. With bad signal quality the actual error rate might be higher then displayed, since the protection cannot detect double-bit errors.</p>
<dt><i>Acq mode:</i></p>
<dd> The current acquisition mode as configured by the user, or forced passive if nxtvepg failed to switch the channel.</p>
<dt><i>Network variance:</i></p>
<dd> The variance of block coverage across all networks. This value is used by acquisition control in the termination criterium for acquisition phases, if the acquisition mode is cyclic. It&#8217;s calculated by separately counting the number of blocks in the database for each network; then for each network calculating the percentage of available blocks in regard to expected blocks; then calculating the average and finally variance of these percentages.</dl>
<p> The diagram at the left displays a history of fill percentages for stream 1 and 2; the meaning of the colors is the same as in the timescale windows.</p>
<h2>MERGED DATABASES</h2>
<p> If you compare databases of different Nextview providers, you will often find that each has one or more nice features, or covers networks, that the others lack. Instead of changing back and forth between several providers all the time, database merging allows to select and combine features or networks from several original databases into one newly created database. </p>
<p> When you select the <code>Merge providers</code> entry from the <code>Configure</code> menu, you will get a dialog with two listboxes: the left one contains a list of all currently available databases. The right one is the list of databases you want to merge. You can add, delete or reorder the entries is this list. When you&#8217;re done with your selection, press <code>Ok</code> to start the merge and switch the browser to the new database. </p>
<p> By ordering providers in your selection, you assign priorities which are important for conflict resolution. A conflict occurs when programme start and stop times differ between providers. The likelyhood of such conflicts depends on the quality of your providers; theoretically they should never happen except if there are late program changes. In reality, conflicts are not that unlikely, particularily for programmes early in the morning. You should put the most reliable provider in the first position, because conflicting programmes from providers further down will be rejected, i.e. not added to the merged database. </p>
<p> The <code>Configure</code> button in the dialog gives you fine-control over the priority of providers during the merge of all distinct programme attributes. You can even completely remove a provider for an attribute, e.g. if they transmit false data (e.g. the Sound attribute was at some time handled wrong by the former German provider 3Sat: they did swap stereo and surround). An exception is the title, where you must not delete any providers. </p>
<p> Attributes that cannot be merged, e.g. editorial rating, are fetched from the first database in the list that contains the attribute for a given programme. An exception are sorting criteria and series, where only the first provider in the list is queried (i.e. even if the first provider does not have a sorting criterion for a given programme, the further databases are not searched) because these types of attributes cannot be mixed between providers (see also &#8220;<font SIZE="-1">FILTERING</font>&#8221;). </p>
<p> Note: If you use a manual or cyclic acquisition mode, you should take care to include all providers of your merged database in the same order. Else, program changes will not appear in your database until the provider with highest priority is loaded. If you stay with the default <code>Follow-UI</code>, acquisition control will automatically cycle across all merged providers in the correct order.</p>
<h2>NAVIGATE</h2>
<p> The Navigate menu contains a tree of filtering options, that&#8217;s transmitted by the selected provider together with the programme data. Filtering enables to restrict the listing of programme information to those titles matching the selected menu entry. </p>
<p> The extent and content of this menu depends entirely on the provider. Unfortunately most providers supply only a very limited menu, so you&#8217;ll probably want to define your own filters, as described in the next two chapters. </p>
<p> Any filter selection can always be undone by the <i>Reset</i> menu entry or the reset button in the main window. </p>
<p> On Windows this menu is en entry inside of the <i>Filter</i> menu for technical reasons (the concept of danamically created menu hierarchies seems to be foreign to Windows, so a popup menu has to be used for the Navigate menu).</p>
<h2>FILTERING</h2>
<p> Similar to <i>Navigate</i>, this menu allows to control which of the programmes in the database are presented in the listing. However here, you are not limited to a preselection of filter options. There&#8217;s a filter for every kind of attributes that can be attached to a program, e.g. it&#8217;s network, start time, theme descriptors, and so on. </p>
<p> Filters can be undone either singularily by selecting the same filter menu entry again, or globally by clicking on the <i>Reset</i> button. </p>
<p> You can combine as many filters as you want to build a complex filter. If you combine two filters of different types, only programmes that match both attributes will be listed (logical <font SIZE="-1">AND</font>). If you choose more than one filter of the same type, all programmes that match either attribute will be listed (logical <font SIZE="-1">OR</font>). Note some filter types also support multiple &#8220;classes&#8221; which allow logical <font SIZE="-1">AND</font> within a category; this is explained in more detail in the filter types list below. </p>
<p> <i>Examples:</i> If you want to get all programmes listed for either network A <font SIZE="-1"><code>OR</code></font> B, simply select both networks in the filter list. If you want to see all movies scheduled on A, i.e. all programmes which run on network A <font SIZE="-1"><code>AND</code></font> are flagged as movies, select network A and theme &#8220;movie &#8211; general&#8221;.</p>
<h2>Filter Types</h2>
<p> The following filter types are available:</p>
<dl>
<dt><code>Theme categories</code></p>
<dd> Restrict the listing to programmes that have any of the given theme categories attached to them (logical <font SIZE="-1">OR</font>). The Nextview standard contains a list of 76 predefined themes, which are structured into 11 main categories and subcategories. A programme can have up to 7 theme descriptors attached. </p>
<p> If you want to restrict the listing to programmes that have more than one of the given themes (logical <font SIZE="-1">AND</font>) you need to specify them in different theme classes. For example: to get a listing of all programmes which are both Sci-Fi and Comedy, select theme category Sci-Fi, then switch to a different theme class, and select theme category Comedy. The actual class numbers do not matter, you just need to use two different ones (i.e. you can use either #1 and #2 or #5 and #6 etc.)</p>
<dt><code>Series</code></p>
<dd> Restrict the listing to programmes that belong to any of the selected series. A series code always implies a network specification (even if the same programme is transmitted on different networks). </p>
<p> Note: This filter type is only available for providers that assign series codes; also not all series may have a code assigned. For other ones you can use text search among programme titles. </p>
<p> When series and theme or likewise series and text searches are combined, programmes which match either of both filter types are listed. This is an exception from the general rule of combining different filters with a logical <font SIZE="-1">AND</font>.</p>
<dt><code>Networks</code></p>
<dd> Restrict the listing to programmes of one or more given networks. The filter is disabled when all checkbuttons are deactivated. </p>
<p> You can also add a network filter listbox to the main window by enabling one of the <i>Show networks</i> checkbuttons in the <i>Show/Hide</i> sub-menu of the Configuration menu (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Show/Hide&#8221;). Also note that selection, order and names of networks are all configurable, in particular you can permanently suppress uninteresting networks from the list.</p>
<dt><code>Text search</code></p>
<dd> Restrict the listing to programmes who&#8217;s title or description (or either if both options are enabled) contain one of the given character sequences. If you enable the <i>match complete text</i> option, an exact match will be required, i.e. a search for &#8220;heute&#8221; will not match on &#8220;heute journal&#8221; (intended for title-only searches, as started from the context menu). If you enable option <i>match case</i>, character case is relevant, i.e. a search for &#8220;heute&#8221; will not match on &#8220;Heute Abend&#8221;. </p>
<p> You can search for more than one text at the same time; you&#8217;ll get all programmes that contain any of the given texts (logical <font SIZE="-1">OR</font>). The listbox above the text entry field lists all currently active texts. You can double click on the options in the list to toggle them between &#8220;yes&#8221; and &#8220;no&#8221; (i.e. option enabled or disabled). The entries also have small context menus which allow to remove single texts or toggle options. </p>
<p> Press <i>Click here to open&#8230;</i> to open a small dialog which allows to swiftly add a large list of texts (e.g. a list of your favorite movie titles.) You can paste text for example from a text editor into the dialog or load them directly from a file. Each line in the text fields will be added as a separate search when you press <font SIZE="-1">OK</font> and all new entries will have the same options. Blanks at the beginning or end of lines are automatically removed and lines starting with # are skipped when loading from a file. </p>
<p> A history of the last 50 searches (manually entered ones only) including options, are stored and available in the drop-down menu below the search text entry field (opened with the arrow button at the left or one of the up/down cursor keys) and the last 10 searches are also available in the <i>Title</i> column header menu in the programme list (the latter in &#8220;single list&#8221; layout only). </p>
<p> Note: use of this search filter type is depreciated for permanent series searches saved in shortcuts if your provider supports series identifiers (see above). In this case should use those instead because the numerical identifiers have a better protection against transmission errors. A text search can fail due to a single erronous character.</p>
<dt><code>Features</code></p>
<dd> Restrict the listing to programmes that match all given attributes (logical <font SIZE="-1">AND</font>), i.e. sound format, picture format, analog/digital, encrypted yes/no, live/new/repeat and subtitles yes/no. </p>
<p> If you want to allow more than one value of the same attribute (e.g. picture format wide <font SIZE="-1">OR</font> Pal+) you have to put them into different feature classes (e.g. first select format wide, then set filter class to 2, then select format <font SIZE="-1">PAL+</font>)</p>
<dt><code>Parental Rating</code></p>
<dd> Restrict the listing to programmes that are suitable for children of the given age or elder, e.g. when you select 14, you get all programmes that are recommended for chilren of age 0 to 14. </p>
<p> Note you can use inverse searches (see below) to find programmes which are recommended only for children above a certain age. For example, if you invert a parental search with age 14, you&#8217;ll get all programmes that are recommended for children of age 16 or older.</p>
<dt><code>Editorial Rating</code></p>
<dd> Restrict the listing to programmes that are rated (by the content provider) to have at least the given quality. The range of rating values is 1 to 7. </p>
<p> Note that some providers do not use all values, e.g. only 1, 3, 5 (thumb down, middle, thumb up.) For that reason only the first provider&#8217;s ratings are used when merging databases (see also &#8220;<font SIZE="-1">MERGED</font> <font SIZE="-1">DATABASES</font>&#8221;)</p>
<dt><code>Start time</code></p>
<dd> Restrict the listing to programmes whose start time lies in the interval and whose start falls onto the given date or weekday. </p>
<p> Following options are available: If you enable <i>Start at current time</i> the interval start is fixed to the actual time when the filter is set and the value given as stop time is interpreted as duration, i.e. it&#8217;s added to the interval start. If you enable <i>Stop at end of day</i> the interval end is fixed to 23:59 of the same day. </p>
<p> For the date you can chose between the following modes: <i>Ignore date</i>: the filter allows programmes that start on any day (in the time window given above). <i>Relative date</i>: allow only programmes that start N days from today, i.e. for zero: today, for 1: tomorrow etc. <i>Weekday</i>: allow programmes starting at the given day of the week (the scale runs from Saturday until Friday.) <i>Day of month</i>: allow only programmes starting the Nth day of any month (the scale runs from 1 to 31.) </p>
<p> Note that the main intention of this filter is to support time restrictions in the provider&#8217;s navigation menus (see &#8220;<font SIZE="-1">NAVIGATE</font>&#8221;) or shortcuts. For manual navigation there are more practical alternatives, e.g. the weekday scale and drop-down menus in the main browser window above the time and date columns (not available in grid layout.)</p>
<dt><code>Program index</code></p>
<dd> Restrict the listing to programmes who&#8217;s index is in the given range. The currently running programme of each network is given index zero, the following programme of each network index one etc. The three most important combinations are available as radio buttons: <i>now</i> (range 0-0), <i>next</i> (range 1-1) and <i>now or next</i> (range 0-1). </p>
<p> For merged databases only indices 0 and 1 are supported.</p>
<dt><code>Duration</code></p>
<dd> Restrict the listing to programmes whose duration (i.e. difference between start and stop time) lies in the given range. When the maxium is set to zero, the filter is switched off. </p>
<p> You can specify the time values either by use of the scales or by entering a value in the format <font SIZE="-1">MM:HH</font> into the text fields and pressing the Return key.</p>
<dt><code>Expired Programmes Display</code></p>
<dd> Unlike all other filter options this one is used to <i>enlarge</i> the set of matching programmes. It allows to include expired programmes (i.e. those with a stop time in the past) into the list; they will be marked with a yellow background (you can change that color, see <tt>&quot;.Xdefaults&quot;</tt> and <tt>&quot;nxtvepg.ad&quot;</tt> in &#8220;<font SIZE="-1">FILES</font>&#8221;.) With the sliders you can set how many days plus hours to shift the expire time threshold. By default the threshold is zero so that expired programmes immediately disappear from the list. </p>
<p> Note you cannot add more programmes than are stored in the database; usually programmes are removed after 4 hours. There&#8217;s a second tab called <i>Configure</i> in the dialog which allows to change the delay after which expired programmes are automatically removed. Press the <i>Update</i> button to set the new value. If it&#8217;s lower than before, programmes will immediately be removed from the database; this operation cannot be undone (unless the progammes are still registered in the provider inventory, which may be the case if you haven&#8217;t updated the database in a long time. In this case you may get a confusing warning that programmes are about to be removed although they won&#8217;t.)</p>
<dt><code>Sorting Criteria</code></p>
<dd> Restrict the listing to programmes that have any of the given sorting criteria attached to them; every programme can have 0..7 sorting criteria attached to it. They work very much like theme descriptors however their meaning is not predefined by the Nextview standard. The content provider can use arbitrary numbers to represent an attribute. Attributes usually are themes that are not in the predefined catalog, e.g. current events like the Olympic Games, but could also be not content related at all. The meaning of these numbers is usually defined by the provider&#8217;s navigation menus (see &#8220;<font SIZE="-1">NAVIGATE</font>&#8221;). </p>
<p> Equivalently to themes, you can assign sorting criteria in different <i>classes</i> to implement a logical <font SIZE="-1">AND</font>, i.e. only programmes that have at least one of the sorting criteria specified in every used class will match. Example: to get all programmes that have 0x01 attached plus either 0x10 or 0x11, specify sorting criterion 0x01 in class #1 and 0x10 and 0x11 in class #2. Note that the dialog displays all values in hexadecimal format, i.e. with digits 0-9 followed by a-f. </p>
<p> The <i>Load all used</i> button in the sorting criteria filter dialog fills the selection listbox with a list of all codes that are actually used in the current database. This allows a quick overview which filter criteria will produce any matches.</p>
<dt><font SIZE="-1"><code>VPS/PDC</code></font></p>
<dd> Restrict the listing to programmes that have a valid <font SIZE="-1">VPS/PDC</font> start time label attached (<font SIZE="-1">VPS/PDC</font> allow to start a video recording at the exact time a programme starts even when delayed; the labels are broadcasted currently in Germany, Austria, Switzerland and England). Additionally you can filter for programmes with a label which differs from the actual start time; these are usually programmes whose start time changed or which were scheduled later (usually the <font SIZE="-1">VPS/PDC</font> label then is the actual start time minus one minute)</dl>
<p> Note that the interpretation of two filter types depends on the provider: sorting criterion and series. That&#8217;s because those are just arbitrary numbers which only have a meaning in the context of the provider&#8217;s navigation menu. </p>
<p> <i>Hint:</i> the filter menu can also be used to examine the filter options that are invoked by the entries in the Navigate menu.</p>
<h2>Inverting filters</h2>
<p> Near the end of the filter menu there&#8217;s the <i>Invert</i> sub-menu which allows to invert the outcome of filtering. There are two levels of inversion: global and individual. </p>
<p> When you select global inversion, you&#8217;ll get exactly the programmes that otherwise would have been filtered out (except for programmes which are permanently filtered out by your network and air-time selection). In other words, all programmes which match your current filter setting are removed from the list. Note: due to the way filter shortcuts are merged when more than one is selected at the same time, it&#8217;s in most cases not recommended to use global invert for filter shortcuts unless you change the combination rule (see &#8220;<font SIZE="-1">FILTER</font> <font SIZE="-1">SHORTCUTS:</font> Shortcut combination modes&#8221;.) </p>
<p> The invert menu also allows to individually negate certain filter types (there are also invert buttons in some filter sub-menus which have the same function). The logic of combining flters is the same as without inverting, i.e. there&#8217;s a logical <font SIZE="-1">OR</font> between filters of the same type (e.g. network A <font SIZE="-1">OR</font> network B) and a logical <font SIZE="-1">AND</font> between different filter types (e.g. network A <font SIZE="-1">AND</font> theme category movie). </p>
<p> <code>Example 1:</code> If you want all programmes which are neither categorized as sports nor as children&#8217;s programmes, select theme filters sport and children&#8217;s and then invert the current theme filter (usually class #1; you can equivalently use the global invert if themes are the only filter). </p>
<p> For the theme and sorting criterion filters it&#8217;s possible to invert only parts of the selection, so that you can require that a programme has a certain attribute and at the same time require that it doesn&#8217;t have another attribute. </p>
<p> <code>Example 2:</code> If you want all programmes which are movies but <font SIZE="-1">NOT</font> adult movies, select theme category Movie, switch the theme class to 2, select theme adult and then invert theme class 2. </p>
<p> Note: although the Feature filter offers the use of different classes so support a logical <font SIZE="-1">OR</font>, the inversion is not based on classes. This is due to the fact that there&#8217;s a logical <font SIZE="-1">OR</font> between feature classes (in contrast to the logical <font SIZE="-1">AND</font> between theme classes).</p>
<h2>FILTER SHORTCUTS</h2>
<p> There&#8217;s a number of predefined filter options in the main window below the clock. These shortcuts enable you to invoke filters by a single click of the mouse. You can freely add, change or remove entries in this list. </p>
<p> When you want to add a shortcut, first set the filters up in the way you want to save them, i.e. either choose existing shortcuts or select an entry from the Navigate menu and/or add filters from the main or context menus. When you have found an interesting selection, invoke <i>Add filter shortcut</i> from the shortcuts menu. </p>
<p> This will open the shortcut edit dialog (which will be described in detail below) with your new shortcut at the start of the list at the left. You should change the shortcut label in the field at the top right; by default it&#8217;s just &#8220;new shortcut&#8221;. The label will be displayed in the shortcut list in the main window. When you&#8217;re done press <i>Save</i>, or <i>Abort</i> if you&#8217;ve changed your mind and don&#8217;t want to add this shortcut after all. If you want to define multiple shortcuts you can leave the Edit dialog open and save just once when you&#8217;re done with all changes. </p>
<p> You can invoke several shortcuts in parallel by moving the mouse with the left button pressed or by pressing the <i></i><font SIZE="-1"><i>CTRL</i></font><i></i> or <i></i><font SIZE="-1"><i>SHIFT</i></font><i></i> keys when selecting in the main winddow&#8217;s shortcut listbox. See the chapter below for possible side-effects when combining shortcuts. </p>
<p> The shortcut list has a small context menu which shows when you click with the right mouse button into the shortcut list. If offers faster access to the same commands which are available in the main menu plus a <i>Delete</i> command; the shortcut above which you press the mouse button is pre-selected for the chosen operation. </p>
<p> When you <i>Update</i> a shortcut and your current filter setting contains different filters than the previously stored setting, you&#8217;ll be asked if the filter mask should be automatically adapted (e.g. if your filter previously searched for theme category &#8216;movie&#8217; but your current filter consists of a text search). See below for more details on filter masks; unless you have manually edited this shortcut&#8217;s mask before, you can safely press &#8220;Yes&#8221;.</p>
<h2>Editing Filter Shortcuts</h2>
<p> To change names and/or organisation of your shortcuts, open the edit dialog (e.g. via the main menu.) On the left of the dialog window there&#8217;s a list of all your shortcuts. In the middle there&#8217;s a row of command buttons which operate on the shortcut selected at the left (explained below). At the right there&#8217;s an editable field with shortcut name, a read-only display of the filter settings currently assigned to the shortcut, and popup menus to change the filter&#8217;s mask and combination rules (also explained in detail below.) </p>
<p> The buttons with up/down arrows will move the selected shortcut up or down. The buttons with arrows pointing to the upper left and lower right are used to move a shortcut entry out of or into a sub-folder respectively. </p>
<p> The <i>Delete</i> button removes the selected shortcut from the list (the deletion won&#8217;t affect the main window until you press <i>Save</i>, so you can leave the dialog with <i>Abort</i> to undo the operation.) </p>
<p> The <i>Invoke</i> button will apply the shortcut&#8217;s filter setting to the main window just as selecting the shortcut in the main window&#8217;s list. You can then change the filter settings via the filter menus. Use the <i>Update</i> button to assign the main window&#8217;s filter settings to the edited shortcut. </p>
<p> You should be careful with the update button since it&#8217;s easy to overwrite the wrong shortcut. If you notice such a mistake, you can undo the change either by leaving the edit dialog with the <i>Abort</i> button or selecting the respecting shortcut in the main window and assigning the original settings via <i>Update</i>.</p>
<h2>Filter Masks</h2>
<p> When you deselect a shortcut, either by selecting another shortcut or clicking on it a second time with <i></i><font SIZE="-1"><i>CTRL</i></font><i></i> held down, all it&#8217;s filters will automatically be undone. Hence when you have two themes shortcuts, e.g. &#8220;Movies&#8221; and &#8220;Sports&#8221;, and select first Movies, then Sports, you&#8217;ll see only sports programmes afterwards. However if you had selected theme movies manually, e.g. by the context menu explained in the next chapter, the movies filter might remain set, so that you&#8217;d get all programmes of theme movies <font SIZE="-1">OR</font> sports. Since that is usually not what one expects, a filter mask has been introduced to the shortcut setting. </p>
<p> The filter mask is defined in the shortcuts dialog with a checkbutton for each filter category. By default, the mask is enabled for every filter category you&#8217;ve included in the shortcut filter setting. When you invoke the shortcut from the main window later, all filters of the given categories will be cleared (masked out) before the shortcut filters are added. To return to the above example: if the &#8220;Sports&#8221; shortcut is defined with a themes mask, the manually set movies filter would be cleared before the theme filter is set to sports. </p>
<p> The masking can also be enabled when no filter of that category has been chosen. This can be used to define <i>undo</i> shortcuts. E.g. choose the mask &#8216;Themes&#8217; if you want a shortcut that allows to clear all theme-related filters at once. Or enabled all masks for a <i>Reset</i> button (the only difference to the pre-defined Reset button would be that the cursor does not jump to the first Now programme.)</p>
<h2>Shortcut combination modes</h2>
<p> By default when combining multiple shortcuts, all filters of all selected shortcuts are simply thrown together (i.e. &#8220;merged&#8221;) and then processed as if they belonged all to one shortcut. The same combination rules apply as described in &#8220;<font SIZE="-1">FILTERING</font>&#8221;. </p>
<p> For example, if one shortcut searches for movies, another one subtitles, the combination will search for programmes which are movies <font SIZE="-1"><code>AND</code></font> have subtitles. Also, if you have one shortcut which filters for movies and one that filters for your favorite series, the combination will filter for all programmes which are either movies <font SIZE="-1"><code>OR</code></font> among your favorite series. </p>
<p> For such simple shortcuts which consist of a single filter type this behavior is usually intuitive. When combining complex filters the result of merging however might not match your expecations. For example, if you have a shortcut &#8220;movies on network A&#8221; and one &#8220;series on network B&#8221; merging would result in &#8220;either movies or series on either network A or B&#8221;, i.e. the list would also include movies on network B. </p>
<p> Hence the shortcut edit dialog has a <i>Combination rule</i> option where you can change the mode into <i></i><font SIZE="-1"><i>OR</i></font><i></i> or <i></i><font SIZE="-1"><i>AND</i></font><i></i>. If you put a shortcut into this mode, it&#8217;s filters will be handled separately from all others. </p>
<p> The only drawback is that the shortcut&#8217;s filters will not be editable via the filter menus. If you ever want to change the filter settings without creating them from scratch, use the <i>Invoke</i> and <i>Update</i> buttons in the edit dialog (see &#8220;<font SIZE="-1">FILTER</font> <font SIZE="-1">SHORTCUTS:</font> Editing Filter Shortcuts&#8221;.)</p>
<h2>Shortcut update dialog</h2>
<p> When you select the <i>Shortcut Update</i> command in the main menu, there will be a small dialog with a list of all shortcuts. The filter settings of the shortcut you select in this list will be overwritten with the currently active filter setting once you press the <i>Update</i> button. You can also use the <i>Update &amp; Edit</i> button to jump directly into the filter edit dialog (see further above in this chapter) </p>
<p> Note that while the shortcut edit dialog window is open, updates (as well as deletions or additions) will only affect the temporary list in the edit dialog window until you press the it&#8217;s <i>Save</i> button. Also the list offered for shortcut updates consists of the shortcuts as they are defined in the temporary list. This allows to test your changes before you commit them. </p>
<p> Note that a faster way to change a single shortcut is to use the context menu, since it allows to skip this intermediate dialog.</p>
<h2>COMPOSITE ATTRIBUTES</h2>
<p> By default the <font SIZE="-1">TV</font> schedule contains for each programme &#8220;basic&#8221; attributes like its date, starting time, title, <font SIZE="-1">TV</font> network in a pre-defined textual format. By using composite attributes you can customize the <font SIZE="-1">TV</font> schedule according to your personal preferences. For example you could (1) alter the display format of pre-defined attributes (e.g. use colors for highlighting), (2) add new attributes, for example with images as markers for favorite programmes and/or (3) compact display by combining several attributes into one. </p>
<p> Composite attributes replace single attributes in the display (e.g. only the theme category column.) Newly created composite attributes will be appended to the list of pre-defined attributes. You can then configure your programme list as a mixture of pre-defined and composite attributes (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Select attributes&#8221;) </p>
<p> Composite attributes are created and edited via the <i>Attribute composition</i> dialog in the <i>Configure</i> menu (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Attribute composition&#8221;) </p>
<p> The &#8220;heart&#8221; of attribute composition is a list of filter shortcuts and reminder groups, which you build as a subset of your personal filter shortcuts and/or reminder groups (see also &#8220;<font SIZE="-1">FILTER</font> <font SIZE="-1">SHORTCUTS</font>&#8221; and &#8220;<font SIZE="-1">REMINDERS</font>&#8221;.) </p>
<p> Whenever nxtvepg displays a composite attribute in the browser, it matches the programme&#8217;s actual attributes (e.g. theme categories or assigned reminders) against the shortcuts and reminder groups associated which the respective composite attribute, in the given order (top to bottom in the dialog&#8217;s list &#8211; so order is important). If a match is found, the text, image or attribute which was assigned to that specific shortcut match is displayed in the column with the format specified for this match. If none match (and there&#8217;s no <i>*no match*</i> entry, see below), nothing is displayed in place of the composite attribute. </p>
<p> Note in this context <i>matching</i> means that a shortcut&#8217;s filters are tried against the <font SIZE="-1">TV</font> programme, i.e. a programme &#8220;matches&#8221; a filter when it would remain displayed when you enable that filter shortcut in the main window. A reminder group is considered matching when the respective <font SIZE="-1">TV</font> show is programmed as a reminder in that group (or matches a shortcut which is assigned to the given reminder group &#8211; but let&#8217;s ignore that for now to avoid confusion.) </p>
<p> Example: to create a personalized version of the <i>Editorial rating</i> (<font SIZE="-1">ER</font>) column, you could create three shortcuts: one with the <font SIZE="-1">ER</font> filter set to &#8220;&gt;=6&#8221;, one with &#8220;&gt;=4&#8221; and one with &#8220;&gt;=2&#8221;; then you&#8217;d create a new user-defined column and insert the three shortcuts in this order; to the first shortcut match you&#8217;d assign the text &#8220;great&#8221;, to the second &#8220;ok&#8221; and to the third &#8220;bad&#8221;. As a result you&#8217;d have a column where the numerical ratings are replaced with your texts. </p>
<p> There is also a special entry at the end of the dialog&#8217;s shortcut list called <i>*no match*</i>. It acts as a catch-all (i.e. wildcard) if none of the shortcuts in the column matches the current programme entry. In the above example this would be all programmes with an <font SIZE="-1">ER</font> below 2 or without a rating. </p>
<p> The catch-all is particularily useful to overlay standard columns with alternate texts for selected programmes. To stay with the <font SIZE="-1">ER</font> example, you could define a column with two shortcut entries: &#8220;&gt;=6&#8221; and &#8220;*no-match*&#8221;. To the &#8220;&gt;=6&#8221; shortcut match you could assign an image marker; to all other the &#8220;<font SIZE="-1">ER</font>&#8221; attribute. Hence programmes with an <font SIZE="-1">ER</font> &gt;=6 (i.e. all &#8220;great&#8221; programmes) would have an image displayed and hence clearly stand out from all other programmes, which get the regular content of the <font SIZE="-1">ER</font> column (i.e. the numerical rating or an empty column for unrated programmes). </p>
<p> You can also use this machanism to combine several columns into one, to keep the listing compact. For example you can combine the <font SIZE="-1">ER</font> column with the theme column, so that for movies with <font SIZE="-1">ER</font> &gt;= 6 the text &#8220;great movie&#8221; is displayed, for all others the regular theme description.</p>
<h2>REMINDERS</h2>
<p> Reminders allow to mark <font SIZE="-1">TV</font> shows which interest you and have nxtvepg mark them in the programme list and display a message or execute an external command when they start. You can select either individual programmes in the programme list or complete filter shortcuts, e.g. for <font SIZE="-1">TV</font> series. </p>
<p> To set a new reminder simply select it with the cursor in the programme list and choose <i>Add reminder for selected title</i> from the <i>Reminder</i> menu. The same command is also available in the context menu, i.e. by clicking on the selected title with the right mouse button. To remove the reminder, simply select the title again and choose <i>Remove reminder for selected title</i>. </p>
<p> By default nxtvepg will display a message popup for every reminded programmme 5 minutes before and directly at the start time. You can change this in the <i>Configure reminder groups&#8230;</i> dialog described in a separate chapter below. </p>
<p> If you want to set a reminder for an entire series, you need to create a filter shortcut first which matches the series (either by searching by series <font SIZE="-1">ID</font> or by title). To reduce the overhead you can create a shortcut which matches all your favorite series and set a reminder for this collection. To assign a reminder to the shortcut use the <i>Edit reminder list</i> described in the next chapter. </p>
<p> Note you can add a single reminder for entries which already match a shortcut reminders. This allows to assign an additional, specific action for that <font SIZE="-1">TV</font> show (if you use different groups.) Additionally you can suppress handling of reminders for individual shows; this option if offered in the Reminder and context menus when applicable. This option may help to get around excessively complex or restrictive shortcut filters. </p>
<p> By default nxtvepg has (in the single list layout) a column titled <i>Mark</i> which contains a red dot for all programmes which have a reminder registered, i.e. both single programmes and those which match shortcuts with associated reminders. You can also set a filter which will display only programmes with reminders in the proramme list by selecting <i>Show reminder matches</i> from the Reminder menu.</p>
<h2>Edit reminder list</h2>
<p> Opens a list of all reminders. Single programmes and shortcuts are listed in separate &#8220;tabs&#8221;; switch between them by clicking on the buttons at the top. </p>
<p> The <code>single programmes</code> list is sorted by start time and network. When you double-click on a reminder, the respective network will be filtered for in the programme list and the cursor jumps onto the programme (if it&#8217;s present in the current database.) To delete a reminder click on the <i>Delete</i> button or press the delete key on your keyboard. You can also select the reminder&#8217;s &#8220;group&#8221; (see below) either by selecting a group in the popup menu from the <i>Set group</i> menubutton or by clicking with the right mousebutton into the group column. </p>
<p> The list will normally not contain reminders for programmes which are already expired. You can use the <i>Display</i> popup menu at the right to change that. You can also include &#8220;suppressed&#8221; reminders, i.e. entries which where created via the respective entry in the main menu to supress shortcut matches; those will appear with the virtual <i>suppress</i> group in the list. </p>
<p> When you switch to the <code>Shortcuts</code> tab, you&#8217;ll see a list of all shortcuts for which you have added reminders. The first time you open the dialog it will be empty. You can add shortcuts by selecting them from the popup menu at the right. Equivalently to single programmes you can change the group or delete the reminders again. All changes to the lists are immediately saved and the markers in the programme list updated. </p>
<p> All changes you make in this dialog take effect immediately.</p>
<h2>Reminder group configuration</h2>
<p> Opens a configuration dialog for reminder groups. Every reminder is assigned to exactly one group which determines which actions are executed at the programmes&#8217; start time. Having groups allows to change actions (and especially: disable them if you&#8217;re not in the mood to watch <font SIZE="-1">TV</font>) easily without having to edit every single reminder. When you create a new reminder with the simple &#8220;add reminder&#8221; menu command it will be assigned to group zero. </p>
<p> By default nxtvepg has only one group which pops up a message 5 minutes before and directly at the start time. You can change this by selecting the group in the list at the left and then modifying the parameters at the right. Or create a new reminder by clicking <i>New</i>. You can also change ordering of groups (only available for your convenience; except for group zero ordering is not relevant.) The <i>Show</i> buttons sets a filter for the programme list so that only programmes matching reminders in the same group as the currently selected shortcut are displayed. </p>
<p> At the top of the parameter input section is the <i>Label</i> entry field. It allows to give the group a name, which is then used in the reminder lists and in reminder confirmation messages. Below is a checkbutton called <i>Temporarily disable all group events</i>. While enabled all actions for that group are suppressed, i.e. you&#8217;ll get no popup messages and scripts are not executed. Note this setting only applies to the current session and is reset when nxtvepg is restarted (you should clear the action lists if you want to disable reminder messages permanently.) The programmes are still marked in the listbox though. </p>
<p> Further below is an entry field where you can give a list of comma separated values which define at which offsets reminder messages are displayed; offsets are substracted from the start time, i.e. when you enter &#8220;5&#8221; a message will appear 5 minutes before the programme&#8217;s nominal start time. You can use negative values (e.g. &#8220;-5&#8221;) if you want reminders to appear later than the start time. In addition you can set start times for commands. Commands are silently executed in the background, unless you enable <i>Ask before executing script</i>. </p>
<p> Note configuration changes (including group additions or deletions) are not applied before you leave the dialog with <font SIZE="-1">OK</font>.</p>
<h2>Reminder Messages</h2>
<p> Once the nominal start time of a &#8220;reminded&#8221; programme (minus the configured time offset) is reached, a message window will appear. If there&#8217;s more than one message triggered at the same time, or if you leave the window open and reminders for additional programmes are triggered, they will all be collected in this window; in this case there&#8217;s a cursor which determines to which reminders the controls explained below apply. When you press <i>Ok</i> all messages are marked as &#8220;done&#8221; and will not appear again. With a double-click or the <i>Tune-TV</i> button you can switch the channel of a connected <font SIZE="-1">TV</font> application to the selected programme, just as in the main programme list. </p>
<p> For message windows there&#8217;s several buttons which allow to control further reminder processing. <i>Suppress</i> will prevent any subsequent messages for the programme. (Note that this is not the same as suppressing reminders in the main menu, since here you supress only messages but the programme remains marked as reminder). <i>Repeat</i> allows to schedule additional reminder messages at arbitrary time offsets. Note that messages configured for the group are suppressed until the manual repetition but will re-appear afterwards.</p>
<h2>CONTEXT MENU</h2>
<p> A quick way to select and deselect filters is by using the context menu, which opens when clicking with the right mouse button onto a programme entry in the main browser window. </p>
<p> This menu consists of several parts, separated by horizontal lines, which depend on the currently selected programme and hence are not always present.</p>
<dl>
<dt><code>Undo currently selected filters</code></p>
<dd> The first section holds entries which allow disable currently selected filters either one by one or globally (reset). See also &#8220;<font SIZE="-1">FILTERING:</font> Filter Types&#8221;</p>
<dt><code>Add new filters</code></p>
<dd> The second section offers a number of possible new filter options, which depend on the currently selected title and the already selected filters. The offered filter types include: themes and network of the selected programme title, it&#8217;s series code, repeat or original transmission suppression (only in cunjunction with series or title text filters) and last but not least the title text. </p>
<p> The title text and series filters allow to check very quickly for repeats of a programme. These filter options are included only if there is a match, i.e. if there&#8217;s another programme with the same title or series code respectively.</p>
<dt><code>Add reminder</code></p>
<dd> This menu entry will add a reminder for the currently selected programme. The reminder will have the default reminder group. To create reminders in different groups use <i>Add reminder into group</i> in the reminder main menu (see also &#8220;<font SIZE="-1">REMINDERS</font>&#8221;)</p>
<dt><code>User-defined entries</code></p>
<dd> The optional fourth section is empty by default, but can be used to invoke user-defined external commands on the selected programme. More precisely, you can execute any command with properties of the selected programme (like title or start time) on its command line. The user commands can be added via the Configure menu (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Context menu configuration&#8221;).</dl>
<h2>CONTROL</h2>
<p> Summary of commands available from the Control menu:</p>
<h2>Enable acquisition</h2>
<p> Toggles acquisition on or off. When you start the browser, acquisition is automatically enabled (although failure to do so is silently ignored). You can suppress automatic start with the <code>-noacq</code> command line switch. Switching off acquisition allows other applications (e.g. a teletext decoder) to use the <font SIZE="-1">TV</font> card while you browse the database, if you have only one <font SIZE="-1">TV</font> card. </p>
<p> You will get an error message if the device is already busy by a different application (there are some applications which cooperate well with nxtvepg, but if in doubt you should quit all other video related applications before starting acquisition) or if you don&#8217;t have permission to access the device (<font SIZE="-1">UNIX</font>, see also &#8220;<font SIZE="-1">FILES</font>&#8221;) or to start the driver (Windows). If you&#8217;re experiencing problems that might be hardware or Operating System related, test with a <font SIZE="-1">TV</font> application or teletext decoder first, because these usually allow for easier debugging (e.g. due to the visible <font SIZE="-1">TV</font> image). See also &#8220;<font SIZE="-1">GETTING</font> <font SIZE="-1">STARTED</font>&#8221;. </p>
<p> <font SIZE="-1">UNIX:</font> When acquisition is switched off, the <i>/dev/vbi</i> device is freed. Acquisition can also been switched on and off automatically (i.e. from a shell script) by sending signal <font SIZE="-1">HUP</font> (e.g. with the <i><a href="/docs/linux/man/1-kill/">kill</a></i>(1) command) to any of the nxtvepg processes or threads. If you&#8217;re using a daemon for acquisition (see the next command) you have to send the signal to one of the daemon processes/threads. To simplify this, the pid of the process which needs to be signalled is stored in <i>/tmp/.vbi.pid</i> while the device is in use.</p>
<h2>Connect to acq. daemon</h2>
<p> Connect to or disconnect from an acquisition daemon, running in the background on the same host, or somewhere else in the network. The address of the daemon and other parameters are configured in the <i>Client/Server</i> menu (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Client/Server&#8221;). By default the daemon is started on the local host. The main advantage of using the daemon is that you can keep running acquisition permanently in the background, even if you terminate the browser, or on <font SIZE="-1">UNIX</font> even the X11 server (i.e. the windowing system). On M$ Windows the daemon is terminated when you log off. </p>
<p> If you attempt to connect, but no daemon is running, you&#8217;ll be offered the option to automatically start the daemon and retry the connect, provided you have configured server hostname <i>localhost</i>. The daemon will be started with the same database directory and rcfile as the browser. </p>
<p> Note that disconnecting from the daemon or terminating the browser does not stop the acquisition and hence does not free the device. If that&#8217;s what you want, choose the <i>Enable acquisition</i> command instead, which terminates the daemon. Of course this option only is available if your daemon is running on the same host and with the same user id as the browser process.</p>
<h2>Dump stream</h2>
<p> <font SIZE="-1">UNIX</font> only: The contents of all incoming Nextview blocks are dumped to <i>stdout</i> in a free text format. This is mainly intended for developers, but it may also help to debug reception problems, because in the dump you&#8217;ll find any block that could be decoded without hamming errors, even before an inventory block (<font SIZE="-1">AI</font>) has been received. This may help if you have very bad reception, because it may take a long time until a error-free copy of the usually large <font SIZE="-1">AI</font> block is received. </p>
<p> When connected to a acquisition daemon, blocks are only dumped if they are new to the database or their content changed (because only those are forwarded by the daemon to the client.)</p>
<h2>Dump raw database</h2>
<p> Open a dialog that allows to dump all blocks in the database to <i>stdout</i> (<font SIZE="-1">UNIX</font> only) or into the named file in a raw text format, which is actually the same as with the <i>Dump stream</i> command. This feature is mainly intended for developers. To understand all the infos in the text dump, you&#8217;ll have to look at the source in <i>epgui/epgtxtdump.c</i> in the nxtvepg source package. </p>
<p> The array of checkbuttons allows to control which kind of blocks will be written. The programme information blocks (<font SIZE="-1">PI</font>) do contain the actual programme descriptions; <i>Defective </i><font SIZE="-1"><i>PI</i></font><i></i> contains those <font SIZE="-1">PI</font> which were not accepted into the database because of inconsistencies like a zero or overlapping running time. For an explanation of the other block types please see the <font SIZE="-1">ETSI</font> specification 707. </p>
<p> You can also export the database in this format via the command line by using option <tt>&quot;-dump raw&quot;</tt>. In this case the options last used in the dialog are effective. </p>
<p> Note that the data can also be exported directly from the command line by using <code>-dump raw</code> (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;)</p>
<h2>Export as text</h2>
<p> Open a dialog that allows to export the complete database into a text file. Each line in the file will represent one item in the database. The item&#8217;s different fields are separated by <font SIZE="-1">TAB</font> characters; the line is terminated by a single new-line character (no line feed character, even on Windows). <h2>Export as <font SIZE="-1">XMLTV</font></h2>
<p> Open a dialog that allows to export the complete database in <font SIZE="-1">XML</font> format, as defined by the <code>xmltv.dtd</code> version 0.5 (see &lt;<a rel="nofollow" href="http://xmltv.org/">http://xmltv.org/</a>&gt;) The generated file contains both the channel table and the complete <font SIZE="-1">TV</font> schedule, including any networks you might have suppressed from the listing inside nxtvepg. </p>
<p> <code>Hint:</code> If you want to restrict the amount of exported data, configure a merged database. This is possible even for a single provider. This way you can exclude certain networks or attributes, e.g. to omit theme categories from the output (see the &#8220;Configure&#8221; sub-menu in the merge configuration dialog.) </p>
<p> Some <font SIZE="-1">TV</font> applcations are known to not parse <font SIZE="-1">XMLTV</font> timestamps correctly. As a work-around for such buggy applications, there&#8217;s an option which allows to export dates and times in local time instead of <font SIZE="-1">UTC</font> (also known as <i>Greenwhich Mean Time</i> or <font SIZE="-1">GMT</font>.) If all programme data appears shifted by one or two hours in your <font SIZE="-1">TV</font> app&#8217;s schedule, try this option. </p>
<p> Note that the database can also be exported directly from the command line by using the <code>-dump xml</code> switch (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;).</p>
<h2>Export as <font SIZE="-1">HTML</font></h2>
<p> Opens a dialog that allows to export the complete database or selected programmes into a file in <font SIZE="-1">HTML</font> format (Hypertext Markup Language) which can then be loaded into a <font SIZE="-1">WWW</font> browser, e.g. <i>Netscape</i> or <i>Opera</i>. This is particularily useful if you want to print out <font SIZE="-1">TV</font> descriptions. </p>
<p> At the top of the dialog window you have to enter the output file name; if you don&#8217;t include an extension, <i>.html</i> is automatically appended. Click on the little folder button to the right for a file selection dialog. Press the <i>Export</i> button to create the <font SIZE="-1">HTML</font> document and <i>Dismiss</i> to close the dialog window. </p>
<p> By default the checkbutton <i>All matching programmes, but max &#8230;</i> is enabled. In this mode all programmes that match current filter setting will be exported, but only up the given number of programmes. It&#8217;s recommended to limit the number of programmes because else very large <font SIZE="-1">HTML</font> documents are created which may take a long time to load into your Web browser. </p>
<p> Use mode <i>Selected programme only</i> to export only the programme which is currently selected in the main window. In combination with the <i>Append to file</i> mode this allows to incrementally build a document with exactly your programmes of interest. </p>
<p> In the box below there are three radio buttons with which you can select the output format. If you choose <i>Write titles</i> you&#8217;ll get a table in the same configuration as in the programme title list in the main window. If you want to have different column types, you can build a separate column configuration by selection <i>Different columns than main window</i> and then pressing the <i>Configure</i> button to select which column types to display. </p>
<p> If you select <i>Write descriptions</i> you&#8217;ll get for each exported programme a feature summary and description, similiar to the info in the lower part of the main window. </p>
<p> If you select <i>Write titles and descriptions</i> you&#8217;ll get the title table on top and all descriptions separately below. In this mode you can select <i>Add hyperlinks to titles</i> to add hyperlinks from titles in the table to the descriptions. </p>
<p> The look of the generated document is almost entirely determined by use of an internal <font SIZE="-1">CSS</font> stylesheet. If you don&#8217;t like the look you can override it with your own stylesheet. Save it to a file named <i>nxtvhtml.css</i> and put it in the same directory as the generated <font SIZE="-1">HTML</font> file. For more information on <font SIZE="-1">HTML</font> and style sheets see &lt;<a rel="nofollow" href="http://www.w3.org/">http://www.w3.org/</a>&gt;. If your column configuration contains images (see &#8220;<font SIZE="-1">COMPOSITE</font> <font SIZE="-1">ATTRIBUTES</font>&#8221;), you have to put them into a subdirectory called <i>images</i>; also your browser has to support the <font SIZE="-1"><code>PNG</code></font> image format.</p>

<h2>Teletext grabber</h2>
<p> <code>Note</code> this is still an experimental feature. Support is still limited to German networks and configuration options are limited. </p>
<p> Open a dialog which allows to enable and configure the teletext <font SIZE="-1">EPG</font> grabber. The grabber works by cyclically tuning all <font SIZE="-1">TV</font> channels, loading the <font SIZE="-1">TV</font> overview teletext pages (e.g. 301-309 in Germany) and building a small database from them. For titles which contain references to other teletext pages, the grabber loads these pages too and extracts descriptions from them. Finally the grabber&#8217;s output is written into separate files in <font SIZE="-1">XMLTV</font> format. </p>
<p> The main intention of the grabber is to improve on the data provided by Nextview <font SIZE="-1">EPG</font>. The main disadvantage of teletext compared to Nextview is the long time it takes to grab teletext. The cause for the long duration is that most <font SIZE="-1">TV</font> networks use sub-pages in their TV-schedules, so that it takes several cycles until all parts of a given page are loaded, usually at least 90 seconds. Assuming only 30 <font SIZE="-1">TV</font> networks, the total load time is already 45 minutes. Another difficulty encountered by the teletext grabber is the lack of a standardized format for the schedules. Hence the data extraction cannot always work correctly. In particular the capabilities to extract theme categories and additional attributes are very limited. But these disadvantages can be compensated by merging teletext <font SIZE="-1">EPG</font> with a Nextview <font SIZE="-1">EPG</font> database (see &#8220;<font SIZE="-1">MERGED</font> <font SIZE="-1">DATABASES</font>&#8221;) </p>
<p> To be able to use the grabber, you have to install a programm called &#8220;Perl&#8221; on your <font SIZE="-1">PC</font>. Perl is included within virtually every <font SIZE="-1">UNIX</font> and Linux installation, so you probably already have it if you use one of these operating systems. If not, you&#8217;ll probably find it in section &#8220;programming languages&#8221; on your distribution&#8217;s <font SIZE="-1">CD</font> or <font SIZE="-1">DVD</font>. M$-Windows users have to download and install Perl manually (from &lt;<a rel="nofollow" href="http://www.activestate.com/Products/ActivePerl/?mp=1">http://www.activestate.com/Products/ActivePerl/?mp=1</a>&gt; or &lt;<a rel="nofollow" href="http://www.cygwin.com/">http://www.cygwin.com/</a>&gt;) and then specify the path to perl in the configuration dialog. (Alternatively you can extend your <tt>&quot;PATH&quot;</tt> environment variable so that perl.exe is automatically found.) </p>
<p> By the default, the grabber is disabled since it&#8217;s still experimental. To enable it, check the box at the top of the configuration dialog. If you haven&#8217;t configured a <font SIZE="-1">TV</font> application yet you&#8217;ll get an error message, since the grabber requires a <font SIZE="-1">TV</font> channel table. The grabber will retrieve <font SIZE="-1">EPG</font> data starting with the first channel listed in the <font SIZE="-1">TV</font> app&#8217;s channel table, and then switch through one-by-one. Currently you cannot change the order or skip any programmes, but you can limit the number of channels in the configuration dialog. </p>
<p> Note: When acquisition mode &#8220;Cyclic: Now &#8211; All&#8221; is selected (see &#8220;<font SIZE="-1">ACQUISITION</font> <font SIZE="-1">MODES</font>&#8221;) the grabber uses an optimized strategy during the &#8220;Now&#8221; stage in which waiting times are minimized by changing the order in which <font SIZE="-1">EPG</font> data is read. This way the grabber requires about 15-20 seconds per channel in average. In the &#8220;Full&#8221; stage the grabber waits for the time given after <i>capture duration</i> in the configuration dialog; by default that&#8217;s 90 seconds (such a large value is required because programme descriptions are often transmitted on so-called &#8220;sub-pages&#8221; which are not included in every teletext cycle.) </p>
<p> To use the grabbed data you have to wait until each channel has been visited at least once. After that you should see an <font SIZE="-1">XML</font> file for each <font SIZE="-1">TV</font> channel in the nxtvepg directory (named &#8220;ttx-XXX.xml&#8221; where <font SIZE="-1">XXX</font> is the <font SIZE="-1">TV</font> channel name.) These files will appear in the provider selection and merge dialogs and can then be used just like Nextview <font SIZE="-1">EPG</font> providers.</p>
<h2>Provider scan</h2>
<p> Open a dialog that allows to start a scan across all <font SIZE="-1">TV</font> channels for Nextview transmissions. You should perform this search at least once, firstly to find out which providers are available in your area, and secondly to determine the <font SIZE="-1">TV</font> frequencies of all <font SIZE="-1">EPG</font> providers. Those are required for most acquisition modes, and due to driver limitations often not available without a scan (e.g. on Windows or Linux with bttv driver &lt;= 0.7.50). Note that the provider scan only works if you use the internal tuner as input source. See also &#8220;<font SIZE="-1">GETTING</font> <font SIZE="-1">STARTED</font>&#8221; and the subsequent chapter on <font SIZE="-1">TV</font> card configuration. </p>
<p> If you live in France, select the French frequency table (which implies the <i>Secam L</i> <font SIZE="-1">TV</font> norm) to be used for the <font SIZE="-1">EPG</font> scan; else use the default frequency table which covers common cable network frequencies in Western Europe with the <font SIZE="-1">PAL</font> <font SIZE="-1">TV</font> norm. Other countries are not supported, since there currently are no Nextview providers. If you live in an area where you receive both <font SIZE="-1">PAL</font> and <font SIZE="-1">SECAM</font> stations, you should perform the <font SIZE="-1">EPG</font> scan twice with different channel tables. </p>
<p> The <i>Use </i><font SIZE="-1"><i>TV</i></font><i> app.</i> button is automatically checked if an <i>xawtv</i> configuration file is found in your home directory (on <font SIZE="-1">UNIX</font>) or a <font SIZE="-1">TV</font> application was set up in the <i></i><font SIZE="-1"><i>TV</i></font><i> app. interaction</i> dialog. Instead of searching all possible <font SIZE="-1">TV</font> channels or frequencies in all bands, nxtvepg then just checks the <font SIZE="-1">TV</font> channels defined there, which usually saves a lot of time and is also more reliable. </p>
<p> Check the <i>Slow</i> button if you have bad reception on some channels. In slow mode the scanner will not skip channels with &#8220;unstable&#8221; video signal (i.e. no <font SIZE="-1">PLL</font> H-lock within 0.150 seconds) and wait twice as long as normal for everything, i.e. up to 4 seconds for a <font SIZE="-1">VPS/PDC</font> channel identification and up to 90 seconds if potential <font SIZE="-1">EPG</font> data packets were found. Note that you can change this setting while the scan is running. </p>
<p> Use the <i>Refresh only</i> mode if you deleted your database files (or if you upgrade from an incompatible software version) or if you want to identify or remove obsolete providers. In this mode only the channels on which Nextview data was received before are checked (the frequencies are kept both in the databases and your rc/ini file). This allows to regain your complete provider selection very quickly. If no data transmission is found on a provider&#8217;s channel, a <i>Remove this provider</i> button will be added to the output window, which you can use after the scan has finished to remove the database and any information recorded about the provider. Note that removal will fail if the database is currently in use, so you may have to stop acquisition and select a different provider. </p>
<p> Technical background information on how the <font SIZE="-1">EPG</font> scan works: The scan will visit every physical <font SIZE="-1">TV</font> frequency (or subsets thereof if you use one of the options described above) and check for a <font SIZE="-1">TV</font> signal. If one is detected within 150 ms or if at least one teletext packet was received, the scan waits up to two seconds for a valid <font SIZE="-1">VPS/PDC</font> channel identification. At the same time it receives packets from all potential <font SIZE="-1">EPG</font> teletext page addresses. If valid data packets have been received (which does not necessarily mean it&#8217;s <font SIZE="-1">EPG</font>, because other services could use the same encoding) the scan waits up to 45 seconds for <font SIZE="-1">EPG</font> inventory messages (<font SIZE="-1">BI</font> and <font SIZE="-1">AI</font> blocks). You can watch these proceedings in the message output window. </p>
<p> Even though the scan tries very hard, it can not warrent that every <font SIZE="-1">EPG</font> provider is found every time. For example some providers do have pauses of more than 45 seconds in their <font SIZE="-1">EPG</font> transmission; or they might have technical problems. So the safest way is to check the nxtvepg web site (see <i>About</i> in the Help menu) for a list of known Nextview <font SIZE="-1">EPG</font> providers. If you receive <font SIZE="-1">TV</font> channels for which a provider is listed, repeat the scan until they are found, e.g. at different times of the day. If you find new providers not listed on the web site, please write a note in the discussion forum on the web site.</p>
<h2><font SIZE="-1">TV</font> card input</h2>
<p> Open a dialog where the <font SIZE="-1">TV</font> card hardware parameters can be configured. </p>
<p> This dialog contains more options on Windows than on <font SIZE="-1">UNIX</font> platforms because on <font SIZE="-1">UNIX</font> the driver is part of the operating system, whereas on Windows it&#8217;s part of the application and has to be configured separately for every application. Hence, before you can use nxtvepg you must firstly decide between using the internal &#8220;dsdrv&#8221; driver and the card vendor&#8217;s <font SIZE="-1">WDM</font> driver; secondly, if using &#8220;dsdrv&#8221;, you need to configure the driver for your hardware in the <i>Configure card</i> sub-dialog. Please refer to &#8220;<font SIZE="-1">GETTING</font> <font SIZE="-1">STARTED</font>&#8221; for a detailed description of these steop. </p>
<p> <i>Video source</i> allows to choose which video input source to use, i.e. where you have connected an video input cable to the <font SIZE="-1">TV</font> card: <i>Tuner</i> or <i>Television</i> refer to input via antenna cable (also known as <font SIZE="-1">RF</font> cable, i.e. terrestrial reception or cable <font SIZE="-1">TV</font>); <i>Composite</i> refers to a cinch video cable as used by satellite receivers or cheap video records; <i>S-Video</i> is an variant of Composite with improved image quality (often wrongly called S-VHS cable since it&#8217;s mostly used by S-VHS video recorders) and easily recognized by the Sub-D connectors (called &#8220;Hosidenstecker&#8221; in German). Depending o your hardware you may only see a sub-set of these input types, or additional ones (e.g. <i>Radio</i>, which will obviously not work as input for nxtvepg.) </p>
<p> Note if you don&#8217;t choose a <font SIZE="-1">TV</font> tuner as input nxtvepg will not be able to automatically switch to your <font SIZE="-1">EPG</font> provider&#8217;s channel. See also &#8220;<font SIZE="-1">DATA</font> <font SIZE="-1">ACQUISITION</font>&#8221;. </p>
<p> If you have more than one <font SIZE="-1">TV</font> tuner card, you can also choose which one to use, just like with the <code>-card</code> command line option (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;) The popup menu will list all card types as configured in the driver. Note that changing the card may also affect the input selection, in particular if the cards use a different ordering for input types. </p>
<p> The slicer quality option selects between different algorithms by which teletext is extracted from the analog video signal. The <i>simple</i> algorithm works only for excellent <font SIZE="-1">TV</font> reception, but has the advantage of using very little <font SIZE="-1">CPU</font> resources. The <i>elaborate</i> algorithm (copied from zapping&#8217;s libzvbi and originally developed for the Linux teletext viewer <i>alevt</i>) is much more error tolerant. When you select <i>automatic</i> acquisition will always start with the simple algorithmm but switch to the elaborate one when the transmission error rate is above recommended limits (see also &#8220;<font SIZE="-1">STATISTICS:</font> Acquisition statistics&#8221;). </p>
<p> <code>Windows only:</code> at the bottom of the dialog window there are additional options, which you only need to try if acquisition does not work correctly. </p>
<p> If you experience data loss due to heavy system load, you can raise the acquisition thread priority (may require special privileges on certain Windows versions.) Default is <i>normal</i>, i.e. the same as for all user applications. </p>
<p> The second checkbutton allows to enable logging during driver startup and shutdown. The output is appended to a file named <i>dsdrv.log</i> in the nxtvepg working directory. Enable this option if you&#8217;re not able to start the driver and cannot find out why. But first see the explanation of driver error messages in the <font SIZE="-1">README</font> file. Note that the logging option is not remembered across program starts, i.e. to make use of it you have to enable the acquisition via the Control menu and not by restarting nxtvepg. </p>
<p> The third option currently only applies to <font SIZE="-1">CX23881</font> based cards: it allows to disable a vendor&#8217;s <font SIZE="-1">WDM</font> driver for the same card. This is a work-around for the fact that <font SIZE="-1">CX23881</font> <font SIZE="-1">WDM</font> drivers are known to access the <font SIZE="-1">TV</font> card even while no application is using them. You should only use it as a last resort, i.e. when you can&#8217;t get the card to work at all. It&#8217;s still an experimental feature, some users have reported that their card configuration was lost or <font SIZE="-1">WDM</font> drivers remained disabled even after nxtvepg was stopped (in both cases other applications will probably not work properly anymore.) You can verify if the <font SIZE="-1">WDM</font> drivers are cause of acquisition problems by de-installing them, rebooting and then trying nxtvepg again (note nxtvepg doesn&#8217;t require any vendor supplied drivers.)</p>
<h2>Client/Server</h2>
<p> Opens a dialog that allows to configure the connection between browser and an acquisition daemon (i.e. a separate instance of nxtvepg which is running in server mode, see <i>-daemon</i> command line switch in &#8220;<font SIZE="-1">OPTIONS</font>&#8221;) The daemon allows to forward all newly acquired <font SIZE="-1">EPG</font> data to one or more connected browsers and to monitor the it&#8217;s acquisition progress. </p>
<p> The dialog contains settings of which some refer to the server-side only, some to the client-side only and some to both server and client. To avoid confusion, there are three radio buttons at the top of the dialog which allow to grey out items that do not refer to the client or server respectively. Note: for server configuration changes to take effect, the daemon must be restarted. If it&#8217;s running locally, you can do this via the Control menu (see &#8220;<font SIZE="-1">CONTROL:</font> Connect to acq. daemon&#8221;)</p>
<dl>
<dt><i>Enable remote control</i></p>
<dd> Note: this feature is not yet implemented. By enabling remote-control you can stop acquisition, change acquisition mode, <font SIZE="-1">TV</font> card parameters or any parameters configured by this dialog in a running daemon via the network connection.</p>
<dt><i>Enable </i><font SIZE="-1"><i>TCP/IP</i></font><i></i></p>
<dd> By enabling connections via the <font SIZE="-1">TCP/IP</font> network protocol, you allow connections from remote hosts. Since there&#8217;s currently no access control in nxtvepg, these hosts can be anywhere in your network, or anywhere in the world if you&#8217;re connected to the Internet. If you don&#8217;t have a firewall which prevents incoming connections of untrusted hosts, this mode is highly depreciated, because nxtvepg is not in any way secured against malicious client connections. </p>
<p> Note: on Windows currently only <font SIZE="-1">TCP/IP</font> is supported, i.e. you have to enable this option if you want to start the daemon.</p>
<dt><i>Server hostname</i></p>
<dd> Client-side only: this setting identifies the host on which the daemon is running. You can enter either a hostname in &#8220;dot.com&#8221; format or an <font SIZE="-1">IP</font> address in &#8220;127.0.0.1&#8221; format. If you set it to <i>localhost</i> the connection is automatically established via <font SIZE="-1">UNIX</font> domain sockets (i.e. pipes), which is more efficient than <font SIZE="-1">TCP/IP</font>. You can still use <font SIZE="-1">TCP/IP</font> locally if you set it to the name of your local host, as returned by <i><a href="/docs/linux/man/1-hostname/">hostname</a></i>(1).</p>
<dt><i>Server </i><font SIZE="-1"><i>TCP</i></font><i> port</i></p>
<dd> If <font SIZE="-1">TCP/IP</font> is enabled, this setting tells server and client which port to use. You can enter an arbitrary number between 1024 and 65535 here, but you have to make sure no other server is using the same port. Make sure you configure the same port number for client and server. The default is 7658.</p>
<dt><i>Bind </i><font SIZE="-1"><i>IP</i></font><i> address</i></p>
<dd> If <font SIZE="-1">TCP/IP</font> is enabled and your server host has more than one <font SIZE="-1">IP</font> address, you can select here on which one to listen for incoming connections. Make sure you use the same <font SIZE="-1">IP</font> address as server hostname on client-side, or a hostname that resolves to that <font SIZE="-1">IP</font> address. This setting is optional; if you leave the field blank (default) the server will bind to all <font SIZE="-1">IP</font> addresses. </p>
<p> Note: on systems that support it, <font SIZE="-1">TCP/IP</font> sockets are created in the IPv6 domain (<i></i><font SIZE="-1"><i>PF_INET6</i></font><i></i>) by default. On some systems (e.g. NetBSD) you cannot connect via IPv4 to an IPv6 server and vice versa, i.e. you need to use the same domain on both ends. If your client only supports IPv4, you can force your server to create an IPv4 socket by binding to an IPv4 address. If you fail to connect to a local IPv6 server via the IPv4 loopback address 127.0.0.1, use the IPv6 equivalent &#8220;::1&#8221;.</p>
<dt><i>Max. connections</i></p>
<dd> This setting limits the number of client connections the server will allow. Once the limit is reached the server will reject further connection attempts.</p>
<dt><i>Log filename</i></p>
<dd> If you enable log generation by the following option, you can choose here where the log will go. Make sure the file is writable to the uid under which the daemon process is running. The file opened and closed for each appended log line (usually there&#8217;s very low traffic into that file) so you can operate on it (e.g. truncate it) without restarting the daemon.</p>
<dt><i>File min. log level</i></p>
<dd> Here you can choose if log information should be written to a file. If you run nxtvepg with <font SIZE="-1">TCP/IP</font> disabled, you don&#8217;t need to use logging; but if you allow remote connections you should keep log files at &#8220;info&#8221; level to be able to check which hosts connect to your server. </p>
<p> The following settings are available: &#8220;no logging&#8221; disables logging; &#8220;error&#8221; enables logging of internal errors that lead to an immediate exit of the daemon; &#8220;warning&#8221; additionally enables logging of unexpected events, i.e. internal errors which do not lead to exit; &#8220;notice&#8221; additionally enables logging of server status changes, i.e. startup and shutdown; &#8220;info&#8221; additionally enables logging of connection establishment or shutdown.</p>
<dt><i>Syslog min. level</i></p>
<dd> Here you can enable or disable logging to <font SIZE="-1">UNIX</font> syslog and Windows application event logging (application name is <i>nxtvepg daemon</i>; this feature is not supported by Windows 95). See <font SIZE="-1">UNIX</font> man pages <i><a href="/docs/linux/man/8-syslogd/">syslogd</a>(8)</i> and <i><a href="/docs/linux/man/5-syslog-conf/">syslog.conf</a>(5)</i> or the Windows event log help for details about the syslog facility. The log levels you can choose here are the same as described in the previous paragraph for logging to files.</dl>
<p> Note that while network mode is enabled configuration of acquisition mode and <font SIZE="-1">TV</font> card input has no effect and no <font SIZE="-1">EPG</font> scan is possible. If you use the same rc/ini file for daemon and <font SIZE="-1">GUI</font> the changed settings will however be used by the daemon upon the next start.</p>
<h2><font SIZE="-1">TV</font> application interaction</h2>
<p> Opens a dialog that allows to configure the interaction between a <font SIZE="-1">TV</font> application and nxtvepg. You should at least configure your <font SIZE="-1">TV</font> application type and path here if you&#8217;re using one of the supported applications; this is a recommended step during the initial installation to speed up the <font SIZE="-1">EPG</font> provider search, as described in &#8220;<font SIZE="-1">GETTING</font> <font SIZE="-1">STARTED</font>&#8221;. </p>
<p> The first four (only three on <font SIZE="-1">UNIX</font>) options allow to switch interaction features on or off. If you want to improve startup time on <font SIZE="-1">UNIX</font>, turn them all off; in this case nxtvepg does not need to search for the <i>xawtv</i> toplevel window (which can take up to several seconds if you have many applications running or a slow connection to your X server.) By default all interaction features are enabled.</p>
<dl>
<dt><i>General enable</i></p>
<dd> Windows only: the option allows to disable or re-enable the allocation of communication resources, and implicitly to switch off or on all interaction features. While disabled, nxtvepg will be invisible for the <font SIZE="-1">TV</font> application. The use of this option is depreciated, as nxtvepg won&#8217;t automatically free the driver when the <font SIZE="-1">TV</font> application is started, and nxtvepg will fail to start acquisition when a <font SIZE="-1">TV</font> appliaction is running. Use this option only if you suspect compatibility problems between the <font SIZE="-1">TV</font> app and nxtvepg, e.g. if one application hangs or crashes during startup if the other is already running. (Not that such behavior is to be expected, but it&#8217;s better to be prepared for anything.)</p>
<dt><i>Tune </i><font SIZE="-1"><i>TV</i></font><i> button</i></p>
<dd> This option hides or shows the equally named button below clock in the nxtvepg main window. If you&#8217;re not interested in remote-controlling the <font SIZE="-1">TV</font> application, switch it off. </p>
<p> Note the button has a little context menu which opens with right mouse button. It contains several remote controls; which one actually work depends on the <font SIZE="-1">TV</font> application.</p>
<dt><i>Cursor follows channel changes</i></p>
<dd> While this option is enabled, nxtvepg will monitor <font SIZE="-1">TV</font> channel changes. Whenever such a change is detected, the cursor in the programme listbox will be set onto the title currently running on that network. During <font SIZE="-1">EPG</font> acquisition <font SIZE="-1">VPS/PDC</font> is used to exactly determine the current programme (only on networks which support <font SIZE="-1">VPS/PDC</font>); however if the nominal running time is in the past it&#8217;s currently not possible to display the programme in the listbox. This info may however be sent to the <font SIZE="-1">TV</font> app (see next option). </p>
<p> If you have just a network filter enabled, it will be switched to the new network so that you&#8217;ll get a complete listing of that network&#8217;s programmes, starting with the currently running one. This works even when you have excluded this network in the network selection configuration. If there are more or other filters than network enabled, then they will remain unchanged. If the current programme on the new network does not match this filter setting, then neither cursor nor listbox content will be changed.</p>
<dt><i>Display </i><font SIZE="-1"><i>EPG</i></font><i> info in </i><font SIZE="-1"><i>TV</i></font><i> app</i></p>
<dd> While this option is enabled, nxtvepg will monitor <font SIZE="-1">TV</font> channel changes. During <font SIZE="-1">EPG</font> acquisition <font SIZE="-1">VPS/PDC</font> are also monitored to determine newly starting programmes. <font SIZE="-1">VPS/PDC</font> also allows to detect channel changes on an external input source, e.g. a satellite receiver connected via the Composite socket. </p>
<p> After a change of channel or current programme title, the info about the currently running title will be displayed in the <font SIZE="-1">TV</font> application. On Windows it&#8217;s entirely up to the <font SIZE="-1">TV</font> application how this information is displayed. </p>
<p> On <font SIZE="-1">UNIX</font> the display format can be selected by the following radio buttons: </p>
<p> With <i>Separate popup</i> nxtvepg will generate a small popup window and put it right beneath the xawtv window. The blue area in the small bar on top represents how much of the (nominal) running time lies in the past. With <i>Video overlay</i> nxtvepg will generate a similar popup, however it&#8217;s placed on top of the video image (please note that this option only works properly with XFree86 version 4 and the XVideo extension; use the <code>xvinfo</code> command to check if your server supports this feature). You can change fonts and colors in this popup via X resources (see &#8220;<font SIZE="-1">FILES</font>&#8221; for details.) <i>Video overlay, 2 lines</i> is the same except that it writes running time and title in separate lines and additionally contains the percentage of expired running time. With <i>Xawtv window title</i> the info will be sent to xawtv and displayed in the window title. Except for this last option, you can configure the desired display duration with the slider at the bottom of the dialog. A duration of zero means the display will never be removed. Finally, with <i>Use external application</i> an arbitrary external application can be invoked to display the information. Title and runtime information can be passed on the command line, in the same way as for external commands in the context menu (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Context menu configuration&#8221;)</dl>
<p> In the middle of the dialog there&#8217;s one line that indicates the current <font SIZE="-1">TV</font> application connection status. It contains the name of the connected application, or <i>not connected</i> either if no <font SIZE="-1">TV</font> application is running or if it doesn&#8217;t support interaction with nxtvepg (see also &#8220;<font SIZE="-1">GETTING</font> <font SIZE="-1">STARTED:</font> Configuring a <font SIZE="-1">TV</font> application&#8221;.) You can connect to different applications than configured below, but if the network names are not synchronized with nxtvepg, the interaction will not work optimally (i.e. nxtvepg might not be able to identify all networks, and hence not be able to provide programme titles). </p>
<p> In the lower part of the dialog window you can configure type and path of your preferred <font SIZE="-1">TV</font> application. This information is used to access the <font SIZE="-1">TV</font> app&#8217;s channel table (i.e. <font SIZE="-1">TV</font> tuner frequencies and station names) during an <font SIZE="-1">EPG</font> provider scan (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Provider scan&#8221;) and in the network name configuration dialog (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Network names&#8221;). </p>
<p> After you&#8217;ve changed the setting, you can press the <i>Test</i> button to check if nxtvepg can parse the channel table correctly. It will complain if it fails to open the file or registry key and if no channels are found. After the test was successful, you shoud open the network names configuration dialog and synchronize network names with nxtvepg. </p>
<p> If your <font SIZE="-1">TV</font> application is not supported, choose <i>none</i>. (If it&#8217;s a freeware application feel free to mail me a download <font SIZE="-1">URL</font> and I will consider supporting it. However I will not support proprietary closed-source software, unless on request by the author.) </p>
<p> Note that not all of the <font SIZE="-1">TV</font> applications listed in the popup menu can currently interact with nxtvepg. The interaction requires modifications in the <font SIZE="-1">TV</font> applications; it&#8217;s up to the respective authors if they want to implement these. (If you are an author of a <font SIZE="-1">TV</font> app, feel free to mail me if you want to add <font SIZE="-1">EPG</font> support to your application; a demo application and reference implementation source code are available on the nxtvepg home page.)</p>
<h2>Select attributes</h2>
<p> Open the programme attribute display configuration dialog, which allows to select which attributes are displayed for the listed <font SIZE="-1">TV</font> programmes. In the listbox on the left of the dialog window there&#8217;s a list of all available attribute categories, e.g. title, running time, weekday, <font SIZE="-1">TV</font> network name, ratings, &#8230; i.e. mostly the same which are available for filtering. You can create your own attributes to extend this list with the dialog described in the next chapter. </p>
<p> The listbox on the right contains the types currently selected for display. The topmost entry appears on the left side of the listbox. Press <i>Apply</i> to refresh the browser listbox with the new column selection and save the new configuration to the config file. </p>
<p> In the &#8220;single list&#8221; layout (see &#8220;<font SIZE="-1">CONFIGURATION:</font> List layout&#8221;) each attribute has it&#8217;s own column in the <font SIZE="-1">TV</font> schedule and and associated filter menu in the button on top of the column (provided column headers have not been disabled, see &#8220;<font SIZE="-1">CONFIGURATION:</font> Show/Hide&#8221;.) You can change the width of each column by moving the mouse pointer to the very right of the menu button and then dragging the border to a new position while keeping the left mouse button pressed down. </p>
<p> In the &#8220;spearate network columns&#8221; layout attributes are printed beneath each other in separate lines in the <font SIZE="-1">TV</font> schedule&#8217;s network columns, unless you select <i>No new line after element</i> while the respective attribute is selected in the right listbox. Empty rows are automatically suppressed, e.g. in contrary to the &#8220;single list&#8221; layout the number of attributes actually displayed may vary. This is particularily useful for user-defined attributes, e.g. you could specify that theme categories are only printed for movies to keep the listing more compact.</p>
<h2>Attribute composition</h2>
<p> Open the configuration dialog for <i>composite attributes</i>, which allows to create new column types for the &#8220;single list&#8221; <font SIZE="-1">TV</font> schedule layout (see &#8220;<font SIZE="-1">CONFIGURATION:</font> List layout&#8221;) or new rows respectively in the &#8220;spearate network columns&#8221; layout, which can afterwards be selected in addition to the predefined attribute types (e.g. &#8220;Title&#8221; and &#8220;Theme&#8221;) as described in the previous chapter. </p>
<p> For a general description of composite attributes see &#8220;<font SIZE="-1">COMPOSITE</font> <font SIZE="-1">ATTRIBUTES</font>&#8221;. This chapter only describes usage of the configuration dialog. This chapter also assumes you&#8217;re familiar with the concept of filter shortcuts (see &#8220;<font SIZE="-1">FILTER</font> <font SIZE="-1">SHORTCUTS</font>&#8221;) and reminders (see &#8220;<font SIZE="-1">REMINDERS</font>&#8221;) </p>
<p> The dialog consists of three sections: at the top to the right there is a drop-down menu which lists all currently defined composite attributes. Here you select which attribute definition you want to edit. Below to the left is a list of shortcuts and reminder groups and 4 buttons to edit the list. On the right side of the shortcut list there are various controls for defining how programmes matching shortcuts or reminder groups should be displayed. </p>
<p> Note that there are dependencies between those sections: when you change to a different attribute definition with the drop-down menu at the top, the rest of the dialog is immediately updated to display the current definition of the composite attribute (you&#8217;ll get a warning if there any unsaved changes in the previous assignments). Also, when you select a shortcut in the listbox, the display attributes at the right are updated. </p>
<p> To create a new composite attribute, you will start by selecting the <i>Create new definition</i> command in the menu at the top right of the dialog window. You should give the label right away, so that you can keep your definitions apart, see &#8220;<font SIZE="-1">CONFIGURATION:</font> Select attributes&#8221;. You should also assign a column header text (only used in the &#8220;single list&#8221; layout), which will appear above the programme list in the main windiw; you&#8217;ll probably use a shorter text here than in the label. </p>
<p> Then you add one or more filters to the list by use of the <i>Add shortcut</i> or <i>Add reminder</i> drop-down menus to the left of the listbox. New entries are always appended at the end of the list, but you can change the ordering by use of the up/down arrow buttons. To remove a shortcut or reminder group from the list, first select it then click the <i>Delete</i> button or key. Note: ordering is important when a programme is matched by more than one shortcut, or if you mix shortcuts with reminder groups, because the display format will be determined by the first matching entry in the list, strting at the top (see also &#8220;<font SIZE="-1">COMPOSITE</font> <font SIZE="-1">ATTRIBUTES</font>&#8221;.) </p>
<p> At the right of the shortcut list there are controls which defines what&#8217;s displayed in the programme list depending on a shortcut or reminder match (for programmes which don&#8217;t match any of the given shortcuts nothing will be displayed, unless you have a <i>*no match*</i> entry.) By default a match is displayed as the name of the matching shortcut or reminder group, but you can easily change that with the controls to the right of the listbox. The choices are: freely defined but static text, one of the pre-defined images or one of the programme&#8217;s attributes (i.e. if you select <i>Time</i> the programme&#8217;s start time will be displayed). </p>
<p> In case you chose to use text (including attributes), you can select bold, underlined or overstrike font and the text color. For all types you can also select a background color. Colors can be applied either just to the user-defined attribute itself, or the entire column (in single list layout; or the entire element in grid layout) The resulting appearance is shown in a <code>Text sample</code> above the controls. These display options can be configured separately for every shortcut match. An exception is the entire-column background color; if such a format is found in multiple attributes, the last one counts. </p>
<p> When you want to try out your attribute definition, press the <i>Apply</i> button at the bottom. The definition is saved and the browser content is updated. If the attribute is not currently used in the browser, you&#8217;re offered in a popup message to automatically append the attribute to the <font SIZE="-1">TV</font> schedule. You can later change it&#8217;s position by using the <i>Select attributes</i> configuration dialog. </p>
<p> There&#8217;s also a <i>Delete</i> button at the bottom which allows to remove obsolete definitions. If the composite attribute is still displayed in the browser, it&#8217;s automatically removed. Note that a deletion cannot be undone, i.e. the information is lost irrecoverably.</p>
<h2>Select networks</h2>
<p> Open the network selection dialog. It allows to permanently suppress <font SIZE="-1">TV</font> networks in a provider&#8217;s listing, e.g. if you can not receive the channel. You can also change the order of the networks, e.g. to put your favorite networks at the top of the filter menus. </p>
<p> This window has two lists: on the left you&#8217;ll find all networks that are covered by the provider in their original order, on the right those that are selected for the programme listing in your preferred order. By default, both lists will have exactly the same content. If you want to exclude networks, select them in the right list and press <i>Delete</i>. You can always include them again by selecting them in the left list and pressing <i>Add</i>. You can change the order in the right list by selecting one or more networks and pressing the <i>up</i> or <i>down</i> arrows. </p>
<p> At the bottom of the dialog window there&#8217;s an entry field named <code>Air times</code> that allows to limit the program listing for a network to a given time frame. For example if you receive <i>Arte</i> only from 19:00 until 07:00 o&#8217;clock, select &#8220;Arte&#8221; either in the left or right list, then enter &#8220;19:00&#8221; and &#8220;07:00&#8221; in the fields (make sure to always use 4 digits and the separating colon). Programmes that fall completely outside that window will not appear in the browser window. If you want to undo the limitation, enter 00:00 until 00:00 or any other equal time values. </p>
<p> Note: you can also operate this dialog (and all other dialogs with similar listbox selections) with he keyboard: use the <font SIZE="-1">TAB</font> key or the mouse to move the keyboard input focus to the left or right listbox. Use the cursor up/down keys to select an item; hold down <font SIZE="-1">SHIFT</font> to select multiple items. In the left list, press Return to add a network to the right list. In the right list, press the Delete key to remove a network, or press <font SIZE="-1">CONTROL</font> and the up/down cursor keys to change the selected items&#8217; position in the list.</p>
<h2>Network names</h2>
<p> Open the network names configuration dialog. It&#8217;s main purpose is to synchronize the network names between nxtvepg and your <font SIZE="-1">TV</font> application. This is required because the network name is used in communication when you use the <i>Tune </i><font SIZE="-1"><i>TV</i></font><i></i> remote controls, and as well for channel change notifications by the <font SIZE="-1">TV</font> applications. For many networks there will be no need to change anything, but for some there exist different variants, e.g. in Germany &#8220;Super <font SIZE="-1">RTL</font>&#8221; vs. &#8220;S-RTL&#8221; or &#8220;<font SIZE="-1">MDR3</font>&#8221; vs. &#8220;<font SIZE="-1">MDR</font>&#8221;. </p>
<p> If you&#8217;re not using <font SIZE="-1">UNIX</font>, you first need to select which <font SIZE="-1">TV</font> application you want to synchronize with and where the configuration files are located. This is done in the <i></i><font SIZE="-1"><i>TV</i></font><i> app. interaction</i> dialog in the Configure menu (see &#8220;<font SIZE="-1">CONFIGURATION:</font> <font SIZE="-1">TV</font> application interaction&#8221;). </p>
<p> Another use of this dialog is to make network naming consistent across all Nextview providers. The names you specify here will be used in the programme listbox and all filter menus, independently of the provider. </p>
<p> On the left side of the dialog you find a list of all networks of all known Nextview providers. The names used here are the ones you configured before, or if you haven&#8217;t done so yet, the names that match the station names of your <font SIZE="-1">TV</font> application best. Unmatched names are marked red. If no <font SIZE="-1">TV</font> application is configured, the network names used by your currently selected <font SIZE="-1">EPG</font> provider are used. </p>
<p> On the right side, you&#8217;re offered four ways to change the name: topmost is a simple entry field where you can type in an arbitrary name. Below is a popup menu which contains all network names defined in your <font SIZE="-1">TV</font> app.&#8217;s channel table. Below is a button which contains the one name in your <font SIZE="-1">TV</font> app.&#8217;s channel table which resembles the current string in the entry field most, or <i>none</i>. It&#8217;s marked red until it&#8217;s identical to the entry field. You can copy the name to the entry field by clicking the button. Below is a listbox with the original names used in the various provider databases. When you select a name from the menu or the listbox, it will be copied into the entry field and the network name list on the left. If you want to save the changed list, leave the dialog with <i>Save</i>, else use <i>Abort</i>. </p>
<p> <code>Note:</code> if you receive channels that carry multiple networks, e.g. in Germany &#8220;Arte / Kinderkanal&#8221;, it&#8217;s recommended to include all networks&#8217; names in the network name on side of the <font SIZE="-1">TV</font> application, separated by a slash. The slash is recognized as separator by nxtvepg and all resulting segments can be used as network names.</p>
<h2>Context menu configuration</h2>

<p>${title} ${network} ${start} ${stop} ${relstart} ${duration} ${CNI} ${description} ${themes} ${VPS} or ${PDC} ${e_rating} ${p_rating} ${sound} ${format} ${digital} ${encrypted} ${live} ${repeat} $<br />
{<br />
    subtitle<br />
}</p>
<p> Start and stop time related keywords can optionally be followed by either a plus or minus sign and a time offset. The offset value is assumed to be given as minutes. For relstart and duration the precision can be changed by means of the format (see below.) Example: to print the start time minus 5 minutes (e.g. to start a recording 5 minutes earlier) use <tt>&quot;${start-5:%H:%M}&quot;</tt> </p>
<p> The keywords can optionally be followed by a colon and an output format specification. Options depend on the type of variable substitution:</p>
<dl>
<dt><i>Start, stop and </i><font SIZE="-1"><i>VPS/PDC</i></font><i> times</i></p>
<dd> All options defined in the <a href="/docs/linux/man/3-strftime/">strftime</a><code>(3)</code> manpage are available; default is <tt>%H:</tt>%M-%d.%m.%Y (hour, minute, day, month, year).</p>
<dt><i>Relative start time and duration</i></p>
<dd> You can choose between minutes (default) and seconds by appending &#8220;m&#8221; or &#8220;s&#8221;.</p>
<dt><i>Theme categories</i></p>
<dd> You can choose between numerical and textual output by appending &#8220;n&#8221; or &#8220;t&#8221;. Use command line option <i>-dump pdc</i> to get a list of theme categories (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;.)</dl>
<p> For all other variables modifiers are currently ignored. </p>
<p> On <font SIZE="-1">UNIX</font> the resulting substrings which replace the formal variables are always enclosed in single quotes, because the command line is passed to a system shell for execution (/bin/sh, i.e. the <i>Bourne Shell</i> by means of the <i>system</i> function; see also system man pages <code>sh</code> or <code>bash</code>) and there are many characters with special meaning. Single quotes inside he substituted string are correctly escaped. </p>
<p> Example: The command line </p>
<p>plan ${start : % d.% m.% Y % H : % M} $<br />
{<br />
    title<br />
}</p>
<p> could for example on <font SIZE="-1">UNIX</font> systems result in </p>
<pre>
  plan '22.08.2001 13:05' 'Käpt'\''n Blaubärs Seemannsgarn'
</pre>
<p> On Windows only single- and double quotes and spaces characters are escaped with a backslash. Hence the above example would result in: </p>
<pre>
  plan 22.08.2001\ 13:05 Käpt\'n\ Blaubärs\ Seemannsgarn
</pre>
<p> Note if you want to prevent the backslash inbetween date and time (if the called program doesn&#8217;t understand it), you can simply use two separate substitutions for date and time. Example: </p>
<pre><code>
plan ${start : % d.% m.% Y} ${start : % H : % M} $
{
    title
}
</code></pre>
<h2>Themes language</h2>
<p> Select the language for programme themes (i.e. content category, see &#8220;<font SIZE="-1">FILTERING</font>&#8221;) in the main window and the filter menu. By default it&#8217;s set to <i>automatic</i>; in this case the language is derived from the selected provider&#8217;s database. Please note that the language of the menus, help etc. currently can not be changed from English.</p>
<h2>Show/Hide</h2>
<p> Toggle visibility of various components in the main window:</p>
<dl>
<dt><i>Show shortcuts</i></p>
<dd> Toggle visibility of the shortcut listbox at the left of the programme list. When you unmap both the shortcuts list and the network list below, the clock and reset buttons are also unmapped so that you get only the programme list.</p>
<dt><i>Show networks (left)</i></p>
<dd> Maps or unmaps the network filter listbox below the shortcuts list, or below the clock if you&#8217;ve unmapped the shortcuts list.</p>
<dt><i>Show networks (middle)</i></p>
<dd> Maps or unmaps the network filter listbox between shortcuts listbox and programme list.</p>
<dt><i>Show layout button</i></p>
<dd> Maps or unmaps the <i>Grid layout</i> checkbutton below the shortcuts or network list in the main window (see also &#8220;<font SIZE="-1">CONFIGURATION:</font> List layout&#8221;). If you&#8217;re permanently using one or the other layout, you will probably want to unmap this button. (It&#8217;s mainly present to make users who upgrade from older versions aware of this new option.)</p>
<dt><i>Show status line</i></p>
<dd> Maps or unmaps the database and acquisition status line at the bottom of the browser window.</p>
<dt><i>Show column headers</i></p>
<dd> Maps or unmaps the browser listbox column header menubar, i.e. the row of menu buttons above the programme list in single list layout.</p>
<dt><i>Show weekday scale</i></p>
<dd> Maps or unmaps the weekday scale to the right of the programme list. (Note you can configure the looks, i.e. font, colors, width and date format via the resource file <tt>&quot;nxtvepg.ad&quot;</tt> or <tt>&quot;.Xdefaults&quot;</tt> on <font SIZE="-1">UNIX</font>, see &#8220;<font SIZE="-1">FILES</font>&#8221;)</p>
<dt><i>Hide on minimize</i></p>
<dd> Windows only: When this option is enabled, the main window&#8217;s entry in the task bar is removed when it&#8217;s minimized or when the program is started with the <i>-iconic</i> command line switch. Instead an icon is added to the system tray in the task bar. A double-click on the tray icon deiconifies the main window. A click with the right mouse button opens a little popup menu. The entries in this menu have the same meaning as the equally named ones in the control menu (see &#8220;<font SIZE="-1">CONTROL</font>&#8221;).</dl>
<h2>List layout</h2>
<p> Select layout of the programme list in the main window:</p>
<dl>
<dt><i>Single list for all networks</i></p>
<dd> This is the original layout (the only layout until nxtvepg version 2.4) in which all programmes of all networks are presented in a single list, sorted by start time.</p>
<dt><i>Separate columns for each network</i></p>
<dd> In this layout programmes are still sorted by start time, but presented in separate columns for each network. Schedules of different networks are aligned, so that programmes which run at the same time are approximately at the same height. </p>
<p> You can join several columns in a single column via the <i>Control</i> menu (meant for networks which share the same channel; use this in conjunction with <i>air times restriction</i> as described in &#8220;<font SIZE="-1">CONFIGURATION:</font> Select networks&#8221;.) The control menu is part of the drop-down menu below the button at the top of the column. This menu also holds commands to increase or decrease the number of visible columns.</dl>
<p> In both layouts you can select which types of attributes are printed for each programme by clicking on the icon in the button row at the top of the list (unless column header buttons are hidden.)</p>
<h2>FILES</h2>
<h2>Files used on <font SIZE="-1">UNIX</font> systems</h2>
<dl>
<dt><code>$HOME/.nxtvepgrc</code></p>
<dd> Configuration file where all personal settings are stored. Per default this is created in your home directory, but a different path and file name can be specified with the <code>-rcfile</code> option (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;).</p>
<dt><code>/usr/tmp/nxtvdb/nxtvdb-####</code></p>
<dd> Directory containing one file for each provider&#8217;s database. The path can be changed with the <code>-dbdir</code> command line option (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;). Note that the path can also be configured during compilation of the software, so if you downloaded a binary version of this package the path may be different. The current default setting can be queried with the <code>-help</code> command line switch. </p>
<p> The last 4 digits of the file names are the hexadecimal <font SIZE="-1">CNI</font> (Country and Network Identifier) of the provider.</p>
<dt><code>/usr/share/nxtvepg/xmltv-etsi.map</code></p>
<dd> This file is used when importing <font SIZE="-1">EPG</font> data from <font SIZE="-1">XMLTV</font> file to map <font SIZE="-1">XMLTV</font> channel identification strings (i.e. the name given in the <i>&lt;channel id=&#8220;&#8230;&#8221;&gt;</i> <font SIZE="-1">XML</font> tags) to <font SIZE="-1">ETSI</font> channel identification numbers. If a file with the same name is in the current working directory, that one is used instead.</p>
<dt><code>/dev/vbi0</code>, <code>/dev/vbi1</code>, etc.</p>
<dd> Device files from which Nextview data is being read during acquisition. The index postfix can be specified with the <code>-card</code> command line option (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;). You must have read/write access to these files; by default this is not the case for many Linux distributions for security reasons (since you might have connected a WebCam and mike and someone could spy on you from remote). However on a single-user system it&#8217;s safe to make them world-readable and writable, i.e. in a root shell enter: </p>
<pre>
  chmod 666 /dev/vbi
</pre>
<p> Alternatively you can make yourself a member of a group in <i>/etc/groups</i> which has access to the devices or create such a group.</p>
<dt><code>/dev/video0</code>, <code>/dev/video1</code>, etc.</p>
<dd> On Linux kernel series 2.4 and earlier (i.e. before revision #2 of the video4linux <font SIZE="-1">API</font>) these device files are used to select the input source (e.g. <font SIZE="-1">TV</font> tuner or one of the composite or S-Video sockets) and tuner frequency for <font SIZE="-1">VBI</font> reception, unless you choose the passive acquisition mode. The index postfix can be specified with the <code>-card</code> command line option. This device must be readable and writable. </p>
<p> The device is only kept open during a provider search (see &#8220;<font SIZE="-1">CONFIGURATION:</font> Provider scan&#8221;). Else, it&#8217;s just opened shortly to set the input source and tuner frequency. If the device is busy (e.g. while you watch <font SIZE="-1">TV</font>), acquisition starts on the currently selected channel and automatically follows any externally controlled changes (this will be reported, e.g. in the status line at the bottom of the browser window, as <i>forced passive</i> acquisition mode, see &#8220;<font SIZE="-1">STATISTICS:</font> Status line&#8221;). </p>
<p> Note: it&#8217;s mandatory that the video device has the same index as the <font SIZE="-1">VBI</font> device. If you have a video device at index 0 which does not support teletext (a webcam, for example) the <font SIZE="-1">VBI</font> device belonging to video device #1 may appear at index 0. You should force the driver to assign device index #1 to the <font SIZE="-1">VBI</font> index. On Linux this is possible by using <i>insmod</i> parameters in <i>/etc/modules.conf</i>, e.g. for bttv: </p>
<pre>
   options bttv video_nr=1 vbi_nr=1
</pre>
<dt><code>/dev/v4l/vbi0</code>, <code>/dev/v4l/video0</code></p>
<dd> If you have enabled <i>devfs</i> in your Linux kernel, the <font SIZE="-1">VBI</font> and video devices will appear in a subdirectory. nxtvepg automatically detects the existance of this directory and will search the devices there instead of the regular paths.</p>
<dt><code>/dev/dvb/adapter0/demux0</code></p>
<dd> This device is used when option <i>-dvbpid</i> is present.</p>
<dt><code>/tmp/.vbi0.pid</code>, <code>/tmp/.vbi1.pid</code>, etc.</p>
<dd> This file contains the <font SIZE="-1">PID</font> of the nxtvepg process (or the acquisition slave process unless threading is used) whenever a <font SIZE="-1">VBI</font> device is kept open. The process can be forced to free the device by sending it signal <i></i><font SIZE="-1"><i>SIGHUP</i></font><i></i>, e.g. from a wrapper script around a teletext decoder. An example which works with all shells: </p>
<pre>
   kill -HUP `cat /tmp/.vbi0.pid`
</pre>
<p> Note that the daemon is not kept alive when acquisition is disabled, so that sending <font SIZE="-1">HUP</font> to the daemon equals sending <font SIZE="-1">TERM</font>. You can restart acquisition by starting a new daemon. The browser attempts to reconnect every 10 seconds when the connection was broken, but you can also trigger an immediate reconnect be sending the <font SIZE="-1">GUI</font> process <font SIZE="-1">SIGHUP</font>. </p>
<p> To restart acquisition in non-daemon mode, signal again with <font SIZE="-1">SIGHUP</font>, either to the acquisition slave process or the browser process.</p>
<dt><code>/tmp/nxtvepg.0</code></p>
<dd> This non-regular file (socket) is created by the daemon to allow local client connections via <font SIZE="-1">UNIX</font> domain sockets. The same socket can be used for more than one client connection. It&#8217;s deleted when the daemon terminates (unless the daemon crashes or receives an uncatchable signal like the infamous signal 9 aka <font SIZE="-1">KILL</font>). See also &#8220;<font SIZE="-1">CONTROL:</font> Connect to acq. daemon&#8221;.</p>
<dt><code>$HOME/.xawtv</code></p>
<dd> This file belongs to the <font SIZE="-1">TV</font> viewer <i>xawtv</i>. It&#8217;s not required or created by nxtvepg. But if it exists, it will be used in the <font SIZE="-1">EPG</font> scan (for a fast scan mode where only the channels defined in this file will be checked) and in the network name configuration dialog. See also &#8220;<font SIZE="-1">CONFIGURATION:</font> <font SIZE="-1">TV</font> application interaction&#8221;.</p>
<dt><code>$HOME/.Xdefaults</code></p>
<dd> This file is usually loaded into the X server at startup (or during login) by use of the <i>xrdb</i> command. It contains a series of parameter assignments called <i>X resource definitions</i> for any number of applications. Note: depending on your X11 startup scripts this file may have a different name, e.g. <i>.Xresources</i>. The file could be used to change the &#8220;look&#8221; of almost every element in every dialog window (within limits, because some options are hard-coded) or the look of entire widget classes, like menus or buttons. However that&#8217;s highly implementation dependent and generally not very useful, hence depreciated. </p>
<p> Defaults for all officially supported options are listed in the so-called &#8220;app-defaults&#8221; file <i>Nxtvepg.ad</i> which is usually installed in <i>/usr/X11/lib/X11/app-defaults</i> (the .ad extension is omitted during installation.) You should not change values there however, because they would be overwritten when you install new versions. Instead copy changed lines into your .Xdefaults file (without the leading comment ! sign.) Note you have to restart nxtvepg for changes to take effect. When X11 is already running you can override individual settings with xrdb like this: </p>
<pre>
   echo &quot;nxtvepg*text_bg: #E9E9EC&quot; | xrdb -merge
</pre>
<p> Color values can specified either symbolically (e.g. &#8220;red&#8221;) or as hexadecimal <font SIZE="-1">RGB</font> values in #RRGGBB format. A special case are the 7 colors for weekday background colors in the main window&#8217;s date scale: it&#8217;s resource value consists of a comma separated list of 7 colors. </p>
<p> Fonts must be specified as triplets of family, size (use negative values to specify the size in pixels and positive values for sizes given in points) and appearance (only &#8220;normal&#8221; or &#8220;bold&#8221; are recommended). Lines starting with a ! sign are treated as comment and hence ignored. Entries that do not adhere to this syntax are silently discarded.</dl>
<h2>Files used on Windows systems</h2>
<dl>
<dt><code>nxtvepg.ini</code></p>
<dd> Configuration file where all configuration and personal preference settings are stored. By default this is created in the working directory, but a different path and file name can be specified with the <code>-rcfile</code> option (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;).</p>
<dt><code>xmltv-etsi.map</code></p>
<dd> This file is used when importing <font SIZE="-1">EPG</font> data from <font SIZE="-1">XMLTV</font> file to map <font SIZE="-1">XMLTV</font> channel identification strings (see <font SIZE="-1">UNIX</font> section above for details.)</p>
<dt><code>Nxtvepg.ad</code></p>
<dd> Allows to change the application&#8217;s appearance, i.e. colors and text fonts. The format and content of the file is identical to the <i>.Xdefaults</i> file described in the <font SIZE="-1">UNIX</font> section.</p>
<dt><code>nxtv____.epg</code></p>
<dd> One file for each provider&#8217;s database is created in the working directory or the one given with the <code>-dbdir</code> command line option (see &#8220;<font SIZE="-1">OPTIONS</font>&#8221;). The last 4 digits of the file base names are the hexadecimal <font SIZE="-1">CNI</font> (Country and Network Identifier) of the provider. You must not change the name of this file, or nxtvepg will refuse to load the database.</p>
<dt><code>vbi_map.dat</code></p>
<dd> This hidden file is used to set up shared memory to allow information exchange between nxtvepg and an attached <font SIZE="-1">TV</font> application. It&#8217;s automatically removed when nxtvepg terminates and should never be accessed (i.e. being written to or removed) by external applications. The file is not created when <font SIZE="-1">TV</font> app. interaction is disabled (see &#8220;<font SIZE="-1">CONFIGURATION:</font> <font SIZE="-1">TV</font> application interaction&#8221;).</dl>

<h2>KNOWN BUGS</h2>
<p> Under Windows there&#8217;s a risk of system crash (&#8220;blue screen&#8221;) when the application is terminated by force, e.g. via the task manager. This is unavoidable because in this case there&#8217;s no chance to stop the driver and hence the <font SIZE="-1">TV</font> card continues to capure data into <font SIZE="-1">RAM</font>. In normal operation this should be very unlikely because all software exceptions (e.g. page faults) and shutdown messages are caught and the driver then stopped before the exit.</p>
