<h2>NAME</h2>
<p> Yacc &#8211; an <a href="/docs/linux/man/1-lalr/">LALR</a>(1) parser generator</p>
<h2>SYNOPSIS</h2>
<p> <code>yacc [ -dgilrtv ] [ -b</code> <i>file_prefix</i> <code>] [ -p</code> <i>symbol_prefix</i> <code>]</code> <i>filename</i></p>
<h2>DESCRIPTION</h2>
<p> <code>Yacc</code> reads the grammar specification in the file <i>filename</i> and generates an <a href="/docs/linux/man/1-lalr/">LALR</a>(1) parser for it. The parsers consist of a set of <a href="/docs/linux/man/1-lalr/">LALR</a>(1) parsing tables and a driver routine written in the C programming language. <code>Yacc</code> normally writes the parse tables and the driver routine to the file <i>y.tab.c.</i> </p>
<p> The following options are available:</p>
<dl>
<dt><code>-b </code><i>file_prefix</i></p>
<dd> The <code>-b</code> option changes the prefix prepended to the output file names to the string denoted by <i>file_prefix.</i> The default prefix is the character <i>y.</i></p>
<dt><code>-d</code></p>
<dd> The <code>-d</code> option causes the header file <code>y.tab.h</code> to be written. It contains #define&#8217;s for the token identifiers.</p>
<dt><code>-g</code></p>
<dd> The <code>-g</code> option causes a graphical description of the generated <a href="/docs/linux/man/1-lalr/">LALR</a>(1) parser to be written to the file <code>y.dot</code> in graphviz format, ready to be processed by <a href="/docs/linux/man/1-dot/">dot</a>(1).</p>
<dt><code>-i</code></p>
<dd> The <code>-i</code> option causes a supplementary header file <code>y.tab.i</code> to be written. It contains extern declarations and supplementary #define&#8217;s as needed to map the conventional <i>yacc</i> <code>yy</code>-prefixed names to whatever the <code>-p</code> option may specify. The code file, e.g., <code>y.tab.c</code> is modified to #include this file as well as the <code>y.tab.h</code> file, enforcing consistent usage of the symbols defined in those files.</p>
<dt>
<dd> The supplementary header file makes it simpler to separate compilation of lex- and yacc-files.</p>
<dt><code>-l</code></p>
<dd> If the <code>-l</code> option is not specified, <code>yacc</code> will insert <i>#line</i> directives in the generated code. The <i>#line</i> directives let the C compiler relate errors in the generated code to the user&#8217;s original code. If the <code>-l</code> option is specified, <code>yacc</code> will not insert the <i>#line</i> directives. <i>#line</i> directives specified by the user will be retained.</p>
<dt><code>-o </code><i>output_file</i></p>
<dd> specify the filename for the parser file. If this option is not given, the output filename is the file prefix concatenated with the file suffix, e.g., <code>y.tab.c</code>. This overrides the <code>-p</code> option.</p>
<dt><code>-p </code><i>symbol_prefix</i></p>
<dd> The <code>-p</code> option changes the prefix prepended to yacc-generated symbols to the string denoted by <i>symbol_prefix.</i> The default prefix is the string <code>yy.</code></p>
<dt><code>-P</code></p>
<dd> create a reentrant parser, e.g., &quot;%pure-parser&quot;.</p>
<dt><code>-r</code></p>
<dd> The <code>-r</code> option causes <code>yacc</code> to produce separate files for code and tables. The code file is named <i>y.code.c,</i> and the tables file is named <i>y.tab.c.</i> The prefix &quot;<i>y.</i>&quot; can be overridden using the <code>-b</code> option.</p>
<dt><code>-s</code></p>
<dd> suppress &quot;<code>#define</code>&quot; statements generated for string literals in a &quot;<code>%token</code>&quot; statement, to more closely match original <code>yacc</code> behavior.</p>
<dt>
<dd> Normally when <code>yacc</code> sees a line such as </p>
<pre>
%token OP_ADD &quot;ADD&quot;
</pre>
<dt>
<dd> it notices that the quoted &quot;ADD&quot; is a valid C identifier, and generates a #define not only for OP_ADD, but for ADD as well, e.g., </p>
<pre><code>
#define OP_ADD 257

#define ADD 258
</code></pre>
<dt>
<dd> The original <code>yacc</code> does not generate the second &quot;<code>#define</code>&quot;. The <code>-s</code> option suppresses this &quot;<code>#define</code>&quot;.</p>
<dt>
<dd> POSIX (IEEE 1003.1 2004) documents only names and numbers for &quot;<code>%token</code>&quot;, though original <code>yacc</code> and bison also accept string literals.</p>
<dt><code>-t</code></p>
<dd> The <code>-t</code> option changes the preprocessor directives generated by <code>yacc</code> so that debugging statements will be incorporated in the compiled code.</p>
<dt><code>-v</code></p>
<dd> The <code>-v</code> option causes a human-readable description of the generated parser to be written to the file <i>y.output.</i></p>
<dt><code>-V</code></p>
<dd> print the version number to the standard output.</p>
<dt><code>-y</code></p>
<dd> <code>yacc</code> ignores this option, which bison supports for ostensible POSIX compatibility.</dl>
<h2>EXTENSIONS</h2>
<p> <code>yacc</code> provides some extensions for compatibility with bison and other implementations of yacc:</p>
<dl>
<dt><code> %expect</code> <i>number</i></p>
<dd> tell <code>yacc</code> the expected number of shift/reduce conflicts. That makes it only report the number if it differs.</p>
<dt><code> %expect-rr</code> <i>number</i></p>
<dd> tell <code>yacc</code> the expected number of reduce/reduce conflicts. That makes it only report the number if it differs. This is (unlike bison) allowable in LALR parsers.</p>
<dt><code> %lex-param</code> { <i>argument-declaration</i> }</p>
<dd> By default, the lexer accepts no parameters, e.g., <code>yylex()</code>. Use this directive to add parameter declarations for your customized lexer.</p>
<dt><code> %parse-param</code> { <i>argument-declaration</i> }</p>
<dd> By default, the parser accepts no parameters, e.g., <code>yyparse()</code>. Use this directive to add parameter declarations for your customized parser.</p>
<dt><code> %pure-parser</code></p>
<dd> Most variables (other than <code>yydebug</code> and <code>yynerrs</code>) are allocated on the stack within <code>yyparse</code>, making the parser reasonably reentrant.</dl>
<h2>PORTABILITY</h2>
<p> According to Robert Corbett, </p>
<pre>
    Berkeley Yacc is an <a href="//www.systutorials.com/docs/linux/man/1-LALR/">LALR</a>(1) parser generator.  Berkeley Yacc has been made
as compatible as possible with AT&amp;T Yacc.  Berkeley Yacc can accept any input
specification that conforms to the AT&amp;T Yacc documentation.  Specifications
that take advantage of undocumented features of AT&amp;T Yacc will probably be
rejected.
</pre>
<p> The rationale in </p>
<pre>
<a rel="nofollow" href="http://pubs.opengroup.org/onlinepubs/9699919799/utilities/yacc.html">http://pubs.opengroup.org/onlinepubs/9699919799/utilities/yacc.html</a>
</pre>
<p> documents some features of AT&amp;T yacc which are no longer required for POSIX compliance. </p>
<p> That said, you may be interested in reusing grammary files with some other implementation which is not strictly compatible with AT&amp;T yacc. For instance, there is bison. Here are a few differences:</p>
<dl>
<dt>&bull;</p>
<dd> <code>Yacc</code> accepts an equals mark preceding the left curly brace of an action (as in the original grammar file <code><a href="ftp://ftp.y">ftp.y</a></code>): </p>
<pre><code>
| STAT CRLF = {
    statcmd();
}
</code></pre>
<dt>&bull;</p>
<dd> <code>Yacc</code> and bison emit code in different order, and in particular bison makes forward reference to common functions such as yylex, yyparse and yyerror without providing prototypes.</p>
<dt>&bull;</p>
<dd> Bison&#8217;s support for &quot;%expect&quot; is broken in more than one release. For best results using bison, delete that directive.</p>
<dt>&bull;</p>
<dd> Bison has no equivalent for some of <code>yacc</code>&#8216;s commmand-line options, relying on directives embedded in the grammar file.</p>
<dt>&bull;</p>
<dd> Bison&#8217;s &quot;<code>-y</code>&quot; option does not affect bison&#8217;s lack of support for features of AT&amp;T yacc which were deemed obsolescent.</dl>
<h2>DIAGNOSTICS</h2>
<p> If there are rules that are never reduced, the number of such rules is reported on standard error. If there are any <a href="/docs/linux/man/1-lalr/">LALR</a>(1) conflicts, the number of conflicts is reported on standard error. </p>
