<h2 class="name">NAME</h2>
<p> yasm &#8211; The Yasm Modular Assembler </p>
<h2>SYNOPSIS</h2>
<dl>
<dt> <code>yasm</code> [<code>-f&nbsp;<wbr></code><i>format</i>] [<code>-o&nbsp;<wbr></code><i>outfile</i>] [<i>other options</i>&#8230;] {<i>infile</i>}</p>
<dt> <code>yasm</code> <code>-h</code></dl>
<h2>DESCRIPTION</h2>
<dd>The Yasm Modular Assembler is a portable, retargetable assembler written under the &#8220;new&#8221; (2 or 3 clause) BSD license. Yasm currently supports the x86 and AMD64 instruction sets, accepts NASM and GAS assembler syntaxes, outputs binary, ELF32, ELF64, COFF, Win32, and Win64 object formats, and generates source debugging information in STABS, DWARF 2, and CodeView 8 formats. </p>
<p> YASM consists of the <code>yasm</code> command, libyasm, the core backend library, and a large number of modules. Currently, libyasm and the loadable modules are statically built into the <code>yasm</code> executable. </p>
<p> The <code>yasm</code> command assembles the file infile and directs output to the file <i>outfile</i> if specified. If <i>outfile</i> is not specified, <code>yasm</code> will derive a default output file name from the name of its input file, usually by appending .o or .obj, or by removing all extensions for a raw binary file. Failing that, the output file name will be yasm.out. </p>
<p> If called with an <i>infile</i> of &#8220;-&#8220;, <code>yasm</code> assembles the standard input and directs output to the file <i>outfile</i>, or yasm.out if no <i>outfile</i> is specified.</p>
<h2>OPTIONS</h2>
<p> Many options may be given in one of two forms: either a dash followed by a single letter, or two dashes followed by a long option name. Options are listed in alphabetical order.</p>
<h3>General Options</h3>
<p> <code>-a </code><i>arch</i> or <code>&#8211;arch=</code><i>arch</i>: Select target architecture</p>
<dl>
<dt>
<dd> Selects the target architecture. The default architecture is &#8220;x86&#8221;, which supports both the IA-32 and derivatives and AMD64 instruction sets. To print a list of available architectures to standard output, use &#8220;help&#8221; as <i>arch</i>. See <code><a href="/docs/linux/man/7-yasm_arch/">yasm_arch</a></code>(7) for a list of supported architectures.</dl>
<p> <code>-f </code><i>format</i> or <code>&#8211;oformat=</code><i>format</i>: Select object format</p>
<dl>
<dt>
<dd> Selects the output object format. The default object format is &#8220;bin&#8221;, which is a flat format binary with no relocation. To print a list of available object formats to standard output, use &#8220;help&#8221; as <i>format</i>. See <code><a href="/docs/linux/man/7-yasm_objfmts/">yasm_objfmts</a></code>(7) for a list of supported object formats.</dl>
<p> <code>-g </code><i>debug</i> or <code>&#8211;dformat=</code><i>debug</i>: Select debugging format</p>
<dl>
<dt>
<dd> Selects the debugging format for debug information. Debugging information can be used by a debugger to associate executable code back to the source file or get data structure and type information. Available debug formats vary between different object formats; <code>yasm</code> will error when an invalid combination is selected. The default object format is selected by the object format. To print a list of available debugging formats to standard output, use &#8220;help&#8221; as <i>debug</i>. See <code><a href="/docs/linux/man/7-yasm_dbgfmts/">yasm_dbgfmts</a></code>(7) for a list of supported debugging formats.</dl>
<p> <code>-L </code><i>list</i> or <code>&#8211;lformat=</code><i>list</i>: Select list file format</p>
<dl>
<dt>
<dd> Selects the format/style of the output list file. List files typically intermix the original source with the machine code generated by the assembler. The default list format is &#8220;nasm&#8221;, which mimics the NASM list file format. To print a list of available list file formats to standard output, use &#8220;help&#8221; as <i>list</i>.</dl>
<p> <code>-l </code><i>listfile</i> or <code>&#8211;list=</code><i>listfile</i>: Specify list filename</p>
<dl>
<dt>
<dd> Specifies the name of the output list file. If this option is not used, no list file is generated.</dl>
<p> <code>-m </code><i>machine</i> or <code>&#8211;machine=</code><i>machine</i>: Select target machine architecture</p>
<dl>
<dt>
<dd> Selects the target machine architecture. Essentially a subtype of the selected architecture, the machine type selects between major subsets of an architecture. For example, for the &#8220;x86&#8221; architecture, the two available machines are &#8220;x86&#8221;, which is used for the IA-32 and derivative 32-bit instruction set, and &#8220;amd64&#8221;, which is used for the 64-bit instruction set. This differentiation is required to generate the proper object file for relocatable object formats such as COFF and ELF. To print a list of available machines for a given architecture to standard output, use &#8220;help&#8221; as <i>machine</i> and the given architecture using <code>-a </code><i>arch</i>. See <code><a href="/docs/linux/man/7-yasm_arch/">yasm_arch</a></code>(7) for more details.</dl>
<p> <code>-o </code><i>filename</i> or <code>&#8211;objfile=</code><i>filename</i>: Specify object filename</p>
<dl>
<dt>
<dd> Specifies the name of the output file, overriding any default name generated by Yasm.</dl>
<p> <code>-p </code><i>parser</i> or <code>&#8211;parser=</code><i>parser</i>: Select parser</p>
<dl>
<dt>
<dd> Selects the parser (the assembler syntax). The default parser is &#8220;nasm&#8221;, which emulates the syntax of NASM, the Netwide Assembler. Another available parser is &#8220;gas&#8221;, which emulates the syntax of GNU AS. To print a list of available parsers to standard output, use &#8220;help&#8221; as <i>parser</i>. See <code><a href="/docs/linux/man/7-yasm_parsers/">yasm_parsers</a></code>(7) for a list of supported parsers.</dl>
<p> <code>-r </code><i>preproc</i> or <code>&#8211;preproc=</code><i>preproc</i>: Select preprocessor</p>
<dl>
<dt>
<dd> Selects the preprocessor to use on the input file before passing it to the parser. Preprocessors often provide macro functionality that is not included in the main parser. The default preprocessor is &#8220;nasm&#8221;, which is an imported version of the actual NASM preprocessor. A &#8220;raw&#8221; preprocessor is also available, which simply skips the preprocessing step, passing the input file directly to the parser. To print a list of available preprocessors to standard output, use &#8220;help&#8221; as <i>preproc</i>.</dl>
<p> <code>-h</code> or <code>&#8211;help</code>: Print a summary of options</p>
<dl>
<dt>
<dd> Prints a summary of invocation options. All other options are ignored, and no output file is generated.</dl>
<p> <code>&#8211;version</code>: Get the Yasm version</p>
<dl>
<dt>
<dd> This option causes Yasm to prints the version number of Yasm as well as a license summary to standard output. All other options are ignored, and no output file is generated.</dl>
<h3>Warning Options</h3>
<p> <code>-W</code> options have two contrary forms: <code>-W</code><i>name</i> and <code>-Wno-</code><i>name</i>. Only the non-default forms are shown here. </p>
<p> The warning options are handled in the order given on the command line, so if <code>-w</code> is followed by <code>-Worphan-labels</code>, all warnings are turned off <i>except</i> for orphan-labels. </p>
<p> <code>-w</code>: Inhibit all warning messages</p>
<dl>
<dt>
<dd> This option causes Yasm to inhibit all warning messages. As discussed above, this option may be followed by other options to re-enable specified warnings.</dl>
<p> <code>-Werror</code>: Treat warnings as errors</p>
<dl>
<dt>
<dd> This option causes Yasm to treat all warnings as errors. Normally warnings do not prevent an object file from being generated and do not result in a failure exit status from <code>yasm</code>, whereas errors do. This option makes warnings equivalent to errors in terms of this behavior.</dl>
<p> <code>-Wno-unrecognized-char</code>: Do not warn on unrecognized input characters</p>
<dl>
<dt>
<dd> Causes Yasm to not warn on unrecognized characters found in the input. Normally Yasm will generate a warning for any non-ASCII character found in the input file.</dl>
<p> <code>-Worphan-labels</code>: Warn on labels lacking a trailing option</p>
<dl>
<dt>
<dd> When using the NASM-compatible parser, causes Yasm to warn about labels found alone on a line without a trailing colon. While these are legal labels in NASM syntax, they may be unintentional, due to typos or macro definition ordering.</dl>
<p> <code>-X </code><i>style</i>: Change error/warning reporting style</p>
<dl>
<dt>
<dd> Selects a specific output style for error and warning messages. The default is &#8220;gnu&#8221; style, which mimics the output of <code>gcc</code>. The &#8220;vc&#8221; style is also available, which mimics the output of Microsoft&#8217;s Visual C++ compiler. </p>
<p> This option is available so that Yasm integrates more naturally into IDE environments such as Visual Studio or Emacs, allowing the IDE to correctly recognize the error/warning message as such and link back to the offending line of source code.</dl>
<h3>Preprocessor Options</h3>
<p> While these preprocessor options theoretically will affect any preprocessor, the only preprocessor currently in Yasm is the &#8220;nasm&#8221; preprocessor. </p>
<p> <code>-D </code><i>macro[=value]</i>: Pre-define a macro</p>
<dl>
<dt>
<dd> Pre-defines a single-line macro. The value is optional (if no value is given, the macro is still defined, but to an empty value).</dl>
<p> <code>-e</code> or <code>&#8211;preproc-only</code>: Only preprocess</p>
<dl>
<dt>
<dd> Stops assembly after the preprocessing stage; preprocessed output is sent to the specified output name or, if no output name is specified, the standard output. No object file is produced.</dl>
<p> <code>-I </code><i>path</i>: Add include file path</p>
<dl>
<dt>
<dd> Adds directory <i>path</i> to the search path for include files. The search path defaults to only including the directory in which the source file resides.</dl>
<p> <code>-P </code><i>filename</i>: Pre-include a file</p>
<dl>
<dt>
<dd> Pre-includes file <i>filename</i>, making it look as though <i>filename</i> was prepended to the input. Can be useful for prepending multi-line macros that the <code>-D</code> can&#8217;t support.</dl>
<p> <code>-U </code><i>macro</i>: Undefine a macro</p>
<dl>
<dt>
<dd> Undefines a single-line macro (may be either a built-in macro or one defined earlier in the command line with <code>-D</code>.</dl>
<h2>EXAMPLES</h2>
<p> To assemble NASM syntax, 32-bit x86 source source.asm into ELF file source.o, warning on orphan labels: </p>
<dl>
<dt>
<dd>
<pre>
yasm -f elf32 -Worphan-labels source.asm
</pre>
</dl>
<p> To assemble NASM syntax AMD64 source x.asm into Win64 file object.obj: </p>
<dl>
<dt>
<dd>
<pre>
yasm -f win64 -o object.obj x.asm
</pre>
</dl>
<p> To assemble already preprocessed NASM syntax x86 source y.asm into flat binary file y.com: </p>
<dl>
<dt>
<dd>
<pre>
yasm -f bin -r raw -o y.com y.asm
</pre>
</dl>
<h2>DIAGNOSTICS</h2>
<p> The <code>yasm</code> command exits 0 on success, and nonzero if an error occurs.</p>
<h2>COMPATIBILITY</h2>
<p> Yasm&#8217;s NASM parser and preprocessor, while they strive to be as compatible as possible with NASM, have a few incompatibilities due to YASM&#8217;s different internal structure. </p>
<p> Yasm&#8217;s GAS parser and preprocessor are missing a number of features present in GNU AS.</p>
<h2>RESTRICTIONS</h2>
<p> As object files are often architecture and machine dependent, not all combinations of object formats, architectures, and machines are legal; trying to use an invalid combination will result in an error. </p>
<p> There is no support for symbol maps.</p>

<h2>BUGS</h2>
<p> When using the &#8220;x86&#8221; architecture, it is overly easy to generate AMD64 code (using the <code>BITS 64</code> directive) and generate a 32-bit object file (by failing to specify <code>-m amd64</code> or selecting a 64-bit object format such as ELF64 on the command line).</p>
