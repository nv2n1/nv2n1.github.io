<h2 class="name">NAME</h2>
<p> winedbg &#8211; Wine debugger </p>
<h2>SYNOPSIS</h2>
<p> <code>winedbg</code> [ <i>options</i> ] [ <i>program_name</i> [ <i>program_arguments</i> ] | <i>wpid</i> ] </p>
<p> <code>winedbg &#8211;gdb</code> [ <i>options</i> ] [ <i>program_name</i> [ <i>program_arguments</i> ] | <i>wpid</i> ] </p>
<p> <code>winedbg &#8211;auto </code><i>wpid</i> </p>
<p> <code>winedbg &#8211;minidump</code> [ <i>file.mdmp</i> ] <i>wpid</i> </p>
<p> <code>winedbg </code><i>file.mdmp</i></p>
<h2>DESCRIPTION</h2>
<p> <code>winedbg</code> is a debugger for Wine. It allows:</p>
<dl>
<dt>
<dd>
<pre>
+ debugging native Win32 applications
+ debugging Winelib applications
+ being a drop-in replacement for Dr Watson
</pre>
</dl>
<h2>MODES</h2>
<p> <code>winedbg</code> can be used in five modes. The first argument to the program determines the mode winedbg will run in.</p>
<dl>
<dt><code>default</code></p>
<dd> Without any explicit mode, this is standard <code>winedbg</code> operating mode. <code>winedbg</code> will act as the front end for the user.</p>
<dt><code>&#8211;gdb</code></p>
<dd> <code>winedbg</code> will be used as a proxy for <code>gdb</code>. <code>gdb</code> will be the front end for command handling, and <code>winedbg</code> will proxy all debugging requests from <code>gdb</code> to the Win32 APIs.</p>
<dt><code>&#8211;auto</code></p>
<dd> This mode is used when <code>winedbg</code> is set up in <i>AeDebug</i> registry entry as the default debugger. <code>winedbg</code> will then display basic information about a crash. This is useful for users who don&#8217;t want to debug a crash, but rather gather relevant information about the crash to be sent to developers.</p>
<dt><code>&#8211;minidump</code></p>
<dd> This mode is similar to the <code>&#8211;auto</code> one, except that instead of printing the information on the screen (as <code>&#8211;auto</code> does), it&#8217;s saved into a minidump file. The name of the file is either passed on the command line, or generated by <code>WineDbg</code> when none is given. This file could later on be reloaded into <code>winedbg</code> for further examination.</p>
<dt><code>file.mdmp</code></p>
<dd> In this mode <code>winedbg</code> reloads the state of a debuggee which has been saved into a minidump file. See either the <code>minidump</code> command below, or the <code>&#8211;minidump mode</code>. </p>
</dl>
<h2>OPTIONS</h2>
<p> When in <code>default</code> mode, the following options are available: </p>
<dl>
<dt><code>&#8211;command&nbsp;</code><i>string</i></p>
<dd> <code>winedbg</code> will execute the command <i>string</i> as if it was keyed on winedbg command line, and then will exit. This can be handy for getting the pid of running processes (winedbg &#8211;command &quot;info proc&quot;).</p>
<dt><code>&#8211;file&nbsp;</code><i>filename</i></p>
<dd> <code>winedbg</code> will execute the list of commands contained in file filename as if they were keyed on winedbg command line, and then will exit.</dl>
<p> When in <code>gdb</code> proxy mode, the following options are available: </p>
<dl>
<dt><code>&#8211;no-start</code></p>
<dd> <code>gdb</code> will not be automatically started. Relevant information for starting <code>gdb</code> is printed on screen. This is somehow useful when not directly using <code>gdb</code> but some graphical front-ends, like <code>ddd</code> or <code>kgbd</code>.</p>
<dt><code>&#8211;port</code>&nbsp;<i>port</i></p>
<dd> Start the <code>gdb</code> server on the given port. If this option is not specified, a randomly chosen port will be used. If <code>&#8211;no-start</code> is specified, the port used will be printed on startup.</p>
<dt><code>&#8211;with-xterm</code></p>
<dd> This will run <code>gdb</code> in its own xterm instead of using the current Unix console for textual display.</dl>
<p> In all modes, the rest of the command line, when passed, is used to identify which programs, if any, has to debugged:</p>
<dl>
<dt><i>program_name</i></p>
<dd> This is the name of an executable to start for a debugging session. <code>winedbg</code> will actually create a process with this executable. If <i>programs_arguments</i> are also given, they will be used as arguments for creating the process to be debugged.</p>
<dt><i>wpid</i></p>
<dd> <code>winedbg</code> will attach to the process which Windows pid is <i>wpid</i>. Use the <code>info proc</code> command within <code>winedbg</code> to list running processes and their Windows pids.</p>
<dt><code>default</code></p>
<dd> If nothing is specified, you will enter the debugger without any run nor attached process. You&#8217;ll have to do the job yourself. </p>
</dl>
<h2>COMMANDS</h2>
<h3>Default mode, and while reloading a minidump file:</h3>
<p> Most of commands used in <code>winedbg</code> are similar to the ones from <code>gdb</code>. Please refer to the <code>gdb</code> documentations for some more details. See the <i>gdb differences</i> section later on to get a list of variations from <code>gdb</code> commands. </p>
<p> <i>Misc. commands</i></p>
<dl>
<dt><code>abort</code></p>
<dd> Aborts the debugger.</p>
<dt><code>quit</code></p>
<dd> Exits the debugger.</p>
<dt><code>attach&nbsp;</code><i>N</i></p>
<dd> Attach to a Wine process (<i>N</i> is its Windows ID, numeric or hexadecimal). IDs can be obtained using the <code>info process</code> command. Note the <code>info process</code> command returns hexadecimal values</p>
<dt>
<dd>
<dt><code>detach</code></p>
<dd> Detach from a Wine-process.</p>
<dt><code>thread&nbsp;</code><i>N</i></p>
<dd> Change the current thread to <i>N</i> (its Windows TID, numeric or hexadecimal).</p>
<dt>
<dd></dl>
<p> <i>Help commands</i></p>
<dl>
<dt><code>help</code></p>
<dd> Prints some help on the commands.</p>
<dt><code>help info</code></p>
<dd> Prints some help on info commands</dl>
<p> <i>Flow control commands</i></p>
<dl>
<dt><code>cont</code></p>
<dd> Continue execution until next breakpoint or exception.</p>
<dt><code>pass</code></p>
<dd> Pass the exception event up to the filter chain.</p>
<dt><code>step</code></p>
<dd> Continue execution until next C line of code (enters function call)</p>
<dt><code>next</code></p>
<dd> Continue execution until next C line of code (doesn&#8217;t enter function call)</p>
<dt><code>stepi</code></p>
<dd> Execute next assembly instruction (enters function call)</p>
<dt><code>nexti</code></p>
<dd> Execute next assembly instruction (doesn&#8217;t enter function call)</p>
<dt><code>finish</code></p>
<dd> Execute until return of current function is reached.</dl>
<p> <code>cont</code>, <code>step</code>, <code>next</code>, <code>stepi</code>, <code>nexti</code> can be postfixed by a number (N), meaning that the command must be executed N times before control is returned to the user. </p>
<p> <i>Breakpoints, watchpoints</p>
<dl>
<dt></i><code>enable&nbsp;</code><i>N</i></p>
<dd> Enables (break|watch)-point <i>N</i></p>
<dt><code>disable&nbsp;</code><i>N</i></p>
<dd> Disables (break|watch)-point <i>N</i></p>
<dt><code>delete&nbsp;</code><i>N</i></p>
<dd> Deletes (break|watch)-point <i>N</i></p>
<dt><code>cond&nbsp;</code><i>N</i></p>
<dd> Removes any existing condition to (break|watch)-point <i>N</i></p>
<dt><code>cond&nbsp;</code><i>N expr</i></p>
<dd> Adds condition <i>expr</i> to (break|watch)-point <i>N</i>. <i>expr</i> will be evaluated each time the (break|watch)-point is hit. If the result is a zero value, the breakpoint isn&#8217;t triggered.</p>
<dt><code>break&nbsp;*&nbsp;</code><i>N</i></p>
<dd> Adds a breakpoint at address <i>N</i></p>
<dt><code>break&nbsp;</code><i>id</i></p>
<dd> Adds a breakpoint at the address of symbol <i>id</i></p>
<dt><code>break&nbsp;</code><i>id N</i></p>
<dd> Adds a breakpoint at the line <i>N</i> inside symbol <i>id</i>.</p>
<dt><code>break&nbsp;</code><i>N</i></p>
<dd> Adds a breakpoint at line <i>N</i> of current source file.</p>
<dt><code>break</code></p>
<dd> Adds a breakpoint at current <code>$PC</code> address.</p>
<dt><code>watch&nbsp;*&nbsp;</code><i>N</i></p>
<dd> Adds a watch command (on write) at address <i>N</i> (on 4 bytes).</p>
<dt><code>watch&nbsp;</code><i>id</i></p>
<dd> Adds a watch command (on write) at the address of symbol <i>id</i>. Size depends on size of <i>id</i>.</p>
<dt><code>rwatch&nbsp;*&nbsp;</code><i>N</i></p>
<dd> Adds a watch command (on read) at address <i>N</i> (on 4 bytes).</p>
<dt><code>rwatch&nbsp;</code><i>id</i></p>
<dd> Adds a watch command (on read) at the address of symbol <i>id</i>. Size depends on size of <i>id</i>.</p>
<dt><code>info break</code></p>
<dd> Lists all (break|watch)-points (with their state).</dl>
<p> You can use the symbol <code>EntryPoint</code> to stand for the entry point of the Dll. </p>
<p> When setting a (break|watch)-point by <i>id</i>, if the symbol cannot be found (for example, the symbol is contained in a not yet loaded module), <code>winedbg</code> will recall the name of the symbol and will try to set the breakpoint each time a new module is loaded (until it succeeds). </p>
<p> <i>Stack manipulation</i></p>
<dl>
<dt><code>bt</code></p>
<dd> Print calling stack of current thread.</p>
<dt><code>bt&nbsp;</code><i>N</i></p>
<dd> Print calling stack of thread of ID <i>N</i>. Note: this doesn&#8217;t change the position of the current frame as manipulated by the <code>up</code> &amp; <code>dn</code> commands).</p>
<dt><code>up</code></p>
<dd> Goes up one frame in current thread&#8217;s stack</p>
<dt><code>up&nbsp;</code><i>N</i></p>
<dd> Goes up <i>N</i> frames in current thread&#8217;s stack</p>
<dt><code>dn</code></p>
<dd> Goes down one frame in current thread&#8217;s stack</p>
<dt><code>dn&nbsp;</code><i>N</i></p>
<dd> Goes down <i>N</i> frames in current thread&#8217;s stack</p>
<dt><code>frame&nbsp;</code><i>N</i></p>
<dd> Sets <i>N</i> as the current frame for current thread&#8217;s stack.</p>
<dt><code>info locals</code></p>
<dd> Prints information on local variables for current function frame.</dl>
<p> <i>Directory &amp; source file manipulation</i></p>
<dl>
<dt><code>show dir</code></p>
<dd> Prints the list of dirs where source files are looked for.</p>
<dt><code>dir&nbsp;</code><i>pathname</i></p>
<dd> Adds <i>pathname</i> to the list of dirs where to look for source files</p>
<dt><code>dir</code></p>
<dd> Deletes the list of dirs where to look for source files</p>
<dt><code>symbolfile&nbsp;</code><i>pathname</i></p>
<dd> Loads external symbol definition file <i>pathname</i></p>
<dt><code>symbolfile&nbsp;</code><i>pathname N</i></p>
<dd> Loads external symbol definition file <i>pathname</i> (applying an offset of <i>N</i> to addresses)</p>
<dt><code>list</code></p>
<dd> Lists 10 source lines forwards from current position.</p>
<dt><code>list &#8211;</code></p>
<dd> Lists 10 source lines backwards from current position</p>
<dt><code>list&nbsp;</code><i>N</i></p>
<dd> Lists 10 source lines from line <i>N</i> in current file</p>
<dt><code>list&nbsp;</code><i>pathname</i><code>:</code><i>N</i></p>
<dd> Lists 10 source lines from line <i>N</i> in file <i>pathname</i></p>
<dt><code>list&nbsp;</code><i>id</i></p>
<dd> Lists 10 source lines of function <i>id</i></p>
<dt><code>list&nbsp;*&nbsp;</code><i>N</i></p>
<dd> Lists 10 source lines from address <i>N</i></dl>
<p> You can specify the end target (to change the 10 lines value) using the &#8216;,&#8217; separator. For example:</p>
<dl>
<dt><code>list 123, 234</code></p>
<dd> lists source lines from line 123 up to line 234 in current file</p>
<dt><code>list foo.c:1,56</code></p>
<dd> lists source lines from line 1 up to 56 in file foo.c</dl>
<p> <i>Displaying</i> </p>
<p> A display is an expression that&#8217;s evaluated and printed after the execution of any <code>winedbg</code> command.</p>
<dl>
<dt><code>display</code></p>
<dd>
<dt><code>info display</code></p>
<dd> Lists the active displays</p>
<dt><code>display&nbsp;</code><i>expr</i></p>
<dd> Adds a display for expression <i>expr</i></p>
<dt><code>display&nbsp;/</code><i>fmt expr</i></p>
<dd> Adds a display for expression <i>expr</i>. Printing evaluated <i>expr</i> is done using the given format (see <code>print command</code> for more on formats)</p>
<dt><code>del display&nbsp;</code><i>N</i></p>
<dd>
<dt><code>undisplay&nbsp;</code><i>N</i></p>
<dd> Deletes display <i>N</i></dl>
<p> <i>Disassembly</i></p>
<dl>
<dt><code>disas</code></p>
<dd> Disassemble from current position</p>
<dt><code>disas&nbsp;</code><i>expr</i></p>
<dd> Disassemble from address <i>expr</i></p>
<dt><code>disas&nbsp;</code><i>expr</i><code>,</code><i>expr</i></p>
<dd> Disassembles code between addresses specified by the two expressions</dl>
<p> <i>Memory&nbsp;(reading, writing, typing)</i></p>
<dl>
<dt><code>x&nbsp;</code><i>expr</i></p>
<dd> Examines memory at address <i>expr</i></p>
<dt><code>x&nbsp;/</code><i>fmt expr</i></p>
<dd> Examines memory at address <i>expr</i> using format <i>fmt</i></p>
<dt><code>print&nbsp;</code><i>expr</i></p>
<dd> Prints the value of <i>expr</i> (possibly using its type)</p>
<dt><code>print&nbsp;/</code><i>fmt expr</i></p>
<dd> Prints the value of <i>expr</i> (possibly using its type)</p>
<dt><code>set&nbsp;</code><i>var</i><code>&nbsp;=&nbsp;</code><i>expr</i></p>
<dd> Writes the value of <i>expr</i> in <i>var</i> variable</p>
<dt><code>whatis&nbsp;</code><i>expr</i></p>
<dd> Prints the C type of expression <i>expr</i></dl>
<dl>
<dt><i>fmt</i></p>
<dd> is either <i>letter</i> or <i>count letter</i>, where <i>letter</i> can be:</p>
<dl>
<dt>
<dd>
<dl>
<dt>s</p>
<dd> an ASCII string</p>
<dt>u</p>
<dd> a UTF16 Unicode string</p>
<dt>i</p>
<dd> instructions (disassemble)</p>
<dt>x</p>
<dd> 32-bit unsigned hexadecimal integer</p>
<dt>d</p>
<dd> 32-bit signed decimal integer</p>
<dt>w</p>
<dd> 16-bit unsigned hexadecimal integer</p>
<dt>c</p>
<dd> character (only printable 0x20-0x7f are actually printed)</p>
<dt>b</p>
<dd> 8-bit unsigned hexadecimal integer</p>
<dt>g</p>
<dd> Win32 GUID</dl>
</dl>
</dl>
<p> <i>Expressions</i> </p>
<p> Expressions in Wine Debugger are mostly written in a C form. However, there are a few discrepancies: </p>
<dl>
<dt>
<dd> Identifiers can take a &#8216;!&#8217; in their names. This allows mainly to specify a module where to look the ID from, e.g. <i>USER32!CreateWindowExA</i>. </p>
<p> In a cast operation, when specifying a structure or a union, you must use the struct or union keyword (even if your program uses a typedef).</dl>
<p> When specifying an identifier, if several symbols with this name exist, the debugger will prompt for the symbol you want to use. Pick up the one you want from its number. </p>
<p> <i>Misc.</i> </p>
<p> <code>minidump </code><i>file.mdmp</i> saves the debugging context of the debuggee into a minidump file called <i>file.mdmp</i>. </p>
<p> <i>Information on Wine internals</i></p>
<dl>
<dt><code>info class</code></p>
<dd> Lists all Windows classes registered in Wine</p>
<dt><code>info class&nbsp;</code><i>id</i></p>
<dd> Prints information on Windows class <i>id</i></p>
<dt><code>info share</code></p>
<dd> Lists all the dynamic libraries loaded in the debugged program (including .so files, NE and PE DLLs)</p>
<dt><code>info share&nbsp;</code><i>N</i></p>
<dd> Prints information on module at address <i>N</i></p>
<dt><code>info regs</code></p>
<dd> Prints the value of the CPU registers</p>
<dt><code>info all-regs</code></p>
<dd> Prints the value of the CPU and Floating Point registers</p>
<dt><code>info segment</code></p>
<dd> Lists all allocated segments (i386 only)</p>
<dt><code>info segment&nbsp;</code><i>N</i></p>
<dd> Prints information on segment <i>N</i> (i386 only)</p>
<dt><code>info stack</code></p>
<dd> Prints the values on top of the stack</p>
<dt><code>info map</code></p>
<dd> Lists all virtual mappings used by the debugged program</p>
<dt><code>info map&nbsp;</code><i>N</i></p>
<dd> Lists all virtual mappings used by the program of Windows pid <i>N</i></p>
<dt><code>info wnd</code></p>
<dd> Displays the window hierarchy starting from the desktop window</p>
<dt><code>info wnd&nbsp;</code><i>N</i></p>
<dd> Prints information of Window of handle <i>N</i></p>
<dt><code>info process</code></p>
<dd> Lists all w-processes in Wine session</p>
<dt><code>info thread</code></p>
<dd> Lists all w-threads in Wine session</p>
<dt><code>info frame</code></p>
<dd> Lists the exception frames (starting from current stack frame). You can also pass, as optional argument, a thread id (instead of current thread) to examine its exception frames.</dl>
<p> Debug messages can be turned on and off as you are debugging using the <code>set</code> command, but only for channels initialized with the <i>WINEDEBUG</i> environment variable.</p>
<dl>
<dt><code>set warn&nbsp;+&nbsp;</code><i>win</i></p>
<dd> Turns on warn on <i>win</i> channel</p>
<dt><code>set&nbsp;+&nbsp;</code><i>win</i></p>
<dd> Turns on warn/fixme/err/trace on <i>win</i> channel</p>
<dt><code>set &#8211;&nbsp;</code><i>win</i></p>
<dd> Turns off warn/fixme/err/trace on <i>win</i> channel</p>
<dt><code>set fixme &#8211; all</code></p>
<dd> Turns off fixme class on all channels</dl>
<h3>Gdb mode:</h3>
<p> See the <code>gdb</code> documentation for all the <code>gdb</code> commands. </p>
<p> However, a few Wine extensions are available, through the <code>monitor</code> command:</p>
<dl>
<dt><code>monitor wnd</code></p>
<dd> Lists all windows in the Wine session</p>
<dt><code>monitor proc</code></p>
<dd> Lists all processes in the Wine session</p>
<dt><code>monitor mem</code></p>
<dd> Displays memory mapping of debugged process</dl>
<h3>Auto and minidump modes:</h3>
<p> Since no user input is possible, no commands are available. </p>
<h2>ENVIRONMENT</h2>
<dl>
<dt><code>WINE_GDB</code></p>
<dd> When used in <code>gdb</code> proxy mode, <code>WINE_GDB</code> specifies the name (and the path) of the executable to be used for <code>gdb</code>. &quot;gdb&quot; is used by default.</dl>
