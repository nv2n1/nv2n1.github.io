<h2>NAME</h2>
<p> exonerate-server &#8211; a sequence comparison server for exonerate </p>
<h2>SYNOPSIS</h2>
<p> <code>exonerate-server [ options ] &lt;index path&gt;</code> </p>
<h2>DESCRIPTION</h2>
<p> <code>exonerate-server</code> is a multi-threaded server for the exonerate sequence alignment program. </p>
<p> It uses a set of sequences and a corresponding index file to allow fast of large datasets. </p>
<h2>OVERVIEW</h2>
<p> Firstly, an <code>.esd</code> file must be made from the sequence files. The <code>.esd</code> file is an Exonerate Sequence Dataset file, and can be used to group together any set of sequences where each sequences containing unique identifiers. This is done by using the <code>fasta2esd</code> utility.</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>fasta2esd genome.fasta genome.esd</code></p>
<dd></dl>
</dl>
<p> Next, an <code>.esi</code> file my be made from the <code>.esd</code> file. The <code>.esi</code> file is an Exonerate Sequence Index file, and contains an index or set of indices corresponding to a particular dataset. This is done by using the <code>esd2esi</code> utility.</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>esd2esi genome.esd genome.esi</code></p>
<dd></dl>
</dl>
<p> Once the <code>.esi</code> file has been generated, the exonerate-server may be started.</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>exonerate-server genome.esi</code></p>
<dd></dl>
</dl>
<p> While the server is running, exonerate may be used to query the server by replacing the target sequences in the command line with the name of the server and port number. The default port number for the exonerate-server is 12886.</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>exonerate query.fasta localhost:12886</code></p>
<dd></dl>
</dl>
<h2>OPTIONS</h2>
<p> Some of the command line options for the exonerate-server are the same as for the exonerate client, and these are documented in the man page for <code>exonerate.</code> The other options which are specific to <code>exonerate-server</code> are documented here.</p>
<dl>
<dt><code>&#8211;port &lt;port&gt;</code></p>
<dd> Specify the port on which the server should listen. By default, <code>exonerate-server</code> will listen on port 12886, but alternative ports may be specified with this option.</p>
<dt><code>&#8211;input &lt;index file&gt;</code></p>
<dd> Specify the index file to be used when the server is started. This option is mandatory. The index file is a <code>.esi</code> file generated by the <code>esd2esi</code> utility.</p>
<dt><code>&#8211;preload &lt;boolean&gt;</code></p>
<dd> By default the indices contained in the <code>.esi</code> file, and the sequences referenced in the corresponding <code>.esd</code> file are loaded into memory when the server is started. This is necessary to achieve fast performance that would otherwise be hampered by frequent disk accesses. This option allows the index and sequence preloading to be turned off, which allows the server to run much more slowly, but with faster startup and a smaller memory footprint. It is not advised to turn preloading off unless testing or debugging the server.</p>
<dt><code>&#8211;maxconnections &lt;count&gt;</code></p>
<dd> The server is multithreaded. This option sets the number client processes which are allowed to connect to the server simultaneously. For good performance, it should not be set to more than the number of CPUs on the machine on which the server is running.</p>
<dt><code>&#8211;verbosity &lt;level&gt;</code></p>
<dd> Set the verbosity level for the server. If it is zero, the server will be silent, and the higher the number, the more messages are reported by the server about what is happening. </p>
</dl>
<h2>INTERFACE</h2>
<p> This section documents the communication interface between the client and server. The interface is documented for people wishing to write their own custom server to sit behind exonerate &#8211; for normal use of exonerate, it is not necessary to know this. </p>
<p> The interface works by the client sending simple command lines and the server sending simple reply lines over a socket. All the commands and replies are simple lines of ASCII text, so it is possible to use telnet as a client for testing a server. </p>
<p> Any command is a single line of text, but a reply may contain many lines of text. The replies are in the form of <code>&lt;tag&gt;: &lt;message&gt;</code> </p>
<p> Any reply can include lines with the tag <code>warning:</code> or <code>error:</code> These <code>warning:</code> and <code>error:</code> tags are echoed by the client, and the client will exit after receiving any <code>error:</code> reply. </p>
<p> When the server is returning a multiline reply, the first line must show the number of lines in the whole reply as: <code>linecount: &lt;count&gt;</code> For examples, see the replies from the <code>get hsps</code> commands in the example session below. </p>
<p> The client will only open a single connection to any server, although a multithreaded server is obviously required to allow multiple clients to connect simultaneously. </p>
<h3>Commands and replies used in for the interface.</h3>
<dl>
<dt>Command:</p>
<dd> <code>version</code></p>
<dt>Reply:</p>
<dd> version &lt;server name&gt; &lt;server version&gt; </p>
<dt>Command:</p>
<dd> <code>exit</code></p>
<dt>Reply:</p>
<dd> ( no reply &#8211; server closes connection ) </p>
<dt>Command:</p>
<dd> <code>dbinfo</code></p>
<dt>Reply:</p>
<dd> dbinfo: &lt;type&gt; &lt;masked&gt; &lt;num_seqs&gt; &lt;max_seq_len&gt; &lt;total_seq_len&gt; </p>
<p> The <code>dbinfo</code> command returns information about the database loaded on the server. The returned fields are: </p>
<dl>
<dt>
<dd>
<dl>
<dt><code>&lt;type&gt;</code></p>
<dd> either dna or protein</p>
<dt><code>&lt;masked&gt;</code></p>
<dd> either softmasked or unmasked</p>
<dt><code>&lt;num_seqs&gt;</code></p>
<dd> the number of sequences in the database</p>
<dt><code>&lt;max_seq_len&gt;</code></p>
<dd> the length of the longest sequence in the database</p>
<dt><code>&lt;total_seq_len&gt;</code></p>
<dd> the total length of all the sequences in the database</dl>
</dl>
<dt>Command:</p>
<dd> <code>lookup</code> &lt;eid&gt;</p>
<dt>Reply:</p>
<dd> lookup: &lt;iid&gt; </p>
<p> The lookup command is used to map an external identifier to an internal identifier. </p>
<dt>Command:</p>
<dd> <code>get info</code> &lt;iid&gt;</p>
<dt>Reply:</p>
<dd> seqinfo: &lt;len&gt; &lt;checksum&gt; &lt;eid&gt; [ &lt;def&gt; ] </p>
<p> The get info command returns information about a sequence in the database. The returned fields are: </p>
<dl>
<dt>
<dd>
<dl>
<dt><code>&lt;len&gt;</code></p>
<dd> the sequence length</p>
<dt><code>&lt;checksum&gt;</code></p>
<dd> a gcg format checksum (see below)</p>
<dt><code>&lt;eid&gt;</code></p>
<dd> the external id (eg. from fasta header)</p>
<dt><code>&lt;def&gt;</code></p>
<dd> a description line for the sequence (also from the fasta header), this field is optional an may be ommitted.</dl>
</dl>
<dt>Command:</p>
<dd> <code>get seq</code> &lt;iid&gt;</p>
<dt>Reply:</p>
<dd> seq: &lt;seq&gt; </p>
<p> The get seq command returns a whole sequence on one line. </p>
<dt>Command:</p>
<dd> <code>get subseq</code> &lt;iid&gt; &lt;start&gt; &lt;len&gt;</p>
<dt>Reply:</p>
<dd> subseq: &lt;sequence&gt; </p>
<p> The get subseq command returns part of a sequence. The start of the sequence is position zero. eg. get subseq 0 0 10 will return the first 10 bases of the first sequence in the database. </p>
<dt>Command:</p>
<dd> <code>set query</code> &lt;seq&gt;</p>
<dt>Reply:</p>
<dd> ok: &lt;len&gt; &lt;checksum&gt; </p>
<p> The seq query command is used to send a query sequence to the server. It returns the length of the sequence and a gcg checksum </p>
<dt>Command:</p>
<dd> <code>revcomp</code> &lt;query | target&gt;</p>
<dt>Reply:</p>
<dd> ok: &lt;query | target&gt; strand &lt;forward | revcomp&gt; </p>
<p> The revcomp query command makes the server reverse complement the query. This is to save the bandwidth of sending the query twice. </p>
<p> The revcomp target command is to tell the server to treat the database as its reverse complement. The client only sends this command when searching a translated database, so need not be implemented for most types of search. </p>
<dt>Command:</p>
<dd> <code>set param</code> &lt;name&gt; &lt;value&gt;</p>
<dt>Reply:</p>
<dd> ok: &lt;set | ignored&gt; </p>
<p> The set parameter command sends parameters from the exonerate command line to the server. This commands can all be ignored by the client for a basic implementation, but cannot be ignored for optimal performance. </p>
<dt>Command:</p>
<dd> <code>get hsps</code></p>
<dt>Reply:</p>
<dd> hspset: &lt;iid&gt; { &lt;query_pos&gt; &lt;target_pos&gt; &lt;length&gt; }</p>
<dt>Or:</p>
<dd> hspset: empty </p>
<p> The get hsps command is the main command for getting sets of hsps. The server may return multiple hspsets. The returned fields are: </p>
<dl>
<dt>
<dd>
<dl>
<dt><code>&lt;iid&gt;</code></p>
<dd> The internal id of the target sequence for these HSPsets.</p>
<dt><code>&lt;query_pos&gt;</code></p>
<dd> The hsp query start position</p>
<dt><code>&lt;target_pos&gt;</code></p>
<dd> The hsp target start position</p>
<dt><code>&lt;length&gt;</code></p>
<dd> The hsp length</dl>
</dl>
<dl>
<dt>
<dd> The last three fields represent an HSP, and may be repeated many times on one <code>hspset:</code> reply line.</dl>
</dl>
