<h2>NAME</h2>
<p> encodedv &#8211; encode a series of images to a digital video stream</p>
<h2>SYNOPSIS</h2>
<p> <code>encodedv</code> [ <code>options</code> ] <i>video_pattern</i> <i>[ audio_input ]</i></p>
<h2>DESCRIPTION</h2>
<p> <code>encodedv</code> takes a series of images in PPM/PGM/video format and optionally an audio stream and compiles them into a DV-encoded video stream. <i>pattern</i> specifies where the input data is located and may be either <i>&#8211;</i> for stdin, or a <code>printf</code>-style pattern taking one numeric argument that gets replaced by the current frame number. Like image%03d.ppm, which gets expanded to image000.ppm, image001.ppm, etc.</p>
<dl>
<dt><code>&#8211;version</code></p>
<dd> show encodedv version number.</p>
<dt><code>-s</code>, <code>&#8211;start-frame</code>=<i>count</i></p>
<dd> start encoding at frame number <i>count</i> (defaults to 0).</p>
<dt><code>-e</code>, <code>&#8211;end-frame</code>=<i>count</i></p>
<dd> end encoding at frame number <i>count</i> (defaults to unlimited).</p>
<dt><code>-l</code>, <code>&#8211;wrong-interlace</code></p>
<dd> flip lines to compensate for wrong interlacing in the input data. Happened with mpeg2dec generated data.</p>
<dt><code>-p</code>, <code>&#8211;vlc-passes</code></p>
<dd> vlc code distribution passes (1-3) greater values = better quality but not necessarily slower encoding! This defaults for best quality = 3.</p>
<dt><code>-v</code>, <code>&#8211;verbose</code></p>
<dd> show encoder statistics / status information</p>
<dt><code>-i</code>, <code>&#8211;input</code>=<i>filter-name</i></p>
<dd> Choose input-filter: [&gt;ppm&lt;, pgm, video] The <code>ppm</code>-filter only supports raw rgb ppm files. The <code>pgm</code> file format is the one generated by <code>mpeg2dec</code> of the livid project. ( <a rel="nofollow" href="http://linuxvideo.org">http://linuxvideo.org</a> ) This means: Y-data appended by U and V data which are scaled down by 2 and placed side by side. This option defaults to PPM. Some things you want to keep in mind: </p>
<p> 1) If you want to stream video frames (using video_pattern = &quot;-&quot;) you have to make sure that there is no trailing garbage at the end of the pictures. This is ignored by most image manipulation programs! </p>
<p> 2) If you are one of the poor persons with a buggy PCI bus-mastering board be sure to have a backup handy if you want to use video support. Some versions of the VIA board chipsets crash your machine and even your harddisk. Since encodedv uses full resolution capturing it is more likely to trigger these bugs than other programs. If you have a VIA board you definitely want to upgrade to Linux 2.4.3 or higher. </p>
<p> 3) The encoded pictures must have the correct resolution. If they don&#8217;t, you may want to try ppmqscale. The used video format is chosen by picture resolution. Use 720&#215;576 for PAL and 720&#215;480 for NTSC. </p>
<p> 4) If you want to speed up things a little bit and you are generating the input pictures automatically you may want to try pgm&#8217;s instead of ppm&#8217;s since they are encoded somewhat faster. But keep in mind, that this pgm format is only optimal for PAL since NTSC averages the U and V values somewhat differently.</p>
<dt><code>-a</code>, <code>&#8211;audio-input</code>=<i>filter-name</i></p>
<dd> Choose audio-input-filter: [&gt;none&lt;, wav, dsp]</p>
<dt><code>-o</code>, <code>&#8211;output</code>=<i>filter-name</i></p>
<dd> Choose output-filter: [&gt;raw&lt;]</p>
<dt><code>-q</code>, <code>&#8211;static-qno</code>=<i>table-no</i></p>
<dd> Static qno tables for quantisation on 2 VLC passes. For turbo (but somewhat lossy encoding) try -q [1,2] -p [2,3]. There are only two static qno tables registered right now: </p>
<p> 1 : for sharp DV pictures </p>
<p> 2 : for somewhat noisy satelite television signal </p>
<p> If you want to add some more, go ahead ;-)</p>
<dt><code>-f</code>, <code>&#8211;fps</code>=<i>fps-number</i></p>
<dd> Set frames per second (default: use all frames)</p>
<dt><code>-d, &#8211;force-dct</code>=<i>dct-mode</i></p>
<dd> Force dct mode (88 or 248) for whole picture</dl>
<p> Help Options</p>
<dl>
<dt>&#8211;<code>?</code>, <code>&#8211;help</code></p>
<dd> Show help message.</p>
<dt><code>&#8211;usage</code></p>
<dd> Display brief usage message.</dl>
