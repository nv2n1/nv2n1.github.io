<h2 class="name">NAME</h2>
<p> examiner &#8211; A ELF binary executable analyzer </p>
<h2>SYNOPSIS</h2>
<p> <code>examiner</code> [ <code>-hvVsHRLq</code> ] [ <code>-d directory</code> ] [ <code>-C coroner.conf</code> ] [ <code>-o outfile</code> ] [ <code>-c &#8216;comment char&#8217;</code> ] -x executable</p>
<h2>DESCRIPTION</h2>
<p> The <i>examiner</i> is a program used to analyze and comment on <font SIZE="-1">ELF</font> executables. Its purpose is mainly intended for forensic analysis but can be used for general reverse engineering. The goal is to take a foreign executable and analyze it without running it. The <i>examiner</i> relies on objdump to do its disassembly and then it parses the assembly output and attempts to put human readable comments to help facilitate analysis of the binary. </p>
<p> The commented file will be created with the name of the target binary with the extension of .commented. By default the Examiner creates <i></i>$HOME<i>/examiner-data</i> directory to store its output. This can be overridden with the <code>-d</code> option. Also if The Coroners Toolkit (<font SIZE="-1">TCT</font>) is installed the <i>examiner</i> will use the directory specified by <font SIZE="-1">TCT. </font> See below for more information for using the Examiner with <font SIZE="-1">TCT. </font> You may use the <code>-o</code> option to specify a seperate file for the commented source. If you use <code>-o &#8211;</code> Then Examiner will print the commented source to <font SIZE="-1">STDOUT.</font> </p>
<p> The <i>examiner</i> requires that you use the <code>-x</code> option to specify an executable to analyze. By default the <i>examiner</i> only reports what Phase of analysis it is currently working on. The <i>examiner</i> analyzes binaries in four phases.</p>
<dl>
<dt><font SIZE="-1">PHASE 1 &#8211;</font> Initial analysis and parsing</p>
<dd>
<dt><font SIZE="-1">PHASE 2 &#8211;</font> Passes over the information and collects info</p>
<dd>
<dt><font SIZE="-1">PHASE 3 &#8211;</font> Manipulates collected data to draw conclusions</p>
<dd>
<dt><font SIZE="-1">PHASE 4 &#8211;</font> Generate the commented output</p>
<dd></dl>
<p> If the <code>-v</code> option is used then the program will report on each step within the phase as well. You can also have a brief summary reported that will give you some information about the total number of functions found, etc. If you don&#8217;t want any output you can use the <code>-q</code> option. </p>
<p> The <i>examiner</i> will attempt to read <font SIZE="-1">ASCII</font> strings from the .rodata section headers. It will then cross references this information in its output. It attempts to only print the printable characters and display hex or C style representations for special characters such as &#8216;
&#8217;. In the commented output the <i>examiner</i> will restrict the length of the string. This feature can be overridden with the <code>-L</code> option. This is really not recommended. </p>
<p> You can generate additional reports that may help in analysis. If the <code>-H</code> option is supplied it will dump each section in the executable. The files are stored in the working directory. These files will have the target executables name with the section as an extension, eg: binary.rodata. </p>
<p> You can generate Reference files with the <code>-R</code> option. These files are generated for help in cross referencing information. Currently it will create three files: functions, interrupts, and sections. The function file contains the guessed function name and it&#8217;s address. The interrupts file list any interrupts that are called and what the stack would look like at the time (sort of). The section file contains a list of all section and their memory ranges. </p>
<p> For a brief summary of all the options you can use the <code>-h</code> option. If you supply the <code>-V</code> option <i>examiner</i> will print its version info and then exit.</p>
<h2>USING EXAMINER WITH TCT</h2>
<p> The <i>examiner</i> can optionally be run on a system that has The Coroners Toolkit (<font SIZE="-1">TCT</font>) installed. The Examiner will use some executables when the are installed. The paths to these may be specified in <font SIZE="-1">TCT</font> paths.pl file. The Examiner will also read in the <i>coroner.conf</i> file to locate the section it should use as its working directory. You can specify a different <i>coroner.conf</i> file with the <code>-C</code> option. </p>
<p> The newer version of the Examiner will read in an optional hash library. This library is simply hash references that would normally be generated by parsing the <i>net.h</i> and <i>unistd.h</i> files. This file <i>examiner_hashes.pl</i> will be parsed if its in the current directory or <i>/usr/share/tct</i>. <i>unistd.h</i> is substituted for <i>syscall.h</i> on <font SIZE="-1">BSD</font> based systems. Check the <i>os</i> directory for some pre-created examiner hashes.</p>
