<h2>NAME</h2>
<p> bltk &#8211; tool kit is used to measure battery life and performance under different workloads on Linux.</p>
<h2>SYNOPSIS</h2>
<p> <code>bltk</code> [-hVvaNAcCBXswiIRDPGOYZyQzxul] [-t sec] [-r results_dir] [-m {0,1}] [-U path] [-g setup] [-J pid] [-T time] [-F file] [-W app] [-L title] [-K comment] [-e app] [-E app] [-p percent] [-d percent] [-o {0,1,2}] [-q file] [-b percent] [-f command] [-k num]</p>
<h2>DESCRIPTION</h2>
<p> <code>The BLTK</code> can be used with various workloads to simulate different types of laptop usage. The following workloads are currently implemented:</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>Idle workload</code></p>
<dd> collect statistics only (mostly used to measure battery life)</p>
<dt><code>Developer workload</code></p>
<dd> simulates code development in Linux environment</p>
<dt><code>Reader workload</code></p>
<dd> simulates text reading on laptop (mostly used to measure battery life)</p>
<dt><code>Playback workload</code></p>
<dd> simulates laptop entertaining usage (produces constant average load on the system)</p>
<dt><code>3d game workload</code></p>
<dd> simulates 3D-gaming on laptop (Unreal Tournament demo is used to create this workload)</p>
<dt><code>Office Activity workload</code></p>
<dd> simulates laptop usage for different office activities (based on OpenOffice.org office suit)</dl>
</dl>
<p> When started, test collects platform/OS initial info and if it&#8217;s OK prompts user to unplug AC adapter. After cable unplugged, workload started. During the workload execution test harness collects various system information (e.g. CPU load, battery drain, display state, CPU frequency, etc&#8230;). After battery completely discharged user should plug the AC cable back and boot the system. When it is done the results are available. </p>
<p> There are several tools for result evaluation. They allow creating report file for test run, to gather results into a table for system comparison, and to draw graphs for different purposes. </p>
<p> <code>Results</code> &#8211; after the battery dies and the system booted back, the results are available. They are stored in &#8216;bltk/&lt;wokload_name&gt;.results&#8217; directory (or in the directory, specified in -r option). If target directory already exist the tool will add numeric extension to its name (.001, .002 e.t.c.) The results consist of the following files (see below for detailed description):</p>
<dl>
<dt><code>cmd</code></p>
<dd> In this file &#8216;bltk&#8217; command with arguments are stored</p>
<dt><code>infoi&lt;N&gt;.log (info1.log, info2.log, &#8230;)</code></p>
<dd> Here initial system info is stored. Another two files (info1.log, info2.log) contains system info after AC adapter was unplugged, and on 5% battery capacity remained. They are used to check whether any changes occurred during test execution.</p>
<dt><code>stat.log</code></p>
<dd> Statistics generated by bltk harness are stored here. One statistic line generated per 1 minute (or per number of seconds, specified in -t option).</p>
<dt><code>system&lt;N&gt;</code></p>
<dd> When -k 1 is used, the system information is stored under this directory. The numbers at the end of directory name have the following meanings:</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>0</code></p>
<dd> initial system info</p>
<dt><code>1</code></p>
<dd> system info after AC adapter was unplugged</p>
<dt><code>2</code></p>
<dd> system info on 5% battery capacity remained</dl>
</dl>
<dt><code>version</code></p>
<dd> this file contains version information</p>
<dt><code>workload</code></p>
<dd> the file contains info about workload</p>
<dt><code>work_out.log</code></p>
<dd>
<dt><code>err.log</code></p>
<dd> There are stored any error messages</p>
<dt><code>warning.log</code></p>
<dd> Contains warnings</p>
<dt><code>work.log</code></p>
<dd> Strings generated by USR1, USR2 signals from workload. String format is the same as in the &#8216;stat.log&#8217; file.</p>
<dt><code>fail</code></p>
<dd> when test fails</p>
<dt><code>score</code></p>
<dd>
<dt><code>Report</code></p>
<dd>
<dt><code>Report.table</code></p>
<dd></dl>
<h2>OPTIONS</h2>
<dl>
<dt><code>-h</code>,<code> &#8211;help</code></p>
<dd> Help; display a help message and then exits.</p>
<dt><code>-V,</code> &#8211;version</p>
<dd> Version; display version number and then exits.</p>
<dt><code>-v,</code> &#8211;verbose</p>
<dd> Verbose</p>
<dt><code>-a,</code> &#8211;ac-ignore</p>
<dd> ignore ac adapter state check (on/off)</p>
<dt><code>-N,</code> &#8211;time-stat-ignore</p>
<dd> disable time statistics</p>
<dt><code>-A,</code> &#8211;ac-stat-ignore</p>
<dd> disable ac adapter statistics</p>
<dt><code>-c,</code> &#8211;cpu-stat-ignore</p>
<dd> disable cpu load statistics</p>
<dt><code>-C,</code> &#8211;cpu-add-stat-ignore</p>
<dd> disable cpu additional statistics</p>
<dt><code>-B,</code> &#8211;bat-stat-ignore</p>
<dd> disable battery statistics</p>
<dt><code>-X,</code> &#8211;disp-stat-ignore</p>
<dd> Disable display state statistics</p>
<dt><code>-H,</code> &#8211;hd-stat-ignore</p>
<dd> disable hard drive state statistics</p>
<dt><code>-t </code>seconds,<code> &#8211;report-time </code>seconds</p>
<dd> frequency of report line generation in seconds</p>
<dt><code>-r </code>results_dir,<code> &#8211;results </code>results_dir</p>
<dd> name of results directory</p>
<dt><code>-s,</code> &#8211;stat-ignore</p>
<dd> disable all statistics</p>
<dt><code>-w,</code> &#8211;work-stat-ignore</p>
<dd> disable workload statistics</p>
<dt><code>-m </code>{0,1},<code> &#8211;stat-memory </code>{0,1}</p>
<dd> dump statistics directly on disk or keep in memory, if statistics are kept in memory, it will be dumpedon disk at low battery capacity, or at the test end</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>0</code></p>
<dd> disk</p>
<dt><code>1</code></p>
<dd> memory (by default)</dl>
</dl>
<dt><code>-i,</code> &#8211;idle-test</p>
<dd> idle test</p>
<dt><code>-I,</code> &#8211;idle</p>
<dd> idle workload</p>
<dt><code>-R,</code> &#8211;reader</p>
<dd> reader workload</p>
<dt><code>-D,</code> &#8211;developer</p>
<dd> developer workload</p>
<dt><code>-P,</code>&#8216;<code>&#8211;player</code></p>
<dd> playback workload</p>
<dt><code>-G,</code> &#8211;game</p>
<dd> 3D-gaming workload</p>
<dt><code>-O,</code> &#8211;office</p>
<dd> office productivity workload</p>
<dt><code>-U </code>path,<code> &#8211;user </code>path</p>
<dd> user-specified workload (path to executable)</p>
<dt><code>-g </code>routine,<code> &#8211;user-init </code>routine</p>
<dd> setup routines for user-specified workload</p>
<dt><code>-Y,</code> &#8211;discharging</p>
<dd> battery discharge mode</p>
<dt><code>-Z,</code> &#8211;charging</p>
<dd> battery charge mode</p>
<dt><code>-J </code>pid,<code> &#8211;jobs </code>pid</p>
<dd> make jobs number</p>
<dt><code>-T </code>seconds,<code> &#8211;time </code>seconds</p>
<dd> workload time</p>
<dt><code>-F,</code> &#8211;file</p>
<dd> workload file</p>
<dt><code>-W,</code> &#8211;prog</p>
<dd> workload program <tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>name of player (player workload, default &#8216;mplayer&#8217;)<br />
 <tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>name of web-browser (reader workload, default &#8216;firefox&#8217;)</p>
<dt><code>-L,</code> &#8211;title</p>
<dd> title of web-browser document</p>
<dt><code>-M,</code> &#8211;manufacturer</p>
<dd> enable time and cpu load statistics only</p>
<dt><code>-S,</code> &#8211;show</p>
<dd> demo/debug mode, one iteration only</p>
<dt><code>-n,</code> &#8211;show-num</p>
<dd> demo/debug mode, &#8216;show-num&#8217; iteration</p>
<dt><code>-j,</code> &#8211;show-cnt</p>
<dd> demo/debug mode, &#8216;show-cnt&#8217; sub iteration</p>
<dt><code>-T </code>seconds,<code> &#8211;show-time </code>seconds</p>
<dd> demo/debug mode, debug time</p>
<dt><code>-K </code>comment,<code> &#8211;comment </code>comment</p>
<dd> user comment for report</p>
<dt><code>-e </code>application,<code> &#8211;init-prog </code>application</p>
<dd> run program before test starting</p>
<dt><code>-E </code>application,<code> &#8211;init-prog-su </code>application</p>
<dd> run program as root before test starting</p>
<dt><code>-y,</code> &#8211;yes</p>
<dd> auto &#8216;yes&#8217; answer to all questions</p>
<dt><code>-Q,</code> &#8211;debug</p>
<dd> debug workload (see cpu-load and disp-load below)</p>
<dt><code>-p </code>percent,<code> &#8211;cpu-load </code>percent</p>
<dd> debug workload, the time cpu loaded in percent</p>
<dt><code>-d </code>percent,<code> &#8211;disp-load </code>percent</p>
<dd> Debug workload, the time display on in percent</p>
<dt><code>-o </code>{0,1,2},<code> &#8211;output </code>{0,1,2}</p>
<dd> direct workload output:</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>0</code></p>
<dd> file</p>
<dt><code>1</code></p>
<dd> file and console</p>
<dt><code>2</code></p>
<dd> /dev/null, other &#8211; console</dl>
</dl>
<dt><code>-z,</code> &#8211;debug-vars</p>
<dd> debug option</p>
<dt><code>-q </code>file,<code> &#8211;debug-vars-file </code>file</p>
<dd> debug option &#8211; debug variables file</p>
<dt><code>-x,</code> &#8211;dpms</p>
<dd> debug option &#8211; try to use display power management</p>
<dt><code>-u,</code> &#8211;spy</p>
<dd> debug option &#8211; try to find out unexpected system activity</p>
<dt><code>-l,</code> &#8211;simul-laptop</p>
<dd> debug option, laptop simulation</p>
<dt><code>-b </code>percent,<code> &#8211;bat-sync </code>percent</p>
<dd> debug option, battery critical capacity, default 5%</p>
<dt><code>-f </code>command,<code> &#8211;user-field </code>command</p>
<dd> the output of user-specified command being added to statistics Example: <tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>-f &quot;cat /proc/acpi/thermal_zone/TZ01/temperature | awk &#8216;{print 2}&#8217;&quot;</p>
<dt><code>-k </code>num,<code> &#8211;stat-system </code>num</p>
<dd> debug option, save system files, default 0</dl>
<h2>EXAMPLES</h2>
<dl>
<dt>bltk -I or &#8211;idle</p>
<dd> idle workload running</p>
<dt>bltk -R or &#8211;reader</p>
<dd> reader workload running</p>
<dt>bltk -D or &#8211;developer</p>
<dd> developer workload running</p>
<dt>bltk -O or &#8211;office</p>
<dd> office workload running</p>
<dt>bltk -P or &#8211;player</p>
<dd> player workload running</p>
<dt>bltk -G or &#8211;game</p>
<dd> game workload running</p>
<dt>bltk -i or &#8211;idle-test -T 60 -t 1</p>
<dd> idle test running for 60 seconds, stats interval 1 second</dl>
