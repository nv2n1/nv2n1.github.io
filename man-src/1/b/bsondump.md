<h2>NAME</h2>
<p> bsondump &#8211; MongoDB BSON Utility</p>
<h2>SYNOPSIS</h2>
<p> The <code>bsondump</code> converts <i>BSON</i> files into human-readable formats, including <i>JSON</i>. For example, <code>bsondump</code> is useful for reading the output files generated by <code>mongodump</code>. </p>
<p> <code>IMPORTANT:</code> <code>bsondump</code> is a diagnostic tool for inspecting BSON files, not a tool for data ingestion or other application use.</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>bsondump</code></p>
<dd>
<dt><code>bsondump</code></p>
<dd>
<dt><code>&#8211;help, -h</code></p>
<dd> Returns information on <code>bsondump</code> options and usage.</p>
<dt><code>&#8211;verbose, -v</code></p>
<dd> Increases the amount of internal reporting returned on standard output or in log files. Increase the verbosity with the <code>-v</code> form by including the option multiple times, (e.g. <code>-vvvvv</code>.)</p>
<dt><code>&#8211;quiet</code></p>
<dd> Runs <code>bsondump</code> in a quiet mode that attempts to limit the amount of output. This option suppresses:</p>
<dt>&bull;</p>
<dd> output from <i>database commands</i></p>
<dt>&bull;</p>
<dd> replication activity</p>
<dt>&bull;</p>
<dd> connection accepted events</p>
<dt>&bull;</p>
<dd> connection closed events</p>
<dt><code>&#8211;version</code></p>
<dd> Returns the <code>bsondump</code> release number.</p>
<dt><code>&#8211;objcheck</code></p>
<dd> Validates each <i>BSON</i> object before outputting it in <i>JSON</i> format. By default, <code>bsondump</code> enables <i>&#8211;objcheck</i>. For objects with a high degree of sub-document nesting, <i>&#8211;objcheck</i> can have a small impact on performance. You can set <i>&#8211;noobjcheck</i> to disable object checking. </p>
<p> Changed in version 2.4: MongoDB enables <i>&#8211;objcheck</i> by default, to prevent any client from inserting malformed or invalid BSON into a MongoDB database. </p>
<dt><code>&#8211;noobjcheck</code></p>
<dd> New in version 2.4. </p>
<p> Disables the default document validation that MongoDB performs on all incoming BSON documents.</p>
<dt><code>&#8211;filter &lt;JSON&gt;</code></p>
<dd> Limits the documents that <code>bsondump</code> exports to only those documents that match the <i>JSON document</i> specified as <code>&#8216;&lt;JSON&gt;&#8217;</code>. Be sure to include the document in single quotes to avoid interaction with your system&#8217;s shell environment.</p>
<dt><code>&#8211;type &lt;=json|=debug&gt;</code></p>
<dd> Changes the operation of <code>bsondump</code> from outputting &quot;<i>JSON</i>&quot; (the default) to a debugging format.</p>
<dt><code>&lt;bsonFilename&gt;</code></p>
<dd> The final argument to <code>bsondump</code> is a document containing <i>BSON</i>. This data is typically generated by <code>bsondump</code> or by MongoDB in a <i>rollback</i> operation.</dl>
<h2>USE</h2>
<p> By default, <code>bsondump</code> outputs data to standard output. To create corresponding <i>JSON</i> files, you will need to use the shell redirect. See the following command: </p>
<pre>
bsondump collection.bson &gt; collection.json
</pre>
<p> Use the following command (at the system shell) to produce debugging output for a <i>BSON</i> file: </p>
<pre>
bsondump --type=debug collection.bson
</pre>
