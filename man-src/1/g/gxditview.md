<h2 class="name">NAME</h2>
<p> gxditview &#8211; display groff intermediate output files </p>
<h2>SYNOPSIS</h2>
<p> [<i>X-toolkit-option</i>&#8230;] [ <code>-backingStore </code><i>backing-store-type</i> ] [ <code>-filename </code><i>string</i> ] [ <code>-page </code><i>n</i> ] [ <code>-printCommand </code><i>string</i> ] [ <code>-resolution </code><i>res</i> ] [<i>file</i>] <code>-help</code> <code>&#8211;help</code></p>
<h2>DESCRIPTION</h2>
<p> The <code>gxditview</code> program displays the <i>groff intermediate</i> <i>output</i>, see <code><a href="/docs/linux/man/5-groff_out/">groff_out</a></code>(5), on an X~display. It uses the standard X11 fonts, so it does not require access to the server machine for font loading. There are several ways to use <code>gxditview</code>. </p>
<p> The <i>groff intermediate output</i> can be generated by <code>groff~-Z</code>. This can be viewed by explicitly calling <code>gxditview</code> <i>filename</i>. If <i>filename</i> is <code>&#8211;</code>, <code>gxditview</code> will read the standard input; <i>filename</i> cannot be omitted. The <i>groff intermediate output</i> is different for all devices. <code>gxditview</code> can view it for all devices, but the quality is device dependent. </p>
<p> The best results are achieved with the <code>X</code>* devices for <code>groff</code>&#8216;s option <code>-T</code>. There are four <code>X</code>* devices: <code>-TX75</code>, <code>-TX75-12</code>, <code>-TX100</code>, <code>-TX100-12</code>. They differ by the X~resolution (75dpi or 100dpi) and the used base font size (10pt or 12pt). They are especially built for <code>gxditview</code>. When using one of them <code>groff</code> generates the <i>intermediate output</i> for this device and calls <code>gxditview</code> automatically for viewing. For example, to view this man page with a base resolution of 12pt, say</p>
<dl>
<dt>
<dd> <code>groff -TX100-12 -man -rS12 gxditview.1</code></dl>
<p> (option <code>-rS</code><i>XX</i> is documented in the <code><a href="/docs/linux/man/7-groff_man/">groff_man</a></code>(7) man page). </p>
<p> <code>groff</code>&#8216;s option <code>-X</code> produces <i>intermediate output</i> for the <i>PostScript</i> device and subsequently uses <code>gxditview</code> as a viewer for it. The quality of the result depends mainly on the chosen point size and display resolution; for rapid previewing, however, something like</p>
<dl>
<dt>
<dd> <code>groff -X -P-resolution -P100 </code><i>document</i></dl>
<p> yields acceptable results. </p>
<p> During the run of <code>gxditview</code>, the left mouse button brings up a menu with the following entries:</p>
<dl>
<dt><code>Next Page</code></p>
<dd> Display the next page.</p>
<dt><code>Previous Page</code></p>
<dd> Display the previous page.</p>
<dt><code>Select Page</code></p>
<dd> Select a particular numbered page specified by a dialog box.</p>
<dt><code>Print</code></p>
<dd> Print the <i>groff intermediate output</i> using a command specified by a dialog box. The default command initially displayed is controlled by the <code>printCommand</code> application resource, and by the <code>-printCommand</code> option.</p>
<dt><code>Open</code></p>
<dd> Open for display a new file specified by a dialog box. The file should contain some <i>groff intermediate</i> <i>output</i>. If the filename starts with <code>|</code> it will be taken to be a command to read from.</p>
<dt><code>Quit</code></p>
<dd> Exit from <code>gxditview</code>.</dl>
<p> The <i>n</i>, <i>Space</i>, <i>Return</i>, and <i>Next</i> (<i>PgDn</i>) keys are bound to the <code>Next Page</code> action. The <i>p</i>, <i>b</i>, <i>BackSpace</i>, <i>Delete</i>, and <i>Prior</i> (<i>PgUp</i>) keys are bound to the <code>Previous Page</code> action. The <i>g</i> key is bound to the <code>SelectPage</code> action. The <i>o</i> key is bound to the <code>OpenFile</code> action. The <i>q</i> key is bound to the <code>Quit</code> action. The <i>r</i> key is bound to the <code>Rerasterize</code> action which rereads the current file, and redisplays the current page; if the current file is a command, the command will be reexecuted. Vertical scrolling can be done with the <i>k</i> and <i>j</i> keys; horizontal scrolling is bound to the <i>h</i> and <i>l</i> keys. The arrow keys (<i>up</i>, <i>down</i>, <i>left</i>, and <i>right</i>) are also bound to the obvious scrolling actions. </p>
<p> The <code>paperlength</code> and <code>paperwidth</code> commands in the <i>DESC</i> file specify the length and width in machine units of the virtual page displayed by <code>gxditview</code>.</p>
<h2>OPTIONS</h2>
<p> The <code>gxditview</code> program accepts all of the standard X~Toolkit command-line options along with the additional options listed below:</p>
<dl>
<dt><code>-help</code></p>
<dd> This option indicates that a brief summary of the allowed options should be printed.</p>
<dt><code>-page</code></p>
<dd> This option specifies the page number of the document to be displayed.</p>
<dt><code>-backingStore&nbsp;</code><i>backing-store-type</i></p>
<dd> Redisplay of the <i>groff intermediate output</i> window can take up to a second or so, this option causes the server to save the window contents so that when it is scrolled around the viewport, the window is painted from contents saved in backing store. <i>backing-store-type</i> can be one of <code>Always</code>, <code>WhenMapped</code> or <code>NotUseful</code>.</p>
<dt><code>-printCommand&nbsp;</code><i>command</i></p>
<dd> The default command displayed in the dialog box for the <code>Print</code> menu entry will be <i>command</i>.</p>
<dt><code>-resolution&nbsp;</code><i>res</i></p>
<dd> The <i>groff intermediate output</i> file will be displayed at a resolution of <i>res</i> dpi, unless the <i>DESC</i> file contains the <code>X11</code> command, in which case the device resolution will be used. This corresponds to the <i>Dvi</i> widget&#8217;s <code>resolution</code> resource. The default is 75.</p>
<dt><code>-filename&nbsp;</code><i>string</i></p>
<dd> The default filename displayed in the dialog box for the <code>Open</code> menu entry will be <i>string</i>. This can be either a filename, or a command starting with <code>|</code>.</dl>
<p> The following standard X~Toolkit command-line arguments are commonly used with <code>gxditview</code>:</p>
<dl>
<dt><code>-bg&nbsp;</code><i>color</i></p>
<dd> This option specifies the color to use for the background of the window. The default is <i>white</i>.</p>
<dt><code>-bd&nbsp;</code><i>color</i></p>
<dd> This option specifies the color to use for the border of the window. The default is <i>black</i>.</p>
<dt><code>-bw&nbsp;</code><i>number</i></p>
<dd> This option specifies the width in pixels of the border surrounding the window.</p>
<dt><code>-fg&nbsp;</code><i>color</i></p>
<dd> This option specifies the color to use for displaying text. The default is <i>black</i>.</p>
<dt><code>-fn&nbsp;</code><i>font</i></p>
<dd> This option specifies the font to be used for displaying widget text. The default is <i>fixed</i>.</p>
<dt><code>-rv</code></p>
<dd> This option indicates that reverse video should be simulated by swapping the foreground and background colors.</p>
<dt><code>-geometry&nbsp;</code><i>geometry</i></p>
<dd> This option specifies the preferred size and position of the window.</p>
<dt><code>-display&nbsp;</code><i>host</i><code>:</code><i>display</i></p>
<dd> This option specifies the X~server to contact.</p>
<dt><code>-xrm&nbsp;</code><i>resourcestring</i></p>
<dd> This option specifies a resource string to be used.</dl>
