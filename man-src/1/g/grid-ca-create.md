<h2 class="name">NAME</h2>
<p> grid-ca-create &#8211; Create a CA to sign certificates for use on a grid </p>
<h2>SYNOPSIS</h2>
<p> <code>grid-ca-create</code> [ -h | -help | -usage | -version | -versions ] [ -openssl-help] </p>
<p> <code>grid-ca-create</code> [ OPTIONS ] [ OPENSSL-OPTIONS ]</p>
<h2>DESCRIPTION</h2>
<p> The <code>grid-ca-create</code> program creates a self-signed CA certificate and related files needed to use the CA with other Globus tools. The <code>grid-ca-create</code> program prompts for information to use to generate the CA certificate, but the prompts may be avoided by using the command line options. </p>
<p> By default, the <code>grid-ca-create</code> program creates the self-signed CA certificate, installs it on the current machine in its trusted certificate directory, and creates a source tarball which can be used to generate an RPM package for the CA. If the RPM package is installed on a machine, users on that machine can create certificate requests for user, host, or service identity certificates to be signed by the CA certificate generated by running <code>grid-ca-create</code>. </p>

<h2>OPTIONS</h2>
<p> The full set of command-line options to <code>grid-ca-create</code> follows. In addition to these, unknown options will be passed to the openssl command when creating the self-signed certificate. </p>
<p> <code>-help, -h, -usage</code></p>
<dl>
<dt>
<dd> Display the command-line options to <code>grid-ca-create</code> and exit.</dl>
<p> <code>-version, -versions</code></p>
<dl>
<dt>
<dd> Display the version number of the <code>grid-ca-create</code> command. The second form includes more details.</dl>
<p> <code>-force</code></p>
<dl>
<dt>
<dd> Overwite existing CA in the destination directory if one exists.</dl>
<p> <code>-bits BITS</code></p>
<dl>
<dt>
<dd> Create a CA certificate with a BITS long RSA key [4096]</dl>
<p> <code>-noint</code></p>
<dl>
<dt>
<dd> Run in non-interactive mode. This will choose defaults for parameters or those specified on the command line without prompting. This option also implies <i>-force</i>.</dl>
<p> <code>-dir </code><i>DIRECTORY</i></p>
<dl>
<dt>
<dd> Create the CA in <i>DIRECTORY</i>. The <i>DIRECTORY</i> must not exist prior to running <code>grid-ca-create</code>.</dl>
<p> <code>-subject </code><i>SUBJECT</i></p>
<dl>
<dt>
<dd> Use <i>SUBJECT</i> as the subject name of the self-signed CA to create. If this is not specified on the command-line, <code>grid-ca-create</code> will default to using the subject name cn=Globus Simple CA, ou=$HOSTNAME, ou=GlobusTest, o=Grid.</dl>
<p> <code>-email </code><i>ADDRESS</i></p>
<dl>
<dt>
<dd> Use <i>ADDRESS</i> as the email address of the CA. The default instructions generated by <code>grid-ca-create</code> tell users to mail the certificate request to this address. If this is not specified on the command-line, <code>grid-ca-create</code> will default to $LOGNAME@$HOSTNAME.</dl>
<p> <code>-days </code><i>DAYS</i></p>
<dl>
<dt>
<dd> Set the default lifetime of the self-signed CA certificate to <i>DAYS</i>. If not set, the <code>grid-ca-create</code> program will default to 1825 days (5 years).</dl>
<p> <code>-pass </code><i>PASSWORD</i></p>
<dl>
<dt>
<dd> Use the string <i>PASSWORD</i> to protect the CA&#8217;s private key. This is useful for automating Simple CA, but may make it easier to compromise the CA if someone obtains a shell on the machine storing the CA&#8217;s private key.</dl>
<p> <code>-nobuild</code></p>
<dl>
<dt>
<dd> Disable building a source tarball for distributing the CA&#8217;s public information to other machines. The source tarball can be created later by using the <code>grid-ca-package</code> command.</dl>
<p> <code>-g</code></p>
<dl>
<dt>
<dd> Create a binary GPT package containing the new CA&#8217;s public information. The package will be created in the current working directory. This package can be deployed by with the <code>gpt-install</code> tool.</dl>
<p> <code>-b</code></p>
<dl>
<dt>
<dd> Create a binary GPT package containing the new CA&#8217;s public information that is backward-compatible with GPT 3.2. Packages created in this manner will work with Globus Toolkit 2.0.0-5.0.x.</dl>
