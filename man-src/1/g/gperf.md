<h2>NAME</h2>
<p> gperf &#8211; generate a perfect hash function from a key set</p>
<h2>SYNOPSIS</h2>
<p> <code>gperf</code> [<i>OPTION</i>]&#8230; [<i>INPUT-FILE</i>]</p>
<h2>DESCRIPTION</h2>
<p> GNU &#8216;gperf&#8217; generates perfect hash functions. </p>
<p> If a long option shows an argument as mandatory, then it is mandatory for the equivalent short option also.</p>
<h3>Output file location:</h3>
<dl>
<dt> <code>&#8211;output-file</code>=<i>FILE</i> Write output to specified file.</dl>
<dd>The results are written to standard output if no output file is specified or if it is -.</p>
<h3>Input file interpretation:</h3>
<dl>
<dt><code>-e</code>, <code>&#8211;delimiters</code>=<i>DELIMITER-LIST</i></p>
<dd> Allow user to provide a string containing delimiters used to separate keywords from their attributes. Default is &quot;,&quot;.</p>
<dt><code>-t</code>, <code>&#8211;struct-type</code></p>
<dd> Allows the user to include a structured type declaration for generated code. Any text before %% is considered part of the type declaration. Key words and additional fields may follow this, one group of fields per line.</p>
<dt><code>&#8211;ignore-case</code></p>
<dd> Consider upper and lower case ASCII characters as equivalent. Note that locale dependent case mappings are ignored.</dl>
<h3>Language for the output code:</h3>
<dl>
<dt><code>-L</code>, <code>&#8211;language</code>=<i>LANGUAGE-NAME</i></p>
<dd> Generates code in the specified language. Languages handled are currently C++, ANSI-C, C, and KR-C. The default is C.</dl>
<h3>Details in the output code:</h3>
<dl>
<dt><code>-K</code>, <code>&#8211;slot-name</code>=<i>NAME</i></p>
<dd> Select name of the keyword component in the keyword structure.</p>
<dt><code>-F</code>, <code>&#8211;initializer-suffix</code>=<i>INITIALIZERS</i></p>
<dd> Initializers for additional components in the keyword structure.</p>
<dt><code>-H</code>, <code>&#8211;hash-function-name</code>=<i>NAME</i></p>
<dd> Specify name of generated hash function. Default is &#8216;hash&#8217;.</p>
<dt><code>-N</code>, <code>&#8211;lookup-function-name</code>=<i>NAME</i></p>
<dd> Specify name of generated lookup function. Default name is &#8216;in_word_set&#8217;.</p>
<dt><code>-Z</code>, <code>&#8211;class-name</code>=<i>NAME</i></p>
<dd> Specify name of generated C++ class. Default name is &#8216;Perfect_Hash&#8217;.</p>
<dt><code>-7</code>, <code>&#8211;seven-bit</code></p>
<dd> Assume 7-bit characters.</p>
<dt><code>-l</code>, <code>&#8211;compare-lengths</code></p>
<dd> Compare key lengths before trying a string comparison. This is necessary if the keywords contain NUL bytes. It also helps cut down on the number of string comparisons made during the lookup.</p>
<dt><code>-c</code>, <code>&#8211;compare-strncmp</code></p>
<dd> Generate comparison code using strncmp rather than strcmp.</p>
<dt><code>-C</code>, <code>&#8211;readonly-tables</code></p>
<dd> Make the contents of generated lookup tables constant, i.e., readonly.</p>
<dt><code>-E</code>, <code>&#8211;enum</code></p>
<dd> Define constant values using an enum local to the lookup function rather than with defines.</p>
<dt><code>-I</code>, <code>&#8211;includes</code></p>
<dd> Include the necessary system include file &lt;string.h&gt; at the beginning of the code.</p>
<dt><code>-G</code>, <code>&#8211;global-table</code></p>
<dd> Generate the static table of keywords as a static global variable, rather than hiding it inside of the lookup function (which is the default behavior).</p>
<dt><code>-P</code>, <code>&#8211;pic</code></p>
<dd> Optimize the generated table for inclusion in shared libraries. This reduces the startup time of programs using a shared library containing the generated code.</p>
<dt><code>-Q</code>, <code>&#8211;string-pool-name</code>=<i>NAME</i></p>
<dd> Specify name of string pool generated by option <code>&#8211;pic</code>. Default name is &#8216;stringpool&#8217;.</p>
<dt><code>&#8211;null-strings</code></p>
<dd> Use NULL strings instead of empty strings for empty keyword table entries.</p>
<dt><code>-W</code>, <code>&#8211;word-array-name</code>=<i>NAME</i></p>
<dd> Specify name of word list array. Default name is &#8216;wordlist&#8217;.</p>
<dt><code>&#8211;length-table-name</code>=<i>NAME</i></p>
<dd> Specify name of length table array. Default name is &#8216;lengthtable&#8217;.</p>
<dt><code>-S</code>, <code>&#8211;switch</code>=<i>COUNT</i></p>
<dd> Causes the generated C code to use a switch statement scheme, rather than an array lookup table. This can lead to a reduction in both time and space requirements for some keyfiles. The COUNT argument determines how many switch statements are generated. A value of 1 generates 1 switch containing all the elements, a value of 2 generates 2 tables with 1/2 the elements in each table, etc. If COUNT is very large, say 1000000, the generated C code does a binary search.</p>
<dt><code>-T</code>, <code>&#8211;omit-struct-type</code></p>
<dd> Prevents the transfer of the type declaration to the output file. Use this option if the type is already defined elsewhere.</dl>
<h3>Algorithm employed by gperf:</h3>
<dl>
<dt><code>-k</code>, <code>&#8211;key-positions</code>=<i>KEYS</i></p>
<dd> Select the key positions used in the hash function. The allowable choices range between 1-255, inclusive. The positions are separated by commas, ranges may be used, and key positions may occur in any order. Also, the meta-character &#8216;*&#8217; causes the generated hash function to consider ALL key positions, and $ indicates the &quot;final character&quot; of a key, e.g., $,1,2,4,6-10.</p>
<dt><code>-D</code>, <code>&#8211;duplicates</code></p>
<dd> Handle keywords that hash to duplicate values. This is useful for certain highly redundant keyword sets.</p>
<dt><code>-m</code>, <code>&#8211;multiple-iterations</code>=<i>ITERATIONS</i></p>
<dd> Perform multiple choices of the <code>-i</code> and <code>-j</code> values, and choose the best results. This increases the running time by a factor of ITERATIONS but does a good job minimizing the generated table size.</p>
<dt><code>-i</code>, <code>&#8211;initial-asso</code>=<i>N</i></p>
<dd> Provide an initial value for the associate values array. Default is 0. Setting this value larger helps inflate the size of the final table.</p>
<dt><code>-j</code>, <code>&#8211;jump</code>=<i>JUMP-VALUE</i></p>
<dd> Affects the &quot;jump value&quot;, i.e., how far to advance the associated character value upon collisions. Must be an odd number, default is 5.</p>
<dt><code>-n</code>, <code>&#8211;no-strlen</code></p>
<dd> Do not include the length of the keyword when computing the hash function.</p>
<dt><code>-r</code>, <code>&#8211;random</code></p>
<dd> Utilizes randomness to initialize the associated values table.</p>
<dt><code>-s</code>, <code>&#8211;size-multiple</code>=<i>N</i></p>
<dd> Affects the size of the generated hash table. The numeric argument N indicates &quot;how many times larger or smaller&quot; the associated value range should be, in relationship to the number of keys, e.g. a value of 3 means &quot;allow the maximum associated value to be about 3 times larger than the number of input keys&quot;. Conversely, a value of 1/3 means &quot;make the maximum associated value about 3 times smaller than the number of input keys&quot;. A larger table should decrease the time required for an unsuccessful search, at the expense of extra table space. Default value is 1.</dl>
<h3>Informative output:</h3>
<dl>
<dt><code>-h</code>, <code>&#8211;help</code></p>
<dd> Print this message.</p>
<dt><code>-v</code>, <code>&#8211;version</code></p>
<dd> Print the gperf version number.</p>
<dt><code>-d</code>, <code>&#8211;debug</code></p>
<dd> Enables the debugging option (produces verbose output to the standard error).</dl>
