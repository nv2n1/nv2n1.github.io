<h2>NAME</h2>
<p> generatorrunner &#8211; plugin-based binding source code generator</p>
<h2>SYNOPSIS</h2>
<p> <code>generatorrunner &#8211;generator-set=&lt;plugin name&gt; [options] header-file typesystem-file</code></p>
<h2>DESCRIPTION</h2>
<p> <code>generatorrunner</code> is a utility that uses the information taken from APIExtractor related to the provided C++ headers and typesystem files and execute generators using this information. Generators are plugins and you need to specify one using the &#8211;generator-set parameter. At the moment there are two generators available: </p>
<p> <code>qtdoc</code> &#8211; Generates Sphinx-based documentation for C++ libraries documented using <code>qdoc3</code> documentation syntax, using the XML files created by the documentation tool <code>(qdoc3).</code> Can be called supplying <code>&#8211;generator-set=qtdoc</code> to <code>generatorrunner</code> or by calling the convenience executable <code>docgenerator.</code> </p>
<p> Other plugins can be used with <code>generatorrunner,</code> provided that they follow the generator front-end specifications, and can be written to generate code or documentation for any target languague you desire. For more information about the generator front-end architecture and current limitations, refer to <a rel="nofollow" href="http://www.pyside.org/home-binding.">http://www.pyside.org/home-binding.</a> </p>
<h2>OPTIONS</h2>
<h3>General options</h3>
<dl>
<dt>&#8211;api-version=&lt;version&gt;</p>
<dd> Specify the supported api version used to generate the bindings.</p>
<dt>&#8211;debug-level=[sparse|medium|full]</p>
<dd> The amount of messages displayed.</p>
<dt>&#8211;documentation-only</p>
<dd> Only generates the documentation.</p>
<dt>&#8211;drop-type-entries=&lt;TypeEntry0&gt;[;TypeEntry1;&#8230;]</p>
<dd> Semicolon separated list of type system entries (classes, namespaces, global functions and enums) to be dropped from generation.</p>
<dt>&#8211;help</p>
<dd> Prints the usage message.</p>
<dt>&#8211;project-file=&lt;file&gt;</p>
<dd> Text file containing a description of the binding project. Replaces and overrides command line arguments.</p>
<dt>&#8211;include-paths=<i>&lt;path&gt;[:path:..]</i></p>
<dd> The directories where the generator will search for the headers. Works like gcc&#8217;s -I flag.</p>
<dt>&#8211;license-file=<i>[licensefile]</i></p>
<dd> Template for copyright headers of generated files.</p>
<dt>&#8211;no-supress-warnings</p>
<dd> Show all warnings.</p>
<dt>&#8211;output-directory=<i>[dir]</i></p>
<dd> The directory where the generated files will be written.</p>
<dt>&#8211;silent</p>
<dd> Avoid printing any messages.</p>
<dt>&#8211;typesytem-paths=<i>&lt;path&gt;[:path:..]</i></p>
<dd> The directories where the generator will search for the external typesystems referred by the main one.</p>
<dt>&#8211;version</p>
<dd> Displays the current version. Drops support for named args.</dl>
<h3>Specific to qtdoc plugin</h3>
<dl>
<dt>&#8211;documentation-code-snippets-dir</p>
<dd> Directory used to search code snippets used by the documentation</p>
<dt>&#8211;documentation-data-dir</p>
<dd> Directory with XML files generated by documentation tool (qdoc3 or Doxygen)</p>
<dt>&#8211;documentation-out-dir</p>
<dd> The directory where the generated documentation files will be written</p>
<dt>&#8211;library-source-dir</p>
<dd> Directory where library source code is located </p>
</dl>
