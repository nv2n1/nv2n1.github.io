<h2>NAME</h2>
<p> gtranslator &#8212; a comfortable gettext po file editor with many bells and whistles. </p>
<h2>SYNOPSIS</h2>
<p> <code>gtranslator [ &#8211;help ] [ &#8211;version ] [ -a filename ] [ -e po-file ] [ -g geometry-string ] [ -l po-file-to-learn ] [ -b ] [ -s ]</code> </p>
<h2>DESCRIPTION</h2>
<p> gtranslator is a comfortable gettext po file editor with many features like special char featured editing, plural forms view, div. charset support, comfortable prefs, list view of messages, regular expression based search function, compile/update possiblities and much much more. </p>
<dl>
<dt>Of course all standard features of a good application like DnD, session support, supplement files for mime types and menu items are present.</p>
<dd>
<dt>Instant comment view, a comfortable quick navigation messages table with customizable colors, colorschemes, UTF-8 support, a high level of preferizabilation and a personal learn buffer/translation memory with autotranslation capabilities are the main features of gtranslator besides the comfortable editing of the translation entries.</p>
<dd></dl>
<h2>OPTIONS</h2>
<dl>
<dt><i>-a &#8211;auto-translate=po-file</i></p>
<dd> Autotranslates the given po file with the entries from the learn buffer and exits afterwards.</p>
<dt><i>-e &#8211;export-learn-buffer=po-file-to-export</i></p>
<dd> Exports the learn buffer contents into the given plain gettext po file and exits.</p>
<dt><i>-g &#8211;geometry=geometry</i></p>
<dd> Let&#8217;s you specify the geometry of gtranslator&#8217;s main window.</p>
<dt><i>-b &#8211;build-informations</i></p>
<dd> Shows the build specifications (date, time, versions, directories) of gtranslator.</p>
<dt><i>-l &#8211;learn=po-file-to-learn</i></p>
<dd> Learns the given po file within the command line without starting the GUI. The personal learn buffer is used as a translation memory to autoaccomplish missing translations/entries.</p>
<dt><i>-s &#8211;learn-statistics</i></p>
<dd> Print out some statistics and information about the learn buffer of gtranslator on the commandline.</p>
<dt><i>&#8211;display</i></p>
<dd> With this option you can select on which screen gtranslator should appear.</p>
<dt><i>&#8211;help</i></p>
<dd> Shows you a little help autogenerated by GNOME and with the options mentioned above.</p>
<dt><i>&#8211;version</i></p>
<dd> Prints out the version number of gtranslator.</p>
<dt><i>&#8211;usage</i></p>
<dd> Shows you the pill of options without an explanation.</dl>
<h2>FILES</h2>
<dl>
<dt><code>~/.gconf/apps/gtranslator</code></p>
<dd>
<dt>Your personal gtranslator settings will be stored there.</p>
<dd>
<dt><code>~/.gtranslator</code></p>
<dd> This directory is used by gtranslator for all it&#8217;s &quot;private&quot; files (e.g. temporary files).</p>
<dt><code>~/.gtranslator/colorschemes/</code></p>
<dd> Your personal colorschemes can be placed in this directory &#8212; gtranslator does also list the colorschemes in this directory in the colorscheme selection box.</p>
<dt><code>~/.gtranslator/etstates/</code></p>
<dd> The state file for the messages table/tree is stored in this directory.</p>
<dt><code>~/.gtranslator/umtf/</code></p>
<dd> Your personal learn buffers (in UMTF format) are stored in this directory &#8212; the learn buffer is used for auto translation issues.</p>
<dt><code>~/.gtranslator/files/</code></p>
<dd> Temporary files used by gtranslator are stored in this directory (mostly this directory should be empty).</dl>
<h2>LEARN BUFFER</h2>
<p> The learn buffer is the implementation of a personal translation memory (TM) in gtranslator. gtranslator uses the <code>UMTF</code> (a compressed XML file which is normally quite good human readable if uncompressed) format for storing it&#8217;s learned strings.<br />
 Your learned strings are then available for the autotranslation feature of gtranslator where gtranslator automatically fills in the corresponding and valuable translations for any message which has already been learned previously. This results in a fairly high percentage of prefilled/pretranslated messages.<br />
 The common and good style of working with the learn buffer and with the autotranslation should be to learn the main po/translation files for your language via gtranslator via calling <code>gtranslator -n -l po-file-to-learn</code> on the command line; this will put the translated strings from this po file into your personal learn buffer.<br />
 You should learn the main po files (for GNOME for example <code>gnumeric</code>, <code>nautilus</code>, <code>evolution</code> or any other bigger, already translated package&#8217;s po file) for your language); you can use a new script from the gtranslator package to automatise this task a little bit: it&#8217;s &#8220;build-gtranslator-learn-buffer.sh&#8221; which is installed into gtranslator&#8217;s scripts directory which you can see by calling <code>gtranslator -b</code> and you simply execute the script with it&#8217;s full path and simply follow the informations on the command line for it.<br />
 Afterwards you can simply use the &quot;Autotranslation&quot; menu entry from the GUI or use the &quot;F10&quot; hotkey to let gtranslator autotranslate all missing translations from your personal learn buffer. This will ease your translation work and make a big portion of the po files be pre-translated.<br />
 With a fairly big personal learn buffer of about 2 MB you can achive many pre-translated messages for a new project/translation.<br />
 If you want to use the stored learn buffer contents to produce a po file with all the &#8220;learned&#8221; translations, you can also use the &#8220;export learn buffer&#8221; capability of gtranslator to get a plain po file version of the learn buffer.</p>
<h2>USAGE EXAMPLES</h2>
<p> Some examples for the options. </p>
<dl>
<dt><code>gtranslator -b</code></p>
<dd> Shows you the real build specs/dates of gtranslator. </p>
<dt><code>gtranslator -s</code></p>
<dd> Give me statistics about the learn buffer of gtranslator. </p>
<dt><code>gtranslator -n -l po-file-to-learn</code></p>
<dd> Learns the given po file &#8220;po-file-to-learn&#8221; on the command line without starting up the GUI. </p>
<dt><code>gtranslator -a po-file</code></p>
<dd> Autotranslates all missing entries from the learn buffer if possible and exits. </p>
<dt><code>gtranslator -e po-file-to-export</code></p>
<dd> Exports your current learn buffer to the given plain gettext po file (&#8220;po-file-to-export&#8221;). </p>
<dt><code>gtranslator po-file</code></p>
<dd> Starts gtranslator with the given po-file loaded on startup. </p>
<dt><code>gtranslator -g &#8220;460&#215;320+0+0&#8221;</code></p>
<dd> Lets gtranslator appear on the left upper edge of the screen &#8220;+0+0&#8221; and gtranslator is sized to &#8220;460&#215;320&#8221; if possible &#8212; if gtranslator needs more size for it&#8217;s window contents, it&#8217;ll expand itself to the necessary dimensions &#8212; even if you defined a smaller geometry string. </p>
</dl>
