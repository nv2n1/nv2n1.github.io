<h2>NAME</h2>
<p> gtkwave &#8211; Visualization tool for VCD, LXT, LXT2, VZT, FST, and GHW files</p>
<h2>SYNTAX</h2>
<p> gtkwave [<i>option</i>]&#8230; [<i>DUMPFILE</i>] [<i>SAVEFILE</i>] [<i>RCFILE</i>] </p>
<h2>DESCRIPTION</h2>
<p> Visualization tool for VCD, LXT, LXT2, VZT, FST, and GHW. VCD is an industry standard simulation dump format. LXT, LXT2, VZT, and FST have been designed specifically for use with gtkwave. GHW is the native VHDL format generated by GHDL. Native dumpers exist in Icarus Verilog and the open source version of VeriWell for the LXT formats so conversion with <i><a href="/docs/linux/man/1-vcd2lxt/">vcd2lxt</a></i>(1) or <i><a href="/docs/linux/man/1-vcd2lxt2/">vcd2lxt2</a></i>(1) is not necessary to take direct advantage of LXT with those simulators. AET2 files can also be processed provided that libae2rw is available but this is only of interest to people who use IBM EDA toolsets.</p>
<h2>OPTIONS</h2>
<dl>
<dt>
<dd>
<p> <code>-n</code>,<code>&#8211;nocli</code> &lt;<i>directory name</i>&gt; Use file requester for dumpfile name.</p>
<dt><code>-f</code>,<code>&#8211;dump</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify dumpfile name.</p>
<dt><code>-F</code>,<code>&#8211;fastload</code></p>
<dd> generate/use VCD recoder fastload files. This is similar to the <code>-g</code>,<code>&#8211;giga</code> option, however the spill file generated is not deleted. Reloading the VCD file another time (either through pressing the reload button or by re-invoking gtkwave at a later time) will use this generated spill file rather than read the value change section of the VCD file. This will speed up reloads on large files greatly as only the variable declaration section needs to be parsed. Note that the spill file contains the file size and modification date of the VCD file in order to detect if it is stale and needs to be regenerated.</p>
<dt><code>-o</code>,<code>&#8211;optimize</code></p>
<dd> optimize VCD to FST. This will automatically call <i><a href="/docs/linux/man/1-vcd2fst/">vcd2fst</a></i>(1) to perform the file conversion. This option is highly recommended with large VCD files in order to cut down on the memory usage required for file viewing. Can be used in conjunction with <code>-v</code>,<code>&#8211;vcd</code>.</p>
<dt><code>-a</code>,<code>&#8211;save</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify savefile name. Useful suffixes for desktop integration are .gtkw and .sav (deprecated).</p>
<dt><code>-A</code>,<code>&#8211;autosavename</code></p>
<dd> Assume savefile is suffix modified dumpfile name (i.e., remove and replace with &quot;.gtkw&quot;).</p>
<dt><code>-r</code>,<code>&#8211;rcfile</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify override <i>.gtkwaverc</i> filename.</p>
<dt><code>-l</code>,<code>&#8211;logfile</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify simulation logfile name. Multiple logfiles may be specified by preceding each with the command flag. By selecting the numbers in the text widget, the marker will immediately zoom to the specific time value.</p>
<dt><code>-d</code>,<code>&#8211;defaultskip</code></p>
<dd> If there is not a <i>.gtkwaverc</i> file in the home directory or current directory and it is not explicitly specified on the command line, when this option is enabled, do not use an implicit configuration file and instead default to the old &quot;whitescreen&quot; behavior.</p>
<dt><code>-D</code>,<code>&#8211;dualid</code> &lt;<i>which</i>&gt;</p>
<dd> Specify multisession identifier information. The format of &quot;which&quot; is m+nnnnnnnn where m is the session number 0 or 1 and nnnnnnnn is a hexadecimal value indicating the shared memory ID of an array of two gtkwave_dual_ipc_t data structures. The intended use of this flag is for front ends such as <i><a href="/docs/linux/man/1-twinwave/">twinwave</a></i>(1).</p>
<dt><code>-s</code>,<code>&#8211;start</code> &lt;<i>time</i>&gt;</p>
<dd> Specify start time for LXT2/VZT block skip.</p>
<dt><code>-e</code>,<code>&#8211;end</code> &lt;<i>time</i>&gt;</p>
<dd> Specify end time for LXT2/VZT block skip.</p>
<dt><code>-t</code>,<code>&#8211;stems</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify stems file for source code annotation. This will automatically launch the <i><a href="/docs/linux/man/1-rtlbrowse/">rtlbrowse</a></i>(1) helper process. See <i><a href="/docs/linux/man/1-vermin/">vermin</a></i>(1) for information on stems file generation.</p>
<dt><code>-c</code>,<code>&#8211;cpu</code> &lt;<i>numcpus</i>&gt;</p>
<dd> Specify number of CPUs available for parallelizable ops (e.g., block prefetching on VZT reads).</p>
<dt><code>-N</code>,<code>&#8211;nowm</code></p>
<dd> Disable window manager for most windows. The intended use of this is to be used in conjunction with the <code>&#8211;script</code> option, however this also can be used to reparent into an alternate window manager.</p>
<dt><code>-M</code>,<code>&#8211;nomenus</code></p>
<dd> Do not render menubar. This is mainly used for making a restricted applet that cannot initiate file I/O on its own, however it also can be used as a workaround in earlier versions of GTK+ that do not handle GTKSocket/GTKPlug focus interactions properly.</p>
<dt><code>-S</code>,<code>&#8211;script</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify Tcl command script file for execution.</p>
<dt><code>-T</code>,<code>&#8211;tcl_init</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify Tcl command script to be loaded on startup. Implies &#8211;wish command flag.</p>
<dt><code>-W</code>,<code>&#8211;wish</code></p>
<dd> Enable Tcl command line on stdio. All script commands can be typed in on stdin.</p>
<dt><code>-R</code>,<code>&#8211;repscript</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify Tcl command script for periodic execution.</p>
<dt><code>-P</code>,<code>&#8211;repperiod</code> &lt;<i>value</i>&gt;</p>
<dd> Specifies delay in milliseconds between successive executions of the repscript. Default is 500.</p>
<dt><code>-X</code>,<code>&#8211;xid</code> &lt;<i>XID</i>&gt;</p>
<dd> Specify XID (in hexadecimal) of window for a GtkPlug to connect to. GTKWave does not directly render to a window but instead renders into a GtkPlug expecting a GtkSocket at the other end. Note that there are issues with accelerators working properly so menus are disabled in the componentized version of GTKWave when it functions as a plug-in.</p>
<dt><code>-1</code>,<code>&#8211;rpcid</code> &lt;<i>RPCID</i>&gt;</p>
<dd> Specify RPCID of GConf session. This is a decimal value zero or greater and is the identifier used by GConf to know what update data to listen to. This option only works if <code>&#8211;with-gconf</code> was specified during <i>./configure</i>.</p>
<dt><code>-2</code>,<code>&#8211;chdir</code> &lt;<i>DIRNAME</i>&gt;</p>
<dd> Specify new current working directory. This is typically used in OSX to run gtkwave if it was compiled and placed in an .app bundle. Note that if the environment variable GTKWAVE_CHDIR is defined, the argument is a dummy argument. This is to support OSX in that the open command has difficulty in passing spaces as command line arguments and it is possible for <i><a href="/docs/linux/man/1-pwd/">pwd</a></i>(1) to return spaces.</p>
<dt><code>-3</code>,<code>&#8211;restore</code></p>
<dd> Restore previous default (0) or <code>&#8211;rpcid</code> RPCID numbered session. This only works for one dumpfile, savefile, rcfile, and current working directory so it has the effect of restoring the most recently loaded file. If used in conjunction with the <code>&#8211;rpcid</code> option, that option must be specified earlier in the command line than the <code>&#8211;restore</code> option. If RPCID is not specified, then the default of 0 is used. This option only works if <code>&#8211;with-gconf</code> was specified during <i>./configure</i>.</p>
<dt><code>-I</code>,<code>&#8211;interactive</code></p>
<dd> Specifies that &quot;interactive&quot; VCD mode is to be used which allows a viewer to navigate a VCD trace while GTKWave is processing the VCD file. When this option is used, the filename is overloaded such that it is the hexadecimal value for the shared memory ID of a writer. Note that the shared memory ID can be passed straight from stdin by using the <code>&#8211;vcd</code> option; see the manpage for <i><a href="/docs/linux/man/1-shmidcat/">shmidcat</a></i>(1) for more details.</p>
<dt><code>-L</code>,<code>&#8211;legacy</code></p>
<dd> Specifies that the viewer should use legacy VCD mode rather than the VCD recoder. Note that using legacy mode will require considerably more memory than the recoder and its use is discouraged for very large traces.</p>
<dt><code>-g</code>,<code>&#8211;giga</code></p>
<dd> Specifies that the viewer should use gigabyte mempacking when recoding (possibly slower). This is equivalent to setting the vlist_spill and vlist_prepack flags in the rc file.</p>
<dt><code>-C</code>,<code>&#8211;comphier</code></p>
<dd> Specifies that the viewer should use compressed hierarchy names when loading the dumpfile (available for VCD recoder, LXT, LXT2, and VZT). This will use less memory at the expense of compression/decompression delay.</p>
<dt><code>-v</code>,<code>&#8211;vcd</code></p>
<dd> Use stdin as a VCD dumpfile.</p>
<dt><code>-O,&#8211;output</code> &lt;<i>filename</i>&gt;</p>
<dd> Specify filename for stdout/stderr redirect. To disable messages to the console, use /dev/null as the filename.</p>
<dt><code>-z</code>,<code>&#8211;slider-zoom</code></p>
<dd> Enable slider stretch zoom for the horizontal time slider. Clicking then dragging the very left or right edge of the slider can be used to provide fine-grained real-time zooming.</p>
<dt><code>-V</code>,<code>&#8211;version</code></p>
<dd> Display version banner then exit.</p>
<dt><code>-h</code>,<code>&#8211;help</code></p>
<dd> Display help then exit.</p>
<dt><code>-x</code>,<code>&#8211;exit</code></p>
<dd> Exit after loading trace (for loader benchmarking).</dl>
<h2>FILES</h2>
<p> <i>~/.gtkwaverc</i> (see manpage <i><a href="/docs/linux/man/5-gtkwaverc/">gtkwaverc</a></i>(5)) </p>
<h2>EXAMPLES</h2>
<dl>
<dt>To run this program the standard way type:</p>
<dd> gtkwave dumpfile.vcd</p>
<dt>Alternatively you can run it with a save file as:</p>
<dd> gtkwave dumpfile.vcd dumpfile.gtkw</p>
<dt>To run interactively using shared memory handle 0x00050003:</p>
<dd> gtkwave -I 00050003 dumpfile.gtkw</p>
<dt>To pick up a dumpfile automatically from a save file (e.g., when launching from an icon):</p>
<dd> gtkwave &#8211;save dumpfile.gtkw</p>
<dt>To run from the app bundle gtkwave.app in OSX using /bin/sh:</p>
<dd> GTKWAVE_CHDIR=`pwd`;export GTKWAVE_CHDIR;open -n -W -a gtkwave &#8211;args &#8211;chdir dummy &#8211;dump des.vzt &#8211;save des.gtkw</p>
<dt>Alternatively, run the following Perl script gtkwave.app/Contents/Resources/bin/gtkwave to process command line arguments from OSX shell scripts.</p>
<dd>
<dt>Note that to pass non-flag items which start with a dash, that it is required to specify &#8212; in order to turn off flag parsing. A second &#8212; will disable parsing of any following arguments such that they can be passed on to Tcl scripts and retrieved via gtkwave::getArgv.</p>
<dd></dl>
<p> Command line options are not necessary for representing the dumpfile, savefile, and rcfile names. They are merely provided to allow specifying them out of order.</p>
<h2>BUGS</h2>
<dl>
<dt>AIX requires -bmaxdata:0x80000000 (-bmaxdata:0xd0000000/dsa for AIX 5.3) to be added to your list of compiler flags for xlc if you want GTKWave to be able to access more than 256MB of virtual memory. The value shown allows the VMM to use up to 2GB (3.25GB AIX5.3). This may be necessary for very large traces.</p>
<dd>
<dt>Shift and Page operations using the wave window hscrollbar may be nonfunctional as you move away from the dump start for very large traces. A trace that goes out to 45 billion ticks has been known to exhibit this problem. This stems from using the gfloat element of the horizontal slider to encode the time value for the left margin. The result is a loss of precision for very large values. Use the hotkeys or buttons at the top of the screen if this is a problem.</p>
<dd>
<dt>When running under Cygwin, it is required to enable Cygserver if shared memory IPC is being used. Specifically, this occurs when <i><a href="/docs/linux/man/1-rtlbrowse/">rtlbrowse</a></i>(1) is launched as a helper process. See the Cygwin documentation for more information on how to enable Cygserver.</p>
<dd></dl>
