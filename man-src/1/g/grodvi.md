<h2 class="name">NAME</h2>
<p> grodvi &#8211; convert groff output to TeX DVI format </p>
<h2>SYNOPSIS</h2>
<p> [ <code>-dl</code> ] [ <code>-F </code><i>dir</i> ] [ <code>-p </code><i>papersize</i> ] [ <code>-w </code><i>n</i> ] [<i>file</i> &#8230;] <code>&#8211;help</code> <code>-v</code> <code>&#8211;version</code></p>
<h2>DESCRIPTION</h2>
<p> <code>grodvi</code> is a driver for <code>groff</code> that produces TeX DVI format. Normally it should be run by <code>groff -Tdvi</code>. This will run <code>troff -Tdvi</code>; it will also input the macros in <i>/usr/:share/:groff/:1.22.4/:tmac/:dvi.tmac</i>. </p>
<p> The DVI file generated by <code>grodvi</code> can be printed by any correctly-written DVI driver. The troff drawing primitives are implemented using the tpic version~2 specials. If the driver does not support these, the <code>\D</code> commands will not produce any output. </p>
<p> There is an additional drawing command available:</p>
<dl>
<dt><code>\D&#8217;R&nbsp;</code><i>dh dv</i><code>&#8216;</code></p>
<dd> Draw a rule (solid black rectangle), with one corner at the current position, and the diagonally opposite corner at the current position +(<i>dh</i>,<i>dv</i>). Afterwards the current position will be at the opposite corner. This produces a rule in the DVI file and so can be printed even with a driver that does not support the tpic specials unlike the other <code>\D</code> commands.</dl>
<p> The groff command <code>\X&#8217;</code><i>anything</i><code>&#8216;</code> is translated into the same command in the DVI file as would be produced by <code>\special{</code><i>anything</i><code>}</code> in TeX; <i>anything</i> may not contain a newline. </p>
<p> For inclusion of EPS image files, <code>-Tdvi</code> loads <i>pspic.tmac</i> automatically, providing the <code>PSPIC</code> macro. Please check <code><a href="/docs/linux/man/5-groff_tmac/">groff_tmac</a></code>(5) for a detailed description. </p>
<p> Font files for <code>grodvi</code> can be created from tfm files using <code><a href="/docs/linux/man/1-tfmtodit/">tfmtodit</a></code>(1). The font description file should contain the following additional commands:</p>
<dl>
<dt><code>internalname&nbsp;</code><i>name</i></p>
<dd> The name of the tfm file (without the <i>.tfm</i> extension) is <i>name</i>.</p>
<dt><code>checksum&nbsp;</code><i>n</i></p>
<dd> The checksum in the tfm file is <i>n</i>.</p>
<dt><code>designsize&nbsp;</code><i>n</i></p>
<dd> The designsize in the tfm file is <i>n</i>.</dl>
<p> These are automatically generated by <code>tfmtodit.</code> </p>
<p> The default color for <code>\m</code> and <code>\M</code> is black. Currently, the drawing color for <code>\D</code> commands is always black, and fill color values are translated to gray. </p>
<p> In <code>troff</code> the <code>\N</code> escape sequence can be used to access characters by their position in the corresponding tfm file; all characters in the tfm file can be accessed this way. </p>
<p> By design, the DVI format doesn&#8217;t care about physical dimensions of the output medium. Instead, <code>grodvi</code> emits the equivalent to TeX&#8217;s <code>\special{papersize=</code><i>width</i><code>,</code><i>length</i><code>}</code> on the first page; <code>dvips</code> (and possibly other DVI drivers) then sets the page size accordingly. If either the page width or length is not positive, no papersize special is output.</p>
<h2>OPTIONS</h2>
<p> Whitespace is permitted between a command-line option and its argument.</p>
<dl>
<dt><code>-d</code></p>
<dd> Do not use tpic specials to implement drawing commands. Horizontal and vertical lines will be implemented by rules. Other drawing commands will be ignored.</p>
<dt><code>-F</code><i>dir</i></p>
<dd> Prepend directory dir<i>/dev</i>name to the search path for font and device description files; <i>name</i> is the name of the device, usually <code>dvi</code>.</p>
<dt><code>-l</code></p>
<dd> Specify landscape orientation.</p>
<dt><code>-p</code><i>papersize</i></p>
<dd> Specify paper dimensions. This overrides the <code>papersize</code>, <code>paperlength</code>, and <code>paperwidth</code> commands in the <i>DESC</i> file; it accepts the same arguments as the <code>papersize</code> command (see <code><a href="/docs/linux/man/5-groff_font/">groff_font</a></code>(5) for details).</p>
<dt><code>-v</code></p>
<dd> Print the version number.</p>
<dt><code>-w</code><i>n</i></p>
<dd> Set the default line thickness to <i>n</i> thousandths of an em. If this option isn&#8217;t specified, the line thickness defaults to 0.04~em.</dl>
<h2>USAGE</h2>
<p> There are styles called <code>R</code>, <code>I</code>, <code>B</code>, and <code>BI</code> mounted at font positions 1 to 4. The fonts are grouped into families <code>T</code> and <code>H</code> having members in each of these styles:</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>TR</code></p>
<dd> CM Roman (cmr10) <code>TI</code> CM Text Italic (cmti10) <code>TB</code> CM Bold Extended Roman (cmbx10) <code>TBI</code> CM Bold Extended Text Italic (cmbxti10) <code>HR</code> CM Sans Serif (cmss10) <code>HI</code> CM Slanted Sans Serif (cmssi10) <code>HB</code> CM Sans Serif Bold Extended (cmssbx10) <code>HBI</code> CM Slanted Sans Serif Bold Extended (cmssbxo10)</dl>
</dl>
<p> There are also the following fonts which are not members of a family:</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>CW</code></p>
<dd> CM Typewriter Text (cmtt10) <code>CWI</code> CM Italic Typewriter Text (cmitt10)</dl>
</dl>
<p> Special fonts are <code>MI</code> (cmmi10), <code>S</code> (cmsy10), <code>EX</code> (cmex10), <code>SC</code> (cmtex10, only for <code>CW</code>), and, perhaps surprisingly, <code>TR</code>, <code>TI</code>, and <code>CW</code>, due to the different font encodings of text fonts. For italic fonts, <code>CWI</code> is used instead of <code>CW</code>. </p>
<p> Finally, the symbol fonts of the American Mathematical Society are available as special fonts <code>SA</code> (msam10) and <code>SB</code> (msbm10). These two fonts are not mounted by default. </p>
<p> Using the option <code>-mec</code> (which loads the file <i>ec.tmac</i>) provides the EC and TC fonts. The design of the EC family is very similar to that of the CM fonts; additionally, they give a much better coverage of groff symbols. Note that <i>ec.tmac</i> must be called before any language-specific files; it doesn&#8217;t take care of hcode values.</p>
<h2>ENVIRONMENT</h2>
<dl>
<dt><i>GROFF_FONT_PATH</i></p>
<dd> A list of directories in which to search for the <i>dev</i>name directory in addition to the default ones. See <code><a href="/docs/linux/man/1-troff/">troff</a></code>(1) and <code><a href="/docs/linux/man/5-groff_font/">groff_font</a></code>(5) for more details.</dl>
<h2>FILES</h2>
<dl>
<dt><i>/usr/:share/:groff/:1.22.4/:font/devdvi/DESC</i></p>
<dd> Device description file.</p>
<dt><i>/usr/:share/:groff/:1.22.4/:font/devdvi/</i>F</p>
<dd> Font description file for font <i>F</i>.</p>
<dt><i>/usr/:share/:groff/:1.22.4/:tmac/dvi.tmac</i></p>
<dd> Macros for use with <code>grodvi</code>.</p>
<dt><i>/usr/:share/:groff/:1.22.4/:tmac/ec.tmac</i></p>
<dd> Macros to switch to EC fonts.</dl>
<h2>BUGS</h2>
<p> Dvi files produced by <code>grodvi</code> use a different resolution (57816 units per inch) from those produced by TeX. Incorrectly written drivers which assume the resolution used by TeX, rather than using the resolution specified in the DVI file will not work with <code>grodvi</code>. </p>
<p> When using the <code>-d</code> option with boxed tables, vertical and horizontal lines can sometimes protrude by one pixel. This is a consequence of the way TeX requires that the heights and widths of rules be rounded.</p>
