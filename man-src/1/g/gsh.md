<h2>NAME</h2>
<p> gsh &#8211; Group Shell</p>
<h2>SYNOPSIS</h2>
<p> <code>gsh</code> [OPTIONS]&#8230; HOSTS&#8230;</p>
<h2>DESCRIPTION</h2>
<p> <i>gsh</i> spawns many remote shells at once and allows to manage them in a single interface.</p>
<h2>PROMPTS</h2>
<p> The <i>gsh</i> prompt shows either &#8216;ready (X)&gt; &#8216; or &#8216;waiting (X/Y)&gt; &#8216;. The &#8216;ready&#8217; prompt means that all enabled remote shells are ready to receive commands and there are X such remote shells. Failing that, the &#8216;waiting&#8217; prompt is shown, meaning that X remote shells are not yet ready to receive commands. Either way, all the readline editing features like navigation in the history, searching in the history, and completion are available. </p>
<p> Commands prefixed by an exclamation mark are executed locally. </p>
<p> Signals like Ctrl-C and Ctrl-Z sent to <i>gsh</i> are forwarded to the remote shells.</p>
<h2>COMPLETION</h2>
<p> The <i>gsh</i> prompt supports completion by pressing the Tab key. Completion results are taken from the command line history, paths from the local filesystem and commands from the user $PATH.</p>
<h2>HOST NAMES EXPANSION</h2>
<p> Host names with numbers can be generated by gsh using the &lt;START-END&gt; syntax. The generated numbers will be zero padded according to the number of zeroes in the START and END numbers.</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>&#8211;version</code></p>
<dd> Show program&#8217;s version number and exit.</p>
<dt><code>-h, &#8211;help</code></p>
<dd> Show the help message and exit.</p>
<dt><code>&#8211;hosts-file=FILE</code></p>
<dd> Read hostnames from given file, one per line. Hostnames are given on the command line, but they can also be read from files. The format is one hostname per line, &#8216;#&#8217; comments and blank lines are skipped.</p>
<dt><code>&#8211;command=CMD</code></p>
<dd> Command to execute on the remote shells. This starts <i>gsh</i> in non-interactive mode. It will start the remote shells, send the command, print the output and exit when the command is completed on all remote shells. This is the same as piping a command on the standard input.</p>
<dt><code>&#8211;ssh=SSH</code></p>
<dd> Ssh command to use [ssh -t %(host)s bash &#8211;noprofile]. By default, <i>gsh</i> spawns lightweight remote shells using the ssh command, but another shell command can be specified here. For example, with &#8211;ssh=&#8217;usleep $((RANDOM*50)); exec ssh&#8217; a delay will be introduced to avoid all hosts accessing a NFS server at the same time. If the hostname should not be added at the end of the command, the macro %(host)s can be inserted where the hostname should be placed. Also, make sure the command you use launchs a pty, this may need the -t option for ssh.</p>
<dt><code>&#8211;log-file=LOG_FILE</code></p>
<dd> File to log each machine conversation [none]. If specified, <i>gsh</i> will log all executed commands and their output in the file. The logging destination can be dynamically changed with the :set_log control command.</p>
<dt><code>&#8211;abort-errors</code></p>
<dd> Abort if some shell fails to initialize [ignore]. By default, <i>gsh</i> just logs an error when it cannot succesfully open a remote shell. With this option, it exits with a failure.</p>
<dt><code>&#8211;debug</code></p>
<dd> Print debugging information. Use this option to see exactly what is transferred between <i>gsh</i> and the remote shells. This option can be dynamically toggled using the set_debug command in the control shell.</dl>
<h2>CONTROL COMMANDS</h2>
<p> Control commands are special purpose commands prefixed by a colon and directed at <i>gsh</i> itself instead of the remote shells. These commands are:</p>
<dl>
<dt><code>:add NAMES&#8230;</code></p>
<dd> Add one or many remote shells.</p>
<dt><code>:chdir LOCAL_PATH</code></p>
<dd> Change the current directory of <i>gsh</i> (not the remote shells).</p>
<dt><code>:disable [SHELLS&#8230;]</code></p>
<dd> Disable sending commands to remote shells. The special characters * ? and [] work as expected.</p>
<dt><code>:enable [SHELLS&#8230;]</code></p>
<dd> Enable sending commands to remote shells. The special characters * ? and [] work as expected.</p>
<dt><code>:export_rank</code></p>
<dd> Set GSH_RANK and GSH_NR_SHELLS on enabled remote shells. The GSH_RANK shell variable uniquely identifies each shell with a number between 0 and GSH_NR_SHELLS &#8211; 1. GSH_NR_SHELLS is the total number of enabled shells.</p>
<dt><code>:help [COMMAND]</code></p>
<dd> List control commands or show their documentations.</p>
<dt><code>:hide_password</code></p>
<dd> Do not echo the next typed line. This is useful when entering password. If debugging or logging is enabled, it will be disabled to avoid displaying a password. Therefore, you will have to reenable logging or debugging afterwards if need be.</p>
<dt><code>:list [SHELLS&#8230;]</code></p>
<dd> List remote shells and their states. The output consists of: &lt;hostname&gt; &lt;enabled?&gt; &lt;state&gt;: &lt;last printed line&gt;. The special characters * ? and [] work as expected.</p>
<dt><code>:purge [SHELLS&#8230;]</code></p>
<dd> Delete disabled remote shells. This helps to have a shorter list. The special characters * ? and [] work as expected.</p>
<dt><code>:quit</code></p>
<dd> Quit <i>gsh</i>.</p>
<dt><code>:reconnect [SHELLS&#8230;]</code></p>
<dd> Try to reconnect to disconnected remote shells. The special characters * ? and [] work as expected.</p>
<dt><code>:rename [NEW_NAME]</code></p>
<dd> Rename all enabled remote shells with the argument. The argument will be shell expanded on the remote processes. With no argument, the original hostname will be restored as the displayed name.</p>
<dt><code>:replicate SHELL:REMOTE_PATH</code></p>
<dd> Copy a path from one remote shell to all others</p>
<dt><code>:reset_prompt [SHELLS&#8230;]</code></p>
<dd> Change the prompt to be recognized by <i>gsh</i>. The special characters * ? and [] work as expected.</p>
<dt><code>:send_ctrl LETTER [SHELLS&#8230;]</code></p>
<dd> Send a control character to remote shells. The first argument is the control character to send like c, d or z. Note that these three control characters can be sent simply by typing them into <i>gsh</i>. The remaining optional arguments are the destination shells. The special characters * ? and [] work as expected.</p>
<dt><code>:set_debug y|n [SHELLS&#8230;]</code></p>
<dd> Enable or disable debugging output for remote shells. The first argument is &#8216;y&#8217; to enable the debugging output, &#8216;n&#8217; to disable it. The remaining optional arguments are the selected shells. The special characters * ? and [] work as expected.</p>
<dt><code>:set_log [LOCAL_PATH]</code></p>
<dd> Duplicate every console I/O into the given local file. If LOCAL_PATH is not given, restore the default behaviour of not logging.</p>
<dt><code>:show_read_buffer [SHELLS&#8230;]</code></p>
<dd> Print the data read by remote shells. The special characters * ? and [] work as expected.</p>
<dt><code>:upload LOCAL_PATH</code></p>
<dd> Upload the specified local path to enabled remote shells.</dl>
