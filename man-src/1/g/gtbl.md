<h2 class="name">NAME</h2>
<p> tbl &#8211; format tables for troff </p>
<h2>SYNOPSIS</h2>
<p> [ <code>-Cv</code> ] [<i>file</i> &#8230;]</p>
<h2>DESCRIPTION</h2>
<p> This manual page describes the GNU version of <code>tbl</code>, which is part of the groff document formatting system. <code>tbl</code> compiles descriptions of tables embedded within <code>troff</code> input files into commands that are understood by <code>troff</code>. Normally, it should be invoked using the <code>-t</code> option of <code>groff.</code> It is highly compatible with Unix <code>tbl</code>. The output generated by GNU <code>tbl</code> cannot be processed with Unix <code>troff</code>; it must be processed with GNU <code>troff</code>. If no files are given on the command line or a filename of <code>&#8211;</code> is given, the standard input is read.</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-C</code></p>
<dd> Enable compatibility mode to recognize <code>.TS</code> and <code>.TE</code> even when followed by a character other than space or newline. Leader characters () are handled as interpreted.</p>
<dt><code>-v</code></p>
<dd> Print the version number.</dl>
<h2>LANGUAGE OVERVIEW</h2>
<p> <code>tbl</code> expects to find table descriptions wrapped in the <code>.TS</code> (table start) and <code>.TE</code> (table end) macros. Within each such table sections, another table can be defined by using the request <code>.T&amp;</code> before the final command <code>.TE</code>. Each table definition has the following structure:</p>
<dl>
<dt><i>Global options</i></p>
<dd> This is optional. This table part can use several of these options distributed in 1 or more lines. The <i>global option part</i> must always be finished by a <code>semi-colon ; .</code></p>
<dt><i>Table format specification</i></p>
<dd> This part must be given, it is not optional. It determines the number of columns (cells) of the table. Moreover each cell is classified by being central, left adjusted, or numerical, etc. This specification can have several lines, but must be finished by a <code>dot .</code> at the end of the last line. After each cell definition, <i>column specifiers</i> can be appended, but that&#8217;s optional.</dl>
<p> Cells are separated by a tab character by default. That can be changed by the <i>global option</i> <code>tab(</code><i>c</i><code>)</code>, where <i>c</i> is an arbitrary character.</p>

<p> The easiest table definition is.</p>
<dl>

 .TE</dl>
<p> By using <code>c c</code> <code>c</code>, each cell in the whole table will be centered. The separating character is here the default <i>tab</i>. </p>
<p> The result is</p>
<dl>
<dt>
<dd>
<table>

<dl>

<p> Here, the separating tab character is changed to the letter <code>@</code>. </p>
<p> Moreover a title can be added and the centering directions can be changed to many other formats:</p>
<dl>
<dt>
<dd> .TS tab(@); c s s l c n . Title left [at] centers@123 another [at] number@75 .TE</dl>

<h2>USAGE</h2>
<h3>Global options</h3>
<p> The line immediately following the <code>.TS</code> macro may contain any of the following global options (ignoring the case of characters &#8211; Unix tbl only accepts options with all characters lowercase or all characters uppercase), separated by spaces, tabs, or commas:</p>
<dl>
<dt><code>allbox</code></p>
<dd> Enclose each item of the table in a box.</p>
<dt><code>box</code></p>
<dd> Enclose the table in a box.</p>
<dt><code>center</code></p>
<dd> Center the table (default is left-justified). The alternative keyword name <code>centre</code> is also recognized (this is a GNU tbl extension).</p>
<dt><code>decimalpoint(</code><i>c</i><code>)</code></p>
<dd> Set the character to be recognized as the decimal point in numeric columns (GNU tbl only).</p>
<dt><code>delim(</code><i>xy</i><code>)</code></p>
<dd> Use <i>x</i> and~<i>y</i> as start and end delimiters for <code><a href="/docs/linux/man/1-eqn/">eqn</a></code>(1).</p>
<dt><code>doublebox</code></p>
<dd> Enclose the table in a double box.</p>
<dt><code>doubleframe</code></p>
<dd> Same as doublebox (GNU tbl only).</p>
<dt><code>expand</code></p>
<dd> Make the table as wide as the current line length (providing a column separation factor). Ignored if one or more &#8216;x&#8217; column specifiers are used (see below).</p>
<dt>
<dd> In case the sum of the column widths is larger than the current line length, the column separation factor is set to zero; such tables extend into the right margin, and there is no column separation at all.</p>
<dt><code>frame</code></p>
<dd> Same as box (GNU tbl only).</p>
<dt><code>linesize(</code><i>n</i><code>)</code></p>
<dd> Set lines or rules (e.g. from <code>box</code>) in <i>n</i>-point type.</p>
<dt><code>nokeep</code></p>
<dd> Don&#8217;t use diversions to prevent page breaks (GNU tbl only). Normally <code>tbl</code> attempts to prevent undesirable breaks in boxed tables by using diversions. This can sometimes interact badly with macro packages&#8217; own use of diversions&#8212;when footnotes, for example, are used.</p>
<dt><code>nospaces</code></p>
<dd> Ignore leading and trailing spaces in data items (GNU tbl only).</p>
<dt><code>nowarn</code></p>
<dd> Turn off warnings related to tables exceeding the current line width (GNU tbl only).</p>
<dt><code>tab(</code><i>x</i><code>)</code></p>
<dd> Use the character <i>x</i> instead of a tab to separate items in a line of input data.</dl>
<p> The global options must end with a semicolon. There might be whitespace between an option and its argument in parentheses.</p>
<h3>Table format specification</h3>
<p> After global options come lines describing the format of each line of the table. Each such format line describes one line of the table itself, except that the last format line (which you must end with a period) describes all remaining lines of the table. A single-key character describes each column of each line of the table. Key characters can be separated by spaces or tabs. You may run format specifications for multiple lines together on the same line by separating them with commas. </p>
<p> You may follow each key character with specifiers that determine the font and point size of the corresponding item, that determine column width, inter-column spacing, etc. </p>
<p> The longest format line defines the number of columns in the table; missing format descriptors at the end of format lines are assumed to be~<code>L</code>. Extra columns in the data (which have no corresponding format entry) are ignored. </p>
<p> The available key characters are:</p>
<dl>
<dt><code>a</code>,<code>A</code></p>
<dd> Center longest line in this column and then left-justifies all other lines in this column with respect to that centered line. The idea is to use such alphabetic subcolumns (hence the name of the key character) in combination with~ <code>L</code>; they are called subcolumns because <code>A</code>~items are indented by~1n relative to <code>L</code>~entries. Example:</p>
<dl>
<dt>
<dd>
<dl>
<dt>
<dd> .TS tab(;); ln,an. item one;1 subitem two;2 subitem three;3 .T&amp; ln,an. item eleven;11 subitem twentytwo;22 subitem thirtythree;33 .TE</dl>
</dl>
<dt>
<dd> Result:</p>
<dl>
<dt>
<dd>
<dl>
<dt>
<dd>
<table>
<tr VALIGN=top>
<td>item one</td>
<td ALIGN=right>1&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td>subitem two</td>
<td ALIGN=right>2&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td>subitem three</td>
<td ALIGN=right>3&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td>item eleven</td>
<td ALIGN=right>11&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td>subitem twentytwo</td>
<td ALIGN=right>22&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;

</tr>
<tr VALIGN=top>
<td>subitem thirtythree</td>
<td ALIGN=right>33&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;

</tr>
</table>
</dl>
</dl>
<dt><code>c</code>,<code>C</code></p>
<dd> Center item within the column.</p>
<dt><code>l</code>,<code>L</code></p>
<dd> Left-justify item within the column.</p>
<dt><code>n</code>,<code>N</code></p>
<dd> Numerically justify item in the column: Units positions of numbers are aligned vertically. If there is one or more dots adjacent to a digit, use the rightmost one for vertical alignment. If there is no dot, use the rightmost digit for vertical alignment; otherwise, center the item within the column. Alignment can be forced to a certain position using &#8216;\&amp;&#8217;; if there is one or more instances of this special (non-printing) character present within the data, use the leftmost one for alignment. Example:</p>
<dl>
<dt>
<dd>
<dl>
<dt>
<dd> .TS n. 1 1.5 1.5.3 abcde a\&amp;bcde .TE</dl>
</dl>
<dt>
<dd> Result:</p>
<dl>
<dt>
<dd>
<dl>
<dt>
<dd>
<table>
<tr VALIGN=top>
<td ALIGN=right>1&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td ALIGN=right>1.5&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td ALIGN=right>1.5.3&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td ALIGN=right>abcde&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
<tr VALIGN=top>
<td ALIGN=right>abcde&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;
</td>
</tr>
</table>
</dl>
</dl>
<dt>
<dd> If numerical entries are combined with <code>L</code> or <code>R</code>~entries &#8211; this can happen if the table format is changed with <code>.T&amp;</code> &#8211; center the widest <i>number</i> (of the data entered under the <code>N</code>~specifier regime) relative to the widest <code>L</code> or <code>R</code>~entry, preserving the alignment of all numerical entries. Contrary to <code>A</code>~type entries, there is no extra indentation.</p>
<dt>
<dd> Using equations (to be processed with <code>eqn</code>) within columns which use the <code>N</code>~specifier is problematic in most cases due to <code>tbl</code>&#8216;s algorithm for finding the vertical alignment, as described above. Using the global <code>delim</code> option, however, it is possible to make <code>tbl</code> ignore the data within <code>eqn</code> delimiters for that purpose.</p>
<dt><code>r</code>,<code>R</code></p>
<dd> Right-justify item within the column.</p>
<dt><code>s</code>,<code>S</code></p>
<dd> Span previous item on the left into this column. Not allowed for the first column.</p>
<dt><code>^</code></p>
<dd> Span down entry from previous row in this column. Not allowed for the first row.</p>
<dt><code>_</code>,<code>&#8211;</code></p>
<dd> Replace this entry with a horizontal line. Note that &#8216;_&#8217; and &#8216;-&#8216; can be used for table fields only, not for column separator lines.</p>
<dt><code>=</code></p>
<dd> Replace this entry with a double horizontal line. Note that &#8216;=&#8217; can be used for table fields only, not for column separator lines.</p>
<dt><code>|</code></p>
<dd> The corresponding column becomes a vertical rule (if two of these are adjacent, a double vertical rule).</dl>
<p> A vertical bar to the left of the first key letter or to the right of the last one produces a line at the edge of the table. </p>
<p> To change the data format within a table, use the <code>.T&amp;</code> command (at the start of a line). It is followed by format and data lines (but no global options) similar to the <code>.TS</code> request.</p>
<h3>Column specifiers</h3>
<p> Here are the specifiers that can appear in suffixes to column key letters (in any order):</p>
<dl>
<dt><code>b</code>,<code>B</code></p>
<dd> Short form of <code>fB</code> (make affected entries bold).</p>
<dt><code>d</code>,<code>D</code></p>
<dd> Start an item that vertically spans rows, using the &#8216;^&#8217; column specifier or &#8216;\^&#8217; data item, at the bottom of its range rather than vertically centering it (GNU tbl only). Example:</p>
<dl>
<dt>
<dd>
<dl>
<dt>
<dd> .TS tab(;) allbox; l l l ld r ^ l rd. 0000;foobar T{ 1111 .br 2222 T};foo r; T{ 3333 .br 4444 T};bar \^;\^ .TE</dl>
</dl>
<dt>
<dd> Result:</p>
<dl>
<dt>
<dd>
<dl>
<dt>
<dd>
<table BORDER>
<tr VALIGN=top>
<td>0000</td>
<td>foobar
</td>
</tr>
<tr VALIGN=top>
<td> 1111<br />
 2222 </td>
<td VALIGN=center ROWSPAN=2>foo
</td>
</tr>
<tr VALIGN=top>
<td ALIGN=right>r</td>
</tr>
<tr VALIGN=top>
<td VALIGN=center ROWSPAN=2> 3333<br />
 4444 </td>
<td ALIGN=right VALIGN=center ROWSPAN=2>bar
</td>
</tr>
<tr VALIGN=top></tr>
</table>
</dl>
</dl>
<dt><code>e</code>,<code>E</code></p>
<dd> Make equally-spaced columns. All columns marked with this specifier get the same width; this happens after the affected column widths have been computed (this means that the largest width value rules).</p>
<dt><code>f</code>,<code>F</code></p>
<dd> Either of these specifiers may be followed by a font name (either one or two characters long), font number (a single digit), or long name in parentheses (the last form is a GNU tbl extension). A one-letter font name must be separated by one or more blanks from whatever follows.</p>
<dt><code>i</code>,<code>I</code></p>
<dd> Short form of <code>fI</code> (make affected entries italic).</p>
<dt><code>m</code>,<code>M</code></p>
<dd> This is a GNU tbl extension. Either of these specifiers may be followed by a macro name (either one or two characters long), or long name in parentheses. A one-letter macro name must be separated by one or more blanks from whatever follows. The macro which name can be specified here must be defined before creating the table. It is called just before the table&#8217;s cell text is output. As implemented currently, this macro is only called if block input is used, that is, text between &#8216;T{&#8216; and &#8216;T}&#8217;. The macro should contain only simple <code>troff</code> requests to change the text block formatting, like text adjustment, hyphenation, size, or font. The macro is called <i>after</i> other cell modifications like <code>b</code>, <code>f</code> or <code>v</code> are output. Thus the macro can overwrite other modification specifiers.</p>
<dt><code>p</code>,<code>P</code></p>
<dd> Followed by a number, this does a point size change for the affected fields. If signed, the current point size is incremented or decremented (using a signed number instead of a signed digit is a GNU tbl extension). A point size specifier followed by a column separation number must be separated by one or more blanks.</p>
<dt><code>t</code>,<code>T</code></p>
<dd> Start an item vertically spanning rows at the top of its range rather than vertically centering it.</p>
<dt><code>u</code>,<code>U</code></p>
<dd> Move the corresponding column up one half-line.</p>
<dt><code>v</code>,<code>V</code></p>
<dd> Followed by a number, this indicates the vertical line spacing to be used in a multi-line table entry. If signed, the current vertical line spacing is incremented or decremented (using a signed number instead of a signed digit is a GNU tbl extension). A vertical line spacing specifier followed by a column separation number must be separated by one or more blanks. No effect if the corresponding table entry isn&#8217;t a text block.</p>
<dt><code>w</code>,<code>W</code></p>
<dd> Minimum column width value. Must be followed either by a <code><a href="/docs/linux/man/1-troff/">troff</a></code>(1) width expression in parentheses or a unitless integer. If no unit is given, en units are used. Also used as the default line length for included text blocks. If used multiple times to specify the width for a particular column, the last entry takes effect.</p>
<dt><code>x</code>,<code>X</code></p>
<dd> An expanded column. After computing all column widths without an <code>x</code>~specifier, use the remaining line width for this column. If there is more than one expanded column, distribute the remaining horizontal space evenly among the affected columns (this is a GNU extension). This feature has the same effect as specifying a minimum column width.</p>
<dt><code>z</code>,<code>Z</code></p>
<dd> Ignore the corresponding column for width-calculation purposes, this is, don&#8217;t use the fields but only the specifiers of this column to compute its width.</dl>
<p> A number suffix on a key character is interpreted as a column separation in en units (multiplied in proportion if the <code>expand</code> option is on &#8211; in case of overfull tables this might be zero). Default separation is 3n. </p>
<p> The column specifier~<code>x</code> is mutually exclusive with <code>e</code> and~<code>w</code> (but <code>e</code> is not mutually exclusive with~<code>w</code>); if specified multiple times for a particular column, the last entry takes effect: <code>x</code>~unsets both <code>e</code> and~<code>w</code>, while either <code>e</code> or <code>w</code> overrides~<code>x</code>.</p>
<h3>Table data</h3>
<p> The format lines are followed by lines containing the actual data for the table, followed finally by <code>.TE</code>. Within such data lines, items are normally separated by tab characters (or the character specified with the <code>tab</code> option). Long input lines can be broken across multiple lines if the last character on the line is &#8216;\&#8217; (which vanishes after concatenation). </p>
<p> Note that <code>tbl</code> computes the column widths line by line, applying \w on each entry which isn&#8217;t a text block. As a consequence, constructions like</p>
<dl>
<dt>
<dd> .TS c,l. \s[20]MM MMMM .TE</dl>
<p> fail; you must either say</p>
<dl>
<dt>
<dd> .TS cp20,lp20. MM MMMM .TE</dl>
<p> or</p>
<dl>
<dt>
<dd> .TS c,l. \s[20]MM \s[20]MMMM .TE</dl>
<p> A dot starting a line, followed by anything but a digit is handled as a troff command, passed through without changes. The table position is unchanged in this case. </p>
<p> If a data line consists of only &#8216;_&#8217; or &#8216;=&#8217;, a single or double line, respectively, is drawn across the table at that point; if a single item in a data line consists of only &#8216;_&#8217; or &#8216;=&#8217;, then that item is replaced by a single or double line, joining its neighbours. If a data item consists only of &#8216;\_&#8217; or &#8216;\=&#8217;, a single or double line, respectively, is drawn across the field at that point which does not join its neighbours. </p>
<p> A data item consisting only of &#8216;\Rx&#8217; (&#8216;x&#8217; any character) is replaced by repetitions of character &#8216;x&#8217; as wide as the column (not joining its neighbours). </p>
<p> A data item consisting only of &#8216;\^&#8217; indicates that the field immediately above spans downward over this row.</p>
<h3>Text blocks</h3>
<p> A text block can be used to enter data as a single entry which would be too long as a simple string between tabs. It is started with &#8216;T{&#8216; and closed with &#8216;T}&#8217;. The former must end a line, and the latter must start a line, probably followed by other data columns (separated with tabs or the character given with the <code>tab</code> global option). </p>
<p> By default, the text block is formatted with the settings which were active before entering the table, possibly overridden by the <code>m</code>, <code>v</code>, and <code>w</code> tbl specifiers. For example, to make all text blocks ragged-right, insert <code>.na</code> right before the starting <code>.TS</code> (and <code>.ad</code> after the table). </p>
<p> If either &#8216;w&#8217; or &#8216;x&#8217; specifiers are not given for <i>all</i> columns of a text block span, the default length of the text block (to be more precise, the line length used to process the text block diversion) is computed as LmuC/(N+1), where &#8216;L&#8217; is the current line length, &#8216;C&#8217; the number of columns spanned by the text block, and &#8216;N&#8217; the total number of columns in the table. Note, however, that the actual diversion width as returned in register <code>
[dl]</code> is used eventually as the text block width. If necessary, you can also control the text block width with a direct insertion of a <code>.ll</code> request right after &#8216;T{&#8216;.</p>
<h3>Miscellaneous</h3>
<p> The number register <code>
[TW]</code> holds the table width; it can&#8217;t be used within the table itself but is defined right before calling <code>.TE</code> so that this macro can make use of it. </p>
<p> <code>tbl</code> also defines a macro <code>.T#</code> which produces the bottom and side lines of a boxed table. While <code>tbl</code> does call this macro itself at the end of the table, it can be used by macro packages to create boxes for multi-page tables by calling it within the page footer. An example of this is shown by the <code>-ms</code> macros which provide this functionality if a table starts with <code>.TS H</code> instead of the standard call to the <code>.TS</code> macro.</p>
<h2>INTERACTION WITH EQN</h2>
<p> <code><a href="/docs/linux/man/1-tbl/">tbl</a></code>(1) should always be called before <code><a href="/docs/linux/man/1-eqn/">eqn</a></code>(1) (<code><a href="/docs/linux/man/1-groff/">groff</a></code>(1) automatically takes care of the correct order of preprocessors).</p>
<h2>GNU TBL ENHANCEMENTS</h2>
<p> There is no limit on the number of columns in a table, nor any limit on the number of text blocks. All the lines of a table are considered in deciding column widths, not just the first 200. Table continuation (<code>.T&amp;</code>) lines are not restricted to the first 200 lines. </p>
<p> Numeric and alphabetic items may appear in the same column. </p>
<p> Numeric and alphabetic items may span horizontally. </p>
<p> <code>tbl</code> uses register, string, macro and diversion names beginning with the digit~<code>3</code>. When using <code>tbl</code> you should avoid using any names beginning with a~<code>3</code>.</p>
<h2>GNU TBL WITHIN MACROS</h2>
<p> Since <code>tbl</code> defines its own macros (right before each table) it is necessary to use an &#8216;end-of-macro&#8217; macro. Additionally, the escape character has to be switched off. Here an example.</p>
<dl>
<dt>
<dd> .eo .de ATABLE .. .TS allbox tab(;); cl. \$1;\$2 .TE &#8230; .ec .ATABLE A table .ATABLE Another table .ATABLE And &quot;another one&quot;</dl>
<p> Note, however, that not all features of <code>tbl</code> can be wrapped into a macro because <code>tbl</code> sees the input earlier than <code>troff</code>. For example, number formatting with vertically aligned decimal points fails if those numbers are passed on as macro parameters because decimal point alignment is handled by <code>tbl</code> itself: It only sees &#8216;\$1&#8217;, &#8216;\$2&#8217;, etc., and therefore can&#8217;t recognize the decimal point.</p>
<h2>BUGS</h2>
<p> You should use <code>.TS H</code>/<code>.TH</code> in conjunction with a supporting macro package for <i>all</i> multi-page boxed tables. If there is no header that you wish to appear at the top of each page of the table, place the <code>.TH</code> line immediately after the format section. Do not enclose a multi-page table within keep/release macros, or divert it in any other way. </p>
<p> A text block within a table must be able to fit on one page. </p>
<p> The <code>bp</code> request cannot be used to force a page-break in a multi-page table. Instead, define <code>BP</code> as follows</p>
<dl>
<dt>
<dd> .de BP . ie &#8216;\n(.z&#8221; .bp \$1 . el \!.BP \$1 ..</dl>
<p> and use <code>BP</code> instead of <code>bp</code>. </p>
<p> Using  directly in a table to get leaders does not work (except in compatibility mode). This is correct behaviour:  is an <code>uninterpreted</code> leader. To get leaders use a real leader, either by using a control A or like this:</p>
<dl>
<dt>
<dd> .ds a  .TS tab(;); <a href="//www.systutorials.com/docs/linux/man/1i-lw/">lw</a>(1i) l. A\*a;B .TE</dl>
<p> A leading and/or trailing &#8216;|&#8217; in a format line, such as</p>
<dl>
<dt>
<dd> |l r|.</dl>
<p> gives output which has a 1n~space between the resulting bordering vertical rule and the content of the adjacent column, as in</p>
<dl>
<dt>
<dd> .TS tab(#); |l r|. left column#right column .TE</dl>
<p> If it is desired to have zero space (so that the rule touches the content), this can be achieved by introducing extra &#8220;dummy&#8221; columns, with no content and zero separation, before and/or after, as in</p>
<dl>
<dt>
<dd> .TS tab(#); r0|l r0|l. #left column#right column# .TE</dl>
<p> The resulting &#8220;dummy&#8221; columns are invisible and have zero width; note that such columns usually don&#8217;t work with TTY devices.</p>
