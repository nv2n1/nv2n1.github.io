<h2 class="name">NAME</h2>
<p> texlogsieve &#8211; filter and summarize LaTeX log files</p>
<h2>SYNOPSIS</h2>
<p> <code>texlogsieve</code> [<i>,OPTION/</i>]&#8230; [<i>,INPUT FILE/</i>] </p>
<h2>DESCRIPTION</h2>
<p> texlogsieve reads a LaTeX log file (or the standard input if no file is specified), filters out less relevant messages, and displays a summary report. </p>
<p> texlogsieve <code>must</code> be run from the same directory as [pdf|lua|xe]latex, because it searches for the files used during compilation (packages loaded from the current directory, files included with \input etc.). Also, since it cannot detect if LaTeX stops for user input, you should <code>really</code> run LaTeX in <i>,nonstopmode/</i> when texlogsieve is reading from a pipe. </p>
<p> The program goes to great lengths to correctly handle TeX line wrapping. It understands the <i>,max_print_line/</i> TeX configuration variable and reads its value from the same places as TeX. Setting <i>,max_print_line/</i> to a value larger than 9999 makes texlogsieve ignore line wrapping. </p>
<p> The defaults are reasonable; hopefully, you can just do </p>
<dl>
<dt>
<dd> [pdf|lua|xe]latex -interaction nonstopmode myfile.tex | texlogsieve</dl>
<p> or </p>
<dl>
<dt>
<dd> texlogsieve myfile.log</dl>
<p> and be satisfied with the result. </p>
<h2>OPTIONS</h2>
<dl>
<dt><code>&#8211;page-delay</code>, <code>&#8211;no-page-delay</code></p>
<dd> Enable/disable grouping messages by page before display. When enabled, messages are only output after the current page is finished (shipout). The advantage is that the page number is included in the message (default enabled). </p>
<dt><code>&#8211;summary</code>, <code>&#8211;no-summary</code></p>
<dd> Enable/disable final summary (default enabled). </p>
<dt><code>&#8211;only-summary</code></p>
<dd> No messages, show only the final summary (default disabled). </p>
<dt><code>&#8211;shipouts</code>, <code>&#8211;no-shipouts</code></p>
<dd> Enable/disable reporting shipouts (default disabled with page-delay, enabled with no-page-delay). </p>
<dt><code>&#8211;repetitions</code>, <code>&#8211;no-repetitions</code></p>
<dd> Allow/prevent repeated messages (default disabled, i.e., repeated messages are supressed). </p>
<dt><code>&#8211;be-redundant</code>, <code>&#8211;no-be-redundant</code></p>
<dd> Present/suppress ordinary messages that will also appear in the summary. This affects messages that have special summaries (such as under/overfull boxes or undefined citations). With &#8211;no-be-redundant (the default), these messages are filtered out and only appear in the final summary. </p>
<dt><code>&#8211;box-detail</code>, <code>&#8211;no-box-detail</code></p>
<dd> Include/exclude detailed information on under/overfull boxes in the final summary. With &#8211;no-box-detail, the summary presents only a list of pages and files that had under/overfull boxes (default enabled). </p>
<dt><code>&#8211;ref-detail</code>, <code>&#8211;no-ref-detail</code></p>
<dd> Include/exclude detailed information on undefined references in the final summary. With &#8211;no-ref-detail, the summary presents only a list of undefined references, without page numbers and filenames (default enabled). </p>
<dt><code>&#8211;cite-detail</code>, <code>&#8211;no-cite-detail</code></p>
<dd> Include/exclude detailed information on undefined citations in the final summary. With &#8211;no-cite-detail, the summary presents only a list of undefined citations, without page numbers and filenames (default enabled). </p>
<dt><code>&#8211;summary-detail</code>, <code>&#8211;no-summary-detail</code></p>
<dd> Toggle &#8211;box-detail, &#8211;ref-detail, and &#8211;cite-detail at once. </p>
<dt><code>&#8211;heartbeat</code>, <code>&#8211;no-heartbeat</code></p>
<dd> Enable/disable progress gauge in page-delay mode (default enabled). </p>
<dt><code>-l</code> <i>,LEVEL/</i>, <code>&#8211;minlevel</code>=<i>,LEVEL/</i></p>
<dd> Filter out messages with severity level lower than LEVEL. Valid levels are DEBUG (no filtering), INFO, WARNING, CRITICAL, and UNKNOWN (default WARNING). </p>
<dt><code>-u</code>, <code>&#8211;unwrap-only</code></p>
<dd> Do not filter messages and do not output the summary, only unwrap long, wrapped lines. The output should be very similar (but not equal) to the input file, but with wrapped lines reconstructed. This activates -l debug, &#8211;no-summary, &#8211;no-page-delay, &#8211;repetitions, &#8211;be-redundant, and &#8211;shipouts, and also supresses the verbose &#8220;open/close file&#8221; and &#8220;shipout&#8221; messages, simulating instead the TeX format, with parens and square brackets. This is useful if you prefer the reports generated by some other tool but want to benefit from texlogsieve&#8217;s line unwrapping algorithm; the output generated by this option should be parseable by other tools (but you probably need to coerce the other tool not to try to unwrap lines). </p>
<dt><code>&#8211;silence-package</code>=<i>,PKGNAME/</i></p>
<dd> Filter out messages that can be identified as coming from the given package. Use this option multiple times to suppress messages from several different packages. </p>
<dt><code>&#8211;silence-string</code>=<i>,EXCERPT OF UNWANTED MESSAGE/</i></p>
<dd> Filter out messages that contain the given string (you only need to provide part of the message text for the whole message to be suppressed). Use this option multiple times to suppress several different messages. The string should be a single line, but that is not a problem for multiline log messages: space characters in the provided string match any sequence of whitespace characters in the message, including newlines. If needed, you may precede the string with &#8220;////&#8221;, in which case you can use lua-style pattern matching ( quotes or escape special characters such as &#8220;\&#8221; for the benefit of the shell, but such quoting and escaping is unnecessary (and harmful) in the configuration file. </p>
<dt><code>&#8211;silence-file</code>=<i>,FILENAME OR FILE GLOB/</i></p>
<dd> Filter out messages that have been generated while the given file was being processed. Do <code>not</code> use absolute or relative paths, only filenames. Simple file globs, such as &#8220;*.cls&#8221;, work as expected. If you are only using packages you already know, silencing &#8220;*.sty&#8221; may be a good idea (note that this does not suppress all messages from all packages, only the messages generated while the packages are being loaded). Use this option multiple times to suppress messages from several different files. </p>
<dt><code>&#8211;semisilence-file</code>=<i>,FILENAME OR FILE GLOB/</i></p>
<dd> Just like the previous option, but non-recursive. This means that messages generated while the given file was being processed are excluded, but messages generated by some other file that was opened by it are not. For example, if &#8220;chapters.tex&#8221; includes (with \input) the files &#8220;chapter1.tex&#8221; and &#8220;chapter2.tex&#8221;, using &#8220;&#8211;silence-file=chapters.tex&#8221; will prevent messages generated by any of the three files from being displayed. If, however, you use &#8220;&#8211;semisilence-file=chapters.tex&#8221;, messages generated by chapters.tex will be suppressed, but messages generated by chapter1.tex or chapter2.tex will not. </p>
<dt><code>&#8211;add-[debug|info|warning|critical]-message</code>=<i>,MESSAGE/</i></p>
<dd> Add MESSAGE to the list of messages known to the program with the given severity level; see Section UNRECOGNIZED MESSAGES below for more information about this. Like &#8211;silence-string, these should be a single line; unlike &#8211;silence-string, you need to embed 
 explicitly to indicate line breaks (this is literally a backslash character followed by the letter &#8220;n&#8221;, <code>not</code> a linefeed character). You may precede the string with &#8220;////&#8221; to use lua-style pattern matching, but embedding 
 to indicate line breaks is unavoidable. Use these options multiple times to add many different messages. </p>
<dt><code>&#8211;set-to-level-[debug|info|warning|critical]</code>=<i>,EXCERPT OF MESSAGE/</i></p>
<dd> Redefine the severity level of messages that contain the provided string to the given level. Check the explanation for &#8211;silence-string, as this works in a similar way. Use these options multiple times to change the severity level of many different messages. </p>
<dt><code>-c</code> <i>,CFGFILE/</i>, <code>&#8211;config-file</code>=<i>,CFGFILE/</i></p>
<dd> Read options from the given configuration file in addition to <i>,texlogsieverc/</i>. </p>
<dt><code>-h</code>, <code>&#8211;help</code></p>
<dd> Show concise options description. </p>
<dt><code>&#8211;version</code></p>
<dd> Print program version. </p>
</dl>
<h2>UNRECOGNIZED MESSAGES</h2>
<p> texlogsieve automatically handles messages such as &#8220;Package blah Info:&#8230;&#8221; or &#8220;LaTeX Warning:&#8230;&#8221;. However, many messages do not follow this pattern. To do its thing, texlogsieve should know about these other messages beforehand. </p>
<p> While texlogsieve recognizes quite a few messages out of the box, you may run into a message generated by some package that it does not know about (you can check for this using &#8220;-l unknown&#8221;). If that is the case, you can use the &#8211;add-[debug|info|warning|critical]-message options to add it to the list of messages known to the program. </p>
<h2>CONFIGURATION FILE</h2>
<p> texlogsieve always searches automatically for the (optional) <i>,texlogsieverc/</i> configuration file in the TeX path (i.e., it searches using Kpathsea). In the default configuration, the current directory is in the search path, so adding a config file with that name to the project directory is enough to make it work. Options in the config file are exactly the same as the long command-line options described above, but without the preceding &#8220;&#8211;&#8221; characters. Lines starting with a &#8220;#&#8221; sign are comments. An example configuration file: </p>
