<h2>NAME</h2>
<p> tek2plot &#8211; translate Tektronix files to other graphics formats</p>
<h2>SYNOPSIS</h2>
<p> <code>tek2plot </code> [ <i>options </i> ] [ <i>files </i> ]</p>
<h2>DESCRIPTION</h2>
<p> <code>tek2plot </code> translates Tektronix graphics files to other formats, or displays them on an X Window System display. The output format is specified with the <code>-T</code> option. The possible output formats are the same as those supported by <code><a href="/docs/linux/man/1-graph/">graph</a></code>(1), <code><a href="/docs/linux/man/1-plot/">plot</a></code>(1), <code><a href="/docs/linux/man/1-pic2plot/">pic2plot</a></code>(1), and <code><a href="/docs/linux/man/1-plotfont/">plotfont</a></code>(1). If an output file is produced, it is written to standard output. </p>
<p> Options and file names may be interspersed on the command line, but the options are processed before the file names are read. If <code>&#8212; </code> is seen, it is interpreted as the end of the options. If no file names are specified, or the file name <code>&#8211; </code> is encountered, the standard input is read.</p>
<h2>OPTIONS</h2>
<h3>General Options</h3>
<dl>
<dt><code>-T</code><i> type</i></p>
<dd>
<dt><code>&#8211;output-format</code><i> type</i></p>
<dd> Select <i>type</i> as the output format. It may be &quot;X&quot;, &quot;png&quot;, &quot;pnm&quot;, &quot;gif&quot;, &quot;svg&quot;, &quot;ai&quot;, &quot;ps&quot;, &quot;cgm&quot;, &quot;fig&quot;, &quot;pcl&quot;, &quot;hpgl&quot;, &quot;regis&quot;, &quot;tek&quot;, or &quot;meta&quot; (the default). These refer respectively to the X Window System, PNG (Portable Network Graphics) format, portable anymap format (PBM/PGM/PPM), a pseudo-GIF format that does not use LZW encoding, the new XML-based Scalable Vector Graphics format, the format used by Adobe Illustrator, Postscript or Encapsulated Postscript (EPS) that can be edited with <code><a href="/docs/linux/man/1-idraw/">idraw</a></code>(1), CGM format (by default, confirming to the WebCGM profile), the format used by the <code><a href="/docs/linux/man/1-xfig/">xfig</a></code>(1) drawing editor, the Hewlett-Packard PCL 5 printer language, the Hewlett-Packard Graphics Language, ReGIS graphics format (which can be displayed by the <code><a href="/docs/linux/man/1-dxterm/">dxterm</a></code>(1) terminal emulator or by a VT330 or VT340 terminal), Tektronix format itself, and device-independent GNU metafile format. Unless <i>type</i> is &quot;X&quot;, an output file is produced and written to standard output.</p>
<dt>
<dd> Omitting the <code>-T</code> option is equivalent to specifying <code>-T meta</code>. GNU metafile format may be translated to other formats with <code><a href="/docs/linux/man/1-plot/">plot</a></code>(1).</p>
<dt><code>-p</code><i> n</i></p>
<dd>
<dt><code>&#8211;page-number</code><i> n</i></p>
<dd> Output only page number <i>n</i>, within the Tektronix file or sequence of Tektronix files that is being translated. <i>n</i> must be a non-negative integer, since a Tektronix file may consist of one or more pages, numbered beginning with zero.</p>
<dt>
<dd> The default behavior if the <code>-p </code> option is not used is to output all nonempty pages in succession. For example, <code>tek2plot -T X</code> displays each Tektronix page in its own X window. If the <code>-T png</code>, <code>-T pnm</code>, <code>-T gif</code>, <code>-T ai</code>, or <code>-T fig</code> option is used, the default behavior is to output only the first nonempty Tektronix page, since files in those output formats contain only a single page of graphics.</p>
<dt>
<dd> Most Tektronix files consist of either one page (page #0) or two pages (an empty page #0, and page #1). Tektronix files produced by the GNU plotting utilities (e.g., by <code>graph -T tek</code>) are normally of the latter sort.</p>
<dt><code>-F</code><i> name</i></p>
<dd>
<dt><code>&#8211;font-name</code><i> name</i></p>
<dd> Use the font <i>name</i> for rendering the native Textronix fonts, if it is available. The default font is &quot;Courier&quot; except for <code>tek2plot -T png</code>, <code>tek2plot -T pnm</code>, <code>tek2plot -T gif</code>, <code>tek2plot -T hpgl</code>, <code>tek2plot -T regis</code>, and <code>tek2plot -T tek</code>, for which it is &quot;HersheySerif&quot;. A list of available fonts can be obtained with the <code>&#8211;help-fonts</code> option (see below). If a font outside the Courier family is used, the <code>&#8211;position-chars</code> option (see below) should probably be specified.</p>
<dt>
<dd> The <code>-F</code> option is useful only if you have a Tektronix file that draws text using native Tektronix fonts. Tektronix files produced by the GNU plotting utilities (e.g., by <code>graph -T tek</code>) do not use native Tektronix fonts: they use Hershey vector fonts instead.</p>
<dt><code>-W</code><i> line_width</i></p>
<dd>
<dt><code>&#8211;line-width</code><i> line_width</i></p>
<dd> Set the width of lines, as a fraction of the width of the display, to be <i>line_width</i>. A negative value means that a default value should be used. This value is format-dependent. The interpretation of zero line width is also format-dependent (in some output formats, a zero-width line is the thinnest line that can be drawn; in others, a zero-width line is invisible).</p>
<dt><code>&#8211;bg-color</code><i> name</i></p>
<dd> Set the color used for the background to be <i>name</i>. This is relevant only to <code>tek2plot -T X</code>, <code>tek2plot -T png</code>, <code>tek2plot -T pnm</code>, <code>tek2plot -T gif</code>, <code>tek2plot -T svg</code>, <code>tek2plot -T cgm</code>, and <code>tek2plot -T regis</code>. An unrecognized name sets the color to the default, which is &quot;white&quot;. The environment variable <font SIZE="-1"><code>BG_COLOR </code></font> can equally well be used to specify the background color. If the <code>-T svg</code> or <code>-T cgm</code> option is used, an output file without a background may be produced by setting the background color to &quot;none&quot;.</p>
<dt>
<dd> If the <code>-T png</code> or <code>-T gif</code> option is used, a transparent PNG file or a transparent pseudo-GIF, respectively, may be produced by setting the <font SIZE="-1"><code>TRANSPARENT_COLOR </code></font> environment variable to the name of the background color.</p>
<dt><code>&#8211;bitmap-size</code><i> bitmap_size</i></p>
<dd> Set the size of the graphics display in which the plot will be drawn, in terms of pixels, to be <i>bitmap_size</i>. The default is &quot;570&#215;570&quot;. This is relevant only to <code>plot -T X</code>, <code>plot -T png</code>, <code>plot -T pnm</code>, and <code>plot -T gif</code>. If you choose a rectangular (non-square) window size, the fonts in the plot will be scaled anisotropically, i.e., by different factors in the horizontal and vertical directions. For <code>plot -T X</code>, this requires an X11R6 display. Any font that cannot be scaled in this way will be replaced by a default scalable font, such as the vector font &quot;HersheySerif&quot;.</p>
<dt>
<dd> The environment variable <font SIZE="-1"><code>BITMAPSIZE </code></font> can equally well be used to specify the window size. For backward compatibility, the X resource <code>Xplot.geometry</code> may be used instead.</p>
<dt><code>&#8211;emulate-color</code><i> option</i></p>
<dd> If <i>option</i> is <i>yes</i>, replace each color in the output by an appropriate shade of gray. This is seldom useful, except when using ` <code>tek2plot -T pcl</code> to prepare output for a PCL 5 device. (Many monochrome PCL 5 devices, such as monochrome LaserJets, do a poor job of emulating color on their own.) You may equally well request color emulation by setting the environment variable <font SIZE="-1"><code>EMULATE_COLOR </code></font> to &quot;yes&quot;.</p>
<dt><code>&#8211;max-line-length</code><i> max_line_length</i></p>
<dd> Set the maximum number of points that a polygonal line may contain, before it is flushed out, to be <i>max_line_length</i>. If this flushing occurs, the polygonal line will be split into two or more sub-lines, though the splitting should not be noticeable. The default value of <i>max_line_length</i> is 500.</p>
<dt>
<dd> The reason for splitting long polygonal lines is that some display devices (e.g., old Postscript printers and HP-GL pen plotters) have limited buffer sizes. The environment variable <font SIZE="-1"><code>MAX_LINE_LENGTH </code></font> can also be used to specify the maximum line length.</p>
<dt><code>&#8211;page-size</code><i> pagesize</i></p>
<dd> Set the size of the page on which the plot will be positioned. This is relevant only to <code>tek2plot -T svg</code>, <code>tek2plot -T ai</code>, <code>tek2plot -T ps</code>, <code>tek2plot -T cgm</code>, <code>tek2plot -T fig</code>, <code>tek2plot -T pcl</code>, and <code>tek2plot -T hpgl</code>. The default is &quot;letter&quot;, which means an 8.5 inch by 11 inch page. Any ISO page size in the range &quot;a0&quot;&#8230;&quot;a4&quot; or ANSI page size in the range &quot;a&quot;&#8230;&quot;e&quot; may be specified (&quot;letter&quot; is an alias for &quot;a&quot; and &quot;tabloid&quot; is an alias for &quot;b&quot;). &quot;legal&quot; and &quot;ledger&quot; are recognized page sizes also. The environment variable <font SIZE="-1"><code>PAGESIZE </code></font> can equally well be used to specify the page size.</p>
<dt>
<dd> The graphics display in which the plot is drawn will be a square region that would occupy nearly the full width of the specified page. An alternative size for the graphics display can be specified. For example, the page size could be specified as &quot;letter,xsize=4in,ysize=6in&quot;, or &quot;a4,xsize=5.0cm,ysize=100mm&quot;. For all of the above except <code>tek2plot -T hpgl</code>, the graphics display will, by default, be centered on the page. For all of the above except <code>tek2plot -T svg</code> and <code>tek2plot -T cgm</code>, the graphics display may be repositioned manually, by specifying the location of its lower left corner, relative to the lower left corner of the page. For example, the page size could be specified as &quot;letter,xorigin=2in,yorigin=3in&quot;, or &quot;a4,xorigin=0.5cm,yorigin=0.5cm&quot;. It is also possible to specify an offset vector. For example, the page size could be specified as &quot;letter,xoffset=1in&quot;, or &quot;letter,xoffset=1in,yoffset=1.2in&quot;, or &quot;a4,yoffset=-1cm&quot;. In SVG format and WebCGM format it is possible to specify the size of the graphics display, but not its position.</p>
<dt><code>&#8211;pen-color</code><i> name</i></p>
<dd> Set the pen color to be <i>name</i>. An unrecognized name sets the pen color to the default, which is &quot;black&quot;.</p>
<dt><code>&#8211;position-chars</code></p>
<dd> Position the characters in each text string individually. If the text font is not a member of the Courier family, and especially if it is not a fixed-width font, this option is recommended. It will improve the appearance of text strings, at the price of making it difficult to edit the output file with <code><a href="/docs/linux/man/1-xfig/">xfig</a></code>(1), <code><a href="/docs/linux/man/1-idraw/">idraw</a></code>(1), or Illustrator.</p>
<dt><code>&#8211;rotation</code><i> angle</i></p>
<dd> Rotate the graphics display by <i>angle</i> degrees. Recognized values are &quot;0&quot;, &quot;90&quot;, &quot;180&quot;, and &quot;270&quot;. &quot;no&quot; and &quot;yes&quot; are equivalent to &quot;0&quot; and &quot;90&quot;, respectively. The environment variable <font SIZE="-1"><code>ROTATION </code></font> can also be used to specify a rotation angle.</p>
<dt><code>&#8211;use-tek-fonts</code></p>
<dd> Use the bitmap fonts that were used on the original Tektronix 4010/4014 terminal. This option is relevant only to <code>tek2plot -T X</code>. The four relevant bitmap fonts are distributed with most versions of the GNU plotting utilities, under the names &quot;tekfont0&quot;&#8230;&quot;tekfont3&quot;. They can easily be installed on any modern X Window System display. For this option to work properly, you must also select a window size of 1024&#215;1024 pixels, either by using the <code>&#8211;bitmap-size 1024&#215;1024</code> option or by setting the value of the <code>Xplot.geometry</code> resource. This is because bitmap fonts, unlike the scalable fonts that <code>tek2plot</code> normally uses, cannot be rescaled.</p>
<dt>
<dd> This option is useful only if you have a file in Tektronix format that draws text using native Tektronix fonts. Tektronix files produced by the GNU plotting utilities (e.g., by <code>graph -T tek</code>) do not use native Tektronix fonts: they use Hershey vector fonts instead.</dl>
<h3>Options for Metafile Output</h3>
<p> The following option is relevant only if the <code>-T</code> option is omitted or if <code>-T meta</code> is used. In this case <code>tek2plot</code> outputs a GNU graphics metafile, which must be translated to other formats with <code><a href="/docs/linux/man/1-plot/">plot</a></code>(1).</p>
<dl>
<dt><code>-O</code></p>
<dd>
<dt><code>&#8211;portable-output</code></p>
<dd> Output the portable (human-readable) version of GNU metafile format, rather than a binary version (the default). The format of the binary version is machine-dependent.</dl>
<h3>Informational Options</h3>
<dl>
<dt><code>&#8211;help</code></p>
<dd> Print a list of command-line options, and exit.</p>
<dt><code>&#8211;help-fonts</code></p>
<dd> Print a table of available fonts, and exit. The table will depend on which output format is specified with the <code>-T </code> option. <code>tek2plot -T X</code>, <code>tek2plot -T svg</code>, <code>tek2plot -T ai</code>, <code>tek2plot -T ps</code>, <code>tek2plot -T cgm</code>, and <code>tek2plot -T fig</code> each support the 35 standard Postscript fonts. <code>tek2plot -T svg</code>, <code>tek2plot -T pcl</code>, and <code>tek2plot -T hpgl</code> support the 45 standard PCL 5 fonts, and the latter two support a number of Hewlett-Packard vector fonts. All seven support a set of 22 Hershey vector fonts, as do <code>tek2plot -T png</code>, <code>tek2plot -T pnm</code>, <code>tek2plot -T gif</code>, <code>tek2plot -T regis</code>, and <code>tek2plot -T tek</code>. <code>tek2plot</code> without a <code>-T</code> option in principle supports any of these fonts, since its output must be translated to other formats with <code><a href="/docs/linux/man/1-plot/">plot</a></code>(1).</p>
<dt>
<dd> The <code><a href="/docs/linux/man/1-plotfont/">plotfont</a></code>(1) utility may be used to obtain a character map of any supported font.</p>
<dt><code>&#8211;list-fonts</code></p>
<dd> Like <code>&#8211;help-fonts</code>, but lists the fonts in a single column to facilitate piping to other programs. If no output format is specified with the <code>-T</code> option, the full set of supported fonts is listed.</p>
<dt><code>&#8211;version</code></p>
<dd> Print the version number of <code>tek2plot</code> and the plotting utilities package, and exit.</dl>
<h2>ENVIRONMENT</h2>
<p> The environment variables <font SIZE="-1"><code>BITMAPSIZE, </code></font> <font SIZE="-1"><code>PAGESIZE, </code></font> <font SIZE="-1"><code>BG_COLOR, </code></font> <font SIZE="-1"><code>EMULATE_COLOR, </code></font> <font SIZE="-1"><code>MAX_LINE_LENGTH </code></font> and <font SIZE="-1"><code>ROTATION </code></font> serve as backups for the options <code>&#8211;bitmap-size</code>, <code>&#8211;page-size</code>, <code>&#8211;bg-color</code>, <code>&#8211;emulate-color</code>, <code>&#8211;max-line-length</code>, and <code>&#8211;rotation</code>, respectively. The remaining environment variables are specific to individual output formats. </p>
<p> <code>tek2plot -T X</code>, which pops up a window on an X Window System display and draws graphics in it, checks the <font SIZE="-1"><code>DISPLAY </code></font> environment variable. Its value determines the display that will be used. </p>
<p> <code>tek2plot -T png</code> and <code>tek2plot -T gif</code>, which produce output in PNG format and pseudo-GIF format respectively, are affected by the <font SIZE="-1"><code>INTERLACE </code></font> environment variable. If its value is &quot;yes&quot;, the output will be interlaced. Also, if the <font SIZE="-1"><code>TRANSPARENT_COLOR </code></font> environment variable is set to the name of a color, that color will be treated as transparent in the output. </p>
<p> <code>tek2plot -T pnm</code>, which produces output in portable anymap (PBM/PGM/PPM) format, is affected by the <font SIZE="-1"><code>PNM_PORTABLE </code></font> environment variable. If its value is &quot;yes&quot;, the output will be in a human-readable format rather than binary (the default). </p>
<p> <code>tek2plot -T cgm</code>, which produces output in CGM (Computer Graphics Metafile) format, is affected by the <font SIZE="-1"><code>CGM_MAX_VERSION </code></font> and <font SIZE="-1"><code>CGM_ENCODING </code></font> environment variables. By default, it produces a binary-encoded version of CGM version 3 format. For backward compatibility, the version number may be reduced by setting <font SIZE="-1"><code>CGM_MAX_VERSION </code></font> to &quot;2&quot; or &quot;1&quot;. Irrespective of version, the output CGM file will use the human-readable clear text encoding if <font SIZE="-1"><code>CGM_ENCODING </code></font> is set to &quot;clear_text&quot;. However, only binary-encoded CGM files conform to the WebCGM profile. </p>
<p> <code>tek2plot -T pcl</code>, which produces PCL 5 output for Hewlett-Packard printers and plotters, is affected by the environment variable <font SIZE="-1"><code>PCL_ASSIGN_COLORS. </code></font> It should be set to &quot;yes&quot; when producing PCL 5 output for a color printer or other color device. This will ensure accurate color reproduction by giving the output device complete freedom in assigning colors, internally, to its &quot;logical pens&quot;. If it is &quot;no&quot; then the device will use a fixed set of colored pens, and will emulate other colors by shading. The default is &quot;no&quot; because monochrome PCL 5 devices, which are much more common than colored ones, must use shading to emulate color. </p>
<p> <code>tek2plot -T hpgl</code>, which produces Hewlett-Packard Graphics Language output, is affected by several environment variables. The most important is <font SIZE="-1"><code>HPGL_VERSION, </code></font> which may be set to &quot;1&quot;, &quot;1.5&quot;, or &quot;2&quot; (the default). &quot;1&quot; means that the output should be generic HP-GL, &quot;1.5&quot; means that the output should be suitable for the HP7550A graphics plotter and the HP758x, HP7595A and HP7596A drafting plotters (HP-GL with some HP-GL/2 extensions), and &quot;2&quot; means that the output should be modern HP-GL/2. If the version is &quot;1&quot; or &quot;1.5&quot; then the only available fonts will be vector fonts, and all lines will be drawn with a default width (the <code>-W</code> option will not work). </p>
<p> The position of the <code>tek2plot -T hpgl</code> graphics display on the page can be rotated 90 degrees counterclockwise by setting the <font SIZE="-1"><code>HPGL_ROTATE </code></font> environment variable to &quot;yes&quot;. This is not the same as the rotation obtained with the <code>&#8211;rotation</code> option, since it both rotates the graphics display and repositions its lower left corner toward another corner of the page. Besides &quot;no&quot; and &quot;yes&quot;, recognized values for <font SIZE="-1"><code>HPGL_ROTATE </code></font> are &quot;0&quot;, &quot;90&quot;, &quot;180&quot;, and &quot;270&quot;. &quot;no&quot; and &quot;yes&quot; are equivalent to &quot;0&quot; and &quot;90&quot;, respectively. &quot;180&quot; and &quot;270&quot; are supported only if <font SIZE="-1"><code>HPGL_VERSION </code></font> is &quot;2&quot; (the default). </p>
<p> By default, <code>tek2plot -T hpgl</code> will draw with a fixed set of pens. Which pens are present may be specified by setting the <font SIZE="-1"><code>HPGL_PENS </code></font> environment variable. If <font SIZE="-1"><code>HPGL_VERSION </code></font> is &quot;1&quot;, the default value of <font SIZE="-1"><code>HPGL_PENS </code></font> is &quot;1=black&quot;; if <font SIZE="-1"><code>HPGL_VERSION </code></font> is &quot;1.5&quot; or &quot;2&quot;, the default value of <font SIZE="-1"><code>HPGL_PENS </code></font> is &quot;1=black:2=red:3=green:4=yellow:5=blue:6=magenta:7=cyan&quot;. The format should be self-explanatory. By setting <font SIZE="-1"><code>HPGL_PENS </code></font> you may specify a color for any pen in the range #1&#8230;#31. All color names recognized by the X Window System may be used. Pen #1 must always be present, though it need not be black. Any other pen in the range #1&#8230;#31 may be omitted. </p>
<p> If <font SIZE="-1"><code>HPGL_VERSION </code></font> is &quot;2&quot; then <code>tek2plot -T hpgl</code> will also be affected by the environment variable <font SIZE="-1"><code>HPGL_ASSIGN_COLORS. </code></font> If its value is &quot;yes&quot;, then <code>tek2plot -T hpgl</code> will not be restricted to the palette specified in <font SIZE="-1"><code>HPGL_PENS: </code></font> it will assign colors to &quot;logical pens&quot; in the range #1&#8230;#31, as needed. The default value is &quot;no&quot; because other than color LaserJet printers and DesignJet plotters, not many HP-GL/2 devices allow the assignment of colors to logical pens. </p>
<p> The drawing of visible white lines is supported only if <font SIZE="-1"><code>HPGL_VERSION </code></font> is &quot;2&quot; and the environment variable <font SIZE="-1"><code>HPGL_OPAQUE_MODE </code></font> is &quot;yes&quot; (the default). If its value is &quot;no&quot; then white lines (if any), which are normally drawn with pen #0, will not be drawn. This feature is to accommodate older HP-GL/2 devices. HP-GL/2 pen plotters, for example, do not support the use of pen #0 to draw visible white lines. Some older HP-GL/2 devices may, in fact, malfunction if asked to draw opaque objects.</p>
