<h2 class="name">NAME</h2>
<p> tracker-index &#8211; List, pause, resume and command data miners indexing content</p>
<h2>SYNOPSIS</h2>
<pre><code>
tracker index-- reindex - mime - type&lt;mime1&gt;[[-m[mime2]]...] tracker index-- file&lt;file1&gt; [[file2]...] tracker index-- import &lt;file1&gt; [[file2]...] tracker index-- backup&lt;file&gt; | --restore&lt;file&gt;
</code></pre>
<h2>DESCRIPTION</h2>
<p> This command perform actions on the current index. The &quot;index&quot; holds a snapshot of the working tree in a database. </p>
<p> The index command allows some level of control on existing data indexed, such as re-indexing content from a specific demographic &#8211; e.g. all JPEG images, or simply reindexing an existing or non-existent file. </p>
<p> It may be a good idea to backup your index before an upgrade in case there is data loss (which should never happen). In those cases, the backup command is made available and of course the restore command will import an older data set (or index) into an empty index. </p>
<p> Finally, there is an import feature which makes testing or applying a &quot;base&quot; data set for use much easier. </p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-m, &#8211;reindex-mime-type</code>=&lt;<i>mime1</i>&gt; [[-m [<i>mime2</i>]] &#8230;]</p>
<dd> Re-index files which match the <i>mime</i> type supplied. This is usually used when installing new extractors which support <i>mime</i> types previously unsupported. This forces Tracker to re-index those files. You can use <code>&#8211;reindex-mime-type</code> more than once per <i>mime</i> type.</p>
<dt><code>-f, &#8211;index</code>=&lt;<i>file1</i>&gt; [[<i>file2</i>] &#8230;]</p>
<dd> (Re)index a file matching the <i>file</i> name(s) supplied.</p>
<dt><code>-b, &#8211;backup</code>=&lt;<i>file</i>&gt;</p>
<dd> Begins backing up the Tracker databases and save it to the <i>file</i> given.</p>
<dt><code>-o, &#8211;restore</code>=&lt;<i>file</i>&gt;</p>
<dd> Begins restoring a previous backup from the <i>file</i> which points to the location of the backup generated by <code>&#8211;backup</code>.</p>
<dt><code>i, &#8211;import</code>=&lt;<i>file1</i>&gt; [[<i>file2</i>] &#8230;]</p>
<dd> Allows data to be imported into the index / database by providing files with Turtle content. </p>
<p> Multiple <i>file</i> arguments can be provided to import data from multiple files. </p>
<p> The <i>file</i> argument can be either a local path or a URI. It also does not have to be an absolute path. </p>
</dl>
