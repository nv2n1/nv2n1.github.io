<h2 class="name">NAME</h2>
<p> hh_server &#8211; Hack language typechecker daemon</p>
<h2>SYNOPSIS</h2>
<p> <code>hh_server</code> [<i>&#8211;check&nbsp;</i>[<i>&#8211;json</i>]] <i>DIRECTORY</i> </p>
<h2>DESCRIPTION</h2>
<p> <code><a href="/docs/linux/man/1-hh_server/">hh_server</a></code>(1) is the actual typechecker that enforces the Hack type system. It is typically accessed via <code><a href="/docs/linux/man/1-hh_client/">hh_client</a></code>(1); see the documentation for that tool for more information on the Hack type system and how to interface with <code><a href="/docs/linux/man/1-hh_server/">hh_server</a></code>(1). </p>
<p> Directly invoking <code><a href="/docs/linux/man/1-hh_server/">hh_server</a></code>(1) is of minimal use, since <code><a href="/docs/linux/man/1-hh_client/">hh_client</a></code>(1) will start and stop it as needed. The only widely useful manual invocation is <i>&#8211;check</i> mode. </p>
<p> With no options, <code><a href="/docs/linux/man/1-hh_server/">hh_server</a></code>(1) will start up, do an initial typecheck of <i>DIRECTORY</i>, and continue running, waiting for connections from <code><a href="/docs/linux/man/1-hh_client/">hh_client</a></code>(1). Again, this is not the normal way the server should be invoked &#8212; just running <code><a href="/docs/linux/man/1-hh_client/">hh_client</a></code>(1) and ignoring the existence of this server binary is sufficient for common use. </p>
<h2>OPTIONS</h2>
<dl>
<dt><code>&#8211;check</code></p>
<dd> Start up, check the <i>DIRECTORY</i>, print type errors in a human-readable format, and then exit. This &quot;batch mode&quot; might be useful in cases where a single check is needed and so starting a long-running daemon is not appropriate, such as in a pre-commit hook. The output is intended for human consumption, not tools; for tool consumption, see <code>&#8211;json</code> below. </p>
<dt><code>&#8211;json</code></p>
<dd> If <code>&#8211;check</code> is specified, generate machine-readable JSON output instead of the human-readable output generated by default. </p>
<dt><code>&#8211;check</code><i> TARGET</i></p>
<dd> Start up and check <i>DIRECTORY</i> in the same manner as <code>&#8211;check</code> mode. Then, re-check <i>TARGET</i> and attempt to add type annotations to locations in those files that are missing. The analysis process is slow and imperfect, but often useful. This process can change the code in ways that fail at runtime; see <i><a rel="nofollow" href="http://docs.hhvm.com/hack/tools/introduction">http://docs.hhvm.com/hack/tools/introduction</a></i> for detailed information on how to combine this mode with <code><a href="/docs/linux/man/1-hackificator/">hackificator</a></code>(1) and <code><a href="/docs/linux/man/1-hack_remove_soft_types/">hack_remove_soft_types</a></code>(1) to do a full and safe conversion from PHP to Hack. </p>
</dl>
<h2>EXIT STATUS</h2>
<p> If <code>&#8211;check</code> is specified, exits with 0 if there are no type errors, nonzero otherwise. Other exit values are undefined. </p>
<h2>ENVIRONMENT and FILES</h2>
<p> Uses the same scheme for constructing a path to a socket for client/server communication that <code><a href="/docs/linux/man/1-hh_client/">hh_client</a></code>(1) uses. See its documentation for a description. </p>
<h2>EXAMPLE</h2>
<p> It might be useful to have a pre-commit hook to make sure that type errors don&#8217;t sneak into trunk. A hook might want to directly invoke <code><a href="/docs/linux/man/1-hh_server/">hh_server</a></code>(1) so that it doesn&#8217;t need a running daemon. That can be done with something like </p>
<pre>
<dl><dt><dd>hh_server --check /var/www
</dl>
</pre>
<p> and, if that fails, printing its output and rejecting the commit. For tool usage, something like </p>
<pre>
<dl><dt><dd>hh_server --check --json /var/www
</dl>
</pre>
<p> might be more appropriate; the JSON output can be passed up to a code review tool and displayed there. </p>
<p> This is only for cases where having a long-running daemon is inappropriate. For normal development usage, invoking <code><a href="/docs/linux/man/1-hh_client/">hh_client</a></code>(1) and allowing it to use the server itself will be much faster to check code and return type errors. </p>
