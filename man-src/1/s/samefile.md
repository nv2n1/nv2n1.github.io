<h2 class="name">NAME</h2>
<p> samefile &#8211; find identical files </p>
<h2>SYNOPSIS</h2>
<p> <code>samefile [-g size] [-l | -r] [-s sep] [-0aiqVvx]</code></p>
<h2>DESCRIPTION</h2>
<p> <code>samefile</code> reads a list of filenames (one filename per line) from stdin. For each filename pair with identical contents, a line consisting of six fields is output: The size in bytes, two filenames, the character &#8220;=&#8221; if the two files are on the same device, &#8220;X&#8221; otherwise, and the link counts of the two files. The output is sorted in reverse order by size as the primary key and the filenames as the secondary key.</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-0</code></p>
<dd> Indicates that the input list of file names is NUL terminated, for example as generated by implementations of <code><a href="/docs/linux/man/1-find/">find</a></code>(1) that support the <code>-print0</code> option. Without this option, the file names are assumed to be newline terminated.</p>
<dt><code>-a</code></p>
<dd> Do not sort files with same size alphabetically.</p>
<dt><code>-g size</code></p>
<dd> Compare only files with size greater than <i>size</i> bytes. Default is 0.</p>
<dt><code>-i</code></p>
<dd> Allow files with the same device/i-node pair to be added to the binary tree. This might be useful if output will be fed into some other program. If this option is used, the statistics displayed when using <code>-v</code> will not contain the &#8220;You have a total of x bytes in identical files&#8221; line because <code>-i</code> prohibits proper calculation of this value.</p>
<dt><code>-l</code></p>
<dd> Do not check if files with identical contents are hard links created by <code><a href="/docs/linux/man/1-ln/">ln</a></code>(1). By default, <code>samefile</code> checks if files with identical contents are hard linked and, if they are, does not write a name pair to stdout. A slight speedup is gained when using this option. This option is incompatible with the <code>-r</code> option.</p>
<dt><code>-q</code></p>
<dd> Do not issue warning messages when <code><a href="/docs/linux/man/2-open/">open</a></code>(2) fails. When you encounter such a warning, <code>open</code> probably failed due to a &#8216;permission denied&#8217; error on files or directories for which you have no read permission. Useful if you are not root and want to compare your files against files in a system directory like <i>/etc</i></p>
<dt><code>-r</code></p>
<dd> Report whether identical files are hard linked. The separator string followed by the [bracketed] link count is appended to each name pair if they are hard links created with <code>ln</code>. This option is incompatible with the <code>-l</code> option. Note that this kind of output has only four fields and will appear unsorted before the actual output of <code>samefile</code>.</p>
<dt><code>-s sep</code></p>
<dd> Use string <code>sep</code> as the output field separator, defaults to a tab character. Useful if filenames contain tab characters and output must be processed by another program, say <code><a href="/docs/linux/man/1-awk/">awk</a></code>(1).</p>
<dt><code>-V</code></p>
<dd> Print the version information and exit.</p>
<dt><code>-v</code></p>
<dd> verbose mode. Write some statistical messages about memory usage and work reduction as well as the sum of the sizes of all identical files to stderr.</p>
<dt><code>-x</code></p>
<dd> Switch off intelligence. This option prevents <code>samefile</code> from being smart. If files <i>file1, file2</i> and <i>file3</i> are identical, it will do 3 comparisons instead of just the two needed and write more output. See the discussion under INTERNALS why this could be useful. If this option is used, the statistics displayed when using <code>-v</code> will not contain the &#8220;You have a total of x bytes in identical files&#8221; line because <code>-x</code> prohibits proper calculation of this value.</dl>
<h2>INTERNALS</h2>
<p> <code>samefile</code> uses two stages to give optimum performance. </p>
<p> In the first stage, all non-plain files are skipped (directories, devices, FIFOs, sockets, symbolic links) as well as files for which <code><a href="/docs/linux/man/2-stat/">stat</a></code>(2) fails and files that have a size less than or equal to <i>size.</i> Output of the first stage (the filenames) is written into a binary tree with one node for every file size. It is also at this early stage where checks for hard links are done. If hard links are found, and <code>-r</code> is requested, the name pairs are output immediately. The whole list of hard linked name pairs will therefore appear before any output of the second stage. </p>
<p> For any i-node only one filename will be added to the binary tree (unless <code>-i</code> was requested.) </p>
<p> In the second stage all files having the same size are compared against each other. The rules of mathematical logic are applied to reduce work and output noise (unless <code>-x</code> is requested): if files a, b, and c have the same size and <code>samefile</code> finds that a = b and a = c then it will not compare b against c (and will not output a line for b and c) but only for a = b and a = c. Note however, that because only the first filename per i-node gets into the second stage, the output for a group of identical files with different i-node numbers is also minimized. Suppose you have six identical files of size 100 in an i-node group consisting of the three i-nodes with numbers 10, 20 and 30 (the term &#8216;i-node group&#8217; has nothing to do with the i-node group notion of some file systems &#8211; it merely refers to a set of i-nodes addressing files with identical contents): </p>
<pre>
$ ls -i
   10 file1     20 file4     30 file6
   10 file2     20 file5
   10 file3
$ ls | samefile
100     file1   file4   =       3       2
100     file1   file6   =       3       1
</pre>
<p> The sum of the sizes in the first column is the amount of disk space you could gain by making all 6 files links to only one file or remove all but one of the files. To be precise, disk space is allocated in blocks &#8211; you will probably gain two blocks here, rather than 200 bytes. Note that it is not enough to just remove file4 and file6 (you would gain only 100 bytes because file5 still exists.) The proper way is to use the -i option. The output will look like </p>
<pre>
100     file1   file2   =       3       3
100     file1   file3   =       3       3
100     file1   file4   =       3       2
100     file1   file5   =       3       2
100     file1   file6   =       3       1
</pre>
<p> Removing all files listed in the third field will leave only file1. Making all files hard links to file1 is easy. If the fourth field is a &#8220;=&#8221; do a forced hard link. If you need to know about <i>all</i> combinations of identical files, then you use both the <code>-i</code> and <code>-x</code> option. This produces </p>
<pre>
$ ls | samefile -ix
100     file1   file2   =       3       3
100     file1   file3   =       3       3
100     file1   file4   =       3       2
100     file1   file5   =       3       2
100     file1   file6   =       3       1
100     file2   file3   =       3       3
100     file2   file4   =       3       2
100     file2   file5   =       3       2
100     file2   file6   =       3       1
100     file3   file4   =       3       2
100     file3   file5   =       3       2
100     file3   file6   =       3       1
100     file4   file5   =       2       2
100     file4   file6   =       2       1
100     file5   file6   =       2       1
</pre>
<h2>EXAMPLES</h2>
<p> Find all identical files in the current working directory: </p>
<pre>
$ ls | samefile
</pre>
<p> Find all identical files in my HOME directory and subdirectories and also tell me if there are hard links: </p>
<pre>
$ find $HOME -type f | samefile -r
</pre>
<p> Find all identical files in the <i>/usr</i> directory tree that are bigger than 10000 bytes and write the result to <i>usr.dups</i> (that one is for the sysadmin folks, you may want to &#8216;amp&#8217; &#8211; put it in the background with the ampersand &amp; &#8211; this command because it takes a few minutes.) </p>
<pre>
$ find /usr -type f | samefile -g 10000 &gt;usr.dups
</pre>
<h2>DIAGNOSTICS</h2>
<p> You will see a short usage message if you use an invalid option.</p>
<dl>
<dt>malloc &#8211; free = xxxx</p>
<dd> I didn&#8217;t free the memory I&#8217;ve <code><a href="/docs/linux/man/3-malloc/">malloc</a></code>(3)ed. You found a bug. Please report it to the author.</p>
<dt>Allocation failed for &#8216;expr&#8217; &#8230;</p>
<dd> Oops! You ran out of virtual memory. You must have a real big filename list. Try to use a smaller one or increase resources available to your processes. For more information see <code><a href="/docs/linux/man/1-ulimit/">ulimit</a></code>(1) or your similar shell builtin.</dl>
