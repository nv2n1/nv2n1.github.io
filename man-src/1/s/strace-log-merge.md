<h2 class="name">NAME</h2>
<p> strace-log-merge &#8211; merge strace -ff -tt output </p>
<h2>SYNOPSIS</h2>
<p> <i>STRACE_LOG</i> <code>&#8211;help</code><i>&nbsp;</i></p>
<h2>DESCRIPTION</h2>
<p> <code>strace-log-merge</code> merges the output of <code>strace -ff -tt[t]</code> command, prepending PID to each line and sorting the result using time stamp as a key.</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>&#8211;help</code></p>
<dd> Show program usage and exit.</p>
<dt><i>STRACE_LOG</i></p>
<dd> Output file name prefix of files produced by a <code>strace -ff -tt[t]</code> command.</dl>
<h2>EXIT STATUS</h2>
<dl>
<dt><code>0</code></p>
<dd> Success</p>
<dt><code>Non-zero</code></p>
<dd> Error occurred: either no argument specified (in that case a usage is printed), or something went wrong during the processing of <i>STRACE_LOG</i>.* files.</dl>

<h2>NOTES</h2>
<p> <i>strace-log-merge</i> does not work well with <code>strace</code> logs generated by <code>strace -tt</code> invocation that pass midnight, as those lack the information required for the proper sorting. Employing the <code>-ttt</code> option in the respective <code>strace</code> invocation should solve the problem.</p>
<h2>BUGS</h2>
<p> <i>strace-log-merge</i> does not perform any checks whether the files specified are in the correct format and implies that only files from a single <i>strace</i> session match <i>STRACE_LOG</i>.* glob pattern.</p>
<h2>HISTORY</h2>
