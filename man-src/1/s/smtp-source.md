<h2 class="name">NAME</h2>
<p> smtp-source &#8211; parallelized SMTP/LMTP test generator </p>
<h2>SYNOPSIS</h2>
<p> <code>smtp-source</code> [<i>options</i>] [<code>inet:</code>]<i>host</i>[:<i>port</i>] </p>
<p> <code>smtp-source</code> [<i>options</i>] <code>unix:</code><i>pathname</i></p>
<h2>DESCRIPTION</h2>
<p> <code>smtp-source</code> connects to the named <i>host</i> and TCP <i>port</i> (default: port 25) and sends one or more messages to it, either sequentially or in parallel. The program speaks either SMTP (default) or LMTP. Connections can be made to UNIX-domain and IPv4 or IPv6 servers. IPv4 and IPv6 are the default. </p>
<p> Note: this is an unsupported test program. No attempt is made to maintain compatibility between successive versions. </p>
<p> Arguments:</p>
<dl>
<dt><code>-4</code></p>
<dd> Connect to the server with IPv4. This option has no effect when Postfix is built without IPv6 support.</p>
<dt><code>-6</code></p>
<dd> Connect to the server with IPv6. This option is not available when Postfix is built without IPv6 support.</p>
<dt><code>-A</code></p>
<dd> Don&#8217;t abort when the server sends something other than the expected positive reply code.</p>
<dt><code>-c</code></p>
<dd> Display a running counter that is incremented each time an SMTP DATA command completes.</p>
<dt><code>-C </code><i>count</i></p>
<dd> When a host sends RESET instead of SYN|ACK, try <i>count</i> times before giving up. The default count is 1. Specify a larger count in order to work around a problem with TCP/IP stacks that send RESET when the listen queue is full.</p>
<dt><code>-d</code></p>
<dd> Don&#8217;t disconnect after sending a message; send the next message over the same connection.</p>
<dt><code>-f </code><i>from</i></p>
<dd> Use the specified sender address (default: &lt;foo [at] myhostname&gt;).</p>
<dt><code>-F </code><i>file</i></p>
<dd> Send the pre-formatted message header and body in the specified <i>file</i>, while prepending &#8216;.&#8217; before lines that begin with &#8216;.&#8217;, and while appending CRLF after each line.</p>
<dt><code>-l </code><i>length</i></p>
<dd> Send <i>length</i> bytes as message payload. The length does not include message headers.</p>
<dt><code>-L</code></p>
<dd> Speak LMTP rather than SMTP.</p>
<dt><code>-m </code><i>message_count</i></p>
<dd> Send the specified number of messages (default: 1).</p>
<dt><code>-M </code><i>myhostname</i></p>
<dd> Use the specified hostname or [address] in the HELO command and in the default sender and recipient addresses, instead of the machine hostname.</p>
<dt><code>-N</code></p>
<dd> Prepend a non-repeating sequence number to each recipient address. This avoids the artificial 100% hit rate in the resolve and rewrite client caches and exercises the trivial-rewrite daemon, better approximating Postfix performance under real-life work-loads.</p>
<dt><code>-o</code></p>
<dd> Old mode: don&#8217;t send HELO, and don&#8217;t send message headers.</p>
<dt><code>-r </code><i>recipient_count</i></p>
<dd> Send the specified number of recipients per transaction (default: 1). Recipient names are generated by prepending a number to the recipient address.</p>
<dt><code>-R </code><i>interval</i></p>
<dd> Wait for a random period of time 0 &lt;= n &lt;= interval between messages. Suspending one thread does not affect other delivery threads.</p>
<dt><code>-s </code><i>session_count</i></p>
<dd> Run the specified number of SMTP sessions in parallel (default: 1).</p>
<dt><code>-S </code><i>subject</i></p>
<dd> Send mail with the named subject line (default: none).</p>
<dt><code>-t </code><i>to</i></p>
<dd> Use the specified recipient address (default: &lt;foo [at] myhostname&gt;).</p>
<dt><code>-T </code><i>windowsize</i></p>
<dd> Override the default TCP window size. To work around broken TCP window scaling implementations, specify a value &gt; 0 and &lt; 65536.</p>
<dt><code>-v</code></p>
<dd> Make the program more verbose, for debugging purposes.</p>
<dt><code>-w </code><i>interval</i></p>
<dd> Wait a fixed time between messages. Suspending one thread does not affect other delivery threads.</p>
<dt>[<code>inet:</code>]<i>host</i>[:<i>port</i>]</p>
<dd> Connect via TCP to host <i>host</i>, port <i>port</i>. The default port is <code>smtp</code>.</p>
<dt><code>unix:</code><i>pathname</i></p>
<dd> Connect to the UNIX-domain socket at <i>pathname</i>.</dl>
<h2>BUGS</h2>
<p> No SMTP command pipelining support.</p>
