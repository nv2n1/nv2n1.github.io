<h2 class="name">NAME</h2>
<p> crtest &#8211; test cases for QDBM Curia</p>
<h2>SYNOPSIS</h2>
<p> <code>crtest write</code> [-s] [-lob] <i>name</i> <i>rnum</i> <i>bnum</i> <i>dnum</i><br />
 <code>crtest read</code> [-wb] [-lob] <i>name</i><br />
 <code>crtest rcat</code> [-c] <i>name</i> <i>rnum</i> <i>bnum</i> <i>dnum</i> <i>pnum</i> <i>align</i><br />
 <code>crtest combo</code> <i>name</i><br />
 <code>crtest wicked</code> [-c] <i>name</i> rnum </p>
<h2>DESCRIPTION</h2>
<p> The command `crtest&#8217; is a utility for facility test and performance test. Check a database generated by the command or measure the execution time of the command. This command is used in the following format. `name&#8217; specifies a database name. `rnum&#8217; specifies the number of records. `bnum&#8217; specifies the number of elements of a bucket array. `dnum&#8217; specifies the number of division of a database. `pnum&#8217; specifies the number of patterns of the keys. `align&#8217; specifies the basic size of alignment. `fbpsiz&#8217; specifies the size of the free block pool. </p>
<dl>
<dt><code>crtest write [-s] [-lob] name rnum bnum dnum</code></p>
<dd> Store records with keys of 8 bytes. They change as `00000001&#8242;, `00000002&#8217;&#8230;</p>
<dt><code>crtest read [-wb] [-lob] name</code></p>
<dd> Retrieve all records of the database above.</p>
<dt><code>crtest rcat [-c] name rnum bnum dnum pnum align fbpsiz</code></p>
<dd> Store records with partway duplicated keys using concatenate mode.</p>
<dt><code>crtest combo name</code></p>
<dd> Perform combination test of various operations.</p>
<dt><code>crtest wicked [-c] name rnum</code></p>
<dd> Perform updating operations selected at random.</dl>
<p> Options feature the following. </p>
<dl>
<dt>
<dd> <code>-s</code> : make the files sparse.<br />
 <code>-lob</code> : handle large objects.<br />
 <code>-wb</code> : use the function `crgetwb&#8217; instead of the function `crget&#8217;.<br />
 <code>-c</code> : perform comparison test with map of Cabin.</dl>
<p> This command returns 0 on success, another on failure. The environment variable `QDBMDBGFD&#8217; specifies the file descriptor to output the history of updating the variable `dpecode&#8217;. </p>
