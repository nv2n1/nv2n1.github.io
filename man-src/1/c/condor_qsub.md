<h2>Name</h2>
<p> <i>condor_qsub</i> Queue jobs that use PBS/SGE-style submission </p>
<h2>Synopsis</h2>
<p> <i>condor_qsub</i> [ &#8212; <code>version</code> ] </p>
<p> <i>condor_qsub</i> [ <code>Specific options</code> ] [ <code>Directory options</code> ] [ <code>Environmental options</code> ] [ <code>File options</code> ] [ <code>Notification options</code> ] [ <code>Resource options</code> ] [ <code>Status options</code> ] [ <code>Submission options</code> ] <i>commandfile</i> </p>
<h2>Description</h2>
<p> <i>condor_qsub</i> submits an HTCondor job. This job is specified in a PBS/Torque style or an SGE style. <i>condor_qsub</i> permits the submission of dependent jobs without the need to specify the full dependency graph at submission time. Doing things this way is neither as efficient as HTCondor&#8217;s DAGMan, nor as functional as SGE&#8217;s <i>qsub</i> or <i>qalter</i> . <i>condor_qsub</i> serves as a minimal translator to be able to use software originally written to interact with PBS, Torque, and SGE in an HTCondor pool. </p>
<p> <i>condor_qsub</i> attempts to behave like <i>qsub</i> . Less than half of the <i>qsub</i> functionality is implemented. Option descriptions describe the differences between the behavior of <i>qsub</i> and <i>condor_qsub</i> . <i>qsub</i> options not listed here are not supported. Some concepts present in PBS and SGE do not apply to HTCondor, and so these options are not implemented. </p>
<p> For a full listing of <i>qsub</i> options, please see </p>

<p> <i>condor_qsub</i> accepts either command line options or the single file, <i>commandfile</i> , that contains all of the commands. </p>
<p> <i>condor_qsub</i> does the opposite of job submission within the <code>grid</code> universe <code>batch</code> grid type, which takes HTCondor jobs submitted with HTCondor syntax and submits them to PBS, SGE, or LSF. </p>
<h2>Options</h2>
<p> <code>-a </code> <i>date_time</i></p>
<dl>
<dt>
<dd> (Submission option) Specify a deferred execution date and time. The PBS/Torque syntax of <i>date_time</i> is a string in the form <i>[[[[CC]YY]MM]DD]hhmm[.SS]</i> . The portions of this string which are optional are <i>CC</i> , <i>YY</i> , <i>MM</i> , <i>DD</i> , and <i>SS</i> . For SGE, <i>MM</i> and <i>DD</i> are <i>not</i> optional. For PBS, <i>MM</i> and <i>DD</i> are optional. <i>condor_qsub</i> follows the PBS style.</p>
<dt>
<dd></dl>
<p> <code>-A </code> <i>account_string</i></p>
<dl>
<dt>
<dd> (Status option) Uses group accounting where the string <i>account_string</i> is the accounting group associated with this job. Unlike SGE, there is no default group of &quot;sge&quot; .</p>
<dt>
<dd></dl>
<p> <code>-b </code> <i>y|n</i></p>
<dl>
<dt>
<dd> (Submission option) Using the SGE definition of its <i>-b</i> option, a value of <i>y</i> causes <i>condor_qsub</i> to <i>not</i> parse the file for additional <i>condor_qsub</i> commands. The default value is <i>n</i> . If the command line argument <code>-f </code> <i>filename</i> is also specified, it negates a value of <i>y</i> .</p>
<dt>
<dd></dl>
<p> <code>-c </code> <i>checkpoint_option</i></p>
<dl>
<dt>
<dd> (Submission option) For standard universe jobs only, controls the how HTCondor produces checkpoints. <i>checkpoint_options</i> may be one of</p>
<dt>
<dd> <code>n or N</code></p>
<dt>
<dd> Do not produce checkpoints.</p>
<dt>
<dd>
<dt>
<dd> <code>s or S</code></p>
<dt>
<dd> Do not produce periodic checkpoints. A job will only produce a checkpoint when the job is evicted.</p>
<dt>
<dd> More options may be implemented in the future.</p>
<dt>
<dd></dl>
<p> <code>&#8211;condor-keep-files</code></p>
<dl>
<dt>
<dd> (Specific option) Directs HTCondor to <i>not</i> remove temporary files generated by <i>condor_qsub</i> , such as HTCondor submit files and sentinel jobs. These temporary files may be important for debugging.</p>
<dt>
<dd></dl>
<p> <code>-cwd</code></p>
<dl>
<dt>
<dd> (Directory option) Specifies the initial directory in which the job will run to be the current directory from which the job was submitted. This sets <code>initialdir</code> for <i>condor_submit</i> .</p>
<dt>
<dd></dl>
<p> <code>-d </code> <i>path</i> or <code>-wd </code> <i>path</i></p>
<dl>
<dt>
<dd> (Directory option) Specifies the initial directory in which the job will run to be <i>path</i> . This sets <code>initialdir</code> for <i>condor_submit</i> .</p>
<dt>
<dd></dl>
<p> <code>-e </code> <i>filename</i></p>
<dl>
<dt>
<dd> (File option) Specifies the <i>condor_submit</i> command <code>error</code> , the file where stderr is written. If not specified, set to the default name of &lt;commandfile&gt;.e&lt;ClusterId&gt; , where &lt;commandfile&gt; is the <i>condor_qsub</i> argument, and &lt;ClusterId&gt; is the job attribute ClusterId assigned for the job.</p>
<dt>
<dd></dl>
<p> <code>&#8211;f </code> <i>qsub_file</i></p>
<dl>
<dt>
<dd> (Specific option) Parse <i>qsub_file</i> to search for and set additional <i>condor_submit</i> commands. Within the file, commands will appear as #PBS or #SGE . <i>condor_qsub</i> will parse the batch file listed as <i>qsub_file</i> .</p>
<dt>
<dd></dl>
<p> <code>-h</code></p>
<dl>
<dt>
<dd> (Status option) Placed submitted job directly into the hold state.</p>
<dt>
<dd></dl>
<p> <code>&#8211;help</code></p>
<dl>
<dt>
<dd> (Specific option) Print usage information and exit.</p>
<dt>
<dd></dl>
<p> <code>-hold_jid </code> <i>&lt;jid&gt;</i></p>
<dl>
<dt>
<dd> (Status option) Submits a job in the hold state. This job is released only when a previously submitted job, identified by its cluster ID as <i>&lt;jid&gt;</i> , exits successfully. Successful completion is defined as not exiting with exit code 100. In implementation, there are three jobs that define this SGE feature. The first job is the previously submitted job. The second job is the newly submitted one that is waiting for the first to finish successfully. The third job is what SGE calls a <i>sentinel</i> job; this is an HTCondor local universe job that watches the history for the first job&#8217;s exit code. This third job will exit once it has seen the exit code and, for a successful termination of the first job, run <i>condor_release</i> on the second job. If the first job is an array job, the second job will only be released after all individual jobs of the first job have completed.</p>
<dt>
<dd></dl>
<p> <code>-i </code> <i>[hostname:]filename </i></p>
<dl>
<dt>
<dd> (File option) Specifies the <i>condor_submit</i> command <code>input</code> , the file from which stdin is read.</p>
<dt>
<dd></dl>
<p> <code>-j </code> <i>characters</i></p>
<dl>
<dt>
<dd> (File option) Acceptable characters for this option are e , o , and n . The only sequence that is relevant is eo ; it specifies that both standard output and standard error are to be sent to the same file. The file will be the one specified by the <code>-o</code> option, if both the <code>-o</code> and <code>-e</code> options exist. The file will be the one specified by the <code>-e</code> option, if only the <code>-e</code> option is provided. If neither the <code>-o</code> nor the <code>-e</code> options are provided, the file will be the default used for the <code>-o</code> option.</p>
<dt>
<dd></dl>
<p> <code>-l </code> <i>resource_spec</i></p>
<dl>
<dt>
<dd> (Resource option) Specifies requirements for the job, such as the amount of RAM and the number of CPUs. Only PBS-style resource requests are supported. <i>resource_spec</i> is a comma separated list of key/value pairs. Each pair is of the form resource_name=value . resource_name and value may be</p>
<dt>
<dd>
&nbsp;<wbr>resource_name&nbsp;<wbr>&nbsp;<wbr>value DescriptionarchstringSets&nbsp;<wbr>&nbsp;<wbr>Arch machine attribute. Enclose in double quotes.filesizeDisk space requested.hoststringHost machine on which the job must run.memsizeAmount of memory requested.nodes&nbsp;<wbr>{&lt;node_count&gt;&nbsp;<wbr>|&nbsp;<wbr>&lt;hostname&gt;}&nbsp;<wbr>[:ppn=&lt;ppn&gt;]&nbsp;<wbr>[:gpus=&lt;gpu&gt;]&nbsp;<wbr>[:&lt;property&gt;&nbsp;<wbr>[:&lt;property&gt;]&nbsp;<wbr>&#8230;]&nbsp;<wbr>[+&nbsp;<wbr>&#8230;]&nbsp;<wbr>Number and/or properties of nodes to be used. For examples, please see&nbsp;<wbr><a rel="nofollow" href="http://docs.adaptivecomputing.com/torque/4-1-3/Content/topics/2-jobs/requestingRes.htm#qsubopsysstringSets">http://docs.adaptivecomputing.com/torque/4-1-3/Content/topics/2-jobs/requestingRes.htm#qsubopsysstringSets</a>&nbsp;<wbr>&nbsp;<wbr>OpSys machine attribute. Enclose in double quotes.procsintegerNumber of CPUs requested.A size value is an integer specified in bytes, following the PBS/Torque default. Append&nbsp;<wbr>&nbsp;<wbr>Kb ,&nbsp;<wbr>&nbsp;<wbr>Mb ,&nbsp;<wbr>&nbsp;<wbr>Gb , or&nbsp;<wbr>&nbsp;<wbr>Tb to specify the value in powers of two quantities greater than bytes.&nbsp;<wbr></p>
<dt>
<dd></dl>
<p> <code>-m </code> <i>a|e|n</i></p>
<dl>
<dt>
<dd> (Notification option) Identify when HTCondor sends notification e-mail. If <i>a</i> , send e-mail when the job terminates abnormally. If <i>e</i> , send e-mail when the job terminates. If <i>n</i> , never send e-mail.</p>
<dt>
<dd></dl>
<p> <code>-M </code> <i>e-mail_address</i></p>
<dl>
<dt>
<dd> (Notification option) Sets the destination address for HTCondor e-mail.</p>
<dt>
<dd></dl>
<p> <code>-o </code> <i>filename</i></p>
<dl>
<dt>
<dd> (File option) Specifies the <i>condor_submit</i> command <code>output</code> , the file where stdout is written. If not specified, set to the default name of &lt;commandfile&gt;.o&lt;ClusterId&gt; , where &lt;commandfile&gt; is the <i>condor_qsub</i> argument, and &lt;ClusterId&gt; is the job attribute ClusterId assigned for the job.</p>
<dt>
<dd></dl>
<p> <code>-p </code> <i>integer</i></p>
<dl>
<dt>
<dd> (Status option) Sets the <code>priority</code> submit command for the job, with 0 being the default. Jobs with higher numerical priority will run before jobs with lower numerical priority.</p>
<dt>
<dd></dl>
<p> <code>&#8211;print</code></p>
<dl>
<dt>
<dd> (Specific option) Send to stdout the contents of the HTCondor submit description file that <i>condor_qsub</i> generates.</p>
<dt>
<dd></dl>
<p> <code>-r </code> <i>y|n</i></p>
<dl>
<dt>
<dd> (Status option) The default value of <i>y</i> implements the default HTCondor policy of assuming that jobs that do not complete are placed back in the queue to be run again. When <i>n</i> , job submission is restricted to only running the job if the job ClassAd attribute NumJobStarts is currently 0. This identifies the job as not re-runnable, limiting it to start once.</p>
<dt>
<dd></dl>
<p> <code>-S </code> <i>shell</i></p>
<dl>
<dt>
<dd> (Submission option) Specifies the path and executable name of a shell. Alters the HTCondor submit description file produced, such that the executable becomes a wrapper script. Within the submit description file will be executable = &lt;shell&gt; and arguments = &lt;commandfile&gt; .</p>
<dt>
<dd></dl>
<p> <code>-t </code> <i>start [-stop:step] </i></p>
<dl>
<dt>
<dd> (Submission option) Queues a set of nearly identical jobs. The SGE-style syntax is supported. <i>start</i> , <i>stop</i> , and <i>step</i> are all integers. <i>start</i> is the starting index of the jobs, <i>stop</i> is the ending index (inclusive) of the jobs, and <i>step</i> is the step size through the indices. Note that using more than one processor or node in a job will not work with this option.</p>
<dt>
<dd></dl>
<p> <code>&#8211;test</code></p>
<dl>
<dt>
<dd> (Specific option) With the intention of testing a potential job submission, parse files and commands to generate error output. Produces, but then removes the HTCondor submit description file. Never submits the job, even if no errors are encountered.</p>
<dt>
<dd></dl>
<p> <code>-v </code> <i>variable list</i></p>
<dl>
<dt>
<dd> (Environmental option) Used to set the submit command <code>environment</code> for the job. <i>variable list</i> is as that defined for the submit command. Note that the syntax needed is specialized to deal with quote marks and white space characters.</p>
<dt>
<dd></dl>
<p> <code>-V</code></p>
<dl>
<dt>
<dd> (Environmental option) Sets getenv = True in the submit description file.</p>
<dt>
<dd></dl>
<p> <code>-W </code> <i>attr_name=attr_value[,attr_name=attr_value&#8230;]</i></p>
<dl>
<dt>
<dd> (File option) PBS/Torque supports a number of attributes. However, <i>condor_qsub</i> only supports the names <i>stagein</i> and <i>stageout</i> for <i>attr_name</i> . The format of <i>attr_value</i> for <i>stagein</i> and <i>stageout</i> is local_file [at] hostname:remote_file[,&#8230;] and we strip it to remote_file[,&#8230;] . HTCondor&#8217;s file transfer mechanism is then used if needed.</p>
<dt>
<dd></dl>
<p> <code>&#8211;version</code></p>
<dl>
<dt>
<dd> (Specific option) Print version information for the <i>condor_qsub</i> program and exit. Note that <i>condor_qsub</i> has its own version numbers which are separate from those of HTCondor.</p>
<dt>
<dd></dl>
<h2>Exit Status</h2>
<p> <i>condor_qsub</i> will exit with a status value of 0 (zero) upon success, and it will exit with the value 1 (one) upon failure to submit a job. </p>
