<h2 class="name">NAME</h2>
<p> cernlib-static &#8211; get libraries needed to link with CERN Program Library </p>
<h2>SYNOPSIS</h2>
<p> <code>cernlib-static</code> [options] <i>library[/version]</i> <i>&#8230;</i> </p>
<h2>DESCRIPTION</h2>
<p> <code>cernlib-static</code> writes to standard output a list of object libraries needed to link a program with the given <i>library(s)</i> of CERNlib; other libraries needed implicitely, both CERNlib and system libraries, are added automatically. <i>library</i> may be any of the CERNlib libraries using a short name like packlib, mathlib, graflib, phtools&#8230; </p>
<p> <i>version</i> allows to specify which version to use for this library, see usage notes. </p>
<h3>Options</h3>
<p> <code>cernlib-static </code> recognizes the following options: </p>
<dl>
<dt><code>-G&nbsp;<wbr></code><i>driver</i></p>
<dd> specifies the graphics interface to use. Defaults to X11. The choices available depend on the system in use:</p>
<dl>
<dt>
<dd>
<dl>
<dt>X11</p>
<dd> all systems. On HP/UX X11R5 is used when available on the system.</p>
<dt>Motif</p>
<dd> all systems. On HP/UX Motif1.2 is used when available on the system.</p>
<dt>GKS</p>
<dd> Vendor specific graphics, DEC Ultrix, IBM/RS6000, SUN only</p>
<dt>GPR</p>
<dd> Vendor specific graphics, Apollo only.</p>
<dt>GL</p>
<dd> Vendor specific graphics, IBM/RS6000 and SGI only.</dl>
</dl>
<dt><code>-s</code></p>
<dd> obsolete option. Ignored. </p>
<dt><code>-l</code></p>
<dd> Don&#8217;t link against system lapack and blas. </p>
<dt><code>-u</code></p>
<dd> do <code>not</code> automatically add vendor libraries needed to link, but not specified by the user. </p>
<dt><code>-v&nbsp;<wbr></code><i>version</i></p>
<dd> Use level <i>version</i> of CERNlib libraries; <i>version </i> can be pro, new or old, or you may specify the explicit version number; the default version is pro. The global version can be overwritten for an individual library by specifying the <i>library </i> as <i>library/version.</i> </p>
</dl>
<h3>USAGE</h3>
<p> <code>cernlib-static </code> expects to find the CERNlib directory tree in /cern; if your system does not have this, set the environment variable CERN to contain the name of the root directory for the CERNlib tree. </p>
<p> After the <i>library</i> a version for that library different from the default version may be specified. The possible values are as for the <code>-v </code> option, or in the case of graflib as for the <code>-G</code> option. </p>
<h3>EXAMPLES</h3>
<p> As <code>cernlib-static</code> writes the list of libraries to standard output, using it as a command will show the list of libraries generated by cernlib-static. Also, it can be used like other commands in the command line surrounded by back quotes(`). At CERN you should use the hepf77 command to link on your system as this gives the compiler parameters which are compatible with Cernlib (in particular for xlf on IBM/RS6000 and fort77 on HP/UX ) you could type:</p>
<dl>
<dt>
<dd> hepf77 your.o `cernlib-static`</dl>
<p> to link your object file with routines from packlib and kernlib; you need not specify packlib, as this is added automatically. Also all kernlib routines are included in packlib. If your application uses graflib and the Motif interface, the command would be:</p>
<dl>
<dt>
<dd> hepf77 your.o `cernlib-static graflib/Motif`</dl>
<p> Again packlib need not be specified. </p>
<p> If you prefer to have an environment variable CERNLIB set at login time, put the following into</p>
<dl>
<dt>
<dd>
&nbsp;<wbr>.profile for sh, ksh or similar</p>
<dl>
<dt>
<dd> CERNLIB=`cernlib-static graflib`; export CERNLIB</dl>
<p>&nbsp;<wbr>.login for users of csh of similar</p>
<dl>
<dt>
<dd> setenv CERNLIB &quot;`cernlib-static graflib`&quot;</dl>
</dl>
<p> The CERNLIB variable can then be used in the link command instead of calling the cernlib-static command. </p>
<h3>BUGS</h3>
<p> There is no checking that any of the libraries (or options) are valid or exist. Most loaders only check the libraries once for symbols, hence the order the libraries given is important. This command does not check that the order given is correct. </p>
<p> For systems other than Alliant, Apollo, DEC Ultrix, Digital Unix (or DEC OSF), HP/UX, SGI, Linux, Sun OS, Sun Solaris the libraries given for the graphics interface are likely to be wrong, even for X11 and Motif. </p>
<h3>FILES</h3>
<p> The cernlib-static command is available in the /cern/pro/bin directory in the CERNlib tree. </p>
