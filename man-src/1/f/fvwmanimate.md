<p><code>FvwmAnimate</code> &#8211; the fvwm animate module </p>
<h2>Synopsis</h2>
<p>Module FvwmAnimate [ModuleAlias] </p>
<p> <code>FvwmAnimate</code> can only be invoked by fvwm. Command line invocation of the FvwmAnimate module will not work. </p>
<p> From within the .fvwm2rc file, <code>FvwmAnimate</code> is spawned as follows: </p>
<pre>Module FvwmAnimate</pre>
<p>or from within an fvwm pop-up menu: </p>
<pre>DestroyMenu Module-Popup
AddToMenu Module-Popup &quot;Modules&quot; Title
+ &quot;Fvwm Animate Icons&quot; Module FvwmAnimate ModuleAlias</pre>
<h2>Description</h2>
<p>The <code>FvwmAnimate</code> module animates iconification and de-iconification or on command. There are currently 6 different animation effects. </p>
<h2>Invocation</h2>
<p><code>FvwmAnimate</code> must be invoked by the <code>fvwm</code> window manager. When invoked with the <i>OptionalName</i> argument, the <i>ModuleAlias</i> is used to find configuration commands, configuration files, and name the internally generated menus and forms instead of &quot;FvwmAnimate&quot;. During startup, FvwmAnimate defines menus and forms for configuring and controlling FvwmAnimate. The default menu name is &quot;MenuFvwmAnimate&quot; and the form name is &quot;FormFvwmAnimate&quot;. If the optional name is used, the menu would be &quot;Menu&lt;ModuleAlias&gt;&quot; and the form would be &quot;Form&lt;ModuleAlias&gt;&quot;. </p>
<p> Assuming you already had a builtin menu called &quot;Module-Popup&quot;, you could use FvwmAnimate by configuring it like this: </p>
<pre>AddToFunc &quot;StartFunction&quot; &quot;I&quot; Module FvwmAnimate
AddToMenu &quot;Module-Popup&quot; &quot;Control Animation&quot; Popup MenuFvwmAnimate</pre>
<h2>Configuration Options</h2>
<p>Since the pop up menu &quot;MenuFvwmAnimate&quot; allows complete control of the <code>FvwmAnimate</code> module, you don&#8217;t really have to know what any of the configuration commands are. This section describes them anyway. </p>
<p> <code>FvwmAnimate</code> gets configuration info from <code>fvwm</code>&#8216;s module configuration database (see <i><a href="/docs/linux/man/1-fvwm/">fvwm</a></i>(1), section <code>MODULE COMMANDS</code>). In addition, <code>FvwmAnimate</code> reads the file $HOME/.FvwmAnimate, and accepts commands from fvwm and its modules as it runs. </p>
<p> If <i>ModuleAlias</i> is used to start FvwmAnimate, the optional name is used in all commands, messages, menus and forms generated by FvwmAnimate and in the configuration file name. Unlike other fvwm modules, there is little reason to use the optional name. </p>
<dl>
<dt>*FvwmAnimate: Color <code>color</code></p>
<dd>Tells <code>FvwmAnimate</code> what color to draw with. The color is &quot;XOR&#8217;ed&quot; (exclusive ORed) onto the background. Depending on the display type you are using, the effect this causes will vary. Especially on 8-bit displays, it helps if the background is a solid color. You have to experiment with this to see how it works. </p>
<p> The default color is not really a color and can be entered as &quot;Black^White&quot;, or more simply &quot;None&quot;. This is the same as the default XOR mask used by fvwm for move and resize frames. </p>
<p> Other colors can be specified using standard X color notation. Ie. color names like &quot;LightBlue&quot;, or RGB values like &quot;#FFFFFF&quot;. </p>
<dt>*FvwmAnimate: Pixmap <code>pixmap</code></p>
<dd>Tells <code>FvwmAnimate</code> to use <code>pixmap</code> to draw with. This can be useful if <code>*FvwmAnimate: Color</code> gives poor results. </p>
<dt>*FvwmAnimate: Delay <code>msecs</code></p>
<dd>Tells <code>FvwmAnimate</code> how many milliseconds to sleep between frames of animation. </p>
<dt>*FvwmAnimate: Iterations <code>iterations</code></p>
<dd>Tells <code>FvwmAnimate</code> how many steps to break the animation into. </p>
<dt>*FvwmAnimate: Twist <code>twist</code></p>
<dd>Tells <code>FvwmAnimate</code> how many revolutions to twist the iconification frame. </p>
<dt>*FvwmAnimate: Width <code>width</code></p>
<dd>Tells <code>FvwmAnimate</code> how wide a line to draw with. The default width of 0 (zero) is a fast line of Width 1. </p>
<dt>*FvwmAnimate: Effect <code>mode</code></p>
<dd>Tells <code>FvwmAnimate</code> which animation effect to use. Currently the effects are: <i>Frame</i>, <i>Lines</i>, <i>Flip</i>, <i>Turn</i>, <i>Zoom3D</i>, <i>Twist</i> <i>Random</i>, and <i>None</i>. <i>None</i> is normally set in the configuration file, in-case FvwmAnimate is started automatically, but an individual user doesn&#8217;t want it running. </p>
<dt>*FvwmAnimate: Stop</p>
<dd>Tells <code>FvwmAnimate</code> to stop. </p>
<dt>*FvwmAnimate: Save</p>
<dd>Tells <code>FvwmAnimate</code> to save the current configuration in a file named &quot;.FvwmAnimate&quot; in the users home directory. This same file is read automatically by FvwmAnimate during startup. </p>
</dl>
<h2>Commands</h2>
<p><code>FvwmAnimate</code> can be asked to produce an animation thru the &quot;SendToModule&quot; command. The format of the command is: </p>
<pre>SendToModule FvwmAnimate animate sx sy sw sh dx dy dw dh</pre>
<p>The second word must match the name <code>FvwmAnimate</code> is started with. The 8 fields after <i>animate</i> must be numbers. The first 4 are for the source (or starting) location of the animation. The last 4 are for the destination of the animation. The 2 pairs of 4 numbers, represent rectangles. The first 2 numbers are the x and y location of the upper right corner. The next 2 numbers are the width and height. One or more spaces can separate the fields in the command. </p>
<p> Modules can use the &quot;SendToModule&quot; command to animate &quot;NoIcon&quot; windows, or you can think up your own ways to have all kinds of fun with this command. </p>
<p> Additional available commands are: <i>pause</i>, <i>play</i>, <i>push</i>, <i>pop</i> and <i>reset</i>. These may be space separated. </p>
<p> <i>pause</i> causes a module to not temporarily produce any animations. <i>play</i> causes a module to produce an animation again. <i>push</i> stores the current playing state for a future and <i>pop</i> restores it. <i>reset</i> removes all stored states and sets playing on. </p>
<p> Suppose, we don&#8217;t want to wait for all 40 xterms to be animated: </p>
<pre>SendToModule FvwmAnimate pause
All (XTerm) Iconify on</pre>
<p>And if we don&#8217;t want to damage the current playing state, then: </p>
<pre>SendToModule FvwmAnimate push pause
All (XTerm) Iconify on
SendToModule FvwmAnimate pop</pre>
