<h2 class="name">NAME</h2>
<p> ffserver &#8211; ffserver video server </p>
<h2>SYNOPSIS</h2>
<p> ffserver [<i>options</i>]</p>
<h2>DESCRIPTION</h2>
<p> <code>ffserver</code> is a streaming server for both audio and video. It supports several live feeds, streaming from files and time shifting on live feeds. You can seek to positions in the past on each live feed, provided you specify a big enough feed storage. </p>
<p> <code>ffserver</code> is configured through a configuration file, which is read at startup. If not explicitly specified, it will read from <i>/etc/ffserver.conf</i>. </p>
<p> <code>ffserver</code> receives prerecorded files or <font SIZE="-1">FFM</font> streams from some <code>ffmpeg</code> instance as input, then streams them over <font SIZE="-1">RTP/RTSP/HTTP.</font> </p>
<p> An <code>ffserver</code> instance will listen on some port as specified in the configuration file. You can launch one or more instances of <code>ffmpeg</code> and send one or more <font SIZE="-1">FFM</font> streams to the port where ffserver is expecting to receive them. Alternately, you can make <code>ffserver</code> launch such <code>ffmpeg</code> instances at startup. </p>
<p> Input streams are called feeds, and each one is specified by a <tt>&quot;&lt;Feed&gt;&quot;</tt> section in the configuration file. </p>
<p> For each feed you can have different output streams in various formats, each one specified by a <tt>&quot;&lt;Stream&gt;&quot;</tt> section in the configuration file.</p>
<h2>DETAILED DESCRIPTION</h2>
<p> <code>ffserver</code> works by forwarding streams encoded by <code>ffmpeg</code>, or pre-recorded streams which are read from disk. </p>
<p> Precisely, <code>ffserver</code> acts as an <font SIZE="-1">HTTP</font> server, accepting <font SIZE="-1">POST</font> requests from <code>ffmpeg</code> to acquire the stream to publish, and serving <font SIZE="-1">RTSP</font> clients or <font SIZE="-1">HTTP</font> clients <font SIZE="-1">GET</font> requests with the stream media content. </p>
<p> A feed is an <font SIZE="-1"><code>FFM</code></font> stream created by <code>ffmpeg</code>, and sent to a port where <code>ffserver</code> is listening. </p>
<p> Each feed is identified by a unique name, corresponding to the name of the resource published on <code>ffserver</code>, and is configured by a dedicated <tt>&quot;Feed&quot;</tt> section in the configuration file. </p>
<p> The feed publish <font SIZE="-1">URL</font> is given by: </p>
<pre>
        http://&lt;ffserver_ip_address&gt;:&lt;http_port&gt;/&lt;feed_name&gt;
</pre>
<p> where <i>ffserver_ip_address</i> is the <font SIZE="-1">IP</font> address of the machine where <code>ffserver</code> is installed, <i>http_port</i> is the port number of the <font SIZE="-1">HTTP</font> server (configured through the <code>HTTPPort</code> option), and <i>feed_name</i> is the name of the corresponding feed defined in the configuration file. </p>
<p> Each feed is associated to a file which is stored on disk. This stored file is used to send pre-recorded data to a player as fast as possible when new content is added in real-time to the stream. </p>
<p> A &#8220;live-stream&#8221; or &#8220;stream&#8221; is a resource published by <code>ffserver</code>, and made accessible through the <font SIZE="-1">HTTP</font> protocol to clients. </p>
<p> A stream can be connected to a feed, or to a file. In the first case, the published stream is forwarded from the corresponding feed generated by a running instance of <code>ffmpeg</code>, in the second case the stream is read from a pre-recorded file. </p>
<p> Each stream is identified by a unique name, corresponding to the name of the resource served by <code>ffserver</code>, and is configured by a dedicated <tt>&quot;Stream&quot;</tt> section in the configuration file. </p>
<p> The stream access <font SIZE="-1">HTTP URL</font> is given by: </p>
<pre>
        http://&lt;ffserver_ip_address&gt;:&lt;http_port&gt;/&lt;stream_name&gt;[&lt;options&gt;]
</pre>
<p> The stream access <font SIZE="-1">RTSP URL</font> is given by: </p>
<pre>
        http://&lt;ffserver_ip_address&gt;:&lt;rtsp_port&gt;/&lt;stream_name&gt;[&lt;options&gt;]
</pre>
<p> <i>stream_name</i> is the name of the corresponding stream defined in the configuration file. <i>options</i> is a list of options specified after the <font SIZE="-1">URL</font> which affects how the stream is served by <code>ffserver</code>. <i>http_port</i> and <i>rtsp_port</i> are the <font SIZE="-1">HTTP</font> and <font SIZE="-1">RTSP</font> ports configured with the options <i>HTTPPort</i> and <i>RTSPPort</i> respectively. </p>
<p> In case the stream is associated to a feed, the encoding parameters must be configured in the stream configuration. They are sent to <code>ffmpeg</code> when setting up the encoding. This allows <code>ffserver</code> to define the encoding parameters used by the <code>ffmpeg</code> encoders. </p>
<p> The <code>ffmpeg</code> <code>override_ffserver</code> commandline option allows one to override the encoding parameters set by the server. </p>
<p> Multiple streams can be connected to the same feed. </p>
<p> For example, you can have a situation described by the following graph: </p>
<pre><code>
_________ __________ | | | |
    ffmpeg 1 -- -- - | feed 1 | -- -- - | stream 1 |
            \ | _________ |\ | __________ |
             \                    \
              \                    \ __________
               \                    \ | |
                \                    \| stream 2 |
                 \ | __________ |
                  \
                   \ _________ __________
                    \ | | | |
                     \| feed 2 | -- -- - | stream 3 |
    | _________ | | __________ |

    _________ __________ | | | |
    ffmpeg 2 -- -- - | feed 3 | -- -- - | stream 4 |
    | _________ | | __________ |

    _________ __________ | | | |
    | file 1 | -- -- - | stream 5 |
    | _________ | | __________ |
</code></pre>
<h3><font SIZE="-1">FFM, FFM2</font> formats</h3>
<p> <font SIZE="-1">FFM</font> and <font SIZE="-1">FFM2</font> are formats used by ffserver. They allow storing a wide variety of video and audio streams and encoding options, and can store a moving time segment of an infinite movie or a whole movie. </p>
<p> <font SIZE="-1">FFM</font> is version specific, and there is limited compatibility of <font SIZE="-1">FFM</font> files generated by one version of ffmpeg/ffserver and another version of ffmpeg/ffserver. It may work but it is not guaranteed to work. </p>
<p> <font SIZE="-1">FFM2</font> is extensible while maintaining compatibility and should work between differing versions of tools. <font SIZE="-1">FFM2</font> is the default.</p>
<h3>Status stream</h3>
<p> <code>ffserver</code> supports an <font SIZE="-1">HTTP</font> interface which exposes the current status of the server. </p>
<p> Simply point your browser to the address of the special status stream specified in the configuration file. </p>
<p> For example if you have: </p>
<pre>
        &lt;Stream status.html&gt;
        Format status
        
        # Only allow local people to get the status
        ACL allow localhost
        ACL allow 192.168.0.0 192.168.255.255
        &lt;/Stream&gt;
</pre>
<p> then the server will post a page with the status information when the special stream <i>status.html</i> is requested.</p>
<h3>How do I make it work?</h3>
<p> As a simple test, just run the following two command lines where <font SIZE="-1">INPUTFILE</font> is some file which you can decode with ffmpeg: </p>
<pre>
        ffserver -f doc/ffserver.conf &amp;
        ffmpeg -i INPUTFILE <a rel="nofollow" href="http://localhost:8090/feed1.ffm">http://localhost:8090/feed1.ffm</a>
</pre>
<p> At this point you should be able to go to your Windows machine and fire up Windows Media Player (<font SIZE="-1">WMP</font>). Go to Open <font SIZE="-1">URL</font> and enter </p>
<pre>
            http://&lt;linuxbox&gt;:8090/test.asf
</pre>
<p> You should (after a short delay) see video and hear audio. </p>
<p> <font SIZE="-1">WARNING:</font> trying to stream test1.mpg doesn&#8217;t work with <font SIZE="-1">WMP</font> as it tries to transfer the entire file before starting to play. The same is true of <font SIZE="-1">AVI</font> files. </p>
<p> You should edit the <i>ffserver.conf</i> file to suit your needs (in terms of frame rates etc). Then install <code>ffserver</code> and <code>ffmpeg</code>, write a script to start them up, and off you go.</p>
<h3>What else can it do?</h3>
<p> You can replay video from .ffm files that was recorded earlier. However, there are a number of caveats, including the fact that the ffserver parameters must match the original parameters used to record the file. If they do not, then ffserver deletes the file before recording into it. (Now that I write this, it seems broken). </p>
<p> You can fiddle with many of the codec choices and encoding parameters, and there are a bunch more parameters that you cannot control. Post a message to the mailing list if there are some &#8216;must have&#8217; parameters. Look in ffserver.conf for a list of the currently available controls. </p>
<p> It will automatically generate the <font SIZE="-1">ASX</font> or <font SIZE="-1">RAM</font> files that are often used in browsers. These files are actually redirections to the underlying <font SIZE="-1">ASF</font> or <font SIZE="-1">RM</font> file. The reason for this is that the browser often fetches the entire file before starting up the external viewer. The redirection files are very small and can be transferred quickly. [The stream itself is often &#8216;infinite&#8217; and thus the browser tries to download it and never finishes.]</p>
<h3>Tips</h3>
<p> * When you connect to a live stream, most players (<font SIZE="-1">WMP, RA,</font> etc) want to buffer a certain number of seconds of material so that they can display the signal continuously. However, ffserver (by default) starts sending data in realtime. This means that there is a pause of a few seconds while the buffering is being done by the player. The good news is that this can be cured by adding a &#8216;?buffer=5&#8217; to the end of the <font SIZE="-1">URL.</font> This means that the stream should start 5 seconds in the past &#8212; and so the first 5 seconds of the stream are sent as fast as the network will allow. It will then slow down to real time. This noticeably improves the startup experience. </p>
<p> You can also add a &#8216;Preroll 15&#8217; statement into the ffserver.conf that will add the 15 second prebuffering on all requests that do not otherwise specify a time. In addition, ffserver will skip frames until a key_frame is found. This further reduces the startup delay by not transferring data that will be discarded.</p>
<h3>Why does the ?buffer / Preroll stop working after a time?</h3>
<p> It turns out that (on my machine at least) the number of frames successfully grabbed is marginally less than the number that ought to be grabbed. This means that the timestamp in the encoded data stream gets behind realtime. This means that if you say &#8216;Preroll 10&#8217;, then when the stream gets 10 or more seconds behind, there is no Preroll left. </p>
<p> Fixing this requires a change in the internals of how timestamps are handled.</p>
<h3>Does the ?date= stuff work.</h3>
<p> Yes (subject to the limitation outlined above). Also note that whenever you start ffserver, it deletes the ffm file (if any parameters have changed), thus wiping out what you had recorded before. </p>
<p> The format of the <tt>&quot;?date=xxxxxx&quot;</tt> is fairly flexible. You should use one of the following formats (the &#8216;T&#8217; is literal): </p>
<pre>
        * YYYY-MM-DDTHH:MM:SS     (localtime)
        * YYYY-MM-DDTHH:MM:SSZ    (UTC)
</pre>
<p> You can omit the YYYY-MM-DD, and then it refers to the current day. However note that <code>?date=16:00:00</code> refers to 16:00 on the current day &#8212; this may be in the future and so is unlikely to be useful. </p>
<p> You use this by adding the ?date= to the end of the <font SIZE="-1">URL</font> for the stream. For example: <code><a rel="nofollow" href="http://localhost:8080/test.asf?date=2002-07-26T23:05:00">http://localhost:8080/test.asf?date=2002-07-26T23:05:00</a></code>.</p>
<h2>OPTIONS</h2>
<p> All the numerical options, if not specified otherwise, accept a string representing a number as input, which may be followed by one of the <font SIZE="-1">SI</font> unit prefixes, for example: &#8216;K&#8217;, &#8216;M&#8217;, or &#8216;G&#8217;. </p>
<p> If &#8216;i&#8217; is appended to the <font SIZE="-1">SI</font> unit prefix, the complete prefix will be interpreted as a unit prefix for binary multiples, which are based on powers of 1024 instead of powers of 1000. Appending &#8216;B&#8217; to the <font SIZE="-1">SI</font> unit prefix multiplies the value by 8. This allows using, for example: &#8216;<font SIZE="-1">KB</font>&#8216;, &#8216;MiB&#8217;, &#8216;G&#8217; and &#8216;B&#8217; as number suffixes. </p>
<p> Options which do not take arguments are boolean options, and set the corresponding value to true. They can be set to false by prefixing the option name with &#8220;no&#8221;. For example using &#8220;-nofoo&#8221; will set the boolean option with name &#8220;foo&#8221; to false.</p>
<h3>Stream specifiers</h3>
<p> Some options are applied per-stream, e.g. bitrate or codec. Stream specifiers are used to precisely specify which stream(s) a given option belongs to. </p>
<p> A stream specifier is a string generally appended to the option name and separated from it by a colon. E.g. <tt>&quot;-codec:a:1 ac3&quot;</tt> contains the <tt>&quot;a:1&quot;</tt> stream specifier, which matches the second audio stream. Therefore, it would select the ac3 codec for the second audio stream. </p>
<p> A stream specifier can match several streams, so that the option is applied to all of them. E.g. the stream specifier in <tt>&quot;-b:a 128k&quot;</tt> matches all audio streams. </p>
<p> An empty stream specifier matches all streams. For example, <tt>&quot;-codec copy&quot;</tt> or <tt>&quot;-codec: copy&quot;</tt> would copy all the streams without reencoding. </p>
<p> Possible forms of stream specifiers are:</p>
<dl>
<dt><i>stream_index</i></p>
<dd> Matches the stream with this index. E.g. <tt>&quot;-threads:1 4&quot;</tt> would set the thread count for the second stream to 4.</p>
<dt><i>stream_type</i><code>[:</code><i>stream_index</i><code>]</code></p>
<dd> <i>stream_type</i> is one of following: &#8216;v&#8217; or &#8216;V&#8217; for video, &#8216;a&#8217; for audio, &#8216;s&#8217; for subtitle, &#8216;d&#8217; for data, and &#8216;t&#8217; for attachments. &#8216;v&#8217; matches all video streams, &#8216;V&#8217; only matches video streams which are not attached pictures, video thumbnails or cover arts. If <i>stream_index</i> is given, then it matches stream number <i>stream_index</i> of this type. Otherwise, it matches all streams of this type.</p>
<dt><code>p:</code><i>program_id</i><code>[:</code><i>stream_index</i><code>]</code></p>
<dd> If <i>stream_index</i> is given, then it matches the stream with number <i>stream_index</i> in the program with the id <i>program_id</i>. Otherwise, it matches all streams in the program.</p>
<dt><code>#</code><i>stream_id</i> <code>or i:</code><i>stream_id</i></p>
<dd> Match the stream by stream id (e.g. <font SIZE="-1">PID</font> in MPEG-TS container).</p>
<dt><code>m:</code><i>key</i><code>[:</code><i>value</i><code>]</code></p>
<dd> Matches streams with the metadata tag <i>key</i> having the specified value. If <i>value</i> is not given, matches streams that contain the given tag with any value.</p>
<dt><code>u</code></p>
<dd> Matches streams with usable configuration, the codec must be defined and the essential information such as video dimension or audio sample rate must be present. </p>
<p> Note that in <code>ffmpeg</code>, matching by metadata will only work properly for input files.</dl>

<dt><code>-opencl_bench</code></p>
<dd> This option is used to benchmark all available OpenCL devices and print the results. This option is only available when FFmpeg has been compiled with <tt>&quot;--enable-opencl&quot;</tt>. </p>
<p> When FFmpeg is configured with <tt>&quot;--enable-opencl&quot;</tt>, the options for the global OpenCL context are set via <code>-opencl_options</code>. See the &#8220;OpenCL Options&#8221; section in the ffmpeg-utils manual for the complete list of supported options. Amongst others, these options include the ability to select a specific platform and device to run the OpenCL code on. By default, FFmpeg will run on the first device of the first platform. While the options for the global OpenCL context provide flexibility to the user in selecting the OpenCL device of their choice, most users would probably want to select the fastest OpenCL device for their system. </p>
<p> This option assists the selection of the most efficient configuration by identifying the appropriate device for the user&#8217;s system. The built-in benchmark is run on all the OpenCL devices and the performance is measured for each device. The devices in the results list are sorted based on their performance with the fastest device listed first. The user can subsequently invoke <code>ffmpeg</code> using the device deemed most appropriate via <code>-opencl_options</code> to obtain the best performance for the OpenCL accelerated code. </p>
<p> Typical usage to use the fastest OpenCL device involve the following steps. </p>
<p> Run the command: </p>
<pre>
        ffmpeg -opencl_bench
</pre>
<p> Note down the platform <font SIZE="-1">ID</font> (<i>pidx</i>) and device <font SIZE="-1">ID</font> (<i>didx</i>) of the first i.e. fastest device in the list. Select the platform and device using the command: </p>
<pre>
        ffmpeg -opencl_options platform_idx=&lt;pidx&gt;:device_idx=&lt;didx&gt; ...
</pre>
<dt><code>-opencl_options options (</code><i>global</i><code>)</code></p>
<dd> Set OpenCL environment options. This option is only available when FFmpeg has been compiled with <tt>&quot;--enable-opencl&quot;</tt>. </p>
<p> <i>options</i> must be a list of <i>key</i>=<i>value</i> option pairs separated by &#8216;:&#8217;. See the &#8220;OpenCL Options&#8221; section in the ffmpeg-utils manual for the list of supported options.</dl>
<h3>AVOptions</h3>
<p> These options are provided directly by the libavformat, libavdevice and libavcodec libraries. To see the list of available AVOptions, use the <code>-help</code> option. They are separated into two categories:</p>
<dl>
<dt><code>generic</code></p>
<dd> These options can be set for any container, codec or device. Generic options are listed under AVFormatContext options for containers/devices and under AVCodecContext options for codecs.</p>
<dt><code>private</code></p>
<dd> These options are specific to the given container, device or codec. Private options are listed under their corresponding containers/devices/codecs.</dl>
<p> For example to write an ID3v2.3 header instead of a default ID3v2.4 to an <font SIZE="-1">MP3</font> file, use the <code>id3v2_version</code> private option of the <font SIZE="-1">MP3</font> muxer: </p>
<pre>
        ffmpeg -i input.flac -id3v2_version 3 out.mp3
</pre>
<p> All codec AVOptions are per-stream, and thus a stream specifier should be attached to them. </p>
<p> Note: the <code>-nooption</code> syntax cannot be used for boolean AVOptions, use <code>-option 0</code>/<code>-option 1</code>. </p>
<p> Note: the old undocumented way of specifying per-stream AVOptions by prepending v/a/s to the options name is now obsolete and will be removed soon.</p>
<h3>Main options</h3>
<dl>
<dt><code>-f</code> <i>configfile</i></p>
<dd> Read configuration file <i>configfile</i>. If not specified it will read by default from <i>/etc/ffserver.conf</i>.</p>
<dt><code>-n</code></p>
<dd> Enable no-launch mode. This option disables all the <tt>&quot;Launch&quot;</tt> directives within the various <tt>&quot;&lt;Feed&gt;&quot;</tt> sections. Since <code>ffserver</code> will not launch any <code>ffmpeg</code> instances, you will have to launch them manually.</p>
<dt><code>-d</code></p>
<dd> Enable debug mode. This option increases log verbosity, and directs log messages to stdout. When specified, the <code>CustomLog</code> option is ignored.</dl>
<h2>CONFIGURATION FILE SYNTAX</h2>
<p> <code>ffserver</code> reads a configuration file containing global options and settings for each stream and feed. </p>
<p> The configuration file consists of global options and dedicated sections, which must be introduced by &quot;&lt;<i></i><font SIZE="-1"><i>SECTION_NAME</i></font><i></i> <i></i><font SIZE="-1"><i>ARGS</i></font><i></i>&gt;&#8220; on a separate line and must be terminated by a line in the form &#8221;&lt;/<i></i><font SIZE="-1"><i>SECTION_NAME</i></font><i></i>&gt;&quot;. <i></i><font SIZE="-1"><i>ARGS</i></font><i></i> is optional. </p>
<p> Currently the following sections are recognized: <code>Feed</code>, <code>Stream</code>, <code>Redirect</code>. </p>
<p> A line starting with <tt>&quot;#&quot;</tt> is ignored and treated as a comment. </p>
<p> Name of options and sections are case-insensitive.</p>
<h3><font SIZE="-1">ACL</font> syntax</h3>
<p> An <font SIZE="-1">ACL</font> (Access Control List) specifies the address which are allowed to access a given stream, or to write a given feed. </p>
<p> It accepts the following forms</p>
<dl>
<dt>&bull;</p>
<dd> Allow/deny access to <i>address</i>. </p>
<pre>
        ACL ALLOW &lt;address&gt;
        ACL DENY &lt;address&gt;
</pre>
<dt>&bull;</p>
<dd> Allow/deny access to ranges of addresses from <i>first_address</i> to <i>last_address</i>. </p>
<pre>
        ACL ALLOW &lt;first_address&gt; &lt;last_address&gt;
        ACL DENY &lt;first_address&gt; &lt;last_address&gt;
</pre>
</dl>
<p> You can repeat the <font SIZE="-1">ACL</font> allow/deny as often as you like. It is on a per stream basis. The first match defines the action. If there are no matches, then the default is the inverse of the last <font SIZE="-1">ACL</font> statement. </p>
<p> Thus &#8216;<font SIZE="-1">ACL</font> allow localhost&#8217; only allows access from localhost. &#8216;<font SIZE="-1">ACL</font> deny 1.0.0.0 1.255.255.255&#8242; would deny the whole of network 1 and allow everybody else.</p>
<h3>Global options</h3>
<dl>
<dt><code>HTTPPort</code> <i>port_number</i></p>
<dd>
<dt><code>Port</code> <i>port_number</i></p>
<dd>
<dt><code>RTSPPort</code> <i>port_number</i></p>
<dd> <i>HTTPPort</i> sets the <font SIZE="-1">HTTP</font> server listening <font SIZE="-1">TCP</font> port number, <i>RTSPPort</i> sets the <font SIZE="-1">RTSP</font> server listening <font SIZE="-1">TCP</font> port number. </p>
<p> <i>Port</i> is the equivalent of <i>HTTPPort</i> and is deprecated. </p>
<p> You must select a different port from your standard <font SIZE="-1">HTTP</font> web server if it is running on the same computer. </p>
<p> If not specified, no corresponding server will be created.</p>
<dt><code>HTTPBindAddress</code> <i>ip_address</i></p>
<dd>
<dt><code>BindAddress</code> <i>ip_address</i></p>
<dd>
<dt><code>RTSPBindAddress</code> <i>ip_address</i></p>
<dd> Set address on which the <font SIZE="-1">HTTP/RTSP</font> server is bound. Only useful if you have several network interfaces. </p>
<p> <i>BindAddress</i> is the equivalent of <i>HTTPBindAddress</i> and is deprecated.</p>
<dt><code>MaxHTTPConnections</code> <i>n</i></p>
<dd> Set number of simultaneous <font SIZE="-1">HTTP</font> connections that can be handled. It has to be defined <i>before</i> the <code>MaxClients</code> parameter, since it defines the <code>MaxClients</code> maximum limit. </p>
<p> Default value is 2000.</p>
<dt><code>MaxClients</code> <i>n</i></p>
<dd> Set number of simultaneous requests that can be handled. Since <code>ffserver</code> is very fast, it is more likely that you will want to leave this high and use <code>MaxBandwidth</code>. </p>
<p> Default value is 5.</p>
<dt><code>MaxBandwidth</code> <i>kbps</i></p>
<dd> Set the maximum amount of kbit/sec that you are prepared to consume when streaming to clients. </p>
<p> Default value is 1000.</p>
<dt><code>CustomLog</code> <i>filename</i></p>
<dd> Set access log file (uses standard Apache log file format). &#8216;-&#8216; is the standard output. </p>
<p> If not specified <code>ffserver</code> will produce no log. </p>
<p> In case the commandline option <code>-d</code> is specified this option is ignored, and the log is written to standard output.</p>
<dt><code>NoDaemon</code></p>
<dd> Set no-daemon mode. This option is currently ignored since now <code>ffserver</code> will always work in no-daemon mode, and is deprecated.</p>
<dt><code>UseDefaults</code></p>
<dd>
<dt><code>NoDefaults</code></p>
<dd> Control whether default codec options are used for the all streams or not. Each stream may overwrite this setting for its own. Default is <i>UseDefaults</i>. The last occurrence overrides the previous if multiple definitions exist.</dl>
<h3>Feed section</h3>
<p> A Feed section defines a feed provided to <code>ffserver</code>. </p>
<p> Each live feed contains one video and/or audio sequence coming from an <code>ffmpeg</code> encoder or another <code>ffserver</code>. This sequence may be encoded simultaneously with several codecs at several resolutions. </p>
<p> A feed instance specification is introduced by a line in the form: </p>
<pre>
        &lt;Feed FEED_FILENAME&gt;
</pre>
<p> where <i></i><font SIZE="-1"><i>FEED_FILENAME</i></font><i></i> specifies the unique name of the <font SIZE="-1">FFM</font> stream. </p>
<p> The following options are recognized within a Feed section.</p>
<dl>
<dt><code>File</code> <i>filename</i></p>
<dd>
<dt><code>ReadOnlyFile</code> <i>filename</i></p>
<dd> Set the path where the feed file is stored on disk. </p>
<p> If not specified, the <i>/tmp/FEED.ffm</i> is assumed, where <i></i><font SIZE="-1"><i>FEED</i></font><i></i> is the feed name. </p>
<p> If <code>ReadOnlyFile</code> is used the file is marked as read-only and it will not be deleted or updated.</p>
<dt><code>Truncate</code></p>
<dd> Truncate the feed file, rather than appending to it. By default <code>ffserver</code> will append data to the file, until the maximum file size value is reached (see <code>FileMaxSize</code> option).</p>
<dt><code>FileMaxSize</code> <i>size</i></p>
<dd> Set maximum size of the feed file in bytes. 0 means unlimited. The postfixes <tt>&quot;K&quot;</tt> (2^10), <tt>&quot;M&quot;</tt> (2^20), and <tt>&quot;G&quot;</tt> (2^30) are recognized. </p>
<p> Default value is 5M.</p>
<dt><code>Launch</code> <i>args</i></p>
<dd> Launch an <code>ffmpeg</code> command when creating <code>ffserver</code>. </p>
<p> <i>args</i> must be a sequence of arguments to be provided to an <code>ffmpeg</code> instance. The first provided argument is ignored, and it is replaced by a path with the same dirname of the <code>ffserver</code> instance, followed by the remaining argument and terminated with a path corresponding to the feed. </p>
<p> When the launched process exits, <code>ffserver</code> will launch another program instance. </p>
<p> In case you need a more complex <code>ffmpeg</code> configuration, e.g. if you need to generate multiple <font SIZE="-1">FFM</font> feeds with a single <code>ffmpeg</code> instance, you should launch <code>ffmpeg</code> by hand. </p>
<p> This option is ignored in case the commandline option <code>-n</code> is specified.</p>
<dt><font SIZE="-1"><code>ACL</code></font> <i>spec</i></p>
<dd> Specify the list of <font SIZE="-1">IP</font> address which are allowed or denied to write the feed. Multiple <font SIZE="-1">ACL</font> options can be specified.</dl>
<h3>Stream section</h3>
<p> A Stream section defines a stream provided by <code>ffserver</code>, and identified by a single name. </p>
<p> The stream is sent when answering a request containing the stream name. </p>
<p> A stream section must be introduced by the line: </p>
<pre>
        &lt;Stream STREAM_NAME&gt;
</pre>
<p> where <i></i><font SIZE="-1"><i>STREAM_NAME</i></font><i></i> specifies the unique name of the stream. </p>
<p> The following options are recognized within a Stream section. </p>
<p> Encoding options are marked with the <i>encoding</i> tag, and they are used to set the encoding parameters, and are mapped to libavcodec encoding options. Not all encoding options are supported, in particular it is not possible to set encoder private options. In order to override the encoding options specified by <code>ffserver</code>, you can use the <code>ffmpeg</code> <code>override_ffserver</code> commandline option. </p>
<p> Only one of the <code>Feed</code> and <code>File</code> options should be set.</p>
<dl>
<dt><code>Feed</code> <i>feed_name</i></p>
<dd> Set the input feed. <i>feed_name</i> must correspond to an existing feed defined in a <tt>&quot;Feed&quot;</tt> section. </p>
<p> When this option is set, encoding options are used to setup the encoding operated by the remote <code>ffmpeg</code> process.</p>
<dt><code>File</code> <i>filename</i></p>
<dd> Set the filename of the pre-recorded input file to stream. </p>
<p> When this option is set, encoding options are ignored and the input file content is re-streamed as is.</p>
<dt><code>Format</code> <i>format_name</i></p>
<dd> Set the format of the output stream. </p>
<p> Must be the name of a format recognized by FFmpeg. If set to <code>status</code>, it is treated as a status stream.</p>
<dt><code>InputFormat</code> <i>format_name</i></p>
<dd> Set input format. If not specified, it is automatically guessed.</p>
<dt><code>Preroll</code> <i>n</i></p>
<dd> Set this to the number of seconds backwards in time to start. Note that most players will buffer 5-10 seconds of video, and also you need to allow for a keyframe to appear in the data stream. </p>
<p> Default value is 0.</p>
<dt><code>StartSendOnKey</code></p>
<dd> Do not send stream until it gets the first key frame. By default <code>ffserver</code> will send data immediately.</p>
<dt><code>MaxTime</code> <i>n</i></p>
<dd> Set the number of seconds to run. This value set the maximum duration of the stream a client will be able to receive. </p>
<p> A value of 0 means that no limit is set on the stream duration.</p>
<dt><font SIZE="-1"><code>ACL</code></font> <i>spec</i></p>
<dd> Set <font SIZE="-1">ACL</font> for the stream.</p>
<dt><code>DynamicACL</code> <i>spec</i></p>
<dd>
<dt><code>RTSPOption</code> <i>option</i></p>
<dd>
<dt><code>MulticastAddress</code> <i>address</i></p>
<dd>
<dt><code>MulticastPort</code> <i>port</i></p>
<dd>
<dt><code>MulticastTTL</code> <i>integer</i></p>
<dd>
<dt><code>NoLoop</code></p>
<dd>
<dt><code>FaviconURL</code> <i>url</i></p>
<dd> Set favicon (favourite icon) for the server status page. It is ignored for regular streams.</p>
<dt><code>Author</code> <i>value</i></p>
<dd>
<dt><code>Comment</code> <i>value</i></p>
<dd>
<dt><code>Copyright</code> <i>value</i></p>
<dd>
<dt><code>Title</code> <i>value</i></p>
<dd> Set metadata corresponding to the option. All these options are deprecated in favor of <code>Metadata</code>.</p>
<dt><code>Metadata</code> <i>key</i><i>value</i></p>
<dd> Set metadata value on the output stream.</p>
<dt><code>UseDefaults</code></p>
<dd>
<dt><code>NoDefaults</code></p>
<dd> Control whether default codec options are used for the stream or not. Default is <i>UseDefaults</i> unless disabled globally.</p>
<dt><code>NoAudio</code></p>

<dt><code>AudioCodec</code> <i>codec_name</i> <code>(</code><i>encoding,audio</i><code>)</code></p>

<dt><code>AudioBitRate</code> <i>rate</i> <code>(</code><i>encoding,audio</i><code>)</code></p>

<p> It must be specified setting the option <code>Format</code> to <code>status</code>.</p>
<h3>Redirect section</h3>
<p> A redirect section specifies where to redirect the requested <font SIZE="-1">URL</font> to another page. </p>
<p> A redirect section must be introduced by the line: </p>
<pre>
        &lt;Redirect NAME&gt;
</pre>
<p> where <i></i><font SIZE="-1"><i>NAME</i></font><i></i> is the name of the page which should be redirected. </p>
<p> It only accepts the option <font SIZE="-1"><code>URL</code></font>, which specify the redirection <font SIZE="-1">URL.</font></p>

        VideoFrameRate 2
        VideoIntraOnly
        VideoSize 352x240
        NoAudio
        Strict -1
        &lt;/Stream&gt;
</pre>

<pre>
        &lt;Stream test.swf&gt;
        Feed feed1.ffm
        Format swf
        VideoFrameRate 2
        VideoIntraOnly
        NoAudio
        &lt;/Stream&gt;
</pre>

<dd> <font SIZE="-1">ASF</font> compatible </p>
<pre>
        &lt;Stream test.asf&gt;
        Feed feed1.ffm
        Format asf
        VideoFrameRate 15
        VideoSize 352x240
        VideoBitRate 256
        VideoBufferSize 40
        VideoGopSize 30
        AudioBitRate 64
        StartSendOnKey
        &lt;/Stream&gt;

<dd> <font SIZE="-1">MP3</font> audio </p>

        Feed feed1.ffm
        Format mp2
        AudioCodec mp3
        AudioBitRate 64
        AudioChannels 1
        AudioSampleRate 44100
        NoVideo
        &lt;/Stream&gt;
</pre>
<dt>&bull;</p>
<dd> Ogg Vorbis audio </p>
<pre>

        Feed feed1.ffm
        Metadata title &quot;Stream title&quot;
        AudioBitRate 64
        AudioChannels 2
        AudioSampleRate 44100
        NoVideo
        &lt;/Stream&gt;
</pre>

        Feed feed1.ffm

        AudioBitRate 32
        NoVideo
        &lt;/Stream&gt;
</pre>

        VideoGopSize 25
        &lt;/Stream&gt;
