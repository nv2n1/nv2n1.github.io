<h2 class="name">NAME</h2>
<p> ogg123 &#8211; plays Ogg Vorbis files</p>
<h2>SYNOPSIS</h2>
<p> <code>ogg123 </code> [ <code>-vqrzZVh</code> ] [ <code>-k</code> <i>seconds </i> ] [ <code>-x</code> <i>nth</i> ] [ <code>-y</code> <i>ntimes</i> ] [ <code>-b</code> <i>buffer_size </i> ] [ <code>-d</code> <i>driver </i> [ <code>-o</code> <i>option:value</i> ] [ <code>-f</code> <i>filename</i> ] ] <i>file</i> <code>&#8230;</code> | <i>directory</i> <code>&#8230;</code> | <i>URL</i> <code>&#8230;</code> </p>
<h2>DESCRIPTION</h2>
<p> <code>ogg123</code> reads Ogg Vorbis audio files and decodes them to the devices specified on the command line. By default, <code>ogg123</code> writes to the standard sound device, but output can be sent to any number of devices. Files can be read from the file system, or URLs can be streamed via HTTP. If a directory is given, all of the files in it or its subdirectories will be played. </p>
<h2>OPTIONS</h2>
<dl>
<dt>&#8211;audio-buffer n</p>
<dd> Use an output audio buffer of approximately &#8216;n&#8217; kilobytes.</p>
<dt>-@ playlist, &#8211;list playlist</p>
<dd> Play all of the files named in the file &#8216;playlist&#8217;. The playlist should have one filename, directory name, or URL per line. Blank lines are permitted. Directories will be treated in the same way as on the command line.</p>
<dt>-b n, &#8211;buffer n</p>
<dd> Use an input buffer of approximately &#8216;n&#8217; kilobytes. HTTP-only option.</p>
<dt>-p n, &#8211;prebuffer n</p>
<dd> Prebuffer &#8216;n&#8217; percent of the input buffer. Playback won&#8217;t begin until this prebuffer is complete. HTTP-only option.</p>
<dt>-d device, &#8211;device device</p>
<dd> Specify output device. See <code>DEVICES</code> section for a list of devices. Any number of devices may be specified.</p>
<dt>-f filename, &#8211;file filename</p>
<dd> Specify output file for file devices. The filename &quot;-&quot; writes to standard out. If the file already exists, <code>ogg123</code> will overwrite it.</p>
<dt>-c c, &#8211;config c</p>
<dd> Config options from command-line.</p>
<dt>-l s, &#8211;delay s</p>
<dd> Set termination timeout in milliseconds. ogg123 will skip to the next song on SIGINT (Ctrl-C), and will terminate if two SIGINTs are received within the specified timeout &#8216;s&#8217;. (default 500)</p>
<dt>-h, &#8211;help</p>
<dd> Show command help.</p>
<dt>-k n, &#8211;skip n</p>
<dd> Skip the first &#8216;n&#8217; seconds. &#8216;n&#8217; may also be in minutes:seconds or hours:minutes:seconds form.</p>
<dt>-K n, &#8211;end n</p>
<dd> Stops playing &#8216;n&#8217; seconds from the start of the stream. &#8216;n&#8217; may also have the same format as used in the <i>&#8211;skip</i> option.</p>
<dt>-o option[:value], &#8211;device-option option[:value]</p>
<dd> Sets the option <i>option</i> to <i>value</i> for the preceding device. See <code>DEVICES</code> for a list of valid options for each device.</p>
<dt>-q, &#8211;quiet</p>
<dd> Quiet mode. No messages are displayed.</p>
<dt>-V, &#8211;version</p>
<dd> Display version information.</p>
<dt>-v, &#8211;verbose</p>
<dd> Increase verbosity.</p>
<dt>-x n, &#8211;nth</p>
<dd> Play every &#8216;n&#8217;th decoded block. Has the effect of playing audio at &#8216;n&#8217; times faster than normal speed.</p>
<dt>-y n, &#8211;ntimes</p>
<dd> Repeat every played block &#8216;n&#8217; times. Has the effect of playing audio &#8216;n&#8217; times slower than normal speed. May be with -x for interesting fractional speeds.</p>
<dt>-r, &#8211;repeat</p>
<dd> Repeat playlist indefinitely.</p>
<dt>-R, &#8211;remote</p>
<dd> Use remote control interface.</p>
<dt>-z, &#8211;shuffle</p>
<dd> Play files in pseudo-random order.</p>
<dt>-Z, &#8211;random</p>
<dd> Play files in pseudo-random order forever. </p>
</dl>
<h2>DEVICES</h2>
<p> <code>ogg123</code> supports a variety of audio output devices through libao. Only those devices supported by the target platform will be available. The <code>-f</code> option may only be used with devices that write to files. </p>
<p> Options supported by all devices:</p>
<dl>
<dt>
<dd>
<dl>
<dt>debug</p>
<dd> Turn on debugging output [if any] for a chosen driver.</p>
<dt>matrix:value</p>
<dd> Force a specific output channel ordering for a given device. <i>value</i> is a comma seperated list of AO style channel names, eg, L,R,C,LFE,BL,BR,SL,SR.</p>
<dt>verbose</p>
<dd> Turn on verbose output for a chosen driver. the -v option will also set the driver verbose option.</p>
<dt>quiet</p>
<dd> Force chosen driver to be completely silent. Even errors will not produce any output. -q will also set the driver quiet option.</dl>
</dl>
<p> <code></p>
<dl>
<dt>aixs</p>
<dd> </code> AIX live output driver. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>dev:value</p>
<dd> Set AIX output device to <i>value</i></dl>
</dl>
<p> <code></p>
<dt>alsa</p>
<dd> </code> Advanced Linux Sound Architecture live output driver. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>buffer_time:value</p>
<dd> Override the default hardware buffer size (in milliseconds).</p>
<dt>dev:value</p>
<dd> ALSA device label to use. Examples include &quot;hw:0&quot; for the first soundcard and &quot;hw:1&quot; for the second. The alsa driver normally chooses one of &quot;surround71&quot;, &quot;surround51&quot;, &quot;surround40&quot; or &quot;default&quot; automatically depending on number of output channels. For more information, see <a rel="nofollow" href="http://alsa.opensrc.org/ALSA+device+labels">http://alsa.opensrc.org/ALSA+device+labels</a></p>
<dt>period_time:value</p>
<dd> Override the default hardware period size (in microseconds).</p>
<dt>period_time:value</p>
<dd> Override the default hardware period size (in microseconds).</p>
<dt>use_mmap:value</p>
<dd> <i>value</i> is set to &quot;yes&quot; or &quot;no&quot; to override the compiled-in default to use or not use mmap device access. In the past, some buggy alsa drivers have behaved better when not using mmap access at the penalty of slightly higher CPU usage.</dl>
</dl>
<p> <code></p>
<dt>arts</p>
<dd> </code> aRts Sound Daemon live output driver. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>multi:value</p>
<dd> <i>value</i> is set to &quot;yes&quot; or &quot;no&quot; to allow opening the aRts playback device for multiply concurrent playback. Although the driver works properly in multi mode, it is known to occasionally crash the aRts server itself. Default behavior is &quot;no&quot;.</dl>
</dl>
<p> <code></p>
<dt>au</p>
<dd> </code> Sun audio file output. Writes the audio samples in AU format. The AU format supports writing to unseekable files like standard out. In such circumstances, the AU header will specify the sample format, but not the length of the recording. </p>
<p> <code></p>
<dt>esd</p>
<dd> </code> Enlightened Sound Daemon live output. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>host:value</p>
<dd> <i>value</i> specifies the hostname where esd is running. This can include a port number after a colon, as in &quot;whizbang.com:555&quot;. (Default = localhost)</dl>
</dl>
<p> <code></p>
<dt>irix</p>
<dd> </code> IRIX live output audio driver. </p>
<p> <code></p>
<dt>macosx</p>
<dd> </code> MacOS X &#8216;AUHAL&#8217; live output driver. This driver supports MacOS X 10.5 and later (10.4 and earlier uses an earlier, incompatable interface). Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>buffer_time:value</p>
<dd> Set the hardware buffer size to the equivalent of <i>value</i> milliseconds.</dl>
</dl>
<p> <code></p>
<dt>nas</p>
<dd> </code> Network Audio Server live output driver. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>buf_size:value</p>
<dd> Set size of audio buffer on server in bytes.</p>
<dt>host:value</p>
<dd> Set location of NAS server; See <a href="/docs/linux/man/1-nas/">nas</a>(1) for format.</dl>
</dl>
<p> <code></p>
<dt>null</p>
<dd> </code> Null driver. All audio data is discarded. (Note: Audio data is not written to <code>/dev/null</code> !) You could use this driver to test raw decoding speed without output overhead. </p>
<p> <code></p>
<dt>oss</p>
<dd> </code> Open Sound System driver for Linux and FreeBSD, versions 2, 3 and 4. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>dsp:value</p>
<dd> DSP device for soundcard. Defaults to <code>/dev/dsp.</code></dl>
</dl>
<p> <code></p>
<dt>pulse</p>
<dd> </code> Pulseaudio live audio sound driver. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>server:value</p>
<dd> Specifies location of remote or alternate Pulseaudio server.</p>
<dt>sink:value</p>
<dd> Specifies a non-default Pulseaudio sink for audio stream.</dl>
</dl>
<p> <code></p>
<dt>raw</p>
<dd> </code> Raw file output. Writes raw audio samples to a file. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>byteorder:value</p>
<dd> Chooses big endian (&quot;big&quot;), little endian (&quot;little&quot;), or native (&quot;native&quot;) byte order. Default is native order.</dl>
</dl>
<p> <code></p>
<dt>roar</p>
<dd> </code> Roar Audio Daemon live output driver. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>host:value</p>
<dd> Specifies location of remote Roar server to use.</dl>
</dl>
<p> <code></p>
<dt>sndio</p>
<dd> </code> OpenBSD SNDIO live output driver. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>dev:value</p>
<dd> Specifies audio device to use for playback.</dl>
</dl>
<p> <code></p>
<dt>sun</p>
<dd> </code> Sun Audio live output driver for NetBSD, OpenBSD, and Solaris. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>dev:value</p>
<dd> Audio device for soundcard. Defaults to <code>/dev/audio.</code></dl>
</dl>
<p> <code></p>
<dt>wav</p>
<dd> </code> WAV file output. Writes the sound data to disk in uncompressed form. If multiple files are played, all of them will be concatenated into the same WAV file. WAV files cannot be written to unseekable files, such as standard out. Use the AU format instead. </p>
<p> <code></p>
<dt>wmm</p>
<dd> </code> Windows MultiMedia live output driver for Win98 and later. Options:</p>
<dl>
<dt>
<dd>
<dl>
<dt>dev:value</p>
<dd> Selects audio device to use for playback by device name.</p>
<dt>id:value</p>
<dd> Selects audio device to use for playback by device id (card number).</dl>
</dl>
</dl>
<h2>EXAMPLES</h2>
<p> The <code>ogg123</code> command line is fairly flexible, perhaps confusingly so. Here are some sample command lines and an explanation of what they do. </p>
<p> Play on the default soundcard:</p>
<dl>
<dt>
<dd> <code>ogg123 test.ogg</code></dl>
<p> Play all of the files in the directory ~/music and its subdirectories.</p>
<dl>
<dt>
<dd> <code>ogg123 ~/music</code></dl>
<p> Play a file using the OSS driver:</p>
<dl>
<dt>
<dd> <code>ogg123 -d oss test.ogg</code></dl>
<p> Pass the &quot;dsp&quot; option to the OSS driver:</p>
<dl>
<dt>
<dd> <code>ogg123 -d oss -o dsp:/dev/mydsp </code></dl>
<p> Use the ESD driver</p>
<dl>
<dt>
<dd> <code>ogg123 -d esd test.ogg</code></dl>
<p> Use the WAV driver with the output file, &quot;test.wav&quot;:</p>
<dl>
<dt>
<dd> <code>ogg123 -d wav -f test.wav test.ogg</code></dl>
<p> Listen to a file while you write it to a WAV file:</p>
<dl>
<dt>
<dd> <code>ogg123 -d oss -d wav -f test.wav test.ogg</code></dl>
<p> Note that options apply to the device declared to the left:</p>
<dl>
<dt>
<dd> <code>ogg123 -d oss -o dsp:/dev/mydsp -d raw -f test2.raw -o byteorder:big test.ogg</code></dl>
<p> Stress test your harddrive:</p>
<dl>
<dt>
<dd> <code>ogg123 -d oss -d wav -f 1.wav -d wav -f 2.wav -d wav -f 3.wav -d wav -f 4.wav -d wav -f 5.wav test.ogg</code></dl>
<p> Create an echo effect with esd and a slow computer:</p>
<dl>
<dt>
<dd> <code>ogg123 -d esd -d esd test.ogg</code></dl>
<h2>INTERRUPT</h2>
<p> You can abort <code>ogg123</code> at any time by pressing Ctrl-C. If you are playing multiple files, this will stop the current file and begin playing the next one. If you want to abort playing immediately instead of skipping to the next file, press Ctrl-C within the first second of the playback of a new file. </p>
<p> Note that the result of pressing Ctrl-C might not be audible immediately, due to audio data buffering in the audio device. This delay is system dependent, but it is usually not more than one or two seconds. </p>
<h2>FILES</h2>
<dl>
<dt>/etc/libao.conf</p>
<dd> Can be used to set the default output device for all libao programs. </p>
<dt>~/.libao</p>
<dd> Per-user config file to override the system wide output device settings.</dl>
<h2>BUGS</h2>
<p> Piped WAV files may cause strange behavior in other programs. This is because WAV files store the data length in the header. However, the output driver does not know the length when it writes the header, and there is no value that means &quot;length unknown&quot;. Use the raw or au output driver if you need to use ogg123 in a pipe. </p>
