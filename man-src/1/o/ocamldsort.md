<h2 class="name">NAME</h2>
<p> ocamldsort &#8211; Dependency sorter for OCaml source files</p>
<h2>SYNOPSIS</h2>
<p> <code>ocamldsort</code> [ <code>-pp</code> <i> pre-command</i> ] [ <code>-d</code> <i>dep-command</i> ]<br />
&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>[&nbsp;<wbr><code>-mli</code>&nbsp;<wbr>]&nbsp;<wbr>[&nbsp;<wbr><code>-nox</code>&nbsp;<wbr>]&nbsp;<wbr>[&nbsp;<wbr><code>-obj</code>&nbsp;<wbr>|&nbsp;<wbr><code>-byte</code>&nbsp;<wbr>|&nbsp;<wbr><code>-opt</code>&nbsp;<wbr>]&nbsp;<wbr>[&nbsp;<wbr><i>filename</i>&nbsp;<wbr>]&nbsp;<wbr><i>&#8230;</i> </p>
<h2>DESCRIPTION</h2>
<p> The <code><a href="/docs/linux/man/1-ocamldsort/">ocamldsort</a></code>(1) command scans a set of Objective Caml source files (.ml and .mli files), sorts them according to their dependencies and prints the sorted files in order to link their corresponding .cmo files. </p>
<p> For <code><a href="/docs/linux/man/1-ocamldsort/">ocamldsort</a></code>(1) to work it must get a list of dependencies generated by <code><a href="/docs/linux/man/1-ocamldep/">ocamldep</a></code>(1), if the standard input to <code><a href="/docs/linux/man/1-ocamldsort/">ocamldsort</a></code>(1) has been redirected then ocamldsort assumes that this is a dependency file generated by <code><a href="/docs/linux/man/1-ocamldep/">ocamldep</a></code>(1). Otherwise ocamldsort calls <code><a href="/docs/linux/man/1-ocamldep/">ocamldep</a></code>(1) to generate the dependency list itself. In either case the source files to be sorted should be given as arguments to the <code><a href="/docs/linux/man/1-ocamldsort/">ocamldsort</a></code>(1) command. </p>
<p> <code><a href="/docs/linux/man/1-ocamldsort/">ocamldsort</a></code>(1) can be used to compile and link simple projects with one command, such as: </p>
<p> ocamlc $(ocamldsort *.ml) </p>
<p> if your project doesn&#8217;t contain .mli files or: </p>
<pre>
ocamlc -c $(ocamldsort -mli *.ml *.mli) &amp;&amp; ocamlc $(ocamldsort -byte *.ml)
</pre>
<p> if it contains .mli files. </p>
<p> However for larger projects where separate compilation is desirable, <code><a href="/docs/linux/man/1-ocamldsort/">ocamldsort</a></code>(1) can also be used from within a makefile. Here is a typical makefile example: </p>
<pre>
TARGET=my_program
OCAMLC=ocamlc
OCAMLOPT=ocamlopt
OCAMLDEP=ocamldep
OCAMLDSORT=ocamldsort
PPFLAGS=-pp camlp4o
MLY=$(shell echo *.mly)
MLL=$(shell echo *.mll)
GENERATED_ML=$(MLY:.mly=.ml) $(MLL:.mll=.ml)
include .generated .depend .ocamldsort
$(TARGET): $(CMO_FILES)
        $(OCAMLC) $(COMPFLAGS) $(LIBS) $^ -o $@
$(TARGET).opt: $(CMX_FILES)
        $(OCAMLOPT) $(COMPFLAGS) $(LIBS_OPT) $^ -o $@
.generated: $(GENERATED_ML)
        @touch .generated
.depend: .generated
        $(OCAMLDEP) *.ml *.mli &gt; $@
.ocamldsort: .depend
        echo CMO_FILES=`&lt; .depend $(OCAMLDSORT) -byte *.ml` &gt; .ocamldsort
        echo CMX_FILES=`&lt; .depend $(OCAMLDSORT) -opt *.ml` &gt;&gt; .ocamldsort
distclean: clean
        rm -f .generated .depend .ocamldsort
        rm -f $(GENERATED_ML)
        rm -f *~
        rm -f $(TARGET) 
clean:
        rm -f *.cmo *.cmi *.cmx *.o 
.SUFFIXES: .mli .ml .cmi .cmo .cmx .mll .mly
%.cmi:%.mli
        $(OCAMLC) $(PPFLAGS) $(COMPFLAGS) -c $&lt;
%.cmo:%.ml
        $(OCAMLC) $(PPFLAGS) $(COMPFLAGS) -c $&lt;
%.cmi %.cmo:%.ml
        $(OCAMLC) $(PPFLAGS) $(COMPFLAGS) -c $&lt;
%.cmx %.o:%.ml
        $(OCAMLOPT) $(PPFLAGS) $(COMPFLAGS)  -c $&lt;
%.ml:%.mll
        $(OCAMLLEX) $&lt;
%.mli %.ml:%.mly
        $(OCAMLYACC) -v $&lt;
</pre>
<h2>OPTIONS</h2>
<p> The following command-line options are recognized by <code><a href="/docs/linux/man/1-ocamlsort/">ocamlsort</a></code>(1): </p>
<dl>
<dt><code>-I</code><i>&nbsp;<wbr>directory</i></p>
<dd> Add the given directory to the list of directories searched for source files. </p>
<dt><code>-pp</code><i>&nbsp;<wbr>pre-command</i></p>
<dd> Command to preprocess file. </p>
<dt><code>-d</code><i>&nbsp;<wbr>dep-command</i></p>
<dd> Command to compute dependencies. <code><a href="/docs/linux/man/1-ocamldep/">ocamldep</a></code>(1) by default. </p>
<dt><code>-mli</code></p>
<dd> Sort files using mli dependencies. </p>
<dt><code>-nox</code></p>
<dd> Ignore filenames containg `*&#8217; so that unexpanded wildcards are ignored. </p>
<dt><code>-obj</code></p>
<dd> Print bytecode filenames (.cmo and .cmi) (deprecated: use -byte). </p>
<dt><code>-byte</code></p>
<dd> Print bytecode filenames (.cmo and .cmi). </p>
<dt><code>-opt</code></p>
<dd> Print opt filenames (.cmx and .cmi). </p>
<dt><code>-v</code></p>
<dd> Output version information and exit. </p>
<dt><code>-help</code>, <code>&#8211;help</code></p>
<dd> Output help and exit. </p>
</dl>
