<p>orbd &#8211; The Object Request Broker Daemon </p>
<p> <code>orbd</code> is used to enable clients to transparently locate and invoke persistent objects on servers in the CORBA environment. </p>
<p> <code>See also:</code> <i>Naming Service</i> @ <a rel="nofollow" href="http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlNaming.html">http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlNaming.html</a> </p>
<h2>Synopsis</h2>
<pre><code>orbd &lt;</code><code>options</code><code>&gt;</code></pre>
<h2>Description</h2>
<p>The Server Manager included with the <code>orbd</code> tool is used to enable clients to transparently locate and invoke persistent objects on servers in the CORBA environment. The persistent servers, while publishing the persistent object references in the Naming Service, include the port number of the ORBD in the object reference instead of the port number of the Server. The inclusion of an ORBD port number in the object reference for persistent object references has the following advantages: </p>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>o</p>
<dd>The object reference in the Naming Service remains independent of the server life cycle. For example, the object reference could be published by the server in the Naming Service when it is first installed, and then, independent of how many times the server is started or shutdown, the ORBD will always return the correct object reference to the invoking client.</p>
<dt>o</p>
<dd>The client needs to lookup the object reference in the Naming Service only once, and can keep re-using this reference independent of the changes introduced due to server life cycle.</dl>
</dl>
<p> To access ORBD&#8217;s Server Manager, the server must be started using <a href="/docs/linux/man/1-servertool/">servertool</a>(1), which is a command-line interface for application programmers to register, unregister, startup, and shutdown a persistent server. For more information on the Server Manager, see the section in this document titled <i>Server Manager</i>. </p>
<p> When <i>orbd</i> starts up, it also starts a naming service. For more information on the naming service, link to <i>Naming Service</i> @ <a rel="nofollow" href="http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlNaming.html.">http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlNaming.html.</a> </p>
<h2>Options</h2>
<h3>Required Options</h3>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>-ORBInitialPort nameserverport</p>
<dd>Specifies the port on which the name server should be started. Once started, <i>orbd</i> will listen for incoming requests on this port. Note that when using Solaris software, you must become root to start a process on a port under 1024. For this reason, we recommend that you use a port number greater than or equal to 1024. (required)</dl>
</dl>
<h3>Other Options</h3>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>-port port</p>
<dd>Specifies the activation port where ORBD should be started, and where ORBD will be accepting requests for persistent objects. The default value for this port is 1049. This port number is added to the port field of the persistent Interoperable Object References (IOR). (optional)</dl>
</dl>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>-defaultdb directory</p>
<dd>Specifies the base where the ORBD persistent storage directory <i>orb.db</i> is created. If this option is not specified, the default value is &quot;./orb.db&quot;. (optional)</dl>
</dl>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>-serverPollingTime milliseconds</p>
<dd>Specifies how often ORBD checks for the health of persistent servers registered via <i>servertool</i>. The default value is 1,000 ms. The value specified for <i>milliseconds</i> must be a valid positive integer. (optional)</dl>
</dl>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>-serverStartupDelay milliseconds</p>
<dd>Specifies how long ORBD waits before sending a location forward exception after a persistent server that is registered via <i>servertool</i> is restarted. The default value is 1,000 ms. The value specified for <i>milliseconds</i> must be a valid positive integer. (optional)</dl>
</dl>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>-Joption</p>
<dd>Pass <i>option</i> to the Java virtual machine, where <i>option</i> is one of the options described on the reference page for <a href="/docs/linux/man/1-java/">java</a>(1). For example, <code>-J-Xms48m</code> sets the startup memory to 48 megabytes. It is a common convention for <code>-J</code> to pass options to the underlying virtual machine.</p>
<dt>
&nbsp;<wbr></p>
<dd></dl>
</dl>
<h2>Starting and Stopping the Naming Service</h2>
<p>A Naming Service is a CORBA service that allows <i>CORBA objects</i> @ <a rel="nofollow" href="http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlGlossary.html#CORBA%20object">http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlGlossary.html#CORBA%20object</a> to be named by means of binding a name to an object reference. The <i>name binding</i> @ <a rel="nofollow" href="http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlGlossary.html#name%20binding">http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlGlossary.html#name%20binding</a> may be stored in the naming service, and a client may supply the name to obtain the desired object reference. </p>
<p> Prior to running a client or a server, you will start ORBD. ORBD includes a persistent Naming Service and a transient Naming Service, both of which are an implementation of the COS Naming Service. </p>
<p> The <tt>Persistent</tt><code> Naming Service</code> provides persistence for naming contexts. This means that this information is persistent across service shutdowns and startups, and is recoverable in the event of a service failure. If ORBD is restarted, the Persistent Naming Service will restore the naming context graph, so that the binding of all clients&#8217; and servers&#8217; names remains intact (persistent). </p>
<p> &nbsp;<wbr> </p>
<p> For backward compatibility, <i>tnameserv</i>, a <tt>Transient</tt><code> Naming Service</code> shipped with older versions of the JDK, is also included in this release of J2SE. A transient naming service retains naming contexts as long as it is running. If there is a service interruption, the naming context graph is lost. </p>
<p> The <i>-ORBInitialPort</i> argument is a required command-line argument for <i>orbd</i>, and is used to set the port number on which the Naming Service will run. The following instructions assume you can use port 1050 for the Java IDL Object Request Broker Daemon. When using Solaris software, you must become root to start a process on a port under 1024. For this reason, we recommend that you use a port number greater than or equal to 1024. You can substitute a different port if necessary. </p>
<p> To start <i>orbd</i> from a UNIX command shell, enter: </p>
<pre><code> orbd -ORBInitialPort 1050&amp;</code></pre>
<p>From an MS-DOS system prompt (Windows), enter: </p>
<pre><code> start orbd -ORBInitialPort 1050</code></pre>
<p>Now that ORBD is running, you can run your server and client applications. When running the client and server applications, they must be made aware of the port number (and machine name, if applicable) where the Naming Service is running. One way to do this is to add the following code to your application: </p>
<pre><code> Properties props = new Properties();
 props.put(&quot;org.omg.CORBA.ORBInitialPort&quot;, &quot;1050&quot;);
 props.put(&quot;org.omg.CORBA.ORBInitialHost&quot;, &quot;MyHost&quot;);
 ORB orb = ORB.init(args, props);</code></pre>
<p>In this example, the Naming Service is running on port 1050 on host &quot;MyHost&quot;. Another way is to specify the port number and/or machine name when running the server or client application from the command line. For example, you would start your &quot;HelloApplication&quot; with the following command line: </p>
<pre><code> java HelloApplication -ORBInitialPort 1050 -ORBInitialHost MyHost</code></pre>
<p>To stop the naming service, use the relevant operating system command, such as <i>pkill orbd</i> on Solaris, or <i>Ctrl+C</i> in the DOS window in which <i>orbd</i> is running. Note that names registered with the naming service may disappear when the service is terminated if the naming service is transient. The Java IDL naming service will run until it is explicitly stopped. </p>
<p> For more information on the Naming Service included with ORBD, see <i>Naming Service</i> @ <a rel="nofollow" href="http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlNaming.html.">http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlNaming.html.</a> </p>
<h2>Server Manager</h2>
<p>To access ORBD&#8217;s Server Manager and run a persistent server, the server must be started using <a href="/docs/linux/man/1-servertool/">servertool</a>(1), which is a command-line interface for application programmers to register, unregister, startup, and shutdown a persistent server. When a server is started using <i>servertool</i>, it must be started on the same host and port on which <i>orbd</i> is executing. If the server is run on a different port, the information stored in the database for local contexts will be invalid and the service will not work properly. </p>
<h3>Server Manager: an Example</h3>
<p>Using the <i>sample tutorial</i> @ <a rel="nofollow" href="http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlExample.html">http://docs.oracle.com/javase/7/docs/technotes/guides/idl/jidlExample.html</a> for our demonstration, you would run the <i>idlj</i> compiler and <i>javac</i> compiler as shown in the tutorial. To run the Server Manager, follow these steps for running the application: </p>
<p> Start <i>orbd</i>. </p>
<p> To start <i>orbd</i> from a UNIX command shell, enter: </p>
<p> &nbsp;<wbr> </p>
<pre><code> orbd -ORBInitialPort 1050 </code></pre>
<p>From an MS-DOS system prompt (Windows), enter: </p>
<pre><code> start orbd -ORBInitialPort 1050</code></pre>
<p>Note that <i>1050</i> is the port on which you want the name server to run. <i>-ORBInitialPort</i> is a required command-line argument. When using Solaris software, you must become root to start a process on a port under 1024. For this reason, we recommend that you use a port number greater than or equal to 1024. </p>
<p> Start the <i>servertool</i>: </p>
<p> To start the Hello server, enter: </p>
<pre><code> servertool -ORBInitialPort 1050</code></pre>
<p>Make sure the name server (<i>orbd</i>) port is the same as in the previous step, for example, <i>-ORBInitialPort 1050</i>. The <i>servertool</i> must be started on the same port as the name server. </p>
<p> The <i>servertool</i> command line interface appears. </p>
<p> Start the Hello server from the <i>servertool</i> prompt: </p>
<pre><code> servertool &gt; register -server HelloServer -classpath . -applicationName
 HelloServerApName</code></pre>
<p>The <i>servertool</i> registers the server, assigns it the name of &quot;HelloServerApName&quot;, and displays its server id, along with a listing of all registered servers. </p>
<p> Run the client application from another terminal window or prompt: </p>
<p> &nbsp;<wbr> </p>
<pre><code> java HelloClient -ORBInitialPort 1050 -ORBInitialHost localhost</code></pre>
<p>For this example, you can omit <i>-ORBInitialHost localhost</i> since the name server is running on the same host as the Hello client. If the name server is running on a different host, use <i>-ORBInitialHost</i> <i>nameserverhost</i> to specify the host on which the IDL name server is running. </p>
<p> Specify the name server (<i>orbd</i>) port as done in the previous step, for example, <i>-ORBInitialPort 1050</i>. </p>
<p> &nbsp;<wbr> </p>
<p> &nbsp;<wbr> </p>
<p> When you have finished experimenting with the Server Manager, be sure to shut down or kill the name server (<i>orbd</i>) and <i>servertool</i>. </p>
<p> To shut down <i>orbd</i> from a DOS prompt, select the window that is running the server and enter <i>Ctrl+C</i> to shut it down. To shut down <i>orbd</i>from a Unix shell, find the process, and kill it. The server will continue to wait for invocations until it is explicitly stopped. </p>
<p> To shut down the <i>servertool</i>, type <i>quit</i> and press the <i>Enter</i> key on the keyboard. </p>
