<h2 class="name">NAME</h2>
<p> out123 &#8211; send raw PCM audio or a waveform pattern to an output device </p>
<h2>SYNOPSIS</h2>
<p> <code>cat audio.raw | out123</code> [ <code>options</code> ] </p>
<p> <code>out123 &#8211;wave-freq</code> freq1[,freq2,&#8230;] [ <code>options</code> ]</p>
<h2>DESCRIPTION</h2>
<p> <code>out123</code> reads raw PCM data (in host byte order) from standard input and plays it on the audio device specified by given options. Alternatively, it can generate periodic signals for playback itself.</p>
<h2>OPTIONS</h2>
<p> <code>out123</code> options may be either the traditional POSIX one letter options, or the GNU style long options. POSIX style options start with a single &#8220;-&#8221;, while GNU long options start with &#8220;&#8211;&#8221;. Option arguments (if needed) follow separated by whitespace (not &#8220;=&#8221;). Note that some options can be absent from your installation when disabled in the build process.</p>
<dl>
<dt><code>&#8211;name </code><i>name</p>
<dd> Set the name of this instance, possibly used in various places. This sets the client name for JACK output.</p>
<dt></i><code>-o </code><i>module</i>, &#8211;output <i>module</i></p>
<dd> Select audio output module. You can provide a comma-separated list to use the first one that works.</p>
<dt><code>&#8211;list-modules</p>
<dd> List the available modules.</p>
<dt>-a </code><i>dev</i>, <code>&#8211;audiodevice </code><i>dev</p>
<dd> Specify the audio device to use. The default is system-dependent (usually /dev/audio or /dev/dsp). Use this option if you have multiple audio devices and the default is not what you want.</p>
<dt></i><code>-s</code>, <code>&#8211;stdout</code></p>
<dd> The audio samples are written to standard output, instead of playing them through the audio device. The output format is the same as the input &#8230; so in this mode, <code>out123</code> acts like the standard tool <code> cat. This shortcut is equivalent to &#8220;-o raw -a -&#8221;.</p>
<dt>-O </code><i>file</i>, <code>&#8211;outfile</p>
<dd> Write raw output into a file (instead of simply redirecting standard output to a file with the shell). This shortcut is equivalent to &#8220;-o raw -a </code><i>file</i>&#8221;.</p>
<dt><code>-w </code><i>file</i>, <code>&#8211;wav</p>
<dd> Write output as WAV file </code><i>file</i> , or standard output if <i>&#8211;</i> is or the empty string used as file name. You can also use <i>&#8211;au</i> and <i>&#8211;cdr</i> for AU and CDR format, respectively. Note that WAV/AU writing to non-seekable files or redirected stdout needs some thought. The header is written with the first actual data. The result of decoding nothing to WAV/AU is a file consisting just of the header when it is seekable and really nothing when not (not even a header). Correctly writing data with prophetic headers to stdout is no easy business. This shortcut is equivalent to &#8220;-o wav -a <i>file</i>&#8221;.</p>
<dt><code>&#8211;au </code><i>file</p>
<dd> Write to file</i> in SUN audio format. If &#8211; or the empty string is used as the filename, the AU file is written to stdout. See paragraph about WAV writing for header fun with non-seekable streams. This shortcut is equivalent to &#8220;-o au -a <i>file</i>&#8221;.</p>
<dt><code>&#8211;cdr </code><i>file</p>
<dd> Write to file</i> as a CDR (CD-ROM audio, more correctly CDDA for Compact Disc Digital Audio). If &#8211; is or the empty string used as the filename, the CDR file is written to stdout. This shortcut is equivalent to &#8220;-o cdr -a <i>file</i>&#8221;.</p>
<dt><code>-r </code><i>rate</i>, <code>&#8211;rate </code><i>rate</p>
<dd> Set sample rate in Hz (default: 44100). If this does not match the actual input sampling rate, you get changed pitch. Might be intentional;-)</p>
<dt></i><code>-c </code><i>count</i>, <code>&#8211;channels </code><i>count</p>
<dd> Set channel count to given value.</p>
<dt></i>-e <i>enc</i>, <code>&#8211;encoding </code><i>enc</p>
<dd> Choose output sample encoding. Possible values look like f32 (32-bit floating point), s32 (32-bit signed integer), u32 (32-bit unsigned integer) and the variants with different numbers of bits (s24, u24, s16, u16, s8, u8) and also special variants like ulaw and alaw 8-bit. See the output of </i><code>out123</code>&#8216;s longhelp for actually available encodings. Default is s16.</p>
<dt><code>-m</code>, <code>&#8211;mono</code></p>
<dd> Set for single-channel audio (default is two channels, stereo).</p>
<dt><code>&#8211;stereo</code></p>
<dd> Select stereo output (2 channels, default).</p>
<dt><code>&#8211;list-encodings</code></p>
<dd> List known encoding short and long names to standard output.</p>
<dt><code>&#8211;test-format</code></p>
<dd> Check if given format is supported by given driver and device (in command line before encountering this), silently returning 0 as exit value if it is the case.</p>
<dt><code>&#8211;test-encodings</code></p>
<dd> Print out the short names of encodings supported with the current setup.</p>
<dt><code>&#8211;query-format</code></p>
<dd> If the selected driver and device communicate some default accepted format, print out a command line fragment for <code>out123</code> setting that format, always in that order: &#8211;rate &lt;r&gt; &#8211;channels &lt;c&gt; &#8211;encoding &lt;e&gt;</p>
<dt><code>-o h</code>, <code>&#8211;headphones</code></p>
<dd> Direct audio output to the headphone connector (some hardware only; AIX, HP, SUN).</p>
<dt><code>-o s</code>, <code>&#8211;speaker</code></p>
<dd> Direct audio output to the speaker (some hardware only; AIX, HP, SUN).</p>
<dt><code>-o l</code>, <code>&#8211;lineout</code></p>
<dd> Direct audio output to the line-out connector (some hardware only; AIX, HP, SUN).</p>
<dt><code>-b </code><i>size</i>, <code>&#8211;buffer </code><i>size</p>
<dd> Use an audio output buffer of size</i> Kbytes. This is useful to bypass short periods of heavy system activity, which would normally cause the audio output to be interrupted. You should specify a buffer size of at least 1024 (i.e. 1 Mb, which equals about 6 seconds of usual audio data) or more; less than about 300 does not make much sense. The default is 0, which turns buffering off.</p>
<dt><code>&#8211;preload </code><i>fraction</p>
<dd> Wait for the buffer to be filled to fraction</i> before starting playback (fraction between 0 and 1). You can tune this prebuffering to either get sound faster to your ears or safer uninterrupted web radio. Default is 0.2 (changed from 1 since version 1.23).</p>
<dt><code>&#8211;devbuffer </code><i>seconds</p>
<dd> Set device buffer in seconds; &lt;= 0 means default value. This is the small buffer between the application and the audio backend, possibly directly related to hardware buffers.</p>
<dt></i><code>&#8211;timelimit </code><i>samples</p>
<dd> Set playback time limit in PCM samples if set to a value greater than zero. </i><code>out123</code> will stop reading from stdin or playing from the generated wave table after reaching that number of samples.</p>
<dt><code>&#8211;wave-freq </code><i>frequencies</p>
<dd> Set wave generator frequency or list of those with comma separation for enabling a generated test signal instead of standard input. Empty values repeat the previous one.</p>
<dt></i><code>&#8211;wave-pat </code><i>patterns</p>
<dd> Set the waveform patterns of the generated waves as comma-separated list. Choices include sine, square, triangle, sawtooth, gauss, pulse, and shot. Empty values repeat the previous one.</p>
<dt></i><code>&#8211;wave-phase </code><i>phases</p>
<dd> Set waveform phase shift(s) as comma-separated list, negative values inverting the pattern in time and empty value repeating the previous.</p>
<dt></i><code>&#8211;wave-limit </code><i>samples</p>
<dd> Set a custom soft limit on the wave table size. Small values cause larger changes in actual frequencies to make whole periods fit.</p>
<dt></i><code>-t</code>, <code>&#8211;test</code></p>
<dd> Test mode. The audio stream is read, but no output occurs.</p>
<dt><code>-v</code>, <code>&#8211;verbose</code></p>
<dd> Increase the verbosity level.</p>
<dt><code>-q</code>, <code>&#8211;quiet</code></p>
<dd> Quiet. Suppress diagnostic messages.</p>
<dt><code>&#8211;aggressive</p>
<dd> Tries to get higher priority</p>
<dt>-T</code>, <code>&#8211;realtime</code></p>
<dd> Tries to gain realtime priority. This option usually requires root privileges to have any effect.</p>
<dt><code>-?</code>, <code>&#8211;help</code></p>
<dd> Shows short usage instructions.</p>
<dt><code>&#8211;longhelp</code></p>
<dd> Shows long usage instructions.</p>
<dt><code>&#8211;version</code></p>
<dd> Print the version string.</dl>
