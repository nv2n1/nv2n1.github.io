<h2 class="name">NAME</h2>
<p> ocamldoc &#8211; The OCaml documentation generator </p>
<h2>SYNOPSIS</h2>
<p> <code>ocamldoc</code> [ <i>options</i> ] <i>filename</i>&nbsp;<wbr>&#8230; </p>
<h2>DESCRIPTION</h2>
<p> The OCaml documentation generator <code><a href="/docs/linux/man/1-ocamldoc/">ocamldoc</a></code>(1) generates documentation from special comments embedded in source files. The comments used by <code>ocamldoc</code> are of the form <i>(** &#8230; *)</i> and follow the format described in the <i>The OCaml user&#8217;s manual</i>. </p>
<p> <code>ocamldoc</code> can produce documentation in various formats: HTML, LaTeX, TeXinfo, Unix man pages, and <code><a href="/docs/linux/man/1-dot/">dot</a></code>(1) dependency graphs. Moreover, users can add their own custom generators. </p>
<p> In this manpage, we use the word <i>element</i> to refer to any of the following parts of an OCaml source file: a type declaration, a value, a module, an exception, a module type, a type constructor, a record field, a class, a class type, a class method, a class value or a class inheritance clause. </p>
<h2>OPTIONS</h2>
<p> The following command-line options determine the format for the generated documentation generated by <code><a href="/docs/linux/man/1-ocamldoc/">ocamldoc</a></code>(1).</p>
<h3>Options for choosing the output format</h3>
<dl>
<dt><code>-html</code></p>
<dd> Generate documentation in HTML default format. The generated HTML pages are stored in the current directory, or in the directory specified with the <code>-d</code> option. You can customize the style of the generated pages by editing the generated <i>style.css</i> file, or by providing your own style sheet using option <code>-css-style</code>. The file <i>style.css</i> is not generated if it already exists.</p>
<dt><code>-latex</code></p>
<dd> Generate documentation in LaTeX default format. The generated LaTeX document is saved in file <i>ocamldoc.out</i>, or in the file specified with the <code>-o</code> option. The document uses the style file <i>ocamldoc.sty</i>. This file is generated when using the <code>-latex</code> option, if it does not already exist. You can change this file to customize the style of your LaTeX documentation.</p>
<dt><code>-texi</code></p>
<dd> Generate documentation in TeXinfo default format. The generated LaTeX document is saved in file <i>ocamldoc.out</i>, or in the file specified with the <code>-o</code> option.</p>
<dt><code>-man</code></p>
<dd> Generate documentation as a set of Unix man pages. The generated pages are stored in the current directory, or in the directory specified with the <code>-d</code> option.</p>
<dt><code>-dot</code></p>
<dd> Generate a dependency graph for the toplevel modules, in a format suitable for displaying and processing by <i><a href="/docs/linux/man/1-dot/">dot</a></i>(1). The <i><a href="/docs/linux/man/1-dot/">dot</a></i>(1) tool is available from <i><a rel="nofollow" href="http://www.research.att.com/sw/tools/graphviz/">http://www.research.att.com/sw/tools/graphviz/</a></i>. The textual representation of the graph is written to the file <i>ocamldoc.out</i>, or to the file specified with the <code>-o</code> option. Use <code>dot</code><i>&nbsp;<wbr>ocamldoc.out</i> to display it.</p>
<dt><code>-g</code><i>&nbsp;<wbr>file</i></p>
<dd> Dynamically load the given file (which extension usually is .cmo or .cma), which defines a custom documentation generator. If the given file is a simple one and does not exist in the current directory, then <code>ocamldoc</code> looks for it in the custom generators default directory, and in the directories specified with the <code>-i</code> option.</p>
<dt><code>-customdir</code></p>
<dd> Display the custom generators default directory.</p>
<dt><code>-i</code><i>&nbsp;<wbr>directory</i></p>
<dd> Add the given directory to the path where to look for custom generators.</dl>
<h3>General options</h3>
<dl>
<dt><code>-d</code><i>&nbsp;<wbr>dir</i></p>
<dd> Generate files in directory <i>dir</i>, rather than the current directory.</p>
<dt><code>-dump</code><i>&nbsp;<wbr>file</i></p>
<dd> Dump collected information into <i>file</i>. This information can be read with the <code>-load</code> option in a subsequent invocation of <code><a href="/docs/linux/man/1-ocamldoc/">ocamldoc</a></code>(1).</p>
<dt><code>-hide</code><i>&nbsp;<wbr>modules</i></p>
<dd> Hide the given complete module names in the generated documentation. <i>modules</i> is a list of complete module names are separated by commas (,), without blanks. For instance: <i>Pervasives,M2.M3</i>.</p>
<dt><code>-inv-merge-ml-mli</code></p>
<dd> Reverse the precedence of implementations and interfaces when merging. All elements in implementation files are kept, and the <code>-m</code> option indicates which parts of the comments in interface files are merged with the comments in implementation files.</p>
<dt><code>-keep-code</code></p>
<dd> Always keep the source code for values, methods and instance variables, when available. The source code is always kept when a .ml file is given, but is by default discarded when a .mli is given. This option allows to always keep the source code.</p>
<dt><code>-load</code><i>&nbsp;<wbr>file</i></p>
<dd> Load information from <i>file</i>, which has been produced by <code>ocamldoc -dump</code>. Several <code>-load</code> options can be given.</p>
<dt><code>-m</code><i>flags</i></p>
<dd> Specify merge options between interfaces and implementations. <i>flags</i> can be one or several of the following characters: </p>
<p> <code>d</code> merge description </p>
<p> <code>a</code> merge @author </p>
<p> <code>v</code> merge @version </p>
<p> <code>l</code> merge @see </p>
<p> <code>s</code> merge @since </p>
<p> <code>o</code> merge @deprecated </p>
<p> <code>p</code> merge @param </p>
<p> <code>e</code> merge @raise </p>
<p> <code>r</code> merge @return </p>
<p> <code>A</code> merge everything</p>
<dt><code>-no-custom-tags</code></p>
<dd> Do not allow custom @-tags.</p>
<dt><code>-no-stop</code></p>
<dd> Keep elements placed after the <code>(**/**)</code> special comment.</p>
<dt><code>-o</code><i>&nbsp;<wbr>file</i></p>
<dd> Output the generated documentation to <i>file</i> instead of <i>ocamldoc.out</i>. This option is meaningful only in conjunction with the <code>-latex</code>,<code>&nbsp;<wbr>-texi</code>, or<code>&nbsp;<wbr>-dot</code> options.</p>
<dt><code>-pp</code><i>&nbsp;<wbr>command</i></p>
<dd> Pipe sources through preprocessor <i>command</i>.</p>
<dt><code>-ppx</code><i>&nbsp;<wbr>command</i></p>
<dd> Pipe abstract syntax tree through preprocessor <i>command</i>.</p>
<dt><code>-sort</code></p>
<dd> Sort the list of top-level modules before generating the documentation.</p>
<dt><code>-stars</code></p>
<dd> Remove blank characters until the first asterisk (&#8216;*&#8217;) in each line of comments.</p>
<dt><code>-t</code><i>&nbsp;<wbr>title</i></p>
<dd> Use <i>title</i> as the title for the generated documentation.</p>
<dt><code>-intro</code><i>&nbsp;<wbr>file</i></p>
<dd> Use content of <i>file</i> as <code>ocamldoc</code> text to use as introduction (HTML, LaTeX and TeXinfo only). For HTML, the file is used to create the whole &quot;index.html&quot; file.</p>
<dt><code>-v</code></p>
<dd> Verbose mode. Display progress information.</p>
<dt><code>-version</code></p>
<dd> Print version string and exit.</p>
<dt><code>-vnum</code></p>
<dd> Print short version number and exit.</p>
<dt><code>-warn-error</code></p>
<dd> Treat <code>ocamldoc</code> warnings as errors.</p>
<dt><code>-hide-warnings</code></p>
<dd> Do not print <code>ocamldoc</code> warnings.</p>
<dt><code>-help</code>&nbsp;<wbr>or<code>&nbsp;<wbr>&#8211;help</code></p>
<dd> Display a short usage summary and exit.</dl>
<h3>Type-checking options</h3>
<p> <code><a href="/docs/linux/man/1-ocamldoc/">ocamldoc</a></code>(1) calls the OCaml type-checker to obtain type information. The following options impact the type-checking phase. They have the same meaning as for the <code><a href="/docs/linux/man/1-ocamlc/">ocamlc</a></code>(1)&nbsp;<wbr>and<code>&nbsp;<wbr><a href="/docs/linux/man/1-ocamlopt/">ocamlopt</a></code>(1) commands.</p>
<dl>
<dt><code>-I</code><i>&nbsp;<wbr>directory</i></p>
<dd> Add <i>directory</i> to the list of directories search for compiled interface files (.cmi files).</p>
<dt><code>-nolabels</code></p>
<dd> Ignore non-optional labels in types.</p>
<dt><code>-rectypes</code></p>
<dd>
&nbsp;<wbr>Allow arbitrary recursive types.&nbsp;<wbr>(See the <code>-rectypes</code> option to <code><a href="/docs/linux/man/1-ocamlc/">ocamlc</a></code>(1).)</dl>
<h3>Options for generating HTML pages</h3>
<p> The following options apply in conjunction with the <code>-html</code> option:</p>
<dl>
<dt><code>-all-params</code></p>
<dd> Display the complete list of parameters for functions and methods.</p>
<dt><code>-css-style</code><i>&nbsp;<wbr>filename</i></p>
<dd> Use <i>filename</i> as the Cascading Style Sheet file.</p>
<dt><code>-colorize-code</code></p>
<dd> Colorize the OCaml code enclosed in [ ] and \{[ ]\}, using colors to emphasize keywords, etc. If the code fragments are not syntactically correct, no color is added.</p>
<dt><code>-index-only</code></p>
<dd> Generate only index files.</p>
<dt><code>-short-functors</code></p>
<dd> Use a short form to display functors: <code>module M : functor (A:Module) -&gt; functor (B:Module2) -&gt; sig .. end</code> is displayed as <code>module M (A:Module) (B:Module2) : sig .. end</code>.</dl>
<h3>Options for generating LaTeX files</h3>
<p> The following options apply in conjunction with the <code>-latex</code> option:</p>
<dl>
<dt><code>-latex-value-prefix prefix</code></p>
<dd> Give a prefix to use for the labels of the values in the generated LaTeX document. The default prefix is the empty string. You can also use the options <code>-latex-type-prefix</code>, <code>-latex-exception-prefix</code>, <code>-latex-module-prefix</code>, <code>-latex-module-type-prefix</code>, <code>-latex-class-prefix</code>, <code>-latex-class-type-prefix</code>, <code>-latex-attribute-prefix</code>, and <code>-latex-method-prefix</code>. </p>
<p> These options are useful when you have, for example, a type and a value with the same name. If you do not specify prefixes, LaTeX will complain about multiply defined labels.</p>
<dt><code>-latextitle</code><i>&nbsp;<wbr>n,style</i></p>
<dd> Associate style number <i>n</i> to the given LaTeX sectioning command <i>style</i>, e.g. <code>section</code>or<code>subsection</code>. (LaTeX only.) This is useful when including the generated document in another LaTeX document, at a given sectioning level. The default association is 1 for section, 2 for subsection, 3 for subsubsection, 4 for paragraph and 5 for subparagraph.</p>
<dt><code>-noheader</code></p>
<dd> Suppress header in generated documentation.</p>
<dt><code>-notoc</code></p>
<dd> Do not generate a table of contents.</p>
<dt><code>-notrailer</code></p>
<dd> Suppress trailer in generated documentation.</p>
<dt><code>-sepfiles</code></p>
<dd> Generate one .tex file per toplevel module, instead of the global <i>ocamldoc.out</i> file.</dl>
<h3>Options for generating TeXinfo files</h3>
<p> The following options apply in conjunction with the <code>-texi</code> option:</p>
<dl>
<dt><code>-esc8</code></p>
<dd> Escape accented characters in Info files.</p>
<dt><code>-info-entry</code></p>
<dd> Specify Info directory entry.</p>
<dt><code>-info-section</code></p>
<dd> Specify section of Info directory.</p>
<dt><code>-noheader</code></p>
<dd> Suppress header in generated documentation.</p>
<dt><code>-noindex</code></p>
<dd> Do not build index for Info files.</p>
<dt><code>-notrailer</code></p>
<dd> Suppress trailer in generated documentation.</dl>
<h3>Options for generating dot graphs</h3>
<p> The following options apply in conjunction with the <code>-dot</code> option:</p>
<dl>
<dt><code>-dot-colors</code><i>&nbsp;<wbr>colors</i></p>
<dd> Specify the colors to use in the generated dot code. When generating module dependencies, <code><a href="/docs/linux/man/1-ocamldoc/">ocamldoc</a></code>(1) uses different colors for modules, depending on the directories in which they reside. When generating types dependencies, <code><a href="/docs/linux/man/1-ocamldoc/">ocamldoc</a></code>(1) uses different colors for types, depending on the modules in which they are defined. <i>colors</i> is a list of color names separated by commas (,), as in <code>Red,Blue,Green</code>. The available colors are the ones supported by the <code><a href="/docs/linux/man/1-dot/">dot</a></code>(1) tool.</p>
<dt><code>-dot-include-all</code></p>
<dd> Include all modules in the <code><a href="/docs/linux/man/1-dot/">dot</a></code>(1) output, not only modules given on the command line or loaded with the <code>-load</code> option.</p>
<dt><code>-dot-reduce</code></p>
<dd> Perform a transitive reduction of the dependency graph before outputting the dot code. This can be useful if there are a lot of transitive dependencies that clutter the graph.</p>
<dt><code>-dot-types</code></p>
<dd> Output dot code describing the type dependency graph instead of the module dependency graph.</dl>
<h3>Options for generating man files</h3>
<p> The following options apply in conjunction with the <code>-man</code> option:</p>
<dl>
<dt><code>-man-mini</code></p>
<dd> Generate man pages only for modules, module types, classes and class types, instead of pages for all elements.</p>
<dt><code>-man-suffix</code><i>suffix</i></p>
<dd> Set the suffix used for generated man filenames. Default is o, as in <i>List.o</i>.</p>
<dt><code>-man-section</code><i>section</i></p>
<dd> Set the section number used for generated man filenames. Default is 3. </p>
</dl>
