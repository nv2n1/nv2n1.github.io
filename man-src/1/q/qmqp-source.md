<h2 class="name">NAME</h2>
<p> qmqp-source &#8211; parallelized QMQP test generator </p>
<h2>SYNOPSIS</h2>
<p> <code>qmqp-source</code> [<i>options</i>] [<code>inet:</code>]<i>host</i>[:<i>port</i>] </p>
<p> <code>qmqp-source</code> [<i>options</i>] <code>unix:</code><i>pathname</i></p>
<h2>DESCRIPTION</h2>
<p> <code>qmqp-source</code> connects to the named host and TCP port (default 628) and sends one or more messages to it, either sequentially or in parallel. The program speaks the QMQP protocol. Connections can be made to UNIX-domain and IPv4 or IPv6 servers. IPv4 and IPv6 are the default. </p>
<p> Note: this is an unsupported test program. No attempt is made to maintain compatibility between successive versions. </p>
<p> Arguments:</p>
<dl>
<dt><code>-4</code></p>
<dd> Connect to the server with IPv4. This option has no effect when Postfix is built without IPv6 support.</p>
<dt><code>-6</code></p>
<dd> Connect to the server with IPv6. This option is not available when Postfix is built without IPv6 support.</p>
<dt><code>-c</code></p>
<dd> Display a running counter that is incremented each time a delivery completes.</p>
<dt><code>-C </code><i>count</i></p>
<dd> When a host sends RESET instead of SYN|ACK, try <i>count</i> times before giving up. The default count is 1. Specify a larger count in order to work around a problem with TCP/IP stacks that send RESET when the listen queue is full.</p>
<dt><code>-f </code><i>from</i></p>
<dd> Use the specified sender address (default: &lt;foo [at] myhostname&gt;).</p>
<dt><code>-l </code><i>length</i></p>
<dd> Send <i>length</i> bytes as message payload. The length includes the message headers.</p>
<dt><code>-m </code><i>message_count</i></p>
<dd> Send the specified number of messages (default: 1).</p>
<dt><code>-M </code><i>myhostname</i></p>
<dd> Use the specified hostname or [address] in the default sender and recipient addresses, instead of the machine hostname.</p>
<dt><code>-r </code><i>recipient_count</i></p>
<dd> Send the specified number of recipients per transaction (default: 1). Recipient names are generated by prepending a number to the recipient address.</p>
<dt><code>-s </code><i>session_count</i></p>
<dd> Run the specified number of QMQP sessions in parallel (default: 1).</p>
<dt><code>-t </code><i>to</i></p>
<dd> Use the specified recipient address (default: &lt;foo [at] myhostname&gt;).</p>
<dt><code>-R </code><i>interval</i></p>
<dd> Wait for a random period of time 0 &lt;= n &lt;= interval between messages. Suspending one thread does not affect other delivery threads.</p>
<dt><code>-v</code></p>
<dd> Make the program more verbose, for debugging purposes.</p>
<dt><code>-w </code><i>interval</i></p>
<dd> Wait a fixed time between messages. Suspending one thread does not affect other delivery threads.</dl>
