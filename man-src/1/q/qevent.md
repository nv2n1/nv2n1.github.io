<h2 class="name">NAME</h2>
<p> qevent &#8211; subscribe and respond to xxQS_NAMExx events </p>
<h2>DESCRIPTION</h2>
<p> <i>qevent</i> subscribes to &quot;events&quot; generated by the xxQS_NAMExx system and loops after writing its pid to the file <i>qevent.pid</i>. It is used by the xxQS_NAMExx test suite, and otherwise can be used to wait for a job or task to finish more efficiently than running <i>qstat</i> in a loop. See the example below.</p>
<h2>SYNOPSIS</h2>
<p> <code>qevent</code> [<code>-h</code>|<code>-help</code>] [<code>-ts</code>|<code>-testsuite</code>] [<code>-sm</code>|<code>-subscribe</code>] [<code>-trigger</code> <i>event script</i> [<code>-trigger</code> <i>event</i> <i>script</i>],&#8230;]</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-h</code>,&nbsp;<code>-help</code></p>
<dd> Show usage</p>
<dt><code>-ts</code>,&nbsp;<code>-testsuite</code></p>
<dd> Run in test suite mode.</p>
<dt><code>-sm</code>,&nbsp;<code>-subscribe</code></p>
<dd> Run in subscribe mode, printing events from the system.</p>
<dt><code>-trigger&nbsp;</code><i>event</i><code>&nbsp;</code><i>script</i></p>
<dd> Start executable <i>script</i> when the specified <i>event</i> occurs. <i>script</i> gets three arguments: event name, job id, and task id. <i>event</i> is one of <code>JB_END</code>: signals a job end; <code>JB_TASK_END</code>: signals a job task end.</dl>
<h2>FILES</h2>
<dl>
<dt><i>qevent.pid</i></p>
<dd> Id of the <i>qevent</i> process.</dl>
<h2>EXAMPLE</h2>
<p> This is an example of waiting for a job which could be used if the <code>-sync</code>, <code>-hold_jid</code>, or <code>-hold_jid_ad</code> options of <i>qsub</i> aren&#8217;t sufficient. </p>
<pre><code>
    $ cat wait-for-job
#!/ bin / sh
    if [ "$2" = $JOBID ]; then
        echo Job $JOBID finished
        kill $(cat qevent.pid)
        exit 0
    fi
    $ export JOBID=`qsub -b y -terse sleep 30`
    $ qevent -trigger JB_END ./wait-for-job 
    Job 122837 finished
    $
</code></pre>
