<h2>NAME</h2>
<p> qpidd &#8211; the Qpid AMQP Message Broker Daemon</p>
<h2>SYNOPSIS</h2>
<p> qpidd [-p port] [&#8211;config config_file] [&#8211;data-dir directory]</p>
<h2>DESCRIPTION</h2>
<p> An AMQP message broker daemon that stores, routes and forwards messages using the Advanced Message Queueing Protocol (AMQP).</p>
<h2>OPTIONS</h2>
<p> The options below are built-in to qpidd. Installing add-on modules provides additional options. To see the full set of options available type &quot;qpidd &#8211;help&quot; </p>
<p> Options may be specified via command line, environment variable or configuration file. See FILES and ENVIRONMENT below for details. </p>
<dl>
<dt><code>-h</code> [ <code>&#8211;help</code> ]</p>
<dd> Displays the help message</p>
<dt><code>-v</code> [ <code>&#8211;version</code> ]</p>
<dd> Displays version information</p>
<dt><code>&#8211;config</code> FILE</p>
<dd> Reads configuration from FILE</dl>
<h3>Module options:</h3>
<dl>
<dt><code>&#8211;module-dir</code> DIR</p>
<dd> Load all shareable modules in this directory</p>
<dt><code>&#8211;load-module</code> FILE</p>
<dd> Specifies additional module(s) to be loaded</p>
<dt><code>&#8211;no-module-dir</code></p>
<dd> Don&#8217;t load modules from module directory</dl>
<h3>Broker Options:</h3>
<dl>
<dt><code>&#8211;data-dir</code> DIR</p>
<dd> Directory to contain persistent data generated by the broker</p>
<dt><code>&#8211;no-data-dir</code></p>
<dd> Don&#8217;t use a data directory. No persistent configuration will be loaded or stored</p>
<dt><code>-p</code> [ <code>&#8211;port</code> ] PORT (5672)</p>
<dd> Tells the broker to listen on PORT</p>
<dt><code>&#8211;worker-threads</code> N (3)</p>
<dd> Sets the broker thread pool size</p>
<dt><code>&#8211;max-connections</code> N (500)</p>
<dd> Sets the maximum allowed connections</p>
<dt><code>&#8211;connection-backlog</code> N (10)</p>
<dd> Sets the connection backlog limit for the server socket</p>
<dt><code>-m</code> [ <code>&#8211;mgmt-enable</code> ] yes|no (1)</p>
<dd> Enable Management</p>
<dt><code>&#8211;mgmt-qmf2</code> yes|no (1)</p>
<dd> Enable broadcast of management information over QMF v2</p>
<dt><code>&#8211;mgmt-qmf1</code> yes|no (1)</p>
<dd> Enable broadcast of management information over QMF v1</p>
<dt><code>&#8211;mgmt-pub-interval</code> SECONDS (10)</p>
<dd> Management Publish Interval</p>
<dt><code>&#8211;queue-purge-interval</code> SECONDS (600)</p>
<dd> Interval between attempts to purge any expired messages from queues</p>
<dt><code>&#8211;auth</code> yes|no (1)</p>
<dd> Enable authentication, if disabled all incoming connections will be trusted</p>
<dt><code>&#8211;realm</code> REALM (QPID)</p>
<dd> Use the given realm when performing authentication</p>
<dt><code>&#8211;default-queue-limit</code> BYTES (104857600)</p>
<dd> Default maximum size for queues (in bytes)</p>
<dt><code>&#8211;tcp-nodelay</code></p>
<dd> Set TCP_NODELAY on TCP connections</p>
<dt><code>&#8211;require-encryption</code></p>
<dd> Only accept connections that are encrypted</p>
<dt><code>&#8211;known-hosts-url</code> URL or &#8216;none&#8217;</p>
<dd> URL to send as &#8216;known-hosts&#8217; to clients (&#8216;none&#8217; implies empty list)</p>
<dt><code>&#8211;sasl-config</code> DIR</p>
<dd> gets sasl config info from nonstandard location</p>
<dt><code>&#8211;max-session-rate</code> MESSAGES/S (0)</p>
<dd> Sets the maximum message rate per session (0=unlimited)</p>
<dt><code>&#8211;async-queue-events</code> yes|no (0)</p>
<dd> Set Queue Events async, used for services like replication</p>
<dt><code>&#8211;default-flow-stop-threshold</code> PERCENT (80)</p>
<dd> Percent of queue&#8217;s maximum capacity at which flow control is activated.</p>
<dt><code>&#8211;default-flow-resume-threshold</code> PERCENT (70)</p>
<dd> Percent of queue&#8217;s maximum capacity at which flow control is de-activated.</p>
<dt><code>&#8211;default-event-threshold-ratio</code> %age of limit (80)</p>
<dd> The ratio of any specified queue limit at which an event will be raised</dl>
<h3>Logging options:</h3>
<dl>
<dt><code>-t</code> [ <code>&#8211;trace</code> ]</p>
<dd> Enables all logging</p>
<dt><code>&#8211;log-enable</code> RULE (notice+)</p>
<dd> Enables logging for selected levels and components. RULE is in the form &#8216;LEVEL[+][:PATTERN]&#8217; Levels are one of:</p>
<dt>
<dd> trace debug info notice warning error</p>
<dt>
<dd> critical For example: &#8216;&#8211;log-enable warning+&#8217; logs all warning, error and critical messages. &#8216;&#8211;log-enable debug:framing&#8217; logs debug messages from the framing namespace. This option can be used multiple times</p>
<dt><code>&#8211;log-time</code> yes|no (1)</p>
<dd> Include time in log messages</p>
<dt><code>&#8211;log-level</code> yes|no (1)</p>
<dd> Include severity level in log messages</p>
<dt><code>&#8211;log-source</code> yes|no (0)</p>
<dd> Include source file:line in log messages</p>
<dt><code>&#8211;log-thread</code> yes|no (0)</p>
<dd> Include thread ID in log messages</p>
<dt><code>&#8211;log-function</code> yes|no (0)</p>
<dd> Include function signature in log messages</p>
<dt><code>&#8211;log-prefix</code> STRING</p>
<dd> Prefix to append to all log messages</dl>
<h3>Logging sink options:</h3>
<dl>
<dt><code>&#8211;log-to-stderr</code> yes|no (1)</p>
<dd> Send logging output to stderr</p>
<dt><code>&#8211;log-to-stdout</code> yes|no (0)</p>
<dd> Send logging output to stdout</p>
<dt><code>&#8211;log-to-file</code> FILE</p>
<dd> Send log output to FILE.</p>
<dt><code>&#8211;log-to-syslog</code> yes|no (0)</p>
<dd> Send logging output to syslog; customize using <code>&#8211;syslog-name</code> and <code>&#8211;syslog-facility</code></p>
<dt><code>&#8211;syslog-name</code> NAME (lt-qpidd)</p>
<dd> Name to use in syslog messages</p>
<dt><code>&#8211;syslog-facility</code> LOG_XXX (LOG_DAEMON)</p>
<dd> Facility to use in syslog messages</dl>
<h3>Daemon options:</h3>
<dl>
<dt><code>-d</code> [ <code>&#8211;daemon</code> ]</p>
<dd> Run as a daemon. Logs to syslog by default in this mode.</p>
<dt><code>&#8211;transport</code> TRANSPORT (tcp)</p>
<dd> The transport for which to return the port</p>
<dt><code>&#8211;pid-dir</code> DIR</p>
<dd> Directory where port-specific PID file is stored</p>
<dt><code>-w</code> [ <code>&#8211;wait</code> ] SECONDS (600)</p>
<dd> Sets the maximum wait time to initialize the daemon. If the daemon fails to initialize, prints an error and returns 1</p>
<dt><code>-c</code> [ <code>&#8211;check</code> ]</p>
<dd> Prints the daemon&#8217;s process ID to stdout and returns 0 if the daemon is running, otherwise returns 1</p>
<dt><code>-q</code> [ <code>&#8211;quit</code> ]</p>
<dd> Tells the daemon to shut down</dl>
<h2>ENVIRONMENT</h2>
<p> <i>QPID_&lt;option&gt;</i></p>
<dl>
<dt>
<dd> There is an environment variable for each option.</dl>
<p> The environment variable is the option name in uppercase, prefixed with QPID_ and &#8216;.&#8217; or &#8216;-&#8216; are replaced with &#8216;_&#8217;. Environment settings are over-ridden by command line settings. For example: </p>
<p>&nbsp;<wbr>&nbsp;<wbr>export QPID_PORT=6000<br />
&nbsp;<wbr>&nbsp;<wbr>export QPID_MAX_CONNECTIONS=10<br />
&nbsp;<wbr>&nbsp;<wbr>export QPID_LOG_TO_FILE=/tmp/qpidd.log</p>
<h2>FILES</h2>
<p> <i>/etc/qpidd.conf</i></p>
<dl>
<dt>
<dd> Default configuration file.</dl>
<p> Configuration file settings are over-ridden by command line or environment variable settings. &#8216;&#8211;config &lt;file&gt;&#8217; or &#8216;export QPID_CONFIG=&lt;file&gt;&#8217; specifies an alternate file. </p>
<p> Each line is a name=value pair. Blank lines and lines beginning with # are ignored. For example: </p>
<p>&nbsp;<wbr>&nbsp;<wbr>#&nbsp;<wbr>My qpidd configuration file.<br />
&nbsp;<wbr>&nbsp;<wbr>port=6000<br />
&nbsp;<wbr>&nbsp;<wbr>max-connections=10<br />
&nbsp;<wbr>&nbsp;<wbr>log-to-file=/tmp/qpidd.log</p>
