<h2 class="name">NAME</h2>
<p> iostat &#8211; Report Central Processing Unit (CPU) statistics and input/output statistics for devices and partitions.</p>
<h2>SYNOPSIS</h2>
<p> <code>iostat [ -c ] [ -d ] [ -h ] [ -k | -m ] [ -N ] [ -s ] [ -t ] [ -V ] [ -x ] [ -y ] [ -z ]</code> <code>[ &#8211;dec={ 0 | 1 | 2 } ] [ { -f | +f } </code><i>directory</i><code> ] [ -j { ID | LABEL | PATH | UUID | &#8230; } ] </code> <code>[ -o JSON ] [ [ -H ] -g </code><i>group_name </i><code>] [ &#8211;human ] [ &#8211;pretty ] [ -p [ </code><i>device</i><code>[,&#8230;] | ALL ] ] [</code> <i>device </i><code>[&#8230;] | ALL ] [ </code><i>interval </i><code>[ </code><i>count </i><code>] ]</code> </p>
<h2>DESCRIPTION</h2>
<p> The <code>iostat</code> command is used for monitoring system input/output device loading by observing the time the devices are active in relation to their average transfer rates. The <code>iostat</code> command generates reports that can be used to change system configuration to better balance the input/output load between physical disks. </p>
<p> The first report generated by the <code>iostat</code> command provides statistics concerning the time since the system was booted, unless the <code>-y</code> option is used (in this case, this first report is omitted). Each subsequent report covers the time since the previous report. All statistics are reported each time the <code>iostat</code> command is run. The report consists of a CPU header row followed by a row of CPU statistics. On multiprocessor systems, CPU statistics are calculated system-wide as averages among all processors. A device header row is displayed followed by a line of statistics for each device that is configured. </p>
<p> The <i>interval</i> parameter specifies the amount of time in seconds between each report. The <i>count </i>parameter can be specified in conjunction with the <i>interval</i> parameter. If the <i>count </i>parameter is specified, the value of <i>count</i> determines the number of reports generated at <i>interval </i>seconds apart. If the <i>interval </i>parameter is specified without the <i>count </i>parameter, the <code>iostat</code> command generates reports continuously. </p>
<h2>REPORTS</h2>
<p> The <code>iostat</code> command generates two types of reports, the CPU Utilization report and the Device Utilization report. </p>
<dl>
<dt>CPU Utilization Report</p>
<dd> The first report generated by the <code>iostat</code> command is the CPU Utilization Report. For multiprocessor systems, the CPU values are global averages among all processors. The report has the following format:</p>
<dl>
<dt>
<dd>
<dl>
<dt>%user</p>
<dd> Show the percentage of CPU utilization that occurred while executing at the user level (application).</p>
<dt>%nice</p>
<dd> Show the percentage of CPU utilization that occurred while executing at the user level with nice priority.</p>
<dt>%system</p>
<dd> Show the percentage of CPU utilization that occurred while executing at the system level (kernel).</p>
<dt>%iowait</p>
<dd> Show the percentage of time that the CPU or CPUs were idle during which the system had an outstanding disk I/O request.</p>
<dt>%steal</p>
<dd> Show the percentage of time spent in involuntary wait by the virtual CPU or CPUs while the hypervisor was servicing another virtual processor.</p>
<dt>%idle</p>
<dd> Show the percentage of time that the CPU or CPUs were idle and the system did not have an outstanding disk I/O request.</dl>
</dl>
</dl>
<dl>
<dt>Device Utilization Report</p>
<dd> The second report generated by the <code>iostat</code> command is the Device Utilization Report. The device report provides statistics on a per physical device or partition basis. Block devices and partitions for which statistics are to be displayed may be entered on the command line. If no device nor partition is entered, then statistics are displayed for every device used by the system, and providing that the kernel maintains statistics for it. If the <code>ALL</code> keyword is given on the command line, then statistics are displayed for every device defined by the system, including those that have never been used. Transfer rates are shown in 1K blocks by default, unless the environment variable <code>POSIXLY_CORRECT</code> is set, in which case 512-byte blocks are used. The report may show the following fields, depending on the flags used (e.g. <code>-x</code>, <code>-s </code>and <code>-k </code>or <code>-m</code>):</p>
<dl>
<dt>
<dd>
<dl>
<dt>Device:</p>
<dd> This column gives the device (or partition) name as listed in the <i>/dev </i>directory.</p>
<dt>tps</p>
<dd> Indicate the number of transfers per second that were issued to the device. A transfer is an I/O request to the device. Multiple logical requests can be combined into a single I/O request to the device. A transfer is of indeterminate size.</p>
<dt>Blk_read/s (kB_read/s, MB_read/s)</p>
<dd> Indicate the amount of data read from the device expressed in a number of blocks (kilobytes, megabytes) per second. Blocks are equivalent to sectors and therefore have a size of 512 bytes.</p>
<dt>Blk_wrtn/s (kB_wrtn/s, MB_wrtn/s)</p>
<dd> Indicate the amount of data written to the device expressed in a number of blocks (kilobytes, megabytes) per second.</p>
<dt>Blk_dscd/s (kB_dscd/s, MB_dscd/s)</p>
<dd> Indicate the amount of data discarded for the device expressed in a number of blocks (kilobytes, megabytes) per second.</p>
<dt>Blk_w+d/s (kB_w+d/s, MB_w+d/s)</p>
<dd> Indicate the amount of data written to or discarded for the device expressed in a number of blocks (kilobytes, megabytes) per second.</p>
<dt>Blk_read (kB_read, MB_read)</p>
<dd> The total number of blocks (kilobytes, megabytes) read.</p>
<dt>Blk_wrtn (kB_wrtn, MB_wrtn)</p>
<dd> The total number of blocks (kilobytes, megabytes) written.</p>
<dt>Blk_dscd (kB_dscd, MB_dscd)</p>
<dd> The total number of blocks (kilobytes, megabytes) discarded.</p>
<dt>Blk_w+d (kB_w+d, MB_w+d)</p>
<dd> The total number of blocks (kilobytes, megabytes) written or discarded.</p>
<dt>r/s</p>
<dd> The number (after merges) of read requests completed per second for the device.</p>
<dt>w/s</p>
<dd> The number (after merges) of write requests completed per second for the device.</p>
<dt>d/s</p>
<dd> The number (after merges) of discard requests completed per second for the device.</p>
<dt>f/s</p>
<dd> The number (after merges) of flush requests completed per second for the device. This counts flush requests executed by disks. Flush requests are not tracked for partitions. Before being merged, flush operations are counted as writes.</p>
<dt>sec/s (kB/s, MB/s)</p>
<dd> The number of sectors (kilobytes, megabytes) read from, written to or discarded for the device per second.</p>
<dt>rsec/s (rkB/s, rMB/s)</p>
<dd> The number of sectors (kilobytes, megabytes) read from the device per second.</p>
<dt>wsec/s (wkB/s, wMB/s)</p>
<dd> The number of sectors (kilobytes, megabytes) written to the device per second.</p>
<dt>dsec/s (dkB/s, dMB/s)</p>
<dd> The number of sectors (kilobytes, megabytes) discarded for the device per second.</p>
<dt>rqm/s</p>
<dd> The number of I/O requests merged per second that were queued to the device.</p>
<dt>rrqm/s</p>
<dd> The number of read requests merged per second that were queued to the device.</p>
<dt>wrqm/s</p>
<dd> The number of write requests merged per second that were queued to the device.</p>
<dt>drqm/s</p>
<dd> The number of discard requests merged per second that were queued to the device.</p>
<dt>%rrqm</p>
<dd> The percentage of read requests merged together before being sent to the device.</p>
<dt>%wrqm</p>
<dd> The percentage of write requests merged together before being sent to the device.</p>
<dt>%drqm</p>
<dd> The percentage of discard requests merged together before being sent to the device.</p>
<dt>areq-sz</p>
<dd> The average size (in kilobytes) of the I/O requests that were issued to the device.<br />
 Note: In previous versions, this field was known as avgrq-sz and was expressed in sectors.</p>
<dt>rareq-sz</p>
<dd> The average size (in kilobytes) of the read requests that were issued to the device.</p>
<dt>wareq-sz</p>
<dd> The average size (in kilobytes) of the write requests that were issued to the device.</p>
<dt>dareq-sz</p>
<dd> The average size (in kilobytes) of the discard requests that were issued to the device.</p>
<dt>await</p>
<dd> The average time (in milliseconds) for I/O requests issued to the device to be served. This includes the time spent by the requests in queue and the time spent servicing them.</p>
<dt>r_await</p>
<dd> The average time (in milliseconds) for read requests issued to the device to be served. This includes the time spent by the requests in queue and the time spent servicing them.</p>
<dt>w_await</p>
<dd> The average time (in milliseconds) for write requests issued to the device to be served. This includes the time spent by the requests in queue and the time spent servicing them.</p>
<dt>d_await</p>
<dd> The average time (in milliseconds) for discard requests issued to the device to be served. This includes the time spent by the requests in queue and the time spent servicing them.</p>
<dt>f_await</p>
<dd> The average time (in milliseconds) for flush requests issued to the device to be served. The block layer combines flush requests and executes at most one at a time. Thus flush operations could be twice as long: Wait for current flush request, then execute it, then wait for the next one.</p>
<dt>aqu-sz</p>
<dd> The average queue length of the requests that were issued to the device.<br />
 Note: In previous versions, this field was known as avgqu-sz.</p>
<dt>%util</p>
<dd> Percentage of elapsed time during which I/O requests were issued to the device (bandwidth utilization for the device). Device saturation occurs when this value is close to 100% for devices serving requests serially. But for devices serving requests in parallel, such as RAID arrays and modern SSDs, this number does not reflect their performance limits.</dl>
</dl>
</dl>
<h2>OPTIONS</h2>
<dl>
<dt><code>-c</code></p>
<dd> Display the CPU utilization report.</p>
<dt><code>-d</code></p>
<dd> Display the device utilization report.</p>
<dt><code>&#8211;dec={ 0 | 1 | 2 }</code></p>
<dd> Specify the number of decimal places to use (0 to 2, default value is 2).</p>
<dt><code>-f </code><i>directory</i></p>
<dd> <code>+f </code><i>directory</i></p>
<dl>
<dt>
<dd> Specify an alternative directory for <code>iostat</code> to read devices statistics. Option <code>-f </code>tells <code>iostat </code>to use only the files located in the alternative directory, whereas option <code>+f</code> tells it to use both the standard kernel files and the files located in the alternative directory to read device statistics. </p>
<p> <i>directory</i> is a directory containing files with statistics for devices managed in userspace. It may contain: </p>
<p> &#8211; a &quot;diskstats&quot; file whose format is compliant with that located in &quot;/proc&quot;,<br />
 &#8211; statistics for individual devices contained in files whose format is compliant with that of files located in &quot;/sys&quot;. </p>
<p> In particular, the following files located in <i>directory</i> may be used by <code>iostat</code>: </p>
<p> <i>directory</i>/block/<i>device</i>/stat<br />
 <i>directory</i>/block/<i>device</i>/<i>partition</i>/stat </p>
<p> <i>partition</i> files must have an entry in <i>directory</i>/dev/block/ directory, e.g.: </p>
<p> <i>directory</i>/dev/block/<i>major</i>:<i>minor</i> &#8211;&gt; ../../block/<i>device</i>/<i>partition</i></dl>
<dt><code>-g </code><i>group_name </i><code>{ </code><i>device </i><code>[&#8230;] | ALL }</code></p>
<dd> Display statistics for a group of devices. The <code>iostat</code> command reports statistics for each individual device in the list then a line of global statistics for the group displayed as <i>group_name</i> and made up of all the devices in the list. The <code>ALL</code> keyword means that all the block devices defined by the system shall be included in the group.</p>
<dt><code>-H</code></p>
<dd> This option must be used with option <code>-g</code> and indicates that only global statistics for the group are to be displayed, and not statistics for individual devices in the group.</p>
<dt><code>-h</code></p>
<dd> This option is equivalent to specifying <code>&#8211;human &#8211;pretty</code>.</p>
<dt><code>&#8211;human</code></p>
<dd> Print sizes in human readable format (e.g. 1.0k, 1.2M, etc.) The units displayed with this option supersede any other default units (e.g. kilobytes, sectors&#8230;) associated with the metrics.</p>
<dt><code>-j { ID | LABEL | PATH | UUID | &#8230; } [ </code><i>device </i><code>[&#8230;] | ALL ]</code></p>
<dd> Display persistent device names. Keywords <code>ID</code>, <code>LABEL</code>, etc. specify the type of the persistent name. These keywords are not limited, only prerequisite is that directory with required persistent names is present in <i>/dev/disk</i>. Optionally, multiple devices can be specified in the chosen persistent name type. Because persistent device names are usually long, option <code>&#8211;pretty</code> is implicitly set with this option.</p>
<dt><code>-k</code></p>
<dd> Display statistics in kilobytes per second.</p>
<dt><code>-m</code></p>
<dd> Display statistics in megabytes per second.</p>
<dt><code>-N</code></p>
<dd> Display the registered device mapper names for any device mapper devices. Useful for viewing LVM2 statistics.</p>
<dt><code>-o JSON</code></p>
<dd> Display the statistics in JSON (Javascript Object Notation) format. JSON output field order is undefined, and new fields may be added in the future.</p>
<dt><code>-p [ { </code><i>device</i><code>[,&#8230;] | ALL } ]</code></p>
<dd> Display statistics for block devices and all their partitions that are used by the system. If a device name is entered on the command line, then statistics for it and all its partitions are displayed. Last, the <code>ALL</code> keyword indicates that statistics have to be displayed for all the block devices and partitions defined by the system, including those that have never been used. If option <code>-j</code> is defined before this option, devices entered on the command line can be specified with the chosen persistent name type.</p>
<dt><code>&#8211;pretty</code></p>
<dd> Make the Device Utilization Report easier to read by a human.</p>
<dt><code>-s</code></p>
<dd> Display a short (narrow) version of the report that should fit in 80 characters wide screens.</p>
<dt><code>-t</code></p>
<dd> Print the time for each report displayed. The timestamp format may depend on the value of the <code>S_TIME_FORMAT </code>environment variable (see below).</p>
<dt><code>-V</code></p>
<dd> Print version number then exit.</p>
<dt><code>-x</code></p>
<dd> Display extended statistics.</p>
<dt><code>-y</code></p>
<dd> Omit first report with statistics since system boot, if displaying multiple records at given interval.</p>
<dt><code>-z</code></p>
<dd> Tell <code>iostat</code> to omit output for any devices for which there was no activity during the sample period. </p>
</dl>
<h2>ENVIRONMENT</h2>
<p> The <code>iostat</code> command takes into account the following environment variables:</p>
<dl>
<dt><code>POSIXLY_CORRECT</code></p>
<dd> When this variable is set, transfer rates are shown in 512-byte blocks instead of the default 1K blocks.</p>
<dt><code>S_COLORS</code></p>
<dd> By default statistics are displayed in color when the output is connected to a terminal. Use this variable to change the settings. Possible values for this variable are <i>never</i>, <i>always </i>or <i>auto</i> (the latter is equivalent to the default settings).<br />
 Please note that the color (being red, yellow, or some other color) used to display a value is not indicative of any kind of issue simply because of the color. It only indicates different ranges of values.</p>
<dt><code>S_COLORS_SGR</code></p>
<dd> Specify the colors and other attributes used to display statistics on the terminal. Its value is a colon-separated list of capabilities that defaults to <code>H=31;1:I=32;22:M=35;1:N=34;1:Z=34;22</code>. Supported capabilities are:</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>H=</code></p>
<dd> SGR (Select Graphic Rendition) substring for percentage values greater than or equal to 75%.</p>
<dt><code>I=</code></p>
<dd> SGR substring for device names.</p>
<dt><code>M=</code></p>
<dd> SGR substring for percentage values in the range from 50% to 75%.</p>
<dt><code>N=</code></p>
<dd> SGR substring for non-zero statistics values.</p>
<dt><code>Z=</code></p>
<dd> SGR substring for zero values.</dl>
</dl>
<dt><code>S_TIME_FORMAT</code></p>
<dd> If this variable exists and its value is <code>ISO</code> then the current locale will be ignored when printing the date in the report header. The <code>iostat</code> command will use the ISO 8601 format (YYYY-MM-DD) instead. The timestamp displayed with option <code>-t</code> will also be compliant with ISO 8601 format. </p>
</dl>
<h2>EXAMPLES</h2>
<dl>
<dt><code>iostat</code></p>
<dd> Display a single history since boot report for all CPU and Devices.</p>
<dt><code>iostat -d 2</code></p>
<dd> Display a continuous device report at two second intervals.</p>
<dt><code>iostat -d 2 6</code></p>
<dd> Display six reports at two second intervals for all devices.</p>
<dt><code>iostat -x sda sdb 2 6</code></p>
<dd> Display six reports of extended statistics at two second intervals for devices sda and sdb.</p>
<dt><code>iostat -p sda 2 6</code></p>
<dd> Display six reports at two second intervals for device sda and all its partitions (sda1, etc.) </p>
</dl>
<h2>BUGS</h2>
<p> <i>/proc </i>filesystem must be mounted for <code>iostat </code>to work. </p>
<p> Kernels older than 2.6.x are no longer supported. </p>
<p> Although <code>iostat</code> speaks of kilobytes (kB), megabytes (MB)&#8230;, it actually uses kibibytes (kiB), mebibytes (MiB)&#8230; A kibibyte is equal to 1024 bytes, and a mebibyte is equal to 1024 kibibytes. </p>
<h2>FILES</h2>
<p> <i>/proc/stat </i>contains system statistics.<br />
 <i>/proc/uptime </i>contains system uptime.<br />
 <i>/proc/diskstats </i>contains disks statistics.<br />
 <i>/sys </i>contains statistics for block devices.<br />
 <i>/proc/self/mountstats </i>contains statistics for network filesystems.<br />
 <i>/dev/disk </i>contains persistent device names. </p>
