<h2 class="name">NAME</h2>
<p> mailbot &#8211; A MIME-aware autoresponder utility </p>
<h2>SYNOPSIS</h2>
<dl>
<dt> <code>mailbot</code> [options] {<i>program</i>} [arg&#8230;]</dl>
<dd>In .mailfilter: </p>
<pre><code>
if (/ ^Subject
    : *info /) {
    cc "| mailbot -t /usr/share/autoresponse/info -d autoresponsedb \
            -A 'From: info [at] domain.com' /usr/bin/sendmail -f ''"
}
</code></pre>
<h2>DESCRIPTION</h2>
<p> <code>mailbot</code> reads an E-mail message on standard input and creates an E-mail message replying to the original message&#8217;s sender. A <code>program</code> is specified as an argument to <code>mailbot</code> after all of <code>mailbot</code> options. <code>program</code> is expected to read the created autoreply on its standard input, and mail it. If <code>program</code> is not specified, <code>mailbot</code> runs &#8216;sendmail -f &quot;&quot;&#8217;. </p>
<p> <code>mailbot</code> has several options for suppressing duplicate autoresponse messages. If <code>mailbot</code> chooses not to send an autoresponse, it quietly terminates without running <code>program</code>. The autoresponse is optionally formatted as a MIME delivery status notification. </p>
<p> The text of the autoresponse is specified by the <code>-t</code> or the <code>-m</code> argument. Either one is required. Everything else is optional. The only exception is the <code>-T replydraft</code> option, which requires the <code>-l</code> option instead of either <code>-t</code> or <code>-m</code>. The default behavior is to send an autoresponse unless the original message has the &quot;Precedence: junk&quot; or the &quot;Precedence: bulk&quot; header, or the &quot;Precedence: list&quot; header, or the &quot;List-ID:&quot; header, or if its MIME content type is &quot;multipart/report&quot; (this is the MIME content type for delivery status notifications). The <code>-M</code> option formats the the autoresponse itself as a MIME delivery status notification.</p>
<h2>OPTIONS</h2>
<p> -A &quot;<i>header: value</i>&quot;</p>
<dl>
<dt>
<dd> Add a header to the autoresponse. Multiple <code>-A</code> options are allowed. In most situations, the <code>-A</code> option must be used to set the &#8220;From:&#8221; header in the autogenerated response.</dl>
<p> -f<i>address</i></p>
<dl>
<dt>
<dd> Address the autoresponse to <i>address</i>, which must be an m[blue]<code>RFC 2822</code>m[]<font SIZE="-2">[1]</font> address. By default <code>mailbot</code> takes the autoresponse address from the From: (or the Reply-To:) header in the original message. <code>-f</code>, if present, overrides and explicitly sets the autoresponse address. &quot;<i>address</i>&quot; must immediately follow the <code>-f</code> option without an intervening space (it&#8217;s a single command line argument). An <code>-f</code> option without an <i>address</i> takes the address from the <code>SENDER</code> environment variable.</dl>
<p> -t <i>filename</i></p>
<dl>
<dt>
<dd> Read text autoresponse from <i>filename</i>, which must contain a plain text message in &#8220;flowed-text&#8221; format. In a &#8220;flowed-text&#8221;-formatted message, each line that ends with a space character indicates that the line logically flows into the next line. This allows the message to be reformatted for any shown display width. </p>
<dl>
<dt>
<dd>
 <font SIZE="+1"> <code>Note</code> </font><br />
 Messages in languages (see the <code>-c</code> option) which use spaces as word delimiters must have <i>two</i> spaces at the end of a flowed line. The last space on a flowed line is logically removed, and the first space separates the last word on the previous line from the first word on the next line. Otherwise, the two words will not have a logical space between them if they get repositioned as part of adjusting the message&#8217;s width for display. </p>
<p> Messages in ideographic languages that do not use spaces as word delimiters need only one space trailing a flowed line. </p>
</dl>
<dl>
<dt>
<dd>
 <font SIZE="+1"> <code>Note</code> </font><br />
 The trailing whitespace has no visual impact when shown by software that does not implemented flowed text format, and always displays messages using their original width. </p>
</dl>
</dl>
<p> -c <i>charset</i></p>
<dl>
<dt>
<dd> Set the autoresponse&#8217;s MIME character set to <i>charset</i>. Run <code>mailbot</code> without any arguments to see the default character set.</dl>
<p> -m <i>filename</i></p>
<dl>
<dt>
<dd> Read a MIME autoresponse from filename. This is similar to the <code>-t</code> option, except that <i>filename</i> contains MIME headers, followed by a blank line, and the corresponding MIME content. The contents of <i>filename</i> are inserted in the autoresponse without further processing. </p>
<p> The specified file must contain the &#8220;Content-Type&#8221; header specifying the &#8220;text/plain&#8221; MIME type, with the &#8220;format=flowed&#8221;, &#8220;delsp=yes&#8221;, and the &#8220;charset&#8221; attributes, which override the <code>-c</code> parameter. If the specified file has a &#8220;Content-Transfer-Encoding&#8221; header it must be either &#8220;7bit&#8221; or &#8220;8bit&#8221;, it may not be &#8220;quoted-printable&#8221;. <code>mailbot</code> always drops any existing &#8220;Content-Transfer-Encoding&#8221; header and always adds the &#8220;Content-Transfer-Encoding: 8bit&#8221; header, even with the <code>-m</code>, since the salutation inserted into the message includes the sender&#8217;s name, which may contain 8-bit characters. Example: </p>
<dl>
<dt>
<dd>
<pre>
Content-Type: text/plain; format=flowed; delsp=yes; charset=&quot;iso-8859-1&quot;
Mary had a little lamb,  
Its fleece was white as snow.  
And everywhere Mary went,  
The lamb was sure to go.
</pre>
</dl>
<dl>
<dt>
<dd>
 <font SIZE="+1"> <code>Note</code> </font><br />
 When the <code>-m</code> option is specified <code>mailbot</code> ignores the locale&#8217;s character set and formats the autoreply according to the character set read from the &#8220;Content-Type&#8221; header. </p>
</dl>
</dl>
<p> -M <i>address</i></p>
<dl>
<dt>
<dd> Format the autoresponse as a delivery status notification (m[blue]<code>RFC 1894</code>m[]<font SIZE="-2">[2]</font>). <i>address</i> is an m[blue]<code>RFC 2822</code>m[]<font SIZE="-2">[1]</font> E-mail address that generates the DSN. Note that the <code>-A</code> option should still be used in addition to <code>-M</code> in order to set the From: header on the autoresponse. <code>-M</code> sets the DSN address only. The <code>-M</code> option automatically sets <code>-T </code><code>replydsn</code></dl>
<p> -R <i>type</i></p>
<dl>
<dt>
<dd> Specify the feedback report type, with <i>type</i> set to abuse, fraud, other, or virus. Must be used together with &#8220;-T feedback&#8221; or &#8220;-T replyfeedback&#8221;.</dl>
<p> -T <i>format</i></p>
<dl>
<dt>
<dd> Set the reply format. <i>format</i> must be one of the following values: </p>
<dl>
<dt>
<dd> &bull; &#8220;reply&#8221; &#8211; the default reply format.</dl>
<dl>
<dt>
<dd> &bull; &#8220;replyall&#8221; &#8211; like &#8220;reply&#8221;, except also puts the recipients in the original message&#8217;s &#8220;To:&#8221; and &#8220;Cc:&#8221; headers into the &#8220;Cc:&#8221; header of the generated reply.</dl>
<dl>
<dt>
<dd> &bull; &#8220;replydsn&#8221; &#8211; like &#8220;reply&#8221;, except the message is formatted as a delivery status notification.</dl>
<dl>
<dt>
<dd> &bull; &#8220;replydraft&#8221; &#8211; like &#8220;reply&#8221;, with the text of the autoresponse coming from a maildir specified by the <code>-l</code> option. See &#8220;Autoreplies from a maildir folder&#8221;, below.</dl>
<dl>
<dt>
<dd> &bull; &#8220;forward&#8221; &#8211; attach the original message as forwarded text.</dl>
<dl>
<dt>
<dd> &bull; &#8220;forwardatt&#8221; &#8211; attach the original message as a forwarded message attachment.</dl>
<dl>
<dt>
<dd> &bull; &#8220;feedback&#8221; &#8211; generate an Email Feedback Report message (see m[blue]<code>RFC 5965</code>m[]<font SIZE="-2">[3]</font>). The &#8220;-R&#8221; option is required when this is specified.</dl>
<dl>
<dt>
<dd> &bull; &#8220;replyfeedback&#8221; &#8211; like &#8220;feedback&#8221;, but also adds a &#8220;To:&#8221; header, addressed to the original message&#8217;s sender.</dl>
</dl>
<p> -N</p>
<dl>
<dt>
<dd> Do not quote the contents of the original message in the message created by &#8220;reply&#8221;, &#8220;replyall&#8221;, &#8220;replydsn&#8221;, &#8220;feedback&#8221;, and &#8220;replyfeedback&#8221; options. </p>
<dl>
<dt>
<dd>
 <font SIZE="+1"> <code>Note</code> </font><br />
 The original message gets quoted, in the absence of this option, only if the original message was formatted as plain text. <code>mailbot</code> is unable to quote an original message which was formatted as HTML, or any other non-plaintext format. </p>
</dl>
<dl>
<dt>
<dd>
 <font SIZE="+1"> <code>Note</code> </font><br />
 For &#8220;replydsn&#8221;, &#8220;feedback&#8221;, and &#8220;replyfeedback&#8221; options, the convention is to attach the original message, or only its headers, separately; so this option should always be specified for these three reply formats. </p>
</dl>
</dl>
<p> -a</p>
<dl>
<dt>
<dd> Attach the entire message, for &#8220;replydsn&#8221;, &#8220;feedback&#8221;, and &#8220;replyfeedback&#8221;, instead of only its headers.</dl>
<p> -e</p>
<dl>
<dt>
<dd> Generate a reply (&#8220;reply&#8221;-formats) to the address listed in any &#8220;Errors-To&#8221; or &#8220;Return-Path&#8221; header, if present, instead of the &#8220;From&#8221; header.</dl>
<p> -S &#8220;salutation&#8221;</p>
<dl>
<dt>
<dd> Use the given <i>salutation</i> in the &#8220;reply&#8221;. The default value is &#8220;%F writes:&#8221;. The following substitutions are recognized in the salutation string: </p>
<dl>
<dt>
<dd> &bull; %% &#8211; an explicit % character.</dl>
<dl>
<dt>
<dd> &bull; %n &#8211; a newline character.</dl>
<dl>
<dt>
<dd> &bull; %C &#8211; the &#8220;X-Newsgroup:&#8221; header from the original message.</dl>
<dl>
<dt>
<dd> &bull; %N &#8211; the &#8220;Newsgroups:&#8221; header from the original message.</dl>
<dl>
<dt>
<dd> &bull; %i &#8211; the &#8220;Message-ID:&#8221; header from the original message.</dl>
<dl>
<dt>
<dd> &bull; %f &#8211; the original message&#8217;s sender&#8217;s address.</dl>
<dl>
<dt>
<dd> &bull; %F &#8211; the original message&#8217;s sender&#8217;s name.</dl>
<dl>
<dt>
<dd> &bull; %S &#8211; the &#8220;Subject:&#8221; header from the original message</dl>
<dl>
<dt>
<dd> &bull; %d &#8211; the original message&#8217;s date, in the local timezone.</dl>
<dl>
<dt>
<dd> &bull; %{<i>&#8230;</i>}d &#8211; use <code>strftime</code>() to format the original message&#8217;s date. A plain %d is equivalent to %{%a, %d %b %Y %H:%M:%S %z}d.</dl>
<p> All other characters in the salutation string are left as is.</dl>
<p> -F &#8220;marker&#8221;</p>
<dl>
<dt>
<dd> When generating a forward, use the <i>marker</i> to separate the forwarded message from the autoreply text, instead of the default &#8220;&#8212; Forwarded message &#8212;&#8220;</dl>
<p> -r <i>addrlist</i></p>
<dl>
<dt>
<dd> <i>addrlist</i> is a comma-separated list of m[blue]<code>RFC 2822</code>m[]<font SIZE="-2">[1]</font> E-mail addresses. <code>mailbot</code> sends an autoresponse only if the original message has at least one of the specified addresses in any To: or Cc: header.</dl>
<p> -d <i>filename</i></p>
<dl>
<dt>
<dd> Create a small database, <i>filename</i>, that keeps track of senders&#8217; E-mail addresses, and prevent duplicate autoresponses going to the same address (suppress autoresponses going back to the same senders, for subsequent received messages). The <code>-d</code> option is only available if <code>maildrop</code> has GDBM/DB extensions enabled.</dl>
<p> -D <i>x</i></p>
<dl>
<dt>
<dd> Do not send duplicate autoresponses (see the <code>-d</code> option) for at least <i>x</i> days (default: 1 day). The <code>-d</code> option creates a database of E-mail addresses and the times an autoresponse was last mailed to them. Another autoresponse to the same address will not be mailed until at least the amount of time specified by the <code>-D</code> option has elapsed.</dl>
<p> -s &quot;<i>subject</i>&quot;</p>
<dl>
<dt>
<dd> Set the Subject: header on the autoresponse to <i>subject</i>.</dl>
<p> -n</p>
<dl>
<dt>
<dd> Show the resulting message, do not send it. Used for debugging purposes.</dl>
<p> &#8211;feedback-original-envelope-id&nbsp;<wbr><i>&quot;&lt;envelopeid&gt;&quot;</i>, &#8211;feedback-original-mail-from&nbsp;<wbr><i>&quot;&lt;mailfrom&gt;&quot;</i>, &#8211;feedback-reporting-mta&nbsp;<wbr>&quot;<i>dns;&nbsp;<wbr>hostname&quot;</i>, &#8211;feedback-source-ip&nbsp;<wbr><i>aaa.bbb.ccc.ddd</i>, &#8211;feedback-incidents&nbsp;<wbr><i>n</i>, &#8211;feedback-authentication-results&nbsp;<wbr><i>&quot;results&quot;</i>, &#8211;feedback-original-rcpt-to&nbsp;<wbr><i>&quot;&lt;rcptto&gt;&quot;</i>, &#8211;feedback-reported-domain&nbsp;<wbr><i>example.com</i></p>
<dl>
<dt>
<dd> Optional parameters to include in the feedback report generated by &#8220;feedback&#8221; and &#8220;replyfeedback&#8221;. <code>mailbot</code> always adds &#8220;Arrival-Date&#8221; with the current time, as well as &#8220;Version&#8221; and &#8220;User-Agent&#8221;. </p>
<p> &#8220;&#8211;feedback-authentication-results&#8221;, &#8220;&#8211;feedback-original-rcpt-to&#8221; and &#8220;&#8211;feedback-reported-domain&#8221; may be specified more than once.</dl>
<p> -l <i>maildir</i></p>
<dl>
<dt>
<dd> Specifies the maildir for the &#8220;-T replydraft&#8221; option. See &#8220;Autoreplies from a maildir folder&#8221;, below.</dl>
<h3>Autoreplies from a maildir folder</h3>
<p> In .mailfilter: </p>
<dl>
<dt>
<dd>
<pre>
cc &quot;| mailbot -T replydraft -l './Maildir/.Vacation' \
        -d autoresponsedb \
        -A 'From: info [at] domain.com' /usr/bin/sendmail -f ''&quot;
to &quot;./Maildir&quot;
</pre>
</dl>
<p> The <code>-T replydraft</code> reply format takes the content of the autoresponse from the most recent message in a maildir. The <code>-l</code> option specifies the maildir. The above example takes the message from $HOME/Maildir/.Drafts which should be a maildir (with the usual cur, new, and tmp subdirectories). It would typically get created by Courier-IMAP as a folder named &#8220;Vacation&#8221;. </p>
<p> This makes it possible to install autoreplies via an IMAP client by creating a folder named &#8220;Vacation&#8221;, and copying a message into it. The contents of the message become the autoresponse. </p>
<p> If the named maildir does not exist, or is empty, <code>mailbot</code> does nothing. If the named maildir has more than one message, the most recent message gets used. </p>
<p> The above example uses additional <code>mailbot</code> options to suppress duplicate autoresponses, and to set the &#8220;From:&#8221; header on the autoresponse.</p>
