<h2 class="name">NAME</h2>
<p> mysql_ssl_rsa_setup &#8211; create SSL/RSA files </p>
<h2>SYNOPSIS</h2>
<dl>
<dt> <code>mysql_ssl_rsa_setup [</code><i>options</i><code>]</code></dl>
<h2>DESCRIPTION</h2>
<dd>This program creates the SSL certificate and key files and RSA key-pair files required to support secure connections using SSL and secure password exchange using RSA over unencrypted connections, if those files are missing. <code>mysql_ssl_rsa_setup</code> can also be used to create new SSL files if the existing ones have expired. </p>
<dl>
<dt>
<dd>
 <font SIZE="+1"> <code>Note</code> </font> </p>
<p> <code>mysql_ssl_rsa_setup</code> uses the <code>openssl</code> command, so its use is contingent on having OpenSSL installed on your machine. </p>
<p> Another way to generate SSL and RSA files, for MySQL distributions compiled using OpenSSL, is to have the server generate them automatically. See Section 6.3.3.1, &#8220;Creating SSL and RSA Certificates and Keys using MySQL&#8221;. </p>
</dl>
<dl>
<dt>
<dd>
 <font SIZE="+1"> <code>Important</code> </font> </p>
<p> <code>mysql_ssl_rsa_setup</code> helps lower the barrier to using SSL by making it easier to generate the required files. However, certificates generated by <code>mysql_ssl_rsa_setup</code> are self-signed, which is not very secure. After you gain experience using the files created by <code>mysql_ssl_rsa_setup</code>, consider obtaining a CA certificate from a registered certificate authority. </p>
</dl>
<p> Invoke <code>mysql_ssl_rsa_setup</code> like this: </p>
<dl>
<dt>
<dd>
<pre>
shell&gt; <code>mysql_ssl_rsa_setup [</code><i>options</i><code>]</code>
</pre>
</dl>
<p> Typical options are <code>&#8211;datadir</code> to specify where to create the files, and <code>&#8211;verbose</code> to see the <code>openssl</code> commands that <code>mysql_ssl_rsa_setup</code> executes. </p>
<p> <code>mysql_ssl_rsa_setup</code> attempts to create SSL and RSA files using a default set of file names. It works as follows: </p>
<dl>
<dt>
<dd> 1. <code>mysql_ssl_rsa_setup</code> checks for the <code>openssl</code> binary at the locations specified by the PATH environment variable. If <code>openssl</code> is not found, <code>mysql_ssl_rsa_setup</code> does nothing. If <code>openssl</code> is present, <code>mysql_ssl_rsa_setup</code> looks for default SSL and RSA files in the MySQL data directory specified by the <code>&#8211;datadir</code> option, or the compiled-in data directory if the <code>&#8211;datadir</code> option is not given.</dl>
<dl>
<dt>
<dd> 2. <code>mysql_ssl_rsa_setup</code> checks the data directory for SSL files with the following names: </p>
<dl>
<dt>
<dd>
<pre>
ca.pem
server-cert.pem
server-key.pem
</pre>
</dl>
</dl>
<dl>
<dt>
<dd> 3. If any of those files are present, <code>mysql_ssl_rsa_setup</code> creates no SSL files. Otherwise, it invokes <code>openssl</code> to create them, plus some additional files: </p>
<dl>
<dt>
<dd>
<pre>
ca.pem               Self-signed CA certificate
ca-key.pem           CA private key
server-cert.pem      Server certificate
server-key.pem       Server private key
client-cert.pem      Client certificate
client-key.pem       Client private key
</pre>
</dl>
<p> These files enable secure client connections using SSL; see Section 6.3.1, &#8220;Configuring MySQL to Use Encrypted Connections&#8221;.</dl>
<dl>
<dt>
<dd> 4. <code>mysql_ssl_rsa_setup</code> checks the data directory for RSA files with the following names: </p>
<dl>
<dt>
<dd>
<pre>
private_key.pem      Private member of private/public key pair
public_key.pem       Public member of private/public key pair
</pre>
</dl>
</dl>
<dl>
<dt>
<dd> 5. If any of these files are present, <code>mysql_ssl_rsa_setup</code> creates no RSA files. Otherwise, it invokes <code>openssl</code> to create them. These files enable secure password exchange using RSA over unencrypted connections for accounts authenticated by the sha256_password or caching_sha2_password plugin; see Section 6.4.1.3, &#8220;SHA-256 Pluggable Authentication&#8221;, and Section 6.4.1.2, &#8220;Caching SHA-2 Pluggable Authentication&#8221;.</dl>
<p> For information about the characteristics of files created by <code>mysql_ssl_rsa_setup</code>, see Section 6.3.3.1, &#8220;Creating SSL and RSA Certificates and Keys using MySQL&#8221;. </p>
<p> At startup, the MySQL server automatically uses the SSL files created by <code>mysql_ssl_rsa_setup</code> to enable SSL if no explicit SSL options are given other than <code>&#8211;ssl</code> (possibly along with <code>&#8211;ssl-cipher</code>). If you prefer to designate the files explicitly, invoke clients with the <code>&#8211;ssl-ca</code>, <code>&#8211;ssl-cert</code>, and <code>&#8211;ssl-key</code> options at startup to name the ca.pem, server-cert.pem, and server-key.pem files, respectively. </p>
<p> The server also automatically uses the RSA files created by <code>mysql_ssl_rsa_setup</code> to enable RSA if no explicit RSA options are given. </p>
<p> If the server is SSL-enabled, clients use SSL by default for the connection. To specify certificate and key files explicitly, use the <code>&#8211;ssl-ca</code>, <code>&#8211;ssl-cert</code>, and <code>&#8211;ssl-key</code> options to name the ca.pem, client-cert.pem, and client-key.pem files, respectively. However, some additional client setup may be required first because <code>mysql_ssl_rsa_setup</code> by default creates those files in the data directory. The permissions for the data directory normally enable access only to the system account that runs the MySQL server, so client programs cannot use files located there. To make the files available, copy them to a directory that is readable (but <i>not</i> writable) by clients: </p>
<dl>
<dt>
<dd> &bull; For local clients, the MySQL installation directory can be used. For example, if the data directory is a subdirectory of the installation directory and your current location is the data directory, you can copy the files like this: </p>
<dl>
<dt>
<dd>
<pre>
cp ca.pem client-cert.pem client-key.pem ..
</pre>
</dl>
</dl>
<dl>
<dt>
<dd> &bull; For remote clients, distribute the files using a secure channel to ensure they are not tampered with during transit.</dl>
<p> If the SSL files used for a MySQL installation have expired, you can use <code>mysql_ssl_rsa_setup</code> to create new ones: </p>
<dl>
<dt>
<dd> 1. Stop the server.</dl>
<dl>
<dt>
<dd> 2. Rename or remove the existing SSL files. You may wish to make a backup of them first. (The RSA files do not expire, so you need not remove them. <code>mysql_ssl_rsa_setup</code> will see that they exist and not overwrite them.)</dl>
<dl>
<dt>
<dd> 3. Run <code>mysql_ssl_rsa_setup</code> with the <code>&#8211;datadir</code> option to specify where to create the new files.</dl>
<dl>
<dt>
<dd> 4. Restart the server.</dl>
<p> <code>mysql_ssl_rsa_setup</code> supports the following command-line options, which can be specified on the command line or in the [mysql_ssl_rsa_setup] and [mysqld] groups of an option file. For information about option files used by MySQL programs, see Section 4.2.2.2, &#8220;Using Option Files&#8221;. </p>
<dl>
<dt>
<dd> &bull; <code>&#8211;help</code>, <code>?</code> </p>
<p> Display a help message and exit.</dl>
<dl>
<dt>
<dd> &bull; <code>&#8211;datadir=</code><i>dir_name</i> </p>
<p> The path to the directory that <code>mysql_ssl_rsa_setup</code> should check for default SSL and RSA files and in which it should create files if they are missing. The default is the compiled-in data directory.</dl>
<dl>
<dt>
<dd> &bull; <code>&#8211;suffix=</code><i>str</i> </p>
<p> The suffix for the Common Name attribute in X.509 certificates. The suffix value is limited to 17 characters. The default is based on the MySQL version number.</dl>
<dl>
<dt>
<dd> &bull; <code>&#8211;uid=name</code>, <code>-v</code> </p>
<p> The name of the user who should be the owner of any created files. The value is a user name, not a numeric user ID. In the absence of this option, files created by <code>mysql_ssl_rsa_setup</code> are owned by the user who executes it. This option is valid only if you execute the program as root on a system that supports the chown() system call.</dl>
<dl>
<dt>
<dd> &bull; <code>&#8211;verbose</code>, <code>-v</code> </p>
<p> Verbose mode. Produce more output about what the program does. For example, the program shows the <code>openssl</code> commands it runs, and produces output to indicate whether it skips SSL or RSA file creation because some default file already exists.</dl>
<dl>
<dt>
<dd> &bull; <code>&#8211;version</code>, <code>-V</code> </p>
<p> Display version information and exit.</dl>
