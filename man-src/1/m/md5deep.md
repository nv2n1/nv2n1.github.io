<h2 class="name">NAME</h2>
<p> md5deep &#8211; Compute and compare MD5 message digests<br />
 sha1deep &#8211; Compute and compare SHA-1 message digests<br />
 sha256deep &#8211; Compute and compare SHA-256 message digests<br />
 sha3deep &#8211; Compute and compare SHA-3-256 message digests<br />
 tigerdeep &#8211; Compute and compare Tiger message digests<br />
 whirlpooldeep &#8211; Compute and compare Whirlpool message digests</p>
<h2>SYNOPSIS</h2>
<p> <code>md5deep </code> -v | -V | -h<br />
 <code>md5deep</code> [-m|-M|-x|-X &lt;file&gt;] [-a|-A &lt;hash&gt;] [-f &lt;file&gt;] [-p &lt;size&gt;] [-i &lt;size&gt;] [-tnwzresS0lbkqZud] [-F &lt;bum&gt;] [-o &lt;fbcplsde&gt;] [-j &lt;num&gt;] [[<code>FILES</code>] </p>
<h2>DESCRIPTION</h2>
<p> Computes the hashes, or message digest, for any number of files while optionally recursively digging through the directory structure. Can also take a list of known hashes and display the filenames of input files whose hashes either do or do not match any of the known hashes. Errors are reported to standard error. If no FILES are specified, reads from standard input. </p>
<dl>
<dt><code>-p &lt;size&gt; </code></p>
<dd> Piecewise mode. Breaks files into chunks before hashing. Chunks may be specified using IEC multipliers b, k, m, g, t, p, or e. (Never let it be said that the author didn&#8217;t plan ahead!) This mode cannot be used with the -z mode. </p>
<dt><code>-i|-I &lt;size&gt; </code></p>
<dd> Size threshold mode. Only hash files smaller than the given the threshold. In -i mode, simply omits those files larger than the threshold. In -I mode, displays all files, but uses asterisks for the hashes of files larger than the threshold. Sizes may be specified using IEC multipliers b, k, m, g, t, p, or e. </p>
<dt><code>-r</code></p>
<dd> Enables recursive mode. All subdirectories are traversed. Please note that recursive mode cannot be used to examine all files of a given file extension. For example, calling md5deep -r *.txt will examine all files in <i>directories</i> that end in .txt. </p>
<dt><code>-e</code></p>
<dd> Displays a progress indicator and estimate of time remaining for each file being processed. Time estimates for files larger than 4GB are not available on Windows. This mode may not be used with th -p mode. </p>
<dt><code>-m</code> &lt;file&gt;</p>
<dd> Enables matching mode. The file given should be a list of known hashes. The input files are examined one at a time, and only those files that match the list of known hashes are output. This flag may be used more than once to add multiple sets of known hashes. Acceptable formats for lists of known hashes are plain (such as those generated by md5deep or md5sum), Hashkeeper files, iLook, and the National Software Reference Library (NSRL) as produced by the National Institute for Standards in Technology.<br />
 If standard input is used with the -m flag, displays &quot;stdin&quot; if the input matches one of the hashes in the list of known hashes. If the hash does not match, the program displays no output.<br />
 This flag may not be used in conjunction with the -x, -X, or -A flags. See the section &quot;UNICODE SUPPORT&quot; below. </p>
<dt><code>-x</code> &lt;file&gt;</p>
<dd> Same as the -m flag above, but does negative matching. That is, only those files NOT in the list of known hashes are displayed.<br />
 This flag may not be used in conjunction with the -m, -M, or -a flags. See the section &quot;UNICODE SUPPORT&quot; below.</p>
<dt><code>-M</code> and <code>-X</code> &lt;file&gt;</p>
<dd> Same as -m and -x above, but displays the hash for each file that does (or does not) match the list of known hashes. </p>
<dt><code>-a</code> &lt;hash&gt;</p>
<dd> Adds a single hash to the list of known hashes used for matching mode, and if not already enabled, enables matching mode. Adding single hashes cannot, by itself, be used to print the hashes of matching files like the -M flag does. When used in conjunction with the -w flag, the filename displayed is just the hash submitted on the command line.<br />
 This flag may not be used in conjunction with the -x, -X, or -A flags. </p>
<dt><code>-A</code> &lt;hash&gt;</p>
<dd> Same as -a above, but does negative matching. This flag may not be used in conjunction with the -m, -M, or -A flags. </p>
<dt><code>-f</code> &lt;file&gt;</p>
<dd> Takes a list of files to be hashed from the specified file. Each line is assumed to be a filename. This flag can only be used once per invocation. If it&#8217;s used a second time, the second instance will clobber the first.<br />
 Note that you can still use other flags, such as the -m or -x modes, and submit additional FILES on the command line. </p>
<dt><code>-w</code></p>
<dd> During any of the matching modes (-m,-M,-x,or -X), displays the filename of the known hash that matched the input file. See the section &quot;UNICODE SUPPORT&quot; below. </p>
<dt><code>-t</code></p>
<dd> Display a timestamp in GMT with each result. On Windows this timestamp will be the file&#8217;s creation time. On all other systems it should be the file&#8217;s change time. </p>
<dt><code>-n</code></p>
<dd> During any of the matching modes (-m,-M,-x,or -X), displays only the filenames of any known hashes that were not matched by any of the input files. </p>
<dt><code>-s</code></p>
<dd> Enables silent mode. All error messages are supressed. </p>
<dt><code>-S</code></p>
<dd> Like silent mode, but still displays warnings on improperly formatted hashes in the list of known hashes. </p>
<dt><code>-z</code></p>
<dd> Enables file size mode. Prepends the hash with a ten digit representation of the size of each file processed. If the file size is greater than 9999999999 bytes (about 9.3GB) the program displays 9999999999 for the size. </p>
<dt><code>-q</code></p>
<dd> Quiet mode. File names are omitted from the output. Each hash is still followed by two spaces before the newline. </p>
<dt><code>-Z</code></p>
<dd> Produces output in Triage format. Each line contans the file&#8217;s size, a tab, a hash of the first 512 bytes, a tab, the hash of the complete file, a tab, and the file name. These values are intended in increasing order of specificity. That is, two files with different sizes cannot possibly match. This is a fast comparison and should be done first. Next, two files with different partial hashes cannot possibly match. This is often faster than hashing the whole file. Finally, if those two pieces align, then it&#8217;s worth reading and hashing the entire file. </p>
<dt><code>-0</code></p>
<dd> Uses a NULL character (/0) to terminate each line instead of a newline. Useful for processing filenames with strange characters. </p>
<dt><code>-l</code></p>
<dd> Enables relative file paths. Instead of printing the absolute path for each file, displays the relative file path as indicated on the command line. This flag may not be used in conjunction with the -b flag. </p>
<dt><code>-b</code></p>
<dd> Enables bare mode. Strips any leading directory information from displayed filenames. This flag may not be used in conjunction with the -l flag. </p>
<dt><code>-k</code></p>
<dd> Enables asterisk mode. An asterisk is inserted in lieu of a second space between the filename and the hash, just like md5sum in its binary (-b) mode. </p>
<dt><code>-c</code></p>
<dd> Enables comma separated values output, or CSV mode. This mode has the side effect of removing the 10 digit size limitation from -z mode. Also note that asterisks from -k mode are not displayed when in CSV mode. </p>
<dt><code>-o</code> &lt;bcpflsd&gt;</p>
<dd> Enables expert mode. Allows the user specify which (and only which) types of files are processed. Directory processing is still controlled with the -r flag. The expert mode options allowed are:<br />
 f &#8211; Regular files<br />
 b &#8211; Block Devices<br />
 c &#8211; Character Devices<br />
 p &#8211; Named Pipes<br />
 l &#8211; Symbolic Links<br />
 s &#8211; Sockets<br />
 d &#8211; Solaris Doors<br />
 e &#8211; Windows PE executables </p>
<dt><code>-jnn</code></p>
<dd> Controls multi-threading. By default the program will create one producer thread to scan the file system and one hashing thread per CPU core. Multi-threading causes output filenames to be in non-deterministic order, as files that take longer to hash will be delayed while they are hashed. If a deterministic order is required, specify <code>-j0</code> to disable multi-threading </p>
<dt><code>-d</code></p>
<dd> Output in Digital Forensics XML (DFXML) format. </p>
<dt><code>-u</code></p>
<dd> Quote Unicode output. For example, the snowman is shown as <code>U+C426</code>. </p>
<dt><code>-F&lt;bum&gt;</code></p>
<dd> Specifies the input mode that is used to read files. The default is <code>-Fb</code> (buffered I/O) which reads files with fopen(). Specifying <code>-Fu</code> will use unbuffered I/O and read the file with open(). Specifying <code>-Fm</code> will use memory-mapped I/O which will be faster on some platforms, but which (currently) will not work with files that produce I/O errors. </p>
<dt><code>-h</code></p>
<dd> Show a help screen and exit. </p>
<dt><code>-v</code></p>
<dd> Show the version number and exit. </p>
<dt><code>-V</code></p>
<dd> Show copyright information and exit. </p>
</dl>
<h2>UNICODE SUPPORT</h2>
<p> As of version 3.0 the program supports Unicode characters in filenames on Microsoft Windows systems for filenames specified on the command line with globbing (e.g. *), for files specified with the <code>-f</code> of files to hash, and for files read from directories using the <code>-r</code> option. </p>
<p> By default all program input and output should be in UTF-8. The program automatically converts this to UTF-16 for opening files). </p>
<p> On Unix/Linux/MacOS, you should use a terminal emulator that supports UTF-8 and UTF-8 characters in filenames will be properly displayed. </p>
<p> On Windows, the programs do not display Unicode characters on the console. You must either redirect output to a file and open the file with Wordpad (which can display Unicode), or you must specify the <code>-u</code> option to quote Unicode using standard <code>U+XXXX</code> notation. </p>
<p> Currently the file name of a file containing known hashes may not be specified as a unicode filename, but you can specify the name using tab completition or an asterisk (e.g. md5deep -m *.txt where there is only one file with a .txt extension). </p>
<h2>RETURN VALUE</h2>
<p> Returns a bit-wise value based on the success of the operation and the status of any matching operations. </p>
<dl>
<dt>0</p>
<dd> Success. Note that the program considers itself successful even when it encounters read errors, permission denied errors, or finds directories when not in recursive mode.</p>
<dt>1</p>
<dd> Unused hashes. Under any of the matching modes, returns this value if one or more of the known hashes was not matched by any of the input files.</p>
<dt>2</p>
<dd> Unmatched inputs. Under any of the matching modes, returns this value if one or more of the input values did not match any of the known hashes.</p>
<dt>64</p>
<dd> User error, such as trying to do both positive and negative matching at the same time.</p>
<dt>128</p>
<dd> Internal error, such as memory corruption or uncaught cycle. All internal errors should be reported to the developer! See the section &quot;Reporting Bugs&quot; below. </p>
</dl>

<h2>KNOWN ISSUES</h2>
<p> Using the -r flag cannot be used to recursively process all files of a given extension in a directory. This is a feature, not a bug. If you need to do this, use the <code><a href="/docs/linux/man/1-find/">find</a></code>(1) command. </p>
