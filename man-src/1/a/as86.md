<h2 class="name">NAME</h2>
<p> as86 &#8211; Assembler for 8086..80386 processors </p>
<h2>SYNOPSIS</h2>
<p> <code>as86</code> [<code>-0123agjuw</code>] [<code>-lm</code>[<code>list</code>]] [<code>-n name</code>] [<code>-o obj</code>] [<code>-b</code>[<code>bin</code>]] [<code>-s sym</code>] [<code>-t textseg</code>] <code>src</code> </p>
<p> <code>as86_encap prog.s prog.v</code> [<code>prefix_</code>] [<code>as86_options</code>] </p>
<h2>DESCRIPTION</h2>
<p> <code>as86</code> is an assembler for the 8086..80386 processors, it&#8217;s syntax is closer to the intel/microsoft form rather than the more normal generic form of the unix system assembler. </p>
<p> The <code>src</code> file can be &#8216;-&#8216; to assemble the standard input. </p>
<p> This assembler can be compiled to support the 6809 cpu and may even work. </p>
<p> <code>as86_encap</code> is a shell script to call as86 and convert the created binary into a C file <code>prog.v</code> to be included in or linked with programs like boot block installers. The <code>prefix_</code> argument is a prefix to be added to all variables defined by the source, it defaults to the name of the source file. The variables defined include <code>prefix_start</code> <code>prefix_size</code> and <code>prefix_data</code> to define and contain the code, plus integers containing the values of all exported labels. Either or both the <code>prog.s</code> and <code>prog.v</code> arguments can be &#8216;-&#8216; for standard in/out. </p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-0</code></p>
<dd> start with 16-bit code segment, warn for all instructions &gt; 8086</p>
<dt><code>-1</code></p>
<dd> start with 16-bit code segment, warn for all instructions &gt; 80186</p>
<dt><code>-2</code></p>
<dd> start with 16-bit code segment, warn for all instructions &gt; 80286</p>
<dt><code>-3</code></p>
<dd> start with 32-bit code segment, don&#8217;t warn for any instructions. (not even 486 or 586)</p>
<dt><code>-a</code></p>
<dd> enable partial compatibility with Minix asld. This swaps the interpretation of round brackets and square brackets as well as making alterations to the code generation and syntax for 16bit jumps and calls. (&quot;jmp @(bx)&quot; is then a valid instruction)</p>
<dt><code>-g</code></p>
<dd> only put global symbols in object or symbol file</p>
<dt><code>-j</code></p>
<dd> replace all short jumps with similar 16 or 32 bit jumps, the 16 bit conditional branches are encoded as a short conditional and a long unconditional branch.</p>
<dt><code>-O </code></p>
<dd> this causes the assembler to add extra passes to try to use forward references to reduce the bytes needed for some instructions. If the labels move on the last pass the assembler will keep adding passes until the labels all stabilise (to a maximum of 30 passes) It&#8217;s probably not a good idea to use this with hand written assembler use the explicit <code>br bmi bcc</code> style opcodes for 8086 code or the <code>jmp near</code> style for conditional i386 instructions and make sure all variables are defined before they are used.</p>
<dt><code>-l</code></p>
<dd> produce list file, filename may follow</p>
<dt><code>-m</code></p>
<dd> print macro expansions in listing</p>
<dt><code>-n</code></p>
<dd> name of module follows (goes in object instead of source name)</p>
<dt><code>-o</code></p>
<dd> produce object file, filename follows</p>
<dt><code>-b</code></p>
<dd> produce a raw binary file, filename may follow. This is a &#8216;raw&#8217; binary file with no header, if there&#8217;s no <code>-s</code> option the file starts at location 0.</p>
<dt><code>-s</code></p>
<dd> produce an ASCII symbol file, filename follows. The format of this table is designed to be easy to parse for encapsulation and related activities in relation to binary files created with the <code>-b</code> option. If a binary file doesn&#8217;t start at location zero the first two items in the table are the start and end addresses of the binary file.</p>
<dt><code>-u</code></p>
<dd> assume undefined symbols are imported-with-unspecified segment.</p>
<dt><code>-w-</code></p>
<dd> allow the assembler to print warning messages.</p>
<dt><code>-t n</code></p>
<dd> move all text segment data in segment n+3.</dl>
<h2>AS86 SOURCE</h2>
<p> Special characters</p>
<dl>
<dt><code>*</code></p>
<dd> Address of the start of the current line.</p>
<dt><code>; !</code></p>
<dd> Either of these marks the start of a comment. In addition any &#8216;unexpected&#8217; character at the start of a line is assumed to be a comment (but it&#8217;s also displayed to the terminal).</p>
<dt><code>$</code></p>
<dd> Prefix for hexadecimal numbers, the &#8216;C&#8217; syntax, eg 0x1234, is also accepted.</p>
<dt><code>%</code></p>
<dd> Prefix for binary numbers.</p>
<dt><code>#</code></p>
<dd> Prefix for immediate operands.</p>
<dt><code>[ ]</code></p>
<dd> Specifies an indirect operand.<br />
 Unlike MASM the assembler has no type information on labels just a segment and offset. This means that the way this operator and the immediate prefix work are like traditional assemblers. </p>
<p> Examples:<br />
 <tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>mov ax,bx</p>
<p> <tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>jmp bx</p>
<p> Direct register addressing, the jump copies BX into PC. </p>
<pre><code>
mov ax, [bx] jmp[bx]
</code></pre>
<p> Simple indirect register addressing, the jump moves the contents of the location specified by BX into the PC. </p>
<p> <tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>mov ax,#1234</p>
<p> Immediate value, ax becomes 1234. </p>
<pre>
        mov ax,1234
        mov ax,_hello
        mov ax,[_hello]
</pre>
<p> Absolute addressing, ax is set to contents of location 1234. Note the third option is not strictly consistant but is in place mainly for asld compatibility. </p>
<pre><code>
mov ax, _table[bx] mov ax, _table[bx + si] mov eax, _table[ebx * 4] mov ax, [bx + _table] mov ax, [bx + si + _table] mov eax, [ebx * 4 + _table]
</code></pre>
<p> Indexed addressing, both formats are ok, I think the first is more correct but I tend to used the second. :-)
</dl>
<p> Conditionals</p>
<dl>
<dt><code>IF, ELSE, ELSEIF, ENDIF</code></p>
<dd> Numeric condition</p>
<dt><code>IFC, ELSEIFC</code></p>
<dd> String compare (str1,str2)</p>
<dt><code>FAIL .FAIL</code></p>
<dd> Generate user error.</dl>
<p> Segment related</p>
<dl>
<dt><code>.TEXT .ROM .DATA .BSS</code></p>
<dd> Set current segment. These can be preceded by the keyword <code>.SECT</code></p>
<dt><code>LOC</code></p>
<dd> Set numeric segment 0=TEXT, 3=DATA,ROM,BSS, 14=MAX. The segment order set by the linker is now 0,4,5,6,7,8,9,A,B,C,D,E,1,2,3. Segment 0 and all segments above 3 are assumed to be text segment. Note the 64k size restrictions are not imposed for segments 3-14.</dl>
<p> Label type definition</p>
<dl>
<dt><code>EXPORT PUBLIC .DEFINE</code></p>
<dd> Export label defined in this object</p>
<dt><code>ENTRY</code></p>
<dd> Force linker to include the specified label in a.out</p>
<dt><code>.GLOBL .GLOBAL</code></p>
<dd> Define label as external and force import even if it isn&#8217;t used.</p>
<dt><code>EXTRN EXTERN IMPORT .EXTERN</code></p>
<dd> Import list of externally defined labels<br />
 NB: It doesn&#8217;t make sense to use imports for raw binary files.</p>
<dt><code>.ENTER</code></p>
<dd> Mark entry for old binary file (obs)</dl>
<p> Data definition</p>
<dl>
<dt><code>DB .DATA1 .BYTE FCB</code></p>
<dd> List of 1 byte objects.</p>
<dt><code>DW .DATA2 .SHORT FDB .WORD</code></p>
<dd> List of 2 byte objects.</p>
<dt><code>DD .DATA4 .LONG</code></p>
<dd> List of 4 byte objects.</p>
<dt><code>.ASCII FCC</code></p>
<dd> Ascii string copied to output.</p>
<dt><code>.ASCIZ</code></p>
<dd> Ascii string copied to output with trailing <code>nul</code> byte.</dl>
<p> Space definition</p>
<dl>
<dt><code>.BLKB RMB .SPACE</code></p>
<dd> Space is counted in bytes.</p>
<dt><code>.BLKW .ZEROW</code></p>
<dd> Space is counted in words. (2 bytes each)</p>
<dt><code>COMM .COMM LCOMM .LCOMM</code></p>
<dd> Common area data definition</dl>
<p> Other useful pseudo operations.</p>
<dl>
<dt><code>.ALIGN .EVEN</code></p>
<dd> Alignment</p>
<dt><code>EQU</code></p>
<dd> Define label</p>
<dt><code>SET</code></p>
<dd> Define re-definable label</p>
<dt><code>ORG .ORG</code></p>
<dd> Set assemble location</p>
<dt><code>BLOCK</code></p>
<dd> Set assemble location and stack old one</p>
<dt><code>ENDB</code></p>
<dd> Return to stacked assemble location</p>
<dt><code>GET INCLUDE</code></p>
<dd> Insert new file (no quotes on name)</p>
<dt><code>USE16&nbsp;<wbr></code>[<code>cpu</code>]</p>
<dd> Define default operand size as 16 bit, argument is cpu type the code is expected to run on (86, 186, 286, 386, 486, 586) instructions for cpus later than specified give a warning.</p>
<dt><code>USE32&nbsp;<wbr></code>[<code>cpu</code>]</p>
<dd> Define default operand size as 32 bit, argument is cpu type the code is expected to run on (86, 186, 286, 386, 486, 586) instructions for cpus later than specified give a warning. If the cpu is not mentioned the assembler ensures it is &gt;= 80386.</p>
<dt><code>END</code></p>
<dd> End of compilation for this file.</p>
<dt><code>.WARN</code></p>
<dd> Switch warnings</p>
<dt><code>.LIST</code></p>
<dd> Listings on/off (1,-1)</p>
<dt><code>.MACLIST</code></p>
<dd> Macro listings on/off (1,-1)</dl>
<p> Macros, now working, the general form is like this. </p>
<p>&nbsp;<wbr>MACRO sax<br />
&nbsp;<wbr>mov ax,#?1<br />
&nbsp;<wbr>MEND<br />
&nbsp;<wbr><a href="/docs/linux/man/1-sax/">sax</a>(1) </p>
<dl>
<dt>Unimplemented/unused.</p>
<dd>
<dt>IDENT</p>
<dd> Define object identity string.</p>
<dt>SETDP</p>
<dd> Set DP value on 6809</p>
<dt>MAP</p>
<dd> Set binary symbol table map number.</p>
<dt>Registers</p>
<dd>

<dt>Operand type specifiers</p>
<dd> BYTE DWORD FWORD FAR PTR PWORD QWORD TBYTE WORD NEAR </p>
<p> The &#8216;near and &#8216;far&#8217; do not allow multi-segment programming, all &#8216;far&#8217; operations are specified explicitly through the use of the instructions: jmpi, jmpf, callf, retf, etc. The &#8216;Near&#8217; operator can be used to force the use of 80386 16bit conditional branches. The &#8216;Dword&#8217; and &#8216;word&#8217; operators can control the size of operands on far jumps and calls.</p>
<dt>General instructions.</p>
<dd> These are in general the same as the instructions found in any 8086 assembler, the main exceptions being a few &#8216;Bcc&#8217; (BCC, BNE, BGE, etc) instructions which are shorthands for a short branch plus a long jump and &#8216;BR&#8217; which is the longest unconditional jump (16 or 32 bit).</p>

<h2>Using GASP</h2>
<p> The Gnu assembler preprocessor provides some reasonable implementations of user biased pseudo opcodes. </p>
<p> It can be invoked in a form similar to:</p>
<dl>
<dt><code>gasp</code></p>
<dd> [<code>-a&#8230;</code>] <code>file.s</code> [<code>file2.s</code>] <code>|</code><br />
 <code>as86</code> [<code>&#8230;</code>] <code>&#8211;</code> [<code>-o obj</code>]&nbsp;<wbr>[<code>-b bin</code>]</dl>
<p> Be aware though that Gasp generates an error for <code>.org</code> commands, if you&#8217;re not using alternate syntax you can use <code>org</code> instead, otherwise use <code>block</code> and <code>endb</code>. The directive <code>export</code> is translated into <code>.global</code>, which forces an import, if you are making a file using <code>-b</code> use <code>public</code> or <code>.define</code> instead. </p>
<p> The GASP list options have no support in as86.</p>

<h2>BUGS</h2>
<p> The 6809 version does not support -0, -3, -a or -j. </p>
<p> If this assembler is compiled with BCC this is classed as a &#8216;small&#8217; compiler, so there is a maximum input line length of 256 characters and the instruction to cpu checking is not included. </p>
<p> The checking for instructions that work on specific cpus is probably not complete, the distinction between 80186 and 80286 is especially problematic. </p>
<p> The <code>.text</code> and <code>.data</code> pseudo operators are not useful for raw binary files. </p>
<p> When using the <code>org</code> directive the assembler can generate object files that may break <a href="/docs/linux/man/1-ld86/">ld86</a>(1). </p>
