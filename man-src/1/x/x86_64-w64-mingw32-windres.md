<h2 class="name">NAME</h2>
<p> windres &#8211; manipulate Windows resources. </p>
<h2>SYNOPSIS</h2>
<p> windres [options] [input-file] [output-file]</p>
<h2>DESCRIPTION</h2>
<p> <code>windres</code> reads resources from an input file and copies them into an output file. Either file may be in one of three formats:</p>
<dl>
<dt>&quot;rc&quot;</p>
<dd> A text format read by the Resource Compiler.</p>
<dt>&quot;res&quot;</p>
<dd> A binary format generated by the Resource Compiler.</p>
<dt>&quot;coff&quot;</p>
<dd> A <font SIZE="-1">COFF</font> object or executable.</dl>
<p> The exact description of these different formats is available in documentation from Microsoft. </p>
<p> When <code>windres</code> converts from the <tt>&quot;rc&quot;</tt> format to the <tt>&quot;res&quot;</tt> format, it is acting like the Windows Resource Compiler. When <code>windres</code> converts from the <tt>&quot;res&quot;</tt> format to the <tt>&quot;coff&quot;</tt> format, it is acting like the Windows <tt>&quot;CVTRES&quot;</tt> program. </p>
<p> When <code>windres</code> generates an <tt>&quot;rc&quot;</tt> file, the output is similar but not identical to the format expected for the input. When an input <tt>&quot;rc&quot;</tt> file refers to an external filename, an output <tt>&quot;rc&quot;</tt> file will instead include the file contents. </p>
<p> If the input or output format is not specified, <code>windres</code> will guess based on the file name, or, for the input file, the file contents. A file with an extension of <i>.rc</i> will be treated as an <tt>&quot;rc&quot;</tt> file, a file with an extension of <i>.res</i> will be treated as a <tt>&quot;res&quot;</tt> file, and a file with an extension of <i>.o</i> or <i>.exe</i> will be treated as a <tt>&quot;coff&quot;</tt> file. </p>
<p> If no output file is specified, <code>windres</code> will print the resources in <tt>&quot;rc&quot;</tt> format to standard output. </p>
<p> The normal use is for you to write an <tt>&quot;rc&quot;</tt> file, use <code>windres</code> to convert it to a <font SIZE="-1">COFF</font> object file, and then link the <font SIZE="-1">COFF</font> file into your application. This will make the resources described in the <tt>&quot;rc&quot;</tt> file available to Windows.</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-i</code> <i>filename</i></p>
<dd>
<dt><code>&#8211;input</code> <i>filename</i></p>
<dd> The name of the input file. If this option is not used, then <code>windres</code> will use the first non-option argument as the input file name. If there are no non-option arguments, then <code>windres</code> will read from standard input. <code>windres</code> can not read a <font SIZE="-1">COFF</font> file from standard input.</p>
<dt><code>-o</code> <i>filename</i></p>
<dd>
<dt><code>&#8211;output</code> <i>filename</i></p>
<dd> The name of the output file. If this option is not used, then <code>windres</code> will use the first non-option argument, after any used for the input file name, as the output file name. If there is no non-option argument, then <code>windres</code> will write to standard output. <code>windres</code> can not write a <font SIZE="-1">COFF</font> file to standard output. Note, for compatibility with <code>rc</code> the option <code>-fo</code> is also accepted, but its use is not recommended.</p>
<dt><code>-J</code> <i>format</i></p>
<dd>
<dt><code>&#8211;input-format</code> <i>format</i></p>
<dd> The input format to read. <i>format</i> may be <code>res</code>, <code>rc</code>, or <code>coff</code>. If no input format is specified, <code>windres</code> will guess, as described above.</p>
<dt><code>-O</code> <i>format</i></p>
<dd>
<dt><code>&#8211;output-format</code> <i>format</i></p>
<dd> The output format to generate. <i>format</i> may be <code>res</code>, <code>rc</code>, or <code>coff</code>. If no output format is specified, <code>windres</code> will guess, as described above.</p>
<dt><code>-F</code> <i>target</i></p>
<dd>
<dt><code>&#8211;target</code> <i>target</i></p>
<dd> Specify the <font SIZE="-1">BFD</font> format to use for a <font SIZE="-1">COFF</font> file as input or output. This is a <font SIZE="-1">BFD</font> target name; you can use the <code>&#8211;help</code> option to see a list of supported targets. Normally <code>windres</code> will use the default format, which is the first one listed by the <code>&#8211;help</code> option.</p>
<dt><code>&#8211;preprocessor</code> <i>program</i></p>
<dd> When <code>windres</code> reads an <tt>&quot;rc&quot;</tt> file, it runs it through the C preprocessor first. This option may be used to specify the preprocessor to use, including any leading arguments. The default preprocessor argument is <tt>&quot;gcc -E -xc-header -DRC_INVOKED&quot;</tt>.</p>
<dt><code>&#8211;preprocessor-arg</code> <i>option</i></p>
<dd> When <code>windres</code> reads an <tt>&quot;rc&quot;</tt> file, it runs it through the C preprocessor first. This option may be used to specify additional text to be passed to preprocessor on its command line. This option can be used multiple times to add multiple options to the preprocessor command line.</p>
<dt><code>-I</code> <i>directory</i></p>
<dd>
<dt><code>&#8211;include-dir</code> <i>directory</i></p>
<dd> Specify an include directory to use when reading an <tt>&quot;rc&quot;</tt> file. <code>windres</code> will pass this to the preprocessor as an <code>-I</code> option. <code>windres</code> will also search this directory when looking for files named in the <tt>&quot;rc&quot;</tt> file. If the argument passed to this command matches any of the supported <i>formats</i> (as described in the <code>-J</code> option), it will issue a deprecation warning, and behave just like the <code>-J</code> option. New programs should not use this behaviour. If a directory happens to match a <i>format</i>, simple prefix it with <code>./</code> to disable the backward compatibility.</p>
<dt><code>-D</code> <i>target</i></p>
<dd>
<dt><code>&#8211;define</code> <i>sym</i><code>[=</code><i>val</i><code>]</code></p>
<dd> Specify a <code>-D</code> option to pass to the preprocessor when reading an <tt>&quot;rc&quot;</tt> file.</p>
<dt><code>-U</code> <i>target</i></p>
<dd>
<dt><code>&#8211;undefine</code> <i>sym</i></p>
<dd> Specify a <code>-U</code> option to pass to the preprocessor when reading an <tt>&quot;rc&quot;</tt> file.</p>
<dt><code>-r</code></p>
<dd> Ignored for compatibility with rc.</p>
<dt><code>-v</code></p>
<dd> Enable verbose mode. This tells you what the preprocessor is if you didn&#8217;t specify one.</p>
<dt><code>-c</code> <i>val</i></p>
<dd>
<dt><code>&#8211;codepage</code> <i>val</i></p>
<dd> Specify the default codepage to use when reading an <tt>&quot;rc&quot;</tt> file. <i>val</i> should be a hexadecimal prefixed by <code>0x</code> or decimal codepage code. The valid range is from zero up to 0xffff, but the validity of the codepage is host and configuration dependent.</p>
<dt><code>-l</code> <i>val</i></p>
<dd>
<dt><code>&#8211;language</code> <i>val</i></p>
<dd> Specify the default language to use when reading an <tt>&quot;rc&quot;</tt> file. <i>val</i> should be a hexadecimal language code. The low eight bits are the language, and the high eight bits are the sublanguage.</p>
<dt><code>&#8211;use-temp-file</code></p>
<dd> Use a temporary file to instead of using popen to read the output of the preprocessor. Use this option if the popen implementation is buggy on the host (eg., certain non-English language versions of Windows 95 and Windows 98 are known to have buggy popen where the output will instead go the console).</p>
<dt><code>&#8211;no-use-temp-file</code></p>
<dd> Use popen, not a temporary file, to read the output of the preprocessor. This is the default behaviour.</p>
<dt><code>-h</code></p>
<dd>
<dt><code>&#8211;help</code></p>
<dd> Prints a usage summary.</p>
<dt><code>-V</code></p>
<dd>
<dt><code>&#8211;version</code></p>
<dd> Prints the version number for <code>windres</code>.</p>
<dt><code>&#8211;yydebug</code></p>
<dd> If <code>windres</code> is compiled with <tt>&quot;YYDEBUG&quot;</tt> defined as <tt>1</tt>, this will turn on parser debugging.</p>
<dt><code>@</code><i>file</i></p>
<dd> Read command-line options from <i>file</i>. The options read are inserted in place of the original @<i>file</i> option. If <i>file</i> does not exist, or cannot be read, then the option will be treated literally, and not removed. </p>
<p> Options in <i>file</i> are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The <i>file</i> may itself contain additional @<i>file</i> options; any such options will be processed recursively.</dl>
