<h2 class="name">NAME</h2>
<p> dvipdfmx, xdvipdfmx, dvipdfm &#8211; produce PDF files directly from DVI files </p>
<h2>SYNOPSIS</h2>
<p> <code>dvipdfmx</code> or <code>dvipdfm</code> [<i>options</i>] <i>file</i>[<code>.dvi</code>]</p>
<h2>DESCRIPTION</h2>
<p> The program <code>dvipdfmx</code> generates a PDF file from a DVI file. DVI files are the output produced by TeX. <code>groff</code> can also generate DVI files using <code>grodvi</code>(-Tdvi). </p>
<p> In TeX Live, <code>dvipdfm</code> is another incarnation of <code>dvipdfmx</code> rather than a separate program. Compatibility is attempted as best as possible. </p>
<p> <code>xdvipdfmx</code> is another incarnation. It is used as the back end for <code><a href="/docs/linux/man/1-xetex/">xetex</a></code>(1) and is not intended to be invoked directly. </p>
<p> <code>dvipdfmx</code> recognizes several commonly used <code>\special</code> commands, which are extensions to the DVI format. Specifically, it understands color specials, papersize specials, tpic specials (which allow it to be used with <code>pic</code>), hypertex specials, and some PostScript specials. These extensions allow documents to contain color, figures, and hyperlinks. The program tries to mimic the behavior of <code>dvips</code> where possible, so that many macro packages produced for use with <code>dvips</code> will also work with <code>dvipdfmx</code>. In addition, <code>dvipdfmx </code> understands its own specific <code>\special</code> commands to allow access to PDF features such as annotations and bookmarks. </p>
<p> As of December 2018, one such special specific to <code>dvipdfmx</code> is <i>pdf:trailerid</i>, which specifies the /ID in the PDF trailer. It is used like this (from the TeX level):<br />
 \special{pdf:trailerid [ (0123456789abcdef) (01234567890abcdef) ]}<br />
 That is, the special takes an array (the square brackets) of two 16-byte PDF strings (the parentheses). This is the same syntax as LuaTeX&#8217;s <i>\pdfvariable trailerid</i>, while different from pdfTeX&#8217;s <i>\pdftrailerid</i>. It must appear on the first output page, otherwise it is ignored. </p>
<p> Unrecognized specials will generate warning messages. Packages that may need a <code>dvipdfm </code> or <code>dvipdfmx </code> driver option include <i>geometry</i>, <i>hyperref</i>, <i>bookmark</i>, <i>graphicx</i>, and <i>xcolor</i>. </p>
<p> For issues related to bounding boxes (and hence image sizes), see <code><a href="/docs/linux/man/1-extractbb/">extractbb</a></code>(1).</p>
<h2>OPTIONS</h2>
<p> Unlike with many other programs, argument values must be separated from option names by a space, not an = sign; option names cannot be abbreviated; and &#8211; and &#8212; cannot be used interchangeably.</p>
<dl>
<dt><code>-c</code></p>
<dd> Ignore (or accept) color <code>\specials</code>. By default, color <code>\special</code>s are interpreted normally (changeable in the configuration file). The <code>-c</code> option may be used to produce a black and white document from a document containing color TeX <code>\special</code> commands.</p>
<dt><code>&#8211;dvipdfm</code></p>
<dd> Enable <code>dvipdfm</code> emulation mode. This is the default if the executable name is `dvipdfm&#8217;.</p>
<dt><code>-d number</code></p>
<dd> Specify the number of decimal digits in the PDF output; must be between 0 and 5, default is 2.</p>
<dt><code>-e</code></p>
<dd> Ignored, for (semi-)compatibility with <code>dvipdfm</code>.</p>
<dt><code>-f map_file</code></p>
<dd> Read the font map file given by <i>map_file</i>. The default map file in TeX Live is <i>pdftex.map</i>, as defined in the configuration file.</p>
<dt><code>&#8211;help</code></p>
<dd> Show a help message and exit successfully.</p>
<dt><code>-i cfgfile</code></p>
<dd> Read <i>cfgfile</i> as another include file, after reading the default <i>dvipdfmx.cfg</i>.</p>
<dt><code>-l</code></p>
<dd> Select landscape mode. In other words, exchange the <i>x</i> and <i>y</i> dimensions of the paper.</p>
<dt><code>-m mag</code></p>
<dd> Magnify the input document by <i>mag</i>.</p>
<dt><code>-o filename</code></p>
<dd> Set the PDF output file name; use `-&#8216; for stdout. By default, the name of the output file is derived from the input, that is, <i>file</i>.pdf.</p>
<dt><code>-p paper</code></p>
<dd> Select the papersize by name (e.g., <code>letter</code>, <code>legal</code>, <code>ledger</code>, <code>tabloid</code>, <code>a3</code>, <code>a4</code>, or <code>a5</code> )</p>
<dt><code>-q</code></p>
<dd> Quiet mode.</p>
<dt><code>-r size</code></p>
<dd> Set resolution of bitmapped fonts to <code>size</code> dots per inch. Bitmapped fonts are generated by the Kpathsea library, which uses Metafont. Bitmapped fonts are included as Type 3 fonts in the PDF output file. Default is 600.</p>
<dt><code>-s page_specifications</code></p>
<dd> Select the pages of the DVI file to be processed; default is `-&#8216;, meaning all pages. The <i>page_specifications</i> consists of a comma separated list of <i>page_ranges</i>: </p>
<pre>
<i>page_specifications := page_specification</i>[,<i>page_specifications</i>]
</pre>
<p> where </p>
<pre><code>
page_specification : = single_page | page_range
                                         page_range : = [first_page] - [last_page]
</code></pre>
<p> An empty <i>first_page</i> is treated as the first page of the DVI file, and an empty <i>last_page</i> is treated as the last page of the DVI file. </p>
<p> Examples:</p>
<dl>
<dt>
<dd>
<dl>
<dt><code>-s 1,3,5</code></p>
<dd> includes pages 1, 3, and 5;</p>
<dt><code>-s &#8211;</code></p>
<dd> includes all pages;</p>
<dt><code>-s -,-</code></p>
<dd> includes two copies of all pages in the DVI file; and</p>
<dt><code>-s 1-10</code></p>
<dd> includes the first ten pages of the DVI file.</dl>
</dl>
<dt><code>-t</code></p>
<dd> Search for thumbnail images of each page in the directory named by the <code>TMPDIR</code> environment variable. The thumbnail images must be named in a specific format: the same base name as the DVI file and the page number as the extension to the file name. <code>dvipdfmx</code> does not generate such thumbnails itself, but it is distributed with a wrapper program named <code>dvipdft </code> that does so.</p>
<dt><code>&#8211;version</code></p>
<dd> Show a help message and exit successfully.</p>
<dt><code>-v </code></p>
<dd> Increase verbosity. Results of the <code>-v</code> option are cumulative (e.g., <code>-vv</code> increases the verbosity by two increments). Maximum verbosity is four.</p>
<dt><code>&#8211;kpathsea-debug number</code></p>
<dd> Have Kpathsea output debugging information; `-1&#8242; for everything (voluminous).</p>
<dt><code>-x x_offset</code></p>
<dd> Set the left margin to <i>x_offset</i>. The default left margin is <code>1.0in</code>. The dimension may be specified in any units understood by TeX (e.g., <code>bp</code>, <code>pt</code>, <code>in</code>, <code>cm</code>).</p>
<dt><code>-y y_offset</code></p>
<dd> Set the top margin to <i>y_offset</i>. The default top margin is <code>1.0in</code>. The dimension may be specified in any units understood by TeX (e.g., <code>bpt</code>, <code>pt</code>, <code>in</code>, <code>cm</code>).</p>
<dt><code>-z number</code></p>
<dd> Set the compression level to <i>compression_level</i>. Compression levels range from 0 (no compression) to 9 (maximum compression) and correspond to the values understood by zlib; default is 9.</p>
<dt><code>-C number</code></p>
<dd> Miscellaneous option flags; see the &#8211;help output for details.</p>
<dt><code>-D template</code></p>
<dd> PostScript to PDF conversion command line template; the default is taken from the configuration file, which also gives all the details and mentions several possibilities.</p>
<dt><code>-E</code></p>
<dd> Always try to embed fonts, ignoring licensing flags, etc.</p>
<dt><code>-I number</code></p>
<dd> Image cache life in hours; default is -2, meaning to not cache images at all. A value of -1 means to erase all old images and also new images; 0 means to erase all old images but leave new images.</p>
<dt><code>-K number</code></p>
<dd> Encryption key length; default 40.</p>
<dt><code>-M</code></p>
<dd> Process MetaPost PostScript output.</p>
<dt><code>-O number</code></p>
<dd> Set maximum depth of open bookmark items; default 0.</p>
<dt><code>-P number</code></p>
<dd> Set permission flags for PDF encryption; default 0x003C.</p>
<dt><code>-S</code></p>
<dd> Enable PDF encryption.</p>
<dt><code>-V number</code></p>
<dd> Set PDF minor version; default 5 (from the configuration file).</dl>
<h2>IMAGE BOUNDING BOXES</h2>
<p> When including images with <code>dvipdfmx</code>, their bounding boxes should be generated by running <code>extractbb</code>. The result will be in an <code>.xbb</code> file; the xbb information is the same as for the PDF format.</p>
<h2>ENVIRONMENT</h2>
<p> <code>dvipdfmx </code> uses the <code>kpathsea</code> library for locating the files that it opens. Hence, the environment variables documented in the <i>Kpathsea library</i> documentation influence <code>dvipdfmx</code>. It also uses the value of the environment variable TMPDIR as the directory to search for thumbnail images of each page.</p>
<h2>FILES</h2>
<p> The precise location of the following files is determined by the <i>Kpathsea library</i> configuration. The location may be determined by using kpsewhich, e.g., </p>
<pre>
<code>kpsewhich -progname=dvipdfmx -format='other text files' dvipdfmx.cfg</code>
</pre>
<dl>
<dt><i>dvipdfmx.cfg</i></p>
<dd> Default configuration file</p>
<dt><i>dvipdfmx-unsafe.cfg</i></p>
<dd> Configuration file that runs Ghostscript without safety checks; use only for trusted source files. It is currently required to use PSTricks with XeTeX: <code>xetex -output-driver=xdvipdfmx -i dvipdfmx-unsafe.cfg -q -E &#8230;</code></p>
<dt><i>pdftex.map</i></p>
<dd> The default font map file (this may be changed in the config file).</p>
<dt><i>*.tfm</i></p>
<dd> TeX font metrics</p>
<dt><i>*.vf</i></p>
<dd> TeX virtual font files</p>
<dt><i>*.pfb</i></p>
<dd> PostScript Type 1 font files</p>
<dt><i>texmf.cnf</i></p>
<dd> The Kpathsea library configuration file. The location of this file may be found by typing </p>
<pre>
<code>kpsewhich texmf.cnf</code>
</pre>
</dl>
