<h2>NAME</h2>
<p> xrootdfs &#8211; xrootd FUSE file system daemon</p>
<h2>SYNOPSIS</h2>
<pre>
<code>xrootdfs</code> [<i>options</i>] <i>parameters</i>
</pre>
<h2>DESCRIPTION</h2>
<p> The <code>xrootdfs</code> daemon provides a file system view of an xrootd cluster using FUSE. Usage synopsis can be displayed by typing &quot;<code>xrootdfs -h</code>&quot;. Short documentation can be found in a README file in the src/XrdFfs source directory. </p>
<h2>EXAMPLES</h2>
<p> Assuming the redirector is <code>rdr:port</code> </p>
<p> run from command line with debugging output</p>
<dl>
<dt>
<dd> xrootdfs -d -o rdr=<a href="root://rdr:port//data,uid=daemon">root://rdr:port//data,uid=daemon</a> /mnt</dl>
<p> use in /etc/fstab</p>
<dl>
<dt>
<dd> xrootdfs /mnt fuse rdr=<a href="root://rdr:port//data,uid=daemon">root://rdr:port//data,uid=daemon</a> 1 2</dl>
<p> use with autofs</p>
<dl>
<dt>
<dd> 1. add a line to /etc/auto.master<br />
 /- /etc/auto.fuse </p>
<p> 2. create /etc/auto.fuse with the following one line<br />
 /mnt -fstype=fuse,uid=2,rdr=<a href="root://rdr\:port//data">root://rdr\:port//data</a> :xrootdfs.sh </p>
<p> 3. create script /usr/bin/xrootdfs.sh (make sure +x bit is set)<br />
 #!/bin/sh<br />
 exec /usr/bin/xrootdfs $@ &gt;/dev/null 2&gt;&amp;1 </p>
</dl>
<h2>NOTES</h2>
<p> Documentation for all components associated with <code>xrootdfs</code> can be found at <a rel="nofollow" href="http://xrootd.org/docs.html">http://xrootd.org/docs.html</a> </p>
<p> xrootdfs allows users and administators to query and change the internal parameters on the fly via the filesystem extened attributes </p>
<p> getfattr -n attribute_name /mount_point<br />
 setfattr -n attribute_name [ -v value ] /mount_point </p>
<p> attribute_name:</p>
<dl>
<dt>
<dd> <code>xroot.url:</code> query the actual ROOT url of the file (this is an old one)<br />
 <code>xrootdfs.fs.nworkers:</code> query or change the number of threads working in parallel on operations such as stat(), unlink()/rmdir(), readdir(), statvfs(), etc.<br />
 <code>xrootdfs.fs.dataserverlist: </code> query or refresh the list of all data servers known to this xrootdfs instance (or &quot;kill -USR1 pid&quot; to refresh) </p>
</dl>
<h2>SECURITY</h2>
<p> By default, XrootdFS does not send individual user identity to the Xrootd storage servers. So Xrootd storage thinks that all operations from an XrootdFS instance come from the user that runs the XrootdFS instance. When the Xrootd &quot;sss&quot; security module (Simple Shared Security) is enabled at both XrootdFS and Xrootd storage system, XrootdFS will send individual user identity infomation to the Xrootd storage servers. This info can be used along with the Xrootd ACL to control file/directory access. </p>
<p> To use &quot;sss&quot; security module, both Xrootd data servers and XrootdFS should be configured to use &quot;sss&quot; in a particular way, e.g. both sides should use a key file that contains the same key generated by the xrdsssadmin program in the following way: </p>
<p> xrdsssadmin -k my_key_name -u anybody -g usrgroup add keyfile </p>
<p> (change only &quot;my_key_name&quot; and &quot;keyfile&quot;). Please refer to environment variable &quot;XrdSecsssKT&quot; in Xrootd &quot;Authentication &amp; Access Control Configuration Reference&quot; for more information on the location of the keyfile and its unix permission bits. That same document also describes the Xrootd ACL DB file. </p>
<p> To enable &quot;sss&quot; with XrootdFS, use the sss=/keyfile option with XrootdFS. </p>
<p> The following example shows how to use both unix and sss security modules with the Xrootd data servers. </p>
<dl>
<dt>
<dd>
&nbsp;<wbr>&nbsp;<wbr>xrootd.seclib&nbsp;<wbr>/usr/lib64/libXrdSec.so </p>
<p>&nbsp;<wbr>&nbsp;<wbr>sec.protocol&nbsp;<wbr>/usr/lib64 sss -s&nbsp;<wbr>/keyfile </p>
<p>&nbsp;<wbr>&nbsp;<wbr>sec.protocol&nbsp;<wbr>/usr/lib64 unix </p>
<p>&nbsp;<wbr>&nbsp;<wbr>acc.authdb&nbsp;<wbr>/your_xrootd_ACL_auth_db_file </p>
<p>&nbsp;<wbr>&nbsp;<wbr>acc.authrefresh 300 </p>
<p>&nbsp;<wbr>&nbsp;<wbr>ofs.authorize </p>
</dl>
<h2>DIAGNOSTICS</h2>
<p> Errors yield an error message and a non-zero exit status. The program never exits upon success. Use the umount command to terminate the program. </p>
<p> Additional logging information can be found in syslog (/var/log/messages)</p>
