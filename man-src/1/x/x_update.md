<h2>NAME</h2>
<p> <code>x_update</code> &#8211; Archiving of Cross-Over Information</p>
<h2>SYNOPSIS</h2>
<p> <code>x_update</code> <i>cross-overfile</i> [ <code>-X</code><i>xbase</i> ] [ <code>-L</code><i>legbase</i> ] [ <code>-V</code> ] [ <code>-W</code><i>max</i> ]</p>
<h2>DESCRIPTION</h2>
<p> <code>x_update</code> reads the ASCII file produced by <code>x_over</code> and writes the information to the database files <i>xx_base.b</i> and <i>xx_legs.b</i> (unless other filenames are specified on the command line) using a compact, binary format. The options recognized are:</p>
<dl>
<dt><code>-X</code></p>
<dd> Indicate alternate <i>xx_base.b</i> file.</p>
<dt><code>-L</code></p>
<dd> Indicate alternate <i>xx_legs.b</i> file.</p>
<dt><code>-V</code></p>
<dd> Selects verbose mode, which will send progress reports to stderr [Default runs &quot;silently&quot;]. Reports the pair currently being processed.</p>
<dt><code>-W</code></p>
<dd> Prints a warning if the number of COEs generated by any pair of legs exceed <i>max</i>.</dl>
<h2>BEWARE</h2>
<p> For security reasons the <i>xx_legs.b</i> are first renamed to <i>xx_legs.b_old</i>, to prevent loss of information if a black-out or system crash should occur during writing of the new <i>xx_legs.b</i> file. It is recommended that the old file is left on the disk in case of other disasters. Note that <code>x_update</code> does not check if a pair of legs already exist in the <i>xx_base.b</i> file. It is the user&#8217;sresponsibility to ensure that duplication of information does not occur. Should some pairs already in the database need to be re-examined, then run <code>x_remove</code> which will wipe out all traces of the specified cruises from the x_system data base files. Now we can pass the pairs that need to be redone through <code>x_over/x_update</code> again.</p>
