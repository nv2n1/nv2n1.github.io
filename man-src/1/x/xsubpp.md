<h2 class="name">NAME</h2>
<p> xsubpp &#8211; compiler to convert Perl XS code into C code </p>
<h2>SYNOPSIS</h2>
<p> <code>xsubpp</code> [<code>-v</code>] [<code>-except</code>] [<code>-s pattern</code>] [<code>-prototypes</code>] [<code>-noversioncheck</code>] [<code>-nolinenumbers</code>] [<code>-nooptimize</code>] [<code>-typemap typemap</code>] [<code>-output filename</code>]&#8230; file.xs</p>
<h2>DESCRIPTION</h2>
<p> This compiler is typically run by the makefiles created by ExtUtils::MakeMaker or by Module::Build or other Perl module build tools. </p>
<p> <i>xsubpp</i> will compile <font SIZE="-1">XS</font> code into C code by embedding the constructs necessary to let C functions manipulate Perl values and creates the glue necessary to let Perl access those functions. The compiler uses typemaps to determine how to map C function parameters and variables to Perl values. </p>
<p> The compiler will search for typemap files called <i>typemap</i>. It will use the following search path to find default typemaps, with the rightmost typemap taking precedence. </p>
<pre>
        ../../../typemap:../../typemap:../typemap:typemap
</pre>
<p> It will also use a default typemap installed as <tt>&quot;ExtUtils::typemap&quot;</tt>.</p>
<h2>OPTIONS</h2>
<p> Note that the <tt>&quot;XSOPT&quot;</tt> MakeMaker option may be used to add these options to any makefiles generated by MakeMaker.</p>
<dl>
<dt><code>-hiertype</code></p>
<dd> Retains &#8216;::&#8217; in type names so that C<font SIZE="-2">++</font> hierarchical types can be mapped.</p>
<dt><code>-except</code></p>
<dd> Adds exception handling stubs to the C code.</p>
<dt><code>-typemap typemap</code></p>
<dd> Indicates that a user-supplied typemap should take precedence over the default typemaps. This option may be used multiple times, with the last typemap having the highest precedence.</p>
<dt><code>-output filename</code></p>
<dd> Specifies the name of the output file to generate. If no file is specified, output will be written to standard output.</p>
<dt><code>-v</code></p>
<dd> Prints the <i>xsubpp</i> version number to standard output, then exits.</p>
<dt><code>-prototypes</code></p>
<dd> By default <i>xsubpp</i> will not automatically generate prototype code for all xsubs. This flag will enable prototypes.</p>
<dt><code>-noversioncheck</code></p>
<dd> Disables the run time test that determines if the object file (derived from the <tt>&quot;.xs&quot;</tt> file) and the <tt>&quot;.pm&quot;</tt> files have the same version number.</p>
<dt><code>-nolinenumbers</code></p>
<dd> Prevents the inclusion of &#8216;#line&#8217; directives in the output.</p>
<dt><code>-nooptimize</code></p>
<dd> Disables certain optimizations. The only optimization that is currently affected is the use of <i>target</i>s by the output C code (see perlguts). This may significantly slow down the generated code, but this is the way <code>xsubpp</code> of 5.005 and earlier operated.</p>
<dt><code>-noinout</code></p>
<dd> Disable recognition of <tt>&quot;IN&quot;</tt>, <tt>&quot;OUT_LIST&quot;</tt> and <tt>&quot;INOUT_LIST&quot;</tt> declarations.</p>
<dt><code>-noargtypes</code></p>
<dd> Disable recognition of ANSI-like descriptions of function signature.</p>
<dt><code>-C<font SIZE="-2">++</font></code></p>
<dd> Currently doesn&#8217;t do anything at all. This flag has been a no-op for many versions of perl, at least as far back as perl5.003_07. It&#8217;s allowed here for backwards compatibility.</p>
<dt><code>-s=&#8230;</code> or <code>-strip=&#8230;</code></p>
<dd> <i>This option is obscure and discouraged.</i> </p>
<p> If specified, the given string will be stripped off from the beginning of the C function name in the generated <font SIZE="-1">XS</font> functions (if it starts with that prefix). This only applies to XSUBs without <tt>&quot;CODE&quot;</tt> or <tt>&quot;PPCODE&quot;</tt> blocks. For example, the <font SIZE="-1">XS:</font> </p>
<pre><code>
void foo_bar(int i);
</code></pre>
<p> when <tt>&quot;xsubpp&quot;</tt> is invoked with <tt>&quot;-s foo_&quot;</tt> will install a <tt>&quot;foo_bar&quot;</tt> function in Perl, but really call <tt>bar(i)</tt> in C. Most of the time, this is the opposite of what you want and failure modes are somewhat obscure, so please avoid this option where possible.</dl>
<h2>ENVIRONMENT</h2>
<p> No environment variables are used.</p>
