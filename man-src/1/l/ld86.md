<h2 class="name">NAME</h2>
<p> ld86 &#8211; Linker for </p>
<p><a href="/docs/linux/man/1-as86/">as86</a>(1)</p>
<h2>SYNOPSIS</h2>
<p> <code>ld86</code> [<code>-03MNdimrstyz</code>[-]] [<code>-llib_extension</code>] [<code>-o outfile</code>] [<code>-Ccrtfile</code>] [<code>-Llibdir</code>] [<code>-Olibfile</code>] [<code>-Ttextaddr</code>] [<code>-Hheapsize</code>] [<code>-Ddataaddr</code>] <code>infile&#8230;</code> </p>
<h2>DESCRIPTION</h2>
<p> This linker understands only the object files produced by the as86 assembler, it can link them into either an impure or a separate I&amp;D executable. </p>
<p> The linking defaults are everything off or none except for <code>-0</code> and the output file is <code>a.out</code>. There is <i>not</i> a standard library location defined in the linker. </p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-0</code></p>
<dd> produce header with 16-bit magic</p>
<dt><code>-3</code></p>
<dd> produce header with 32-bit magic</p>
<dt><code>-7</code></p>
<dd> produce Seventh Edition UNIX a.out header.</p>
<dt><code>-d</code></p>
<dd> delete the header from the output file, used for MSDOS COM files. As a side effect this also includes -s as there&#8217;s nowhere to put a symbol table.</p>
<dt><code>-Cx</code></p>
<dd> add file libdir-from-search/crtx.o to list of files linked</p>
<dt><code>-D</code></p>
<dd> data base address follows (in format suitable for strtoul)</p>
<dt><code>-H</code></p>
<dd> the top of heap (initial stack) address (in format suitable for strtoul)</p>
<dt><code>-Lx</code></p>
<dd> add dir name x to the head of the list of library dirs searched</p>
<dt><code>-M</code></p>
<dd> print symbols linked on stdout</p>
<dt><code>-N</code></p>
<dd> Create a native Linux OMAGIC output file. If the contents are i386 code the binary can be either linked by GCC or executed by linux. If the <code>-z</code> option is also included the linker can generate a QMAGIC executable.</p>
<dt><code>-Ox</code></p>
<dd> add library or object file libdir-from-search/x to list of files linked</p>
<dt><code>-T</code></p>
<dd> text base address follows (in format suitable for strtoul)</p>
<dt><code>-i</code></p>
<dd> separate I&amp;D output</p>
<dt><code>-lx</code></p>
<dd> add library libdir-from-search/libx.a to list of files linked</p>
<dt><code>-m</code></p>
<dd> print modules linked on stdout</p>
<dt><code>-o</code></p>
<dd> output file name follows</p>
<dt><code>-s</code></p>
<dd> strip symbols</p>
<dt><code>-r</code></p>
<dd> Generate a relocatable object from one source object, if the linker is given the -N option also the output format will be the hosts native format if possible.</p>
<dt><code>-t</code></p>
<dd> trace modules being looked at on stdout</p>
<dt><code>-y</code></p>
<dd> Alter the symbol tables to add label &#8216;extensions&#8217; so that labels with more than 8 characters can be stored in elks executables.</p>
<dt><code>-z</code></p>
<dd> produce &quot;unmapped zero page&quot; or &quot;QMAGIC&quot; executables</dl>
<p> All the options not taking an argument may be turned off by following the option letter by a &#8216;-&#8216;, as for cc1.</p>
<h2>PREDEFINED LABELS</h2>
<p> The linker predefines several labels that can be imported into user programs.</p>
<dl>
<dt><code>__etext</code></p>
<dd> Standard C variable for the end of the text segment.</p>
<dt><code>__edata</code></p>
<dd> Standard C variable for the end of the initilised data.</p>
<dt><code>__end</code></p>
<dd> Standard C variable for the end of the bss area.</p>
<dt><code>__segoff</code></p>
<dd> The offset within the executable file between the start of the text segment and the start of the data segment in 16 byte &#8216;paragraphs&#8217;. Note this is <code>zero</code> for impure (tiny model) executables and is adjusted for executables that don&#8217;t start at offset 0 within the segment.</p>
<dt><code>__segXDL</code></p>
<dd> The lowest address with data in segment &#8216;X&#8217;. (eg __seg0DL is for segment zero or the text segment, __seg3DL is for the data segment) The value &#8216;X&#8217; is a hex digit.</p>
<dt><code>__segXDH</code></p>
<dd> The top of segment &#8216;X&#8217;s data area.</p>
<dt><code>__segXCL</code></p>
<dd> The bottom of segment &#8216;X&#8217;s &#8216;common data&#8217; or unitilised data area. Each segment has both an initilised and unitilised data area.</p>
<dt><code>__segXCH</code></p>
<dd> The top of segment &#8216;X&#8217;s common area.</p>
<dt><code>__segXSO</code></p>
<dd> This is the adjusted offset from segment 0 of the start of segment &#8216;X&#8217; in &#8216;paragraphs&#8217;. </p>
</dl>
<h2>HISTORY</h2>
<p> The 6809 version does not support -i. </p>
<p> The previous versions of the linker could produce an 8086 executable with segments of a size &gt;64k, now only i386 executables may have segments this large. </p>
<h2>BUGS</h2>
<p> The linker cannot deal with reverse seeks caused by <code>org</code> instructions in the object file. Unlike previous versions the current one traps the error rather than trying to fill up the hard disk. </p>
<p> The linker produces a broken a.out object file if given one input and the <code>-r</code> option this is so it is compatible with pre-dev86 versions. </p>
