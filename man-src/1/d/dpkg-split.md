<h2 class="name">NAME</h2>
<p> dpkg-split &#8211; Debian package archive split/join tool </p>
<h2>SYNOPSIS</h2>
<p> <code>dpkg-split</code> [<i>option</i>&#8230;] <i>command</i></p>
<h2>DESCRIPTION</h2>
<p> <code>dpkg-split</code> splits Debian binary package files into smaller parts and reassembles them again, to support the storage of large package files on small media such as floppy disks. </p>
<p> It can be operated manually using the <code>&#8211;split</code>, <code>&#8211;join</code> and <code>&#8211;info</code> options. </p>
<p> It also has an automatic mode, invoked using the <code>&#8211;auto</code> option, where it maintains a queue of parts seen but not yet reassembled and reassembles a package file when it has seen all of its parts. The <code>&#8211;listq</code> and <code>&#8211;discard</code> options allow the management of the queue. </p>
<p> All splitting, joining and queueing operations produce informative messages on standard output; these may safely be ignored.</p>
<h2>COMMANDS</h2>
<dl>
<dt><code>-s</code>, <code>&#8211;split</code> <i>complete-archive</i> [<i>prefix</i>]</p>
<dd> Splits a single Debian binary package into several parts. </p>
<p> The parts are named <i>prefix</i><code>.</code><i>N</i><code>of</code><i>M</i><code>.deb</code> where <i>N</i> is the part number, starting at 1, and <i>M</i> is the total number of parts (both in decimal). </p>
<p> If no <i>prefix</i> is supplied then the <i>complete-archive</i> filename is taken, including directory, with any trailing <code>.deb</code> removed.</p>
<dt><code>-j</code>, <code>&#8211;join</code> <i>part</i>&#8230;</p>
<dd> Joins the parts of a package file together, reassembling the original file as it was before it was split. </p>
<p> The part files given as arguments must be all the parts of exactly the same original binary file. Each part must occur exactly once in the argument list, though the parts to not need to be listed in order. </p>
<p> The parts must of course all have been generated with the same part size specified at split time, which means that they must usually have been generated by the same invocation of <code>dpkg-split &#8211;split</code>. </p>
<p> The parts&#8217; filenames are not significant for the reassembly process. </p>
<p> By default the output file is called <i>package</i><code>_</code><i>version</i><code>_</code><i>arch</i><code>.deb</code>.</p>
<dt><code>-I</code>, <code>&#8211;info</code> <i>part</i>&#8230;</p>
<dd> Prints information, in a human-readable format, about the part file(s) specified. Arguments which are not binary package parts produce a message saying so instead (but still on standard output).</p>
<dt><code>-a</code>, <code>&#8211;auto -o</code> <i>complete-output part</i></p>
<dd> Automatically queue parts and reassemble a package if possible. </p>
<p> The <i>part</i> specified is examined, and compared with other parts of the same package (if any) in the queue of packages file parts. </p>
<p> If all parts of the package file of which <i>part</i> is a part are available then the package is reassembled and written to <i>complete-output</i> (which should not usually already exist, though this is not an error). </p>
<p> If not then the <i>part</i> is copied into the queue and <i>complete-output</i> is not created. </p>
<p> If <i>part</i> is not a split binary package part then <code>dpkg-split</code> will exit with status <code>1</code>; if some other trouble occurs then it will exit with status <code>2</code>. </p>
<p> The <code>&#8211;output</code> or <code>-o</code> option must be supplied when using <code>&#8211;auto</code>. (If this were not mandatory the calling program would not know what output file to expect.)</p>
<dt><code>-l</code>, <code>&#8211;listq</code></p>
<dd> Lists the contents of the queue of packages to be reassembled. </p>
<p> For each package file of which parts are in the queue the output gives the name of the package, the parts in the queue, and the total number of bytes stored in the queue.</p>
<dt><code>-d</code>, <code>&#8211;discard</code> [<i>package</i>&#8230;]</p>
<dd> This discards parts from the queue of those waiting for the remaining parts of their packages. </p>
<p> If no <i>package</i> is specified then the queue is cleared completely; if any are specified then only parts of the relevant package(s) are deleted.</p>
<dt><code>-?</code>, <code>&#8211;help</code></p>
<dd> Show the usage message and exit.</p>
<dt><code>&#8211;version</code></p>
<dd> Show the version and exit.</dl>
<h2>OPTIONS</h2>
<dl>
<dt><code>&#8211;depotdir</code> <i>directory</i></p>
<dd> Specifies an alternative directory for the queue of parts awaiting automatic reassembly. The default is <code>/var/lib/dpkg</code>.</p>
<dt><code>-S</code>, <code>&#8211;partsize</code> <i>kibibytes</i></p>
<dd> Specifies the maximum part size when splitting, in kibibytes (1024 bytes). The default is 450 KiB.</p>
<dt><code>-o</code>, <code>&#8211;output</code> <i>complete-output</i></p>
<dd> Specifies the output file name for a reassembly. </p>
<p> This overrides the default for a manual reassembly (<code>&#8211;join</code>) and is mandatory for an automatic queue-or-reassemble (<code>&#8211;auto</code>).</p>
<dt><code>-Q</code>, <code>&#8211;npquiet</code></p>
<dd> When doing automatic queue-or-reassembly <code>dpkg-split</code> usually prints a message if it is given a <i>part</i> that is not a binary package part. This option suppresses this message, to allow programs such as <code>dpkg</code> to cope with both split and unsplit packages without producing spurious messages.</p>
<dt><code>&#8211;msdos</code></p>
<dd> Forces the output filenames generated by <code>&#8211;split</code> to be MSDOS-compatible. </p>
<p> This mangles the prefix &#8211; either the default derived from the input filename or the one supplied as an argument: alphanumerics are lowercased, plus signs are replaced by <code>x</code>&#8216;s and all other characters are discarded. </p>
<p> The result is then truncated as much as is necessary, and filenames of the form <i>prefixN</i><code>of</code><i>M</i><code>.deb</code> are generated.</dl>
<h2>EXIT STATUS</h2>
<dl>
<dt><code>0</code></p>
<dd> The requested split, merge, or other command succeeded. <code>&#8211;info</code> commands count as successful even if the files are not binary package parts.</p>
<dt><code>1</code></p>
<dd> Only occurs with <code>&#8211;auto</code> and indicates that the <i>part</i> file was not a binary package part.</p>
<dt><code>2</code></p>
<dd> Fatal or unrecoverable error due to invalid command-line usage, a file that looked like a package part file but was corrupted, or interactions with the system, such as accesses to the database, memory allocations, etc.</dl>
<h2>ENVIRONMENT</h2>
<dl>
<dt><font SIZE="-1"><code>DPKG_COLORS</code></font></p>
<dd> Sets the color mode (since dpkg 1.18.5). The currently accepted values are: <code>auto</code> (default), <code>always</code> and <code>never</code>.</p>
<dt><font SIZE="-1"><code>SOURCE_DATE_EPOCH</code></font></p>
<dd> If set, it will be used as the timestamp (as seconds since the epoch) in the <code><a href="/docs/linux/man/5-deb-split/">deb-split</a></code>(5)&#8217;s <code><a href="/docs/linux/man/5-ar/">ar</a></code>(5) container.</dl>
<h2>FILES</h2>
<dl>
<dt><i>/var/lib/dpkg/parts</i></p>
<dd> The default queue directory for part files awaiting automatic reassembly. </p>
<p> The filenames used in this directory are in a format internal to <code>dpkg-split</code> and are unlikely to be useful to other programs, and in any case the filename format should not be relied upon.</dl>
<h2>BUGS</h2>
<p> Full details of the packages in the queue are impossible to get without digging into the queue directory yourself. </p>
<p> There is no easy way to test whether a file that may be a binary package part is one.</p>
