<h2 class="name">NAME</h2>
<p> dpkg-deb &#8211; Debian package archive (.deb) manipulation tool </p>
<h2>SYNOPSIS</h2>
<p> <code>dpkg-deb</code> [<i>option</i>&#8230;] <i>command</i></p>
<h2>DESCRIPTION</h2>
<p> <code>dpkg-deb</code> packs, unpacks and provides information about Debian archives. </p>
<p> Use <code>dpkg</code> to install and remove packages from your system. </p>
<p> You can also invoke <code>dpkg-deb</code> by calling <code>dpkg</code> with whatever options you want to pass to <code>dpkg-deb</code>. <code>dpkg</code> will spot that you wanted <code>dpkg-deb</code> and run it for you. </p>
<p> For most commands taking an input archive argument, the archive can be read from standard input if the archive name is given as a single minus character (&laquo;<code>&#8211;</code>&raquo;); otherwise lack of support will be documented in their respective command description.</p>
<h2>COMMANDS</h2>
<dl>
<dt><code>-b</code>, <code>&#8211;build</code> <i>binary-directory</i> [<i>archive</i>|<i>directory</i>]</p>
<dd> Creates a debian archive from the filesystem tree stored in <i>binary-directory</i>. <i>binary-directory</i> must have a <font SIZE="-1"><code>DEBIAN</code></font> subdirectory, which contains the control information files such as the control file itself. This directory will <i>not</i> appear in the binary package&#8217;s filesystem archive, but instead the files in it will be put in the binary package&#8217;s control information area. </p>
<p> Unless you specify <code>&#8211;nocheck</code>, <code>dpkg-deb</code> will read <code>DEBIAN/control</code> and parse it. It will check the file for syntax errors and other problems, and display the name of the binary package being built. <code>dpkg-deb</code> will also check the permissions of the maintainer scripts and other files found in the <font SIZE="-1"><code>DEBIAN</code></font> control information directory. </p>
<p> If no <i>archive</i> is specified then <code>dpkg-deb</code> will write the package into the file <i>binary-directory</i><code>.deb</code>. </p>
<p> If the archive to be created already exists it will be overwritten. </p>
<p> If the second argument is a directory then <code>dpkg-deb</code> will write to the file <i>directory</i><code>/</code><i>package</i><code>_</code><i>version</i><code>_</code><i>arch</i><code>.deb.</code> When a target directory is specified, rather than a file, the <code>&#8211;nocheck</code> option may not be used (since <code>dpkg-deb</code> needs to read and parse the package control file to determine which filename to use).</p>
<dt><code>-I</code>, <code>&#8211;info</code> <i>archive</i> [<i>control-file-name</i>&#8230;]</p>
<dd> Provides information about a binary package archive. </p>
<p> If no <i>control-file-name</i>s are specified then it will print a summary of the contents of the package as well as its control file. </p>
<p> If any <i>control-file-name</i>s are specified then <code>dpkg-deb</code> will print them in the order they were specified; if any of the components weren&#8217;t present it will print an error message to stderr about each one and exit with status 2.</p>
<dt><code>-W</code>, <code>&#8211;show</code> <i>archive</i></p>
<dd> Provides information about a binary package archive in the format specified by the <code>&#8211;showformat</code> argument. The default format displays the package&#8217;s name and version on one line, separated by a tabulator.</p>
<dt><code>-f</code>, <code>&#8211;field</code> <i>archive</i> [<i>control-field-name</i>&#8230;]</p>
<dd> Extracts control file information from a binary package archive. </p>
<p> If no <i>control-field-name</i>s are specified then it will print the whole control file. </p>
<p> If any are specified then <code>dpkg-deb</code> will print their contents, in the order in which they appear in the control file. If more than one <i>control-field-name</i> is specified then <code>dpkg-deb</code> will precede each with its field name (and a colon and space). </p>
<p> No errors are reported for fields requested but not found.</p>
<dt><code>-c</code>, <code>&#8211;contents</code> <i>archive</i></p>
<dd> Lists the contents of the filesystem tree archive portion of the package archive. It is currently produced in the format generated by <code>tar</code>&#8216;s verbose listing.</p>
<dt><code>-x</code>, <code>&#8211;extract</code> <i>archive directory</i></p>
<dd> Extracts the filesystem tree from a package archive into the specified directory. </p>
<p> Note that extracting a package to the root directory will <i>not</i> result in a correct installation! Use <code>dpkg</code> to install packages. </p>
<p> <i>directory</i> (but not its parents) will be created if necessary, and its permissions modified to match the contents of the package.</p>
<dt><code>-X</code>, <code>&#8211;vextract</code> <i>archive directory</i></p>
<dd> Is like <code>&#8211;extract</code> (<code>-x</code>) with <code>&#8211;verbose</code> (<code>-v</code>) which prints a listing of the files extracted as it goes.</p>
<dt><code>-R</code>, <code>&#8211;raw-extract</code> <i>archive directory</i></p>
<dd> Extracts the filesystem tree from a package archive into a specified directory, and the control information files into a <font SIZE="-1"><code>DEBIAN</code></font> subdirectory of the specified directory (since dpkg 1.16.1). </p>
<p> The target directory (but not its parents) will be created if necessary. </p>
<p> The input archive is not (currently) processed sequentially, so reading it from standard input (&laquo;<code>&#8211;</code>&raquo;) is <code>not</code> supported.</p>
<dt><code>&#8211;ctrl-tarfile</code> <i>archive</i></p>
<dd> Extracts the control data from a binary package and sends it to standard output in <code>tar</code> format (since dpkg 1.17.14). Together with <code><a href="/docs/linux/man/1-tar/">tar</a></code>(1) this can be used to extract a particular control file from a package archive. The input archive will always be processed sequentially.</p>
<dt><code>&#8211;fsys-tarfile</code> <i>archive</i></p>
<dd> Extracts the filesystem tree data from a binary package and sends it to standard output in <code>tar</code> format. Together with <code><a href="/docs/linux/man/1-tar/">tar</a></code>(1) this can be used to extract a particular file from a package archive. The input archive will always be processed sequentially.</p>
<dt><code>-e</code>, <code>&#8211;control</code> <i>archive</i> [<i>directory</i>]</p>
<dd> Extracts the control information files from a package archive into the specified directory. </p>
<p> If no directory is specified then a subdirectory <font SIZE="-1"><code>DEBIAN</code></font> in the current directory is used. </p>
<p> The target directory (but not its parents) will be created if necessary.</p>
<dt><code>-?</code>, <code>&#8211;help</code></p>
<dd> Show the usage message and exit.</p>
<dt><code>&#8211;version</code></p>
<dd> Show the version and exit.</dl>
<h2>OPTIONS</h2>
<dl>
<dt><code>&#8211;showformat=</code><i>format</i></p>
<dd> This option is used to specify the format of the output <code>&#8211;show</code> will produce. The format is a string that will be output for each package listed. </p>
<p> The string may reference any status field using the &#8220;${<i>field-name</i>}&#8221; form, a list of the valid fields can be easily produced using <code>-I</code> on the same package. A complete explanation of the formatting options (including escape sequences and field tabbing) can be found in the explanation of the <code>&#8211;showformat</code> option in <code><a href="/docs/linux/man/1-dpkg-query/">dpkg-query</a></code>(1). </p>
<p> The default for this field is &#8220;${Package}	${Version}
&#8221;.</p>
<dt><code>-z</code><i>compress-level</i></p>
<dd> Specify which compression level to use on the compressor backend, when building a package (default is 9 for gzip, 6 for xz and 19 for zstd). The accepted values are 0-9 with: 0 being mapped to compressor none for gzip. Before dpkg 1.16.2 level 0 was equivalent to compressor none for all compressors.</p>
<dt><code>-S</code><i>compress-strategy</i></p>
<dd> Specify which compression strategy to use on the compressor backend, when building a package (since dpkg 1.16.2). Allowed values are <code>none</code> (since dpkg 1.16.4), <code>filtered</code>, <code>huffman</code>, <code>rle</code> and <code>fixed</code> for gzip (since dpkg 1.17.0) and <code>extreme</code> for xz.</p>
<dt><code>-Z</code><i>compress-type</i></p>
<dd> Specify which compression type to use when building a package. Allowed values are <code>gzip</code>, <code>xz</code> (since dpkg 1.15.6), <code>zstd</code> (since dpkg 1.19.0.5ubuntu2) and <code>none</code> (default is <code>zstd</code>).</p>
<dt><code>&#8211;[no-]uniform-compression</code></p>
<dd> Specify that the same compression parameters should be used for all archive members (i.e. <code>control.tar</code> and <code>data.tar</code>; since dpkg 1.17.6). Otherwise only the <code>data.tar</code> member will use those parameters. The only supported compression types allowed to be uniformly used are <code>none</code>, <code>gzip</code>, <code>xz</code> and <code>zstd</code>. The <code>&#8211;no-uniform-compression</code> option disables uniform compression (since dpkg 1.19.0). Uniform compression is the default (since dpkg 1.19.0).</p>
<dt><code>&#8211;root-owner-group</code></p>
<dd> Set the owner and group for each entry in the filesystem tree data to root with id 0 (since dpkg 1.19.0). </p>
<p> <code>Note</code>: This option can be useful for rootless builds (see <i>rootless-builds.txt</i>), but should <code>not</code> be used when the entries have an owner or group that is not root. Support for these will be added later in the form of a meta manifest.</p>
<dt><code>&#8211;deb-format=</code><i>format</i></p>
<dd> Set the archive format version used when building (since dpkg 1.17.0). Allowed values are <code>2.0</code> for the new format, and <code>0.939000</code> for the old one (default is <code>2.0</code>). </p>
<p> The old archive format is less easily parsed by non-Debian tools and is now obsolete; its only use is when building packages to be parsed by versions of dpkg older than 0.93.76 (September 1995), which was released as i386 a.out only.</p>
<dt><code>&#8211;nocheck</code></p>
<dd> Inhibits <code>dpkg-deb &#8211;build</code>&#8216;s usual checks on the proposed contents of an archive. You can build any archive you want, no matter how broken, this way.</p>
<dt><code>-v</code>, <code>&#8211;verbose</code></p>
<dd> Enables verbose output (since dpkg 1.16.1). This currently only affects <code>&#8211;extract</code> making it behave like <code>&#8211;vextract</code>.</p>
<dt><code>-D</code>, <code>&#8211;debug</code></p>
<dd> Enables debugging output. This is not very interesting.</dl>
<h2>EXIT STATUS</h2>
<dl>
<dt><code>0</code></p>
<dd> The requested action was successfully performed.</p>
<dt><code>2</code></p>
<dd> Fatal or unrecoverable error due to invalid command-line usage, or interactions with the system, such as accesses to the database, memory allocations, etc.</dl>
<h2>ENVIRONMENT</h2>
<dl>
<dt><font SIZE="-1"><code>DPKG_COLORS</code></font></p>
<dd> Sets the color mode (since dpkg 1.18.5). The currently accepted values are: <code>auto</code> (default), <code>always</code> and <code>never</code>.</p>
<dt><font SIZE="-1"><code>TMPDIR</code></font></p>
<dd> If set, <code>dpkg-deb</code> will use it as the directory in which to create temporary files and directories.</p>
<dt><font SIZE="-1"><code>SOURCE_DATE_EPOCH</code></font></p>
<dd> If set, it will be used as the timestamp (as seconds since the epoch) in the <code><a href="/docs/linux/man/5-deb/">deb</a></code>(5)&#8217;s <code><a href="/docs/linux/man/5-ar/">ar</a></code>(5) container and used to clamp the mtime in the <code><a href="/docs/linux/man/5-tar/">tar</a></code>(5) file entries.</dl>
<h2>NOTES</h2>
<p> Do not attempt to use just <code>dpkg-deb</code> to install software! You must use <code>dpkg</code> proper to ensure that all the files are correctly placed and the package&#8217;s scripts run and its status and contents recorded.</p>
<h2>BUGS</h2>
<p> <code>dpkg-deb -I</code> <i>package1</i><code>.deb</code> <i>package2</i><code>.deb</code> does the wrong thing. </p>
<p> There is no authentication on <code>.deb</code> files; in fact, there isn&#8217;t even a straightforward checksum. (Higher level tools like <font SIZE="-1">APT</font> support authenticating <code>.deb</code> packages retrieved from a given repository, and most packages nowadays provide an md5sum control file generated by debian/rules. Though this is not directly supported by the lower level tools.)</p>
