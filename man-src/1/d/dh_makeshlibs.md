<h2 class="name">NAME</h2>
<p> dh_makeshlibs &#8211; automatically create shlibs file and call dpkg-gensymbols </p>
<h2>SYNOPSIS</h2>
<p> <code>dh_makeshlibs</code> [<i>debhelper options</i>] [<code>-m</code><i>major</i>] [<code>-V</code><i>[dependencies]</i>] [<code>-n</code>] [<code>-X</code><i>item</i>] [<code>&#8212;</code> <i>params</i>]</p>
<h2>DESCRIPTION</h2>
<p> <code>dh_makeshlibs</code> is a debhelper program that automatically scans for shared libraries, and generates a shlibs file for the libraries it finds. </p>
<p> It will also ensure that ldconfig is invoked during install and removal when it finds shared libraries. Since debhelper 9.20151004, this is done via a dpkg trigger. In older versions of debhelper, <code>dh_makeshlibs</code> would generate a maintainer script for this purpose.</p>
<h2>FILES</h2>
<dl>
<dt>debian/<i>package</i>.shlibs</p>
<dd> Installs this file, if present, into the package as DEBIAN/shlibs. If omitted, debhelper will generate a shlibs file automatically if it detects any libraries. </p>
<p> Note in compat levels 9 and earlier, this file was installed by <i><a href="/docs/linux/man/1-dh_installdeb/">dh_installdeb</a></i>(1) rather than <code>dh_makeshlibs</code>.</p>
<dt>debian/<i>package</i>.symbols</p>
<dd>
<dt>debian/<i>package</i>.symbols.<i>arch</i></p>
<dd> These symbols files, if present, are passed to <i><a href="/docs/linux/man/1-dpkg-gensymbols/">dpkg-gensymbols</a></i>(1) to be processed and installed. Use the <i>arch</i> specific names if you need to provide different symbols files for different architectures.</dl>
<h2>OPTIONS</h2>
<dl>
<dt><code>-m</code><i>major</i>, <code>&#8211;major=</code><i>major</i></p>
<dd> Instead of trying to guess the major number of the library with objdump, use the major number specified after the -m parameter. This is much less useful than it used to be, back in the bad old days when this program looked at library filenames rather than using objdump.</p>
<dt><code>-V</code>, <code>-V</code><i>dependencies</i></p>
<dd>
<dt><code>&#8211;version-info</code>, <code>&#8211;version-info=</code><i>dependencies</i></p>
<dd> By default, the shlibs file generated by this program does not make packages depend on any particular version of the package containing the shared library. It may be necessary for you to add some version dependency information to the shlibs file. If <code>-V</code> is specified with no dependency information, the current upstream version of the package is plugged into a dependency that looks like &quot;<i>packagename</i> <code>(&gt;</code>= <i>packageversion</i><code>)</code>&quot;. Note that in debhelper compatibility levels before v4, the Debian part of the package version number is also included. If <code>-V</code> is specified with parameters, the parameters can be used to specify the exact dependency information needed (be sure to include the package name). </p>
<p> Beware of using <code>-V</code> without any parameters; this is a conservative setting that always ensures that other packages&#8217; shared library dependencies are at least as tight as they need to be (unless your library is prone to changing <font SIZE="-1">ABI</font> without updating the upstream version number), so that if the maintainer screws up then they won&#8217;t break. The flip side is that packages might end up with dependencies that are too tight and so find it harder to be upgraded.</p>
<dt><code>-n</code>, <code>&#8211;no-scripts</code></p>
<dd> Do not add the &#8220;ldconfig&#8221; trigger even if it seems like the package might need it. The option is called <code>&#8211;no-scripts</code> for historical reasons as <code>dh_makeshlibs</code> would previously generate maintainer scripts that called <code>ldconfig</code>.</p>
<dt><code>-X</code><i>item</i>, <code>&#8211;exclude=</code><i>item</i></p>
<dd> Exclude files that contain <i>item</i> anywhere in their filename or directory from being treated as shared libraries.</p>
<dt><code>&#8211;add-udeb=</code><i>udeb</i></p>
<dd> Create an additional line for udebs in the shlibs file and use <i>udeb</i> as the package name for udebs to depend on instead of the regular library package.</p>
<dt><code>&#8212;</code> <i>params</i></p>
<dd> Pass <i>params</i> to <i><a href="/docs/linux/man/1-dpkg-gensymbols/">dpkg-gensymbols</a></i>(1).</dl>
<h2>EXAMPLES</h2>
<dl>
<dt><code>dh_makeshlibs</code></p>
<dd> Assuming this is a package named <i>libfoobar1</i>, generates a shlibs file that looks something like:<br />
&nbsp;libfoobar 1 libfoobar1</p>
<dt><code>dh_makeshlibs -V</code></p>
<dd> Assuming the current version of the package is 1.1-3, generates a shlibs file that looks something like:<br />
&nbsp;libfoobar 1 libfoobar1&nbsp;(&gt;=&nbsp;1.1)</p>
<dt><code>dh_makeshlibs -V &#8216;libfoobar1 (&gt;= 1.0)&#8217;</code></p>
<dd> Generates a shlibs file that looks something like:<br />
&nbsp;<wbr>&nbsp;libfoobar 1 libfoobar1&nbsp;(&gt;=&nbsp;1.0)</dl>
