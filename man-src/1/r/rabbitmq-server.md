<h2 class="name">NAME</h2>
<p> rabbitmq-server &#8211; start RabbitMQ AMQP server </p>
<h2>SYNOPSIS</h2>
<dl>
<dt> <code>rabbitmq-server</code> [-detached]</dl>
<h2>DESCRIPTION</h2>
<dd>RabbitMQ is an implementation of AMQP, the emerging standard for high performance enterprise messaging. The RabbitMQ server is a robust and scalable implementation of an AMQP broker. </p>
<p> Running rabbitmq-server in the foreground displays a banner message, and reports on progress in the startup sequence, concluding with the message &quot;broker running&quot;, indicating that the RabbitMQ broker has been started successfully. To shut down the server, just terminate the process or use <a href="/docs/linux/man/1-rabbitmqctl/">rabbitmqctl</a>(1).</p>
<h2>ENVIRONMENT</h2>
<p> RABBITMQ_MNESIA_BASE</p>
<dl>
<dt>
<dd> Defaults to /var/lib/rabbitmq/mnesia. Set this to the directory where Mnesia database files should be placed.</dl>
<p> RABBITMQ_LOG_BASE</p>
<dl>
<dt>
<dd> Defaults to /var/log/rabbitmq. Log files generated by the server will be placed in this directory.</dl>
<p> RABBITMQ_NODENAME</p>
<dl>
<dt>
<dd> Defaults to rabbit. This can be useful if you want to run more than one node per machine &#8211; <code>RABBITMQ_NODENAME</code> should be unique per erlang-node-and-machine combination. See the m[blue]<code>clustering on a single machine guide</code>m[]<font SIZE="-2">[1]</font> for details.</dl>
<p> RABBITMQ_NODE_IP_ADDRESS</p>
<dl>
<dt>
<dd> By default RabbitMQ will bind to all interfaces, on IPv4 and IPv6 if available. Set this if you only want to bind to one network interface or address family.</dl>
<p> RABBITMQ_NODE_PORT</p>
<dl>
<dt>
<dd> Defaults to 5672.</dl>
<h2>OPTIONS</h2>
<p> -detached</p>
<dl>
<dt>
<dd> Start the server process in the background. Note that this will cause the pid not to be written to the pid file. </p>
<p> For example: </p>
<pre>
rabbitmq-server -detached
</pre>
<p> Runs RabbitMQ AMQP server in the background.</dl>
