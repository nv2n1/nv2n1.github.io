<h2>NAME</h2>
<p> reprepro &#8211; produce, manage and sync a local repository of Debian packages</p>
<h2>SYNOPSIS</h2>
<p> <code>reprepro &#8211;help</code> </p>
<p> <code>reprepro</code> [ <i>options</i> ] <i>command</i> [ <i>per-command-arguments</i> ]</p>
<h2>DESCRIPTION</h2>
<p> reprepro is a tool to manage a repository of Debian packages (.deb, .udeb, .dsc, &#8230;). It stores files either being injected manually or downloaded from some other repository (partially) mirrored into a pool/ hierarchy. Managed packages and checksums of files are stored in a Berkeley DB database file, so no database server is needed. Checking signatures of mirrored repositories and creating signatures of the generated Package indices is supported. </p>
<p> Former working title of this program was mirrorer.</p>
<h2>GLOBAL OPTIONS</h2>
<p> Options can be specified before the command. Each affects a different subset of commands and is ignored by other commands.</p>
<dl>
<dt><code>-h &#8211;help</code></p>
<dd> Displays a short list of options and commands with description.</p>
<dt><code>-v, -V, &#8211;verbose</code></p>
<dd> Be more verbose. Can be applied multiple times. One uppercase <code>-V</code> counts as five lowercase <code>-v.</code></p>
<dt><code>&#8211;silent</code></p>
<dd> Be less verbose. Can be applied multiple times. One <code>-v</code> and one <code>-s</code> cancel each other out.</p>
<dt><code>-f, &#8211;force</code></p>
<dd> This option is ignored, as it no longer exists.</p>
<dt><code>-b, &#8211;basedir </code><i>basedir</i></p>
<dd> Sets the base-dir all other default directories are relative to. If none is supplied and the <code>REPREPRO_BASE_DIR</code> environment variable is not set either, the current directory will be used.</p>
<dt><code>&#8211;outdir </code><i>outdir</i></p>
<dd> Sets the base-dir of the repository to manage, i.e. where the <code>pool/</code> subdirectory resides. And in which the <code>dists/</code> directory is placed by default. If this starts with &#8216;<code>+b/</code>&#8216;, it is relative to basedir. </p>
<p> The default for this is <i>basedir</i>.</p>
<dt><code>&#8211;confdir </code><i>confdir</i></p>
<dd> Sets the directory where the configuration is searched in. </p>
<p> If this starts with &#8216;<code>+b/</code>&#8216;, it is relative to basedir. </p>
<p> If none is given, <code>+b/conf</code> (i.e. <i>basedir</i><code>/conf</code>) will be used.</p>
<dt><code>&#8211;distdir </code><i>distdir</i></p>
<dd> Sets the directory to generate index files relatively to. (i.e. things like Packages.gz, Sources.gz and Release.gpg) </p>
<p> If this starts with &#8216;<code>+b/</code>&#8216;, it is relative to basedir, if starting with &#8216;<code>+o/</code>&#8216; relative to outdir. </p>
<p> If none is given, <code>+o/dists</code> (i.e. <i>outdir</i><code>/dists</code>) is used. </p>
<p> <code>Note:</code> apt has <code>dists</code> hard-coded in it, so this is mostly only useful for testing or when your webserver pretends another directory structure than your physical layout. </p>
<p> <code>Warning:</code> Beware when changing this forth and back between two values not ending in the same directory. Reprepro only looks if files it wants are there. If nothing of the content changed and there is a file it will not touch it, assuming it is the one it wrote last time, assuming any different <code>&#8211;distdir</code> ended in the same directory. So either clean a directory before setting <code>&#8211;distdir</code> to it or do an <code>export</code> with the new one first to have a consistent state.</p>
<dt><code>&#8211;logdir </code><i>logdir</i></p>
<dd> The directory where files generated by the <code>Log:</code> directive are stored if they have no absolute path. </p>
<p> If this starts with &#8216;<code>+b/</code>&#8216;, it is relative to basedir, if starting with &#8216;<code>+o/</code>&#8216; relative to outdir, with &#8216;<code>+c/</code>&#8216; relative to confdir. </p>
<p> If none is given, <code>+b/logs</code> (i.e. <i>basedir</i><code>/logs</code>) is used.</p>
<dt><code>&#8211;dbdir </code><i>dbdir</i></p>
<dd> Sets the directory where reprepro keeps its databases. </p>
<p> If this starts with &#8216;<code>+b/</code>&#8216;, it is relative to basedir, if starting with &#8216;<code>+o/</code>&#8216; relative to outdir, with &#8216;<code>+c/</code>&#8216; relative to confdir. </p>
<p> If none is given, <code>+b/db</code> (i.e. <i>basedir</i><code>/db</code>) is used. </p>
<p> <code>Note:</code> This is permanent data, no cache. One has almost to regenerate the whole repository when this is lost.</p>
<dt><code>&#8211;listdir </code><i>listdir</i></p>
<dd> Sets the directory where downloads it downloads indices to when importing from other repositories. This is temporary data and can be safely deleted when not in an update run. </p>
<p> If this starts with &#8216;<code>+b/</code>&#8216;, it is relative to basedir, if starting with &#8216;<code>+o/</code>&#8216; relative to outdir, with &#8216;<code>+c/</code>&#8216; relative to confdir. </p>
<p> If none is given, <code>+b/lists</code> (i.e. <i>basedir</i><code>/lists</code>) is used.</p>
<dt><code>&#8211;morguedir </code><i>morguedir</i></p>
<dd> Files deleted from the pool are stored into <i>morguedir</i>. </p>
<p> If this starts with &#8216;<code>+b/</code>&#8216;, it is relative to basedir, if starting with &#8216;<code>+o/</code>&#8216; relative to outdir, with &#8216;<code>+c/</code>&#8216; relative to confdir. </p>
<p> If none is given, deleted files are just deleted.</p>
<dt><code>&#8211;methoddir </code><i>methoddir</i></p>
<dd> Look in <i>methoddir</i> instead of <code>/usr/lib/apt/methods</code> for methods to call when importing from other repositories.</p>
<dt><code>-C, &#8211;component </code><i>components</i></p>
<dd> Limit the specified command to this components only. This will force added packages to this components, limit removing packages from this components, only list packages in this components, and/or otherwise only look at packages in this components, depending on the command in question. </p>
<p> Multiple components are specified by separating them with <code>|</code>, as in <code>-C &#8216;main|contrib&#8217;</code>.</p>
<dt><code>-A, &#8211;architecture </code><i>architectures</i></p>
<dd> Limit the specified command to this architectures only. (i.e. only list such packages, only remove packages from the specified architectures, or otherwise only look at/act on this architectures depending on the specific command). </p>
<p> Multiple architectures are specified by separating them with <code>|</code>, as in <code>-A &#8216;sparc|i386&#8217;</code>. </p>
<p> Note that architecture <code>all</code> packages can be included to each architecture but are then handled separately. Thus by using <code>-A</code> in a specific way one can have different versions of an architecture <code>all</code> package in different architectures of the same distribution.</p>
<dt><code>-T, &#8211;type </code>dsc|deb|udeb</p>
<dd> Limit the specified command to this packagetypes only. (i.e. only list such packages, only remove such packages, only include such packages, &#8230;)</p>
<dt><code>-S, &#8211;section </code><i>section</i></p>
<dd> Overrides the section of inclusions. (Also override possible override files)</p>
<dt><code>-P, &#8211;priority </code><i>priority</i></p>
<dd> Overrides the priority of inclusions. (Also override possible override files)</p>
<dt><code>&#8211;export=</code>(<code>never</code>|<code>changed</code>|<code>lookedat</code>|<code>force</code>)</p>
<dd> This option specify whether and how the high level actions (e.g. install, update, pull, delete) should export the index files of the distributions they work with.</p>
<dt><code>&#8211;export=lookedat</code></p>
<dd> In this mode every distribution the action handled will be exported, unless there was an error possibly corrupting it.<br />
 <i>Note</i> that only missing files and files whose intended content changed between before and after the action will be written. To get a guaranteed current export, use the <code>export</code> action.<br />
 For backwards compatibility, <code>lookedat</code> is also available under the old name <code>normal</code>. The name <code>normal</code> is deprecated and will be removed in future versions.</p>
<dt><code>&#8211;export=changed</code></p>
<dd> In this mode every distribution actually changed will be exported, unless there was an error possibly corrupting it. (i.e. if nothing changed, not even missing files will be created.)<br />
 <i>Note</i> that only missing files and files whose intended content changed between before and after the action will be written. To get a guaranteed current export, use the <code>export</code> action.</p>
<dt><code>&#8211;export=force</code></p>
<dd> Always export all distributions looked at, even if there was some error possibly bringing it into a inconsistent state.</p>
<dt><code>&#8211;export=never</code></p>
<dd> No index files are exported. You will have to call <code>export</code> later.<br />
 <i>Note</i> that you most likely additionally need the <code>&#8211;keepunreferencedfiles</code> option, if you do not want some of the files pointed to by the untouched index files to vanish.</p>
<dt><code>&#8211;ignore=</code><i>what</i></p>
<dd> Ignore errors of type <i>what</i>. See the section <code>ERROR IGNORING</code> for possible values.</p>
<dt><code>&#8211;nolistsdownload</code></p>
<dd> When running <code>update</code>, <code>checkupdate</code> or <code>predelete</code> do not download any Release or index files. This is hardly useful except when you just run one of those command for the same distributions. And even then reprepro is usually good in not downloading except <code>Release</code> and <code>Release.gpg</code> files again.</p>
<dt><code>&#8211;nothingiserror</code></p>
<dd> If nothing was done, return with exitcode 1 instead of the usual 0. </p>
<p> Note that &quot;nothing was done&quot; means the primary purpose of the action in question. Auxillary actions (opening and closeing the database, exporting missing files with &#8211;export=lookedat, &#8230;) usually do not count. Also note that this is not very well tested. If you find an action that claims to have done something in some cases where you think it should not, please let me know.</p>
<dt><code>&#8211;keeptemporaries</code></p>
<dd> Do not delete temporary <code>.new</code> files when exporting a distribution fails. (reprepro first create <code>.new</code> files in the <code>dists</code> directory and only if everything is generated, all files are put into their final place at once. If this option is not specified and something fails, all are deleted to keep <code>dists</code> clean).</p>
<dt><code>&#8211;keepunreferencedfiles</code></p>
<dd> Do not delete files that are no longer used because the package they are from is deleted/replaced with a newer version from the last distribution it was in.</p>
<dt><code>&#8211;keepunusednewfiles</code></p>
<dd> The include, includedsc, includedeb and processincoming by default delete any file they added to the pool that is not marked used at the end of the operation. While this keeps the pool clean and allows changing before trying to add again, this needs copying and checksum calculation every time one tries to add a file.</p>
<dt><code>&#8211;keepdirectories</code></p>
<dd> Do not try to rmdir parent directories after files or directories have been removed from them. (Do this if your directories have special permissions you want keep, do not want to be pestered with warnings about errors to remove them, or have a buggy rmdir call deleting non-empty directories.)</p>
<dt><code>&#8211;ask-passphrase</code></p>
<dd> Ask for passphrases when signing things and one is needed. This is a quick and dirty implementation using the obsolete <code><a href="/docs/linux/man/3-getpass/">getpass</a>(3)</code> function with the description gpgme is supplying. So the prompt will look quite funny and support for passphrases with more than 8 characters depend on your libc. I suggest using gpg-agent or something like that instead.</p>
<dt><code>&#8211;noskipold</code></p>
<dd> When updating do not skip targets where no new index files and no files marked as already processed are available. </p>
<p> If you changed a script to preprocess downloaded index files or changed a Listfilter, you most likely want to call reprepro with &#8211;noskipold.</p>
<dt><code>&#8211;waitforlock </code><i>count</i></p>
<dd> If there is a lockfile indicating another instance of reprepro is currently using the database, retry <i>count</i> times after waiting for 10 seconds each time. The default is 0 and means to error out instantly.</p>
<dt><code>&#8211;spacecheck full</code>|none</p>
<dd> The default is <code>full</code>:<br />
 In the update commands, check for every to be downloaded file which filesystem it is on and how much space is left.<br />
 To disable this behaviour, use <code>none</code>.</p>
<dt><code>&#8211;dbsafetymargin</code><i> bytes-count</i></p>
<dd> If checking for free space, reserve <i>byte-count</i> bytes on the filesystem containing the <code>db/</code> directory. The default is 104857600 (i.e. 100MB), which is quite large. But as there is no way to know in advance how large the databases will grow and libdb is extremely touchy in that regard, lower only when you know what you do.</p>
<dt><code>&#8211;safetymargin</code><i> bytes-count</i></p>
<dd> If checking for free space, reserve <i>byte-count</i> bytes on filesystems not containing the <code>db/</code> directory. The default is 1048576 (i.e. 1MB).</p>
<dt><code>&#8211;noguessgpgtty</code></p>
<dd> Don&#8217;t set the environment variable <code>GPG_TTY</code>, even when it is not set, stdin is terminal and <code>/proc/self/fd/0</code> is a readable symbolic link.</p>
<dt><code>&#8211;gnupghome</code></p>
<dd> Set the <code>GNUPGHOME</code> evnironment variable to the given directory as argument to this option. And your gpg will most likely use the content of this variable instead of &quot;~/.gnupg&quot;. Take a look at <code><a href="/docs/linux/man/1-gpg/">gpg</a></code>(1) to be sure. This option in the command line is usually not very useful, as it is possible to set the environment variable directly. Its main reason for existance is that it can be used in <i>conf</i><code>/options</code>.</p>
<dt><code>&#8211;gunzip</code><i> gz-uncompressor</i></p>
<dd> While reprepro links against <code>libz</code>, it will look for the program given with this option (or <code>gunzip</code> if not given) and use that when uncompressing index files while downloading from remote repositories. (So that downloading and uncompression can happen at the same time). If the program is not found or is <code>NONE</code> (all-uppercase) then uncompressing will always be done using the built in uncompression method. The program has to accept the compressed file as stdin and write the uncompressed file into stdout.</p>
<dt><code>&#8211;bunzip2</code><i> bz2-uncompressor</i></p>
<dd> When uncompressing downloaded index files or when not linked against <code>libbz2</code> reprepro will use this program to uncompress <code>.bz2</code> files. The default value is <code>bunzip2</code>. If the program is not found or is <code>NONE</code> (all-uppercase) then uncompressing will always be done using the built in uncompression method or not be possible when not linked against <code>libbz2</code>. The program has to accept the compressed file as stdin and write the uncompressed file into stdout.</p>
<dt><code>&#8211;unlzma</code><i> lzma-uncompressor</i></p>
<dd> When trying to uncompress or read lzma compressed files, this program will be used. The default value is <code>unlzma</code>. If the program is not found or is <code>NONE</code> (all-uppercase) then uncompressing lzma files will not be possible. The program has to accept the compressed file as stdin and write the uncompressed file into stdout.</p>
<dt><code>&#8211;unxz</code><i> xz-uncompressor</i></p>
<dd> When trying to uncompress or read xz compressed files, this program will be used. The default value is <code>unxz</code>. If the program is not found or is <code>NONE</code> (all-uppercase) then uncompressing xz files will not be possible. The program has to accept the compressed file as stdin and write the uncompressed file into stdout.</p>
<dt><code>&#8211;lunzip</code><i> lzip-uncompressor</i></p>
<dd> When trying to uncompress or read lzip compressed files, this program will be used. The default value is <code>lunzip</code>. If the program is not found or is <code>NONE</code> (all-uppercase) then uncompressing lz files will not be possible. The program has to accept the compressed file as stdin and write the uncompressed file into stdout.</p>
<dt><code>&#8211;list-max</code><i> count</i></p>
<dd> Limits the output of <code>list</code>, <code>listmatched</code> and <code>listfilter</code> to the first <i>count</i> results. The default is 0, which means unlimited.</p>
<dt><code>&#8211;list-skip</code><i> count</i></p>
<dd> Omitts the first <i>count</i> results from the output of <code>list</code>, <code>listmatched</code> and <code>listfilter</code>.</p>
<dt><code>&#8211;list-format</code><i> format</i></p>
<dd> Set the output format of <code>list</code>, <code>listmatched</code> and <code>listfilter</code> commands. The format is similar to dpkg-query&#8217;s <code>&#8211;showformat</code>: fields are specified as <code>${</code><i>fieldname</i><code>}</code> or <code>${</code><i>fieldname</i><code>;</code><i>length</i><code>}</code>. Zero length or no length means unlimited. Positive numbers mean fill with spaces right, negative fill with spaces left. </p>
