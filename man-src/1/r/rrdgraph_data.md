<p> rrdgraph_data &#8211; preparing data for graphing in rrdtool graph </p>
<h2>SYNOPSIS</h2>
<p> <code>DEF:</code><i>&lt;vname&gt;</i>=<i>&lt;rrdfile&gt;</i>:<i>&lt;ds-name&gt;</i>:<i>&lt;</i><i>CF</i><i>&gt;</i>[:step=<i>&lt;step&gt;</i>][:start=<i>&lt;time&gt;</i>][:end=<i>&lt;time&gt;</i>][:reduce=<i>&lt;</i>CF<i>&gt;</i>] </p>
<p> <code>VDEF</code>:<i>vname</i>=<i></i><i>RPN</i><i> expression</i> </p>
<p> <code>CDEF</code>:<i>vname</i>=<i></i><i>RPN</i><i> expression</i></p>
<h2>DESCRIPTION</h2>
<p> These three instructions extract data values out of the <code>RRD</code> files, optionally altering them (think, for example, of a bytes to bits conversion). If so desired, you can also define variables containing useful information such as maximum, minimum etcetera. Two of the instructions use a language called <code>RPN</code> which is described in its own manual page. </p>
<p> Variable names (<i>vname</i>) must be made up strings of the following characters <tt>&quot;A-Z, a-z, 0-9, -,_&quot;</tt> and a maximum length of 255 characters. </p>
<p> When picking variable names, make sure you do not choose a name that is already taken by an RPN operator. A safe bet it to use lowercase or mixed case names for variables since operators will always be in uppercase.</p>
<h2>DEF</h2>
<p> <code>DEF:</code><i>&lt;vname&gt;</i>=<i>&lt;rrdfile&gt;</i>:<i>&lt;ds-name&gt;</i>:<i>&lt;</i><i>CF</i><i>&gt;</i>[:step=<i>&lt;step&gt;</i>][:start=<i>&lt;time&gt;</i>][:end=<i>&lt;time&gt;</i>][:reduce=<i>&lt;</i>CF<i>&gt;</i>] </p>
<p> This command fetches data from an <code>RRD</code> file. The virtual name <i>vname</i> can then be used throughout the rest of the script. By default, an <code>RRA</code> which contains the correct consolidated data at an appropriate resolution will be chosen. The resolution can be overridden with the &#8211;step option. The resolution can again be overridden by specifying the <code>step size</code>. The time span of this data is the same as for the graph by default, you can override this by specifying <code>start and end</code>. Remember to escape colons in the time specification! </p>
<p> If the resolution of the data is higher than the resolution of the graph, the data will be further consolidated. This may result in a graph that spans slightly more time than requested. Ideally each point in the graph should correspond with one <code>CDP</code> from an <code>RRA</code>. For instance, if your <code>RRD</code> has an <code>RRA</code> with a resolution of 1800 seconds per <code>CDP</code>, you should create an image with width 400 and time span 400*1800 seconds (use appropriate start and end times, such as <tt>&quot;--start end-8days8hours&quot;</tt>). </p>
<p> If consolidation needs to be done, the <code>CF</code> of the <code>RRA</code> specified in the <code>DEF</code> itself will be used to reduce the data density. This behavior can be changed using <tt>&quot;:reduce=</tt>&lt;CF&gt;<tt>&quot;</tt>. This optional parameter specifies the <code>CF</code> to use during the data reduction phase. </p>
<p> Example: </p>
<pre>
        DEF:ds0=router.rrd:ds0:AVERAGE
        DEF:ds0weekly=router.rrd:ds0:AVERAGE:step=7200
        DEF:ds0weekly=router.rrd:ds0:AVERAGE:start=end-1h
        DEF:ds0weekly=router.rrd:ds0:AVERAGE:start=11\:00:end=start+1h
</pre>
<h2>VDEF</h2>
<p> <code>VDEF</code>:<i>vname</i>=<i></i><i>RPN</i><i> expression</i> </p>
<p> This command returns a value and/or a time according to the <code>RPN</code> statements used. The resulting <i>vname</i> will, depending on the functions used, have a value and a time component. When you use this <i>vname</i> in another <code>RPN</code> expression, you are effectively inserting its value just as if you had put a number at that place. The variable can also be used in the various graph and print elements. </p>
<p> Example: <tt>&quot;VDEF:avg=mydata,AVERAGE&quot;</tt> </p>
<p> Note that currently only aggregation functions work in VDEF rpn expressions. Patches to change this are welcome.</p>
<h2>CDEF</h2>
<p> <code>CDEF</code>:<i>vname</i>=<i></i><i>RPN</i><i> expression</i> </p>
<p> This command creates a new set of data points (in memory only, not in the <code>RRD</code> file) out of one or more other data series. The <code>RPN</code> instructions are used to evaluate a mathematical function on each data point. The resulting <i>vname</i> can then be used further on in the script, just as if it were generated by a <code>DEF</code> instruction. </p>
<p> Example: <tt>&quot;CDEF:mydatabits=mydata,8,*&quot;</tt></p>
<h2>About CDEF versus VDEF</h2>
<p> At some point in processing, <code>RRDtool</code> has gathered an array of rates ready to display. </p>
<p> <code>CDEF</code> works on such an array. For example, <i>CDEF:new=ds0,8,*</i> would multiply each of the array members by eight (probably transforming bytes into bits). The result is an array containing the new values. </p>
<p> <code>VDEF</code> also works on such an array but in a different way. For example, <i>VDEF:max=ds0,MAXIMUM</i> would scan each of the array members and store the maximum value.</p>
<h3>When do you use <code>VDEF</code> versus <code>CDEF</code>?</h3>
<p> Use <code>CDEF</code> to transform your data prior to graphing. In the above example, we&#8217;d use a <code>CDEF</code> to transform bytes to bits before graphing the bits. </p>
<p> You use a <code>VDEF</code> if you want <i>max(1,5,3,2,4)</i> to return five which would be displayed in the graph&#8217;s legend (to answer, what was the maximum value during the graph period). </p>
<p> If you want to apply &#8216;complex&#8217; operations to the result of a VDEF you have to use a CDEF again since VDEFs only look like RPN expressions, they aren&#8217;t really.</p>
