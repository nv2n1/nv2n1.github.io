<h2>DESCRIPTION</h2>
<p> These instructions allow you to generate your image or report. If you don&#8217;t use any graph elements, no graph is generated. Similarly, no report is generated if you don&#8217;t use print options.</p>
<h3><font SIZE="-1">PRINT</font></h3>
<p> <i></i><font SIZE="-1">PRINT:</font><i>vname</i>:<i>format[</i>:strftime<i>]</i> </p>
<p> Depending on the context, either the value component or the time component of a <font SIZE="-1"><code>VDEF</code></font> is printed using <i>format</i>. It is an error to specify a <i>vname</i> generated by a <font SIZE="-1"><code>DEF</code></font> or <font SIZE="-1"><code>CDEF</code></font>. </p>
<p> Any text in <i>format</i> is printed literally with one exception: The percent character introduces a formatter string. This string can be: </p>
<p> For printing values:</p>
<dl>
<dt><code>%%</code></p>
<dd> just prints a literal &#8216;%&#8217; character</p>
<dt><code>%#.#le</code></p>
<dd> prints numbers like 1.2346e+04. The optional integers # denote field width and decimal precision.</p>
<dt><code>%#.#lf</code></p>
<dd> prints numbers like 12345.6789, with optional field width and precision.</p>
<dt><code>%s</code></p>
<dd> place this after %le, %lf or %lg. This will be replaced by the appropriate <font SIZE="-1">SI</font> magnitude unit and the value will be scaled accordingly (123456 -&gt; 123.456 k).</p>
<dt><code>%S</code></p>
<dd> is similar to %s. It does, however, use a previously defined magnitude unit. If there is no such unit yet, it tries to define one (just like %s) unless the value is zero, in which case the magnitude unit stays undefined. Thus, formatter strings using %S and no %s will all use the same magnitude unit except for zero values.</dl>
<p> If you <font SIZE="-1">PRINT</font> a <font SIZE="-1">VDEF</font> value, you can also print the time associated with it by appending the string <code>:strftime</code> to the format. Note that RRDtool uses the strftime function of your OSs C library. This means that the conversion specifier may vary. Check the manual page if you are uncertain. The following is a list of conversion specifiers usually supported across the board.</p>
<dl>
<dt><code>%a</code></p>
<dd> The abbreviated weekday name according to the current locale.</p>
<dt><code>%A</code></p>
<dd> The full weekday name according to the current locale.</p>
<dt><code>%b</code></p>
<dd> The abbreviated month name according to the current locale.</p>
<dt><code>%B</code></p>
<dd> The full month name according to the current locale.</p>
<dt><code>%c</code></p>
<dd> The preferred date and time representation for the current locale.</p>
<dt><code>%d</code></p>
<dd> The day of the month as a decimal number (range 01 to 31).</p>
<dt><code>%H</code></p>
<dd> The hour as a decimal number using a 24-hour clock (range 00 to 23).</p>
<dt><code>%I</code></p>
<dd> The hour as a decimal number using a 12-hour clock (range 01 to 12).</p>
<dt><code>%j</code></p>
<dd> The day of the year as a decimal number (range 001 to 366).</p>
<dt><code>%m</code></p>
<dd> The month as a decimal number (range 01 to 12).</p>
<dt><code>%M</code></p>
<dd> The minute as a decimal number (range 00 to 59).</p>
<dt><code>%p</code></p>
<dd> Either `<font SIZE="-1">AM</font>&#8216; or `<font SIZE="-1">PM</font>&#8216; according to the given time value, or the corresponding strings for the current locale. Noon is treated as `pm&#8217; and midnight as `am&#8217;. Note that in many locales and `pm&#8217; notation is unsupported and in such cases <tt>%p</tt> will return an empty string.</p>
<dt><code>%s</code></p>
<dd> The second as a decimal number (range 00 to 61).</p>
<dt><code>%S</code></p>
<dd> The seconds since the epoch (1.1.1970) (libc dependent non standard!)</p>
<dt><code>%U</code></p>
<dd> The week number of the current year as a decimal number, range 00 to 53, starting with the first Sunday as the first day of week 01. See also <tt>%V</tt> and <tt>%W</tt>.</p>
<dt><code>%V</code></p>
<dd> The <font SIZE="-1">ISO</font> 8601:1988 week number of the current year as a decimal number, range 01 to 53, where week 1 is the first week that has at least 4 days in the current year, and with Monday as the first day of the week. See also <tt>%U</tt> and <tt>%W</tt>.</p>
<dt><code>%w</code></p>
<dd> The day of the week as a decimal, range 0 to 6, Sunday being 0. See also <tt>%u</tt>.</p>
<dt><code>%W</code></p>
<dd> The week number of the current year as a decimal number, range 00 to 53, starting with the first Monday as the first day of week 01.</p>
<dt><code>%x</code></p>
<dd> The preferred date representation for the current locale without the time.</p>
<dt><code>%X</code></p>
<dd> The preferred time representation for the current locale without the date.</p>
<dt><code>%y</code></p>
<dd> The year as a decimal number without a century (range 00 to 99).</p>
<dt><code>%Y</code></p>
<dd> The year as a decimal number including the century.</p>
<dt><code>%Z</code></p>
<dd> The time zone or name or abbreviation.</p>
<dt><code>%%</code></p>
<dd> A literal `%&#8217; character.</dl>
<p> <i></i><font SIZE="-1">PRINT:</font><i>vname</i>:<i></i><font SIZE="-1"><i>CF</i></font><i></i>:<i>format</i> </p>
<p> <i>Deprecated. Use the new form of this command in new scripts.</i> The first form of this command is to be used with <font SIZE="-1"><code>CDEF</code></font> <i>vname</i>s.</p>
<h3><font SIZE="-1">GRAPH</font></h3>
<p> <i></i><font SIZE="-1">GPRINT</font><i></i>:<i>vname</i>:<i>format</i> </p>
<p> This is the same as <tt>&quot;PRINT&quot;</tt>, but printed inside the graph. </p>
<p> <i></i><font SIZE="-1">GPRINT</font><i></i>:<i>vname</i>:<i></i><font SIZE="-1"><i>CF</i></font><i></i>:<i>format</i> </p>
<p> <i>Deprecated. Use the new form of this command in new scripts.</i> This is the same as <tt>&quot;PRINT&quot;</tt>, but printed inside the graph. </p>
<p> <i></i><font SIZE="-1">COMMENT</font><i></i>:<i>text</i> </p>
<p> Text is printed literally in the legend section of the graph. Note that in RRDtool 1.2 you have to escape colons in <font SIZE="-1">COMMENT</font> text in the same way you have to escape them in <code>*PRINT</code> commands by writing <code>&#8216;\:&#8217;</code>. </p>
<p> <i></i><font SIZE="-1">VRULE</font><i></i>:<i>time</i>#<i>color[</i>:<i>legend][</i>:dashes<i>[</i>=<i>on_s[,off_s[,on_s,off_s]&#8230;]][</i>:dash-offset=<i>offset]]</i> </p>
<p> Draw a vertical line at <i>time</i>. Its color is composed from three hexadecimal numbers specifying the rgb color components (00 is off, <font SIZE="-1">FF</font> is maximum) red, green and blue followed by an optional alpha. Optionally, a legend box and string is printed in the legend section. <i>time</i> may be a number or a variable from a <font SIZE="-1"><code>VDEF</code></font>. It is an error to use <i>vname</i>s from <font SIZE="-1"><code>DEF</code></font> or <font SIZE="-1"><code>CDEF</code></font> here. Dashed lines can be drawn using the <code>dashes</code> modifier. See <font SIZE="-1"><code>LINE</code></font> for more details. </p>
<p> <i></i><font SIZE="-1">HRULE</font><i></i>:<i>value</i>#<i>color[</i>:<i>legend][</i>:dashes<i>[</i>=<i>on_s[,off_s[,on_s,off_s]&#8230;]][</i>:dash-offset=<i>offset]]</i> </p>
<p> Draw a horizontal line at <i>value</i>. <font SIZE="-1">HRULE</font> acts much like <font SIZE="-1">LINE</font> except that will have no effect on the scale of the graph. If a <font SIZE="-1">HRULE</font> is outside the graphing area it will just not be visible. </p>
<p> <i></i><font SIZE="-1">LINE</font><i>[width]</i>:<i>value[</i>#<i>color][</i>:<i>[legend][</i>:STACK<i>][</i>:skipscale<i>]][</i>:dashes<i>[</i>=<i>on_s[,off_s[,on_s,off_s]&#8230;]][</i>:dash-offset=<i>offset]]</i> </p>
<p> Draw a line of the specified width onto the graph. <i>width</i> can be a floating point number. If the color is not specified, the drawing is done &#8216;invisibly&#8217;. This is useful when stacking something else on top of this line. Also optional is the legend box and string which will be printed in the legend section if specified. The <code>value</code> can be generated by <font SIZE="-1"><code>DEF</code></font>, <font SIZE="-1"><code>VDEF</code></font>, and <font SIZE="-1"><code>CDEF</code></font>. If the optional <font SIZE="-1"><code>STACK</code></font> modifier is used, this line is stacked on top of the previous element which can be a <font SIZE="-1"><code>LINE</code></font> or an <font SIZE="-1"><code>AREA</code></font>. </p>
<p> Normally the graphing function makes sure that the entire <font SIZE="-1"><code>LINE</code></font> or <font SIZE="-1"><code>AREA</code></font> is visible in the chart. The scaling of the chart will be modified accordingly if necessary. Any <font SIZE="-1"><code>LINE</code></font> or <font SIZE="-1"><code>AREA</code></font> can be excluded from this process by adding the option <code>skipscale</code>. </p>
<p> The <code>dashes</code> modifier enables dashed line style. Without any further options a symmetric dashed line with a segment length of 5 pixels will be drawn. The dash pattern can be changed if the <code>dashes=</code> parameter is followed by either one value or an even number (1, 2, 4, 6, &#8230;) of positive values. Each value provides the length of alternate <i>on_s</i> and <i>off_s</i> portions of the stroke. The <code>dash-offset</code> parameter specifies an <i>offset</i> into the pattern at which the stroke begins. </p>
<p> When you do not specify a color, you cannot specify a legend. Should you want to use <font SIZE="-1"><code>STACK</code></font>, use the &#8220;LINEx:&lt;value&gt;::STACK&#8221; form. </p>
<p> <i></i><font SIZE="-1">AREA</font><i></i>:<i>value[</i>#<i>color][</i>:<i>[legend][</i>:STACK<i>][</i>:skipscale<i>]]</i> </p>
<p> See <font SIZE="-1"><code>LINE</code></font>, however the area between the x-axis and the line will be filled. </p>
<p> <i></i><font SIZE="-1">TICK</font><i></i>:<i>vname</i>#<i>rrggbb[aa][</i>:<i>fraction[</i>:<i>legend]]</i> </p>
<p> Plot a tick mark (a vertical line) for each value of <i>vname</i> that is non-zero and not *UNKNOWN*. The <i>fraction</i> argument specifies the length of the tick mark as a fraction of the y-axis; the default value is 0.1 (10% of the axis). Note that the color specification is not optional. The <font SIZE="-1">TICK</font> marks normally start at the lower edge of the graphing area. If the fraction is negative they start at the upper border of the graphing area. </p>
<p> <i></i><font SIZE="-1">SHIFT</font><i></i>:<i>vname</i>:<i>offset</i> </p>
<p> Using this command <code>RRDtool</code> will graph the following elements with the specified offset. For instance, you can specify an offset of (&nbsp;<wbr>7*24*60*60&nbsp;<wbr>=&nbsp;<wbr>)&nbsp;<wbr>604&#8217;800 seconds to &#8220;look back&#8221; one week. Make sure to tell the viewer of your graph you did this &#8230; As with the other graphing elements, you can specify a number or a variable here. </p>
<p> <i></i><font SIZE="-1">TEXTALIGN</font><i></i>:<i>{</i>left<i>|</i>right<i>|</i>justified<i>|</i>center<i>}</i> </p>
<p> Labels are placed below the graph. When they overflow to the left, they wrap to the next line. By default, lines are justified left and right. The <font SIZE="-1"><code>TEXTALIGN</code></font> function lets you change this default. This is a command and not an option, so that you can change the default several times in your argument list. </p>
<p> <i></i><font SIZE="-1">STACK</font><i></i>:<i>vname</i>#<i>color[</i>:<i>legend]</i> </p>
<p> <i>Deprecated. Use the </i><font SIZE="-1">STACK</font><i> modifiers on the other commands instead!</i> </p>
<p> <code>Some notes on stacking</code> </p>
<p> When stacking, an element is not placed above the X-axis but rather on top of the previous element. There must be something to stack upon. </p>
<p> You can use an <code>invisible</code> <font SIZE="-1">LINE</font> or <font SIZE="-1">AREA</font> to stacked upon. </p>
<p> An <code>unknown</code> value makes the entire stack unknown from that moment on. You don&#8217;t know where to begin (the unknown value) and therefore do not know where to end. </p>
<p> If you want to make sure you will be displaying a certain variable, make sure never to stack upon the unknown value. Use a <font SIZE="-1">CDEF</font> instruction with <font SIZE="-1"><code>IF</code></font> and <font SIZE="-1"><code>UN</code></font> to do so.</p>
<h2>NOTES on legend arguments</h2>
<h3>Escaping the colon</h3>
<p> A colon &#8216;:&#8217; in a <i>legend</i> argument will mark the end of the legend. To enter a &#8216;:&#8217; as part of a legend, the colon must be escaped with a backslash &#8216;\:&#8217;. Beware that many environments process backslashes themselves, so it may be necessary to write two backslashes in order to one being passed onto rrd_graph.</p>
<h3>String Formatting</h3>
<p> The text printed below the actual graph can be formatted by appending special escape characters at the end of a text. When ever such a character occurs, all pending text is pushed onto the graph according to the character specified. </p>
<p> Valid markers are: <code>\j</code> for justified, <code>\l</code> for left aligned, <code></code> for right aligned, and <code>
