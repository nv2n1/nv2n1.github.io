<p> rrdgraph_graph - rrdtool graph command reference </p>
<h2>SYNOPSIS</h2>
<p> <code>PRINT</code><code>:</code><i>vname</i><code>:</code><i>format</i> </p>
<p> <code>GPRINT</code><code>:</code><i>vname</i><code>:</code><i>format</i> </p>
<p> <code>COMMENT</code><code>:</code><i>text</i> </p>
<p> <code>VRULE</code><code>:</code><i>time</i><code>#</code><i>color</i>[<code>:</code><i>legend</i>][<code>:dashes</code>[<code>=</code><i>on_s</i>[,<i>off_s</i>[,<i>on_s</i>,<i>off_s</i>]...]][<code>:dash-offset=</code><i>offset</i>]] </p>
<p> <code>HRULE</code><code>:</code><i>value</i><code>#</code><i>color</i>[<code>:</code><i>legend</i>][<code>:dashes</code>[<code>=</code><i>on_s</i>[,<i>off_s</i>[,<i>on_s</i>,<i>off_s</i>]...]][<code>:dash-offset=</code><i>offset</i>]] </p>
<p> <code>LINE</code>[<i>width</i>]<code>:</code><i>value</i>[<code>#</code><i>color</i>][<code>:</code>[<i>legend</i>][<code>:STACK</code>][<code>:skipscale</code>][<code>:dashes</code>[<code>=</code><i>on_s</i>[,<i>off_s</i>[,<i>on_s</i>,<i>off_s</i>]...]][<code>:dash-offset=</code><i>offset</i>]] </p>
<p> <code>AREA</code><code>:</code><i>value</i>[<code>#</code><i>color</i>][<code>:</code>[<i>legend</i>][<code>:STACK</code>][<code>:skipscale</code>]] </p>
<p> <code>TICK</code><code>:</code><i>vname</i><code>#</code><i>rrggbb</i>[<i>aa</i>][<code>:</code><i>fraction</i>[<code>:</code><i>legend</i>]] </p>
<p> <code>SHIFT</code><code>:</code><i>vname</i><code>:</code><i>offset</i> </p>
<p> <code>TEXTALIGN</code><code>:</code>{<code>left</code>|<code>right</code>|<code>justified</code>|<code>center</code>} </p>
<p> <code>PRINT</code><code>:</code><i>vname</i><code>:</code><i></i><i>CF</i><i></i><code>:</code><i>format</i> (deprecated) </p>
<p> <code>GPRINT</code><code>:</code><i>vname</i><code>:</code><i></i><i>CF</i><i></i><code>:</code><i>format</i> (deprecated) </p>
<p> <code>STACK</code><code>:</code><i>vname</i><code>#</code><i>color</i>[<code>:</code><i>legend</i>] (deprecated)  </p>
<h2>DESCRIPTION</h2>
<p> These instructions allow you to generate your image or report. If you don&#8217;t use any graph elements, no graph is generated. Similarly, no report is generated if you don&#8217;t use print options.  </p>
<h3>PRINT</h3>
<p> <i></i>PRINT:<i>vname</i>:<i>format[</i>:strftime <i>]</i> </p>
<p> Depending on the context, either the value component or the time component of a <code>VDEF</code> is printed using <i>format</i>. It is an error to specify a <i>vname</i> generated by a <code>DEF</code> or <code>CDEF</code>. </p>
<p> Any text in <i>format</i> is printed literally with one exception: The percent character introduces a formatter string. This string can be: </p>
<p> For printing values: </p>
<dl>
<dt><code>%%</code></dt>
<dd> <p> just prints a literal &#8216;%&#8216; character </p>
 </dd>
<dt><code>%#.#le</code></dt>
<dd> <p> prints numbers like 1.2346e+04. The optional integers # denote field width and decimal precision. </p>
 </dd>
<dt><code>%#.#lf</code></dt>
<dd> <p> prints numbers like 12345.6789, with optional field width and precision. </p>
 </dd>
<dt><code>%s</code></dt>
<dd> <p> place this after %le, %lf or %lg. This will be replaced by the appropriate SI magnitude unit and the value will be scaled accordingly (123456 -&gt; 123.456 k). </p>
 </dd>
<dt><code>%S</code></dt>
<dd> <p> is similar to %s. It does, however, use a previously defined magnitude unit. If there is no such unit yet, it tries to define one (just like %s) unless the value is zero, in which case the magnitude unit stays undefined. Thus, formatter strings using %S and no %s will all use the same magnitude unit except for zero values. </p>
 </dd></dl>
<p> If you PRINT a VDEF value, you can also print the time associated with it by appending the string <code>:strftime</code> to the format. Note that RRDtool uses the strftime function of your OSs C library. This means that the conversion specifier may vary. Check the manual page if you are uncertain. The following is a list of conversion specifiers usually supported across the board. </p>
<dl>
<dt><code>%a</code></dt>
<dd> <p> The abbreviated weekday name according to the current locale. </p>
 </dd>
<dt><code>%A</code></dt>
<dd> <p> The full weekday name according to the current locale. </p>
 </dd>
<dt><code>%b</code></dt>
<dd> <p> The abbreviated month name according to the current locale. </p>
 </dd>
<dt><code>%B</code></dt>
<dd> <p> The full month name according to the current locale. </p>
 </dd>
<dt><code>%c</code></dt>
<dd> <p> The preferred date and time representation for the current locale. </p>
 </dd>
<dt><code>%d</code></dt>
<dd> <p> The day of the month as a decimal number (range 01 to 31). </p>
 </dd>
<dt><code>%H</code></dt>
<dd> <p> The hour as a decimal number using a 24-hour clock (range 00 to 23). </p>
 </dd>
<dt><code>%I</code></dt>
<dd> <p> The hour as a decimal number using a 12-hour clock (range 01 to 12). </p>
 </dd>
<dt><code>%j</code></dt>
<dd> <p> The day of the year as a decimal number (range 001 to 366). </p>
 </dd>
<dt><code>%m</code></dt>
<dd> <p> The month as a decimal number (range 01 to 12). </p>
 </dd>
<dt><code>%M</code></dt>
<dd> <p> The minute as a decimal number (range 00 to 59). </p>
 </dd>
<dt><code>%p</code></dt>
<dd> <p> Either `AM&#8216; or `PM&#8216; according to the given time value, or the corresponding strings for the current locale. Noon is treated as `pm&#8217; and midnight as `am&#8217;. Note that in many locales and `pm&#8217; notation is unsupported and in such cases <code>%p</code> will return an empty string. </p>
 </dd>
<dt><code>%s</code></dt>
<dd> <p> The second as a decimal number (range 00 to 61). </p>
 </dd>
<dt><code>%S</code></dt>
<dd> <p> The seconds since the epoch (1.1.1970) (libc dependent non standard!) </p>
 </dd>
<dt><code>%U</code></dt>
<dd> <p> The week number of the current year as a decimal number, range 00 to 53, starting with the first Sunday as the first day of week 01. See also <code>%V</code> and <code>%W</code>. </p>
 </dd>
<dt><code>%V</code></dt>
<dd> <p> The ISO 8601:1988 week number of the current year as a decimal number, range 01 to 53, where week 1 is the first week that has at least 4 days in the current year, and with Monday as the first day of the week. See also <code>%U</code> and <code>%W</code>. </p>
 </dd>
<dt><code>%w</code></dt>
<dd> <p> The day of the week as a decimal, range 0 to 6, Sunday being 0. See also <code>%u</code>. </p>
 </dd>
<dt><code>%W</code></dt>
<dd> <p> The week number of the current year as a decimal number, range 00 to 53, starting with the first Monday as the first day of week 01. </p>
 </dd>
<dt><code>%x</code></dt>
<dd> <p> The preferred date representation for the current locale without the time. </p>
 </dd>
<dt><code>%X</code></dt>
<dd> <p> The preferred time representation for the current locale without the date. </p>
 </dd>
<dt><code>%y</code></dt>
<dd> <p> The year as a decimal number without a century (range 00 to 99). </p>
 </dd>
<dt><code>%Y</code></dt>
<dd> <p> The year as a decimal number including the century. </p>
 </dd>
<dt><code>%Z</code></dt>
<dd> <p> The time zone or name or abbreviation. </p>
 </dd>
<dt><code>%%</code></dt>
<dd> <p> A literal `%&#8216; character. </p>
 </dd></dl>
<p> <i></i>PRINT:<i>vname</i>:<i></i><i>CF</i><i></i>:<i>format</i> </p>
<p> <i>Deprecated. Use the new form of this command in new scripts.</i> The first form of this command is to be used with <code>CDEF</code> <i>vname</i>s.  </p>
<h3>GRAPH</h3>
<p> <i></i>GPRINT<i></i>:<i>vname</i>:<i>format</i> </p>
<p> This is the same as <code>&quot;PRINT&quot;</code>, but printed inside the graph. </p>
<p> <i></i>GPRINT<i></i>:<i>vname</i>:<i></i><i>CF</i><i></i>:<i>format</i> </p>
<p> <i>Deprecated. Use the new form of this command in new scripts.</i> This is the same as <code>&quot;PRINT&quot;</code>, but printed inside the graph. </p>
<p> <i></i>COMMENT<i></i>:<i>text</i> </p>
<p> Text is printed literally in the legend section of the graph. Note that in RRDtool 1.2 you have to escape colons in COMMENT text in the same way you have to escape them in <code>*PRINT</code> commands by writing <code>&#8216;\:&#8216;</code>. </p>
<p> <i></i>VRULE<i></i>:<i>time</i>#<i>color[</i>:<i>legend][</i>:dashes <i>[</i>=<i>on_s[,off_s[,on_s,off_s]...]][</i>:dash-offset=<i>offset]]</i> </p>
<p> Draw a vertical line at <i>time</i>. Its color is composed from three hexadecimal numbers specifying the rgb color components (00 is off, FF is maximum) red, green and blue followed by an optional alpha. Optionally, a legend box and string is printed in the legend section. <i>time</i> may be a number or a variable from a <code>VDEF</code>. It is an error to use <i>vname</i>s from <code>DEF</code> or <code>CDEF</code> here. Dashed lines can be drawn using the <code>dashes</code> modifier. See <code>LINE</code> for more details. </p>
<p> <i></i>HRULE<i></i>:<i>value</i>#<i>color[</i>:<i>legend][</i>:dashes <i>[</i>=<i>on_s[,off_s[,on_s,off_s]...]][</i>:dash-offset=<i>offset]]</i> </p>
<p> Draw a horizontal line at <i>value</i>. HRULE acts much like LINE except that will have no effect on the scale of the graph. If a HRULE is outside the graphing area it will just not be visible. </p>
<p> <i></i>LINE<i>[width]</i>:<i>value[</i>#<i>color][</i>:<i>[legend][</i>:STACK <i>][</i>:skipscale <i>]][</i>:dashes <i>[</i>=<i>on_s[,off_s[,on_s,off_s]...]][</i>:dash-offset=<i>offset]]</i> </p>
<p> Draw a line of the specified width onto the graph. <i>width</i> can be a floating point number. If the color is not specified, the drawing is done &#8216;invisibly&#8217;. This is useful when stacking something else on top of this line. Also optional is the legend box and string which will be printed in the legend section if specified. The <code>value</code> can be generated by <code>DEF</code>, <code>VDEF</code>, and <code>CDEF</code>. If the optional <code>STACK</code> modifier is used, this line is stacked on top of the previous element which can be a <code>LINE</code> or an <code>AREA</code>. </p>
<p> Normally the graphing function makes sure that the entire <code>LINE</code> or <code>AREA</code> is visible in the chart. The scaling of the chart will be modified accordingly if necessary. Any <code>LINE</code> or <code>AREA</code> can be excluded from this process by adding the option <code>skipscale</code>. </p>
<p> The <code>dashes</code> modifier enables dashed line style. Without any further options a symmetric dashed line with a segment length of 5 pixels will be drawn. The dash pattern can be changed if the <code>dashes=</code> parameter is followed by either one value or an even number (1, 2, 4, 6, ...) of positive values. Each value provides the length of alternate <i>on_s</i> and <i>off_s</i> portions of the stroke. The <code>dash-offset</code> parameter specifies an <i>offset</i> into the pattern at which the stroke begins. </p>
<p> When you do not specify a color, you cannot specify a legend. Should you want to use <code>STACK</code>, use the ``LINEx:&lt;value&gt;::STACK&#8217;&#8216; form. </p>
<p> <i></i>AREA<i></i>:<i>value[</i>#<i>color][</i>:<i>[legend][</i>:STACK <i>][</i>:skipscale <i>]]</i> </p>
<p> See <code>LINE</code>, however the area between the x-axis and the line will be filled. </p>
<p> <i></i>TICK<i></i>:<i>vname</i>#<i>rrggbb[aa][</i>:<i>fraction[</i>:<i>legend]]</i> </p>
<p> Plot a tick mark (a vertical line) for each value of <i>vname</i> that is non-zero and not *UNKNOWN*. The <i>fraction</i> argument specifies the length of the tick mark as a fraction of the y-axis; the default value is 0.1 (10% of the axis). Note that the color specification is not optional. The TICK marks normally start at the lower edge of the graphing area. If the fraction is negative they start at the upper border of the graphing area. </p>
<p> <i></i>SHIFT<i></i>:<i>vname</i>:<i>offset</i> </p>
<p> Using this command <code>RRDtool</code> will graph the following elements with the specified offset. For instance, you can specify an offset of (&nbsp;<wbr>7*24*60*60&nbsp;<wbr>=&nbsp;<wbr>)&nbsp;<wbr>604&#8217;800 seconds to ``look back&#8217;&#8216; one week. Make sure to tell the viewer of your graph you did this ... As with the other graphing elements, you can specify a number or a variable here. </p>
<p> <i></i>TEXTALIGN<i></i>:<i>{</i>left <i>|</i>right <i>|</i>justified <i>|</i>center <i>}</i> </p>
<p> Labels are placed below the graph. When they overflow to the left, they wrap to the next line. By default, lines are justified left and right. The <code>TEXTALIGN</code> function lets you change this default. This is a command and not an option, so that you can change the default several times in your argument list. </p>
<p> <i></i>STACK<i></i>:<i>vname</i>#<i>color[</i>:<i>legend]</i> </p>
<p> <i>Deprecated. Use the </i>STACK<i> modifiers on the other commands instead!</i> </p>
<p> <code>Some notes on stacking</code> </p>
<p> When stacking, an element is not placed above the X-axis but rather on top of the previous element. There must be something to stack upon. </p>
<p> You can use an <code>invisible</code> LINE or AREA to stacked upon. </p>
<p> An <code>unknown</code> value makes the entire stack unknown from that moment on. You don&#8217;t know where to begin (the unknown value) and therefore do not know where to end. </p>
<p> If you want to make sure you will be displaying a certain variable, make sure never to stack upon the unknown value. Use a CDEF instruction with <code>IF</code> and <code>UN</code> to do so.  </p>
<h2>NOTES on legend arguments</h2>
<h3>Escaping the colon</h3>
<p> A colon &#8216;:&#8216; in a <i>legend</i> argument will mark the end of the legend. To enter a &#8216;:&#8216; as part of a legend, the colon must be escaped with a backslash &#8216;\:&#8216;. Beware that many environments process backslashes themselves, so it may be necessary to write two backslashes in order to one being passed onto rrd_graph.  </p>
<h3>String Formatting</h3>
<p> The text printed below the actual graph can be formatted by appending special escape characters at the end of a text. When ever such a character occurs, all pending text is pushed onto the graph according to the character specified. </p>
<p> Valid markers are: <code>\j</code> for justified, <code>\l</code> for left aligned, <code>\r</code> for right aligned, and <code>\c</code> for centered. In the next section there is an example showing how to use centered formatting. </p>
<p> <code>\n</code> is a valid alias for <code>\l</code> since incomplete parsing in earlier versions of RRDtool lead to this behavior and a number of people has been using it. </p>
<p> Normally there are two space characters inserted between every two items printed into the graph. The space following a string can be suppressed by putting a <code>\g</code> at the end of the string. The <code>\g</code> also ignores any space inside the string if it is at the very end of the string. This can be used in connection with %s to suppress empty unit strings. </p>
<pre><code> GPRINT:a:MAX:%lf%s\g
</code></pre>
<p> A special case is COMMENT:<code>\s</code> which inserts some additional vertical space before placing the next row of legends. </p>
<p> If you want to have left and right aligned legends on the same line use COMMENT:<code>\u</code> to go one line back like this: </p>
<pre><code> COMMENT:left\l
 COMMENT:\u
 COMMENT:right\r
</code></pre>
<p> There is also a &#8216;nop&#8217; control for situations where you want a string to actually end in a backslash character sequence <code>\.</code> </p>
<pre><code> COMMENT:OS\2\.
</code></pre>
<p> When using a proportional font in your graph, the tab characters or the sequence <code>\t</code> will line-up legend elements. Note that the tabs inserted are relative to the start of the current legend element! </p>
<p> Since RRDtool 1.3 is using Pango for rending text, you can use Pango markup. Pango uses the xml <code>span</code> tags for inline formatting instructions.: </p>
<p> A simple example of a marked-up string might be: </p>
<pre><code> &lt;span foreground=&quot;blue&quot; size=&quot;x-large&quot;&gt;Blue text&lt;/span&gt; is &lt;i&gt;cool&lt;/i&gt;!
</code></pre>
<p> The complete list of attributes for the span tag (taken from the pango documentation): </p>
<dl>
<dt><code>font_desc</code></dt>
<dd> <p> A font description string, such as ``Sans Italic 12&#8217;&#8216;; note that any other span attributes will override this description. So if you have ``Sans Italic&#8217;&#8216; and also a style=``normal&#8217;&#8216; attribute, you will get Sans normal, not italic. </p>
 </dd>
<dt><code>font_family</code></dt>
<dd> <p> A font family name </p>
 </dd>
<dt><code>face</code></dt>
<dd> <p> Synonym for font_family </p>
 </dd>
<dt><code>size</code></dt>
<dd> <p> Font size in 1024ths of a point, or one of the absolute sizes &#8216;xx-small&#8217;, &#8216;x-small&#8217;, &#8216;small&#8217;, &#8216;medium&#8217;, &#8216;large&#8217;, &#8216;x-large&#8217;, &#8216;xx-large&#8217;, or one of the relative sizes &#8216;smaller&#8217; or &#8216;larger&#8217;. If you want to specify a absolute size, it&#8217;s usually easier to take advantage of the ability to specify a partial font description using &#8216;font_desc&#8217;; you can use font_desc=&#8216;12.5&#8217; rather than size=&#8216;12800&#8217;. </p>
 </dd>
<dt><code>style</code></dt>
<dd> <p> One of &#8216;normal&#8217;, &#8216;oblique&#8217;, &#8216;italic&#8217; </p>
 </dd>
<dt><code>weight</code></dt>
<dd> <p> One of &#8216;ultralight&#8217;, &#8216;light&#8217;, &#8216;normal&#8217;, &#8216;bold&#8217;, &#8216;ultrabold&#8217;, &#8216;heavy&#8217;, or a numeric weight </p>
 </dd>
<dt><code>variant</code></dt>
<dd> <p> &#8216;normal&#8217; or &#8216;smallcaps&#8217; </p>
 </dd>
<dt><code>stretch</code></dt>
<dd> <p> One of &#8216;ultracondensed&#8217;, &#8216;extracondensed&#8217;, &#8216;condensed&#8217;, &#8216;semicondensed&#8217;, &#8216;normal&#8217;, &#8216;semiexpanded&#8217;, &#8216;expanded&#8217;, &#8216;extraexpanded&#8217;, &#8216;ultraexpanded&#8217; </p>
 </dd>
<dt><code>foreground</code></dt>
<dd> <p> An RGB color specification such as &#8216;#00FF00&#8217; or a color name such as &#8216;red&#8217; </p>
 </dd>
<dt><code>background</code></dt>
<dd> <p> An RGB color specification such as &#8216;#00FF00&#8217; or a color name such as &#8216;red&#8217; </p>
 </dd>
<dt><code>underline</code></dt>
<dd> <p> One of &#8216;none&#8217;, &#8216;single&#8217;, &#8216;double&#8217;, &#8216;low&#8217;, &#8216;error&#8217; </p>
 </dd>
<dt><code>underline_color</code></dt>
<dd> <p> The color of underlines; an RGB color specification such as &#8216;#00FF00&#8217; or a color name such as &#8216;red&#8217; </p>
 </dd>
<dt><code>rise</code></dt>
<dd> <p> Vertical displacement, in 10000ths of an em. Can be negative for subscript, positive for superscript. </p>
 </dd>
<dt><code>strikethrough</code></dt>
<dd> <p> &#8216;true&#8217; or &#8216;false&#8217; whether to strike through the text </p>
 </dd>
<dt><code>strikethrough_color</code></dt>
<dd> <p> The color of crossed out lines; an RGB color specification such as &#8216;#00FF00&#8217; or a color name such as &#8216;red&#8217; </p>
 </dd>
<dt><code>fallback</code></dt>
<dd> <p> &#8216;true&#8217; or &#8216;false&#8217; whether to enable fallback. If disabled, then characters will only be used from the closest matching font on the system. No fallback will be done to other fonts on the system that might contain the characters in the text. Fallback is enabled by default. Most applications should not disable fallback. </p>
 </dd>
<dt><code>lang</code></dt>
<dd> <p> A language code, indicating the text language </p>
 </dd>
<dt><code>letter_spacing</code></dt>
<dd> <p> Inter-letter spacing in 1024ths of a point. </p>
 </dd>
<dt><code>gravity</code></dt>
<dd> <p> One of &#8216;south&#8217;, &#8216;east&#8217;, &#8216;north&#8217;, &#8216;west&#8217;, &#8216;auto&#8217;. </p>
 </dd>
<dt><code>gravity_hint</code></dt>
<dd> <p> One of &#8216;natural&#8217;, &#8216;strong&#8217;, &#8216;line&#8217;. </p>
 </dd></dl>
<p> To save you some typing, there are also some shortcuts: </p>
<dl>
<dt><code>b</code></dt>
<dd> <p> Bold </p>
 </dd>
<dt><code>big</code></dt>
<dd> <p> Makes font relatively larger, equivalent to &lt;span size=``larger&#8217;&#8216;&gt; </p>
 </dd>
<dt><code>i</code></dt>
<dd> <p> Italic </p>
 </dd>
<dt><code>s</code></dt>
<dd> <p> Strike through </p>
 </dd>
<dt><code>sub</code></dt>
<dd> <p> Subscript </p>
 </dd>
<dt><code>sup</code></dt>
<dd> <p> Superscript </p>
 </dd>
<dt><code>small</code></dt>
<dd> <p> Makes font relatively smaller, equivalent to &lt;span size=``smaller&#8217;&#8216;&gt; </p>
 </dd>
<dt><code>tt</code></dt>
<dd> <p> Monospace font </p>
 </dd>
<dt><code>u</code></dt>
<dd> <p> Underline </p>
 </dd></dl>
