<h2 class="name">NAME</h2>
<p> patgen &#8211; generate patterns for TeX hyphenation </p>
<h2>SYNOPSIS</h2>
<p> <code>patgen</code> <i>dictionary_file pattern_file patout_file translate_file</i></p>
<h2>DESCRIPTION</h2>
<p> This manual page is not meant to be exhaustive. See also the Info file or manual <i>Web2C: A TeX implementation </i> available as part of the TeX Live distribution or at <i><a rel="nofollow" href="http://tug.org/web2c">http://tug.org/web2c</a></i>. </p>
<p> The <i>patgen</i> program reads the <i>dictionary_file</i> containing a list of hyphenated words and the <i>pattern_file</i> containing previously-generated patterns (if any) for a particular language (not a complete TeX source file; see below), and produces the <i>patout_file</i> with (previously- plus newly-generated) hyphenation patterns for that language. The <i>translate_file</i> defines language specific values for the parameters <i>left_hyphen_min</i> and <i>right_hyphen_min</i> used by TeX&#8217;s hyphenation algorithm and the external representation of the lower and upper case version(s) of all `letters&#8217; of that language. Further details of the pattern generation process such as hyphenation levels and pattern lengths are requested interactively from the user&#8217;s terminal. Optionally <i>patgen</i> creates a new dictionary file <code>pattmp.</code><i>n</i> showing the good and bad hyphens found by the generated patterns, where <i>n</i> is the highest hyphenation level. </p>
<p> The patterns generated by <i>patgen</i> can be read by <code>initex</code> for use in hyphenating words. For a real-life example of <i>patgen</i>&#8216;s output, see <i>$TEXMFMAIN/tex/generic/hyphen/hyphen.tex</i>, which contains the patterns TeX uses for English by default. At some sites, patterns for (many) other languages may be available, and the local <code>tex</code> programs may have them preloaded. </p>
<p> All filenames must be complete; no adding of default extensions or path searching is done.</p>
<h2>FILE FORMATS</h2>
<dl>
<dt><code>Letters</code></p>
<dd> When <code>initex</code> digests hyphenation patterns, TeX first expands macros and the result must entirely consist of digits (hyphenation levels), dots (`.&#8217;, edge of a word), and letters. In pattern files for non-English languages letters are often represented by macros or other expandable constructs. For the purpose of <i>patgen</i> these are just character sequences, subject to the condition that no such sequence is a prefix of another one.</p>
<dt><code>Dictionary file</code></p>
<dd> A dictionary file contains a weighted list of hyphenated words, one word per line starting in column 1. A digit in column 1 indicates a global word weight (initially =1) applicable to all following words up to the next global word weight. A digit at some intercharacter position indicates a weight for that position only. </p>
<p> The hyphens in a word are indicated by `-&#8216;, `*&#8217;, or `.&#8217; (or their replacements as defined in the translate file) for hyphens yet to be found, `good&#8217; hyphens (correctly found by the patterns), and `bad&#8217; hyphens (erroneously found by the patterns) respectively; when reading a dictionary file `*&#8217; is treated like `-&#8216; and `.&#8217; is ignored.</p>
<dt><code>Pattern file</code></p>
<dd> A pattern file contains only patterns in the format above, e.g., from a previous run of patgen. It may <i>not</i> contain any TeX comments or control sequences. For instance, this is not a valid pattern file: </p>
<pre>
% this is a pattern file read by TeX.
\patterns{%
 ...
}
</pre>
<p> It can only contain the actual patterns, i.e., the `&#8230;&#8217;.</p>
<dt><code>Translate file</code></p>
<dd> A translate file starts with a line containing the values of <i>left_hyphen_min</i> in columns 1-2, <i>right_hyphen_min</i> in columns 3-4, and either a blank or the replacement for one of the &quot;hyphen&quot; characters `-&#8216;, `*&#8217;, and `.&#8217; in columns 5, 6, and 7. (Input lines are padded with blanks as for many TeX related programs.) </p>
<p> Each following line defines one `letter&#8217;: an arbitrary delimiter character in column 1, followed by one or more external representations of that character (first the `lower&#8217; case one used for output), each one terminated by the delimiter and the whole sequence terminated by another delimiter. </p>
<p> If the translate file is empty, the values <i>left_hyphen_min</i>=2, <i>right_hyphen_min</i>=3, and the 26 lower case letters <code>a</code>&#8230;<code>z</code> with their upper case representations <code>A</code>&#8230;<code>Z</code> are assumed.</p>
<dt><code>Terminal input</code></p>
<dd> After reading the <i>translate_file</i> and any previously-generated patterns from <i>pattern_file</i>, <i>patgen</i> requests input from the user&#8217;s terminal. </p>
<p> First the integer values of <i>hyph_start</i> and <i>hyph_finish</i>, the lowest and highest hyphenation level for which patterns are to be generated. The value of <i>hyph_start</i> should be larger than any hyphenation level already present in <i>pattern_file</i>. </p>
<p> Then, for each hyphenation level, the integer values of <i>pat_start</i> and <i>pat_finish</i>, the smallest and largest pattern length to be analyzed, as well as <i>good weight</i>, <i>bad weight</i>, and <i>threshold</i>, the weights for good and bad hyphens and a weight threshold for useful patterns. </p>
<p> Finally the decision (`y&#8217; or `Y&#8217; vs. anything else) whether or not to produce a hyphenated word list.</dl>
