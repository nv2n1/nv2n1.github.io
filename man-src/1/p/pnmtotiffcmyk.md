<h2 class="name">NAME</h2>
<p> pnmtotiffcmyk &#8211; convert a portable anymap into a CMYK encoded TIFF file </p>
<h2>SYNOPSIS</h2>
<p> <code>pnmtotiffcmyk </code> [<code>Compargs</code>][<code>Tiffargs</code>][<code>Convargs</code>][ <i>pnmfile</i> ]</p>
<dl>
<dt>Compargs:</p>
<dd> [<code>-none</code>|<code>-packbits</code>|<code>-lzw</code> [<code>-predictor</code> <i>n</i>]]</p>
<dt>Tiffargs:</p>
<dd> [<code>-msb2lsb</code>|<code>-lsb2msb</code>] [<code>-rowsperstrip</code> <i>n</i>]<br />
 [<code>-lowdotrange</code> <i>n</i>] [<code>-highdotrange</code> <i>n</i>]<br />
 [<code>-knormal</code>|<code>-konly</code>|<code>-kremove</code>] </p>
<dt>Convargs:</p>
<dd> [[<code>-default</code>][<code>Defargs</code>]|<code>-negative</code>]</p>
<dt>Defargs:</p>
<dd> [<code>-theta</code> <i>deg</i>] [<code>-gamma</code> <i>n</i>] [<code>-gammap</code> <i>-1</i>|<code>-gammap</code> <i>n</i>]</dl>
<h2>DESCRIPTION</h2>
<p> Reads a portable anymap as input. Produces a CMYK encoded TIFF file as output. Optionally modifies the colour balance and black level, and removes CMY from under K.</p>
<h2>OPTIONS</h2>
<p> The order of most options is not important, but options for particular conversion algorithms must appear after the algorithm is selected (<code>-default</code>,<code>-negative</code>). If no algorithm is selected then <code>-default</code> is assumed and the appropriate options (<code>-theta</code>,<code>-gamma</code>,<code>-gammap</code>) can appear anywhere.</p>
<dl>
<dt><code>-none</code>,<code>-packbits</code>,<code>-lzw</code>,<code>-predictor</code></p>
<dd> Tiff files can be compressed. By default LZW decompression is used, but (apparently) some readers cannot read this, so you may want to select a different algorithm (<code>-none</code>,<code>-packbits</code>). For LZW compression, a <code>-predictor</code> value of 2 forces horizontal differencing of scanlines before encoding; a value of 1 forces no differencing.</p>
<dt><code>-msb2lsb</code>,<code>-lsb2msb</code></p>
<dd> These flags control fill order (default is <code>-msb2lsb</code>).</p>
<dt><code>-rowsperstrip</code></p>
<dd> This sets the number of rows in an image strip (data in the Tiff files generated by this program is stored in strips &#8211; each strip is compressed individually). The default gives a strip size of no more than 8 kb.</p>
<dt><code>-lowdotrange</code>,<code>-highdotrange</code></p>
<dd> These options set tag values that may be useful for printers. They have not been tested.</p>
<dt><code>-knormal</code>,<code>-kremove</code>,<code>-konly</code></p>
<dd> These options modify the values written to the Tiff file after the conversion calculations (described below) are completed. They are useful only for testing and debugging the code. </p>
<p> <code>-kremove</code> sets the black (K) layer to zero while <code>-konly</code> sets all inks to the black value.</p>
<dt><code>-default</code>,<code>-negative</code></p>
<dd> <code>-negative</code> selects a simple algorithm that generates a colour negative. None of the following options apply to this algorithm, which is included as an example in the source to help implementors of other conversions. <code>-default</code> is not needed, unless it is used to countermand a <code>-negative</code> on the same command line. The default conversion from RGB to CMYK can be modified by altering the options listed below. </p>
<p> The CMYKTiff web site includes tests on the conversion parameters. The test images illustrate the command line options in practice and may make the following explanation clearer.</p>
<dt><code>-theta</code><i>&nbsp;deg</i></p>
<dd> The basic conversion from RGB to CMY uses C = 1-R, M = 1-G, Y = 1-B. <code>-theta</code> provides a simple correction for any colour bias that may occur in the printed image because, in practice, inks do not exactly complement the primary colours. It rotates the colours by the amount given (<i>deg</i>) in degrees. Unless you are trying to produce unusual effects you will need to use small values (try generating three images at -10, 0 (the default) and 10 degrees and seeing which has the best colour balance.</p>
<dt><code>-gamma</code><i>&nbsp;n</i></p>
<dd> The black (K) component of the image is calculated as min(C,Y,M). <code>-gamma</code> applies a gamma correction to this level. In other words, the final black level is K (normalised to the range 0 to 1) raised to the <i>n</i>th power. In practice this means that a value greater than 1 makes the image lighter and a value less than 1 makes the image darker. The range of allowed values is 0.1 to 10.</p>
<dt><code>-gammap</code><i>&nbsp;n</i></p>
<dd> This option controls the removal of CMY under K. If <i>n</i> is -1 then no removal occurs and C, M, Y and K are calculated as above. This means that, when printed, dark areas contain all four inks, which can make high contrast areas, like lettering, appear fuzzy. </p>
<p> By default, when <code>-gammap</code> is not given on the command line, the colours are reduced in dark areas by subtracting the black level. The value subtracted is calculated with the same gamma correction given by <code>-gamma</code>. Hopefully this will reduce fuzziness without changing the appearance of the image significantly. </p>
<p> If <code>-gammap</code><i>&nbsp;n</i> is given, with n between 0.01 and 10, then black is still subtracted, but the subtracted value is calculated using <i>n</i> rather than any value supplied with <code>-gamma</code>. For example, it may be best to only subtract black from the coloured inks in the very darkest regions. In that case, <i>n</i> should be a large value, such as 5.</dl>
<h2>BUGS</h2>
<p> This program is not self-contained. It must be used with NetPbm and libtiff must be available (libtiff is included in the 1mar94 release of NetPbm).</p>
