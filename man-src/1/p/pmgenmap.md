<h2>NAME</h2>
<p> <code>pmgenmap</code> &#8211; generate C code to simplify handling of performance metrics</p>
<h2>SYNOPSIS</h2>
<p> <code>pmgenmap</code> [<i>infile</i>]</p>
<h2>DESCRIPTION</h2>
<p> Given one or more lists of metric names in <i>infile</i> or on standard input, <code>pmgenmap</code> generates C declarations and <code><a href="/docs/linux/man/1-cpp/">cpp</a></code>(1) macros suitable for use across the Performance Metrics Programming Interface (PMAPI) on standard output. </p>
<p> The declarations produced by <code>pmgenmap</code> simplify the coding for client applications using the PMAPI. </p>
<p> The input should consist of one or more lists of metric names of the form </p>
<pre>
listname {
    metricname1 symbolname1
    metricname2 symbolname2
    ...
}
</pre>
<p> which will generate C and <code><a href="/docs/linux/man/1-cpp/">cpp</a></code>(1) declarations of the form </p>
<pre><code>
char *listname[] = {
#define symbolname1 0
    "metricname1",
#define symbolname2 1
    "metricname2",
    ...};
</code></pre>
<p> The array declarations produced are suitable as parameters to <code><a href="/docs/linux/man/3-pmlookupname/">pmLookupName</a></code>(3) and the <code>#define</code>d constants may be used to index the <i>vset</i>s in the <i>pmResult</i> structure returned by a <code><a href="/docs/linux/man/3-pmfetch/">pmFetch</a></code>(3) call. </p>
<p> Obviously, <i>listname</i> must conform to the C identifier naming rules, each <i>symbolname</i> must conform to the <code><a href="/docs/linux/man/1-cpp/">cpp</a></code>(1) macro naming rules, and each <i>metricname</i> is expected to be a valid performance metrics name (see <code><a href="/docs/linux/man/5-pmns/">pmns</a></code>(5) for more details). </p>
<p> The input may include <code>sh</code>-style comment lines, i.e. with a `<code>#</code>&#8216; as the first non-blank character of a line, and these are translated on output to either single line or multi-line C comments in the K&amp;R style. For example, the input: </p>
<pre>
# leading block of multi-line comments
# initialization group
foo {
        a.b.c   ONE
        d.e.f.g TWO
        # embedded block of multi-lines
        # comments and boring pad text
        xx.yy.zz        THREE
}
# trailing single line comment
</pre>
<p> Produces the output: </p>
<p>/*<br />
 * leading block of multi-line comments<br />
 * initialization group<br />
 */<br />
char *foo[] = {<br />
#define ONE 0<br />
    &#8220;a.b.c&#8221;,<br />
#define TWO 1<br />
    &#8220;d.e.f.g&#8221;,<br />
/*<br />
 * embedded block of multi-lines<br />
 * comments and boring pad text<br />
 */<br />
#define THREE 2<br />
    &#8220;xx.yy.zz&#8221;,<br />
};<br />
/* trailing single line comment */</p>
<h2>EXAMPLE</h2>
<p> For brevity we have removed the error handling code, and assumed the chosen metrics do not have multiple values. </p>
<p> The input file </p>
<pre>
mystats {
    kernel.percpu.cpu.idle     IDLE
    kernel.percpu.cpu.sys      SYS
    kernel.percpu.cpu.user     USER
    hinv.ncpu                       NCPU
}
</pre>
<p> produces the following C code, suitable for <code>#include</code>-ing </p>
<p>/*<br />
 * Performance Metrics Name Space Map<br />
 * Built by pmgenmap from the file<br />
 * mystats.metrics<br />
 * on Wed Dec 28 19:44:17 EST 1994<br />
 *<br />
 * Do not edit this file!<br />
 */<br />
char *mystats[] = {<br />
#define IDLE 0<br />
    &#8220;kernel.percpu.cpu.idle&#8221;,<br />
#define SYS 1<br />
    &#8220;kernel.percpu.cpu.sys&#8221;,<br />
#define USER 2<br />
    &#8220;kernel.percpu.cpu.user&#8221;,<br />
#define NCPU 3<br />
    &#8220;hinv.ncpu&#8221;,<br />
};</p>
<p> Using the code generated by <code>pmgenmap</code>, we are now able to easily obtain metrics from the Performance Metrics Collection Subsystem (PMCS) as follows: </p>
<pre><code>
#define MAX_PMID 4
int trip = 0;
int numpmid = sizeof(mystats) / sizeof(mystats[0]);
double duration;
pmResult *resp;
pmResult *prev;
pmID pmidlist[MAX_PMID];
pmNewContext(PM_CONTEXT_HOST, "localhost");
pmLookupName(numpmid, mystats, pmidlist);
pmFetch(numpmid, pmidlist, &amp;resp);
printf("%d CPUs: %d usr   %d sys   %d   idle, 
       resp-&gt;vset[NCPU]
           -&gt;vlist[0]
           .value.lval,
       resp-&gt;vset[USER]-&gt;vlist[0].value.lval,
       resp-&gt;vset[SYS]-&gt;vlist[0].value.lval,
       resp-&gt;vset[IDLE]-&gt;vlist[0].value.lval);
</code></pre>
<p> Some calls to ensure portability have been removed from the code above for the sake of clarity &#8211; the example above should not be used as a template for programming. In particular, the raw values of the metrics were used when <code><a href="/docs/linux/man/3-pmlookupdesc/">pmLookupDesc</a></code>(3) should have been called to determine the semantics of each metric. </p>
<p> More complete examples that demonstrate the use of <code>pmgenmap</code> which may be used as a basis for program development are included in the PCP demos, e.g. <i>$PCP_DEMOS_DIR/pmclient</i>.</p>
