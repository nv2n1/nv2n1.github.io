<h2 class="name">NAME</h2>
<p> pic &#8211; compile pictures for troff or TeX </p>
<h2>SYNOPSIS</h2>
<p> [ <code>-nvCSU</code> ] [<i>file</i> &#8230;] <code>-t</code> [ <code>-cvzCSU</code> ] [<i>file</i> &#8230;]</p>
<h2>DESCRIPTION</h2>
<p> This manual page describes the GNU version of <code>pic</code>, which is part of the groff document formatting system. <code>pic</code> compiles descriptions of pictures embedded within <code>troff</code> or TeX input files into commands that are understood by TeX or <code>troff</code>. Each picture starts with a line beginning with <code>.PS</code> and ends with a line beginning with <code>.PE</code>. Anything outside of <code>.PS</code> and <code>.PE</code> is passed through without change. </p>
<p> It is the user&#8217;s responsibility to provide appropriate definitions of the <code>PS</code> and <code>PE</code> macros. When the macro package being used does not supply such definitions (for example, old versions of -ms), appropriate definitions can be obtained with <code>-mpic</code>: These will center each picture.</p>
<h2>OPTIONS</h2>
<p> Options that do not take arguments may be grouped behind a single <code>&#8211;</code>. The special option <code>&#8212;</code> can be used to mark the end of the options. A filename of <code>&#8211;</code> refers to the standard input.</p>
<dl>
<dt><code>-C</code></p>
<dd> Recognize <code>.PS</code> and <code>.PE</code> even when followed by a character other than space or newline.</p>
<dt><code>-S</code></p>
<dd> Safer mode; do not execute <code>sh</code> commands. This can be useful when operating on untrustworthy input (enabled by default).</p>
<dt><code>-U</code></p>
<dd> Unsafe mode; revert the default option <code>-S</code>.</p>
<dt><code>-n</code></p>
<dd> Don&#8217;t use the groff extensions to the troff drawing commands. You should use this if you are using a postprocessor that doesn&#8217;t support these extensions. The extensions are described in <code><a href="/docs/linux/man/5-groff_out/">groff_out</a></code>(5). The <code>-n</code> option also causes <code>pic</code> not to use zero-length lines to draw dots in troff mode.</p>
<dt><code>-t</code></p>
<dd> TeX mode.</p>
<dt><code>-c</code></p>
<dd> Be more compatible with <code>tpic</code>. Implies <code>-t</code>. Lines beginning with <code>\</code> are not passed through transparently. Lines beginning with <code>.</code> are passed through with the initial <code>.</code> changed to <code>\</code>. A line beginning with <code>.ps</code> is given special treatment: it takes an optional integer argument specifying the line thickness (pen size) in milliinches; a missing argument restores the previous line thickness; the default line thickness is 8 milliinches. The line thickness thus specified takes effect only when a non-negative line thickness has not been specified by use of the <code>thickness</code> attribute or by setting the <code>linethick</code> variable.</p>
<dt><code>-v</code></p>
<dd> Print the version number.</p>
<dt><code>-z</code></p>
<dd> In TeX mode draw dots using zero-length lines.</dl>
<p> The following options supported by other versions of <code>pic</code> are ignored:</p>
<dl>
<dt><code>-D</code></p>
<dd> Draw all lines using the \D escape sequence. <code>pic</code> always does this.</p>
<dt><code>-T</code><i>&nbsp;dev</i></p>
<dd> Generate output for the <code>troff</code> device <i>dev</i>. This is unnecessary because the <code>troff</code> output generated by <code>pic</code> is device-independent.</dl>
