<p>perlapi &#8211; autogenerated documentation for the perl public API </p>
<h2>Description</h2>
<p>This file contains the documentation of the perl public <font SIZE="-1">API</font> generated by <i>embed.pl</i>, specifically a listing of functions, macros, flags, and variables that may be used by extension writers. At the end is a list of functions which have yet to be documented. The interfaces of those are subject to change without notice. Anything not listed here is not part of the public <font SIZE="-1">API,</font> and should not be used by extension writers at all. For these reasons, blindly using functions listed in proto.h is to be avoided when writing extensions. </p>
<p> In Perl, unlike C, a string of characters may generally contain embedded <tt>&quot;NUL&quot;</tt> characters. Sometimes in the documentation a Perl string is referred to as a &#8220;buffer&#8221; to distinguish it from a C string, but sometimes they are both just referred to as strings. </p>
<p> Note that all Perl <font SIZE="-1">API</font> global variables must be referenced with the <tt>&quot;PL_&quot;</tt> prefix. Again, those not listed here are not to be used by extension writers, and can be changed or removed without notice; same with macros. Some macros are provided for compatibility with the older, unadorned names, but this support may be disabled in a future release. </p>
<p> Perl was originally written to handle US-ASCII only (that is characters whose ordinal numbers are in the range 0 &#8211; 127). And documentation and comments may still use the term <font SIZE="-1">ASCII,</font> when sometimes in fact the entire range from 0 &#8211; 255 is meant. </p>
<p> The non-ASCII characters below 256 can have various meanings, depending on various things. (See, most notably, perllocale.) But usually the whole range can be referred to as <font SIZE="-1">ISO-8859-1.</font> Often, the term &#8220;Latin-1&#8221; (or &#8220;Latin1&#8221;) is used as an equivalent for <font SIZE="-1">ISO-8859-1.</font> But some people treat &#8220;Latin1&#8221; as referring just to the characters in the range 128 through 255, or somethimes from 160 through 255. This documentation uses &#8220;Latin1&#8221; and &#8220;Latin-1&#8221; to refer to all 256 characters. </p>
<p> Note that Perl can be compiled and run under either <font SIZE="-1">ASCII</font> or <font SIZE="-1">EBCDIC</font> (See perlebcdic). Most of the documentation (and even comments in the code) ignore the <font SIZE="-1">EBCDIC</font> possibility. For almost all purposes the differences are transparent. As an example, under <font SIZE="-1">EBCDIC,</font> instead of <font SIZE="-1">UTF-8,</font> UTF-EBCDIC is used to encode Unicode strings, and so whenever this documentation refers to <tt>&quot;utf8&quot;</tt> (and variants of that name, including in function names), it also (essentially transparently) means <tt>&quot;UTF-EBCDIC&quot;</tt>. But the ordinals of characters differ between <font SIZE="-1">ASCII, EBCDIC,</font> and the <font SIZE="-1">UTF-</font> encodings, and a string encoded in UTF-EBCDIC may occupy a different number of bytes than in <font SIZE="-1">UTF-8.</font> </p>
<p> The listing below is alphabetical, case insensitive.</p>
<h2>Array Manipulation Functions</h2>
<dl COMPACT>
<dt>av_clear</p>
<dd>Frees the all the elements of an array, leaving it empty. The <font SIZE="-1">XS</font> equivalent of <tt>&quot;@array = ()&quot;</tt>. See also &#8220;av_undef&#8221;. </p>
<p> Note that it is possible that the actions of a destructor called directly or indirectly by freeing an element of the array could cause the reference count of the array itself to be reduced (e.g. by deleting an entry in the symbol table). So it is a possibility that the <font SIZE="-1">AV</font> could have been freed (or even reallocated) on return from the call unless you hold a reference to it. </p>
<pre> void av_clear(AV *av)</pre>
<dt>av_create_and_push</p>
<dd><font SIZE="-1">NOTE:</font> this function is experimental and may change or be removed without notice. </p>
<p> Push an <font SIZE="-1">SV</font> onto the end of the array, creating the array if necessary. A small internal helper function to remove a commonly duplicated idiom. </p>
<pre> void av_create_and_push(AV **const avp,
 SV *const val)</pre>
<dt>av_create_and_unshift_one</p>
<dd><font SIZE="-1">NOTE:</font> this function is experimental and may change or be removed without notice. </p>
<p> Unshifts an <font SIZE="-1">SV</font> onto the beginning of the array, creating the array if necessary. A small internal helper function to remove a commonly duplicated idiom. </p>
<pre> SV** av_create_and_unshift_one(AV **const avp,
 SV *const val)</pre>
<dt>av_delete</p>
<dd>Deletes the element indexed by <tt>&quot;key&quot;</tt> from the array, makes the element mortal, and returns it. If <tt>&quot;flags&quot;</tt> equals <tt>&quot;G_DISCARD&quot;</tt>, the element is freed and <font SIZE="-1">NULL</font> is returned. <font SIZE="-1">NULL</font> is also returned if <tt>&quot;key&quot;</tt> is out of range. </p>
<p> Perl equivalent: <tt>&quot;splice(@myarray, $key, 1, undef)&quot;</tt> (with the <tt>&quot;splice&quot;</tt> in void context if <tt>&quot;G_DISCARD&quot;</tt> is present). </p>
<pre> SV* av_delete(AV *av, SSize_t key, I32 flags)</pre>
<dt>av_exists</p>
<dd>Returns true if the element indexed by <tt>&quot;key&quot;</tt> has been initialized. </p>
<p> This relies on the fact that uninitialized array elements are set to <tt>&quot;NULL&quot;</tt>. </p>
<p> Perl equivalent: <tt>&quot;exists($myarray[$key])&quot;</tt>. </p>
<pre> bool av_exists(AV *av, SSize_t key)</pre>
<dt>av_extend</p>
<dd>Pre-extend an array. The <tt>&quot;key&quot;</tt> is the index to which the array should be extended. </p>
<pre> void av_extend(AV *av, SSize_t key)</pre>
<dt>av_fetch</p>
<dd>Returns the <font SIZE="-1">SV</font> at the specified index in the array. The <tt>&quot;key&quot;</tt> is the index. If lval is true, you are guaranteed to get a real <font SIZE="-1">SV</font> back (in case it wasn&#8217;t real before), which you can then modify. Check that the return value is non-null before dereferencing it to a <tt>&quot;SV*&quot;</tt>. </p>
<p> See &#8220;Understanding the Magic of Tied Hashes and Arrays&#8221; in perlguts for more information on how to use this function on tied arrays. </p>
<p> The rough perl equivalent is <tt>$myarray[$key]</tt>. </p>
<pre> SV** av_fetch(AV *av, SSize_t key, I32 lval)</pre>
<dt>AvFILL</p>
<dd>Same as <tt>&quot;av_top_index()&quot;</tt> or <tt>&quot;av_tindex()&quot;</tt>. </p>
<pre> int AvFILL(AV* av)</pre>
<dt>av_fill</p>
<dd>Set the highest index in the array to the given number, equivalent to Perl&#8217;s <tt>&quot;$#array = $fill;&quot;</tt>. </p>
<p> The number of elements in the array will be <tt>&quot;fill + 1&quot;</tt> after <tt>&quot;av_fill()&quot;</tt> returns. If the array was previously shorter, then the additional elements appended are set to <font SIZE="-1">NULL.</font> If the array was longer, then the excess elements are freed. <tt>&quot;av_fill(av, -1)&quot;</tt> is the same as <tt>&quot;av_clear(av)&quot;</tt>. </p>
<pre> void av_fill(AV *av, SSize_t fill)</pre>
<dt>av_len</p>
<dd>Same as &#8220;av_top_index&#8221;. Note that, unlike what the name implies, it returns the highest index in the array, so to get the size of the array you need to use <tt>&quot;av_len(av) + 1&quot;</tt>. This is unlike &#8220;sv_len&#8221;, which returns what you would expect. </p>
<pre> SSize_t av_len(AV *av)</pre>
<dt>av_make</p>
<dd>Creates a new <font SIZE="-1">AV</font> and populates it with a list of SVs. The SVs are copied into the array, so they may be freed after the call to <tt>&quot;av_make&quot;</tt>. The new <font SIZE="-1">AV</font> will have a reference count of 1. </p>
<p> Perl equivalent: <tt>&quot;my @new_array = ($scalar1, $scalar2, $scalar3...);&quot;</tt> </p>
<pre> AV* av_make(SSize_t size, SV **strp)</pre>
<dt>av_pop</p>
<dd>Removes one <font SIZE="-1">SV</font> from the end of the array, reducing its size by one and returning the <font SIZE="-1">SV</font> (transferring control of one reference count) to the caller. Returns <tt>&amp;PL_sv_undef</tt> if the array is empty. </p>

<pre> SV* av_pop(AV *av)</pre>
<dt>av_push</p>
<dd>Pushes an <font SIZE="-1">SV</font> (transferring control of one reference count) onto the end of the array. The array will grow automatically to accommodate the addition. </p>
<p> Perl equivalent: <tt>&quot;push @myarray, $val;&quot;</tt>. </p>
<pre> void av_push(AV *av, SV *val)</pre>
<dt>av_shift</p>
<dd>Removes one <font SIZE="-1">SV</font> from the start of the array, reducing its size by one and returning the <font SIZE="-1">SV</font> (transferring control of one reference count) to the caller. Returns <tt>&amp;PL_sv_undef</tt> if the array is empty. </p>
<p> Perl equivalent: <tt>&quot;shift(@myarray);&quot;</tt> </p>
<pre> SV* av_shift(AV *av)</pre>
<dt>av_store</p>
<dd>Stores an <font SIZE="-1">SV</font> in an array. The array index is specified as <tt>&quot;key&quot;</tt>. The return value will be <tt>&quot;NULL&quot;</tt> if the operation failed or if the value did not need to be actually stored within the array (as in the case of tied arrays). Otherwise, it can be dereferenced to get the <tt>&quot;SV*&quot;</tt> that was stored there (= <tt>&quot;val&quot;</tt>)). </p>
<p> Note that the caller is responsible for suitably incrementing the reference count of <tt>&quot;val&quot;</tt> before the call, and decrementing it if the function returned <tt>&quot;NULL&quot;</tt>. </p>
<p> Approximate Perl equivalent: <tt>&quot;splice(@myarray, $key, 1, $val)&quot;</tt>. </p>
<p> See &#8220;Understanding the Magic of Tied Hashes and Arrays&#8221; in perlguts for more information on how to use this function on tied arrays. </p>
<pre> SV** av_store(AV *av, SSize_t key, SV *val)</pre>
<dt>av_tindex</p>
<dd>Same as <tt>&quot;av_top_index()&quot;</tt>. </p>
<pre> int av_tindex(AV* av)</pre>
<dt>av_top_index</p>
<dd>Returns the highest index in the array. The number of elements in the array is <tt>&quot;av_top_index(av) + 1&quot;</tt>. Returns -1 if the array is empty. </p>
<p> The Perl equivalent for this is <tt>$#myarray</tt>. </p>
<p> (A slightly shorter form is <tt>&quot;av_tindex&quot;</tt>.) </p>
<pre> SSize_t av_top_index(AV *av)</pre>

<p> See &#8220;av_clear&#8221; for a note about the array possibly being invalid on return. </p>
<pre> void av_undef(AV *av)</pre>
<dt>av_unshift</p>
<dd>Unshift the given number of <tt>&quot;undef&quot;</tt> values onto the beginning of the array. The array will grow automatically to accommodate the addition. </p>
<p> Perl equivalent: <tt>&quot;unshift @myarray, ((undef) x $num);&quot;</tt> </p>
<pre> void av_unshift(AV *av, SSize_t num)</pre>

<h2>Character case changing</h2>
<p>Perl uses &#8220;full&#8221; Unicode case mappings. This means that converting a single character to another case may result in a sequence of more than one character. For example, the uppercase of <tt>&quot;ß&quot;</tt> (<font SIZE="-1">LATIN SMALL LETTER SHARP S</font>) is the two character sequence <tt>&quot;SS&quot;</tt>. This presents some complications The lowercase of all characters in the range 0..255 is a single character, and thus <tt>&quot;toLOWER_L1&quot;</tt> is furnished. But, <tt>&quot;toUPPER_L1&quot;</tt> can&#8217;t exist, as it couldn&#8217;t return a valid result for all legal inputs. Instead <tt>&quot;toUPPER_uvchr&quot;</tt> has an <font SIZE="-1">API</font> that does allow every possible legal result to be returned.) Likewise no other function that is crippled by not being able to give the correct results for the full range of possible inputs has been implemented here.</p>
<dl COMPACT>
<dt>toFOLD</p>
<dd>Converts the specified character to foldcase. If the input is anything but an <font SIZE="-1">ASCII</font> uppercase character, that input character itself is returned. Variant <tt>&quot;toFOLD_A&quot;</tt> is equivalent. (There is no equivalent <tt>&quot;to_FOLD_L1&quot;</tt> for the full Latin1 range, as the full generality of &#8220;toFOLD_uvchr&#8221; is needed there.) </p>
<pre> U8 toFOLD(U8 ch)</pre>
<dt>toFOLD_utf8</p>
<dd>This is like <tt>&quot;toFOLD_utf8_safe&quot;</tt>, but doesn&#8217;t have the <tt>&quot;e&quot;</tt> parameter The function therefore can&#8217;t check if it is reading beyond the end of the string. Starting in Perl v5.30, it will take the <tt>&quot;e&quot;</tt> parameter, becoming a synonym for <tt>&quot;toFOLD_utf8_safe&quot;</tt>. At that time every program that uses it will have to be changed to successfully compile. In the meantime, the first runtime call to <tt>&quot;toFOLD_utf8&quot;</tt> from each call point in the program will raise a deprecation warning, enabled by default. You can convert your program now to use <tt>&quot;toFOLD_utf8_safe&quot;</tt>, and avoid the warnings, and get an extra measure of protection, or you can wait until v5.30, when you&#8217;ll be forced to add the <tt>&quot;e&quot;</tt> parameter. </p>
<pre> UV toFOLD_utf8(U8* p, U8* s, STRLEN* lenp)</pre>
<dt>toFOLD_utf8_safe</p>
<dd>Converts the first <font SIZE="-1">UTF-8</font> encoded character in the sequence starting at <tt>&quot;p&quot;</tt> and extending no further than <tt>&quot;e - 1&quot;</tt> to its foldcase version, and stores that in <font SIZE="-1">UTF-8</font> in <tt>&quot;s&quot;</tt>, and its length in bytes in <tt>&quot;lenp&quot;</tt>. Note that the buffer pointed to by <tt>&quot;s&quot;</tt> needs to be at least <tt>&quot;UTF8_MAXBYTES_CASE+1&quot;</tt> bytes since the foldcase version may be longer than the original character. </p>
<p> The first code point of the foldcased version is returned (but note, as explained at the top of this section, that there may be more). </p>
<p> The suffix <tt>&quot;_safe&quot;</tt> in the function&#8217;s name indicates that it will not attempt to read beyond <tt>&quot;e - 1&quot;</tt>, provided that the constraint <tt>&quot;s &lt; e&quot;</tt> is true (this is asserted for in <tt>&quot;-DDEBUGGING&quot;</tt> builds). If the <font SIZE="-1">UTF-8</font> for the input character is malformed in some way, the program may croak, or the function may return the <font SIZE="-1">REPLACEMENT CHARACTER,</font> at the discretion of the implementation, and subject to change in future releases. </p>
<pre> UV toFOLD_utf8_safe(U8* p, U8* e, U8* s,
 STRLEN* lenp)</pre>
<dt>toFOLD_uvchr</p>
<dd>Converts the code point <tt>&quot;cp&quot;</tt> to its foldcase version, and stores that in <font SIZE="-1">UTF-8</font> in <tt>&quot;s&quot;</tt>, and its length in bytes in <tt>&quot;lenp&quot;</tt>. The code point is interpreted as native if less than 256; otherwise as Unicode. Note that the buffer pointed to by <tt>&quot;s&quot;</tt> needs to be at least <tt>&quot;UTF8_MAXBYTES_CASE+1&quot;</tt> bytes since the foldcase version may be longer than the original character. </p>
<p> The first code point of the foldcased version is returned (but note, as explained at the top of this section, that there may be more). </p>
<pre> UV toFOLD_uvchr(UV cp, U8* s, STRLEN* lenp)</pre>
<dt>toLOWER</p>

<h2>Character classification</h2>
<p>This section is about functions (really macros) that classify characters into types, such as punctuation versus alphabetic, etc. Most of these are analogous to regular expression character classes. (See &#8220;<font SIZE="-1">POSIX</font> Character Classes&#8221; in perlrecharclass.) There are several variants for each class. (Not all macros have all variants; each item below lists the ones valid for it.) None are affected by <tt>&quot;use bytes&quot;</tt>, and only the ones with <tt>&quot;LC&quot;</tt> in the name are affected by the current locale. </p>
<p> The base function, e.g., <tt>&quot;isALPHA()&quot;</tt>, takes an octet (either a <tt>&quot;char&quot;</tt> or a <tt>&quot;U8&quot;</tt>) as input and returns a boolean as to whether or not the character represented by that octet is (or on non-ASCII platforms, corresponds to) an <font SIZE="-1">ASCII</font> character in the named class based on platform, Unicode, and Perl rules. If the input is a number that doesn&#8217;t fit in an octet, <font SIZE="-1">FALSE</font> is returned. </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_A&quot;</tt> (e.g., <tt>&quot;isALPHA_A()&quot;</tt>) is identical to the base function with no suffix <tt>&quot;_A&quot;</tt>. This variant is used to emphasize by its name that only ASCII-range characters can return <font SIZE="-1">TRUE.</font> </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_L1&quot;</tt> imposes the Latin-1 (or <font SIZE="-1">EBCDIC</font> equivalent) character set onto the platform. That is, the code points that are <font SIZE="-1">ASCII</font> are unaffected, since <font SIZE="-1">ASCII</font> is a subset of Latin-1. But the non-ASCII code points are treated as if they are Latin-1 characters. For example, <tt>&quot;isWORDCHAR_L1()&quot;</tt> will return true when called with the code point 0xDF, which is a word character in both <font SIZE="-1">ASCII</font> and <font SIZE="-1">EBCDIC</font> (though it represents different characters in each). </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_uvchr&quot;</tt> is like the <tt>&quot;is</tt>FOO<tt>_L1&quot;</tt> variant, but accepts any <font SIZE="-1">UV</font> code point as input. If the code point is larger than 255, Unicode rules are used to determine if it is in the character class. For example, <tt>&quot;isWORDCHAR_uvchr(0x100)&quot;</tt> returns <font SIZE="-1">TRUE,</font> since 0x100 is <font SIZE="-1">LATIN CAPITAL LETTER A WITH MACRON</font> in Unicode, and is a word character. </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_utf8_safe&quot;</tt> is like <tt>&quot;is</tt>FOO<tt>_uvchr&quot;</tt>, but is used for <font SIZE="-1">UTF-8</font> encoded strings. Each call classifies one character, even if the string contains many. This variant takes two parameters. The first, <tt>&quot;p&quot;</tt>, is a pointer to the first byte of the character to be classified. (Recall that it may take more than one byte to represent a character in <font SIZE="-1">UTF-8</font> strings.) The second parameter, <tt>&quot;e&quot;</tt>, points to anywhere in the string beyond the first character, up to one byte past the end of the entire string. The suffix <tt>&quot;_safe&quot;</tt> in the function&#8217;s name indicates that it will not attempt to read beyond <tt>&quot;e - 1&quot;</tt>, provided that the constraint <tt>&quot;s &lt; e&quot;</tt> is true (this is asserted for in <tt>&quot;-DDEBUGGING&quot;</tt> builds). If the <font SIZE="-1">UTF-8</font> for the input character is malformed in some way, the program may croak, or the function may return <font SIZE="-1">FALSE,</font> at the discretion of the implementation, and subject to change in future releases. </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_utf8&quot;</tt> is like <tt>&quot;is</tt>FOO<tt>_utf8_safe&quot;</tt>, but takes just a single parameter, <tt>&quot;p&quot;</tt>, which has the same meaning as the corresponding parameter does in <tt>&quot;is</tt>FOO<tt>_utf8_safe&quot;</tt>. The function therefore can&#8217;t check if it is reading beyond the end of the string. Starting in Perl v5.30, it will take a second parameter, becoming a synonym for <tt>&quot;is</tt>FOO<tt>_utf8_safe&quot;</tt>. At that time every program that uses it will have to be changed to successfully compile. In the meantime, the first runtime call to <tt>&quot;is</tt>FOO<tt>_utf8&quot;</tt> from each call point in the program will raise a deprecation warning, enabled by default. You can convert your program now to use <tt>&quot;is</tt>FOO<tt>_utf8_safe&quot;</tt>, and avoid the warnings, and get an extra measure of protection, or you can wait until v5.30, when you&#8217;ll be forced to add the <tt>&quot;e&quot;</tt> parameter. </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_LC&quot;</tt> is like the <tt>&quot;is</tt>FOO<tt>_A&quot;</tt> and <tt>&quot;is</tt>FOO<tt>_L1&quot;</tt> variants, but the result is based on the current locale, which is what <tt>&quot;LC&quot;</tt> in the name stands for. If Perl can determine that the current locale is a <font SIZE="-1">UTF-8</font> locale, it uses the published Unicode rules; otherwise, it uses the C library function that gives the named classification. For example, <tt>&quot;isDIGIT_LC()&quot;</tt> when not in a <font SIZE="-1">UTF-8</font> locale returns the result of calling <tt>&quot;isdigit()&quot;</tt>. <font SIZE="-1">FALSE</font> is always returned if the input won&#8217;t fit into an octet. On some platforms where the C library function is known to be defective, Perl changes its result to follow the <font SIZE="-1">POSIX</font> standard&#8217;s rules. </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_LC_uvchr&quot;</tt> is like <tt>&quot;is</tt>FOO<tt>_LC&quot;</tt>, but is defined on any <font SIZE="-1">UV.</font> It returns the same as <tt>&quot;is</tt>FOO<tt>_LC&quot;</tt> for input code points less than 256, and returns the hard-coded, not-affected-by-locale, Unicode results for larger ones. </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_LC_utf8_safe&quot;</tt> is like <tt>&quot;is</tt>FOO<tt>_LC_uvchr&quot;</tt>, but is used for <font SIZE="-1">UTF-8</font> encoded strings. Each call classifies one character, even if the string contains many. This variant takes two parameters. The first, <tt>&quot;p&quot;</tt>, is a pointer to the first byte of the character to be classified. (Recall that it may take more than one byte to represent a character in <font SIZE="-1">UTF-8</font> strings.) The second parameter, <tt>&quot;e&quot;</tt>, points to anywhere in the string beyond the first character, up to one byte past the end of the entire string. If the <font SIZE="-1">UTF-8</font> for the input character is malformed in some way, the program may croak, or the function may return <font SIZE="-1">FALSE,</font> at the discretion of the implementation, and subject to change in future releases. </p>
<p> Variant <tt>&quot;is</tt>FOO<tt>_LC_utf8&quot;</tt> is like <tt>&quot;is</tt>FOO<tt>_LC_utf8_safe&quot;</tt>, but takes just a single parameter, <tt>&quot;p&quot;</tt>, which has the same meaning as the corresponding parameter does in <tt>&quot;is</tt>FOO<tt>_LC_utf8_safe&quot;</tt>.
