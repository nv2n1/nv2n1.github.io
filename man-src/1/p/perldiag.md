<h2 class="name">NAME</h2>
<p> perldiag &#8211; various Perl diagnostics </p>
<h2>DESCRIPTION</h2>
<p> These messages are classified as follows (listed in increasing order of desperation): </p>
<pre>
    (W) A warning (optional).
    (D) A deprecation (enabled by default).
    (S) A severe warning (enabled by default).
    (F) A fatal error (trappable).
    (P) An internal error you should never see (trappable).
    (X) A very fatal error (nontrappable).
    (A) An alien error message (not generated by Perl).
</pre>
<p> The majority of messages from the first three classifications above (W, D &amp; S) can be controlled using the <tt>&quot;warnings&quot;</tt> pragma. </p>
<p> If a message can be controlled by the <tt>&quot;warnings&quot;</tt> pragma, its warning category is included with the classification letter in the description below. E.g. <tt>&quot;(W closed)&quot;</tt> means a warning in the <tt>&quot;closed&quot;</tt> category. </p>
<p> Optional warnings are enabled by using the <tt>&quot;warnings&quot;</tt> pragma or the <code>-w</code> and <code>-W</code> switches. Warnings may be captured by setting <tt>$SIG{__WARN__}</tt> to a reference to a routine that will be called on each warning instead of printing it. See perlvar. </p>
<p> Severe warnings are always enabled, unless they are explicitly disabled with the <tt>&quot;warnings&quot;</tt> pragma or the <code>-X</code> switch. </p>
<p> Trappable errors may be trapped using the eval operator. See &#8220;eval&#8221; in perlfunc. In almost all cases, warnings may be selectively disabled or promoted to fatal errors using the <tt>&quot;warnings&quot;</tt> pragma. See warnings. </p>
<p> The messages are in alphabetical order, without regard to upper or lower-case. Some of these messages are generic. Spots that vary are denoted with a <tt>%s</tt> or other printf-style escape. These escapes are ignored by the alphabetical order, as are all characters other than letters. To look up your message, just ignore anything that is not a letter.</p>
<dl>
<dt><code>accept()</code> on closed socket %s</p>
<dd> (W closed) You tried to do an accept on a closed socket. Did you forget to check the return value of your <code>socket()</code> call? See &#8220;accept&#8221; in perlfunc.</p>
<dt>Aliasing via reference is experimental</p>
<dd> (S experimental::refaliasing) This warning is emitted if you use a reference constructor on the left-hand side of an assignment to alias one variable to another. Simply suppress the warning if you want to use the feature, but know that in doing so you are taking the risk of using an experimental feature which may change or be removed in a future Perl version: </p>
<pre>
    no warnings &quot;experimental::refaliasing&quot;;
    use feature &quot;refaliasing&quot;;
    \$x = \$y;
</pre>
<dt>Allocation too large: %x</p>
<dd> (X) You can&#8217;t allocate more than 64K on an MS-DOS machine.</p>
<dt>&#8216;%c&#8217; allowed only after types %s in %s</p>
<dd> (F) The modifiers &#8216;!&#8217;, &#8216;&lt;&#8216; and &#8216;&gt;&#8217; are allowed in <code>pack()</code> or <code>unpack()</code> only after certain types. See &#8220;pack&#8221; in perlfunc.</p>
<dt>alpha-&gt;<code>numify()</code> is lossy</p>
<dd> (W numeric) An alpha version can not be numified without losing information.</p>
<dt>Ambiguous call resolved as CORE::%s(), qualify as such or use &amp;</p>
<dd> (W ambiguous) A subroutine you have declared has the same name as a Perl keyword, and you have used the name without qualification for calling one or the other. Perl decided to call the builtin because the subroutine is not imported. </p>
<p> To force interpretation as a subroutine call, either put an ampersand before the subroutine name, or qualify the name with its package. Alternatively, you can import the subroutine (or pretend that it&#8217;s imported with the <tt>&quot;use subs&quot;</tt> pragma). </p>
<p> To silently interpret it as the Perl operator, use the <tt>&quot;CORE::&quot;</tt> prefix on the operator (e.g. <tt>&quot;CORE::log($x)&quot;</tt>) or declare the subroutine to be an object method (see &#8220;Subroutine Attributes&#8221; in perlsub or attributes).</p>
<dt>Ambiguous range in transliteration operator</p>
<dd> (F) You wrote something like <tt>&quot;tr/a-z-0//&quot;</tt> which doesn&#8217;t mean anything at all. To include a <tt>&quot;-&quot;</tt> character in a transliteration, put it either first or last. (In the past, <tt>&quot;tr/a-z-0//&quot;</tt> was synonymous with <tt>&quot;tr/a-y//&quot;</tt>, which was probably not what you would have expected.)</p>
<dt>Ambiguous use of %s resolved as %s</p>
<dd> (S ambiguous) You said something that may not be interpreted the way you thought. Normally it&#8217;s pretty easy to disambiguate it by supplying a missing quote, operator, parenthesis pair or declaration.</p>
<dt>Ambiguous use of -%s resolved as -&amp;%s()</p>
<dd> (S ambiguous) You wrote something like <tt>&quot;-foo&quot;</tt>, which might be the string <tt>&quot;-foo&quot;</tt>, or a call to the function <tt>&quot;foo&quot;</tt>, negated. If you meant the string, just write <tt>&quot;-foo&quot;</tt>. If you meant the function call, write <tt>&quot;-foo()&quot;</tt>.</p>
<dt>Ambiguous use of %c resolved as operator %c</p>
<dd> (S ambiguous) <tt>&quot;%&quot;</tt>, <tt>&quot;&amp;&quot;</tt>, and <tt>&quot;*&quot;</tt> are both infix operators (modulus, bitwise and, and multiplication) <i>and</i> initial special characters (denoting hashes, subroutines and typeglobs), and you said something like <tt>&quot;*foo * foo&quot;</tt> that might be interpreted as either of them. We assumed you meant the infix operator, but please try to make it more clear &#8212; in the example given, you might write <tt>&quot;*foo * foo()&quot;</tt> if you really meant to multiply a glob by the result of calling a function.</p>
<dt>Ambiguous use of %c{%s} resolved to %c%s</p>
<dd> (W ambiguous) You wrote something like <tt>&quot;@{foo}&quot;</tt>, which might be asking for the variable <tt>@foo</tt>, or it might be calling a function named foo, and dereferencing it as an array reference. If you wanted the variable, you can just write <tt>@foo</tt>. If you wanted to call the function, write <tt>&quot;@{foo()}&quot;</tt> &#8230; or you could just not have a variable and a function with the same name, and save yourself a lot of trouble.</p>
<dt>Ambiguous use of %c{%s[&#8230;]} resolved to %c%s[&#8230;]</p>
<dd>
<dt>Ambiguous use of %c{%s{&#8230;}} resolved to %c%s{&#8230;}</p>
<dd> (W ambiguous) You wrote something like <tt>&quot;${foo[2]}&quot;</tt> (where foo represents the name of a Perl keyword), which might be looking for element number 2 of the array named <tt>@foo</tt>, in which case please write <tt>$foo[2]</tt>, or you might have meant to pass an anonymous arrayref to the function named foo, and then do a scalar deref on the value it returns. If you meant that, write <tt>&quot;${foo([2])}&quot;</tt>. </p>
<p> In regular expressions, the <tt>&quot;${foo[2]}&quot;</tt> syntax is sometimes necessary to disambiguate between array subscripts and character classes. <tt>&quot;/$length[2345]/&quot;</tt>, for instance, will be interpreted as <tt>$length</tt> followed by the character class <tt>&quot;[2345]&quot;</tt>. If an array subscript is what you want, you can avoid the warning by changing <tt>&quot;/${length[2345]}/&quot;</tt> to the unsightly <tt>&quot;/${\$length[2345]}/&quot;</tt>, by renaming your array to something that does not coincide with a built-in keyword, or by simply turning off warnings with <tt>&quot;no warnings 'ambiguous';&quot;</tt>.</p>
<dt>&#8216;|&#8217; and &#8216;&lt;&#8216; may not both be specified on command line</p>
<dd> (F) An error peculiar to <font SIZE="-1">VMS.</font> Perl does its own command line redirection, and found that <font SIZE="-1">STDIN</font> was a pipe, and that you also tried to redirect <font SIZE="-1">STDIN</font> using &#8216;&lt;&#8216;. Only one <font SIZE="-1">STDIN</font> stream to a customer, please.</p>
<dt>&#8216;|&#8217; and &#8216;&gt;&#8217; may not both be specified on command line</p>
<dd> (F) An error peculiar to <font SIZE="-1">VMS.</font> Perl does its own command line redirection, and thinks you tried to redirect stdout both to a file and into a pipe to another command. You need to choose one or the other, though nothing&#8217;s stopping you from piping into a program or Perl script which &#8216;splits&#8217; output into two streams, such as </p>
<pre><code>
open(OUT, "&gt;$ARGV[0]") or die "Can't write to $ARGV[0]: $!";
while (&lt;STDIN&gt;) {
    print;
    print OUT;
}
close OUT;
</code></pre>
<dt>Applying %s to %s will act on scalar(%s)</p>
<dd> (W misc) The pattern match (<tt>&quot;//&quot;</tt>), substitution (<tt>&quot;s///&quot;</tt>), and transliteration (<tt>&quot;tr///&quot;</tt>) operators work on scalar values. If you apply one of them to an array or a hash, it will convert the array or hash to a scalar value (the length of an array, or the population info of a hash) and then work on that scalar value. This is probably not what you meant to do. See &#8220;grep&#8221; in perlfunc and &#8220;map&#8221; in perlfunc for alternatives.</p>
<dt>Arg too short for msgsnd</p>
<dd> (F) <code>msgsnd()</code> requires a string at least as long as sizeof(long).</p>
<dt>Argument &quot;%s&quot; isn&#8217;t numeric%s</p>
<dd> (W numeric) The indicated string was fed as an argument to an operator that expected a numeric value instead. If you&#8217;re fortunate the message will identify which operator was so unfortunate. </p>
<p> Note that for the <tt>&quot;Inf&quot;</tt> and <tt>&quot;NaN&quot;</tt> (infinity and not-a-number) the definition of &#8220;numeric&#8221; is somewhat unusual: the strings themselves (like &#8220;Inf&#8221;) are considered numeric, and anything following them is considered non-numeric.</p>
<dt>Argument list not closed for PerlIO layer &quot;%s&quot;</p>
<dd> (W layer) When pushing a layer with arguments onto the Perl I/O system you forgot the ) that closes the argument list. (Layers take care of transforming data between external and internal representations.) Perl stopped parsing the layer list at this point and did not attempt to push this layer. If your program didn&#8217;t explicitly request the failing operation, it may be the result of the value of the environment variable <font SIZE="-1">PERLIO.</font></p>
<dt>Argument &quot;%s&quot; treated as 0 in increment (++)</p>
<dd> (W numeric) The indicated string was fed as an argument to the <tt>&quot;++&quot;</tt> operator which expects either a number or a string matching <tt>&quot;/^[a-zA-Z]*[0-9]*\z/&quot;</tt>. See &#8220;Auto-increment and Auto-decrement&#8221; in perlop for details.</p>
<dt>Array passed to stat will be coerced to a scalar%s</p>
<dd> (W syntax) You called <code>stat()</code> on an array, but the array will be coerced to a scalar &#8211; the number of elements in the array.</p>
<dt>A signature parameter must start with &#8216;$&#8217;, &#8216;@&#8217; or &#8216;%&#8217;</p>
<dd> (F) Each subroutine signature parameter declaration must start with a valid sigil; for example: </p>
<pre>
    sub foo ($a, $, $b = 1, @c) {}
</pre>
<dt>A slurpy parameter may not have a default value</p>
<dd> (F) Only scalar subroutine signature parameters may have a default value; for example: </p>
<p>sub foo($a = 1)<br />
{<br />
}<br />
#legal sub foo(@a = (1))<br />
{<br />
}<br />
#invalid sub foo(% a = (a = &gt; b))<br />
{<br />
}<br />
#invalid</p>
<dt>assertion botched: %s</p>
<dd> (X) The malloc package that comes with Perl had an internal failure.</p>
<dt>Assertion %s failed: file &quot;%s&quot;, line %d</p>
<dd> (X) A general assertion failed. The file in question must be examined.</p>
<dt>Assigned value is not a reference</p>
<dd> (F) You tried to assign something that was not a reference to an lvalue reference (e.g., <tt>&quot;\$x = $y&quot;</tt>). If you meant to make <tt>$x</tt> an alias to <tt>$y</tt>, use <tt>&quot;\$x = \$y&quot;</tt>.</p>
<dt>Assigned value is not %s reference</p>
<dd> (F) You tried to assign a reference to a reference constructor, but the two references were not of the same type. You cannot alias a scalar to an array, or an array to a hash; the two types must match. </p>
<p>\$x = \@y;<br />
#error \@x = \%y;<br />
#error $y = [];<br />
\$x = $y;<br />
#error;<br />
did you mean \$y ?</p>
<dt>Assigning non-zero to $[ is no longer possible</p>
<dd> (F) When the &#8220;array_base&#8221; feature is disabled (e.g., and under <tt>&quot;use v5.16;&quot;</tt>, and as of Perl 5.30) the special variable <tt>$[</tt>, which is deprecated, is now a fixed zero value.</p>
<dt>Assignment to both a list and a scalar</p>
<dd> (F) If you assign to a conditional operator, the 2nd and 3rd arguments must either both be scalars or both be lists. Otherwise Perl won&#8217;t know which context to supply to the right side.</p>
<dt>Assuming <font SIZE="-1">NOT</font> a <font SIZE="-1">POSIX</font> class since %s in regex; marked by &lt;&#8211; HERE in m/%s/</p>
<dd> (W regexp) You had something like these: </p>
<p> [[:alnum]]<br />
 [[:digit:xyz]</p>
<p> They look like they might have been meant to be the <font SIZE="-1">POSIX</font> classes <tt>&quot;[:alnum:]&quot;</tt> or <tt>&quot;[:digit:]&quot;</tt>. If so, they should be written: </p>
<p>[[:alnum:]]<br />
    [[:digit:] xyz]</p>
<p> Since these aren&#8217;t legal <font SIZE="-1">POSIX</font> class specifications, but are legal bracketed character classes, Perl treats them as the latter. In the first example, it matches the characters <tt>&quot;:&quot;</tt>, <tt>&quot;[&quot;</tt>, <tt>&quot;a&quot;</tt>, <tt>&quot;l&quot;</tt>, <tt>&quot;m&quot;</tt>, <tt>&quot;n&quot;</tt>, and <tt>&quot;u&quot;</tt>. </p>
<p> If these weren&#8217;t meant to be <font SIZE="-1">POSIX</font> classes, this warning message is spurious, and can be suppressed by reordering things, such as </p>
<p>[[al:num]]</p>
<p> or </p>
<p>[[:munla]]</p>
<dt>&lt;&gt; at require-statement should be quotes</p>
<dd> (F) You wrote <tt>&quot;require &lt;file&gt;&quot;</tt> when you should have written <tt>&quot;require 'file'&quot;</tt>.</p>
<dt>Attempt to access disallowed key &#8216;%s&#8217; in a restricted hash</p>
<dd> (F) The failing code has attempted to get or set a key which is not in the current set of allowed keys of a restricted hash.</p>
<dt>Attempt to bless into a freed package</p>
<dd> (F) You wrote <tt>&quot;bless $foo&quot;</tt> with one argument after somehow causing the current package to be freed. Perl cannot figure out what to do, so it throws up its hands in despair.</p>
<dt>Attempt to bless into a reference</p>
<dd> (F) The <font SIZE="-1">CLASSNAME</font> argument to the <code>bless()</code> operator is expected to be the name of the package to bless the resulting object into. You&#8217;ve supplied instead a reference to something: perhaps you wrote </p>
<pre>
    bless $self, $proto;
</pre>
<p> when you intended </p>
<pre>
    bless $self, ref($proto) || $proto;
</pre>
<p> If you actually want to bless into the stringified version of the reference supplied, you need to stringify it yourself, for example by: </p>
<pre>
    bless $self, &quot;$proto&quot;;
</pre>
<dt>Attempt to clear deleted array</p>
<dd> (S debugging) An array was assigned to when it was being freed. Freed values are not supposed to be visible to Perl code. This can also happen if <font SIZE="-1">XS</font> code calls <tt>&quot;av_clear&quot;</tt> from a custom magic callback on the array.</p>
<dt>Attempt to delete disallowed key &#8216;%s&#8217; from a restricted hash</p>
<dd> (F) The failing code attempted to delete from a restricted hash a key which is not in its key set.</p>
<dt>Attempt to delete readonly key &#8216;%s&#8217; from a restricted hash</p>
<dd> (F) The failing code attempted to delete a key whose value has been declared readonly from a restricted hash.</p>
<dt>Attempt to free non-arena <font SIZE="-1">SV:</font> 0x%x</p>
<dd> (S internal) All <font SIZE="-1">SV</font> objects are supposed to be allocated from arenas that will be garbage collected on exit. An <font SIZE="-1">SV</font> was discovered to be outside any of those arenas.</p>
<dt>Attempt to free nonexistent shared string &#8216;%s&#8217;%s</p>
<dd> (S internal) Perl maintains a reference-counted internal table of strings to optimize the storage and access of hash keys and other strings. This indicates someone tried to decrement the reference count of a string that can no longer be found in the table.</p>
<dt>Attempt to free temp prematurely: <font SIZE="-1">SV</font> 0x%x</p>
<dd> (S debugging) Mortalized values are supposed to be freed by the <code>free_tmps()</code> routine. This indicates that something else is freeing the <font SIZE="-1">SV</font> before the <code>free_tmps()</code> routine gets a chance, which means that the <code>free_tmps()</code> routine will be freeing an unreferenced scalar when it does try to free it.</p>
<dt>Attempt to free unreferenced glob pointers</p>
<dd> (S internal) The reference counts got screwed up on symbol aliases.</p>
<dt>Attempt to free unreferenced scalar: <font SIZE="-1">SV</font> 0x%x</p>
<dd> (S internal) Perl went to decrement the reference count of a scalar to see if it would go to 0, and discovered that it had already gone to 0 earlier, and should have been freed, and in fact, probably was freed. This could indicate that <code>SvREFCNT_dec()</code> was called too many times, or that <code>SvREFCNT_inc()</code> was called too few times, or that the <font SIZE="-1">SV</font> was mortalized when it shouldn&#8217;t have been, or that memory has been corrupted.</p>
<dt>Attempt to pack pointer to temporary value</p>
<dd> (W pack) You tried to pass a temporary value (like the result of a function, or a computed expression) to the &#8220;p&#8221; <code>pack()</code> template. This means the result contains a pointer to a location that could become invalid anytime, even before the end of the current statement. Use literals or global values as arguments to the &#8220;p&#8221; <code>pack()</code> template to avoid this warning.</p>
<dt>Attempt to reload %s aborted.</p>
<dd> (F) You tried to load a file with <tt>&quot;use&quot;</tt> or <tt>&quot;require&quot;</tt> that failed to compile once already. Perl will not try to compile this file again unless you delete its entry from <tt>%INC</tt>. See &#8220;require&#8221; in perlfunc and &#8220;%INC&#8221; in perlvar.</p>
<dt>Attempt to set length of freed array</p>
<dd> (W misc) You tried to set the length of an array which has been freed. You can do this by storing a reference to the scalar representing the last index of an array and later assigning through that reference. For example </p>
<p>$r = do<br />
{<br />
    my @a;<br />
    \$ #a<br />
};<br />
$$r = 503</p>
<dt>Attempt to use reference as lvalue in substr</p>
<dd> (W substr) You supplied a reference as the first argument to <code>substr()</code> used as an lvalue, which is pretty strange. Perhaps you forgot to dereference it first. See &#8220;substr&#8221; in perlfunc.</p>
<dt>Attribute prototype(%s) discards earlier prototype attribute in same sub</p>
<dd> (W misc) A sub was declared as sub foo : prototype(A) : prototype(B) {}, for example. Since each sub can only have one prototype, the earlier declaration(s) are discarded while the last one is applied.</p>
<dt>av_reify called on tied array</p>
<dd> (S debugging) This indicates that something went wrong and Perl got <i>very</i> confused about <tt>@_</tt> or <tt>@DB::args</tt> being tied.</p>
<dt>Bad arg length for %s, is %u, should be %d</p>
<dd> (F) You passed a buffer of the wrong size to one of <code>msgctl()</code>, <code>semctl()</code> or <code>shmctl()</code>. In C parlance, the correct sizes are, respectively, sizeof(struct msqid_ds *), sizeof(struct semid_ds *), and sizeof(struct shmid_ds *).</p>
<dt>Bad evalled substitution pattern</p>
<dd> (F) You&#8217;ve used the <tt>&quot;/e&quot;</tt> switch to evaluate the replacement for a substitution, but perl found a syntax error in the code to evaluate, most likely an unexpected right brace &#8216;}&#8217;.</p>
<dt>Bad filehandle: %s</p>
<dd> (F) A symbol was passed to something wanting a filehandle, but the symbol has no filehandle associated with it. Perhaps you didn&#8217;t do an <code>open()</code>, or did it in another package.</p>
<dt>Bad <code>free()</code> ignored</p>
<dd> (S malloc) An internal routine called <code>free()</code> on something that had never been <code>malloc()</code>ed in the first place. Mandatory, but can be disabled by setting environment variable <tt>&quot;PERL_BADFREE&quot;</tt> to 0. </p>
<p> This message can be seen quite often with DB_File on systems with &#8220;hard&#8221; dynamic linking, like <tt>&quot;AIX&quot;</tt> and <tt>&quot;OS/2&quot;</tt>. It is a bug of <tt>&quot;Berkeley DB&quot;</tt> which is left unnoticed if <tt>&quot;DB&quot;</tt> uses <i>forgiving</i> system <code>malloc()</code>.</p>
<dt>Bad hash</p>
<dd> (P) One of the internal hash routines was passed a null <font SIZE="-1">HV</font> pointer.</p>
<dt>Badly placed ()&#8217;s</p>
<dd> (A) You&#8217;ve accidentally run your script through <code>csh</code> instead of Perl. Check the #! line, or manually feed your script into Perl yourself.</p>
<dt>Bad name after %s</p>
<dd> (F) You started to name a symbol by using a package prefix, and then didn&#8217;t finish the symbol. In particular, you can&#8217;t interpolate outside of quotes, so </p>
<pre>
    $var = 'myvar';
    $sym = mypack::$var;
</pre>
<p> is not the same as </p>
<pre>
    $var = 'myvar';
    $sym = &quot;mypack::$var&quot;;
</pre>
<dt>Bad plugin affecting keyword &#8216;%s&#8217;</p>
<dd> (F) An extension using the keyword plugin mechanism violated the plugin <font SIZE="-1">API.</font></p>
<dt>Bad <code>realloc()</code> ignored</p>
<dd> (S malloc) An internal routine called <code>realloc()</code> on something that had never been <code>malloc()</code>ed in the first place. Mandatory, but can be disabled by setting the environment variable <tt>&quot;PERL_BADFREE&quot;</tt> to 1.</p>
<dt>Bad symbol for array</p>
<dd> (P) An internal request asked to add an array entry to something that wasn&#8217;t a symbol table entry.</p>
<dt>Bad symbol for dirhandle</p>
<dd> (P) An internal request asked to add a dirhandle entry to something that wasn&#8217;t a symbol table entry.</p>
<dt>Bad symbol for filehandle</p>
<dd> (P) An internal request asked to add a filehandle entry to something that wasn&#8217;t a symbol table entry.</p>
<dt>Bad symbol for hash</p>
<dd> (P) An internal request asked to add a hash entry to something that wasn&#8217;t a symbol table entry.</p>
<dt>Bad symbol for scalar</p>
<dd> (P) An internal request asked to add a scalar entry to something that wasn&#8217;t a symbol table entry.</p>
<dt>Bareword found in conditional</p>
<dd> (W bareword) The compiler found a bareword where it expected a conditional, which often indicates that an || or &amp;&amp; was parsed as part of the last argument of the previous construct, for example: </p>
<pre>
    open FOO || die;
</pre>
<p> It may also indicate a misspelled constant that has been interpreted as a bareword: </p>
<p>use constant TYPO = &gt; 1;<br />
if (TYOP) {<br />
    print &#8220;foo&#8221;<br />
}</p>
<p> The <tt>&quot;strict&quot;</tt> pragma is useful in avoiding such errors.</p>

<dd>
<dt>Bareword in require maps to disallowed filename &quot;%s&quot;</p>
<dd>
<dt>Bareword in require maps to empty filename</p>
<dd> (F) The bareword form of require has been invoked with a filename which could not have been generated by a valid bareword permitted by the parser. You shouldn&#8217;t be able to get this error from Perl code, but <font SIZE="-1">XS</font> code may throw it if it passes an invalid module name to <tt>&quot;Perl_load_module&quot;</tt>.</p>
<dt>Bareword in require must not start with a double-colon: &quot;%s&quot;</p>
<dd> (F) In <tt>&quot;require Bare::Word&quot;</tt>, the bareword is not allowed to start with a double-colon. Write <tt>&quot;require ::Foo::Bar&quot;</tt> as <tt>&quot;require Foo::Bar&quot;</tt> instead.</p>
<dt>Bareword &quot;%s&quot; not allowed while &quot;strict subs&quot; in use</p>
<dd> (F) With &#8220;strict subs&#8221; in use, a bareword is only allowed as a subroutine identifier, in curly brackets or to the left of the &#8220;=&gt;&#8221; symbol. Perhaps you need to predeclare a subroutine?</p>
<dt>Bareword &quot;%s&quot; refers to nonexistent package</p>
<dd> (W bareword) You used a qualified bareword of the form <tt>&quot;Foo::&quot;</tt>, but the compiler saw no other uses of that namespace before that point. Perhaps you need to predeclare a package?</p>
<dt><font SIZE="-1">BEGIN</font> failed&#8212;compilation aborted</p>
