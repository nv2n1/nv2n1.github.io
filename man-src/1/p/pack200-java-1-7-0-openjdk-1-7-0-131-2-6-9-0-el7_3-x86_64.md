<p>pack200 &#8211; JAR Packing tool </p>
<h2>Synopsis</h2>
<p><tt>pack200</tt><i> [ </i><i>options</i> ] <i>output-file</i> <i>JAR-file</i> </p>
<p> Options may be in any order. The last option on the command line or in a properties file supersedes all previously specified options. </p>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>options</p>
<dd>Command-line options.</p>
<dt>output-file</p>
<dd>Name of the output file.</p>
<dt>JAR-file</p>
<dd>Name of the input file.</dl>
</dl>
<h2>Description</h2>
<p>The <i>pack200</i> tool is a Java application that transforms a JAR file into a compressed <i>pack200</i> file using the Java <i>gzip</i> compressor. The <i>pack200</i> files are highly compressed files that can be directly deployed, saving bandwidth and reducing download time. </p>
<p> The <i>pack200</i> tool uses several options to fine-tune and set the compression engine. </p>
<h3>Typical usage:</h3>
<p><i>% pack200 myarchive.pack.gz myarchive.jar</i> </p>
<p> In this example, <i>myarchive.pack.gz</i> is produced using the default <i>pack200</i> settings. </p>
<h2>Options</h2>
<p><tt>-r --repack</tt> </p>
<p> Produces a JAR file by packing the file <i>myarchive.jar</i> and unpacking it. The resulting file can be used as an input to the <i><a href="/docs/linux/man/1-jarsigner/">jarsigner</a>(1)</i> tool. </p>
<p> <i>% pack200 &#8211;repack myarchive-packer.jar myarchive.jar</i> </p>
<p> <i>% pack200 &#8211;repack myarchive.jar</i> </p>
<p> <tt>-g --no-gzip</tt> </p>
<p> Produces a <i>pack200</i> file. With this option a suitable compressor must be used, and the target system must use a corresponding decompresser. </p>
<p> <i>% pack200 &#8211;no-gzip myarchive.pack myarchive.jar</i> </p>
<p> <tt>-G --strip-debug</tt> </p>
<p> Strips attributes used for debugging from the output. These include <i>SourceFile</i>, <i>LineNumberTable</i>, <i>LocalVariableTable</i> and <i>LocalVariableTypeTable</i>. Removing these attributes reduces the size of both downloads and installations but reduces the usefulness of debuggers. </p>
<p> <tt>--keep-file-order</tt> </p>
<p> Preserve the order of files in the input file; this is the default behavior. </p>
<p> <tt>-O --no-keep-file-order</tt> </p>
<p> The packer will reorder and transmit all elements. Additionally, the packer may remove JAR directory names. This will reduce the download size; however, certain JAR file optimizations, such as indexing, may not work correctly. </p>
<p> <tt>-Svalue --segment-limit=</tt><i>value</i> </p>
<p> The value is the estimated target size N (in bytes) of each archive segment. If a single input file requires<br />
 more than N bytes, it will be given its own archive segment. As a special case, a value of <i>-1</i> will produce a single large segment with all input files, while a value of <i>0</i> will produce one segment for each class. Larger archive segments result in less fragmentation and better compression, but processing them requires more memory. </p>
<p> The size of each segment is estimated by counting the size of each input file to be transmitted in the segment, along with the size of its name and other transmitted properties. </p>
<p> The default is -1, which means the packer will always create a single segment output file. In cases where extremely large output files are generated, users are strongly encouraged to use segmenting or break up the input file into smaller JARs. </p>
<p> A 10MB JAR packed without this limit will typically pack about 10% smaller, but the packer may require a larger Java heap (about ten times the segment limit). </p>
<p> <tt>-Evalue --effort=</tt><i>value</i> </p>
<p> If the value is set to a single decimal digit, the packer will use the indicated amount of effort in compressing the archive. Level <i>1</i> may produce somewhat larger size and faster compression speed, while level <i>9</i> will take much longer but may produce better compression. The special value <i>0</i> instructs the packer to copy through the original JAR file directly with no compression. The JSR 200 standard requires any unpacker to understand this special case as a pass-through of the entire archive. </p>
<p> The default is <i>5</i>, investing a modest amount of time to produce reasonable compression. </p>
<p> <tt>-Hvalue --deflate-hint=</tt><i>value</i> </p>
<p> Overrides the default, which preserves the input information, but may cause the transmitted archive to be larger. The possible values are: </p>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>true</p>
<dd>
<dt>false</p>
<dd>In either case, the packer will set the deflation hint accordingly in the output archive, and will not transmit the individual deflation hints of archive elements.</dl>
</dl>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>keep</p>
<dd>Preserve deflation hints observed in the input JAR. (This is the default.)</dl>
</dl>
<p> <tt>-mvalue --modification-time=</tt><i>value</i> </p>
<p> The possible values are: </p>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>latest</p>
<dd>The packer will attempt to determine the latest modification time, among all the available entries in the original archive, or the latest modification time of all the available entries in that segment. This single value will be transmitted as part of the segment and applied to all the entries in each segment. This can marginally decrease the transmitted size of the archive at the expense of setting all installed files to a single date.</p>
<dt>keep</p>
<dd>Preserves modification times observed in the input JAR. (This is the default.)</dl>
</dl>
<p> <tt>-Pfile --pass-file=</tt><i>file</i> </p>
<p> Indicates that a file should be passed through bytewise with no compression. By repeating the option, multiple files may be specified. There is no pathname transformation, except that the system file separator is replaced by the JAR file separator &quot;<i>/</i>&quot;. The resulting file names must match exactly as strings with their occurrences in the JAR file. If file is a directory name, all files under that directory will be passed. </p>
<p> <tt>-Uaction --unknown-attribute=</tt><i>action</i> </p>
<p> Overrides the default behavior; i.e., the classfile containing the unknown attribute will be passed through with the specified action. The possible values for actions are: </p>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>error</p>
<dd>The <i>pack200</i> operation as a whole will fail with a suitable explanation.</p>
<dt>strip</p>
<dd>The attribute will be dropped. Note: Removing the required VM attributes may cause Class Loader failures.</p>
<dt>pass</p>
<dd>Upon encountering this attribute, the entire class will be transmitted as though it is a resource.</dl>
</dl>
<p> <tt>-Cattribute-name=</tt><i>layout</i> <code>&#8211;class-attribute=</code><i>attribute-name=action</i><br />
 <tt>-Fattribute-name=</tt><i>layout</i> <code>&#8211;field-attribute=</code><i>attribute-name=action</i><br />
 <tt>-Mattribute-name=</tt><i>layout</i> <code>&#8211;method-attribute=</code><i>attribute-name=action</i><br />
 <tt>-Dattribute-name=</tt><i>layout</i> <code>&#8211;code-attribute=</code><i>attribute-name=action</i> </p>
<p> With the above four options, the attribute layout can be specified for a class entity, such as Class attribute, Field attribute, Method attribute, and Code attribute. The attribute-name is the name of the attribute for which the layout or action is being defined. The possible values for action are: </p>
<dl COMPACT>
<dd>
<dl COMPACT>
<dt>some-layout-string</p>
<dd>The layout language is defined in the JSR 200 specification.</dl>
<p> Example: <i>&#8211;class-attribute=SourceFile=RUH</i></p>
<dl COMPACT>
<dt>error</p>
<dd>Upon encountering this attribute, the pack200 operation will fail with a suitable explanation.</p>
<dt>strip</p>
<dd>Upon encountering this attribute, the attribute will be removed from the output. Note: removing VM-required attributes may cause Class Loader failures.</dl>
</dl>
<p> Example: <i>&#8211;class-attribute=CompilationID=pass</i> will cause the class file containing this attribute to be passed through without further action by the packer. </p>
<p> <tt>-f</tt><i> </i><i>pack.properties</i> <code>&#8211;config-file=</code><i>pack.properties</i> </p>
<p> A configuration file, containing Java properties to initialize the packer, may be specified on the command line. </p>
<p> <i>% pack200 -f pack.properties myarchive.pack.gz myarchive.jar</i><br />
 <i>% more pack.properties</i><br />
 <i># Generic properties for the packer.</i><br />
 <i>modification.time=latest</i><br />
 <i>deflate.hint=false</i><br />
 <i>keep.file.order=false</i><br />
 <i># This option will cause the files bearing new attributes to</i><br />
 <i># be reported as an error rather than passed uncompressed.</i><br />
 <i>unknown.attribute=error</i><br />
 <i># Change the segment limit to be unlimited.</i><br />
 <i>segment.limit=-1</i> </p>
<p> <tt>-v --verbose</tt> </p>
<p> Outputs minimal messages. Multiple specification of this option will output more verbose messages. </p>
<p> <tt>-q --quiet</tt> </p>
<p> Specifies quiet operation with no messages. </p>
<p> <tt>-lfilename --log-file=</tt><i>filename</i> </p>
<p> Specifies a log file to output messages. </p>
<p> <tt>-? -h --help</tt> </p>
<p> Prints help information about this command. </p>
<p> <tt>-V --version</tt> </p>
<p> Prints version information about this command. </p>
<p> <tt>-J</tt><i>option</i> </p>
<p> Passes <i>option</i> to the Java launcher called by <i>pack200</i>. For example, <i>-J-Xms48m</i> sets the startup memory to 48 megabytes. Although it does not begin with <i>-X</i>, it is not a standard option of <i>pack200</i>. It is a common convention for <i>-J</i> to pass options to the underlying VM executing applications written in Java. </p>
<h2>Exit Status</h2>
<p>The following exit values are returned: </p>
<p> <i>&nbsp;<wbr>0</i> for successful completion; </p>
<p> <i>&gt;0</i> if an error occurs. </p>
