<h2>NAME</h2>
<dl>
<dt><code>knsupdate</code></p>
<dd> &#8211; Dynamic DNS update utility (libknot equivalent of ISC nsupdate)</dl>
<h2>SYNOPSIS</h2>
<p> <code>knsupdate</code> [<i>options</i>] [<i>filename</i>]</p>
<h2>DESCRIPTION</h2>
<p> The utility sends Dynamic DNS update message to DNS server. Update content is read from a file (if the parameter <i>filename</i> is given) or from standard input. The format of the update is described in <code>INPUT FORMAT</code> section.</p>
<h2>OPTIONS</h2>
<dl>
<dt><code>-d</code></p>
<dd> Enable debugging messages.</p>
<dt><code>-v</code></p>
<dd> Use TCP protocol instead of the default UDP.</p>
<dt><code>-p</code><i>&nbsp;<wbr>port</i></p>
<dd> Set the port to use for connections to a server (if not explicitly specified in the update). The default is <i>53</i>.</p>
<dt><code>-t</code><i>&nbsp;<wbr>timeout</i></p>
<dd> The total timeout (all UDP update tries) of the update request in seconds. The default is <i>12</i>. If set to zero, the timeout is infinite.</p>
<dt><code>-r</code><i>&nbsp;<wbr>retries</i></p>
<dd> The number of retries for UDP requests. The default is <i>3</i>.</p>
<dt><code>-k</code><i>&nbsp;<wbr>keyfile</i></p>
<dd> Use TSIG or SIG-0 key stored in file to authenticate the request. The tool supports keys generated by ISC <code>dnssec-keygen</code>. The key comprises of public (.key extension) and private part (.private extension). Either of these file names or a name without the extension can be specified as <i>keyfile</i> parameter.</p>
<dt><code>-y</code><i>&nbsp;<wbr></i>[<i>hmac:</i>]<i>name:key</i></p>
<dd> Use TSIG key to authenticate the request. The <i>hmac</i> part specifies the algorithm (the default is hmac-md5), <i>name</i> specifies the key name, and <i>key</i> specifies the shared secret encoded in Base64.</p>
<dt><code>-h</code>,&nbsp;<wbr><code>&#8211;help</code></p>
<dd> Print help.</p>
<dt><code>-V</code>,&nbsp;<wbr><code>&#8211;version</code></p>
<dd> Print program version.</dl>
<h2>NOTE</h2>
<p> Options <code>-k</code> and <code>-y</code> cannot be used mutually.</p>
<h2>INPUT FORMAT</h2>
<p> The input format is textual and is made up of commands. Every command is placed on a separate line of the input. Lines starting with a semicolon are comments and are not processed.</p>
<dl>
<dt>List of commands format and their description:</p>
<dd>
<dt><code>server</code><i>&nbsp;<wbr>name</i><code>&nbsp;<wbr></code>[<i>port</i>]</p>
<dd> Specifies a receiving server of the dynamic update message. Parameter <i>name</i> can be either a host name or an IP address. If the <i>port</i> is not specified, default port is used. The default port value can be controlled using program option <code>-p</code>.</p>
<dt><code>local</code><i>&nbsp;<wbr>address</i><code>&nbsp;<wbr></code>[<i>port</i>]</p>
<dd> Specifies outgoing <i>address</i> and <i>port</i>. If no local is specified, the address and port are set by the system automatically. Default port number is <i>0</i>.</p>
<dt><code>zone</code><i>&nbsp;<wbr>name</i></p>
<dd> Specifies that all updates are done within a zone named <i>name</i>. If not used, the default zone is the root zone.</p>
<dt><code>origin</code><i>&nbsp;<wbr>name</i></p>
<dd> Specifies fully qualified domain name suffix which is appended to non-fqd owners in update commands. The default origin is the root zone.</p>
<dt><code>class</code><i>&nbsp;<wbr>name</i></p>
<dd> Sets <i>name</i> as a default class for all updates. If not used, the default class is <i>IN</i>.</p>
<dt><code>ttl</code><i>&nbsp;<wbr>value</i></p>
<dd> Sets <i>value</i> as a default TTL (in seconds). If not used, the default value is <i>0</i>.</p>
<dt><code>key</code><i>&nbsp;<wbr>name</i><code>&nbsp;<wbr></code><i>key</i></p>
<dd> Specifies TSIG key to authenticate the request. This command has the same semantics as the program option <code>-y</code>, except that the MAC algorithm cannot be set.</p>
<dt>[<code>prereq</code>] <code>nxdomain</code> <i>name</i></p>
<dd> Adds a prerequisite for non-existing record owned by <i>name</i>.</p>
<dt>[<code>prereq</code>] <code>yxdomain</code> <i>name</i></p>
<dd> Adds a prerequisite for existing record owned by <i>name</i>.</p>
<dt>[<code>prereq</code>] <code>nxrrset</code> <i>name</i> [<i>class</i>] <i>type</i></p>
<dd> Adds a prerequisite for non-existing record of the <i>type</i> owned by <i>name</i>. Internet class is expected.</p>
<dt>[<code>prereq</code>] <code>yxrrset</code> <i>name</i> [<i>class</i>] <i>type</i> [<i>data</i>]</p>
<dd> Adds a prerequisite for existing record of the <i>type</i> owned by <i>name</i> with optional <i>data</i>. Internet class is expected.</p>
<dt>[<code>update</code>] <code>add</code> <i>name</i> [<i>ttl</i>] [<i>class</i>] <i>type</i> <i>data</i></p>
<dd> Adds a request to add a new resource record into the zone. Please note that if the <i>name</i> is not fully qualified domain name, current <i>origin</i> name is appended to it.</p>
<dt>[<code>update</code>] <code>del</code>[<code>ete</code>] <i>name</i> [<i>ttl</i>] [<i>class</i>] [<i>type</i>] [<i>data</i>]</p>
<dd> Adds a request to remove all (or matching <i>class</i>, <i>type</i>, <i>data</i>) resource records from the zone. There is the same requirement for the <i>name</i> parameter as in the <code>update add</code> command. The <i>ttl</i> item is ignored.</p>
<dt><code>show</code></p>
<dd> Displays current content of the update message.</p>
<dt><code>send</code></p>
<dd> Sends the current update message and cleans the list of updates.</p>
<dt><code>answer</code></p>
<dd> Displays the last answer from the server.</p>
<dt><code>debug</code></p>
<dd> Enable debugging. This command has the same meaning as program option <code>-d</code>.</dl>
<h2>NOTE</h2>
<h3>Missing features with regard to ISC nsupdate</h3>
<p> Options <code>-D</code>, <code>-g</code>, <code>-o</code>, <code>-l</code>, <code>-L</code>, <code>-R</code>, <code>-u</code>.</p>
<dl>
<dt>Commands: <code>gsstsig</code>, <code>oldgsstsig</code>, <code>realm</code>.</p>
<dd></dl>
<h3>Differences with regard to ISC nsupdate</h3>
<p> Zone name/server guessing, if the zone name/server is not specified.</p>
<dl>
<dt>Empty line doesn&#8217;t send an update.</p>
<dd>
<dt>Bind-like key format (<code>ddns-confgen</code> output) is not supported.</p>
<dd></dl>
<h2>EXAMPLES</h2>
<p> <code>Example 1. Add two records to the zone example.com.:</code></p>
<dl>
<dt>
<pre>
<dd>knsupdate
server 192.168.1.1
zone example.com.
origin example.com.
ttl 3600
add test1.example.com. 7200 A 192.168.2.2
add test2 TXT &quot;hello&quot;
show
send
answer
</pre>
</dl>
