<p>selabel_x &#8211; userspace SELinux labeling interface and configuration file format for the X Window System contexts backend. This backend is also used to determine the default context for labeling remotely connected X clients</p>
<h2>Synopsis</h2>
<pre><code>#include &lt;selinux/label.h&gt;
int selabel_lookup(struct selabel_handle *hnd,

                   char **context,

                   const char *object_name, int object_type);
int selabel_lookup_raw(struct selabel_handle *hnd,

                       char **context,

                       const char *object_name, int object_type);</code></pre>
<h2>Description</h2>
<p>The X contexts backend maps from X Window System object names into security contexts. It is used to find the appropriate context for X Window System objects whose significance and/or usage semantics are determined primarily by name. The returned <i>context</i> must be freed using <code><a href="/docs/linux/man/3-freecon/">freecon</a></code>(3).<br />
 <code><a href="/docs/linux/man/3-selabel_lookup/">selabel_lookup</a></code>(3) describes the function with its return and error codes. </p>
<p> This backend is also used to determine the default context for labeling remotely connected X clients. </p>
<p> The <i>object_type</i> argument should be set to one of the following values:</p>
<dl>
<dd>
<dl>
<dt><code>SELABEL_X_PROP</code></p>
<dd>The <i>object_name</i> argument specifies the name of a window property, such as &quot;WM_NAME&quot;.</p>
<dt><code>SELABEL_X_SELN</code></p>
<dd>The <i>object_name</i> argument specifies the name of a selection, such as &quot;PRIMARY&quot;.</p>
<dt><code>SELABEL_X_EXT</code></p>
<dd>The <i>object_name</i> argument specifies the name of a protocol extension, such as &quot;RENDER&quot;.</p>
<dt><code>SELABEL_X_EVENT</code></p>
<dd>The <i>object_name</i> argument specifies the name of an event type, such as &quot;X11:ButtonPress&quot;.</p>
<dt><code>SELABEL_X_CLIENT</code></p>
<dd>The <i>object_name</i> argument is ignored, however it should be set to either <i>*</i> (an asterisk or &#8216;wildcard&#8217; that will select the default entry) or a specific entry such as &quot;remote&quot; in the X contexts file as shown in the <code>EXAMPLE</code> section. The default context for labeling remote X clients is then returned.</p>
<dt><code>SELABEL_X_POLYPROP</code></p>
<dd>Like <code>SELABEL_X_PROP</code>, but checks if the property was marked as being polyinstantiated. See <code>NOTES</code> below.</p>
<dt><code>SELABEL_X_POLYSELN</code></p>
<dd>Like <code>SELABEL_X_SELN</code>, but checks if the selection was marked as being polyinstantiated. See <code>NOTES</code> below.</dl>
</dl>
<p> Any messages generated by <code><a href="/docs/linux/man/3-selabel_lookup/">selabel_lookup</a></code>(3) are sent to <i>stderr</i> by default, although this can be changed by <code><a href="/docs/linux/man/3-selinux_set_callback/">selinux_set_callback</a></code>(3). </p>
<p> <code>selabel_lookup_raw</code> behaves identically to <code>selabel_lookup</code> but does not perform context translation. </p>
<p> The <code>FILES</code> section details the configuration files used to determine the X object context.</p>
<h2>Options</h2>
<p>In addition to the global options described in <code><a href="/docs/linux/man/3-selabel_open/">selabel_open</a></code>(3), this backend recognizes the following options:</p>
<dl>
<dd>
<dl>
<dt><code>SELABEL_OPT_PATH</code></p>
<dd>A non-null value for this option specifies a path to a file that will be opened in lieu of the standard X contexts file (see the <code>FILES</code> section for details).</dl>
</dl>
<h2>Files</h2>
<p>The X context file used to retrieve a default context depends on the <code>SELABEL_OPT_PATH</code> parameter passed to <code><a href="/docs/linux/man/3-selabel_open/">selabel_open</a></code>(3). If <i>NULL</i>, then the <code>SELABEL_OPT_PATH</code> value will default to the active policy X contexts location (as returned by <code><a href="/docs/linux/man/3-selinux_x_context_path/">selinux_x_context_path</a></code>(3)), otherwise the actual <code>SELABEL_OPT_PATH</code> value specified is used. </p>
<p> The default X object contexts file is:</p>
<dl>
<dd><i>/etc/selinux/{SELINUXTYPE}/contexts/x_contexts</i></dl>
<p> Where <i>{SELINUXTYPE}</i> is the entry from the selinux configuration file <i>config</i> (see <code><a href="/docs/linux/man/5-selinux_config/">selinux_config</a></code>(5)). </p>
<p> The entries within the X contexts file are shown in the <code>Object Name String Values</code> and <code>FILE FORMAT</code> sections.</p>

<h2>File Format</h2>
<p>Each line within the X contexts file is as follows:</p>
<dl>
<dd><i>object_type object_name context</i></dl>
<p> Where:</p>
<dl>
<dd><i>object_type</i></p>
<dl>
<dd>This is the string representation of the object type shown in the <code>Object Name String Values</code> section. There can be multiple lines with the same <i>object_type</i> string that will form a block of entries (each with a different <i>object_name</i> entry).</dl>
<p> <i>object_name</i></p>
<dl>
<dd>These are the object names of the specific X-server resource such as <code>PRIMARY</code>, <code>CUT_BUFFER0</code> etc. They are generally defined in the X-server source code (<i>protocol.txt</i> and <i>BuiltInAtoms</i> in the dix directory of the xorg-server source package). The entry can contain &#8216;*&#8217; for wildcard matching or &#8216;?&#8217; for substitution. Note that if the &#8216;*&#8217; is used, then be aware that the order of entries in the file is important. The &#8216;*&#8217; on its own is used to ensure a default fallback context is assigned and should be the last entry in the <i>object_type</i> block.</dl>
<p> <i>context</i></p>
<dl>
<dd>The security context that will be applied to the object.</dl>
</dl>
<p> Example 1: </p>
<pre># object_type object_name context
selection PRIMARY system_u:object_r:clipboard_xselection_t:s0
selection * system_u:object_r:xselection_t:s0</pre>
<p>Example 2 &#8211; This example shows how a client entry can be configured to ensure an entry is always found: </p>
<pre># object_type object_name context
client * system_u:object_r:remote_t:s0</pre>
<h2>Notes</h2>
<dl>
<dt>1.</p>
<dd>Properties and selections are marked as either polyinstantiated or not. For these name types, the &quot;POLY&quot; option searches only the names marked as being polyinstantiated, while the other option searches only the names marked as not being polyinstantiated. Users of the interface should check both mappings, optionally taking action based on the result (e.g. polyinstantiating the object).</p>
<dt>2.</p>
<dd>If contexts are to be validated, then the global option <code>SELABEL_OPT_VALIDATE</code> must be set before calling <code><a href="/docs/linux/man/3-selabel_open/">selabel_open</a></code>(3). If this is not set, then it is possible for an invalid context to be returned.</dl>
