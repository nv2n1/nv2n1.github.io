<p>exclusion &#8211; Exclude a set of hosts from a definition in a shorewall configuration file.</p>
<h2>Synopsis</h2>
<dl>
<dt> <code>!</code><i>address-or-range</i>[,<i>address-or-range</i>]&#8230;</p>
<dt> <code>!</code><i>zone-name</i>[,<i>zone-name</i>]&#8230;</dl>
<h2>Description</h2>
<dd>The first form of exclusion is used when you wish to exclude one or more addresses from a definition. An exclamation point is followed by a comma-separated list of addresses. The addresses may be single host addresses (e.g., 192.168.1.4) or they may be network addresses in CIDR format (e.g., 192.168.1.0/24). If your kernel and iptables include iprange support, you may also specify ranges of ip addresses of the form <i>lowaddress</i>&#8211;<i>highaddress</i> No embedded white-space is allowed. Exclusion can appear after a list of addresses and/or address ranges. In that case, the final list of address is formed by taking the first list and then removing the addresses defined in the exclusion. Beginning in Shorewall 4.4.13, the second form of exclusion is allowed after <code>all</code> and <code>any</code> in the SOURCE and DEST columns of /etc/shorewall/rules. It allows you to omit arbitrary zones from the list generated by those key words.</p>
<dl>
<dd><font SIZE="+1"> <code>Warning</code> </font><br />
 If you omit a sub-zone and there is an explicit or explicit CONTINUE policy, a connection to/from that zone can still be matched by the rule generated for a parent zone. For example: /etc/shorewall/zones:</p>
<dl>
<dd>
<pre>#ZONE TYPE
z1 ip
z2:z1 ip
...</pre>
</dl>
<p> /etc/shorewall/policy:</p>
<dl>
<dd>
<pre>#SOURCE DEST POLICY
z1 net CONTINUE
z2 net REJECT</pre>
</dl>
<p> /etc/shorewall/rules:</p>
<dl>
<dd>
<pre>#ACTION SOURCE DEST PROTO DPORT
ACCEPT all!z2 net tcp 22</pre>
</dl>
<p> In this case, SSH connections from <code>z2</code> to <code>net</code> will be accepted by the generated <code>z1</code> to net ACCEPT rule.  In most contexts, ipset names can be used as an <i>address-or-range</i>. Beginning with Shorewall 4.4.14, ipset lists enclosed in +[&#8230;] may also be included (see m[blue]<code>shorewall-ipsets</code>m[]<font SIZE="-2">[1]</font> (5)). The semantics of these lists when used in an exclusion are as follows:</p>
<dl>
<dd>&bull; !+[<i>set1</i>,<i>set2</i>,&#8230;<i>setN</i>] produces a packet match if the packet does not match at least one of the sets. In other words, it is like NOT match <i>set1</i> OR NOT match <i>set2</i> &#8230; OR NOT match <i>setN</i>.</dl>
<dl>
<dd>&bull; +[!<i>set1</i>,!<i>set2</i>,&#8230;!<i>setN</i>] produces a packet match if the packet does not match any of the sets. In other words, it is like NOT match <i>set1</i> AND NOT match <i>set2</i> &#8230; AND NOT match <i>setN</i>.</dl>
<h2>Examples</h2>
<p>Example 1 &#8211; All IPv4 addresses except 192.168.3.4</p>
<dl>
<dd>!192.168.3.4</dl>
<p> Example 2 &#8211; All IPv4 addresses except the network 192.168.1.0/24 and the host 10.2.3.4</p>
<dl>
<dd>!192.168.1.0/24,10.1.3.4</dl>
<p> Example 3 &#8211; All IPv4 addresses except the range 192.168.1.3-192.168.1.12 and the network 10.0.0.0/8</p>
<dl>
<dd>!192.168.1.3-192.168.1.12,10.0.0.0/8</dl>
<p> Example 4 &#8211; The network 192.168.1.0/24 except hosts 192.168.1.3 and 192.168.1.9</p>
<dl>
<dd>192.168.1.0/24!192.168.1.3,192.168.1.9</dl>
<p> Example 5 &#8211; All parent zones except loc</p>
<dl>
<dd>any!loc</dl>
