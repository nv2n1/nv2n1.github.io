<p>slapo-retcode &#8211; return code overlay to slapd</p>
<h2>Synopsis</h2>
<p>/etc/openldap/slapd.conf</p>
<h2>Description</h2>
<p>The <code>retcode</code> overlay to <code><a href="/docs/linux/man/8-slapd/">slapd</a></code>(8) is useful to test the behavior of clients when server-generated erroneous and/or unusual responses occur, e.g. error codes, referrals, excessive response times and so on. The error responses are generated according to different strategies. In the first case, all operations targeted at a specific configurable subtree cause the object related to the request DN to be looked up and checked for return code data: a response code, plus an optional textual message, an optional configurable delay, an optional matched DN field, and, when the response code is &quot;referral&quot;, a (list of) referral(s). Well-known response codes from standard track documents are provided in <code>retcode.conf</code>, which can be included after instantiating the overlay. In the second case, objects of classes inherited from the <code>errAbsObject</code>, like <code>errObject</code> or <code>errAuxObject</code>, when returned as intermediate responses of a search request, are changed into the response dictated by their content. A third mode causes objects to be looked up from the underlying database to discover if their class inherits from <code>errABsObject</code>; in that case, their content is used to compute the corresponding response. The behavior is disabled by using the <code>manageDSAit</code> control (RFC 3296); in that case, the resulting object, either present in the directory or dynamically generated by the overlay, or contained in the request, is handled as usual. The config directives that are specific to the <code>retcode</code> overlay must be prefixed by <code>retcode-</code>, to avoid conflicts with directives specific to the underlying database or to other stacked overlays. The following specific directives can be used to configure the retcode overlay:</p>
<dl>
<dt><code>retcode-parent &lt;DN&gt;</code></p>
<dd>This directive defines the parent DN where dynamically generated entries reside. If not defined, the suffix of the database is used.</p>
<dt> <code>retcode-item &lt;RDN&gt; &lt;errCode&gt; [op=&lt;oplist&gt;] [text=&lt;message&gt;]</code> <code>[ref=&lt;referral&gt;] [sleeptime=&lt;sec&gt;] [matched=&lt;DN&gt;]</code> <code>[unsolicited=&lt;OID&gt;[:&lt;data&gt;]] [flags=[{pre|post}-]disconnect[,&#8230;]]</code></p>
<dl>
<dd>
<dd>A dynamically generated entry, located below <code>retcode-parent</code>. The <code>errCode</code> is the number of the response code; it can be in any format supported by <code><a href="/docs/linux/man/3-strtol/">strtol</a></code>(3). The optional <code>oplist</code> is a list of operations that cause response code generation; if absent, all operations are affected. The <code>matched</code> field is the matched DN that is returned along with the error, while the <code>text</code> field is an optional diagnostics message. The <code>ref</code> field is only allowed for the <code>referral</code> response code. The <code>sleeptime</code> field causes <code><a href="/docs/linux/man/8-slapd/">slapd</a></code>(8) to sleep the specified number of seconds before proceeding with the operation. The <code>unsolicited</code> field can be used to cause the return of an RFC 4511 unsolicited response message; if <code>OID</code> is not &quot;0&quot;, an extended response is generated, with the optional <code>data</code> appended. If <code>flags</code> contains <code>disconnect</code>, or <code>pre-disconnect</code>, <code><a href="/docs/linux/man/8-slapd/">slapd</a></code>(8) disconnects abruptly, without notice; <code>post-disconnect</code> causes disconnection right after sending response as appropriate.</dl>
<dt><code>retcode-indir</code></p>
<dd>Enables exploitation of in-directory stored errAbsObject. May result in a lot of unnecessary overhead.</p>
<dt><code>retcode-sleep [-]&lt;n&gt;</code></p>
<dd>Defines a sleep time in seconds that is spent before actually handling any operation. If negative, a random time between 0 and the absolute value of the argument is used. </p>
<h2>Schema</h2>
<p>The <code>retcode</code> overlay utilizes the &quot;return code&quot; schema described herein. This schema is specifically designed for use with this overlay and is not intended to be used otherwise. It is also noted that the schema described here is <i>a work in</i> <i>progress</i>, and hence subject to change without notice. The schema is loaded automatically by the overlay. </p>
<p> The schema includes a number of object classes and associated attribute types as described below. </p>

<h2>Example</h2>
<pre><code>overlay         retcode
retcode-parent  &quot;ou=RetCodes,dc=example,dc=com&quot;

# retcode.conf is found in tests/data/ of the source tree
include         ./retcode.conf

# Wait 10 seconds, then return success (0x00)
retcode-item    &quot;cn=Success after 10 seconds&quot; 0x00 sleeptime=10
# Wait 10 seconds, then return timelimitExceeded (0x03)
retcode-item    &quot;cn=Timelimit after 10 seconds&quot; 0x03 sleeptime=10


</code></pre>
