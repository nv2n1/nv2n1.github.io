<p>selabel_file &#8211; userspace SELinux labeling interface and configuration file format for the file contexts backend</p>
<h2>Synopsis</h2>
<pre><code>#include &lt;selinux/label.h&gt;
int selabel_lookup(struct selabel_handle *hnd,

                   char **context,

                   const char *path, int mode);
int selabel_lookup_raw(struct selabel_handle *hnd,

                       char **context,

                       const char *path, int mode);</code></pre>
<h2>Description</h2>
<p>The file contexts backend maps from pathname/mode combinations into security contexts. It is used to find the appropriate context for each file when relabeling a file system. The returned <i>context</i> must be freed using <code><a href="/docs/linux/man/3-freecon/">freecon</a></code>(3).<br />
 <code><a href="/docs/linux/man/3-selabel_lookup/">selabel_lookup</a></code>(3) describes the function with its return and error codes, however the following <i>errno</i> is clarified further for the file contexts backend:</p>
<dl>
<dd>
<dl>
<dt><code>ENOENT</code></p>
<dd>No context corresponding to the <i>path</i> and <i>mode</i> was found &#8211; This will also be returned when the file contexts series of files have a context of <code>&lt;&lt;none&gt;&gt;</code> against the <i>path</i> (see the <code>FILE FORMAT</code> section).</dl>
</dl>
<p> The <i>path</i> argument should be set to the full pathname of the file whose assigned context is being checked. The <i>mode</i> argument should be set to the mode bits of the file, as determined by <code><a href="/docs/linux/man/2-lstat/">lstat</a></code>(2). <i>mode</i> may be zero, however full matching may not occur. </p>
<p> Any messages generated by <code><a href="/docs/linux/man/3-selabel_lookup/">selabel_lookup</a></code>(3) are sent to <i>stderr</i> by default, although this can be changed by <code><a href="/docs/linux/man/3-selinux_set_callback/">selinux_set_callback</a></code>(3). </p>
<p> <code><a href="/docs/linux/man/3-selabel_lookup_raw/">selabel_lookup_raw</a></code>(3) behaves identically to <code><a href="/docs/linux/man/3-selabel_lookup/">selabel_lookup</a></code>(3) but does not perform context translation. </p>
<p> The <code>FILES</code> section details the configuration files used to determine a file context.</p>
<h2>Options</h2>
<p>In addition to the global options described in <code><a href="/docs/linux/man/3-selabel_open/">selabel_open</a></code>(3), this backend recognizes the following options:</p>
<dl>
<dd>
<dl>
<dt><code>SELABEL_OPT_PATH</code></p>
<dd>A non-null value for this option specifies a path to a file that will be opened in lieu of the standard file contexts file. This value is also used as the base name for determining the names of local customization files.</p>
<dt><code>SELABEL_OPT_BASEONLY</code></p>
<dd>A non-null value for this option indicates that any local customizations to the file contexts mapping should be ignored.</p>
<dt><code>SELABEL_OPT_SUBSET</code></p>
<dd>A non-null value for this option is interpreted as a path prefix, for example &quot;/etc&quot;. Only file context specifications with starting with a first component that prefix matches the given prefix are loaded. This may increase lookup performance, however any attempt to look up a path not starting with the given prefix may fail. This optimization is no longer required due to the use of <i>file_contexts.bin</i> files and is deprecated.</dl>
</dl>
<h2>Files</h2>
<p>The file context files used to retrieve the default context depends on the <code>SELABEL_OPT_PATH</code> parameter passed to <code><a href="/docs/linux/man/3-selabel_open/">selabel_open</a></code>(3). If <i>NULL</i>, then the <code>SELABEL_OPT_PATH</code> value will default to the active policy file contexts location (as returned by <code><a href="/docs/linux/man/3-selinux_file_context_path/">selinux_file_context_path</a></code>(3)), otherwise the actual <code>SELABEL_OPT_PATH</code> value specified is used. </p>
<p> If <code>SELABEL_OPT_BASEONLY</code> is set, then the following files will be processed:</p>
<dl>
<dd>
<dl>
<dt>1.</p>
<dd>The mandatory file contexts file that is either the fully qualified file name from <i>SELABEL_OPT_PATH.value</i> or if <i>NULL</i>, then the path returned by <code><a href="/docs/linux/man/3-selinux_file_context_path/">selinux_file_context_path</a></code>(3).</p>
<dt>2.</p>
<dd>The optional local and distribution substitution files that perform path aliasing on the &#8216;in memory&#8217; version of the file contexts file.<br />
 These files have the same name as the mandatory file contexts file with the extensions <i>.subs</i> and <i>.subs_dist</i> added.</dl>
</dl>
<p> If the <code>SELABEL_OPT_BASEONLY</code> is not set, then the following files will be processed:</p>
<dl>
<dd>
<dl>
<dt>1.</p>
<dd>The mandatory file contexts file that is either the fully qualified file name from <i>SELABEL_OPT_PATH.value</i> or if <i>NULL</i>, then the path returned by <code><a href="/docs/linux/man/3-selinux_file_context_path/">selinux_file_context_path</a></code>(3).</p>
<dt>2.</p>
<dd>The optional local customizations file that has the same name as the mandatory file contexts file with the extension <i>.local</i> added.<br />
 <code><a href="/docs/linux/man/3-selinux_file_context_local_path/">selinux_file_context_local_path</a></code>(3) will return the default path to this file.</p>
<dt>3.</p>
<dd>The optional user home directory customizations file that has the same name as the mandatory file contexts file with the extension <i>.homedirs</i> added.<br />
 <code><a href="/docs/linux/man/3-selinux_file_context_homedir_path/">selinux_file_context_homedir_path</a></code>(3) will return the default path to this file.</p>
<dt>4.</p>
<dd>The optional local and distribution substitution files that perform any path aliasing on the &#8216;in memory&#8217; version of the file contexts file (and the <i>.local</i> and/or <i>.homedirs</i> if present). These files have the same name as the mandatory file contexts file with the extensions <i>.subs</i> and <i>.subs_dist</i> added.<br />
 <code><a href="/docs/linux/man/3-selinux_file_context_subs_path/">selinux_file_context_subs_path</a></code>(3) and <code><a href="/docs/linux/man/3-selinux_file_context_subs_dist_path/">selinux_file_context_subs_dist_path</a></code>(3) will return the default paths to these files.</dl>
</dl>
<p> The default file context series of files are:</p>
<dl>
<dd><i>/etc/selinux/{SELINUXTYPE}/contexts/files/file_contexts</i><br />
 <i>/etc/selinux/{SELINUXTYPE}/contexts/files/file_contexts.local</i><br />
 <i>/etc/selinux/{SELINUXTYPE}/contexts/files/file_contexts.homedirs</i><br />
 <i>/etc/selinux/{SELINUXTYPE}/contexts/files/file_contexts.subs</i><br />
 <i>/etc/selinux/{SELINUXTYPE}/contexts/files/file_contexts.subs_dist</i></dl>
<p> Where <i>{SELINUXTYPE}</i> is the entry from the selinux configuration file <i>config</i> (see <code><a href="/docs/linux/man/5-selinux_config/">selinux_config</a></code>(5)). </p>
<p> Only the <i>file_contexts</i> file is mandatory, the remainder are optional. </p>
<p> The entries within the file contexts series of files are shown in the <code>FILE FORMAT</code> section.</p>
<h2>File Format</h2>
<h2>File Contexts Format</h2>
<p>Each line within the <i>file_contexts</i> and the two customization files (<i>.local</i> and <i>.homedirs</i>) is as follows: </p>
<dl>
<dd><i>pathname [file_type] context</i></dl>
<p> Where: </p>
<dl>
<dd><i>pathname</i></p>
<dl>
<dd>An entry that defines the pathname that may be in the form of a regular expression.</dl>
<p> <i>file_type</i></p>
<dl>
<dd>An optional file type consisting of:</p>
<dl>
<dd><i>-b</i> &#8211; Block Device <i>-c</i> &#8211; Character Device<br />
 <i>-d</i> &#8211; Directory <i>-p</i> &#8211; Named Pipe<br />
 <i>-l</i> &#8211; Symbolic Link <i>-s</i> &#8211; Socket<br />
 <i>&#8212;</i> &#8211; Ordinary file</dl>
</dl>
<p> <i>context</i></p>
<dl>
<dd>This entry can be either:</p>
<dl>
<dd>
<dl>
<dt>a.</p>
<dd>The security context that will be assigned to the file (i.e. returned as <i>context</i>).</p>
<dt>b.</p>
<dd>A value of <code>&lt;&lt;none&gt;&gt;</code> can be used to indicate that the matching files should not be re-labeled and causes <code><a href="/docs/linux/man/3-selabel_lookup/">selabel_lookup</a></code>(3) to return -1 with <i>errno</i> set to <code>ENOENT</code>.</dl>
</dl>
</dl>
</dl>
<p> Example:</p>
<dl>
<dd># ./contexts/files/file_contexts<br />
 # pathname file_type context<br />
 /.* system_u:object_r:default_t:s0<br />
 /[^/]+ &#8212; system_u:object_r:etc_runtime_t:s0<br />
 /tmp/.* &lt;&lt;none&gt;&gt;</dl>
<h2>Substitution File Format</h2>
<p>Each line within the substitution files (<i>.subs</i> and <i>.subs_dist</i>) has the form:</p>
<dl>
<dd><i>subs_pathname pathname</i></dl>
<p> Where:</p>
<dl>
<dd><i>pathname</i></p>
<dl>
<dd>A path that matches an entry in one or more of the file contexts policy configuration file.</dl>
<p> <i>subs_pathname</i></p>
<dl>
<dd>The path that will be aliased (considered equivalent) with pathname by the look up process.</dl>
</dl>
<p> Example:</p>
<dl>
<dd># ./contexts/files/file_contexts.subs<br />
 # pathname subs_pathname<br />
 /myweb /var/www<br />
 /myspool /var/spool/mail </p>
<p> Using the above example, when <code><a href="/docs/linux/man/3-selabel_lookup/">selabel_lookup</a></code>(3) is passed a path of <i>/myweb/index.html</i> the function will substitute the <i>/myweb</i> component with <i>/var/www</i>, therefore the path used is: </p>
<dl>
<dd><i>/var/www/index.html</i></dl>
</dl>
<h2>Notes</h2>
<dl>
<dt>1.</p>
<dd>If contexts are to be validated, then the global option <code>SELABEL_OPT_VALIDATE</code> must be set before calling <code><a href="/docs/linux/man/3-selabel_open/">selabel_open</a></code>(3). If this is not set, then it is possible for an invalid context to be returned.</p>
<dt>2.</p>
<dd>If the size of file contexts series of files contain many entries, then <code><a href="/docs/linux/man/3-selabel_open/">selabel_open</a></code>(3) may have a delay as it reads in the files, and if requested validates the entries.</p>
<dt>3.</p>
<dd>Depending on the version of SELinux it is possible that a <i>file_contexts.template</i> file may also be present, however this is now deprecated.<br />
 The template file has the same format as the <i>file_contexts</i> file and may also contain the keywords <code>HOME_ROOT</code>, <code>HOME_DIR</code>, <code>ROLE</code> and <code>USER</code>. This functionality has now been moved to the policy store and managed by <code><a href="/docs/linux/man/8-semodule/">semodule</a></code>(8) and <code><a href="/docs/linux/man/8-genhomedircon/">genhomedircon</a></code>(8).</dl>
