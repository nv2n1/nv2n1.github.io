<p>blrules &#8211; shorewall Blacklist file</p>
<h2>Synopsis</h2>
<dl>
<dt> <code>/etc/shorewall/blrules</code></dl>
<h2>Description</h2>
<dd>This file is used to perform blacklisting and whitelisting. </p>
<p> Rules in this file are applied depending on the setting of BLACKLISTNEWONLY in m[blue]<code>shorewall.conf</code>m[]<font SIZE="-2">[1]</font>(5). If BLACKLISTNEWONLY=No, then they are applied regardless of the connection tracking state of the packet. If BLACKLISTNEWONLY=Yes, they are applied to connections in the NEW and INVALID states. </p>
<p> The format of rules in this file is the same as the format of rules in m[blue]<code>shorewall-rules (5)</code>m[]<font SIZE="-2">[2]</font>. The difference in the two files lies in the ACTION (first) column. </p>
<p> <code>ACTION- {</code><code>ACCEPT</code><code>|BLACKLIST|blacklog|CONTINUE|DROP|A_DROP|REJECT|A_REJECT|</code><code>WHITELIST</code><code>|</code><code>LOG</code><code>|</code><code>QUEUE</code><code>|</code><code>NFQUEUE</code><code>[</code><code>(</code><i>queuenumber</i><code>)</code><code>]</code><code>|[?]COMMENT</code><code>|</code><i>action</i><code>|</code><i>macro</i><code>[</code><code>(</code><i>target</i><code>)</code><code>]}</code><code>[:</code><code>{</code><i>log-level</i><code>|</code><code>none</code><code>}[</code><code>!</code><code>][</code><code>:</code><i>tag</i><code>]]</code></p>
<dl>
<dd>Specifies the action to be taken if the packet matches the rule. Must be one of the following. </p>
<p> <code>BLACKLIST</code></p>
<dl>
<dd>Added in Shorewall 4.5.3. This is actually a macro that expands as follows: </p>
<dl>
<dd>&bull; If BLACKLIST_LOGLEVEL is specified in m[blue]<code>shorewall.conf</code>m[]<font SIZE="-2">[1]</font>(5), then the macro expands to <code>blacklog</code>.</dl>
<dl>
<dd>&bull; Otherwise it expands to the action specified for BLACKLIST_DISPOSITION in m[blue]<code>shorewall.conf</code>m[]<font SIZE="-2">[1]</font>(5).</dl>
</dl>
<p> <code>blacklog</code></p>
<dl>
<dd>May only be used if BLACKLIST_LOGLEVEL is specified in m[blue]<code>shorewall.conf</code>m[]<font SIZE="-2">[1]</font>(5). Logs, audits (if specified) and applies the BLACKLIST_DISPOSITION specified in m[blue]<code>shorewall.conf</code>m[]<font SIZE="-2">[1]</font> (5).</dl>
<p> <code>ACCEPT|CONTINUE|WHITELIST</code></p>
<dl>
<dd>Exempt the packet from the remaining rules in this file.</dl>
<p> <code>DROP</code></p>
<dl>
<dd>Ignore the packet.</dl>
<p> A_DROP and A_DROP!</p>
<dl>
<dd>Audited versions of DROP. Requires AUDIT_TARGET support in the kernel and ip6tables.</dl>
<p> <code>REJECT</code></p>
<dl>
<dd>disallow the packet and return an icmp-unreachable or an RST packet.</dl>
<p> A_REJECT</p>
<dl>
<dd>Audited versions of REJECT. Require AUDIT_TARGET support in the kernel and ip6tables.</dl>
<p> <code>LOG</code></p>
<dl>
<dd>Simply log the packet and continue with the next rule.</dl>
<p> <code>QUEUE</code></p>
<dl>
<dd>Queue the packet to a user-space application such as ftwall (<a rel="nofollow" href="http://p2pwall.sf.net">http://p2pwall.sf.net</a>). The application may reinsert the packet for further processing.</dl>
<p> <code>NFLOG</code>[(<i>nflog-parameters</i>)]</p>
<dl>
<dd>queues matching packets to a back end logging daemon via a netlink socket then continues to the next rule. See m[blue]<code><a rel="nofollow" href="http://www.shorewall.net/shorewall_logging.html">http://www.shorewall.net/shorewall_logging.html</a></code>m[]<font SIZE="-2">[3]</font>.</dl>
<p> <code>NFQUEUE</code></p>
<dl>
<dd>Queues the packet to a user-space application using the nfnetlink_queue mechanism. If a <i>queuenumber</i> is not specified, queue zero (0) is assumed.</dl>
<p> <code>?COMMENT</code></p>
<dl>
<dd>The rest of the line will be attached as a comment to the Netfilter rule(s) generated by the following entries. The comment will appear delimited by &quot;/* &#8230; */&quot; in the output of &quot;shorewall show &lt;chain&gt;&quot;. To stop the comment from being attached to further rules, simply include ?COMMENT on a line by itself.</dl>
<p> <i>action</i></p>
<dl>
<dd>The name of an <i>action</i> declared in m[blue]<code>shorewall-actions</code>m[]<font SIZE="-2">[4]</font>(5) or in /usr/share/shorewall/actions.std.</dl>
<p> <i>macro</i></p>
<dl>
<dd>The name of a macro defined in a file named macro.<i>macro</i>. If the macro accepts an action parameter (Look at the macro source to see if it has PARAM in the TARGET column) then the <i>macro</i> name is followed by the parenthesized <i>target</i> (<code>ACCEPT</code>, <code>DROP</code>, <code>REJECT</code>, &#8230;) to be substituted for the parameter. </p>
<p> Example: FTP(ACCEPT).</dl>
<p> The <code>ACTION</code> may optionally be followed by &quot;:&quot; and a syslog log level (e.g, REJECT:info or Web(ACCEPT):debug). This causes the packet to be logged at the specified level. </p>
<p> If the <code>ACTION</code> names an <i>action</i> declared in m[blue]<code>shorewall-actions</code>m[]<font SIZE="-2">[4]</font>(5) or in /usr/share/shorewall/actions.std then: </p>
<dl>
<dd>&bull; If the log level is followed by &quot;!&#8217; then all rules in the action are logged at the log level.</dl>
<dl>
<dd>&bull; If the log level is not followed by &quot;!&quot; then only those rules in the action that do not specify logging are logged at the specified level.</dl>
<dl>
<dd>&bull; The special log level <code>none!</code> suppresses logging by the action.</dl>
<p> You may also specify <code>NFLOG</code> (must be in upper case) as a log level.This will log to the NFLOG target for routing to a separate log through use of ulogd (m[blue]<code><a rel="nofollow" href="http://www.netfilter.org/projects/ulogd/index.html">http://www.netfilter.org/projects/ulogd/index.html</a></code>m[]). </p>
<p> Actions specifying logging may be followed by a log tag (a string of alphanumeric characters) which is appended to the string generated by the LOGPREFIX (in m[blue]<code>shorewall.conf</code>m[]<font SIZE="-2">[1]</font>(5)).</dl>
<p> For the remaining columns, see m[blue]<code>shorewall-rules (5)</code>m[]<font SIZE="-2">[2]</font>.</p>
<h2>Example</h2>
<p>Example 1:</p>
<dl>
<dd>Drop Teredo packets from the net. </p>
<dl>
<dd>
<pre>DROP net:[2001::/32] all</pre>
</dl>
</dl>
<p> Example 2:</p>
<dl>
<dd>Don&#8217;t subject packets from 2001:DB8::/64 to the remaining rules in the file. </p>
<dl>
<dd>
<pre>WHITELIST net:[2001:DB8::/64] all</pre>
</dl>
</dl>
