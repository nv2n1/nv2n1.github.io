<p>nat &#8211; Shorewall one-to-one NAT file</p>
<h2>Synopsis</h2>
<dl>
<dt> <code>/etc/shorewall/nat</code></dl>
<h2>Description</h2>
<dd>This file is used to define one-to-one Network Address Translation (NAT).</p>
<dl>
<dd><font SIZE="+1"> <code>Warning</code> </font><br />
 If all you want to do is simple port forwarding, do NOT use this file. See m[blue]<code><a rel="nofollow" href="http://www.shorewall.net/FAQ.htm#faq1">http://www.shorewall.net/FAQ.htm#faq1</a></code>m[]<font SIZE="-2">[1]</font>. Also, in many cases, Proxy ARP (m[blue]<code>shorewall-proxyarp</code>m[]<font SIZE="-2">[2]</font>(5)) is a better solution that one-to-one NAT.  The columns in the file are as follows (where the column name is followed by a different name in parentheses, the different name is used in the alternate specification syntax). <code>EXTERNAL</code> &#8211; {<i>address</i>|?COMMENT}</p>
<dl>
<dd>External IP Address &#8211; this should NOT be the primary IP address of the interface named in the next column and must not be a DNS Name. If you put ?COMMENT in this column, the rest of the line will be attached as a comment to the Netfilter rule(s) generated by the following entries in the file. The comment will appear delimited by &quot;/* &#8230; */&quot; in the output of &quot;shorewall show nat&quot; To stop the comment from being attached to further rules, simply include ?COMMENT on a line by itself.</dl>
<p> <code>INTERFACE</code> &#8211; <i>interfacelist</i>[<code>:</code>[<i>digit</i>]]</p>
<dl>
<dd>Interfaces that have the <code>EXTERNAL</code> address. If ADD_IP_ALIASES=Yes in m[blue]<code>shorewall.conf</code>m[]<font SIZE="-2">[3]</font>(5), Shorewall will automatically add the EXTERNAL address to this interface. Also if ADD_IP_ALIASES=Yes, you may follow the interface name with &quot;:&quot; and a <i>digit</i> to indicate that you want Shorewall to add the alias with this name (e.g., &quot;eth0:0&quot;). That allows you to see the alias with ifconfig. <code>That is the only thing that this name is good for &#8212; you cannot use it anywhere else in your Shorewall configuration. </code> Each interface must match an entry in m[blue]<code>shorewall-interfaces</code>m[]<font SIZE="-2">[4]</font>(5). Shorewall allows loose matches to wildcard entries in m[blue]<code>shorewall-interfaces</code>m[]<font SIZE="-2">[4]</font>(5). For example, ppp0 in this file will match a m[blue]<code>shorewall-interfaces</code>m[]<font SIZE="-2">[4]</font>(5) entry that defines ppp+. If you want to override ADD_IP_ALIASES=Yes for a particular entry, follow the interface name with &quot;:&quot; and no digit (e.g., &quot;eth0:&quot;).</dl>
<p> <code>INTERNAL</code> &#8211; <i>address</i></p>
<dl>
<dd>Internal Address (must not be a DNS Name).</dl>
<p> <code>ALLINTS</code> &#8211; [<code>Yes</code>|<code>No</code>]</p>
<dl>
<dd>If Yes or yes, NAT will be effective from all hosts. If No or no (or left empty) then NAT will be effective only through the interface named in the <code>INTERFACE</code> column. This column was formerly labelled ALL INTERFACES.</dl>
<p> <code>LOCAL</code> &#8211; [<code>Yes</code>|<code>No</code>]</p>
<dl>
<dd>If <code>Yes</code> or <code>yes</code>, NAT will be effective from the firewall system</dl>
<h2>Restrictions</h2>
<p>DNAT rules always preempt one-to-one NAT rules. This has subtile consequences when there are sub-zones on an <i>interface</i>. Consider the following: </p>
<p> /etc/shorewall/zones: </p>
<dl>
<dd>
<pre>#ZONE TYPE OPTIONS IN OUT
# OPTIONS OPTIONS
fw firewall
net ipv4
loc ipv4
smc:net ipv4</pre>
</dl>
<p> /etc/shorewall/interfaces: </p>
<dl>
<dd>
<pre>#ZONE INTERFACE OPTIONS
net eth0 dhcp,tcpflags,nosmurfs,routefilter,logmartians,sourceroute=0
loc eth1 tcpflags,nosmurfs,routefilter,logmartians</pre>
</dl>
<p> /etc/shorewall/hosts: </p>
<dl>
<dd>
<pre>#ZONE HOST(S) OPTIONS
smc eth0:10.1.10.0/24</pre>
</dl>
<p> /etc/shorewall/nat: </p>
<dl>
<dd>
<pre>#EXTERNAL INTERFACE INTERNAL ALLINTS LOCAL
10.1.10.100 eth0 172.20.1.100</pre>
</dl>
<p> Note that the EXTERNAL address is in the <code>smc</code> zone. </p>
<p> /etc/shorewall/rules: </p>
<dl>
<dd>
<pre>#ACTION SOURCE DEST PROTO DPORT SPORT ORIGDEST RATE USER MARK CONNLIMIT TIME HEADERS SWITCH HELPER
?SECTION ALL
?SECTION ESTABLISHED
?SECTION RELATED
?SECTION INVALID
?SECTION UNTRACKED
?SECTION NEW
...
DNAT net loc:172.20.1.4 tcp 80</pre>
</dl>
<p> For the one-to-one NAT to work correctly in this configuration, one of two approaches can be taken: </p>
<dl>
<dd>1. Define a CONTINUE policy with <code>smc</code> as the SOURCE zone (preferred): </p>
<dl>
<dd>
<pre>#SOURCE DEST POLICY LOG LEVEL LIMIT:BURST
<code>smc $FW CONTINUE</code>
loc net ACCEPT
net all DROP info
# THE FOLLOWING POLICY MUST BE LAST
all all REJECT info</pre>
</dl>
</dl>
<dl>
<dd>2. Set IMPLICIT_CONTINUE=Yes in m[blue]<code><a href="/docs/linux/man/5-shorewall-conf/">shorewall.conf</a>(5)</code>m[]<font SIZE="-2">[5]</font>.</dl>
