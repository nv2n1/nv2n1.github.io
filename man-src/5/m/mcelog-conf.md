<p>mcelog.conf &#8211; mcelog.conf reference</p>
<h2>Synopsis</h2>
<p><code>/etc/mcelog.conf</code></p>
<h2>Description</h2>
<p>/etc/mcelog.conf is the main configuration file for <code><a href="/docs/linux/man/8-mcelog/">mcelog</a>(8).</code> This is configuration file separated into sections including a default section. General format <code>optionname = value</code> White space is not allowed in value currently, except at the end where it is dropped In general all command line options that are not commands work here. See man mcelog or mcelog &#8211;help for a list. e.g. to enable the &#8211;no-syslog option use <code>no-syslog = yes (or no to disable)</code> When the option has a argument <code>logfile = /tmp/logfile</code> Below are the options which are not command line options. Set cpu type for which mcelog decodes events: <code>cpu = type</code> For valid values for type please see mcelog &#8211;help. If this value is set incorrectly the decoded output will be likely incorrect. By default when this parameter is not set mcelog uses the CPU it is running on on very new kernels the mcelog events reported by the kernel also carry the CPU type which is used too when available and not overridden. Enable daemon mode: <code>daemon = yes</code> By default mcelog just processes the currently pending events and exits. In daemon mode it will keep running as a daemon in the background and poll the kernel for events and then decode them. Filter out known broken events by default. <code>filter = yes</code> Don&#8217;t log memory errors individually. They still get accounted if that is enabled. <code>filter-memory-errors = yes</code> Output in undecoded raw format to be easier machine readable (default is decoded). <code>raw = yes</code> Set cpu mhz to decode uptime from time stamp counter (output unreliable, not needed on new kernels which report the event time directly. A lot of systems don&#8217;t have a linear time stamp clock and the output is wrong then. Normally mcelog tries to figure out if it the TSC is reliable and only uses the current frequency then. Setting a frequency forces timestamp decoding. This setting is obsolete with modern kernels which report the time directly. <code>cpumhz = 1800.00</code> Log output options Log decoded machine checks in syslog (default stdout or syslog for daemon)<tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt><br />
 <code>syslog = yes</code> Log decoded machine checks in syslog with error level <code>syslog-error = yes</code> Never log anything to syslog <code>no-syslog = yes </code> Append log output to logfile instead of stdout. only when no syslog logging is active <code>logfile = filename</code> Use smbios information to decode dimms (needs root). This function is not recommended to use right now and generally not needed. The exception is memdb prepopulation, which is configured separately below. <code>dmi = no</code> When in daemon mode run as this user after set up. Note that the triggers will run as this user too. Setting this to non root will mean that triggers cannot take some corrective action, like offlining objects. <code>run-credentials-user = root</code> Group to run as daemon with default to the group of the run-credentials-user <code>run-credentials-group = nobody</code></p>
<h3>The server config section</h3>
<p>User allowed to access client socket. when set to * match any root is always allowed to access. default: root only <code>client-user = root</code> Group allowed to access mcelog When no group is configured any group matches (but still user checking). when set to * match any <code>client-group = root</code> Path to the unix socket for client&lt;-&gt;server communication. When no socket-path is configured the server will not start <code>socket-path = /var/run/mcelog-client</code> When mcelog starts it checks if a server is already running. this configures the timeout for this check. <code>initial-ping-timeout = 2 </code></p>
<h3>The dimm config section</h3>
<p>Is the in memory dimm error tracking enabled? Only works on systems with integrated memory controller and which are supported. Only takes effect in daemon mode. <code>dimm-tracking-enabled = yes</code> Use dmi information from the bios to prepopulate dimm database. Note this might not work with all BIOS and requires mcelog to run as root. Alternative is to let mcelog create DIMM objects on demand. <code>dmi-prepopulate = yes</code> Execute these triggers when the rate of corrected or uncorrected Errors per DIMM exceeds the threshold. Note when the hardware does not report DIMMs this might also be per channel. The default of 10/24h is reasonable for server quality DDR3 DIMMs as of 2009/10. <code>uc-error-trigger = dimm-error-trigger</code> <code>uc-error-threshold = 1 / 24h</code> <code>ce-error-trigger = dimm-error-trigger</code> <code>ce-error-threshold = 10 / 24h</code></p>
<h3>The socket config section</h3>
<p>Enable memory error accounting per socket. <code>socket-tracking-enabled = yes</code> Threshold and trigger for uncorrected memory errors on a socket. mem-uc-error-trigger = socket-memory-error-trigger <code>mem-uc-error-threshold = 100 / 24h</code> Trigger script for corrected memory errors on a socket. <code>mem-ce-error-trigger = socket-memory-error-trigger</code> Threshold on when to trigger a correct error for the socket. <code>mem-ce-error-threshold = 100 / 24h</code><br />
&nbsp;<wbr>log socket error threshold explicitly? <code>mem-ce-error-log = yes</code> Trigger script for uncorrected bus error events <code>bus-uc-threshold-trigger = bus-error-trigger</code> Trigger script for uncorrected iomca erors <code>iomca-threshold-trigger = iomca-error-trigger</code> Trigger script for other uncategorized errors <code>unknown-threshold-trigger = unknown-error-trigger</code></p>
<h3>The cache config section</h3>
<p>Processing of cache error thresholds reported by intel cpus. <code>cache-threshold-trigger = cache-error-trigger</code> Should cache threshold events be logged explicitly? <code>cache-threshold-log = yes</code></p>
<h3>The page config section</h3>
<p>Memory error accouting per 4k memory page. Threshold for the correct memory errors trigger script. <code>memory-ce-threshold = 10 / 24h</code> Trigger script for corrected errors. memory-ce-trigger = page-error-trigger Should page threshold events be logged explicitly? <code>memory-ce-log = yes</code> Specify the internal action in mcelog to exceeding a page error threshold this is done in addition to executing the trigger script if available off no action account only account errors soft try to soft-offline page without killing any processes<br />
&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>This requires an uptodate kernel. Might not be successfull. hard try to hard-offline page by killing processes<br />
&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>Requires an uptodate kernel. Might not be successfull. soft-then-hard First try to soft offline, then try hard offlining <code>memory-ce-action = off|account|soft|hard|soft-then-hard</code> <code>memory-ce-action = soft</code></p>
<h3>The trigger config section</h3>
<p>Maximum number of running triggers <code>children-max = 2</code> Execute triggers in this directory <code>directory = /etc/mcelog</code> </p>
