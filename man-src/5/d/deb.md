<p>deb &#8211; Debian binary package format</p>
<h2>Synopsis</h2>
<p><i>filename</i><code>.deb</code></p>
<h2>Description</h2>
<p>The <code>.deb</code> format is the Debian binary package file format. It is understood since dpkg 0.93.76, and is generated by default since dpkg 1.2.0 and 1.1.1elf (i386/ELF builds). </p>
<p> The format described here is used since Debian 0.93; details of the old format are described in <code><a href="/docs/linux/man/5-deb-old/">deb-old</a></code>(5).</p>
<h2>Format</h2>
<p>The file is an <code>ar</code> archive with a magic value of <code>!&lt;arch&gt;</code>. Only the common <code>ar</code> archive format is supported, with no long file name extensions, but with file names containing an optional trailing slash, which limits their length to 15 characters (from the 16 allowed). File sizes are limited to 10 <font SIZE="-1">ASCII</font> decimal digits, allowing for up to approximately 9536.74 MiB member files. </p>
<p> The <code>tar</code> archives currently allowed are, the old-style (v7) format, the pre-POSIX ustar format, a subset of the <font SIZE="-1">GNU</font> format (new style long pathnames and long linknames, supported since dpkg 1.4.1.17; large file metadata since dpkg 1.18.24), and the <font SIZE="-1">POSIX</font> ustar format (long names supported since dpkg 1.15.0). Unrecognized tar typeflags are considered an error. Each tar entry size inside a tar archive is limited to 11 <font SIZE="-1">ASCII</font> octal digits, allowing for up to 8 GiB tar entries. The <font SIZE="-1">GNU</font> large file metadata support permits 95-bit tar entry sizes and negative timestamps, and 63-bit <font SIZE="-1">UID, GID</font> and device numbers. </p>
<p> The first member is named <code>debian-binary</code> and contains a series of lines, separated by newlines. Currently only one line is present, the format version number, <code>2.0</code> at the time this manual page was written. Programs which read new-format archives should be prepared for the minor number to be increased and new lines to be present, and should ignore these if this is the case. </p>
<p> If the major number has changed, an incompatible change has been made and the program should stop. If it has not, then the program should be able to safely continue, unless it encounters an unexpected member in the archive (except at the end), as described below. </p>
<p> The second required member is named <code>control.tar</code>. It is a tar archive containing the package control information, either not compressed (supported since dpkg 1.17.6), or compressed with gzip (with <code>.gz</code> extension) or xz (with <code>.xz</code> extension, supported since 1.17.6), as a series of plain files, of which the file <code>control</code> is mandatory and contains the core control information, the <code>md5sums</code>, <code>conffiles</code>, <code>triggers</code>, <code>shlibs</code> and <code>symbols</code> files contain optional control information, and the <code>preinst</code>, <code>postinst</code>, <code>prerm</code> and <code>postrm</code> files are optional maintainer scripts. The control tarball may optionally contain an entry for &#8216;<code>.</code>&#8216;, the current directory. </p>
<p> The third, last required member is named <code>data.tar</code>. It contains the filesystem as a tar archive, either not compressed (supported since dpkg 1.10.24), or compressed with gzip (with <code>.gz</code> extension), xz (with <code>.xz</code> extension, supported since dpkg 1.15.6), bzip2 (with <code>.bz2</code> extension, supported since dpkg 1.10.24) or lzma (with <code>.lzma</code> extension, supported since dpkg 1.13.25). </p>
<p> These members must occur in this exact order. Current implementations should ignore any additional members after <code>data.tar</code>. Further members may be defined in the future, and (if possible) will be placed after these three. Any additional members that may need to be inserted after <code>debian-binary</code> and before <code>control.tar</code> or <code>data.tar</code> and which should be safely ignored by older programs, will have names starting with an underscore, &#8216;<code>_</code>&#8216;. </p>
<p> Those new members which won&#8217;t be able to be safely ignored will be inserted before <code>data.tar</code> with names starting with something other than underscores, or will (more likely) cause the major version number to be increased.</p>
