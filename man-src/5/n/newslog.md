<p>newslog &#8211; Description of INN log files</p>
<h2>Description</h2>
<p>Most log files created by Usenet programs reside in the <i>pathlog</i> directory set in <i>inn.conf</i> and have a <tt>&quot;.log&quot;</tt> extension. Several versions are usually kept with an additional extension such as <tt>.1</tt>, <tt>.2</tt>, etc. &#8212; the higher the number, the older the log. These old versions are stored in <i>pathlog</i>/OLD; they may be compressed and thus may have a <tt>&quot;.1.gz&quot;</tt>, <tt>&quot;.2.gz&quot;</tt>, etc. extension, up to <tt>&quot;.nn.gz&quot;</tt> where <tt>&quot;nn&quot;</tt> is the number of old logs kept by <code>scanlogs</code> which is set by <i>logcycles</i> in <i>inn.conf</i>. </p>
<p> The <code>scanlogs</code> script and related utilities are responsible for rotating and compressing these files. Some log files always have data (like <i>news.notice</i>), others only have data if there is a problem (like <i>news.err</i>), and others are only created if a particular program is used (like <i>send-uucp.log</i> used by <code>send-uucp</code>) or if a configuration parameter is set (like <i>innfeed.log</i> used by <code>innfeed</code> when <i>debug-level</i> is set in <i>innfeed.conf</i>). </p>
<p> Besides, the <code>innstat</code> script monitors the size of all log files. </p>
<p> Here are the log files used by <font SIZE="-1">INN:</font></p>
<dl>
<dt><i>control.log</i></p>
<dd>This file maintains a count of the number of newgroup and rmgroup control messages seen for each newsgroup. The count is of the number of control messages with the indicated arguments, regardless if they were actually processed. All control arguments, including invalid ones, are counted. An example of lines which can be found in that log file is: </p>
<pre> 3 Control: newgroup foo.bar moderated
 3 Control: rmgroup misc.removed
 1 Control: newgroup misc.created</pre>
<p>This file is updated by <code>tally.control</code>, which is invoked by <code>scanlogs</code> if either one of these two log files exists in <i>pathlog</i>: </p>
<pre> newgroup.log
 rmgroup.log</pre>
<p>These two log files contain a summary line describing the control message and the action taken by <code>controlchan</code>, followed by the article indented by four spaces, and a blank line. Whereas these files are rotated, <i>control.log</i> is not rotated so as to keep the count of seen control messages. </p>
<p> Note that other control log files are also rotated by <code>scanlogs</code>, if they exist, but their contents are not summarized. Here are their names: </p>
<pre> checkgroups.log
 default.log
 ihave.log
 miscctl.log
 sendme.log
 sendsys.log
 senduuname.log
 version.log</pre>
<p>In order to create these files, the &lt;type&gt; and &lt;action&gt; fields of relevant <i>control.ctl</i> entries should be correctly set. For instance: </p>
<pre> Type Action Meaning
 ---- ------ -------
 all log=miscctl Log all messages by default.
 newgroup doit=newgroup Create group and log message.
 newgroup log=newgroup Log message.
 rmgroup verify-*=rmgroup PGP verify, remove group and log message.
 checkgroups doit=checkgroups Process and log message.</pre>
<dt><i>controlbatch.log</i></p>
<dd>The <code>controlbatch</code> program appends all status messages to this file. It is rotated by <code>scanlogs</code>.</p>
<dt><i>errlog</i></p>
<dd>This file contains the standard output and standard error of any program spawned by <code>innd</code>, such as channel feeds configured in <i>newsfeeds</i>. This file should normally be empty. <code>scanlogs</code> will print the entire contents of this log file if it is non-empty so that it appears in daily Usenet reports generated by <code>news.daily</code>. Then, <code>scanlogs</code> rotates this log file.</p>
<dt><i>expire.log</i></p>
<dd>By default, when <code>news.daily</code> is going to expire old news articles, it writes the name of the program it invokes, followed by <tt>&quot;start&quot;</tt> and the time it has started. Any output from that program is then written, indented by four spaces. Then, the name of the program is written, followed by <tt>&quot;end&quot;</tt> and the time it has ended. </p>
<p> Programs called, if needed, are in order: <code>expireover</code>, <code>ctlinnd</code> (with the <tt>&quot;lowmark&quot;</tt> option), <code>expirerm</code> and <code>expire</code>. Removed articles are listed in <i>expire.list</i> and low marks for each newsgroup (that is to say the number of the oldest article available in the newsgroup) in <i>expire.lastlowmark</i>. </p>
<p> After the expiry process, <code>scanlogs</code> rotates <i>expire.log</i>.</p>
<dt><i>innfeed.log</i></p>
<dd>When <i>debug-level</i> is set in <i>innfeed.conf</i>, <code>innfeed</code> appends debugging messages to this file. Note that the name of this file can be changed with the <i>log-file</i> parameter in <i>innfeed.conf</i>. Be that as it may, the right log file is rotated by <code>scanlogs</code>. </p>
<p> <code>innfeed</code> also logs its status in <i>innfeed.status</i> (or the name set in <i>status-file</i>) if <i>gen-html</i> is set to false but this log file is not processed by <code>scanlogs</code>.</p>
<dt><i>news</i></p>
<dd>This file logs articles received by <code>innd</code>. Typical lines are: </p>
<pre> Aug 25 13:37:41.839 + news.server.fr &lt;cancel.4066 [at] foo.com&gt; 1658 a.peer other.server.org inpaths!
 Aug 25 13:37:41.839 c news.server.fr &lt;cancel.4066 [at] foo.com&gt; Cancelling &lt;m070725 [at] foo.com&gt;
 Aug 25 13:37:54.638 - a.peer &lt;23k82 [at] bar.net&gt; 437 Poison newsgroup</pre>
<p>The first one indicates that an article from <tt>&quot;news.server.fr&quot;</tt> has been accepted (<tt>&quot;+&quot;</tt>). Its Message-ID is <tt>&quot;&lt;cancel.4066 [at] foo.com&gt;&quot;</tt> and we will send the article to two peers (<tt>&quot;a.peer&quot;</tt> and <tt>&quot;other.server.org&quot;</tt>, as specified in <i>newsfeeds</i>) and <tt>&quot;inpaths!&quot;</tt> (see <code>ninpaths</code> for more details about it). The second line mentions that this previous article is a cancel message (<tt>&quot;c&quot;</tt>) for <tt>&quot;&lt;m070725 [at] foo.com&gt;&quot;</tt> and that it has been processed (inndeed, <code>controlchan</code> processes all control articles except for cancels which are handled by <code>innd</code>). The third line indicates that the article whose Message-ID is <tt>&quot;&lt;23k82 [at] bar.net&gt;&quot;</tt> has been rejected (<tt>&quot;-&quot;</tt>) because it is posted to a poison newsgroup (a Perl or a Python filter located in <i>pathfilter</i> must have brought that reject along). </p>
<p> See the &#8220;<font SIZE="-1">LOGGING</font>&#8221; section of the <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) man page for more information about the format of this log file. </p>
<p> <code>innreport</code> summarizes the rejected articles reported in this file and <code>scanlogs</code> rotates it.</p>
<dt><i>news.crit</i></p>
<dd>All critical error messages issued by <code>innd</code> are appended to this file via syslog. This log file should normally be empty. <code>scanlogs</code> will print the entire contents of this log file if it is non-empty so that it appears in daily Usenet reports generated by <code>news.daily</code>. Then, <code>scanlogs</code> rotates this log file. </p>
<p> You should have the following line in your system <i>syslog.conf</i> file, using a tab character for the delimiter: </p>
<pre> news.crit &lt;pathlog&gt;/news.crit</pre>
<p>(A typical entry is shown; it should agree with <i>pathlog</i> in <i>inn.conf</i> and be tab-delimited.)</p>
<dt><i>news.err</i></p>
<dd>All major error messages issued by <code>innd</code> are appended to this file via syslog. This log file should normally be empty. <code>innreport</code> will print the first <i>max_unknown</i> lines of this log file if it is non-empty so that they appear in daily Usenet reports generated by <code>news.daily</code>. This parameter can be set in <i>innreport.conf</i>. Then, <code>scanlogs</code> rotates this log file. </p>
<p> You should have the following line in your system <i>syslog.conf</i> file, using a tab character for the delimiter: </p>
<pre> news.err &lt;pathlog&gt;/news.err</pre>
<p>(A typical entry is shown; it should agree with <i>pathlog</i> in <i>inn.conf</i> and be tab-delimited.)</p>
<dt><i>news.notice</i></p>
<dd>All standard error messages and status messages issued by <code>innd</code>, <code>innfeed</code>, <code>nnrpd</code> and some other programs are appended to this file via syslog. <code>scanlogs</code> uses the Perl script <code>innreport</code> to summarize this file. Then, <code>scanlogs</code> rotates this log file. </p>
<p> You should have the following line in your system <i>syslog.conf</i> file, using a tab character for the delimiter: </p>
<pre> news.notice &lt;pathlog&gt;/news.notice</pre>
<p>(A typical entry is shown; it should agree with <i>pathlog</i> in <i>inn.conf</i> and be tab-delimited.)</p>
<dt><i>nntpsend.log</i></p>
<dd>The <code>nntpsend</code> program appends all status messages to this file. It is rotated by <code>scanlogs</code>.</p>
<dt><i>perl-nocem.log</i></p>
<dd>The <code>perl-nocem</code> program appends all status messages to this file if <tt>&quot;Sys::Syslog&quot;</tt> is not used (otherwise, such messages are appended to <i>news.notice</i>). It is rotated by <code>scanlogs</code>.</p>
<dt><i>send-ihave.log</i></p>
<dd>The <code>send-ihave</code> program appends all status messages to this file. It is rotated by <code>scanlogs</code>.</p>
<dt><i>send-nntp.log</i></p>
<dd>The <code>send-nntp</code> program appends all status messages to this file. It is rotated by <code>scanlogs</code>.</p>
<dt><i>send-uucp.log</i></p>
<dd>The <code>send-uucp</code> program appends all status messages to this file. It is rotated by <code>scanlogs</code>.</p>
<dt><i>unwanted.log</i></p>
<dd>This log maintains a count of the number of articles that were rejected because they were posted to newsgroups that do not exist at the local site. This file is updated by <code>innreport</code> while processing the <i>news.notice</i> log file and it is maintained in reverse numeric order (the most popular rejected group first). This file is not rotated so as to keep the count of the articles posted to newsgroups which are absent from the <i>active</i> file of the news server. </p>
<p> Note that <i>logtrash</i> has to be set to true in <i>inn.conf</i> for this file to be generated.</dl>
<p> Finally, these files are also rotated by <code>scanlogs</code>, if they exist, but their contents are not summarized. Here are their names: </p>
<pre> badcontrol.log
 badpgp.log
 failedpgp.log</pre>
<p>They can be used by programs which <font SIZE="-1">PGP</font> verify articles.</p>
