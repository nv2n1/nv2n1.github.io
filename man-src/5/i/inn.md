<p>inn.conf &#8211; Configuration data for InterNetNews programs</p>
<h2>Description</h2>
<p><i>inn.conf</i> in <i>pathetc</i> is the primary general configuration file for all InterNetNews programs. Settings which control the general operation of various programs, as well as the paths to all portions of the news installation, are found here. The <font SIZE="-1">INNCONF</font> environment variable, if set, specifies an alternate path to <i>inn.conf</i>. </p>
<p> This file is intended to be fairly static. Any changes made to it will generally not affect any running programs until they restart. Unlike nearly every other configuration file, <i>inn.conf</i> cannot be reloaded dynamically using <i><a href="/docs/linux/man/8-ctlinnd/">ctlinnd</a></i>(8); <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) must be stopped and restarted for relevant changes to <i>inn.conf</i> to take effect (<tt>&quot;ctlinnd xexec innd&quot;</tt> is the fastest way to do this.) </p>
<p> Blank lines and lines starting with a number sign (<tt>&quot;#&quot;</tt>) are ignored. All other lines specify parameters, and should be of the following form: </p>
<pre> &lt;name&gt;: &lt;value&gt;</pre>
<p>(Any amount of whitespace can be put after the colon and is optional.) If the value contains embedded whitespace or any of the characters <tt>&quot;[]&lt;&quot;</tt>&#8220;\:&gt;, it must be enclosed in double quotes (&#8221;&quot;). A backslash (<tt>&quot;\&quot;</tt>) can be used to escape quotes and backslashes inside double quotes. &lt;name&gt; is case-sensitive; <tt>&quot;server&quot;</tt> is not the same as <tt>&quot;Server&quot;</tt> or <tt>&quot;SERVER&quot;</tt>. (<i>inn.conf</i> parameters are generally all in lowercase.) </p>
<p> If &lt;name&gt; occurs more than once in the file, the first value is used. Some parameters specified in the file may be overridden by environment variables. Most parameters have default values if not specified in <i>inn.conf</i>; those defaults are noted in the description of each parameter. </p>
<p> Many parameters take a boolean value. For all such parameters, the value may be specified as <tt>&quot;true&quot;</tt>, <tt>&quot;yes&quot;</tt>, or <tt>&quot;on&quot;</tt> to turn it on and may be any of <tt>&quot;false&quot;</tt>, <tt>&quot;no&quot;</tt>, or <tt>&quot;off&quot;</tt> to turn it off. The case of these values is significant. </p>
<p> This documentation is extremely long and organized as a reference manual rather than as a tutorial. If this is your first exposure to <font SIZE="-1">INN</font> and these parameters, it would be better to start by reading other man pages and referring to this one only when an <i>inn.conf</i> parameter is explicitly mentioned. Those parameters which need to be changed when setting up a new server are discussed in <i></i><font SIZE="-1"><i>INSTALL</i></font><i></i>.</p>
<h2>Parameters</h2>
<h2>General Settings</h2>
<p>These parameters are used by a wide variety of different components of <font SIZE="-1">INN</font>.</p>
<dl>
<dt><i>domain</i></p>
<dd>This should be the domain name of the local host. It should not have a leading period, and it should not be a full host address. It is used only if the <i>GetFQDN()</i> routine in <i><a href="/docs/linux/man/3-libinn/">libinn</a></i>(3) cannot get the fully-qualified domain name by using either the <i><a href="/docs/linux/man/3-gethostname/">gethostname</a></i>(3) or <i><a href="/docs/linux/man/3-gethostbyname/">gethostbyname</a></i>(3) calls. The check is very simple; if either routine returns a name with a period in it, then it is assumed to have the full domain name. As this parameter is rarely used, do not use it to affect the righthand side of autogenerated Message-IDs; see instead <i>virtualhost</i> and <i>domain</i> in <i><a href="/docs/linux/man/5-readers-conf/">readers.conf</a></i>(5). The default value is unset.</p>
<dt><i>innflags</i></p>
<dd>The flags to pass to innd on startup. See <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) for details on the possible flags. The default value is unset.</p>
<dt><i>mailcmd</i></p>
<dd>The path to the program to be used for mailing reports and control messages. The default is <i>pathbin</i>/innmail. This should not normally need to be changed.</p>
<dt><i>mta</i></p>
<dd>The command to use when mailing postings to moderators and for the use of <i><a href="/docs/linux/man/1-innmail/">innmail</a></i>(1). The message, with headers and an added To: header, will be piped into this program. The string <tt>%s</tt>, if present, will be replaced by the e-mail address of the moderator. It&#8217;s strongly recommended for this command to include <tt>%s</tt> on the command line rather than use the addresses in the To: and Cc: headers of the message, since the latter approach allows the news server to be abused as a mechanism to send mail to arbitrary addresses and will result in unexpected behavior. There is no default value for this parameter; it must be set in <i>inn.conf</i> or a fatal error message will be logged via syslog. </p>
<p> For most systems, <tt>&quot;/usr/lib/sendmail -oi -oem %s&quot;</tt> (adjusted for the correct path to <code>sendmail</code>, and between double quotes) is a good choice.</p>
<dt><i>pathhost</i></p>
<dd>What to put into the Path: header to represent the local site. This is added to the Path: header of all articles that pass through the system, including locally posted articles, and is also used when processing some control messages and when naming the server in status reports. There is no default value; this parameter must be set in <i>inn.conf</i> or <font SIZE="-1">INN</font> will not start. A good value to use is the fully-qualified hostname of the system.</p>
<dt><i>runasgroup</i></p>
<dd>The group under which the news server will run. The default is <tt>&quot;news&quot;</tt> and should not normally need to be changed.</p>
<dt><i>runasuser</i></p>
<dd>The user under which the news server will run. The default is <tt>&quot;news&quot;</tt> and should not normally need to be changed.</p>
<dt><i>server</i></p>
<dd>The name of the default <font SIZE="-1">NNTP</font> server. If <i>nnrpdposthost</i> is not set and <font SIZE="-1">UNIX</font> domain sockets are not supported, <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) tries to hand off locally-posted articles through an <font SIZE="-1">INET</font> domain socket to this server. <i><a href="/docs/linux/man/8-actsync/">actsync</a></i>(8), <i><a href="/docs/linux/man/8-nntpget/">nntpget</a></i>(8), and <i><a href="/docs/linux/man/8-getlist/">getlist</a></i>(8) also use this value as the default server to connect to. In the latter cases, the value of the <font SIZE="-1">NNTPSERVER</font> environment variable, if it exists, overrides this. The default value is unset.</dl>
<h2>Feed Configuration</h2>
<p>These parameters govern incoming and outgoing feeds: what size of articles are accepted, what filtering and verification is performed on them, whether articles in groups not carried by the server are still stored and propagated, and other similar settings.</p>
<dl>
<dt><i>artcutoff</i></p>
<dd>Articles older than this number of days are dropped. This setting should probably match the setting on the <tt>&quot;/remember/&quot;</tt> line in <i>expire.ctl</i>. The default value is <tt>10</tt>.</p>
<dt><i>bindaddress</i></p>
<dd>Which <font SIZE="-1">IP</font> address <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) should bind itself to. This must be in dotted-quad format (nnn.nnn.nnn.nnn). If set to <tt>&quot;all&quot;</tt> or not set, innd defaults to listening on all interfaces. The value of the <font SIZE="-1">INND_BIND_ADDRESS</font> environment variable, if set, overrides this setting. The default value is unset.</p>
<dt><i>bindaddress6</i></p>
<dd>Like <i>bindaddress</i> but for IPv6 sockets. If only one of the <i>bindaddress</i> and <i>bindaddress6</i> parameters is used, then only the socket for the corresponding address family is created. If both parameters are used then two sockets are created. If neither of them is used, the list of sockets to listen on will be determined by the system library <i><a href="/docs/linux/man/3-getaddrinfo/">getaddrinfo</a>(3)</i> function. The value of the <font SIZE="-1">INND_BIND_ADDRESS6</font>, if set, overrides this setting. The default value is unset. </p>
<p> Note that you will generally need to put double quotes (&quot;&quot;) around this value if you set it, since IPv6 addresses contain colons.</p>
<dt><i>dontrejectfiltered</i></p>
<dd>Normally <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) rejects incoming articles when directed to do so by any enabled article filters (Perl or Python). However, this parameter causes such articles <i>not</i> to be rejected; instead filtering can be applied on outbound articles. If this parameter is set, all articles will be accepted on the local machine, but articles rejected by the filter will <i>not</i> be fed to any peers specified in <i>newsfeeds</i> with the <tt>&quot;Af&quot;</tt> flag.</p>
<dt><i>hiscachesize</i></p>
<dd>If set to a value other than <tt>0</tt>, a hash of recently received Message-IDs is kept in memory to speed history lookups. The value is the amount of memory to devote to the cache in kilobytes. The cache is only used for incoming feeds and a small cache can hold quite a few Message-IDs, so large values aren&#8217;t necessarily useful unless you have incoming feeds that are badly delayed. <code>innreport</code> can provide useful statistics regarding the use of the history cache, especially when it misses. A good value for a system with more than one incoming feed is <tt>256</tt>; systems with only one incoming feed should probably set this to <tt>0</tt>. The default value is <tt>256</tt>.</p>
<dt><i>ignorenewsgroups</i></p>
<dd>Whether newsgroup creation control messages (newgroup and rmgroup) should be fed as if they were posted to the newsgroup they are creating or deleting rather than to the newsgroups listed in the Newsgroups: header. If this parameter is set, the newsgroup affected by the control message will be extracted from the Control: header and the article will be fed as if its Newsgroups: header contained solely that newsgroup. This is useful for routing control messages to peers when they are posted to irrelevant newsgroups that shouldn&#8217;t be matched against the peer&#8217;s desired newsgroups in <i>newsfeeds</i>. This is a boolean value and the default is false.</p>
<dt><i>immediatecancel</i></p>
<dd>When using the timecaf storage method, article cancels are normally just cached to be cancelled, not cancelled immediately. If this is set to true, they will instead by cancelled as soon as the cancel is processed. This is a boolean value and the default is false. </p>
<p> This setting is ignored unless the timecaf storage method is used.</p>
<dt><i>linecountfuzz</i></p>
<dd>If set to something other than <tt>0</tt>, the line count of the article is checked against the Lines: header of the article (if present) and the article is rejected if the values differ by more than this amount. A reasonable setting is <tt>5</tt>, which is the standard maximum signature length plus one (some injection software calculates the Lines: header before adding the signature). The default value is <tt>0</tt>, which tells <font SIZE="-1">INN</font> not to check the Lines: header of incoming articles.</p>
<dt><i>maxartsize</i></p>
<dd>The maximum size of article (headers and body) that will be accepted by the server, in bytes. A value of <tt>0</tt> allows any size of article, but note that <code>innd</code> will crash if system memory is exceeded. The default value is <tt>1000000</tt> (approximately 1&nbsp;<wbr><font SIZE="-1">MB</font>). This is checked against the article in wire format (<font SIZE="-1">CRLF</font> at the end of each line, leading periods protected, and with the trailing &#8220;
.
&#8221; at the end). See also <i>localmaxartsize</i>.</p>
<dt><i>maxconnections</i></p>
<dd>The maximum number of incoming <font SIZE="-1">NNTP</font> connections <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will accept. The default value is <tt>50</tt>.</p>
<dt><i>pathalias</i></p>
<dd>If set, this value is prepended to the Path: header of accepted posts (before <i>pathhost</i>) if it doesn&#8217;t already appear in the Path: header. The main purpose of this parameter is to configure all news servers within a particular organization to add a common identity string to the Path: header. The default value is unset.</p>
<dt><i>pathcluster</i></p>
<dd>If set, this value is appended to the Path: header of accepted posts (after <i>pathhost</i>) if it isn&#8217;t already present as the last element of the Path: header. The main purpose of this parameter is to make several news servers appear as one server. The default value is unset. </p>
<p> Note that the Path: header reads right to left, so appended means inserted at the leftmost side of the Path: header.</p>
<dt><i>pgpverify</i></p>
<dd>Whether to enable <font SIZE="-1">PGP</font> verification of control messages other than cancel. This is a boolean value and the default is based on whether configure found pgp, pgpv, or gpgv.</p>
<dt><i>port</i></p>
<dd>What <font SIZE="-1">TCP</font> port <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) should listen on. The default value is <tt>119</tt>, the standard <font SIZE="-1">NNTP</font> port.</p>
<dt><i>refusecybercancels</i></p>
<dd>Whether to refuse all articles whose message IDs start with <tt>&quot;&lt;cancel.&quot;</tt>. This message <font SIZE="-1">ID</font> convention is widely followed by spam cancellers, so the vast majority of such articles will be cancels of spam. This check, if enabled, is done before the history check and the message <font SIZE="-1">ID</font> is not written to the history file. This is a boolean value and the default is false. </p>
<p> This is a somewhat messy, inefficient, and inexact way of refusing spam cancels. A much better way is to ask all of your upstream peers to not send to you any articles with <tt>&quot;cyberspam&quot;</tt> in the Path: header (usually accomplished by having them mark <tt>&quot;cyberspam&quot;</tt> as an alias for your machine in their feed configuration). The filtering enabled by this parameter is hard-coded; general filtering of message IDs can be done via the embedded filtering support.</p>
<dt><i>remembertrash</i></p>
<dd>By default, <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) records rejected articles in history so that, if offered the same article again, it can be refused before it is sent. If you wish to disable this behavior, set this to false. This can cause a substantial increase in the amount of bandwidth consumed by incoming news if you have several peers and reject a lot of articles, so be careful with it. Even if this is set to true, <font SIZE="-1">INN</font> won&#8217;t log some rejected articles to history if there&#8217;s reason to believe the article might be accepted if offered by a different peer, so there is usually no reason to set this to false (although doing so can decrease the size of the history file). This is a boolean value and the default is true.</p>
<dt><i>sourceaddress</i></p>
<dd>Which local <font SIZE="-1">IP</font> address to bind to for outgoing <font SIZE="-1">NNTP</font> sockets (used by <i><a href="/docs/linux/man/8-innxmit/">innxmit</a></i>(8) among other programs, as well as <i><a href="/docs/linux/man/8-innfeed/">innfeed</a></i>(8) as long as not overridden by <i>bindaddress</i> in <i><a href="/docs/linux/man/5-innfeed-conf/">innfeed.conf</a></i>(5)). This must be in dotted-quad format (nnn.nnn.nnn.nnn). If set to <tt>&quot;all&quot;</tt>, the operating system will choose the source <font SIZE="-1">IP</font> address for outgoing connections. The default value is unset.</p>
<dt><i>sourceaddress6</i></p>
<dd>Like <i>sourceaddress</i> but for IPv6 sockets. Note that you will generally need to put double quotes (&quot;&quot;) around this value if you set it, since IPv6 addresses contain colons.</p>
<dt><i>verifycancels</i></p>
<dd>Set this to true to enable a simplistic check on all cancel messages, attempting to verify (by simple header comparison) that the cancel message is from the same person as the original post. This can&#8217;t be done if the cancel arrives before the article does, and is extremely easy to spoof. While this check may once have served a purpose, it&#8217;s now essentially security via obscurity, commonly avoided by abusers, and probably not useful. This is a boolean value, and the default is false.</p>
<dt><i>verifygroups</i></p>
<dd>Set this to true to reject incoming articles which contain an unknown newsgroup in the whole list of newsgroups to which they are posted. In case <i>wanttrash</i> is set to true, such articles will still be rejected. This is a boolean value, and the default is false.</p>
<dt><i>wanttrash</i></p>
<dd>Set this to true if you want to file articles posted to unknown newsgroups (newsgroups not in the <i>active</i> file) into the <tt>&quot;junk&quot;</tt> newsgroup rather than rejecting them. This is sometimes useful for a transit news server that needs to propagate articles in all newsgroups regardless if they&#8217;re carried locally. This is a boolean value and the default is false.</p>
<dt><i>wipcheck</i></p>
<dd>If <font SIZE="-1">INN</font> is offered an article by a peer on one channel, it will return deferral responses (code 436) to all other offers of that article for this many seconds. (After this long, if the peer that offered the article still hasn&#8217;t sent it, it will be accepted from other channels.) The default value is <tt>5</tt> and probably doesn&#8217;t need to be changed.</p>
<dt><i>wipexpire</i></p>
<dd>How long, in seconds, to keep track of message IDs offered on a channel before expiring articles that still haven&#8217;t been sent. The default value is <tt>10</tt> and probably doesn&#8217;t need to be changed.</dl>
<h2>History Settings</h2>
<p>The following parameter affect the history database.</p>
<dl>
<dt><i>hismethod</i></p>
<dd>Which history storage method to use. The only currently supported value is <tt>&quot;hisv6&quot;</tt>. There is no default value; this parameter must be set.</p>
<dl>
<dd>
<dl>
<dt>hisv6</p>
<dd>Stores history data in the <font SIZE="-1">INN</font> history v6 format: <i><a href="/docs/linux/man/5-history/">history</a></i>(5) text file and a number of <i><a href="/docs/linux/man/3-dbz/">dbz</a></i>(3) database files; this may be in true history v6 format, or tagged hash format, depending on the build options. Separation of these two is a project which has not yet been undertaken.</dl>

<h2>Article Storage</h2>
<p>These parameters affect how articles are stored on disk.</p>
<dl>
<dt><i>cnfscheckfudgesize</i></p>
<dd>If set to a value other than <tt>0</tt>, the claimed size of articles in <font SIZE="-1">CNFS</font> cycbuffs is checked against <i>maxartsize</i> plus this value, and if larger, the <font SIZE="-1">CNFS</font> cycbuff is considered corrupt. This can be useful as a sanity check after a system crash, but be careful using this parameter if you have changed <i>maxartsize</i> recently. The default value is <tt>0</tt>.</p>
<dt><i>enableoverview</i></p>
<dd>Whether to write out overview data for articles. If set to false, <font SIZE="-1">INN</font> will run much faster, but reading news from the system will be impossible (the server will be for news transit only). If this option is set to true, <i>ovmethod</i> must also be set. This is a boolean value and the default is true.</p>
<dt><i>extraoverviewadvertised</i></p>
<dd>Besides the seven standard overview fields (which are in order <tt>&quot;Subject:&quot;</tt>, <tt>&quot;From:&quot;</tt>, <tt>&quot;Date:&quot;</tt>, <tt>&quot;Message-ID:&quot;</tt>, <tt>&quot;References:&quot;</tt>, <tt>&quot;:bytes&quot;</tt> and <tt>&quot;:lines&quot;</tt>) and the eighth <tt>&quot;Xref:full&quot;</tt> field required by <font SIZE="-1">INN</font> in order to handle crossposts, it is possible to add other fields in the overview database. This parameter expects a list of such header names. Overview data for these additional headers will be generated for each new article at the time of arrival. For instance, if you specify: </p>
<pre> extraoverviewadvertised: [ Path NNTP-Hosting-Host ]</pre>
<p>it implies that <code>nnrpd</code> will advertise <tt>&quot;Path:full&quot;</tt> and <tt>&quot;NNTP-Hosting-Host:full&quot;</tt> as the ninth and tenth fields in response to <font SIZE="-1">LIST</font> <font SIZE="-1">OVERVIEW</font>.FMT and that these two headers will be stored in the overview database for each new article. </p>
<p> The default value is an empty list (no additional fields are stored). Owing to optimizations when <code>innd</code> parses the articles it receives, it is possible that all the values in the list are not recognized by <code>innd</code> as standard headers. In such cases, <code>innd</code> will log an error in <i>news.err</i> at startup and the unrecognized fields will be discarded. </p>
<p> You should advertise only fields for which the overview database is consistent, that is to say it records the content or absence of these fields for <i>all</i> articles, including those already existing in the news spool. Consequently, if you decide to add or remove a field from your overview database, you should either modify <i>extraoverviewadvertised</i> and rebuild your overview database with <i><a href="/docs/linux/man/8-makehistory/">makehistory</a></i>(8) after removing all existing overview files, or implement a transition period by first using <i>extraoverviewhidden</i> as described below. </p>
<p> Use of a transition period can accommodate most overview reconfigurations, but certain drastic changes may still require a complete overview rebuild. </p>
<p> If for instance you want to store the content of the To: header in addition to the fields already stored above, you should use: </p>
<pre> extraoverviewadvertised: [ Path NNTP-Hosting-Host ]
 extraoverviewhidden: [ To ]</pre>
<p>This way, <tt>&quot;To:full&quot;</tt> will not be advertised by <code>nnrpd</code> but will be stored for each new article. Once you know that all articles in your overview database record the content or absence of that new field (if <i><a href="/docs/linux/man/5-expire-ctl/">expire.ctl</a></i>(5) is parametered so that all your articles expire within 30 days, you can assume the database is in such a state after 30 days &#8212; however, note that time to expiration can be unpredictable with <font SIZE="-1">CNFS</font> and you then have to use <tt>&quot;cnfsstat -a&quot;</tt> for checking on when buffers have rolled over), you should put: </p>
<pre> extraoverviewadvertised: [ Path NNTP-Hosting-Host To ]
 extraoverviewhidden: [ ]</pre>
<p>The <tt>&quot;To&quot;</tt> value must be added at the end of the list because order matters and fields mentioned in <i>extraoverviewhidden</i> are generated after those mentioned in <i>extraoverviewadvertised</i>. <code>nnrpd</code> will now advertise <tt>&quot;To:full&quot;</tt> in response to the <font SIZE="-1">LIST</font> <font SIZE="-1">OVERVIEW</font>.FMT command (<tt>&quot;full&quot;</tt> indicates that the header appears followed by its value). </p>
<p> Now suppose you want to remove the content of the NNTP-Hosting-Host: header from the overview. As order matters, the overview database will no longer be consistent for the To: header. Therefore, you need to specify: </p>
<pre> extraoverviewadvertised: [ Path ]
 extraoverviewhidden: [ To ]</pre>
<p>And once overview data is accurate for all articles, you should use: </p>
<pre> extraoverviewadvertised: [ Path To ]
 extraoverviewhidden: [ ]</pre>
<p>Note that you have to restart <code>nnrpd</code> if it runs as a daemon whenever you change the value of <i>extraoverviewadvertised</i>; a mere <tt>&quot;ctlinnd xexec innd&quot;</tt> is not enough.</p>
<dt><i>extraoverviewhidden</i></p>
<dd>This parameter should be used in conjunction with <i>extraoverviewadvertised</i> (see above for more details). It expects a list of headers names. Overview data for these headers will be generated for each new article at the time of arrival but, contrary to the fields mentioned in <i>extraoverviewadvertised</i>, <code>nnrpd</code> will not advertise them in response to the <font SIZE="-1">LIST</font> <font SIZE="-1">OVERVIEW</font>.FMT command. It also implies that <code>nnrpd</code> will not look in the overview database for fields mentioned in <i>extraoverviewhidden</i> when it handles <font SIZE="-1">HDR</font>, <font SIZE="-1">XHDR</font> and <font SIZE="-1">XPAT</font> requests; <code>nnrpd</code> will have to parse the headers of the requested articles in the news spool, which is slower than directly querying the overview database. </p>
<p> The default value is an empty list (no additional fields are stored). Owing to optimizations when <code>innd</code> parses the articles it receives, it is possible that all the values in the list are not recognized by <code>innd</code> as standard headers. In such cases, <code>innd</code> will log an error in <i>news.err</i> at startup and the unrecognized fields will be discarded.</p>
<dt><i>groupbaseexpiry</i></p>
<dd>Whether to enable newsgroup-based expiry. If set to false, article expiry is done based on storage class of storing method. If set to true (and overview information is available), expiry is done by newsgroup name. This affects the format of <i>expire.ctl</i>. This is a boolean value and the default is true.</p>
<dt><i>mergetogroups</i></p>
<dd>Whether to file all postings to <tt>&quot;to.*&quot;</tt> groups in the pseudonewsgroup <tt>&quot;to&quot;</tt>. If this is set to true, the newsgroup <tt>&quot;to&quot;</tt> must exist in the <i>active</i> file or <font SIZE="-1">INN</font> will not start. (See the discussion of <tt>&quot;to.&quot;</tt> groups in <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) under <font SIZE="-1">CONTROL</font> <font SIZE="-1">MESSAGES</font>.) This is a boolean value and the default is false.</p>
<dt><i>nfswriter</i></p>
<dd>For servers writing articles, determine whether the article spool is on <font SIZE="-1">NFS</font> storage. If set, <font SIZE="-1">INN</font> attempts to flush articles to the spool in a more timely manner, rather than relying on the operating system to flush things such as the <font SIZE="-1">CNFS</font> article bitmaps. You should only set this parameter if you are attempting to use a shared <font SIZE="-1">NFS</font> spool on a machine acting as a single writer within a cluster. This is a boolean value and the default is false.</p>
<dt><i>overcachesize</i></p>
<dd>How many cache slots to reserve for open overview files. If <font SIZE="-1">INN</font> is writing overview files (see <i>enableoverview</i>), <i>ovmethod</i> is set to <tt>&quot;tradindexed&quot;</tt>, and this is set to a value other than <tt>0</tt>, <font SIZE="-1">INN</font> will keep around and open that many recently written-to overview files in case more articles come in for those newsgroups. Every overview cache slot consumes two file descriptors, so be careful not to set this value too high. You may be able to use the <tt>&quot;limit&quot;</tt> command to see how many open file descriptors your operating system allows. <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) also uses an open file descriptor for each incoming feed and outgoing channel or batch file, and if it runs out of open file descriptors, it may throttle and stop accepting new news. The default value is <tt>64</tt> (which is probably still too low if you have a large number of file descriptors available). </p>
<p> This setting is ignored unless <i>ovmethod</i> is set to <tt>&quot;tradindexed&quot;</tt>.</p>
<dt><i>ovgrouppat</i></p>
<dd>If set, restricts the overview data stored by <font SIZE="-1">INN</font> to only the newsgroups matching this comma-separated list of wildmat expressions. Newsgroups not matching this setting may not be readable, and if <i>groupbaseexpiry</i> is set to true and the storage method for these newsgroups does not have self-expire functionality, storing overview data will fail. The default is unset.</p>
<dt><i>ovmethod</i></p>
<dd>Which overview storage method to use. Currently supported values are <tt>&quot;tradindexed&quot;</tt>, <tt>&quot;buffindexed&quot;</tt>, and <tt>&quot;ovdb&quot;</tt>. There is no default value; this parameter must be set if <i>enableoverview</i> is true (the default).</p>
<dl>
<dd>
<dl>
<dt>buffindexed</p>
<dd>Stores overview data and index information into buffers, which are preconfigured files defined in <i>buffindexed.conf</i>. <tt>&quot;buffindexed&quot;</tt> never consumes additional disk space beyond that allocated to these buffers.</p>
<dt>tradindexed</p>
<dd>Uses two files per newsgroup, one containing the overview data and one containing the index. Fast for readers, but slow to write to.</p>
<dt>ovdb</p>
<dd>Stores data into a Berkeley&nbsp;<wbr><font SIZE="-1">DB</font> database. See the <i><a href="/docs/linux/man/5-ovdb/">ovdb</a></i>(5) man page.</dl>
</dl>
<dl>
<dd></dl>
<dt><i>storeonxref</i></p>
<dd>If set to true, articles will be stored based on the newsgroup names in the Xref: header rather than in the Newsgroups: header. This affects what the patterns in <i>storage.conf</i> apply to. The primary interesting effect of setting this to true is to enable filing of all control messages according to what storage class the control pseudogroups are filed in rather than according to the newsgroups the control messages are posted to. This is a boolean value and the default is true.</p>
<dt><i>useoverchan</i></p>
<dd>Whether to <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) should create overview data internally through <i><a href="/docs/linux/man/3-libstorage/">libstorage</a></i>(3). If set to false, innd creates overview data by itself. If set to true, innd does not create; instead overview data must be created by <i><a href="/docs/linux/man/8-overchan/">overchan</a></i>(8) from an appropriate entry in <i>newsfeeds</i>. Setting to true may be useful, if innd cannot keep up with incoming feed and the bottleneck is creation of overview data within innd. This is a boolean value and the default is false.</p>
<dt><i>wireformat</i></p>
<dd>Only used with the tradspool storage method, this says whether to write articles in wire format. Wire format means storing articles with <tt>&quot;
&quot;</tt> at the end of each line and with periods at the beginning of lines doubled, the article format required by the <font SIZE="-1">NNTP</font> protocol. Articles stored in this format are suitable for sending directly to a network connection without requiring conversion, and therefore setting this to true can make the server more efficient. The primary reason not to set this is if you have old existing software that looks around in the spool and doesn&#8217;t understand how to read wire format. Storage methods other than tradspool always store articles in wire format. This is a boolean value and the default is false.</p>
<dt><i>xrefslave</i></p>
<dd>Whether to act as the slave of another server. If set, <font SIZE="-1">INN</font> attempts to duplicate exactly the article numbering of the server feeding it by looking at the Xref: header of incoming articles and assigning the same article numbers to articles as was noted in the Xref: header from the upstream server. The result is that clients should be able to point at either server interchangeably (using some load balancing scheme, for example) and see the same internal article numbering. Servers with this parameter set should generally only have one upstream feed, and should always have <i>nnrpdposthost</i> set to hand locally posted articles off to the master server. The upstream should be careful to always feed articles in order (<i><a href="/docs/linux/man/8-innfeed/">innfeed</a></i>(8) can have problems with this in the event of a backlog). This is a boolean value and the default is false.</dl>
<h2>Reading</h2>
<p>These parameters affect the behavior of <font SIZE="-1">INN</font> for readers. Most of them are used by <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8). There are some special sets of settings that are broken out separately after the initial alphabetized list. </p>
<p> Note that the two parameters <i>nnrpperlauth</i> and <i>nnrppythonauth</i> are now obsolete; see &#8220;Changes to Perl Authentication Support for nnrpd&#8221; in <i>doc/hook-perl</i> and &#8220;Changes to Python Authentication and Access Control Support for nnrpd&#8221; in <i>doc/hook-python</i> for more information.</p>
<dl>
<dt><i>allownewnews</i></p>
<dd>Whether to allow use of the <font SIZE="-1">NEWNEWS</font> command by clients. This command used to put a heavy load on the server in older versions of <font SIZE="-1">INN</font>, but is now reasonably efficient, at least if only one newsgroup is specified by the client. This is a boolean value and the default is true. If you use the <i>access</i> parameter in <i>readers.conf</i>, be sure to read about the way it overrides <i>allownewnews</i>.</p>
<dt><i>articlemmap</i></p>
<dd>Whether to attempt to <i>mmap()</i> articles. Setting this to true will give better performance on most systems, but some systems have problems with <i>mmap()</i>. If this is set to false, articles will be read into memory before being sent to readers. This is a boolean value and the default is true.</p>
<dt><i>clienttimeout</i></p>
<dd>How long (in seconds) a client connection can be idle before it exits. When setting this parameter, be aware that some newsreaders use the same connection for reading and posting and don&#8217;t deal well with the connection timing out while a post is being composed. If the system isn&#8217;t having a problem with too many long-lived connections, it may be a good idea to increase this value to <tt>3600</tt> (an hour). The default value is <tt>1800</tt> (thirty minutes).</p>
<dt><i>initialtimeout</i></p>
<dd>How long (in seconds) <code>nnrpd</code> will wait for the first command from a reader connection before dropping the connection. This is a defensive timeout intended to protect the news server from badly behaved reader clients that open and abandon a multitude of connections without every closing them. The default value is <tt>10</tt> (ten seconds), which may need to be increased if many clients connect via slow network links.</p>
<dt><i>msgidcachesize</i></p>
<dd>How many cache slots to reserve for message-IDs to storage token translations. When serving overview data to clients (<font SIZE="-1">NEWNEWS</font>, <font SIZE="-1">OVER</font>, etc.), <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) can cache the storage token associated with a message-ID and save the cost of looking it up in the <i>history</i> file; for some configurations, setting this parameter can save more than 90% of the wall clock time for a session. The default value is <tt>16000</tt>.</p>
<dt><i>nfsreader</i></p>
<dd>For servers reading articles, determine whether the article spool is on <font SIZE="-1">NFS</font> storage. If set, <font SIZE="-1">INN</font> will attempt to force articles and overviews to be read directly from the <font SIZE="-1">NFS</font> spool rather than from cached copies. You should only set this parameter if you are attempting to use a shared <font SIZE="-1">NFS</font> spool on a machine acting as a reader within a cluster. This is a boolean value and the default is false.</p>
<dt><i>nfsreaderdelay</i></p>
<dd>If <i>nfsreader</i> is set, <font SIZE="-1">INN</font> will use the value of <i>nfsreaderdelay</i> to delay the apparent arrival time of articles to clients by this amount. Note that only answers to <font SIZE="-1">GROUP</font> and <font SIZE="-1">NEWNEWS</font> commands are affected. This value should be tuned based on the <font SIZE="-1">NFS</font> cache timeouts locally. The default is <tt>60</tt>, that is to say one minute.</p>
<dt><i>nnrpdcheckart</i></p>
<dd>Whether <code>nnrpd</code> should check the existence of an article before listing it as present in response to an <font SIZE="-1">NNTP</font> command. The primary use of this setting is to prevent nnrpd from returning information about articles which are no longer present on the server but which still have overview data available. Checking the existence of articles before returning overview information slows down the overview commands, but reduces the number of &#8220;article is missing&#8221; errors seen by the client. This is a boolean value and the default is true.</p>
<dt><i>nnrpdflags</i></p>
<dd>When <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) is spawned from <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8), these flags are passed as arguments to the nnrpd process. This setting does not affect instances of nnrpd that are started in daemon mode, or instances that are started via another listener process such as <i><a href="/docs/linux/man/8-inetd/">inetd</a></i>(8) or <i><a href="/docs/linux/man/8-xinetd/">xinetd</a></i>(8). Shell quoting and metacharacters are not supported. This is a string value and the default is unset.</p>
<dt><i>nnrpdloadlimit</i></p>
<dd>If set to a value other than <tt>0</tt>, connections to nnrpd will be refused if the system load average is higher than this value. The default value is <tt>16</tt>.</p>
<dt><i>noreader</i></p>
<dd>Normally, <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will fork a copy of <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) for all incoming connections from hosts not listed in <i>incoming.conf</i>. If this parameter is set to true, those connections will instead be rejected with a 502 error code. This should be set to true for a transit-only server that doesn&#8217;t support readers, or if nnrpd is running in daemon mode or being started out of inetd. This is a boolean value and the default is false.</p>
<dt><i>readerswhenstopped</i></p>
<dd>Whether to allow readers to connect even if the server is paused or throttled. This is only applicable if <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) is spawned from <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) rather than run out of inetd or in daemon mode. This is a boolean value and the default is false.</p>
<dt><i>readertrack</i></p>
<dd>Whether to enable the tracking system for client behavior. Tracked information is recorded to <i>pathlog</i>/tracklogs/log-ID, where <font SIZE="-1">ID</font> is determined by nnrpd&#8217;s <font SIZE="-1">PID</font> and launch time.) Currently the information recorded includes initial connection and posting; only information about clients listed in <i>nnrpd.track</i> is recorded. This is a boolean value and the default is false.</p>
<dt><i>tradindexedmmap</i></p>
<dd>Whether to attempt to <i>mmap()</i> tradindexed overviews articles. Setting this to true will give better performance on most systems, but some systems have problems with <i>mmap()</i>. If this is set to false, overviews will be read into memory before being sent to readers. This is a boolean value and the default is true.</dl>
<p> <font SIZE="-1">INN</font> has optional support for generating keyword information automatically from article body text and putting that information in overview for the use of clients that know to look for it. The following parameters control that feature. </p>
<p> This may be too slow if you&#8217;re taking a substantial feed, and probably will not be useful for the average news reader; enabling this is not recommended unless you have some specific intention to take advantage of it.</p>
<dl>
<dt><i>keywords</i></p>
<dd>Whether the keyword generation support should be enabled. This is a boolean value and the default is false. </p>
<p> <font SIZE="-1">FIXME:</font> Currently, support for keyword generation is configured into <font SIZE="-1">INN</font> semi-randomly (based on whether configure found the regex library); it should be an option to configure and that option should be mentioned here.</p>
<dt><i>keyartlimit</i></p>
<dd>Articles larger than this value in bytes will not have keywords generated for them (since it would take too long to do so). The default value is <tt>100000</tt> (approximately 100&nbsp;<wbr><font SIZE="-1">KB</font>).</p>
<dt><i>keylimit</i></p>
<dd>Maximum number of bytes allocated for keyword data. If there are more keywords than will fit into this many bytes when separated by commas, the rest are discarded. The default value is <tt>512</tt>.</p>
<dt><i>keymaxwords</i></p>
<dd>Maximum number of keywords that will be generated for an article. (The keyword generation code will attempt to discard &#8220;noise&#8221; words, so the number of keywords actually written into the overview will usually be smaller than this even if the maximum number of keywords is found.) The default value is <tt>250</tt>.</dl>
<h2>Posting</h2>
<p>These parameters are only used by <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8), <i><a href="/docs/linux/man/1-inews/">inews</a></i>(1), and other programs that accept or generate postings. There are some special sets of settings that are broken out separately after the initial alphabetized list.</p>
<dl>
<dt><i>addnntppostingdate</i></p>
<dd>Whether to add an NNTP-Posting-Date: header to all local posts. This is a boolean value and the default is true.</p>
<dt><i>addnntppostinghost</i></p>
<dd>Whether to add an NNTP-Posting-Host: header to all local posts giving the <font SIZE="-1">FQDN</font> or <font SIZE="-1">IP</font> address of the system from which the post was received. This is a boolean value and the default is true. Note that <font SIZE="-1">INN</font> either does not add this header or adds the name or <font SIZE="-1">IP</font> address of the client. There is no intrinsic support for obfuscating the name of the client. That has to be done with a user-written Perl filter, if desired.</p>
<dt><i>checkincludedtext</i></p>
<dd>Whether to check local postings for the ratio of new to quoted text and reject them if that ratio is under 50%. Included text is recognized by looking for lines beginning with <tt>&quot;&gt;&quot;</tt>, <tt>&quot;|&quot;</tt>, or <tt>&quot;:&quot;</tt>. This is a boolean value and the default is false.</p>
<dt><i>complaints</i></p>
<dd>The value of the X-Complaints-To: header added to all local posts. The default is the newsmaster&#8217;s e-mail address. (If the newsmaster, selected at configure time and defaulting to <tt>&quot;usenet&quot;</tt>, doesn&#8217;t contain <tt>&quot;@&quot;</tt>, the address will consist of the newsmaster, a <tt>&quot;@&quot;</tt>, and the value of <i>fromhost</i>.)</p>
<dt><i>fromhost</i></p>
<dd>Contains a domain used to construct e-mail addresses. The address of the local news administrator will be given as &lt;user&gt;@<i>fromhost</i>, where &lt;user&gt; is the newsmaster user set at compile time (<tt>&quot;usenet&quot;</tt> by default). This setting will also be used by <i><a href="/docs/linux/man/8-mailpost/">mailpost</a></i>(8) to fully qualify addresses and by <i><a href="/docs/linux/man/1-inews/">inews</a></i>(1) to generate the Sender: header (and From: header if missing). The value of the <font SIZE="-1">FROMHOST</font> environment variable, if set, overrides this setting. The default is the fully-qualified domain name of the local host.</p>
<dt><i>localmaxartsize</i></p>
<dd>The maximum article size (in bytes) for locally posted articles. Articles larger than this will be rejected. A value of <tt>0</tt> allows any size of article, but note that <code>nnrpd</code> and <code>innd</code> will crash if system memory is exceeded. See also <i>maxartsize</i>, which applies to all articles including those posted locally. The default value is <tt>1000000</tt> (approximately 1&nbsp;<wbr><font SIZE="-1">MB</font>).</p>
<dt><i>moderatormailer</i></p>
<dd>The address to which to send submissions for moderated groups. It is only used if the <i>moderators</i> file doesn&#8217;t exist, or if the moderated group to which an article is posted is not matched by any entry in that file, and takes the same form as an entry in the <i>moderators</i> file. In most cases, <tt>&quot;%s [at] moderators.isc.org&quot;</tt> is a good value for this parameter (<tt>%s</tt> is expanded into a form of the newsgroup name). See <i><a href="/docs/linux/man/5-moderators/">moderators</a></i>(5) for more details about the syntax. The default is unset. If this parameter isn&#8217;t set and an article is posted to a moderated group that does not have a matching entry in the <i>moderators</i> file, the posting will be rejected with an error.</p>
<dt><i>nnrpdauthsender</i></p>
<dd>Whether to generate a Sender: header based on reader authentication. If this parameter is set, a Sender: header will be added to local posts containing the identity assigned by <i>readers.conf</i>. If the assigned identity does not include an <tt>&quot;@&quot;</tt>, the reader&#8217;s hostname is used. If this parameter is set but no identity is be assigned, the Sender: header will be removed from all posts even if the poster includes one. This is a boolean value and the default is false.</p>
<dt><i>nnrpdposthost</i></p>
<dd>If set, <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) and <i><a href="/docs/linux/man/1-rnews/">rnews</a></i>(1) will pass all locally posted articles to the specified host rather than trying to inject them locally. See also <i>nnrpdpostport</i>. This should always be set if <i>xrefslave</i> is true. The default value is unset.</p>
<dt><i>nnrpdpostport</i></p>
<dd>The port on the remote server to connect to to post when <i>nnrpdposthost</i> is used. The default value is <tt>119</tt>.</p>
<dt><i>organization</i></p>
<dd>What to put in the Organization: header if it is left blank by the poster. The value of the <font SIZE="-1">ORGANIZATION</font> environment variable, if set, overrides this setting. The default is unset, which tells <font SIZE="-1">INN</font> not to insert an Organization: header.</p>
<dt><i>spoolfirst</i></p>
<dd>If true, <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) will spool new articles rather than attempting to send them to <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8). If false, nnrpd will spool articles only if it receives an error trying to send them to innd. Setting this to true can be useful if nnrpd must respond as fast as possible to the client; however, when set, articles will not appear to readers until they are given to innd. nnrpd won&#8217;t do this; <tt>&quot;rnews -U&quot;</tt> must be run periodically to take the spooled articles and post them. This is a boolean value and the default is false.</p>
<dt><i>strippostcc</i></p>
<dd>Whether to strip To:, Cc:, and Bcc: headers out of all local posts via <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8). The primary purpose of this setting is to prevent abuse of the news server by posting to a moderated group and including To: or Cc: headers in the post so that the news server will send the article to arbitrary addresses. <font SIZE="-1">INN</font> now protects against this abuse in other ways provided <i>mta</i> is set to a command that includes <tt>%s</tt> and honors it, so this is generally no longer needed. This is a boolean value and the default is false.</dl>
<p> <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) has support for controlling high-volume posters via an exponential backoff algorithm, as configured by the following parameters. </p>
<p> Exponential posting backoff works as follows: News clients are indexed by <font SIZE="-1">IP</font> address (or username, see <i>backoffauth</i> below). Each time a post is received from an <font SIZE="-1">IP</font> address, the time of posting is stored (along with the previous sleep time, see below). After a configurable number of posts in a configurable period of time, <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) will activate posting backoff and begin to sleep for increasing periods of time before actually posting anything. Posts will still be accepted, but at an increasingly reduced rate. </p>
<p> After backoff has been activated, the length of time to sleep is computed based on the difference in time between the last posting and the current posting. If this difference is less than <i>backoffpostfast</i>, the new sleep time will be 1 + (previous sleep time * <i>backoffk</i>). If this difference is less than <i>backoffpostslow</i> but greater than <i>backoffpostfast</i>, then the new sleep time will equal the previous sleep time. If this difference is greater than <i>backoffpostslow</i>, the new sleep time is zero and posting backoff is deactivated for this poster. </p>
<p> Exponential posting backoff will not be enabled unless <i>backoffdb</i> is set and <i>backoffpostfast</i> and <i>backoffpostslow</i> are set to something other than their default values. </p>
<p> Here are the parameters that control exponential posting backoff:</p>
<dl>
<dt><i>backoffauth</i></p>
<dd>Whether to index posting backoffs by user rather than by source <font SIZE="-1">IP</font> address. You must be using authentication in <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) for a value of true to have any meaning. This is a boolean value and the default is false.</p>
<dt><i>backoffdb</i></p>
<dd>The path to a directory, writeable by the news user, that will contain the backoff database. There is no default for this parameter; you must provide a path to a creatable or writeable directory to enable exponential backoff.</p>
<dt><i>backoffk</i></p>
<dd>The amount to multiply the previous sleep time by if the user is still posting too quickly. A value of <tt>2</tt> will double the sleep time for each excessive post. The default value is <tt>1</tt>.</p>
<dt><i>backoffpostfast</i></p>
<dd>Postings from the same identity that arrive in less than this amount of time (in seconds) will trigger increasing sleep time in the backoff algorithm. The default value is <tt>0</tt>.</p>
<dt><i>backoffpostslow</i></p>
<dd>Postings from the same identity that arrive in greater than this amount of time (in seconds) will reset the backoff algorithm. Another way to look at this constant is to realize that posters will be allowed to generate at most 86400/<i>backoffpostslow</i> posts per day. The default value is <tt>1</tt>.</p>
<dt><i>backofftrigger</i></p>
<dd>This many postings are allowed before the backoff algorithm is triggered. The default value is <tt>10000</tt>.</dl>
<p> Finally, here are the parameters used by <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) to provide <font SIZE="-1">TLS/SSL</font> support:</p>
<dl>
<dt><i>tlscafile</i></p>
<dd>The path to a file containing certificate authority root certificates, used to present a trust chain to a <font SIZE="-1">TLS</font> client. This parameter is only used if <code>nnrpd</code> is built with <font SIZE="-1">TLS/SSL</font> support. There is no default value.</p>
<dt><i>tlscapath</i></p>
<dd>The path to a directory containing certificate authority root certificates. Each file in the directory should contain one <font SIZE="-1">CA</font> certificate, and the name of the file should be the <font SIZE="-1">CA</font> subject name hash value. See the OpenSSL documentation for more information. This parameter is only used if <code>nnrpd</code> is built with <font SIZE="-1">TLS/SSL</font> support. There is no default value.</p>
<dt><i>tlscertfile</i></p>
<dd>The path to a file containing the server certificate to present to <font SIZE="-1">TLS</font> clients. This parameter is only used if <code>nnrpd</code> is built with <font SIZE="-1">TLS/SSL</font> support. The default value is <i>pathnews</i>/lib/cert.pem.</p>
<dt><i>tlskeyfile</i></p>
<dd>The path to a file containing the encryption key for the server certificate named in <i>tlscertfile</i>. This may be the same as <i>tlscertfile</i> if, when you created the certificate, you put the key in the same file (if, for example, you gave the same file name to both the <code>-out</code> and <code>-keyout</code> options to <tt>&quot;openssl req&quot;</tt>). This parameter is only used if <code>nnrpd</code> is built with <font SIZE="-1">TLS/SSL</font> support. The default value is <i>pathnews</i>/lib/key.pem. </p>
<p> This file must only be readable by the news user or <code>nnrpd</code> will refuse to use it.</dl>
<h2>Monitoring</h2>
<p>These parameters control the behavior of <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8), the program that monitors <font SIZE="-1">INN</font> and informs the news administrator if anything goes wrong with it.</p>
<dl>
<dt><i>doinnwatch</i></p>
<dd>Whether to start <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8) from rc.news. This is a boolean value, and the default is true.</p>
<dt><i>innwatchbatchspace</i></p>
<dd>Free space in <i>pathoutgoing</i>, in <i><a href="/docs/linux/man/8-inndf/">inndf</a></i>(8) output units (normally kilobytes), at which <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will be throttled by <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8), assuming a default <i>innwatch.ctl</i>. The default value is <tt>4000</tt>.</p>
<dt><i>innwatchlibspace</i></p>
<dd>Free space in <i>pathdb</i>, in <i><a href="/docs/linux/man/8-inndf/">inndf</a></i>(8) output units (normally kilobytes), at which <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will be throttled by <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8), assuming a default <i>innwatch.ctl</i>. The default value is <tt>25000</tt>.</p>
<dt><i>innwatchloload</i></p>
<dd>Load average times 100 at which <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will be restarted by <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8) (undoing a previous pause or throttle), assuming a default <i>innwatch.ctl</i>. The default value is <tt>1000</tt> (that is, a load average of 10.00).</p>
<dt><i>innwatchhiload</i></p>
<dd>Load average times 100 at which <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will be throttled by <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8), assuming a default <i>innwatch.ctl</i>. The default value is <tt>2000</tt> (that is, a load average of 20.00).</p>
<dt><i>innwatchpauseload</i></p>
<dd>Load average times 100 at which <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will be paused by <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8), assuming a default <i>innwatch.ctl</i>. The default value is <tt>1500</tt> (that is, a load average of 15.00).</p>
<dt><i>innwatchsleeptime</i></p>
<dd>How long (in seconds) <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8) will sleep between each check of <font SIZE="-1">INN</font>. The default value is <tt>600</tt>.</p>
<dt><i>innwatchspoolnodes</i></p>
<dd>Free inodes in <i>patharticles</i> at which <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will be throttled by <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8), assuming a default <i>innwatch.ctl</i>. The default value is <tt>200</tt>.</p>
<dt><i>innwatchspoolspace</i></p>
<dd>Free space in <i>patharticles</i> and <i>pathoverview</i>, in <i><a href="/docs/linux/man/8-inndf/">inndf</a></i>(8) output units (normally kilobytes), at which <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will be throttled by <i><a href="/docs/linux/man/8-innwatch/">innwatch</a></i>(8), assuming a default <i>innwatch.ctl</i>. The default value is <tt>25000</tt>.</dl>
<h2>Logging</h2>
<p>These parameters control what information <font SIZE="-1">INN</font> logs.</p>
<dl>
<dt><i>docnfsstat</i></p>
<dd>Whether to start <i><a href="/docs/linux/man/8-cnfsstat/">cnfsstat</a></i>(8) when <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) is started. cnfsstat will log the status of all <font SIZE="-1">CNFS</font> cycbuffs to syslog on a periodic basis (frequency is the default for <tt>&quot;cnfsstat -l&quot;</tt>, currently 600 seconds). This is a boolean value and the default is false.</p>
<dt><i>incominglogfrequency</i></p>
<dd>How many articles to process on an incoming channel before logging the activity. The default value is <tt>200</tt>.</p>
<dt><i>logartsize</i></p>
<dd>Whether the size of accepted articles (in bytes) should be written to the article log file. This is useful for flow rate statistics and is recommended. This is a boolean value and the default is true.</p>
<dt><i>logcancelcomm</i></p>
<dd>Set this to true to log <tt>&quot;ctlinnd cancel&quot;</tt> commands to syslog. This is a boolean value and the default is false.</p>
<dt><i>logcycles</i></p>
<dd>How many old logs <i><a href="/docs/linux/man/8-scanlogs/">scanlogs</a></i>(8) keeps. <i><a href="/docs/linux/man/8-scanlogs/">scanlogs</a></i>(8) is generally run by <i><a href="/docs/linux/man/8-news-daily/">news.daily</a></i>(8) and will archive compressed copies of this many days worth of old logs. The default value is <tt>3</tt>.</p>
<dt><i>logipaddr</i></p>
<dd>Whether the verified name of the remote feeding host should be logged to the article log for incoming articles rather than the last entry in the Path: header. The only reason to ever set this to false is due to some interactions with <i>newsfeeds</i> flags; see <i><a href="/docs/linux/man/5-newsfeeds/">newsfeeds</a></i>(5) for more information. This is a boolean value and the default is true.</p>
<dt><i>logsitename</i></p>
<dd>Whether the names of the sites to which accepted articles will be sent should be put into the article log file. This is useful for debugging and statistics. This is a boolean value and the default is true.</p>
<dt><i>logstatus</i></p>
<dd>Whether <code>innd</code> should write a shortened version of its status report to syslog every <i>status</i> seconds. This is a boolean value and the default is false. If set to true, see the <i>status</i> parameter for more details on how to enable status reporting.</p>
<dt><i>nnrpdoverstats</i></p>
<dd>Whether nnrpd overview statistics should be logged via syslog. This can be useful for measuring overview performance. This is a boolean value and the default is false.</p>
<dt><i>nntplinklog</i></p>
<dd>Whether to put the storage <font SIZE="-1">API</font> token for accepted articles (used by nntplink) in the article log. This is a boolean value and the default is false.</p>
<dt><i>stathist</i></p>
<dd>Where to write history statistics for analysis with <i>contrib/stathist.pl</i>; this can be modified with <i><a href="/docs/linux/man/8-ctlinnd/">ctlinnd</a></i>(8) while innd is running. Logging does not occur unless a path is given, and there is no default value.</p>
<dt><i>status</i></p>
<dd>How frequently (in seconds) <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) should write out a status report. The report is written to <i>pathhttp</i>/inn_status.html. If this is set to <tt>0</tt> or <tt>&quot;false&quot;</tt>, status reporting is disabled. The default value is <tt>0</tt>.</p>
<dt><i>timer</i></p>
<dd>How frequently (in seconds) <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) should report performance timings to syslog. If this is set to <tt>0</tt>, performance timing is disabled. Enabling this is highly recommended, and <i><a href="/docs/linux/man/8-innreport/">innreport</a></i>(8) can produce a nice summary of the timings. If set to <tt>0</tt>, performance timings in <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) are also disabled, although nnrpd always reports statistics on exit and therefore any non-zero value is equivalent for it. The default value is <tt>0</tt>.</dl>
<h2>System Tuning</h2>
<p>The following parameters can be modified to tune the low-level operation of <font SIZE="-1">INN</font>. In general, you shouldn&#8217;t need to modify any of them except possibly <i>rlimitnofile</i> unless the server is having difficulty.</p>
<dl>
<dt><i>badiocount</i></p>
<dd>How many read or write failures until a channel is put to sleep or closed. The default value is <tt>5</tt>.</p>
<dt><i>blockbackoff</i></p>
<dd>Each time an attempted write returns <font SIZE="-1">EAGAIN</font> or <font SIZE="-1">EWOULDBLOCK</font>, <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will wait for an increasing number of seconds before trying it again. This is the multiplier for the sleep time. If you&#8217;re having trouble with channel feeds not keeping up, it may be good to change this value to <tt>2</tt> or <tt>3</tt>, since then when the channel fills <font SIZE="-1">INN</font> will try again in a couple of seconds rather than waiting two minutes. The default value is <tt>120</tt>.</p>
<dt><i>chaninacttime</i></p>
<dd>The time (in seconds) to wait between noticing inactive channels. The default value is <tt>600</tt>.</p>
<dt><i>chanretrytime</i></p>
<dd>How many seconds to wait before a channel restarts. The default value is <tt>300</tt>.</p>
<dt><i>datamovethreshold</i></p>
<dd>The threshold for deciding whether to move already-read data to the top of buffer or extend the buffer. The buffer described here is used for reading <font SIZE="-1">NNTP</font> data. Increasing this value may improve performance, but it should not be increased on Systems with insufficient memory. Permitted values are between <tt>0</tt> and <tt>1048576</tt> (out of range values are treated as <tt>1048576</tt>) and the default value is <tt>8192</tt>.</p>
<dt><i>icdsynccount</i></p>
<dd>How many article writes between updating the active and history files. The default value is <tt>10</tt>.</p>
<dt><i>keepmmappedthreshold</i></p>
<dd>When using buffindexed, retrieving overview data (that is, responding to <font SIZE="-1">XOVER</font> or running expireover) causes mmapping of all overview data blocks which include requested overview data for newsgroup. But for high volume newsgroups like control.cancel, this may cause too much mmapping at once leading to system resource problems. To avoid this, if the amount to be mmapped exceeds <i>keepmmappedthreshold</i> (in <font SIZE="-1">KB</font>), buffindexed mmap&#8217;s just one overview block (8&nbsp;<wbr><font SIZE="-1">KB</font>). This parameter is specific to buffindexed overview storage method. The default value is <tt>1024</tt> (1&nbsp;<wbr><font SIZE="-1">MB</font>).</p>
<dt><i>maxcmdreadsize</i></p>
<dd>If set to anything other than <tt>0</tt>, maximum buffer size (in bytes) for reading <font SIZE="-1">NNTP</font> command will have this value. It should not be large on systems which are slow to process and store articles, as that would lead to <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) spending a long time on each channel and keeping other channels waiting. The default value is <font SIZE="-1">BUFSIZ</font> defined in stdio.h (<tt>1024</tt> in most environments, see <i><a href="/docs/linux/man/3-setbuf/">setbuf</a></i>(3)).</p>
<dt><i>maxforks</i></p>
<dd>How many times to attempt a <i><a href="/docs/linux/man/2-fork/">fork</a></i>(2) before giving up. The default value is <tt>10</tt>.</p>
<dt><i>nicekids</i></p>
<dd>If set to anything other than <tt>0</tt>, all child processes of <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) will have this <i><a href="/docs/linux/man/2-nice/">nice</a></i>(2) value. This is usually used to give all child processes of <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) a lower priority (higher nice value) so that <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) can get the lion&#8217;s share of the <font SIZE="-1">CPU</font> when it needs it. The default value is <tt>4</tt>.</p>
<dt><i>nicenewnews</i></p>
<dd>If set to anything greater than <tt>0</tt>, all <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) processes that receive and process a <font SIZE="-1">NEWNEWS</font> command will <i><a href="/docs/linux/man/2-nice/">nice</a></i>(2) themselves to this value (giving other nnrpd processes a higher priority). The default value is <tt>0</tt>. Note that this value will be ignored if set to a lower value than <i>nicennrpd</i> (or <i>nicekids</i> if <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) is spawned from <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8)).</p>
<dt><i>nicennrpd</i></p>
<dd>If set to anything greater than <tt>0</tt>, all <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) processes will <i><a href="/docs/linux/man/1-nice/">nice</a></i>(1) themselves to this value. This gives other news processes a higher priority and can help <i><a href="/docs/linux/man/8-overchan/">overchan</a></i>(8) keep up with incoming news (if that&#8217;s the object, be sure <i><a href="/docs/linux/man/8-overchan/">overchan</a></i>(8) isn&#8217;t also set to a lower priority via <i>nicekids</i>). The default value is <tt>0</tt>, which will cause <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) processes spawned from <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) to use the value of <i>nicekids</i>, while <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) run as a daemon will use the system default priority. Note that for <i><a href="/docs/linux/man/8-nnrpd/">nnrpd</a></i>(8) processes spawned from <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8), this value will be ignored if set to a value lower than <i>nicekids</i>.</p>
<dt><i>pauseretrytime</i></p>
<dd>Wait for this many seconds before noticing inactive channels. Wait for this many seconds before innd processes articles when it&#8217;s paused or the number of channel write failures exceeds <i>badiocount</i>. The default value is <tt>300</tt>.</p>
<dt><i>peertimeout</i></p>
<dd>How long (in seconds) an <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) incoming channel may be inactive before innd closes it. The default value is <tt>3600</tt> (an hour).</p>
<dt><i>rlimitnofile</i></p>
<dd>The maximum number of file descriptors that <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) or <i><a href="/docs/linux/man/8-innfeed/">innfeed</a></i>(8) can have open at once. If <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) or <i><a href="/docs/linux/man/8-innfeed/">innfeed</a></i>(8) attempts to open more file descriptors than this value, it is possible the program may throttle or otherwise suffer reduced functionality. The number of open file descriptors is roughly the maximum number of incoming feeds and outgoing batches for <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8) and the number of outgoing streams for <i><a href="/docs/linux/man/8-innfeed/">innfeed</a></i>(8). If this parameter is set to a negative value, the default limit of the operating system will be used; this will normally be adequate on systems other than Solaris. Nearly all operating systems have some hard maximum limit beyond which this value cannot be raised, usually either 128, 256, or 1024. The default value of this parameter is <tt>&quot;-1&quot;</tt>. Setting it to <tt>256</tt> on Solaris systems is highly recommended.</dl>
<h2>Paths and File Names</h2>
<dl>
<dt><i>patharchive</i></p>
<dd>Where to store archived news. The default value is <i>pathspool</i>/archive.</p>
<dt><i>patharticles</i></p>
<dd>The path to where the news articles are stored (for storage methods other than <font SIZE="-1">CNFS</font>). The default value is <i>pathspool</i>/articles.</p>
<dt><i>pathbin</i></p>
<dd>The path to the news binaries. The default value is <i>pathnews</i>/bin.</p>
<dt><i>pathcontrol</i></p>
<dd>The path to the files that handle control messages. The code for handling each separate type of control message is located here. Be very careful what you put in this directory with a name ending in <tt>&quot;.pl&quot;</tt>, as it can potentially be a severe security risk. The default value is <i>pathbin</i>/control.</p>
<dt><i>pathdb</i></p>
<dd>The path to the database files used and updated by the server (currently, <i>active</i>, <i>active.times</i>, <i>history</i> and its indices, and <i>newsgroups</i>). The default value is <i>pathnews</i>/db.</p>
<dt><i>pathetc</i></p>
<dd>The path to the news configuration files. The default value is <i>pathnews</i>/etc.</p>
<dt><i>pathfilter</i></p>
<dd>The path to the Perl and Python filters. The default value is <i>pathbin</i>/filter.</p>
<dt><i>pathhttp</i></p>
<dd>Where any <font SIZE="-1">HTML</font> files (such as periodic status reports) are placed. If the news reports should be available in real-time on the web, the files in this directory should be served by a web server. The default value is the value of <i>pathnews</i>/http.</p>
<dt><i>pathincoming</i></p>
<dd>Location where incoming batched news is stored. The default value is <i>pathspool</i>/incoming.</p>
<dt><i>pathlog</i></p>
<dd>Where the news log files are written. The default value is <i>pathnews</i>/log.</p>
<dt><i>pathnews</i></p>
<dd>The home directory of the news user and usually the root of the news hierarchy. There is no default; this parameter must be set in <i>inn.conf</i> or <font SIZE="-1">INN</font> will refuse to start.</p>
<dt><i>pathoutgoing</i></p>
<dd>Default location for outgoing feed files. The default value is <i>pathspool</i>/outgoing.</p>
<dt><i>pathoverview</i></p>
<dd>The path to news overview files. The default value is <i>pathspool</i>/overview.</p>
<dt><i>pathrun</i></p>
<dd>The path to files required while the server is running and run-time state information. This includes lock files and the sockets for communicating with <i><a href="/docs/linux/man/8-innd/">innd</a></i>(8). This directory and the control sockets in it should be protected from unprivileged users other than the news user. The default value is <i>pathnews</i>/run.</p>
<dt><i>pathspool</i></p>
<dd>The root of the news spool hierarchy. This used mostly to set the defaults for other parameters, and to determine the path to the backlog directory for <i><a href="/docs/linux/man/8-innfeed/">innfeed</a></i>(8). The default value is <i>pathnews</i>/spool.</p>
<dt><i>pathtmp</i></p>
<dd>Where <font SIZE="-1">INN</font> puts temporary files. For security reasons, this is not the same as the system temporary files directory (<font SIZE="-1">INN</font> creates a lot of temporary files with predictable names and does not go to particularly great lengths to protect against symlink attacks and the like; this is safe provided that normal users can&#8217;t write into its temporary directory). The default value is set at configure time and defaults to <i>pathnews</i>/tmp.</dl>
<h2>Example</h2>
<p>Here is a very minimalist example that only sets those parameters that are required. </p>
<pre> mta: &quot;/usr/lib/sendmail -oi -oem %s&quot;
 ovmethod: tradindexed
 pathhost: news.example.com
 pathnews: /usr/local/news
 hismethod: hisv6</pre>
<p>For a more comprehensive example, see the sample <i>inn.conf</i> distributed with <font SIZE="-1">INN</font> and installed as a starting point; it contains all of the default values for reference.</p>
