<p>gitmailmap &#8211; Map author/committer names and/or E-Mail addresses</p>
<h2>Synopsis</h2>
<p>$GIT_WORK_TREE/.mailmap</p>
<h2>Description</h2>
<p>If the file <code>.mailmap</code> exists at the toplevel of the repository, or at the location pointed to by the <code>mailmap.file</code> or <code>mailmap.blob</code> configuration options (see <code><a href="/docs/linux/man/1-git-config/">git-config</a></code>(1)), it is used to map author and committer names and email addresses to canonical real names and email addresses.</p>
<h2>Syntax</h2>
<p>The <i>#</i> character begins a comment to the end of line, blank lines are ignored. </p>
<p> In the simple form, each line in the file consists of the canonical real name of an author, whitespace, and an email address used in the commit (enclosed by <i>&lt;</i> and <i>&gt;</i>) to map to the name. For example: </p>
<dl>
<dd>
<pre>Proper Name &lt;commit [at] email.xx&gt;</pre>
</dl>
<p> The more complex forms are: </p>
<dl>
<dd>
<pre>&lt;proper [at] email.xx&gt; &lt;commit [at] email.xx&gt;</pre>
</dl>
<p> which allows mailmap to replace only the email part of a commit, and: </p>
<dl>
<dd>
<pre>Proper Name &lt;proper [at] email.xx&gt; &lt;commit [at] email.xx&gt;</pre>
</dl>
<p> which allows mailmap to replace both the name and the email of a commit matching the specified commit email address, and: </p>
<dl>
<dd>
<pre>Proper Name &lt;proper [at] email.xx&gt; Commit Name &lt;commit [at] email.xx&gt;</pre>
</dl>
<p> which allows mailmap to replace both the name and the email of a commit matching both the specified commit name and email address. </p>
<p> Both E-Mails and names are matched case-insensitively. For example this would also match the <i>Commit Name &lt;commit [at] email.xx&gt;</i> above: </p>
<dl>
<dd>
<pre>Proper Name &lt;proper [at] email.xx&gt; CoMmIt NaMe &lt;CoMmIt [at] EmAiL.xX&gt;</pre>
</dl>
<h2>Notes</h2>
<p>Git does not follow symbolic links when accessing a <code>.mailmap</code> file in the working tree. This keeps behavior consistent when the file is accessed from the index or a tree versus from the filesystem.</p>
<h2>Examples</h2>
<p>Your history contains commits by two authors, Jane and Joe, whose names appear in the repository under several forms:</p>
<dl>
<dd>
<pre>Joe Developer &lt;joe [at] example.com&gt;
Joe R. Developer &lt;joe [at] example.com&gt;
Jane Doe &lt;jane [at] example.com&gt;
Jane Doe &lt;jane [at] laptop.(none)&gt;
Jane D. &lt;jane [at] desktop.(none)&gt;</pre>
</dl>
<p> Now suppose that Joe wants his middle name initial used, and Jane prefers her family name fully spelled out. A <code>.mailmap</code> file to correct the names would look like:</p>
<dl>
<dd>
<pre>Joe R. Developer &lt;joe [at] example.com&gt;
Jane Doe &lt;jane [at] example.com&gt;
Jane Doe &lt;jane [at] desktop.(none)&gt;</pre>
</dl>
<p> Note that there&#8217;s no need to map the name for <i>&lt;jane [at] laptop.(none)&gt;</i> to only correct the names. However, leaving the obviously broken <i>&lt;jane [at] laptop.(none)&gt;</i> and <i>&lt;jane [at] desktop.(none)&gt;</i> E-Mails as-is is usually not what you want. A <code>.mailmap</code> file which also corrects those is:</p>
<dl>
<dd>
<pre>Joe R. Developer &lt;joe [at] example.com&gt;
Jane Doe &lt;jane [at] example.com&gt; &lt;jane [at] laptop.(none)&gt;
Jane Doe &lt;jane [at] example.com&gt; &lt;jane [at] desktop.(none)&gt;</pre>
</dl>
<p> Finally, let&#8217;s say that Joe and Jane shared an E-Mail address, but not a name, e.g. by having these two commits in the history generated by a bug reporting system. I.e. names appearing in history as:</p>
<dl>
<dd>
<pre>Joe &lt;bugs [at] example.com&gt;
Jane &lt;bugs [at] example.com&gt;</pre>
</dl>
<p> A full <code>.mailmap</code> file which also handles those cases (an addition of two lines to the above example) would be:</p>
<dl>
<dd>
<pre>Joe R. Developer &lt;joe [at] example.com&gt;
Jane Doe &lt;jane [at] example.com&gt; &lt;jane [at] laptop.(none)&gt;
Jane Doe &lt;jane [at] example.com&gt; &lt;jane [at] desktop.(none)&gt;
Joe R. Developer &lt;joe [at] example.com&gt; Joe &lt;bugs [at] example.com&gt;
Jane Doe &lt;jane [at] example.com&gt; Jane &lt;bugs [at] example.com&gt;</pre>
</dl>
