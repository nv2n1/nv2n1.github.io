<p>virt-who-config &#8211; configuration for virt-who</p>
<h2>Synopisis</h2>
<p>/etc/virt-who.conf /etc/virt-who.d/*</p>
<h2>Description</h2>
<p>Configuration format is ini-like. The configuration files located at /etc/virt-who.d/ are called virtualization backend configurations. The configuration located at /etc/virt-who.conf is the main configuration for virt-who. Below are descriptions of both the required and optional options for both kinds of configs and how they are used.</p>
<h2>General Configuration</h2>
<p>The general configuration file (located at /etc/virt-who.conf), has two special sections <code>global</code> and <code>defaults</code>. The settings that can be specified in <code>defaults</code> are any setting listed in the <code>VIRTUALIZATION BACKEND CONFIGURATION</code> section of this manual. These settings are applied as defaults to the configurations found in /etc/virt-who.d/*. </p>
<p> The settings in the <code>global</code> affect the overall operation of the application. The following are options that can be specified in the <code>global</code> section:</p>
<dl>
<dt><code>interval</code></p>
<dd>how often to check connected hypervisors for changes (seconds). Also affects how often a mapping is reported.</p>
<dt><code>reporter_id</code></p>
<dd>The id of this virt-who instance, reported with all mappings. Defaults to HOSTNAME-MACHINEID</p>
<dt><code>debug</code></p>
<dd>Enable debugging output</p>
<dt><code>oneshot</code></p>
<dd>Send the list of guest IDs and exit immediately</p>
<dt><code>log_per_config</code></p>
<dd>Write a seperate log file per configuration in the config directory</p>
<dt><code>log_dir</code></p>
<dd>The absolute path of the directory to write logs to.</p>
<dt><code>log_file</code></p>
<dd>The file name to write logs to (used only if log_per_config=False)</p>
<dt><code>configs</code></p>
<dd>A list of files containing configurations for virt-who Used to specify locations other than default </p>
</dl>
<h2>Virtualization Backend Configuration</h2>
<p>Each section (or group), denoted by an arbitrary name for the configuration (in square brackets), is read in </p>
<p> Only required key is <code>type</code> that has to have one of the allowed virtualization backend names, see <a href="/docs/linux/man/8-virt-who/">virt-who</a>(8). </p>
<p> Please note that special characters must not be escaped (opposed to /etc/sysconfig/virt-who). </p>
<p> Other options that can be supplied are:</p>
<dl>
<dt><code>server</code></p>
<dd>Hostname, IP address or URL of the server that provides virtualization information (not applicable for vdsm mode).</p>
<dt><code>username</code></p>
<dd>Username for authentication to the server (not applicable for vdsm mode). May include domain. Do not escape the backslash between domain and username.</p>
<dt><code>password</code></p>
<dd>Password for authentication to the server (not applicable for vdsm mode).</p>
<dt><code>encrypted_password</code></p>
<dd>Alternative to the password option, encrypted password that is generated by <a href="/docs/linux/man/8-virt-who-password/">virt-who-password</a>(8) utility.</p>
<dt><code>owner</code></p>
<dd>Owner for use with Subscription Asset Manager, the Red Hat Customer Portal, or Satellite 6 (not applicable for Satellite 5)</p>
<dt><code>env</code></p>
<dd>Environment for use with Subscription Asset Manager or Satellite 6 (not applicable for Satellite 5)</p>
<dt><code>rhsm_username</code></p>
<dd>Optional username to use to communicate with Subscription Asset Manager or Satellite 6 instead of the registered system&#8217;s identity certificate. (not applicable for Satellite 5)</p>
<dt><code>rhsm_password</code></p>
<dd>Optional password to use to communicate with Subscription Asset Manager or Satellite 6 instead of the registered system&#8217;s identity certificate. (not applicable for Satellite 5)</p>
<dt><code>rhsm_encrypted_password</code></p>
<dd>Alternative to the rhsm_password option, encrypted password that is generated by <a href="/docs/linux/man/8-virt-who-password/">virt-who-password</a>(8) utility.</p>
<dt><code>rhsm_hostname</code></p>
<dd>Optional hostname of the Subscription Asset Manager or Satellite 6 server to use in place of the host defined in the system&#8217;s rhsm.conf.</p>
<dt><code>rhsm_port</code></p>
<dd>Optional port for the Subscription Asset Manager or Satellite 6 server to use in place of the port defined in the system&#8217;s rhsm.conf.</p>
<dt><code>rhsm_prefix</code></p>
<dd>Optional prefix for the Subscription Asset Manager or Satellite 6 server to use in place of the prefix defined in the system&#8217;s rhsm.conf.</p>
<dt><code>rhsm_proxy_hostname</code></p>
<dd>Optional proxy host name for the Subscription Asset Manager or Satellite 6 server to use in place of the proxy host name defined in the system&#8217;s rhsm.conf.</p>
<dt><code>rhsm_proxy_port</code></p>
<dd>Optional proxy port for the Subscription Asset Manager or Satellite 6 server to use in place of the proxy port defined in the system&#8217;s rhsm.conf.</p>
<dt><code>rhsm_proxy_user</code></p>
<dd>Optional proxy username for the Subscription Asset Manager or Satellite 6 server to use in place of the proxy username defined in the system&#8217;s rhsm.conf.</p>
<dt><code>rhsm_proxy_password</code></p>
<dd>Optional proxy password for the Subscription Asset Manager or Satellite 6 server to use in place of the proxy password defined in the system&#8217;s rhsm.conf.</p>
<dt><code>rhsm_encrypted_proxy_password</code></p>
<dd>Alternative to the rhsm_proxy_password option; encrypted password generated by the <a href="/docs/linux/man/8-virt-who-password/">virt-who-password</a>(8) utility.</p>
<dt><code>sat_server</code></p>
<dd>Hostname, IP address or URL of the Satellite 5 server.</p>
<dt><code>sat_username</code></p>
<dd>Username for authentication to the Satellite 5 server.</p>
<dt><code>sat_password</code></p>
<dd>Password for authentication to the Satellite 5 server.</p>
<dt><code>sat_encrypted_password</code></p>
<dd>Alternative to sat_password option, encrypted password that is generated by <a href="/docs/linux/man/8-virt-who-password/">virt-who-password</a>(8) utility.</p>
<dt><code>filter_hosts</code></p>
<dd>Only hosts which uuid (or hostname or hwuuid, based on <code>hypervisor_id</code>) is specified in comma-separated list in this option will be reported. Put the value into the double-quotes if it contains special characters (like comma). <code>filter_host_uuids</code> is deprecated alias for this option.</p>
<dt><code>exclude_hosts</code></p>
<dd>Hosts which uuid (or hostname or hwuuid, based on <code>hypervisor_id</code>) is specified in comma-separated list in this option will <code>NOT</code> be reported. Put the value into the double-quotes if it contains special characters (like comma). <code>exclude_host_uuids</code> is deprecated alias for this option.</p>
<dt><code>hypervisor_id</code></p>
<dd>Property that should be used as identification of the hypervisor. Can be one of following: <code>uuid</code>, <code>hostname</code>, <code>hwuuid</code>. Note that some virtualization backends don&#8217;t have all of them implemented. Default is <code>uuid</code>. <code>hwuuid</code> is applicable to esx and rhevm only. This property is meant to be set up before initial run of virt-who. Changing it later will result in duplicated entries in the subscription manager. </p>
</dl>
<h2>Example</h2>
<p>[test-esx]<br />
 type=esx<br />
 server=1.2.3.4<br />
 username=admin<br />
 password=password<br />
 owner=test<br />
 env=staging<br />
 rhsm_username=admin<br />
 rhsm_password=password </p>
<h2>Backend Specific Options</h2>
<h3>Esx Backend</h3>
<dl>
<dt><code>filter_host_parents</code></p>
<dd>Only hosts which parent (usually ComputeResource) name is specified in comma-separated list in this option will be reported. Put the name into the double-quotes if it contains special characters (like comma).</p>
<dt><code>exclude_host_parents</code></p>
<dd>Hosts which parent (usually ComputeResource) name is specified in comma-separated list in this option will <code>NOT</code> be reported. Put the name into the double-quotes if it contains special characters (like comma).</p>
<dt><code>simplified_vim</code></p>
<dd>virt-who by default uses stripped-down version of vimService.wsdl file that contains vSphere SOAP API definition. Set this option to <code>false</code> to use server provided wsdl file that will be retrieved automatically. </p>
</dl>
<h3>Rhev-M Backend</h3>
<dl>
<dt><code>server</code></p>
<dd>The default port number is 8443 (that was used the default in RHEV-M &lt;= 3.0). Newer RHEV-M installations uses port 443 by default. Use correct value for your server in format: </p>
<p> server=&lt;HOSTNAME_OR_IP_ADDRESS&gt;:&lt;PORT_NUMBER&gt; </p>
</dl>
<h3>Fake Backend</h3>
<p>Fake backend reads host/guests associations from the file on disk, for example: </p>
<p> [fake-virt]<br />
 type=fake<br />
 file=/path/to/json<br />
 is_hypervisor=True </p>
<dl>
<dt><code>type</code></p>
<dd>Must be always <code>fake</code>. </p>
<dt><code>is_hypervisor</code></p>
<dd>If true (default), the option determines that the fake data are fetched from multihost environment. </p>
<dt><code>file</code></p>
<dd>Absolute path to the JSON file that has the same structure as file returned from <code>virt-who &#8211;print</code> command, for example:<br />
