<p><code>updmap.cfg</code> &#8211; configuration of font mapping/inclusion for dvips and friends.</p>
<h2>Description</h2>
<p>The file <code>updmap.cfg</code> is the central font configuration file of a teTeX system and is read by <code><a href="/docs/linux/man/1-updmap/">updmap</a></code>(1). It describes if and how fonts should be included (or not included) into PS-/PDF-files. This works for Outline (Postscript Type1) and Bitmap Fonts (Postscript Type3) mostly coming from MetaFont. <code>updmap</code> is a utility that creates font configuration files for <code><a href="/docs/linux/man/1-dvips/">dvips</a></code>(1), <code><a href="/docs/linux/man/1-pdftex/">pdftex</a></code>(1), <code><a href="/docs/linux/man/1-xdvi/">xdvi</a></code>(1), <code><a href="/docs/linux/man/1-ps2pk/">ps2pk</a></code>(1), <code><a href="/docs/linux/man/1-gsftopk/">gsftopk</a></code>(1), and <code><a href="/docs/linux/man/1-dvipdfmx/">dvipdfmx</a></code>(1). In an ideal world, updmap would be unnecessary &#8212; each of these programs would read the same configuration file to learn what fonts are available and how they should be treated. As things stand, however, each of these tools has subtly different requirements and thereby needs its own font configuration file. <code>updmap</code> creates font configuration files for all of these programs from several sources, namely all <code>updmap.cfg</code>, allowing you to easily keep all the different configuration files in sync. Running &quot;updmap &#8211;help&quot; will output the main documentation for using <code>updmap</code>. <code>dvipsPreferOutline</code><br />
 Configures if <code>dvips</code> (by default) should prefer bitmap fonts or outline fonts if both are available? Independent of this setting, outlines can be forced by putting &quot;p psfonts_t1.map&quot; into a config file that dvips reads. Bitmaps can be forced by putting &quot;p psfonts_pk.map&quot; into a config file. We provide such config files which can be enabled via <code>dvips</code> <i>-Poutline</i> (resp. <code>dvips</code> <i>-Ppk</i>).<br />
 Valid settings for dvipsPreferOutline are <i>true</i> / <i>false</i>. <code>LW35</code><br />
 Which fonts of the &quot;Basic 35 Laserwriter Fonts&quot; do you want to use and how are the filenames chosen? Valid settings:<br />
 URW: URW fonts with &quot;vendor&quot; filenames (e.g. n019064l.pfb)<br />
 URWkb: URW fonts with &quot;berry&quot; filenames (e.g. uhvbo8ac.pfb)<br />
 ADOBE: Adobe fonts with &quot;vendor&quot; filenames (e.g. hvnbo___.pfb)<br />
 ADOBEkb: Adobe fonts with &quot;berry&quot; filenames (e.g. phvbo8an.pfb) <code>dvipsDownloadBase35</code><br />
 Configures if <code>dvips</code> (by default) should download the 35 base PostScript fonts into the document (set <i>true</i>) or should these fonts be used from the ps interpreter / printer (set <i>false</i>).<br />
 The user can override the default by specifying <code>dvips</code> <i>-Pdownload35</i> (resp. <code>dvips</code> <i>-Pbuiltin35</i>) to download the LW35 fonts (resp. use the built-in fonts).<br />
 Valid settings are <i>true</i> / <i>false</i>. <code>pdftexDownloadBase14</code><br />
 Should <code>pdftex</code> download the 14 base PDF fonts? Since some configurations (ps / pdf tools / printers) use bad default fonts, it is safer to download the fonts. The pdf files get bigger, but that is the cost.<br />
 Valid settings are <i>true</i> (download the fonts) or <i>false</i> (don&#8217;t download the fonts). Adobe recommends embedding all fonts. <code>pxdviUse</code><br />
 Should special map files for pxdvi be created? pxdvi is an adaption of xdvi with support for reading and displaying files generated by the ptex family of engines.<br />
 Valid settings are <i>true</i> (generate configuration) or <i>false</i>. See <a rel="nofollow" href="http://www.tug.org/texlive/updmap-kanji.html">http://www.tug.org/texlive/updmap-kanji.html</a> for detailed discussion. <code>kanjiEmbed</code><br />
 <code>kanjiVariant</code><br />
 The options <code>kanjiEmbed</code> and <code>kanjiVariant</code> specify special replacements in the map lines. In a map, the string &quot;@kanjiEmbed@&quot; will be replaced by the value of that option; similarly for <code>kanjiVariant</code>. In this way, users of Japanese TeX can select different fonts to be included in the final output. <code>Map</code><br />
 Points to a map file, which describes a mapping from a font (called in the TeX document) to the pfb file containing the Postscript code.<br />
 Usage: <code>Map</code> filename.map The syntax of map files is the same as <code><a href="/docs/linux/man/1-dvips/">dvips</a></code>(1) uses, see the section &quot;psfonts.map&quot; in the manual of <code><a href="/docs/linux/man/1-dvips/">dvips</a></code>(1). <code>MixedMap</code><br />
 Similar to <code>Map</code>. It should be used when there is Type1 and a bitmap implementation of the font (the latter mostly coming from MetaFont). These entries will not be used in the default map of <code>dvips</code> if <code>dvipsPreferOutline</code> is set to <i>false</i>.<br />
 Usage: <code>MixedMap</code> filename.map <code>KanjiMap</code><br />
 Similar to <code>Map</code>. This should be used for kanji fonts.<br />
 Usage: <code>KanjiMap</code> filename.map The sign <code>#</code> precedes a comment. Map files not to be used should be commented out using the string <code>#!</code> at the beginning of the line. Such entries can be (de-)activated using <code>updmap</code> with the options <i>&#8211;enable</i> and <i>&#8211;disable</i>, respectively. </p>
