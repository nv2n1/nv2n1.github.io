<p>pmieconf &#8211; generalized pmie rules and customizations</p>
<h2>Description</h2>
<p>The pmieconf file formats are used by the <code><a href="/docs/linux/man/1-pmieconf/">pmieconf</a></code>(1) tool as a way to generalize <code><a href="/docs/linux/man/1-pmie/">pmie</a></code>(1) rule sets such that they can be easily configured for different systems and different environments. There are two completely different (although closely related) file formats discussed here, namely &#8220;pmieconf-rules&#8221; and &#8220;pmieconf-pmie&#8221;. </p>
<p> The directory <code>$PCP_VAR_DIR/config/pmieconf</code> contains information about all the default system <code>pmie</code> generalized rules and variables, including default values for all variables. These files are in the pmieconf-rules format. Although new pmieconf-rules files can be added, the files in this directory should never be changed. Instead, use the <code>pmieconf</code> utility to change variable values in the <code>pmie</code> configuration file. </p>
<p> The pmieconf-pmie format allows site specific customizations of the rules contained in pmieconf-rules files and their associated variables. The pmieconf-pmie format is generated by <code>pmieconf</code> and should not be edited by hand. This generated file is in the <code>pmie</code> format, with some additional information held at the head of the file &#8211; thus, the pmieconf-pmie format is a superset of the <code>pmie</code> file format (extended to hold customizations to the generalized rules, but also containing the actual performance rules for <code>pmie</code> to evaluate) which can also be parsed by <code>pmie</code> (all extensions are hidden within comments, and are thus meaningless to <code>pmie</code> itself). </p>
<p> The file <code>$PCP_VAR_DIR/config/pmieconf/config.pmie</code> contains local system settings for <code>pmieconf</code> configurable variables. The variable settings in this file replace the default values specified in <code>$PCP_VAR_DIR/config/pmieconf/*/*</code>.</p>
<h2>Pmieconf-Pmie Syntax</h2>
<p>All rule customization lines in a valid pmieconf-pmie specification are prefixed by &#8220;//&#8221; and are located at the head of the file &#8211; this allows files containing a pmieconf-pmie specification to be successfully parsed by <code>pmie</code>. A pmieconf-pmie must always have the first line in the form: </p>
<pre> // pmieconf-pmie <i>version</i> <i>pmieconf_path</i></pre>
<p>The <i>version</i> specifies which version of the pmieconf-pmie syntax should be used to parse this file. Currently the only supported version is 1. The <i>pmieconf_path</i> specifies the path to the pmieconf-rules files which were used, by <code>pmieconf</code>, to generate this file. This is discussed in the <code><a href="/docs/linux/man/1-pmieconf/">pmieconf</a></code>(1) man page (see the <code>-r</code> option). </p>
<p> The remainder of the specification consists of one line entries for each of the modified variables. The syntax for each line is: </p>
<pre> // <i>rule_version</i> <i>rule_name</i> <i>rule_variable</i> = <i>value</i></pre>
<p>The <i>rule_version</i> and <i>rule_name</i> are used to identify the rule with which to associate the customization. These are followed by the <i>rule_variable</i> name (i.e. the variable of rule <i>rule_name</i> which has been changed) for which the new <i>value</i> is to be used. </p>
<p> A pmieconf-pmie specification must be terminated with the &#8220;end&#8221; keyword. This is used by <code>pmieconf</code> to distinguish where the customizations ends, and the actual <code>pmie</code> rule component begins.</p>
<h2>Pmieconf-Pmie Example</h2>
<p>The following example is a valid pmieconf-pmie format file, as generated by <code>pmieconf</code>. In order to make changes by hand which are preserved by <code>pmieconf</code>, see the comments contained in the generated file (below) as to where such changes should be made. </p>
<pre> // pmieconf-pmie 1 $PCP_VAR_DIR/config/pmieconf
 // 1 memory.exhausted delta = &quot;4 minutes&quot;
 // 1 memory.exhausted enabled = yes
 // 1 memory.exhausted pcplog_action = yes
 // end
 //
 // --- START GENERATED SECTION (do not change this section) ---
 // generated by pmieconf on: [DATESTAMP]
 //
 // 1 memory.exhausted
 delta = 4 minutes;
 some_host (
 ( avg_sample (swap.pagesout @0..9 ) ) &gt; 0 &amp;&amp;
 30 %_sample swap.pagesout &gt;= 5
 ) -&gt; shell 10 min &quot;$PCP_BINADM_DIR/pmpost Severe demand for real memory&quot; \
 &quot; %vpgsout/s@%h&quot;;
 // --- END GENERATED SECTION (changes below will be preserved) ---</pre>
<p>To see how this all works, you can generate this file as follows: </p>
<pre> # cat - | pmieconf -f /tmp/pmieconf.out \
 -r $PCP_VAR_DIR/config/pmieconf/memory:$PCP_VAR_DIR/config/pmieconf/global
 modify memory.exhausted delta &quot;4 minutes&quot;
 modify memory.exhausted enabled yes
 modify memory.exhausted pcplog_action yes
 ^D
 # </pre>
<p>Then verify that the generated file is a valid <code>pmie</code> configuration file using: </p>
<pre> # pmie -C /tmp/pmieconf.out</pre>
<p>This parses the file, and then exits after reporting any syntax errors. Now replace -C with -v (above), and watch <code>pmie</code> do its work!</p>
<h2>Pmieconf-Rules Syntax</h2>
<p>A pmieconf-rules specification consists of a number of separate data objects which together form a complete rule specification (note that a specification may span multiple files and even multiple subdirectories). Each object must have an <i>identifier</i> string and a data <i>type</i>, followed by an (optional) list of <i>attribute</i>s. </p>
<p> The generic specification of a pmieconf-rules object is thus: </p>
<pre> <i>type</i> <i>identifier</i> [ <i>attribute</i> = <i>value</i> ]* ;</pre>
<p>The set of valid <i>type</i>s is: &quot;rule&quot; (rule definition), &quot;string&quot; (arbitrary, double-quote enclosed string), &quot;double&quot;, &quot;integer&quot;, &quot;unsigned&quot;, &quot;percent&quot; (real number between 0 and 100), &quot;hostlist&quot; (space separated list of host names), &quot;instlist&quot; (space separated list of metric instance names), and the four <code>pmie</code> action types, namely &quot;print&quot;, &quot;shell&quot;, &quot;alarm&quot;, and &quot;syslog&quot;. </p>
<p> Rule names use the &#8220;.&#8221; character to introduce the concept of a rule group, e.g. &quot;memory.exhausted&quot; associates this rule with the &quot;memory&quot; group. <code>pmieconf</code> can operate at either the level of rule groups or individual rules. The group name &quot;global&quot; is reserved and may not be used with any rule. </p>
<p> Usually when an object is created it is associated with the current rule. However, if an object&#8217;s name is preceded by the reserved group name &quot;global&quot;, then that object is visible to all rules. </p>
<p> The set of valid <i>attribute</i>s is: &quot;help&quot; (descriptive text about this object), &quot;modify&quot; (<i>value</i> is yes/no, flags whether <code>pmieconf</code> should allow changes), &quot;enabled&quot; (<i>value</i> is yes/no, flags whether this is on or off &#8211; only meaningful for rules and actions), &quot;display&quot; (yes/no &#8211; flags whether <code>pmieconf</code> should show this object), &quot;default&quot; (<i>value</i> determined by <i>type</i>, and is the default value for this object), and specific to objects of rule type are the &quot;version&quot;, &quot;predicate&quot;, and &quot;enumerate&quot; attributes. &quot;version&quot; and &quot;predicate&quot; are fairly self explanatory (&quot;predicate&quot; must equate to a valid <code>pmie</code> rule when expanded), but &quot;enumerate&quot; requires further discussion. </p>
<p> The &quot;enumerate&quot; clause is useful when you wish to generate multiple, similar <code>pmie</code> rules from a single predicate. This is most useful for rule definitions wishing to use the &quot;some_inst&quot; clause in the <code>pmie</code> language across multiple hosts. For a rule to use these together, it must be certain that the instance list is the same on all of the monitored hosts. This is rarely true, so the &quot;enumerate&quot; attribute allows us to generate multiple rules, expanded over variables of either type &quot;instlist&quot; or &quot;hostlist&quot;. These variables make up the value for the &quot;enumerate&quot; attribute &#8211; which is a space-separated list of &quot;instlist&quot; or &quot;hostlist&quot; variable names. </p>
<p> Objects can be incorporated into other object definitions using the $<i>identifier</i>$ syntax. See the example later for more insight into how this is useful. </p>
<p> When <code>pmieconf</code> is generating the <code>pmie</code> configuration file, it looks at each enabled rule with N enabled actions (where N &gt; 0) and expands the string: </p>
<pre> // &quot;version&quot; <i>identifier</i>
 delta = $delta$;
 &quot;predicate&quot; -&gt; $threshold$ $action1$ &amp; ... &amp; $actionN$ ;</pre>
<p>The delta, threshold, and action variables are defined globally (using the &quot;global&quot; keyword) for all rules, but can, of course, be changed at the level of an individual rule or rule group.</p>
<h2>Pmieconf-Rules Example</h2>
<p>The following is an example of a single pmieconf-rules specification, showing a number of different aspects of the language discussed above. The example defines a rule (&quot;memory.exhausted&quot;) and a string (&quot;rule&quot;). </p>
<pre> rule memory.exhausted
 default = &quot;$rule$&quot;
 predicate =
 &quot;some_host (
 ( avg_sample (swap.pagesout $hosts$ @0..9 ) ) &gt; 0 &amp;&amp;
 $pct$ %_sample swap.pagesout $hosts$ @0..9 &gt;= $threshold$
 )&quot;
 enabled = yes
 version = 1
 help =
 &quot;The system is swapping modified pages out of main memory to the
 swap partitions, and has been doing this on at least pct of the
 last 10 evaluations of this rule.
 There appears to be insufficient main memory to meet the resident
 demands of the current workload.&quot;;
 string rule
 default = &quot;Severe demand for real memory&quot;
 modify = no
 display = no;</pre>
<p>Note that for the above rule to be complete, &quot;threshold&quot; and &quot;pct&quot; would also need to be defined &#8211; for the full expression of this rule, refer to <i>$PCP_VAR_DIR/config/pmieconf/memory/exhausted</i>.</p>
