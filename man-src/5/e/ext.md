<p>ext &#8211; format of .ext files produced by Magic&#8217;s hierarchical extractor</p>
<h2>Description</h2>
<p>Magic&#8217;s extractor produces a <code>.ext</code> file for each cell in a hierarchical design. The <code>.ext</code> file for cell <i>name</i> is <i>name</i><code>.ext</code>. This file contains three kinds of information: environmental information (scaling, timestamps, etc), the extracted circuit corresponding to the mask geometry of cell <i>name</i>, and the connections between this mask geometry and the subcells of <i>name</i>. A <code>.ext</code> file consists of a series of lines, each of which begins with a keyword. The keyword beginning a line determines how the remainder of the line is interpreted. The following set of keywords define the environmental information:</p>
<dl>
<dt><code>tech&nbsp;<wbr></code><i>techname</i></p>
<dd>Identifies the technology of cell <i>name</i> as <i>techname</i>, e.g, <code>nmos</code>, <code>cmos</code>.</p>
<dt><code>timestamp&nbsp;<wbr></code><i>time</i></p>
<dd>Identifies the time when cell <i>name</i> was last modified. The value <i>time</i> is the time stored by Unix, i.e, seconds since 00:00 GMT January 1, 1970. Note that this is <i>not</i> the time <i>name</i> was extracted, but rather the timestamp value stored in the <code>.mag</code> file. The incremental extractor compares the timestamp in each <code>.ext</code> file with the timestamp in each <code>.mag</code> file in a design; if they differ, that cell is re-extracted.</p>
<dt><code>version&nbsp;<wbr></code><i>version</i></p>
<dd>Identifies the version of <code>.ext</code> format used to write <i>name</i><code>.ext</code>. The current version is <code>5.1</code>.</p>
<dt><code>style&nbsp;<wbr></code><i>style</i></p>
<dd>Identifies the style that the cell has been extracted with.</p>
<dt><code>scale&nbsp;<wbr></code><i>rscale cscale lscale</i></p>
<dd>Sets the scale to be used in interpreting resistance, capacitance, and linear dimension values in the remainder of the <code>.ext</code> file. Each resistance value must be multiplied by <i>rscale</i> to give the real resistance in milliohms. Each capacitance value must be multiplied by <i>cscale</i> to give the real capacitance in attofarads. Each linear dimension (e.g, width, height, transform coordinates) must be multiplied by <i>lscale</i> to give the real linear dimension in centimicrons. Also, each area dimension (e.g, transistor channel area) must be multiplied by <i>scale*scale</i> to give the real area in square centimicrons. At most one <code>scale</code> line may appear in a <code>.ext</code> file. If none appears, all of <i>rscale</i>, <i>cscale</i>, and <i>lscale</i> default to 1.</p>
<dt><code>resistclasses&nbsp;<wbr></code><i>r1 r2 &#8230;</i></p>
<dd>Sets the resistance per square for the various resistance classes appearing in the technology file. The values <i>r1</i>, <i>r2</i>, etc. are in milliohms; they are not scaled by the value of <i>rscale</i> specified in the <code>scale</code> line above. Each node in a <code>.ext</code> file has a perimeter and area for each resistance class; the values <i>r1</i>, <i>r2</i>, etc. are used to convert these perimeters and areas into actual node resistances. See &#8220;Magic Tutorial #8: Circuit Extraction&#8221; for a description of how resistances are computed from perimeters and areas by the program <code>ext2sim</code>.</dl>
<p> The following keywords define the circuit formed by the mask information in cell <i>name</i>. This circuit is extracted independently of any subcells; its connections to subcells are handled by the keywords in the section after this one.</p>
<dl>
<dt><code>node </code><i>name R C x y type a1 p1 a2 p2 &#8230; aN pN</i></p>
<dd>Defines an electrical node in <i>name</i>. This node is referred to by the name <i>name</i> in subsequent <code>equiv</code> lines, connections to the terminals of transistors in <code>fet</code> lines, and hierarchical connections or adjustments using <code>merge</code> or <code>adjust</code>. The node has a total capacitance to ground of <i>C</i> attofarads, and a lumped resistance of <i>R</i> milliohms. For purposes of going back from the node name to the geometry defining the node, <i>(x,y)</i> is the coordinate of a point inside the node, and <i>type</i> is the layer on which this point appears. The values <i>a1</i>, <i>p1</i>, &#8230; <i>aN</i>, <i>pN</i> are the area and perimeter for the material in each of the resistance classes described by the <code>resistclasses</code> line at the beginning of the <code>.ext</code> file; these values are used to compute adjusted hierarchical resistances more accurately. <code>NOTE:</code> since many analysis tools compute transistor gate capacitance themselves from the transistor&#8217;s area and perimeter, the capacitance between a node and substrate (GND!) normally does not include the capacitance from transistor gates connected to that node. If the <code>.sim</code> file was produced by <i><a href="/docs/linux/man/1-ext2sim/">ext2sim</a></i>(1), check the technology file that was used to produce the original <code>.ext</code> files to see whether transistor gate capacitance is included or excluded; see &#8220;Magic Maintainer&#8217;s Manual #2: The Technology File&#8221; for details.</p>
<dt><code>attr </code><i>name xl yl xh yh type text</i></p>
<dd>One of these lines appears for each label ending in the character &#8220;<code>@</code>&#8221; that was attached to geometry in the node <i>name</i>. The location of each attribute label (<i>xl yl xh yh</i>) and the type of material to which it was attached (<i>type</i>) are given along with the text of the label minus the trailing &#8220;<code>@</code>&#8221; character (<i>text</i>).</p>
<dt><code>equiv&nbsp;<wbr></code><i>node1 node2</i></p>
<dd>Defines two node names in cell <i>name</i> as being equivalent: <i>node1</i> and <i>node2</i>. In a collection of node names related by <code>equiv</code> lines, exactly one must be defined by a <code>node</code> line described above.</p>
<dt><code>fet&nbsp;<wbr></code><i>type xl yl xh yh area perim sub GATE T1 T2 &#8230;</i></p>
<dd>Defines a transistor in <i>name</i>. The kind of transistor is <i>type</i>, a string that comes from the technology file and is intended to have meaning to simulation programs. The coordinates of a square entirely contained in the gate region of the transistor are <i>(xl, yl)</i> for its lower-left and <i>(xh, yh)</i> for its upper-right. All four coordinates are in the <i>name</i>&#8216;s coordinate space, and are subject to scaling as described in <code>scale</code> above. The gate region of the transistor has area <i>area</i> square centimicrons and perimeter <i>perim</i> centimicrons. The substrate of the transistor is connected to node <i>sub</i>. The remainder of a <code>fet</code> line consists of a series of triples: <i>GATE</i>, <i>T1</i>, &#8230;. Each describes one of the terminals of the transistor; the first describes the gate, and the remainder describe the transistor&#8217;s non-gate terminals (e.g, source and drain). Each triple consists of the name of a node connecting to that terminal, a terminal length, and an attribute list. The terminal length is in centimicrons; it is the length of that segment of the channel perimeter connecting to adjacent material, such as polysilicon for the gate or diffusion for a source or drain. The attribute list is either the single token &#8220;0&#8221;, meaning no attributes, or a comma-separated list of strings. The strings in the attribute list come from labels attached to the transistor. Any label ending in the character &#8220;<code>^</code>&#8221; is considered a gate attribute and appears on the gate&#8217;s attribute list, minus the trailing &#8220;<code>^</code>&#8221;. Gate attributes may lie either along the border of a channel or in its interior. Any label ending in the character &#8220;<code>$</code>&#8221; is considered a non-gate attribute. It appears on the list of the terminal along which it lies, also minus the trailing &#8220;<code>$</code>&#8221;. Non-gate attributes may only lie on the border of the channel.</dl>
<p> The keywords in this section describe information that is not processed hierarchically: path lengths and accurate resistances that are computed by flattening an entire node and then producing a value for the flattened node.</p>
<dl>
<dt><code>killnode&nbsp;<wbr></code><i>node</i></p>
<dd>During resistance extraction, it is sometimes necessary to break a node up into several smaller nodes. The appearance of a <code>killnode</code> line during the processing of a <code>.ext</code> file means that all information currently accumulated about <i>node</i>, along with all fets that have a terminal connected to <i>node</i>, should be thrown out; it will be replaced by information later in the <code>.ext</code> file. The order of processing <code>.ext</code> files is important in order for this to work properly: children are processed before their parents, so a <code>killnode</code> in a parent overrides one in a child.</p>
<dt><code>resist&nbsp;<wbr></code><i>node1 node2 R</i></p>
<dd>Defines a resistor of <i>R</i> milliohms between the two nodes <i>node1</i> and <i>node2</i>. Both names are hierarchical.</p>
<dt><code>distance&nbsp;<wbr></code><i>name1 name2 dmin dmax</i></p>
<dd>Gives the distance between two electrical terminals <i>name1</i> (a driver) and <i>name2</i> (a receiver). Note that these are terminals and not nodes: the names (which are hierarchical label names) are used to specify two different locations on the same electrical node. The two distances, <i>dmin</i> and <i>dmax</i>, are the lengths (in lambda) of the shortest and longest acyclic paths between the driver and receiver.</dl>
<p> The keywords in this last section describe the subcells used by <i>name</i>, and how connections are made to and between them.</p>
<dl>
<dt><code>use&nbsp;<wbr></code><i>def use-id TRANSFORM</i></p>
<dd>Specifies that cell <i>def</i> with instance identifier <i>use-id</i> is a subcell of cell <i>name</i>. If cell <i>def</i> is arrayed, then <i>use-id</i> will be followed by two bracketed subscript ranges of the form: <code>[</code><i>lo</i><code>,</code><i>hi</i><code>,</code><i>sep</i><code>]</code>. The first range is for x, and the second for y. The subscripts for a given dimension are <i>lo</i> through <i>hi</i> inclusive, and the separation between adjacent array elements is <i>sep</i> centimicrons. <i>TRANSFORM</i> is a set of six integers that describe how coordinates in <i>def</i> are to be transformed to coordinates in the parent <i>name</i>. It is used by <i><a href="/docs/linux/man/1-ext2sim/">ext2sim</a></i>(1) in transforming transistor locations to coordinates in the root of a design. The six integers of <i>TRANSFORM</i> (<i>ta, tb, tc, td, te, tf</i>) are interpreted as components in the following transformation matrix, by which all coordinates in <i>def</i> are post-multiplied to get coordinates in <i>name</i>: </p>
<pre><i>ta</i> <i>td</i> 0
<i>tb</i> <i>te</i> 0
<i>tc</i> <i>tf</i> 1</pre>
<dt><code>merge&nbsp;<wbr></code><i>path1 path2 C a1 p1 a2 p2 &nbsp;<wbr>&#8230; aN pN</i></p>
<dd>Used to specify a connection between two subcells, or between a subcell and mask information of <i>name</i>. Both <i>path1</i> and <i>path2</i> are hierarchical node names. To refer to a node in cell <i>name</i> itself, its pathname is just its node name. To refer to a node in a subcell of <i>name</i>, its pathname consists of the <i>use-id</i> of the subcell (as it appeared in a <code>use</code> line above), followed by a slash&nbsp;<wbr>(<i>/</i>), followed by the node name in the subcell. For example, if <i>name</i> contains subcell <i>sub</i> with use identifier <i>sub-id</i>, and <i>sub</i> contains node <i>n</i>, the full pathname of node <i>n</i> relative to <i>name</i> will be <i>sub-id/n</i>.</dl>
<p> Connections between adjacent elements of an array are represented using a special syntax that takes advantage of the regularity of arrays. A use-id in a path may optionally be followed by a range of the form <code>[</code><i>lo</i><code>:</code><i>hi</i><code>]</code> (before the following slash). Such a use-id is interpreted as the elements <i>lo</i> through <i>hi</i> inclusive of a one-dimensional array. An element of a two-dimensional array may be subscripted with two such ranges: first the y range, then the x range. Whenever one <i>path</i> in a <code>merge</code> line contains such a subscript range, the other must contain one of comparable size. For example,<br />
 &nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr> <code>merge</code>&nbsp;<wbr>&nbsp;<wbr>sub-id[1:4,2:8]/a&nbsp;<wbr>&nbsp;<wbr>sub-id[2:5,1:7]/b is acceptable because the range 1:4 is the same size as 2:5, and the range 2:8 is the same size as 1:7. When a connection occurs between nodes in different cells, it may be that some resistance and capacitance has been recorded redundantly. For example, polysilicon in one cell may overlap polysilicon in another, so the capacitance to substrate will have been recorded twice. The values <i>C</i>, <i>a1</i>, <i>p1</i>, etc. in a <code>merge</code> line provide a way of compensating for such overlap. Each of <i>a1</i>, <i>p1</i>, etc. (usually negative) are added to the area and perimeter for material of each resistance class to give an adjusted area and perimeter for the aggregate node. The value <i>C</i> attofarads (also usually negative) is added to the sum of the capacitances (to substrate) of nodes <i>path1</i> and <i>path2</i> to give the capacitance of the aggregate node.</p>
<dl>
<dt><code>cap&nbsp;<wbr></code><i>node1 node2 C</i></p>
<dd>Defines a capacitor between the nodes <i>node1</i> and <i>node2</i>, with capacitance <i>C</i>. This construct is used to specify both internodal capacitance within a single cell and between cells. </p>
