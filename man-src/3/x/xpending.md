<p>XFlush, XSync, XEventsQueued, XPending &#8211; handle output buffer or event queue </p>
<h2>Syntax</h2>
<dl COMPACT>
<dd>int XFlush(Display *<i>display</i>);</p>
<dd>int XSync(Display *<i>display</i>, Bool <i>discard</i>);</p>
<dd>int XEventsQueued(Display *<i>display</i>, int <i>mode</i>);</p>
<dd>int XPending(Display *<i>display</i>);</dl>
<h2>Arguments</h2>
<dl COMPACT>
<dt><i>discard</i></p>
<dd>Specifies a Boolean value that indicates whether <code>XSync</code> discards all events on the event queue.</p>
<dt><i>display</i></p>
<dd>Specifies the connection to the X server.</p>
<dt><i>mode</i></p>
<dd>Specifies the mode. You can pass <code>QueuedAlready</code>, <code>QueuedAfterFlush</code>, or <code>QueuedAfterReading</code>.</dl>
<h2>Description</h2>
<p>The <code>XFlush</code> function flushes the output buffer. Most client applications need not use this function because the output buffer is automatically flushed as needed by calls to <code>XPending</code>, <code>XNextEvent</code>, and <code>XWindowEvent</code>. Events generated by the server may be enqueued into the library&#8217;s event queue. </p>
<p> The <code>XSync</code> function flushes the output buffer and then waits until all requests have been received and processed by the X server. Any errors generated must be handled by the error handler. For each protocol error received by Xlib, <code>XSync</code> calls the client application&#8217;s error handling routine (see section 11.8.2). Any events generated by the server are enqueued into the library&#8217;s event queue. </p>
<p> Finally, if you passed <code>False</code>, <code>XSync</code> does not discard the events in the queue. If you passed <code>True</code>, <code>XSync</code> discards all events in the queue, including those events that were on the queue before <code>XSync</code> was called. Client applications seldom need to call <code>XSync</code>. </p>
<p> If mode is <code>QueuedAlready</code>, <code>XEventsQueued</code> returns the number of events already in the event queue (and never performs a system call). If mode is <code>QueuedAfterFlush</code>, <code>XEventsQueued</code> returns the number of events already in the queue if the number is nonzero. If there are no events in the queue, <code>XEventsQueued</code> flushes the output buffer, attempts to read more events out of the application&#8217;s connection, and returns the number read. If mode is <code>QueuedAfterReading</code>, <code>XEventsQueued</code> returns the number of events already in the queue if the number is nonzero. If there are no events in the queue, <code>XEventsQueued</code> attempts to read more events out of the application&#8217;s connection without flushing the output buffer and returns the number read. </p>
<p> <code>XEventsQueued</code> always returns immediately without I/O if there are events already in the queue. <code>XEventsQueued</code> with mode <code>QueuedAfterFlush</code> is identical in behavior to <code>XPending</code>. <code>XEventsQueued</code> with mode <code>QueuedAlready</code> is identical to the <code>XQLength</code> function. </p>
<p> The <code>XPending</code> function returns the number of events that have been received from the X server but have not been removed from the event queue. <code>XPending</code> is identical to <code>XEventsQueued</code> with the mode <code>QueuedAfterFlush</code> specified.</p>
