<p><code>XmOutline</code> &#8212; The Outline widget class</p>
<h2>Synopsis</h2>
<pre>#include &lt;Xm/Outline.h&gt;</pre>
<h2>Description</h2>
<p>The Outline widget is a container that shows the relationship of its children in a graphical tree-like format. Each child of the Outline widget is a node in the Outline. The parent-child relationships between these nodes are completely distinct from the widget hierarchy. The hierarchy of nodes is created by specifying the tree &quot;parent&quot; of each node as a constraint resource. If a node&#8217;s parent is NULL then it is assumed to be a root of the tree. Although each widget can only have one parent, the Outline widget supports adding more than one &quot;root&quot; node to a single Outline. </p>
<p> Note: The Outline widget assumes that it will be totally responsible for mapping and unmapping its children. Therefore no child of this widget should ever modify its mappedWhenManaged resource. If a child does modify this resource the behavior is undefined. </p>
<h3>User Interaction</h3>
<p>Each node in the outline can have one of four states: open, closed, always open, and hidden. The state of a node changes how it appears to the user and what actions are available to the user. </p>
<dl COMPACT>
<dd>Open<tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>This node will have an open folder shown to its left that<br />
 may be selected by the user to close this node. When a node is open all of its children will be visible to the user. </p>
<dd>Closed<tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>This node will have a closed folder shown to its left that<br />
 may be selected by the user to open this node. When a node is closed none of its children will be visible to the user. </p>
<dd>Always Open<tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>This node will have no folder button associated with it.<br />
 All of its children will be visible to the user. </p>
<dd>Hidden<tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr></tt>This node will not be shown to the user and all of its<br />
 children will appear and act exactly as if they were children of this node&#8217;s parent. It will appear to the user as if this node does not exist.</dl>
<p> To maintain consistency of the user interface we have found that it is best to use the node state &quot;Always Open&quot; for nodes with no children. This way the user will only see a folder button next to a node that has children to display. A folder button associated with a node that has no children has no defined semantics.</p>
<h3>Classes</h3>
<p>Outline inherits behavior and resources from the <code>Core</code>, <code>Composite</code>, <code>Constraint</code>, <code>XmManager</code>, and <code>XmHierarchy</code> classes. </p>
<p> The class pointer is <code>xmOutlineWidgetClass</code>. </p>
<p> The class name is <code>XmOutline</code>.</p>
<h3>New Resources</h3>
<p>The following table defines a set of widget resources used by the programmer to specify data. The programmer can also set the resource values for the inherited classes to set attributes for this widget. To reference a resource by name or by class in a <code>.Xdefaults</code> file, remove the <code>XmN</code> or <code>XmC</code> prefix and use the remaining letters. To specify one of the defined values for a resource in a <code>.Xdefaults</code> file, remove the <code>Xm</code> prefix and use the remaining letters (in either lowercase or uppercase, but include any underscores between words). The codes in the access column indicate if the given resource can be set at creation time (C), set by using <code>XtSetValues</code> (S), retrieved by using <code>XtGetValues</code> (G), or is not applicable (N/A). </p>

<h3>Geometry Management</h3>
<p>The preferred size of the entire outline will be just large enough to contain all nodes in the hierarchy. As the node state changes the outline will attempt to resize itself to just contain its currently visible children. If the outline is forced away from its desired size the children will not be moved and will either be clipped, or appear in the upper left hand corner of the window. For this reason it is usually desirable to put the outline into a Scrolled Window widget. </p>
