<p><code>XmDialogShell</code> &#8212; The DialogShell widget class</p>
<h2>Synopsis</h2>
<pre>#include &lt;Xm/DialogS.h&gt;</pre>
<h2>Description</h2>
<p>Modal and modeless dialogs use DialogShell as the Shell parent. DialogShell widgets cannot be iconified. Instead, all secondary DialogShell widgets associated with an ApplicationShell widget are iconified and de-iconified as a group with the primary widget. </p>
<p> The client indirectly manipulates DialogShell through the convenience interfaces during creation, and it can directly manipulate its BulletinBoard-derived child. Much of the functionality of DialogShell assumes that its child is a BulletinBoard subclass, although it can potentially stand alone. </p>
<p> Setting <code>XmNheight</code>, <code>XmNwidth</code>, or <code>XmNborderWidth</code> for either a DialogShell or its managed child usually sets that resource to the same value in both the parent and the child. When an off-the-spot input method exists, the height and width of the shell may be greater than those of the managed child in order to accommodate the input method. In this case, setting <code>XmNheight</code> or <code>XmNwidth</code> for the shell does not necessarily set that resource to the same value in the managed child, and setting <code>XmNheight</code> or <code>XmNwidth</code> for the child does not necessarily set that resource to the same value in the shell. </p>
<p> For the managed child of a DialogShell, regardless of the value of the shell&#8217;s <code>XmNallowShellResize</code> resource, setting <code>XmNx</code> or <code>XmNy</code> sets the corresponding resource of the parent but does not change the child&#8217;s position relative to the parent. The <code>XtGetValues</code> resource for the child&#8217;s <code>XmNx</code> or <code>XmNy</code> yields the value of the corresponding resource in the parent. The x and y-coordinates of the child&#8217;s upper left outside corner relative to the parent&#8217;s upper left inside corner are both 0 (zero) minus the value of <code>XmNborderWidth</code>. </p>
<p> Note that the <i>Inter-Client Communication Conventions Manual</i> (ICCCM) allows a window manager to change or control the border width of a reparented top-level window. </p>
<p> DialogShell uses the <code>XmQTdialogShellSavvy</code> trait.</p>
<h3>Classes</h3>
<p>DialogShell inherits behavior, resources, and traits from the <code>Core</code>, <code>Composite</code>, <code>Shell</code>, <code>WMShell</code>, <code>VendorShell</code>, and <code>TransientShell</code> classes. </p>
<p> The class pointer is <code>xmDialogShellWidgetClass</code>. </p>
<p> The class name is <code>XmDialogShell</code>.</p>
<h3>New Resources</h3>
<p>DialogShell defines no new resources but overrides the <code>XmNdeleteResponse</code> resource in the <code>VendorShell</code> class.</p>
<h3>Inherited Resources</h3>
<p>DialogShell inherits behavior and resources from the superclasses described in the following tables, which define sets of widget resources used by the programmer to specify data. </p>
<p> For a complete description of each resource, refer to the reference page for that superclass. The programmer can also set the resource values for the inherited classes to set attributes for this widget. To reference a resource by name or by class in a <code>.Xdefaults</code> file, remove the <code>XmN</code> or <code>XmC</code> prefix and use the remaining letters. To specify one of the defined values for a resource in a <code>.Xdefaults</code> file, remove the <code>Xm</code> prefix and use the remaining letters (in either lowercase or uppercase, but include any underscores between words). The codes in the access column indicate if the given resource can be set at creation time (C), set by using <code>XtSetValues</code> (S), retrieved by using <code>XtGetValues</code> (G), or is not applicable (N/A). </p>
