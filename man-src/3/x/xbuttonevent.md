<p> When you receive these events, their structure members are set as follows. </p>
<p> The type member is set to the event type constant name that uniquely identifies it. For example, when the X server reports a <code>GraphicsExpose</code> event to a client application, it sends an <code>XGraphicsExposeEvent</code> structure with the type member set to <code>GraphicsExpose</code>. The display member is set to a pointer to the display the event was read on. The send_event member is set to <code>True</code> if the event came from a <code>SendEvent</code> protocol request. The serial member is set from the serial number reported in the protocol but expanded from the 16-bit least-significant bits to a full 32-bit value. The window member is set to the window that is most useful to toolkit dispatchers. </p>
<p> These structures have the following common members: window, root, subwindow, time, x, y, x_root, y_root, state, and same_screen. The window member is set to the window on which the event was generated and is referred to as the event window. As long as the conditions previously discussed are met, this is the window used by the X server to report the event. The root member is set to the source window&#8217;s root window. The x_root and y_root members are set to the pointer&#8217;s coordinates relative to the root window&#8217;s origin at the time of the event. </p>
<p> The same_screen member is set to indicate whether the event window is on the same screen as the root window and can be either <code>True</code> or <code>False</code>. If <code>True</code>, the event and root windows are on the same screen. If <code>False</code>, the event and root windows are not on the same screen. </p>
<p> If the source window is an inferior of the event window, the subwindow member of the structure is set to the child of the event window that is the source window or the child of the event window that is an ancestor of the source window. Otherwise, the X server sets the subwindow member to <code>None</code>. The time member is set to the time when the event was generated and is expressed in milliseconds. </p>
<p> If the event window is on the same screen as the root window, the x and y members are set to the coordinates relative to the event window&#8217;s origin. Otherwise, these members are set to zero. </p>
<p> The state member is set to indicate the logical state of the pointer buttons and modifier keys just prior to the event, which is the bitwise inclusive OR of one or more of the button or modifier key masks: <code>Button1Mask</code>, <code>Button2Mask</code>, <code>Button3Mask</code>, <code>Button4Mask</code>, <code>Button5Mask</code>, <code>ShiftMask</code>, <code>LockMask</code>, <code>ControlMask</code>, <code>Mod1Mask</code>, <code>Mod2Mask</code>, <code>Mod3Mask</code>, <code>Mod4Mask</code>, and <code>Mod5Mask</code>. </p>
<p> Each of these structures also has a member that indicates the detail. For the <code>XKeyPressedEvent</code> and <code>XKeyReleasedEvent</code> structures, this member is called a keycode. It is set to a number that represents a physical key on the keyboard. The keycode is an arbitrary representation for any key on the keyboard (see sections 12.7 and 16.1). </p>
<p> For the <code>XButtonPressedEvent</code> and <code>XButtonReleasedEvent</code> structures, this member is called button. It represents the pointer button that changed state and can be the <code>Button1</code>, <code>Button2</code>, <code>Button3</code>, <code>Button4</code>, or <code>Button5</code> value. For the <code>XPointerMovedEvent</code> structure, this member is called is_hint. It can be set to <code>NotifyNormal</code> or <code>NotifyHint</code>.</p>
