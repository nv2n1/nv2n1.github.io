<h2 class="name">NAME</h2>
<p> a64l, l64a &#8211; convert between long and base-64 </p>
<h2>SYNOPSIS</h2>

<h2>DESCRIPTION</h2>
<p> These functions provide a conversion between 32-bit long integers and little-endian base-64 ASCII strings (of length zero to six). If the string used as argument for <code>a64l</code>() has length greater than six, only the first six bytes are used. If the type <i>long</i> has more than 32 bits, then <code>l64a</code>() uses only the low order 32 bits of <i>value</i>, and <code>a64l</code>() sign-extends its 32-bit result. </p>
<p> The 64 digits in the base-64 system are: </p>
<dl>
<dt>
<dd>
<pre>
'.'     represents a 0
'/'     represents a 1
0-9     represent  2-11
A-Z     represent 12-37
a-z     represent 38-63
</pre>
</dl>
<p> So 123 = 59*64ha0 + 1*64ha1 = &quot;v/&quot;.</p>

<h2>CONFORMING TO</h2>
<p> POSIX.1-2001, POSIX.1-2008.</p>
<h2>NOTES</h2>
<p> The value returned by <code>l64a</code>() may be a pointer to a static buffer, possibly overwritten by later calls. </p>
<p> The behavior of <code>l64a</code>() is undefined when <i>value</i> is negative. If <i>value</i> is zero, it returns an empty string. </p>
<p> These functions are broken in glibc before 2.2.5 (puts most significant digit first). </p>
<p> This is not the encoding used by <code><a href="/docs/linux/man/1-uuencode/">uuencode</a></code>(1).</p>
