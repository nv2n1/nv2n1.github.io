<h2>Description</h2>
<p>The <i>libnuma</i> library offers a simple programming interface to the NUMA (Non Uniform Memory Access) policy supported by the Linux kernel. On a NUMA architecture some memory areas have different latency or bandwidth than others. Available policies are page interleaving (i.e., allocate in a round-robin fashion from all, or a subset, of the nodes on the system), preferred node allocation (i.e., preferably allocate on a particular node), local allocation (i.e., allocate on the node on which the task is currently executing), or allocation only on specific nodes (i.e., allocate on some subset of the available nodes). It is also possible to bind tasks to specific nodes. Numa memory allocation policy may be specified as a per-task attribute, that is inherited by children tasks and processes, or as an attribute of a range of process virtual address space. Numa memory policies specified for a range of virtual address space are shared by all tasks in the process. Furthermore, memory policies specified for a range of a shared memory attached using <i><a href="/docs/linux/man/2-shmat/">shmat</a>(2)</i> or <i><a href="/docs/linux/man/2-mmap/">mmap</a>(2)</i> from shmfs/hugetlbfs are shared by all processes that attach to that region. Memory policies for shared disk backed file mappings are currently ignored. The default memory allocation policy for tasks and all memory range is local allocation. This assumes that no ancestor has installed a non-default policy. For setting a specific policy globally for all memory allocations in a process and its children it is easiest to start it with the <code><a href="/docs/linux/man/8-numactl/">numactl</a></code>(8) utility. For more finegrained policy inside an application this library can be used. All numa memory allocation policy only takes effect when a page is actually faulted into the address space of a process by accessing it. The <code>numa_alloc_*</code> functions take care of this automatically. A <i>node</i> is defined as an area where all memory has the same speed as seen from a particular CPU. A node can contain multiple CPUs. Caches are ignored for this definition. Most functions in this library are only concerned about numa nodes and their memory. The exceptions to this are: <i>numa_node_to_cpus</i>(), <i>numa_node_of_cpu</i>(), <i>numa_bind</i>(), <i>numa_run_on_node</i>(), <i>numa_run_on_node_mask</i>(), <i>numa_run_on_node_mask_all</i>(), and <i>numa_get_run_node_mask</i>(). These functions deal with the CPUs associated with numa nodes. See the descriptions below for more information. Some of these functions accept or return a pointer to struct bitmask. A struct bitmask controls a bit map of arbitrary length containing a bit representation of nodes. The predefined variable <i>numa_all_nodes_ptr</i> points to a bit mask that has all available nodes set; <i>numa_no_nodes_ptr</i> points to the empty set. Before any other calls in this library can be used <code>numa_available</code>() must be called. If it returns -1, all other functions in this library are undefined. <code>numa_max_possible_node()</code> returns the number of the highest possible node in a system. In other words, the size of a kernel type nodemask_t (in bits) minus 1. This number can be gotten by calling <code>numa_num_possible_nodes()</code> and subtracting 1. <code>numa_num_possible_nodes()</code> returns the size of kernel&#8217;s node mask (kernel type nodemask_t). In other words, large enough to represent the maximum number of nodes that the kernel can handle. This will match the kernel&#8217;s MAX_NUMNODES value. This count is derived from /proc/self/status, field Mems_allowed. <code>numa_max_node</code>() returns the highest node number available on the current system. (See the node numbers in /sys/devices/system/node/ ). Also see <code>numa_num_configured_nodes().</code> <code>numa_num_configured_nodes()</code> returns the number of memory nodes in the system. This count includes any nodes that are currently disabled. This count is derived from the node numbers in /sys/devices/system/node. (Depends on the kernel being configured with /sys (CONFIG_SYSFS)). <code>numa_get_mems_allowed()</code> returns the mask of nodes from which the process is allowed to allocate memory in it&#8217;s current cpuset context. Any nodes that are not included in the returned bitmask will be ignored in any of the following libnuma memory policy calls. <code>numa_num_configured_cpus()</code> returns the number of cpus in the system. This count includes any cpus that are currently disabled. This count is derived from the cpu numbers in /sys/devices/system/cpu. If the kernel is configured without /sys (CONFIG_SYSFS=n) then it falls back to using the number of online cpus. <code>numa_all_nodes_ptr</code> points to a bitmask that is allocated by the library with bits representing all nodes on which the calling task may allocate memory. This set may be up to all nodes on the system, or up to the nodes in the current cpuset. The bitmask is allocated by a call to <code>numa_allocate_nodemask()</code> using size <code>numa_max_possible_node().</code> The set of nodes to record is derived from /proc/self/status, field &quot;Mems_allowed&quot;. The user should not alter this bitmask. <code>numa_no_nodes_ptr</code> points to a bitmask that is allocated by the library and left all zeroes. The bitmask is allocated by a call to <code>numa_allocate_nodemask()</code> using size <code>numa_max_possible_node().</code> The user should not alter this bitmask. <code>numa_all_cpus_ptr</code> points to a bitmask that is allocated by the library with bits representing all cpus on which the calling task may execute. This set may be up to all cpus on the system, or up to the cpus in the current cpuset. The bitmask is allocated by a call to <code>numa_allocate_cpumask()</code> using size <code>numa_num_possible_cpus().</code> The set of cpus to record is derived from /proc/self/status, field &quot;Cpus_allowed&quot;. The user should not alter this bitmask. <code>numa_num_task_cpus()</code> returns the number of cpus that the calling task is allowed to use. This count is derived from the map /proc/self/status, field &quot;Cpus_allowed&quot;. Also see the bitmask <code>numa_all_cpus_ptr.</code> <code>numa_num_task_nodes()</code> returns the number of nodes on which the calling task is allowed to allocate memory. This count is derived from the map /proc/self/status, field &quot;Mems_allowed&quot;. Also see the bitmask <code>numa_all_nodes_ptr.</code> <code>numa_parse_bitmap()</code> parses <i>line</i> , which is a character string such as found in /sys/devices/system/node/nodeN/cpumap into a bitmask structure. The string contains the hexadecimal representation of a bit map. The bitmask may be allocated with <code>numa_allocate_cpumask().</code> Returns 0 on success. Returns -1 on failure. This function is probably of little use to a user application, but it is used by <i>libnuma</i> internally. <code>numa_parse_nodestring()</code> parses a character string list of nodes into a bit mask. The bit mask is allocated by <code>numa_allocate_nodemask().</code> The string is a comma-separated list of node numbers or node ranges. A leading ! can be used to indicate &quot;not&quot; this list (in other words, all nodes except this list), and a leading + can be used to indicate that the node numbers in the list are relative to the task&#8217;s cpuset. The string can be &quot;all&quot; to specify all ( <code>numa_num_task_nodes()</code> ) nodes. Node numbers are limited by the number in the system. See <code>numa_max_node()</code> and <code>numa_num_configured_nodes().</code><br />
 Examples: 1-5,7,10 !4-5 +0-3<br />
 If the string is of 0 length, bitmask <code>numa_no_nodes_ptr</code> is returned. Returns 0 if the string is invalid. <code>numa_parse_nodestring_all()</code> is similar to <code>numa_parse_nodestring</code> , but can parse all possible nodes, not only current nodeset. <code>numa_parse_cpustring()</code> parses a character string list of cpus into a bit mask. The bit mask is allocated by <code>numa_allocate_cpumask().</code> The string is a comma-separated list of cpu numbers or cpu ranges. A leading ! can be used to indicate &quot;not&quot; this list (in other words, all cpus except this list), and a leading + can be used to indicate that the cpu numbers in the list are relative to the task&#8217;s cpuset. The string can be &quot;all&quot; to specify all ( <code>numa_num_task_cpus()</code> ) cpus. Cpu numbers are limited by the number in the system. See <code>numa_num_task_cpus()</code> and <code>numa_num_configured_cpus().</code><br />
 Examples: 1-5,7,10 !4-5 +0-3<br />
 Returns 0 if the string is invalid. <code>numa_parse_cpustring_all()</code> is similar to <code>numa_parse_cpustring</code> , but can parse all possible cpus, not only current cpuset. <code>numa_node_size</code>() returns the memory size of a node. If the argument <i>freep</i> is not NULL, it used to return the amount of free memory on the node. On error it returns -1. <code>numa_node_size64</code>() works the same as <code>numa_node_size</code>() except that it returns values as <i>long long</i> instead of <i>long</i>. This is useful on 32-bit architectures with large nodes. <code>numa_preferred</code>() returns the preferred node of the current task. This is the node on which the kernel preferably allocates memory, unless some other policy overrides this. <code>numa_set_preferred</code>() sets the preferred node for the current task to <i>node</i>. The system will attempt to allocate memory from the preferred node, but will fall back to other nodes if no memory is available on the the preferred node. Passing a <i>node</i> of -1 argument specifies local allocation and is equivalent to calling <code>numa_set_localalloc</code>(). <code>numa_get_interleave_mask</code>() returns the current interleave mask if the task&#8217;s memory allocation policy is page interleaved. Otherwise, this function returns an empty mask. <code>numa_set_interleave_mask</code>() sets the memory interleave mask for the current task to <i>nodemask</i>. All new memory allocations are page interleaved over all nodes in the interleave mask. Interleaving can be turned off again by passing an empty mask (<i>numa_no_nodes</i>). The page interleaving only occurs on the actual page fault that puts a new page into the current address space. It is also only a hint: the kernel will fall back to other nodes if no memory is available on the interleave target. <code>numa_interleave_memory</code>() interleaves <i>size</i> bytes of memory page by page from <i>start</i> on nodes specified in <i>nodemask</i>. The <i>size</i> argument will be rounded up to a multiple of the system page size. If <i>nodemask</i> contains nodes that are externally denied to this process, this call will fail. This is a lower level function to interleave allocated but not yet faulted in memory. Not yet faulted in means the memory is allocated using <code><a href="/docs/linux/man/2-mmap/">mmap</a></code>(2) or <code><a href="/docs/linux/man/2-shmat/">shmat</a></code>(2), but has not been accessed by the current process yet. The memory is page interleaved to all nodes specified in <i>nodemask</i>. Normally <code>numa_alloc_interleaved</code>() should be used for private memory instead, but this function is useful to handle shared memory areas. To be useful the memory area should be several megabytes at least (or tens of megabytes of hugetlbfs mappings) If the <code>numa_set_strict</code>() flag is true then the operation will cause a numa_error if there were already pages in the mapping that do not follow the policy. <code>numa_bind</code>() binds the current task and its children to the nodes specified in <i>nodemask</i>. They will only run on the CPUs of the specified nodes and only be able to allocate memory from them. This function is equivalent to calling <i>numa_run_on_node_mask(nodemask)</i> followed by <i>numa_set_membind(nodemask)</i>. If tasks should be bound to individual CPUs inside nodes consider using <i>numa_node_to_cpus</i> and the <i><a href="/docs/linux/man/2-sched_setaffinity/">sched_setaffinity</a>(2)</i> syscall. <code>numa_set_localalloc</code>() sets the memory allocation policy for the calling task to local allocation. In this mode, the preferred node for memory allocation is effectively the node where the task is executing at the time of a page allocation. <code>numa_set_membind</code>() sets the memory allocation mask. The task will only allocate memory from the nodes set in <i>nodemask</i>. Passing an empty <i>nodemask</i> or a <i>nodemask</i> that contains nodes other than those in the mask returned by <i>numa_get_mems_allowed</i>() will result in an error. <code>numa_get_membind</code>() returns the mask of nodes from which memory can currently be allocated. If the returned mask is equal to <i>numa_all_nodes</i>, then memory allocation is allowed from all nodes. <code>numa_alloc_onnode</code>() allocates memory on a specific node. The <i>size</i> argument will be rounded up to a multiple of the system page size. if the specified <i>node</i> is externally denied to this process, this call will fail. This function is relatively slow compared to the <i><a href="/docs/linux/man/3-malloc/">malloc</a></i>(3), family of functions. The memory must be freed with <code>numa_free</code>(). On errors NULL is returned. <code>numa_alloc_local</code>() allocates <i>size</i> bytes of memory on the local node. The <i>size</i> argument will be rounded up to a multiple of the system page size. This function is relatively slow compared to the <i><a href="/docs/linux/man/3-malloc/">malloc</a></i>(3) family of functions. The memory must be freed with <code>numa_free</code>(). On errors NULL is returned. <code>numa_alloc_interleaved</code>() allocates <i>size</i> bytes of memory page interleaved on all nodes. This function is relatively slow and should only be used for large areas consisting of multiple pages. The interleaving works at page level and will only show an effect when the area is large. The allocated memory must be freed with <code>numa_free</code>(). On error, NULL is returned. <code>numa_alloc_interleaved_subset</code>() attempts to allocate <i>size</i> bytes of memory page interleaved on all nodes. The <i>size</i> argument will be rounded up to a multiple of the system page size. The nodes on which a process is allowed to allocate memory may be constrained externally. If this is the case, this function may fail. This function is relatively slow compare to <i><a href="/docs/linux/man/3-malloc/">malloc</a></i>(3), family of functions and should only be used for large areas consisting of multiple pages. The interleaving works at page level and will only show an effect when the area is large. The allocated memory must be freed with <code>numa_free</code>(). On error, NULL is returned. <code>numa_alloc</code>() allocates <i>size</i> bytes of memory with the current NUMA policy. The <i>size</i> argument will be rounded up to a multiple of the system page size. This function is relatively slow compare to the <i><a href="/docs/linux/man/3-malloc/">malloc</a></i>(3) family of functions. The memory must be freed with <code>numa_free</code>(). On errors NULL is returned. <code>numa_realloc</code>() changes the size of the memory area pointed to by <i>old_addr</i> from <i>old_size</i> to <i>new_size.</i> The memory area pointed to by <i>old_addr</i> must have been allocated with one of the <code>numa_alloc*</code> functions. The <i>new_size</i> will be rounded up to a multiple of the system page size. The contents of the memory area will be unchanged to the minimum of the old and new sizes; newly allocated memory will be uninitialized. The memory policy (and node bindings) associated with the original memory area will be preserved in the resized area. For example, if the initial area was allocated with a call to <code>numa_alloc_onnode(),</code> then the new pages (if the area is enlarged) will be allocated on the same node. However, if no memory policy was set for the original area, then <code>numa_realloc</code>() cannot guarantee that the new pages will be allocated on the same node. On success, the address of the resized area is returned (which might be different from that of the initial area), otherwise NULL is returned and <i>errno</i> is set to indicate the error. The pointer returned by <code>numa_realloc</code>() is suitable for passing to <code>numa_free</code>(). <code>numa_free</code>() frees <i>size</i> bytes of memory starting at <i>start</i>, allocated by the <code>numa_alloc_*</code> functions above. The <i>size</i> argument will be rounded up to a multiple of the system page size. <code>numa_run_on_node</code>() runs the current task and its children on a specific node. They will not migrate to CPUs of other nodes until the node affinity is reset with a new call to <code>numa_run_on_node_mask</code>(). Passing -1 permits the kernel to schedule on all nodes again. On success, 0 is returned; on error -1 is returned, and <i>errno</i> is set to indicate the error. <code>numa_run_on_node_mask</code>() runs the current task and its children only on nodes specified in <i>nodemask</i>. They will not migrate to CPUs of other nodes until the node affinity is reset with a new call to <code>numa_run_on_node_mask</code>() or <code>numa_run_on_node</code>(). Passing <i>numa_all_nodes</i> permits the kernel to schedule on all nodes again. On success, 0 is returned; on error -1 is returned, and <i>errno</i> is set to indicate the error. <code>numa_run_on_node_mask_all</code>() runs the current task and its children only on nodes specified in <i>nodemask</i> like <i>numa_run_on_node_mask</i> but without any cpuset awareness. <code>numa_get_run_node_mask</code>() returns a mask of CPUs on which the current task is allowed to run. <code>numa_tonode_memory</code>() put memory on a specific node. The constraints described for <code>numa_interleave_memory</code>() apply here too. <code>numa_tonodemask_memory</code>() put memory on a specific set of nodes. The constraints described for <code>numa_interleave_memory</code>() apply here too. <code>numa_setlocal_memory</code>() locates memory on the current node. The constraints described for <code>numa_interleave_memory</code>() apply here too. <code>numa_police_memory</code>() locates memory with the current NUMA policy. The constraints described for <code>numa_interleave_memory</code>() apply here too. <code>numa_distance</code>() reports the distance in the machine topology between two nodes. The factors are a multiple of 10. It returns 0 when the distance cannot be determined. A node has distance 10 to itself. Reporting the distance requires a Linux kernel version of <i>2.6.10</i> or newer. <code>numa_set_bind_policy</code>() specifies whether calls that bind memory to a specific node should use the preferred policy or a strict policy. The preferred policy allows the kernel to allocate memory on other nodes when there isn&#8217;t enough free on the target node. strict will fail the allocation in that case. Setting the argument to specifies strict, 0 preferred. Note that specifying more than one node non strict may only use the first node in some kernel versions. <code>numa_set_strict</code>() sets a flag that says whether the functions allocating on specific nodes should use use a strict policy. Strict means the allocation will fail if the memory cannot be allocated on the target node. Default operation is to fall back to other nodes. This doesn&#8217;t apply to interleave and default. <code>numa_get_interleave_node()</code> is used by <i>libnuma</i> internally. It is probably not useful for user applications. It uses the MPOL_F_NODE flag of the get_mempolicy system call, which is not intended for application use (its operation may change or be removed altogether in future kernel versions). See <a href="/docs/linux/man/2-get_mempolicy/">get_mempolicy</a>(2). <code>numa_pagesize()</code> returns the number of bytes in page. This function is simply a fast alternative to repeated calls to the getpagesize system call. See <a href="/docs/linux/man/2-getpagesize/">getpagesize</a>(2). <code>numa_sched_getaffinity()</code> retrieves a bitmask of the cpus on which a task may run. The task is specified by <i>pid.</i> Returns the return value of the sched_getaffinity system call. See <a href="/docs/linux/man/2-sched_getaffinity/">sched_getaffinity</a>(2). The bitmask must be at least the size of the kernel&#8217;s cpu mask structure. Use <code>numa_allocate_cpumask()</code> to allocate it. Test the bits in the mask by calling <code>numa_bitmask_isbitset().</code> <code>numa_sched_setaffinity()</code> sets a task&#8217;s allowed cpu&#8217;s to those cpu&#8217;s specified in <i>mask.</i> The task is specified by <i>pid.</i> Returns the return value of the sched_setaffinity system call. See <a href="/docs/linux/man/2-sched_setaffinity/">sched_setaffinity</a>(2). You may allocate the bitmask with <code>numa_allocate_cpumask().</code> Or the bitmask may be smaller than the kernel&#8217;s cpu mask structure. For example, call <code>numa_bitmask_alloc()</code> using a maximum number of cpus from <code>numa_num_configured_cpus().</code> Set the bits in the mask by calling <code>numa_bitmask_setbit().</code> <code>numa_node_to_cpus</code>() converts a node number to a bitmask of CPUs. The user must pass a bitmask structure with a mask buffer long enough to represent all possible cpu&#8217;s. Use numa_allocate_cpumask() to create it. If the bitmask is not long enough <i>errno</i> will be set to <i>ERANGE</i> and -1 returned. On success 0 is returned. <code>numa_node_of_cpu</code>() returns the node that a cpu belongs to. If the user supplies an invalid cpu <i>errno</i> will be set to <i>EINVAL</i> and -1 will be returned. <code>numa_allocate_cpumask</code> () returns a bitmask of a size equal to the kernel&#8217;s cpu mask (kernel type cpumask_t). In other words, large enough to represent NR_CPUS cpus. This number of cpus can be gotten by calling <code>numa_num_possible_cpus().</code> The bitmask is zero-filled. <code>numa_free_cpumask</code> frees a cpumask previously allocate by <i>numa_allocate_cpumask.</i> <code>numa_allocate_nodemask()</code> returns a bitmask of a size equal to the kernel&#8217;s node mask (kernel type nodemask_t). In other words, large enough to represent MAX_NUMNODES nodes. This number of nodes can be gotten by calling <code>numa_num_possible_nodes().</code> The bitmask is zero-filled. <code>numa_free_nodemask()</code> frees a nodemask previous allocated by <i>numa_allocate_nodemask().</i> <code>numa_bitmask_alloc()</code> allocates a bitmask structure and its associated bit mask. The memory allocated for the bit mask contains enough words (type unsigned long) to contain <i>n</i> bits. The bit mask is zero-filled. The bitmask structure points to the bit mask and contains the <i>n</i> value. <code>numa_bitmask_clearall()</code> sets all bits in the bit mask to 0. The bitmask structure points to the bit mask and contains its size ( <i>bmp</i> -&gt;size). The value of <i>bmp</i> is always returned. Note that <code>numa_bitmask_alloc()</code> creates a zero-filled bit mask. <code>numa_bitmask_clearbit()</code> sets a specified bit in a bit mask to 0. Nothing is done if the <i>n</i> value is greater than the size of the bitmask (and no error is returned). The value of <i>bmp</i> is always returned. <code>numa_bitmask_equal()</code> returns 1 if two bitmasks are equal. It returns 0 if they are not equal. If the bitmask structures control bit masks of different sizes, the &quot;missing&quot; trailing bits of the smaller bit mask are considered to be 0. <code>numa_bitmask_free()</code> deallocates the memory of both the bitmask structure pointed to by <i>bmp</i> and the bit mask. It is an error to attempt to free this bitmask twice. <code>numa_bitmask_isbitset()</code> returns the value of a specified bit in a bit mask. If the <i>n</i> value is greater than the size of the bit map, 0 is returned. <code>numa_bitmask_nbytes()</code> returns the size (in bytes) of the bit mask controlled by <i>bmp.</i> The bit masks are always full words (type unsigned long), and the returned size is the actual size of all those words. <code>numa_bitmask_setall()</code> sets all bits in the bit mask to 1. The bitmask structure points to the bit mask and contains its size ( <i>bmp</i> -&gt;size). The value of <i>bmp</i> is always returned. <code>numa_bitmask_setbit()</code> sets a specified bit in a bit mask to 1. Nothing is done if <i>n</i> is greater than the size of the bitmask (and no error is returned). The value of <i>bmp</i> is always returned. <code>copy_bitmask_to_nodemask()</code> copies the body (the bit map itself) of the bitmask structure pointed to by <i>bmp</i> to the nodemask_t structure pointed to by the <i>nodemask</i> pointer. If the two areas differ in size, the copy is truncated to the size of the receiving field or zero-filled. <code>copy_nodemask_to_bitmask()</code> copies the nodemask_t structure pointed to by the <i>nodemask</i> pointer to the body (the bit map itself) of the bitmask structure pointed to by the <i>bmp</i> pointer. If the two areas differ in size, the copy is truncated to the size of the receiving field or zero-filled. <code>copy_bitmask_to_bitmask()</code> copies the body (the bit map itself) of the bitmask structure pointed to by the <i>bmpfrom</i> pointer to the body of the bitmask structure pointed to by the <i>bmpto</i> pointer. If the two areas differ in size, the copy is truncated to the size of the receiving field or zero-filled. <code>numa_bitmask_weight()</code> returns a count of the bits that are set in the body of the bitmask pointed to by the <i>bmp</i> argument.<br />
 <code>numa_move_pages()</code> moves a list of pages in the address space of the currently executing or current process. It simply uses the move_pages system call.<br />
 <i>pid</i> &#8211; ID of task. If not valid, use the current task.<br />
 <i>count</i> &#8211; Number of pages.<br />
 <i>pages</i> &#8211; List of pages to move.<br />
 <i>nodes</i> &#8211; List of nodes to which pages can be moved.<br />
 <i>status</i> &#8211; Field to which status is to be returned.<br />
 <i>flags</i> &#8211; MPOL_MF_MOVE or MPOL_MF_MOVE_ALL<br />
 See <a href="/docs/linux/man/2-move_pages/">move_pages</a>(2). <code>numa_migrate_pages()</code> simply uses the migrate_pages system call to cause the pages of the calling task, or a specified task, to be migated from one set of nodes to another. See <a href="/docs/linux/man/2-migrate_pages/">migrate_pages</a>(2). The bit masks representing the nodes should be allocated with <code>numa_allocate_nodemask()</code> , or with <code>numa_bitmask_alloc()</code> using an <i>n</i> value returned from <code>numa_num_possible_nodes().</code> A task&#8217;s current node set can be gotten by calling <code>numa_get_membind().</code> Bits in the <i>tonodes</i> mask can be set by calls to <code>numa_bitmask_setbit().</code> <code>numa_error</code>() is a <i>libnuma</i> internal function that can be overridden by the user program. This function is called with a <i>char *</i> argument when a <i>libnuma</i> function fails. Overriding the library internal definition makes it possible to specify a different error handling strategy when a <i>libnuma</i> function fails. It does not affect <code>numa_available</code>(). The <code>numa_error</code>() function defined in <i>libnuma</i> prints an error on <i>stderr</i> and terminates the program if <i>numa_exit_on_error</i> is set to a non-zero value. The default value of <i>numa_exit_on_error</i> is zero. <code>numa_warn</code>() is a <i>libnuma</i> internal function that can be also overridden by the user program. It is called to warn the user when a <i>libnuma</i> function encounters a non-fatal error. The default implementation prints a warning to <i>stderr</i>. The first argument is a unique number identifying each warning. After that there is a <code><a href="/docs/linux/man/3-printf/">printf</a></code>(3)-style format string and a variable number of arguments. <i>numa_warn</i> exits the program when <i>numa_exit_on_warn</i> is set to a non-zero value. The default value of <i>numa_exit_on_warn</i> is zero. </p>
<h2>Compatibility with libnuma version 1</h2>
<p>Binaries that were compiled for libnuma version 1 need not be re-compiled to run with libnuma version 2.<br />
 Source codes written for libnuma version 1 may be re-compiled without change with version 2 installed. To do so, in the code&#8217;s Makefile add this option to CFLAGS: -DNUMA_VERSION1_COMPATIBILITY</p>
<h2>Thread Safety</h2>
<p><i>numa_set_bind_policy</i> and <i>numa_exit_on_error</i> are process global. The other calls are thread safe.</p>
