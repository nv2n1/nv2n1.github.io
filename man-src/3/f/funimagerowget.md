<h2>NAME</h2>
<p> <code>FunImageRowGet &#8211; get row(s) of an image</code></p>
<h2>SYNOPSIS</h2>
<pre><code>
#include &lt;funtools.h&gt;
</code></pre>
<p>void *FunImageRowGet(Fun fun, void *buf, int rstart, int rstop,<br />
                     char *plist)</p>
<h2>DESCRIPTION</h2>
<p> The FunImageRowGet() routine returns one or more image rows from the specified section of a Funtools data file. If the input data are of type image, the array is generated by extracting the specified image rows and then binning them according to the specified bin factor. If the input data are contained in a binary table or raw event file, the rows are binned on the columns specified by the <code>bincols=</code> keyword (using appropriate default columns as needed), after which the image section and bin factors are applied. </p>
<p> The first argument is the Funtools handle returned by <i>FunOpen()</i>. The second <code>buf</code> argument is a pointer to a data buffer to fill. If <font SIZE="-1">NULL</font> is specified, <i>FunImageGet()</i> will allocate a buffer of the appropriate size. </p>
<p> The third and fourth arguments specify the first and last row to retrieve. Rows are counted starting from 1, up to the value of <font SIZE="-1">FUN_YMAX</font>(fun). The final <code>plist</code> (i.e., parameter list) argument is a string containing one or more comma-delimited <code>keyword=value</code> parameters. It can be used to specify the return data type using the <code>bitpix=</code> keyword. If no such keyword is specified in the plist string, the data type of the image is the same as the data type of the original input file, or is of type int for <font SIZE="-1">FITS</font> binary tables. </p>
<p> If the <code>bitpix=</code>value is supplied in the plist string, the data type of the returned image will be one of the supported <font SIZE="-1">FITS</font> image data types:</p>
<dl>
<dt>*</p>
<dd> 8 unsigned char</p>
<dt>*</p>
<dd> 16 short</p>
<dt>*</p>
<dd> 32 int</p>
<dt>*</p>
<dd> -32 float</p>
<dt>*</p>
<dd> -64 double</dl>
<p> For example: </p>
<pre><code>
double *drow;
Fun fun;
... open files...
    /* get section dimensions */
    FunInfoGet(fun, FUN_SECT_DIM1, &amp;dim1, FUN_SECT_DIM2, &amp;dim2, 0);
/* allocate one line's worth */
drow = malloc(dim1 * sizeof(double));
/* retrieve and process each input row (starting at 1) */
for (i = 1; i &lt;= dim2; i++) {
    if (!FunImageRowGet(fun, drow, i, i, "bitpix=-64"))
        gerror(stderr, "can't FunImageRowGet: %d %s
", i, iname);
    /* reverse the line */
    for (j = 1; j &lt;= dim1; j++) {
        ... process drow[j - 1]...
    }
}
...
</code></pre>
<p> On success, a pointer to the image buffer is returned. (This will be the same as the second argument, if <font SIZE="-1">NULL</font> is not passed to the latter.) On error, <font SIZE="-1">NULL</font> is returned. Note that the considerations described above for specifying binning columns in <i>FunImageGet()</i> also apply to FunImageRowGet().</p>
