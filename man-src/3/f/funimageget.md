<h2>NAME</h2>
<p> <code>FunImageGet &#8211; get an image or image section</code></p>
<h2>SYNOPSIS</h2>
<pre><code>
#include &lt;funtools.h&gt;
</code></pre>
<pre>
  void *FunImageGet(Fun fun, void *buf, char *plist)
</pre>
<h2>DESCRIPTION</h2>
<p> The FunImageGet() routine returns an binned image array of the specified section of a Funtools data file. If the input data are already of type image, the array is generated by extracting the specified image section and then binning it according to the specified bin factor. If the input data are contained in a binary table or raw event file, the rows are binned on the columns specified by the <code>bincols=</code> keyword (using appropriate default columns as necessary), after which the image section and bin factors are applied. In both cases, the data is automatically converted from <font SIZE="-1">FITS</font> to native format, if necessary. </p>
<p> The first argument is the Funtools handle returned by <i>FunOpen()</i>. The second <code>buf</code> argument is a pointer to a data buffer to fill. If <font SIZE="-1">NULL</font> is specified, FunImageGet will allocate a buffer of the appropriate size. Generally speaking, you always want Funtools to allocate the buffer because the image dimensions will be determined by Funtools image sectioning on the command line. </p>
<p> The third <code>plist</code> (i.e., parameter list) argument is a string containing one or more comma-delimited <code>keyword=value</code> parameters. It can be used to specify the return data type using the <code>bitpix=</code> keyword. If no such keyword is specified in the plist string, the data type of the returned image is the same as the data type of the original input file, or is of type int for <font SIZE="-1">FITS</font> binary tables. </p>
<p> If the <code>bitpix=</code> keyword is supplied in the plist string, the data type of the returned image will be one of the supported <font SIZE="-1">FITS</font> image data types:</p>
<dl>
<dt>*</p>
<dd> 8 unsigned char</p>
<dt>*</p>
<dd> 16 short</p>
<dt>*</p>
<dd> 32 int</p>
<dt>*</p>
<dd> -32 float</p>
<dt>*</p>
<dd> -64 double</dl>
<p> For example: </p>
<p>void *buf;<br />
/* extract data section into an image buffer */<br />
if (!(buf = FunImageGet(fun, NULL, NULL)))<br />
    gerror(stderr, &#8220;could not FunImageGet: %s
&#8221;, iname);</p>
<p> will allocate buf and retrieve the image in the file data format. In this case, you will have to determine the data type (using the <font SIZE="-1">FUN_SECT_BITPIX</font> value in the <i>FunInfoGet()</i> routine) and then use a switch statement to process each data type: </p>
<p>int bitpix;<br />
void *buf;<br />
unsigned char *cbuf;<br />
short *sbuf;<br />
int *ibuf;<br />
&#8230; buf = FunImageGet(fun, NULL, NULL);<br />
FunInfoGet(fun, FUN_SECT_BITPIX, &amp;bitpix, 0);<br />
/* set appropriate data type buffer to point to image buffer */<br />
switch (bitpix) {<br />
case 8:<br />
    cbuf = (unsigned char *)buf;<br />
    break;<br />
case 16:<br />
    sbuf = (short *)buf;<br />
    break;<br />
case 32:<br />
    ibuf = (int *)buf;<br />
    break;<br />
    &#8230;</p>
<p> See the imblank example code for more details on how to process an image when the data type is not specified beforehand. </p>
<p> It often is easier to specify the data type directly: </p>
<p>double *buf;<br />
/* extract data section into a double image buffer */<br />
if (!(buf = FunImageGet(fun, NULL, &#8220;bitpix=-64&#8221;)))<br />
    gerror(stderr, &#8220;could not FunImageGet: %s
&#8221;, iname);</p>
<p> will extract the image while converting to type double. </p>
<p> On success, a pointer to the image buffer is returned. (This will be the same as the second argument, if <font SIZE="-1">NULL</font> is not passed to the latter.) On error, <font SIZE="-1">NULL</font> is returned. </p>
<p> In summary, to retrieve image or row data into a binned image, you simply call <i>FunOpen()</i> followed by <i>FunImageGet()</i>. Generally, you then will want to call <i>FunInfoGet()</i> to retrieve the axis dimensions (and data type) of the section you are processing (so as to take account of sectioning and blocking of the original data): </p>
<p>double *buf;<br />
int i, j;<br />
int dim1, dim2;<br />
&#8230; other declarations, etc.</p>
<p>/* open the input FITS file */<br />
if (!(fun = FunOpen(argv[1], &#8220;rc&#8221;, NULL)))<br />
    gerror(stderr, &#8220;could not FunOpen input file: %s
&#8221;, argv[1]);</p>
<p>/* extract and bin the data section into a double float image buffer */<br />
if (!(buf = FunImageGet(fun, NULL, &#8220;bitpix=-64&#8221;)))<br />
    gerror(stderr, &#8220;could not FunImageGet: %s
&#8221;, argv[1]);</p>
<pre>
  /* get dimension information from funtools structure */
  FunInfoGet(fun, FUN_SECT_DIM1, &amp;dim1, FUN_SECT_DIM2, &amp;dim2, 0);
</pre>
<p>/* loop through pixels and reset values below limit to value */<br />
for (i = 0; i &lt; dim1 * dim2; i++) {<br />
    if (buf[i] &lt;= blimit)<br />
        buf[i] = bvalue;<br />
}</p>
<p> Another useful plist string value is &#8220;mask=all&#8221;, which returns an image populated with regions id values. Image pixels within a region will contain the associated region id (region values start at 1), and otherwise will contain a 0 value. Thus, the returned image is a region mask which can be used to process the image data (which presumably is retrieved by a separate call to FunImageGet) pixel by pixel. </p>
<p> If a <font SIZE="-1">FITS</font> binary table or a non-FITS raw event file is being binned into an image, it is necessary to specify the two columns that will be used in the 2D binning. This usually is done on the command line using the <code>bincols=(x,y)</code> keyword: </p>
<pre>
  funcnts &quot;foo.ev[EVENTS,bincols=(detx,dety)]&quot;
</pre>
<p> The full form of the <code>bincols=</code> specifier is: </p>
<pre><code>
bincols = ([xname[:tlmin[:tlmax:[binsiz]]]], [yname[:tlmin[:tlmax[:binsiz]]]])
</code></pre>
<p> where the tlmin, tlmax, and binsiz specifiers determine the image binning dimensions: </p>
<pre>
  dim = (tlmax - tlmin)/binsiz     (floating point data)
  dim = (tlmax - tlmin)/binsiz + 1 (integer data)
</pre>
<p> These tlmin, tlmax, and binsiz specifiers can be omitted if <font SIZE="-1">TLMIN</font>, <font SIZE="-1">TLMAX</font>, and <font SIZE="-1">TDBIN</font> header parameters (respectively) are present in the <font SIZE="-1">FITS</font> binary table header for the column in question. Note that if only one parameter is specified, it is assumed to be tlmax, and tlmin defaults to 1. If two parameters are specified, they are assumed to be tlmin and tlmax. </p>
<p> If <code>bincols</code> is not specified on the command line, Funtools tries to use appropriate defaults: it looks for the environment variable <font SIZE="-1">FITS_BINCOLS</font> (or <font SIZE="-1">FITS_BINKEY</font>). Then it looks for the Chandra parameters <font SIZE="-1">CPREF</font> (or <font SIZE="-1">PREFX</font>) in the <font SIZE="-1">FITS</font> binary table header. Failing this, it looks for columns named &#8220;X&#8221; and &#8220;Y&#8221; and if these are not found, it looks for columns containing the characters &#8220;X&#8221; and &#8220;Y&#8221;. </p>
<p> See Binning <font SIZE="-1">FITS</font> Binary Tables and Non-FITS Event Files for more information.</p>
