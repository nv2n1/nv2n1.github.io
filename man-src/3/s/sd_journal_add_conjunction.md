<p>sd_journal_add_match, sd_journal_add_disjunction, sd_journal_add_conjunction, sd_journal_flush_matches &#8211; Add or remove entry matches</p>
<h2>Synopsis</h2>
<pre><code>#include &lt;systemd/sd-journal.h&gt;

int sd_journal_add_match(sd_journal *j, const void *data, size_t size);

int sd_journal_add_disjunction(sd_journal *j);

int sd_journal_add_conjunction(sd_journal *j);

void sd_journal_flush_matches(sd_journal *j);</code></pre>
<h2>Description</h2>
<p><code>sd_journal_add_match()</code></p>
<dd>adds a match by which to filter the entries of the journal file. Matches applied with this call will filter what can be iterated through and read from the journal file via calls like <code><a href="/docs/linux/man/3-sd_journal_next/">sd_journal_next</a></code>(3) and <code><a href="/docs/linux/man/3-sd_journal_get_data/">sd_journal_get_data</a></code>(3). Matches are of the form &quot;FIELD=value&quot;, where the field part is a short uppercase string consisting only of 0-9, A-Z and the underscore. It may not begin with two underscores or be the empty string. The value part may be any value, including binary. If a match is applied, only entries with this field set will be iterated. Multiple matches may be active at the same time: If they apply to different fields, only entries with both fields set like this will be iterated. If they apply to the same fields, only entries where the field takes one of the specified values will be iterated. Well known fields are documented in <code><a href="/docs/linux/man/7-systemd-journal-fields/">systemd.journal-fields</a></code>(7). Whenever a new match is added the current entry position is reset, and <code><a href="/docs/linux/man/3-sd_journal_next/">sd_journal_next</a></code>(3) (or a similar call) needs to be called before entries can be read again. </p>
<p> <code>sd_journal_add_disjunction()</code> may be used to insert a disjunction (i.e. logical OR) in the match list. If this call is invoked, all previously added matches since the last invocation of <code>sd_journal_add_disjunction()</code> or <code>sd_journal_add_conjunction()</code> are combined in an OR with all matches added afterwards, until <code>sd_journal_add_disjunction()</code> or <code>sd_journal_add_conjunction()</code> is invoked again to begin the next OR or AND term. </p>
<p> <code>sd_journal_add_conjunction()</code> may be used to insert a conjunction (i.e. logical AND) in the match list. If this call is invoked, all previously added matches since the last invocation of <code>sd_journal_add_conjunction()</code> are combined in an AND with all matches added afterwards, until <code>sd_journal_add_conjunction()</code> is invoked again to begin the next AND term. The combination of <code>sd_journal_add_match()</code>, <code>sd_journal_add_disjunction()</code> and <code>sd_journal_add_conjunction()</code> may be used to build complex search terms, even though full logical expressions are not available. Note that <code>sd_journal_add_conjunction()</code> operates one level &#8216;higher&#8217; than <code>sd_journal_add_disjunction()</code>. It is hence possible to build an expression of AND terms, consisting of OR terms, consisting of AND terms, consisting of OR terms of matches (the latter OR expression is implicitly created for matches with the same field name, see above). </p>
<p> <code>sd_journal_flush_matches()</code> may be used to flush all matches, disjunction and conjunction terms again. After this call all filtering is removed and all entries in the journal will be iterated again. </p>
<p> Note that filtering via matches only applies to the way the journal is read, it has no effect on storage on disk.</p>
<h2>Return Value</h2>
<p><code>sd_journal_add_match()</code>, <code>sd_journal_add_disjunction()</code> and <code>sd_journal_add_conjunction()</code> return 0 on success or a negative errno-style error code. <code>sd_journal_flush_matches()</code> returns nothing.</p>
<h2>Notes</h2>
<p>The <code>sd_journal_add_match()</code>, <code>sd_journal_add_disjunction()</code>, <code>sd_journal_add_conjunction()</code> and <code>sd_journal_flush_matches()</code> interfaces are available as a shared library, which can be compiled and linked to with the <code>libsystemd</code>&nbsp;<wbr><code><a href="/docs/linux/man/1-pkg-config/">pkg-config</a></code>(1) file.</p>
<h2>Examples</h2>
<p>The following example adds matches to a journal context object to iterate only through messages generated by the Avahi service at the four error log levels, plus all messages of the message ID 03bb1dab98ab4ecfbf6fff2738bdd964 coming from any service (this example lacks the necessary error checking): </p>
<pre><code>... int add_matches(sd_journal *j)
{
    sd_journal_add_match(j, &quot;_SYSTEMD_UNIT=avahi-daemon.service&quot;, 0);
    sd_journal_add_match(j, &quot;PRIORITY=0&quot;, 0);
    sd_journal_add_match(j, &quot;PRIORITY=1&quot;, 0);
    sd_journal_add_match(j, &quot;PRIORITY=2&quot;, 0);
    sd_journal_add_match(j, &quot;PRIORITY=3&quot;, 0);
    sd_journal_add_disjunction(j);
    sd_journal_add_match(j, &quot;MESSAGE_ID=03bb1dab98ab4ecfbf6fff2738bdd964&quot;, 0);
}</code></pre>
