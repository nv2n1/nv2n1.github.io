sd-id128, sd_id128_t, SD_ID128_MAKE, SD_ID128_CONST_STR, SD_ID128_FORMAT_STR, SD_ID128_FORMAT_VAL, sd_id128_equal - APIs for processing 128-bit IDs 

<h2>Synopsis</h2><pre>#include &lt;systemd/sd-id128.h&gt;</pre><dl COMPACT><dt> <b>pkg-config --cflags --libs libsystemd</b></dl><h2>Description</h2><dd>sd-id128.h provides APIs to process and generate 128-bit ID values. The 128-bit ID values processed and generated by these APIs are a generalization of OSF UUIDs as defined by m[blue]<b>RFC 4122</b>m[]<font SIZE="-2">[1]</font> but use a simpler string format. These functions impose no structure on the used IDs, much unlike OSF UUIDs or Microsoft GUIDs, but are fully compatible with those types of IDs. 

 See <b><a HREF="/docs/linux/man/3-sd_id128_to_string/">sd_id128_to_string</a></b>(3), <b><a HREF="/docs/linux/man/3-sd_id128_randomize/">sd_id128_randomize</a></b>(3) and <b><a HREF="/docs/linux/man/3-sd_id128_get_machine/">sd_id128_get_machine</a></b>(3) for more information about the implemented functions. 

 A 128-bit ID is implemented as the following union type: 

<dl COMPACT><dd><pre>typedef union sd_id128 {
 uint8_t bytes[16];
 uint64_t qwords[2];
} sd_id128_t;</pre></dl>
 

 This union type allows accessing the 128-bit ID as 16 separate bytes or two 64-bit words. It is generally safer to access the ID components by their 8-bit array to avoid endianness issues. This union is intended to be passed call-by-value (as opposed to call-by-reference) and may be directly manipulated by clients. 

 A couple of macros are defined to denote and decode 128-bit IDs: 

 <b>SD_ID128_MAKE()</b> may be used to denote a constant 128-bit ID in source code. A commonly used idiom is to assign a name to a 128-bit ID using this macro: 

<dl COMPACT><dd><pre>#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)</pre></dl>
 

 <b>SD_ID128_CONST_STR()</b> may be used to convert constant 128-bit IDs into constant strings for output. The following example code will output the string &quot;fc2e22bc6ee647b6b90729ab34a250b1&quot;: 

<dl COMPACT><dd><pre>int main(int argc, char *argv[]) {
 puts(SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}</pre></dl>
 

 <b>SD_ID128_FORMAT_STR</b> and <b>SD_ID128_FORMAT_VAL()</b> may be used to format a 128-bit ID in a <b><a HREF="/docs/linux/man/3-printf/">printf</a></b>(3) format string, as shown in the following example: 

<dl COMPACT><dd><pre>int main(int argc, char *argv[]) {
 sd_id128_t id;
 id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
 printf(&quot;The ID encoded in this C file is &quot; SD_ID128_FORMAT_STR &quot;.\n&quot;, SD_ID128_FORMAT_VAL(id));
 return 0;
}</pre></dl>
 

 Use <b>sd_id128_equal()</b> to compare two 128-bit IDs: 

<dl COMPACT><dd><pre>int main(int argc, char *argv[]) {
 sd_id128_t a, b, c;
 a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
 b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
 c = a;
 assert(sd_id128_equal(a, c));
 assert(!sd_id128_equal(a, b));
 return 0;
}</pre></dl>
 

 Note that new, randomized IDs may be generated with <b><a HREF="/docs/linux/man/1-journalctl/">journalctl</a></b>(1)'s <b>--new-id</b> option.
<h2>Notes</h2>These APIs are implemented as a shared library, which can be compiled and linked to with the <b>libsystemd</b>&nbsp;<wbr><b><a HREF="/docs/linux/man/1-pkg-config/">pkg-config</a></b>(1) file.
