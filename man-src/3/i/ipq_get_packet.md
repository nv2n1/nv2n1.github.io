<h2 class="name">NAME</h2>
<p> ipq_message_type, ipq_get_packet, ipq_getmsgerr &#8212; query queue messages </p>
<h2>SYNOPSIS</h2>
<p> <code>#include &lt;<a href="file:/usr/include/linux/netfilter.h">linux/netfilter.h</a>&gt;</code><br />
 <code>#include &lt;<a href="file:/usr/include/libipq.h">libipq.h</a>&gt;</code> </p>
<p> <code>int ipq_message_type(const unsigned char *</code><i>buf</i><code>);</code><br />
 <code>ipq_packet_msg_t *ipq_get_packet(const unsigned char *</code><i>buf</i><code>);</code><br />
 <code>int ipq_get_msgerr(const unsigned char *</code><i>buf</i><code>);</code></p>
<h2>DESCRIPTION</h2>
<p> The <code>ipq_message_type</code> function returns the type of queue message returned to userspace via <code>ipq_read</code>. </p>
<p> <code>ipq_message_type</code> should always be called following a successful call to <code>ipq_read</code> to determine whether the message is a packet message or an error message. The <i>buf</i> parameter should be the same data obtained from the previous call to <code>ipq_read</code>. </p>
<p> <code>ipq_message_type</code> will return one of the following values:</p>
<dl>
<dt><code>NLMSG_ERROR</code></p>
<dd> An error message generated by the Netlink transport.</dl>
<dl>
<dt><code>IPQM_PACKET</code></p>
<dd> A packet message containing packet metadata and optional packet payload data.</dl>
<p> The <code>ipq_get_packet</code> function should be called if <code>ipq_message_type</code> returns <code>IPQM_PACKET</code>. The <i>buf</i> parameter should point to the same data used for the call to <code>ipq_message_type</code>. The pointer returned by <code>ipq_get_packet</code> points to a packet message, which is declared as follows: </p>
<dl>
<dt>
<dd>
<pre><code>
typedef struct ipq_packet_msg {
    unsigned long packet_id;    /* ID of queued packet */
    unsigned long mark;         /* Netfilter mark value */
    long timestamp_sec;         /* Packet arrival time (seconds) */
    long timestamp_usec;        /* Packet arrvial time (+useconds) */
    unsigned int hook;          /* Netfilter hook we rode in on */
    char indev_name[IFNAMSIZ];  /* Name of incoming interface */
    char outdev_name[IFNAMSIZ]; /* Name of outgoing interface */
    unsigned short hw_protocol; /* Hardware protocol (network order) */
    unsigned short hw_type;     /* Hardware type */
    unsigned char hw_addrlen;   /* Hardware address length */
    unsigned char hw_addr[8];   /* Hardware address */
    size_t data_len;            /* Length of packet data */
    unsigned char payload[0];   /* Optional packet data */
} ipq_packet_msg_t;
</code></pre>
</dl>
<p> Each of these fields may be read by the application. If the queue mode is <code>IPQ_COPY_PACKET</code> and the <i>data_len</i> value is greater than zero, the packet payload contents may be accessed in the memory following the <code>ipq_packet_msg_t</code> structure to a range of <i>data_len.</i> </p>
<p> The <i>packet_id</i> field contains a packet identifier to be used when calling <code>ipq_set_verdict</code>. </p>
<p> The <code>ipq_get_msgerr</code> function should be called if <code>ipq_message_type</code> returns <code>NLMSG_ERROR.</code> The <i>buf</i> parameter should point to the same data used for the call to <code>ipq_message_type</code>. The value returned by <code>ipq_get_msgerr</code> is set by higher level kernel code and corresponds to standard <code>errno</code> values.</p>
