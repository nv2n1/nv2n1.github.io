<h2>DESCRIPTION</h2>
<p> Bf Em All the functions in this manual page are deprecated in the MIT implementation, and will soon be deprecated in Heimdal too, don&#8217;t use them. Ef </p>
<p> Getting initial credential ticket for a principal. <code>krb5_get_in_cred</code> is the function all other krb5_get_in function uses to fetch tickets. The other krb5_get_in function are more specialized and therefor somewhat easier to use. </p>
<p> If your need is only to verify a user and password, consider using krb5_verify_user3 instead, it have a much simpler interface. </p>
<p> <code>krb5_get_in_tkt</code> and <code>krb5_get_in_cred</code> fetches initial credential, queries after key using the Fa key_proc argument. The differences between the two function is that <code>krb5_get_in_tkt</code> stores the credential in a <code>krb5_creds</code> while <code>krb5_get_in_cred</code> stores the credential in a <code>krb5_ccache</code> </p>
<p> <code>krb5_get_in_tkt_with_password</code> <code>krb5_get_in_tkt_with_keytab</code> and <code>krb5_get_in_tkt_with_skey</code> does the same work as <code>krb5_get_in_cred</code> but are more specialized. </p>
<p> <code>krb5_get_in_tkt_with_password</code> uses the clients password to authenticate. If the password argument is <code>NULL</code> the user user queried with the default password query function. </p>
<p> <code>krb5_get_in_tkt_with_keytab</code> searches the given keytab for a service entry for the client principal. If the keytab is <code>NULL</code> the default keytab is used. </p>
<p> <code>krb5_get_in_tkt_with_skey</code> uses a key to get the initial credential. </p>
<p> There are some common arguments to the krb5_get_in functions, these are: </p>
<p> Fa options are the <code>KDC_OPT</code> flags. </p>
<p> Fa etypes is a <code>NULL</code> terminated array of encryption types that the client approves. </p>
<p> Fa addrs a list of the addresses that the initial ticket. If it is <code>NULL</code> the list will be generated by the library. </p>
<p> Fa pre_auth_types a <code>NULL</code> terminated array of pre-authentication types. If Fa pre_auth_types is <code>NULL</code> the function will try without pre-authentication and return those pre-authentication that the KDC returned. </p>
<p> Fa ret_as_reply will (if not <code>NULL</code> be filled in with the response of the KDC and should be free with Fn krb5_free_kdc_rep . </p>
<p> Fa key_proc is a pointer to a function that should return a key salted appropriately. Using <code>NULL</code> will use the default password query function. </p>
<p> Fa decrypt_proc Using <code>NULL</code> will use the default decryption function. </p>
<p> Fa decryptarg will be passed to the decryption function Fa decrypt_proc . </p>
<p> Fa creds creds should be filled in with the template for a credential that should be requested. The client and server elements of the creds structure must be filled in. Upon return of the function it will be contain the content of the requested credential Fa ( krb5_get_in_cred ) , or it will be freed with krb5_free_creds3 (all the other krb5_get_in functions). </p>
<p> Fa ccache will store the credential in the credential cache Fa ccache . The credential cache will not be initialized, thats up the the caller. </p>
<p> <code>krb5_password_key_proc</code> is a library function that is suitable using as the Fa krb5_key_proc argument to <code>krb5_get_in_cred</code> or <code>krb5_get_in_tkt</code> Fa keyseed should be a pointer to a <code>NUL</code> terminated string or <code>NULL</code> <code>krb5_password_key_proc</code> will query the user for the pass on the console if the password isn&#8217;t given as the argument Fa keyseed . </p>
<p> Fn krb5_free_kdc_rep frees the content of Fa rep .</p>
