<p>pbs_deljob &#8211; delete a pbs batch job</p>
<h2>Synopsis</h2>
<pre><code>#include &lt;pbs_error.h&gt;

#include &lt;pbs_ifl.h&gt;</code></pre>
<pre>int pbs_deljob(int connect, char&nbsp;<wbr>*job_id, char&nbsp;<wbr>*extend)</pre>
<h2>Description</h2>
<p>Issue a batch request to delete a batch job. If the batch job is running, the execution server will send the <code>SIGTERM</code> signal followed by <code>SIGKILL .</code> </p>
<p> A <i>Delete Job</i> batch request is generated and sent to the server over the connection specified by <i> which is the return value of </i><code>pbs_connect</code>(). </p>
<p> The argument, <i> identifies which job is to be deleted, it is specified in the form: </i><code> </p>
<p> The argument, </code><i> is overloaded to serve two purposes. If the pointer points to a string of the form:<br />
 </i><code>deldelay=nnnn</code>,<br />
 it is used to provide control over the delay between sending <code>SIGTERM</code> and <code>SIGKILL</code> signals to a running job. The characters <code>nnnn</code> specify a unsigned decimal integer time delay in seconds. If <i> is the null pointer or points to a null string, the administrator established default time delay is used. </p>
<p> If points to a string other than the above, it is taken as text to be appended to the message mailed to to the job owner. This mailing occurs if the job is deleted by a user other than the job owner. </i></p>
<h2>See Also</h2>
<p><a href="//www.systutorials.com/docs/linux/man/1B-qdel/">qdel</a>(1B) and <a href="//www.systutorials.com/docs/linux/man/3B-pbs_connect/">pbs_connect</a>(3B)</p>
<h2>Diagnostics</h2>
<p>When the batch request generated by the <code>pbs_deljob</code>() function has been completed successfully by a batch server, the routine will return 0 (zero). Otherwise, a non zero error is returned. The error number is also set in pbs_errno.</p>
