<p>pbs_rerunjob &#8211; rerun a pbs batch job</p>
<h2>Synopsis</h2>
<pre><code>#include &lt;pbs_error.h&gt;

#include &lt;pbs_ifl.h&gt;</code></pre>
<pre>int pbs_rerunjob(int connect, char&nbsp;<wbr>*job_id, char&nbsp;<wbr>*extend)</pre>
<h2>Description</h2>
<p>Issue a batch request to rerun a batch job. </p>
<p> A <i>Rerun Job</i> batch request is generated and sent to the server over the connection specified by <i> which is the return value of </i><code>pbs_connect</code>(). </p>
<p> If the job is marked as being not rerunable, the request will fail and an error will be returned. </p>
<p> The argument, <i> identifies which job is to be rerun it is specified in the form: </i><code> </p>
<p> The parameter, </code><i> is reserved for implementation defined extensions. As if TORQUE 2.2, the string define RERUNFORCE</i> may be used to force a rerun if the mini-server fails. This is dangerous. Do not used it.</p>

<p><a href="//www.systutorials.com/docs/linux/man/1B-qrerun/">qrerun</a>(1B), <a href="//www.systutorials.com/docs/linux/man/1B-qsub/">qsub</a>(1B), and <a href="//www.systutorials.com/docs/linux/man/3B-pbs_connect/">pbs_connect</a>(3B)</p>
<h2>Diagnostics</h2>
<p>When the batch request generated by <code>pbs_rerunjob</code>() function has been completed successfully by a batch server, the routine will return 0 (zero). Otherwise, a non zero error is returned. The error number is also set in pbs_errno.</p>
