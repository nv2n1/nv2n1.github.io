<h2>Description</h2>
<p>Issue a batch request to run a batch job. </p>
<p> For <i>pbs_runjob()</i> a &quot;Run Job&quot; batch request is generated and sent to the server over the connection specified by <i> which is the return value of </i><code>pbs_connect</code>(). The server will reply when the job has started execution unless file in-staging is required. In that case, the server will reply when the staging operations are started. </p>
<p> For <i>pbs_asyrunjob()</i> an &quot;Asynchronous Run Job&quot; request is generated and set to the server over the connection. The server will validate the request and reply before initiating the execution of the job. This version of the call can be used to reduce latency in scheduling, especially when the scheduler must start a large number of jobs. </p>
<p> These requests requires that the issuing user have operator or administrator privilege. </p>
<p> The argument, <i> identifies which job is to be run it is specified in the form: </i><code> </p>
<p> The argument, </code><i> if not the null pointer or null string, specifies the location where the job should be run. The location is the name of a host in the the cluster managed by the server. </p>
<p> The argument, is reserved for implementation defined extensions. </i></p>

<h2>Diagnostics</h2>
<p>When the batch request generated by the <code>pbs_runjob</code>() or <code>pbs_asyrunjob</code>() functions has been completed successfully by a batch server, the routines will return 0 (zero). Otherwise, a non zero error is returned. The error number is also set in pbs_errno.</p>
