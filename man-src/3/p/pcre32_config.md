<p>PCRE &#8211; Perl-compatible regular expressions </p>

<p> <code>#include &lt;pcre.h&gt;</code> </p>
<p> <font SIZE="-1"><code>int pcre_config(int </code><i>what</i>, void *<i>where</i>); </font> </p>
<p> <code>int pcre16_config(int </code><i>what</i>, void *<i>where</i>); </p>
<p> <code>int pcre32_config(int </code><i>what</i>, void *<i>where</i>);  </p>
<h2>DESCRIPTION</h2>
<p>This function makes it possible for a client program to find out which optional features are available in the version of the PCRE library it is using. The arguments are as follows: </p>
<p> <br />
&nbsp;<wbr>&nbsp;<i>what</i>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;A code specifying what information is required <br />
&nbsp;<wbr>&nbsp;<i>where</i>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;Points to where to put the data </p>
<p>The <i>where</i> argument must point to an integer variable, except for PCRE_CONFIG_MATCH_LIMIT, PCRE_CONFIG_MATCH_LIMIT_RECURSION, and PCRE_CONFIG_PARENS_LIMIT, when it must point to an unsigned long integer, and for PCRE_CONFIG_JITTARGET, when it must point to a const char*. <p>The function yields 0 on success or PCRE_ERROR_BADOPTION otherwise. <p>There is a complete description of the PCRE native API in the <code>pcreapi</code> page and a description of the POSIX API in the <code>pcreposix</code> page. </p>
