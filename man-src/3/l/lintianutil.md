<p>Lintian::Util &#8211; Lintian utility functions </p>
<h2>Synopsis</h2>
<pre> use Lintian::Util qw(normalize_pkg_path);
 my $path = normalize_pkg_path('usr/bin/', '../lib/git-core/git-pull');
 if (defined $path) {
 # ...
 }</pre>
<h2>Description</h2>
<p>This module contains a number of utility subs that are nice to have, but on their own did not warrant their own module. </p>
<p> Most subs are imported only on request.</p>
<h2>Variables</h2>
<dl COMPACT>
<dt>$PKGNAME_REGEX</dt>
<dd>Regular expression that matches valid package names. The expression is not anchored and does not enforce any &#8220;boundary&#8221; characters.</dd>
<dt>$PKGREPACK_REGEX</dt>
<dd>Regular expression that matches &#8220;repacked&#8221; package names. The expression is not anchored and does not enforce any &#8220;boundary&#8221; characters. It should only be applied to the upstream portion (see #931846).</dd>
<dt>$PKGVERSION_REGEX</dt>
<dd>Regular expression that matches valid package versions. The expression is not anchored and does not enforce any &#8220;boundary&#8221; characters.</dd></dl>
<h2>Functions</h2>
<dl COMPACT>
<dt>get_deb_info(DEBFILE)</dt>
<dd>Extracts the control file from DEBFILE and returns it as a hashref. </dd>
<p> Basically, this is a fancy convenience for setting up an ar + tar pipe and passing said pipe to &#8220;parse_dpkg_control(HANDLE[, FLAGS[, LINES]])&#8221;. </p>
<p> DEBFILE must be an ar file containing a &#8220;control.tar.gz&#8221; member, which in turn should contain a &#8220;control&#8221; file. If the &#8220;control&#8221; file is empty this will return an empty list. </p>
<p> Note: the control file is only expected to have a single paragraph and thus only the first is returned (in the unlikely case that there are more than one). </p>
<p> This function may fail with any of the messages that &#8220;parse_dpkg_control&#8221; do. It can also emit: </p>
<pre> &quot;cannot fork to unpack %s: %s
&quot;</pre>
<dt>get_dsc_info (DSCFILE)</dt>
<dd>Convenience function for reading dsc files. It will read the DSCFILE using &#8220;read_dpkg_control(FILE[, FLAGS[, LINES]])&#8221; and then return the first paragraph. If the file has no paragraphs, <tt>&quot;undef&quot;</tt> is returned instead. </dd>
<p> Note: the control file is only expected to have a single paragraph and thus only the first is returned (in the unlikely case that there are more than one). </p>
<p> This function may fail with any of the messages that &#8220;read_dpkg_control(FILE[, FLAGS[, LINES]])&#8221; do.</p>
<dt>drain_pipe(FD)</dt>
<dd>Reads and discards any remaining contents from FD, which is assumed to be a pipe. This is mostly done to avoid having the &#8220;write&#8221;-end die with a SIGPIPE due to a &#8220;broken pipe&#8221; (which can happen if you just close the pipe). </dd>
<p> May cause an exception if there are issues reading from the pipe. </p>
<p> Caveat: This will block until the pipe is closed from the &#8220;write&#8221;-end, so only use it with pipes where the &#8220;write&#8221;-end will eventually close their end by themselves (or something else will make them close it).</p>
<dt>get_file_digest(ALGO, FILE)</dt>
<dd>Creates an ALGO digest object that is seeded with the contents of FILE. If you just want the hex digest, please use &#8220;get_file_checksum(ALGO, FILE)&#8221; instead. </dd>
<p> ALGO can be &#8216;md5&#8217; or shaX, where X is any number supported by Digest::SHA (e.g. &#8216;sha256&#8217;). </p>
<p> This sub is a convenience wrapper around Digest::{MD5,SHA}.</p>
<dt>get_file_checksum(ALGO, FILE)</dt>
<dd>Returns a hexadecimal string of the message digest checksum generated by the algorithm ALGO on FILE. </dd>
<p> ALGO can be &#8216;md5&#8217; or shaX, where X is any number supported by Digest::SHA (e.g. &#8216;sha256&#8217;). </p>
<p> This sub is a convenience wrapper around Digest::{MD5,SHA}.</p>
<dt>is_string_utf8_encoded(STRING)</dt>
<dd>Returns a truth value if STRING can be decoded as valid UTF-8.</dd>
<dt>file_is_encoded_in_non_utf8 (&#8230;)</dt>
<dd>Undocumented</dd>
<dt><code>do_fork()</code></dt>
<dd>Overrides fork to reset signal handlers etc. in the child.</dd>
<dt>clean_env ([CLOC])</dt>
<dd>Destructively cleans <tt>%ENV</tt> &#8211; removes all variables <tt>%ENV</tt> except a selected few whitelisted variables. </dd>
<p> The list of whitelisted <tt>%ENV</tt> variables are: </p>
<pre> PATH
 LC_ALL (*)
 TMPDIR</pre>
<p>(*) LC_ALL is a special case as clean_env will change its value to either &#8220;C.UTF-8&#8221; or &#8220;C&#8221; (if CLOC is given and a truth value).</p>
<dt>perm2oct(PERM)</dt>
<dd>Translates PERM to an octal permission. PERM should be a string describing the permissions as done by <i>tar t</i> or <i>ls -l</i>. That is, it should be a string like &#8220;-rw-r&#8212;r&#8211;&#8221;. </dd>
<p> If the string does not appear to be a valid permission, it will cause a trappable error. </p>
<p> Examples: </p>
<pre> # Good
 perm2oct('-rw-r--r--') == 0644
 perm2oct('-rwxr-xr-x') == 0755
 # Bad
 perm2oct('broken') # too short to be recognised
 perm2oct('-resurunet') # contains unknown permissions</pre>
<dt>run_cmd([OPTS, ]COMMAND[, ARGS&#8230;])</dt>
<dd>Executes the given <tt>&quot;COMMAND&quot;</tt> with the (optional) arguments <tt>&quot;ARGS&quot;</tt> and returns the status code as one would see it from a shell script. Shell features cannot be used. </dd>
<p> OPTS, if given, is a hash reference with zero or more of the following key-value pairs:</p>
<dl COMPACT>
<dd>
</dd><dl COMPACT>
<dt>chdir</dt>
<dd>The child process with chdir to the given directory before executing the command.</dd>
<dt>in</dt>
<dd>The STDIN of the child process will be reopened and read from the filename denoted by the value of this key. By default, STDIN will reopened to read from /dev/null.</dd>
<dt>out</dt>
<dd>The STDOUT of the child process will be reopened and write to filename denoted by the value of this key. By default, STDOUT is discarded.</dd>
<dt>update-env-vars</dt>
<dd>Each key/value pair defined in the hashref associated with <code>update-env-vars</code> will be updated in the child processes&#8217;s environment. If a value is <tt>&quot;undef&quot;</tt>, then the corresponding environment variable will be removed (if set). Otherwise, the environment value will be set to that value.</dd></dl>
</dl>

<dt>locate_helper_tool(TOOLNAME)</dt>
<dd>Given the name of a helper tool, returns the path to it. The tool must be available in the &#8220;helpers&#8221; subdir of one of the &#8220;lintian root&#8221; directories used by Lintian. </dd>
<p> The tool name should follow the same rules as check names. Particularly, third-party checks should namespace their tools in the same way they namespace their checks. E.g. &#8220;python/some-helper&#8221;. </p>
<p> If the tool cannot be found, this sub will cause a trappable error.</p>
<dt>strip ([LINE])</dt>
<dd>Strips whitespace from the beginning and the end of LINE and returns it. If LINE is omitted, <tt>$_</tt> will be used instead. Example </dd>
<pre> @lines = map { strip } &lt;$fd&gt;;</pre>
<p>In void context, the input argument will be modified so it can be used as a replacement for chomp in some cases: </p>
<pre> while ( my $line = &lt;$fd&gt; ) {
 strip ($line);
 # $line no longer has any leading or trailing whitespace
 }</pre>
<p>Otherwise, a copy of the string is returned: </p>
<pre> while ( my $orig = &lt;$fd&gt; ) {
 my $stripped = strip ($orig);
 if ($stripped ne $orig) {
 # $orig had leading or/and trailing whitespace
 }
 }</pre>
<dt>lstrip ([LINE])</dt>
<dd>Like strip but only strip leading whitespace.</dd>
<dt>rstrip ([LINE])</dt>
<dd>Like strip but only strip trailing whitespace.</dd>
<dt>check_path (CMD)</dt>

<dt>signal_number2name(NUM)</dt>
<dd>Given a number, returns the name of the signal (without leading &#8220;SIG&#8221;). Example: </dd>

<dt>normalize_pkg_path(PATH)</dt>
<dd>Normalize PATH by removing superfluous path segments. PATH is assumed to be relative the package root. Note that the result will never start nor end with a slash, even if PATH does. </dd>
<p> As the name suggests, this is a path &#8220;normalization&#8221; rather than a true path resolution (for that use Cwd::realpath). Particularly, it assumes none of the path segments are symlinks. </p>
<p> normalize_pkg_path will return <tt>&quot;q{}&quot;</tt> (i.e. the empty string) if PATH is normalized to the root dir and <tt>&quot;undef&quot;</tt> if the path cannot be normalized without escaping the package root. </p>
<p> Examples:<br/>
&nbsp;<wbr>&nbsp;normalize_pkg_path(&#8216;usr/share/java/../../../usr/share/ant/file&#8217;)<br/>
&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;eq&nbsp;&#8216;usr/share/ant/file&#8217;<br/>
&nbsp;<wbr>&nbsp;normalize_pkg_path(&#8216;usr/..&#8217;)&nbsp;eq q{}; </p>
<pre> The following will return C&lt;undef&gt;:
 normalize_pkg_path('usr/bin/../../../../etc/passwd')</pre>
<dt>normalize_pkg_path(CURDIR, LINK_TARGET)</dt>
<dd>Normalize the path obtained by following a link with LINK_TARGET as its target from CURDIR as the current directory. CURDIR is assumed to be relative to the package root. Note that the result will never start nor end with a slash, even if CURDIR or DEST does. </dd>
<p> normalize_pkg_path will return <tt>&quot;q{}&quot;</tt> (i.e. the empty string) if the target is the root dir and <tt>&quot;undef&quot;</tt> if the path cannot be normalized without escaping the package root. </p>
<p> <code>CAVEAT</code>: This function is <i>not always sufficient</i> to test if it is safe to open a given symlink. Use is_ancestor_of for that. If you must use this function, remember to check that the target is not a symlink (or if it is, that it can be resolved safely). </p>
<p> Examples: </p>
<pre> normalize_pkg_path('usr/share/java', '../ant/file') eq 'usr/share/ant/file'
 normalize_pkg_path('usr/share/java', '../../../usr/share/ant/file')
 normalize_pkg_path('usr/share/java', '/usr/share/ant/file')
 eq 'usr/share/ant/file'
 normalize_pkg_path('/usr/share/java', '/') eq q{};
 normalize_pkg_path('/', 'usr/..') eq q{};
 The following will return C&lt;undef&gt;:
 normalize_pkg_path('usr/bin', '../../../../etc/passwd')
 normalize_pkg_path('usr/bin', '/../etc/passwd')</pre>
<dt>is_ancestor_of(PARENTDIR, PATH)</dt>
<dd>Returns true if and only if PATH is PARENTDIR or a path stored somewhere within PARENTDIR (or its subdirs). </dd>
<p> This function will resolve the paths; any failure to resolve the path will cause a trappable error.</p>
