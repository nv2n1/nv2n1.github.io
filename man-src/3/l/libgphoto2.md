<h2 class="name">NAME</h2>
<p> libgphoto2 &#8211; cross-platform digital camera library </p>
<h2>SYNOPSIS</h2>
<pre><code>
#include &lt;gphoto2/gphoto2.h&gt;
</code></pre>
<h2>DESCRIPTION</h2>
<p> The gphoto2 library provides applications with access to a variety of cameras. </p>
<p> This man page will be extended with autogenerated documentation of the interface types and methods used for communication between the gphoto2 library and a frontend.</p>
<h2>FILES</h2>
<dl>
<dt><i>~/.gphoto/settings</i></p>
<dd> Here gphoto2 applications may store their configuration used to access gphoto2.</dl>
<p> To track down errors, you can add the <code>&#8211;debug</code> parameter to the <code>gphoto2</code> command line and, if dealing with USB problems, setting the environment variable <code>USB_DEBUG</code><i>=1</i>.</p>
<h2>ENVIRONMENT VARIABLES</h2>
<dl>
<dt><code>CAMLIBS</code></p>
<dd> If set, defines the directory where the libgphoto2 library looks for its camera drivers (camlibs). You only need to set this on OS/2 systems and broken/test installations.</p>
<dt><code>IOLIBS</code></p>
<dd> If set, defines the directory where the libgphoto2_port library looks for its I/O drivers (iolibs). You only need to set this on OS/2 systems and broken/test installations.</p>
<dt><code>LD_DEBUG</code></p>
<dd> Set this to <i>all</i> to receive lots of debug information regarding library loading on <code>ld</code> based systems.</p>
<dt><code>USB_DEBUG</code></p>
<dd> If set, defines the numeric debug level with which the libusb library will print messages. In order to get some debug output, set it to <i>1</i>.</dl>
