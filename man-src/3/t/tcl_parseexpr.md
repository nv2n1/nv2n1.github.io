<h2>Arguments</h2>
<dl COMPACT>
<dd>Tcl_Interp <i>*interp</i> (out) For procedures other than <code>Tcl_FreeParse</code>, <code>Tcl_EvalTokens</code> and <code>Tcl_EvalTokensStandard</code>, used only for error reporting; if NULL, then no error messages are left after errors. For <code>Tcl_EvalTokens</code> and <code>Tcl_EvalTokensStandard</code>, determines the context for evaluating the script and also is used for error reporting; must not be NULL.</p>
<dd>const char <i>*start</i> (in) Pointer to first character in string to parse.</p>
<dd>int <i>numBytes</i> (in) Number of bytes in string to parse, not including any terminating null character. If less than 0 then the script consists of all characters following <i>start</i> up to the first null character.</p>
<dd>int <i>nested</i> (in) Non-zero means that the script is part of a command substitution so an unquoted close bracket should be treated as a command terminator. If zero, close brackets have no special meaning.</p>
<dd>int <i>append</i> (in) Non-zero means that <i>*parsePtr</i> already contains valid tokens; the new tokens should be appended to those already present. Zero means that <i>*parsePtr</i> is uninitialized; any information in it is ignored. This argument is normally 0.</p>
<dd>Tcl_Parse <i>*parsePtr</i> (out) Points to structure to fill in with information about the parsed command, expression, variable name, etc. Any previous information in this structure is ignored, unless <i>append</i> is non-zero in a call to <code>Tcl_ParseBraces</code>, <code>Tcl_ParseQuotedString</code>, or <code>Tcl_ParseVarName</code>.</p>
<dd>const char <i>**termPtr</i> (out) If not NULL, points to a location where <code>Tcl_ParseBraces</code>, <code>Tcl_ParseQuotedString</code>, and <code>Tcl_ParseVar</code> will store a pointer to the character just after the terminating character (the close-brace, the last character of the variable name, or the close-quote (respectively)) if the parse was successful.</p>
<dd>Tcl_Parse <i>*usedParsePtr</i> (in) Points to structure that was filled in by a previous call to <code>Tcl_ParseCommand</code>, <code>Tcl_ParseExpr</code>, <code>Tcl_ParseVarName</code>, etc. </p>
</dl>
<h2>Description</h2>
<p>These procedures parse Tcl commands or portions of Tcl commands such as expressions or references to variables. Each procedure takes a pointer to a script (or portion thereof) and fills in the structure pointed to by <i>parsePtr</i> with a collection of tokens describing the information that was parsed. The procedures normally return <code>TCL_OK</code>. However, if an error occurs then they return <code>TCL_ERROR</code>, leave an error message in <i>interp</i>&#8216;s result (if <i>interp</i> is not NULL), and leave nothing in <i>parsePtr</i>. </p>
<p> <code>Tcl_ParseCommand</code> is a procedure that parses Tcl scripts. Given a pointer to a script, it parses the first command from the script. If the command was parsed successfully, <code>Tcl_ParseCommand</code> returns <code>TCL_OK</code> and fills in the structure pointed to by <i>parsePtr</i> with information about the structure of the command (see below for details). If an error occurred in parsing the command then <code>TCL_ERROR</code> is returned, an error message is left in <i>interp</i>&#8216;s result, and no information is left at <i>*parsePtr</i>. </p>
<p> <code>Tcl_ParseExpr</code> parses Tcl expressions. Given a pointer to a script containing an expression, <code>Tcl_ParseExpr</code> parses the expression. If the expression was parsed successfully, <code>Tcl_ParseExpr</code> returns <code>TCL_OK</code> and fills in the structure pointed to by <i>parsePtr</i> with information about the structure of the expression (see below for details). If an error occurred in parsing the command then <code>TCL_ERROR</code> is returned, an error message is left in <i>interp</i>&#8216;s result, and no information is left at <i>*parsePtr</i>. </p>
<p> <code>Tcl_ParseBraces</code> parses a string or command argument enclosed in braces such as <code>{hello}</code> or <code>{string 	 with 	 tabs}</code> from the beginning of its argument <i>start</i>. The first character of <i>start</i> must be <code>{</code>. If the braced string was parsed successfully, <code>Tcl_ParseBraces</code> returns <code>TCL_OK</code>, fills in the structure pointed to by <i>parsePtr</i> with information about the structure of the string (see below for details), and stores a pointer to the character just after the terminating <code>}</code> in the location given by <i>*termPtr</i>. If an error occurs while parsing the string then <code>TCL_ERROR</code> is returned, an error message is left in <i>interp</i>&#8216;s result, and no information is left at <i>*parsePtr</i> or <i>*termPtr</i>. </p>
<p> <code>Tcl_ParseQuotedString</code> parses a double-quoted string such as <code>&quot;sum is [expr {$a+$b}]&quot;</code> from the beginning of the argument <i>start</i>. The first character of <i>start</i> must be <code>&#34;</code>. If the double-quoted string was parsed successfully, <code>Tcl_ParseQuotedString</code> returns <code>TCL_OK</code>, fills in the structure pointed to by <i>parsePtr</i> with information about the structure of the string (see below for details), and stores a pointer to the character just after the terminating <code>&#34;</code> in the location given by <i>*termPtr</i>. If an error occurs while parsing the string then <code>TCL_ERROR</code> is returned, an error message is left in <i>interp</i>&#8216;s result, and no information is left at <i>*parsePtr</i> or <i>*termPtr</i>. </p>
<p> <code>Tcl_ParseVarName</code> parses a Tcl variable reference such as <code>$abc</code> or <code>$x([expr {$index + 1}])</code> from the beginning of its <i>start</i> argument. The first character of <i>start</i> must be <code>$</code>. If a variable name was parsed successfully, <code>Tcl_ParseVarName</code> returns <code>TCL_OK</code> and fills in the structure pointed to by <i>parsePtr</i> with information about the structure of the variable name (see below for details). If an error occurs while parsing the command then <code>TCL_ERROR</code> is returned, an error message is left in <i>interp</i>&#8216;s result (if <i>interp</i> is not NULL), and no information is left at <i>*parsePtr</i>. </p>
<p> <code>Tcl_ParseVar</code> parse a Tcl variable reference such as <code>$abc</code> or <code>$x([expr {$index + 1}])</code> from the beginning of its <i>start</i> argument. The first character of <i>start</i> must be <code>$</code>. If the variable name is parsed successfully, <code>Tcl_ParseVar</code> returns a pointer to the string value of the variable. If an error occurs while parsing, then NULL is returned and an error message is left in <i>interp</i>&#8216;s result. </p>
<p> The information left at <i>*parsePtr</i> by <code>Tcl_ParseCommand</code>, <code>Tcl_ParseExpr</code>, <code>Tcl_ParseBraces</code>, <code>Tcl_ParseQuotedString</code>, and <code>Tcl_ParseVarName</code> may include dynamically allocated memory. If these five parsing procedures return <code>TCL_OK</code> then the caller must invoke <code>Tcl_FreeParse</code> to release the storage at <i>*parsePtr</i>. These procedures ignore any existing information in <i>*parsePtr</i> (unless <i>append</i> is non-zero), so if repeated calls are being made to any of them then <code>Tcl_FreeParse</code> must be invoked once after each call. </p>
<p> <code>Tcl_EvalTokensStandard</code> evaluates a sequence of parse tokens from a Tcl_Parse structure. The tokens typically consist of all the tokens in a word or all the tokens that make up the index for a reference to an array variable. <code>Tcl_EvalTokensStandard</code> performs the substitutions requested by the tokens and concatenates the resulting values. The return value from <code>Tcl_EvalTokensStandard</code> is a Tcl completion code with one of the values <code>TCL_OK</code>, <code>TCL_ERROR</code>, <code>TCL_RETURN</code>, <code>TCL_BREAK</code>, or <code>TCL_CONTINUE</code>, or possibly some other integer value originating in an extension. In addition, a result value or error message is left in <i>interp</i>&#8216;s result; it can be retrieved using <code>Tcl_GetObjResult</code>. </p>
<p> <code>Tcl_EvalTokens</code> differs from <code>Tcl_EvalTokensStandard</code> only in the return convention used: it returns the result in a new Tcl_Obj. The reference count of the object returned as result has been incremented, so the caller must invoke <code>Tcl_DecrRefCount</code> when it is finished with the object. If an error or other exception occurs while evaluating the tokens (such as a reference to a non-existent variable) then the return value is NULL and an error message is left in <i>interp</i>&#8216;s result. The use of <code>Tcl_EvalTokens</code> is deprecated. </p>
<h2>Tcl_Parse Structure</h2>
<p><code>Tcl_ParseCommand</code>, <code>Tcl_ParseExpr</code>, <code>Tcl_ParseBraces</code>, <code>Tcl_ParseQuotedString</code>, and <code>Tcl_ParseVarName</code> return parse information in two data structures, Tcl_Parse and Tcl_Token:</p>
<dl COMPACT>
<dd>
<pre>typedef struct Tcl_Parse {
 const char *<i>commentStart</i>;
 int <i>commentSize</i>;
 const char *<i>commandStart</i>;
 int <i>commandSize</i>;
 int <i>numWords</i>;
 Tcl_Token *<i>tokenPtr</i>;
 int <i>numTokens</i>;
 ...
} Tcl_Parse;
typedef struct Tcl_Token {
 int <i>type</i>;
 const char *<i>start</i>;
 int <i>size</i>;
 int <i>numComponents</i>;
} Tcl_Token;</pre>
</dl>
<p> The first five fields of a Tcl_Parse structure are filled in only by <code>Tcl_ParseCommand</code>. These fields are not used by the other parsing procedures. </p>
<p> <code>Tcl_ParseCommand</code> fills in a Tcl_Parse structure with information that describes one Tcl command and any comments that precede the command. If there are comments, the <i>commentStart</i> field points to the <code>#</code> character that begins the first comment and <i>commentSize</i> indicates the number of bytes in all of the comments preceding the command, including the newline character that terminates the last comment. If the command is not preceded by any comments, <i>commentSize</i> is 0. <code>Tcl_ParseCommand</code> also sets the <i>commandStart</i> field to point to the first character of the first word in the command (skipping any comments and leading space) and <i>commandSize</i> gives the total number of bytes in the command, including the character pointed to by <i>commandStart</i> up to and including the newline, close bracket, or semicolon character that terminates the command. The <i>numWords</i> field gives the total number of words in the command. </p>
<p> All parsing procedures set the remaining fields, <i>tokenPtr</i> and <i>numTokens</i>. The <i>tokenPtr</i> field points to the first in an array of Tcl_Token structures that describe the components of the entity being parsed. The <i>numTokens</i> field gives the total number of tokens present in the array. Each token contains four fields. The <i>type</i> field selects one of several token types that are described below. The <i>start</i> field points to the first character in the token and the <i>size</i> field gives the total number of characters in the token. Some token types, such as <code>TCL_TOKEN_WORD</code> and <code>TCL_TOKEN_VARIABLE</code>, consist of several component tokens, which immediately follow the parent token; the <i>numComponents</i> field describes how many of these there are. The <i>type</i> field has one of the following values:</p>
<dl COMPACT>
<dt><code>TCL_TOKEN_WORD</code></p>
<dd>This token ordinarily describes one word of a command but it may also describe a quoted or braced string in an expression. The token describes a component of the script that is the result of concatenating together a sequence of subcomponents, each described by a separate subtoken. The token starts with the first non-blank character of the component (which may be a double-quote or open brace) and includes all characters in the component up to but not including the space, semicolon, close bracket, close quote, or close brace that terminates the component. The <i>numComponents</i> field counts the total number of sub-tokens that make up the word, including sub-tokens of <code>TCL_TOKEN_VARIABLE</code> and <code>TCL_TOKEN_BS</code> tokens.</p>
<dt><code>TCL_TOKEN_SIMPLE_WORD</code></p>
<dd>This token has the same meaning as <code>TCL_TOKEN_WORD</code>, except that the word is guaranteed to consist of a single <code>TCL_TOKEN_TEXT</code> sub-token. The <i>numComponents</i> field is always 1.</p>
<dt><code>TCL_TOKEN_EXPAND_WORD</code></p>
<dd>This token has the same meaning as <code>TCL_TOKEN_WORD</code>, except that the command parser notes this word began with the expansion prefix <code>{*}</code>, indicating that after substitution, the list value of this word should be expanded to form multiple arguments in command evaluation. This token type can only be created by Tcl_ParseCommand.</p>
<dt><code>TCL_TOKEN_TEXT</code></p>
<dd>The token describes a range of literal text that is part of a word. The <i>numComponents</i> field is always 0.</p>
<dt><code>TCL_TOKEN_BS</code></p>
<dd>The token describes a backslash sequence such as <code>
</code> or <code>�</code>. The <i>numComponents</i> field is always 0.</p>
<dt><code>TCL_TOKEN_COMMAND</code></p>
<dd>The token describes a command whose result must be substituted into the word. The token includes the square brackets that surround the command. The <i>numComponents</i> field is always 0 (the nested command is not parsed; call <code>Tcl_ParseCommand</code> recursively if you want to see its tokens).</p>
<dt><code>TCL_TOKEN_VARIABLE</code></p>
<dd>The token describes a variable substitution, including the <code>$</code>, variable name, and array index (if there is one) up through the close parenthesis that terminates the index. This token is followed by one or more additional tokens that describe the variable name and array index. If <i>numComponents</i> is 1 then the variable is a scalar and the next token is a <code>TCL_TOKEN_TEXT</code> token that gives the variable name. If <i>numComponents</i> is greater than 1 then the variable is an array: the first sub-token is a <code>TCL_TOKEN_TEXT</code> token giving the array name and the remaining sub-tokens are <code>TCL_TOKEN_TEXT</code>, <code>TCL_TOKEN_BS</code>, <code>TCL_TOKEN_COMMAND</code>, and <code>TCL_TOKEN_VARIABLE</code> tokens that must be concatenated to produce the array index. The <i>numComponents</i> field includes nested sub-tokens that are part of <code>TCL_TOKEN_VARIABLE</code> tokens in the array index.</p>
<dt><code>TCL_TOKEN_SUB_EXPR</code></p>
<dd>The token describes one subexpression of an expression (or an entire expression). A subexpression may consist of a value such as an integer literal, variable substitution, or parenthesized subexpression; it may also consist of an operator and its operands. The token starts with the first non-blank character of the subexpression up to but not including the space, brace, close-paren, or bracket that terminates the subexpression. This token is followed by one or more additional tokens that describe the subexpression. If the first sub-token after the <code>TCL_TOKEN_SUB_EXPR</code> token is a <code>TCL_TOKEN_OPERATOR</code> token, the subexpression consists of an operator and its token operands. If the operator has no operands, the subexpression consists of just the <code>TCL_TOKEN_OPERATOR</code> token. Each operand is described by a <code>TCL_TOKEN_SUB_EXPR</code> token. Otherwise, the subexpression is a value described by one of the token types <code>TCL_TOKEN_WORD</code>, <code>TCL_TOKEN_TEXT</code>, <code>TCL_TOKEN_BS</code>, <code>TCL_TOKEN_COMMAND</code>, <code>TCL_TOKEN_VARIABLE</code>, and <code>TCL_TOKEN_SUB_EXPR</code>. The <i>numComponents</i> field counts the total number of sub-tokens that make up the subexpression; this includes the sub-tokens for any nested <code>TCL_TOKEN_SUB_EXPR</code> tokens.</p>
<dt><code>TCL_TOKEN_OPERATOR</code></p>
<dd>The token describes one operator of an expression such as <code>&amp;&amp;</code> or <code>hypot</code>. A <code>TCL_TOKEN_OPERATOR</code> token is always preceded by a <code>TCL_TOKEN_SUB_EXPR</code> token that describes the operator and its operands; the <code>TCL_TOKEN_SUB_EXPR</code> token&#8217;s <i>numComponents</i> field can be used to determine the number of operands. A binary operator such as <code>*</code> is followed by two <code>TCL_TOKEN_SUB_EXPR</code> tokens that describe its operands. A unary operator like <code>&#8211;</code> is followed by a single <code>TCL_TOKEN_SUB_EXPR</code> token for its operand. If the operator is a math function such as <code>log10</code>, the <code>TCL_TOKEN_OPERATOR</code> token will give its name and the following <code>TCL_TOKEN_SUB_EXPR</code> tokens will describe its operands; if there are no operands (as with <code>rand</code>), no <code>TCL_TOKEN_SUB_EXPR</code> tokens follow. There is one trinary operator, <code>?</code>, that appears in if-then-else subexpressions such as <i>x</i><code>?</code><i>y</i><code>:</code><i>z</i>; in this case, the <code>?</code> <code>TCL_TOKEN_OPERATOR</code> token is followed by three <code>TCL_TOKEN_SUB_EXPR</code> tokens for the operands <i>x</i>, <i>y</i>, and <i>z</i>. The <i>numComponents</i> field for a <code>TCL_TOKEN_OPERATOR</code> token is always 0.</dl>
<p> After <code>Tcl_ParseCommand</code> returns, the first token pointed to by the <i>tokenPtr</i> field of the Tcl_Parse structure always has type <code>TCL_TOKEN_WORD</code> or <code>TCL_TOKEN_SIMPLE_WORD</code> or <code>TCL_TOKEN_EXPAND_WORD</code>. It is followed by the sub-tokens that must be concatenated to produce the value of that word. The next token is the <code>TCL_TOKEN_WORD</code> or <code>TCL_TOKEN_SIMPLE_WORD</code> of <code>TCL_TOKEN_EXPAND_WORD</code> token for the second word, followed by sub-tokens for that word, and so on until all <i>numWords</i> have been accounted for. </p>
<p> After <code>Tcl_ParseExpr</code> returns, the first token pointed to by the <i>tokenPtr</i> field of the Tcl_Parse structure always has type <code>TCL_TOKEN_SUB_EXPR</code>. It is followed by the sub-tokens that must be evaluated to produce the value of the expression. Only the token information in the Tcl_Parse structure is modified: the <i>commentStart</i>, <i>commentSize</i>, <i>commandStart</i>, and <i>commandSize</i> fields are not modified by <code>Tcl_ParseExpr</code>. </p>
<p> After <code>Tcl_ParseBraces</code> returns, the array of tokens pointed to by the <i>tokenPtr</i> field of the Tcl_Parse structure will contain a single <code>TCL_TOKEN_TEXT</code> token if the braced string does not contain any backslash-newlines. If the string does contain backslash-newlines, the array of tokens will contain one or more <code>TCL_TOKEN_TEXT</code> or <code>TCL_TOKEN_BS</code> sub-tokens that must be concatenated to produce the value of the string. If the braced string was just <code>{}</code> (that is, the string was empty), the single <code>TCL_TOKEN_TEXT</code> token will have a <i>size</i> field containing zero; this ensures that at least one token appears to describe the braced string. Only the token information in the Tcl_Parse structure is modified: the <i>commentStart</i>, <i>commentSize</i>, <i>commandStart</i>, and <i>commandSize</i> fields are not modified by <code>Tcl_ParseBraces</code>. </p>
<p> After <code>Tcl_ParseQuotedString</code> returns, the array of tokens pointed to by the <i>tokenPtr</i> field of the Tcl_Parse structure depends on the contents of the quoted string. It will consist of one or more <code>TCL_TOKEN_TEXT</code>, <code>TCL_TOKEN_BS</code>, <code>TCL_TOKEN_COMMAND</code>, and <code>TCL_TOKEN_VARIABLE</code> sub-tokens. The array always contains at least one token; for example, if the argument <i>start</i> is empty, the array returned consists of a single <code>TCL_TOKEN_TEXT</code> token with a zero <i>size</i> field. Only the token information in the Tcl_Parse structure is modified: the <i>commentStart</i>, <i>commentSize</i>, <i>commandStart</i>, and <i>commandSize</i> fields are not modified. </p>
<p> After <code>Tcl_ParseVarName</code> returns, the first token pointed to by the <i>tokenPtr</i> field of the Tcl_Parse structure always has type <code>TCL_TOKEN_VARIABLE</code>. It is followed by the sub-tokens that make up the variable name as described above. The total length of the variable name is contained in the <i>size</i> field of the first token. As in <code>Tcl_ParseExpr</code>, only the token information in the Tcl_Parse structure is modified by <code>Tcl_ParseVarName</code>: the <i>commentStart</i>, <i>commentSize</i>, <i>commandStart</i>, and <i>commandSize</i> fields are not modified. </p>
<p> All of the character pointers in the Tcl_Parse and Tcl_Token structures refer to characters in the <i>start</i> argument passed to <code>Tcl_ParseCommand</code>, <code>Tcl_ParseExpr</code>, <code>Tcl_ParseBraces</code>, <code>Tcl_ParseQuotedString</code>, and <code>Tcl_ParseVarName</code>. </p>
<p> There are additional fields in the Tcl_Parse structure after the <i>numTokens</i> field, but these are for the private use of <code>Tcl_ParseCommand</code>, <code>Tcl_ParseExpr</code>, <code>Tcl_ParseBraces</code>, <code>Tcl_ParseQuotedString</code>, and <code>Tcl_ParseVarName</code>; they should not be referenced by code outside of these procedures. </p>
