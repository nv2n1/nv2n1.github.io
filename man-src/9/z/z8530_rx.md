<p>z8530_rx &#8211; Handle a PIO receive event</p>
<h2>Synopsis</h2>
<pre><code>void z8530_rx(struct z8530_channel *c);</code></pre>
<h2>Arguments</h2>
<p><i>c</i></p>
<dl>
<dd>
<dd>Z8530 channel to process</dl>
<h2>Description</h2>
<p>Receive handler for receiving in PIO mode. This is much like the async one but not quite the same or as complex</p>
<h2>Note</h2>
<p>Its intended that this handler can easily be separated from the main code to run realtime. That&#8217;ll be needed for some machines (eg to ever clock 64kbits on a sparc ;)). </p>
<p> The RT_LOCK macros don&#8217;t do anything now. Keep the code covered by them as short as possible in all circumstances &#8211; clocks cost baud. The interrupt handler is assumed to be atomic w.r.t. to other code &#8211; this is true in the RT case too. </p>
<p> We only cover the sync cases for this. If you want 2Mbit async do it yourself but consider medical assistance first. This non DMA synchronous mode is portable code. The DMA mode assumes PCI like ISA DMA </p>
<p> Called with the device lock held</p>
