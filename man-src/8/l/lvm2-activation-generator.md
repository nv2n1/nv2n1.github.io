<p>lvm2-activation-generator &#8211; generator for systemd units to activate LVM volumes on boot</p>
<h2>Synopsis</h2>
<p><code>/lib/systemd/system-generators/lvm2-activation-generator</code> </p>
<h2>Description</h2>
<p>The lvm2-activation-generator is called by <code><a href="/docs/linux/man/1-systemd/">systemd</a></code>(1) on boot to generate systemd units at runtime to activate LVM Logical Volumes (LVs) when global/event_activation=0 is set in <code><a href="/docs/linux/man/5-lvm-conf/">lvm.conf</a></code>(5). These units use <code>vgchange -ay</code> to activate LVs. If event_activation=1, the lvm2-activation-generator exits immediately without generating any systemd units, and LVM fully relies on event-based activation to activate LVs. In this case, event-generated <code>pvscan &#8211;cache -aay</code> commands activate LVs. These systemd units are generated by lvm2-activation-generator: <i>lvm2-activation-early.service</i> is run before systemd&#8217;s special <code>cryptsetup.target</code> to activate LVs that are not layered on top of encrypted devices. <i>lvm2-activation.service</i> is run after systemd&#8217;s special <code>cryptsetup.target</code> to activate LVs that are layered on top of encrypted devices. <i>lvm2-activation-net.service</i> is run after systemd&#8217;s special <code>remote-fs-pre.target</code> to activate LVs that are layered on attached remote devices. Note that all the underlying LVM devices (Physical Volumes) need to be present when the service is run. If the there are any devices that appear to the system later, LVs using these devices need to be activated directly by <code><a href="/docs/linux/man/8-lvchange/">lvchange</a></code>(8) or <code><a href="/docs/linux/man/8-vgchange/">vgchange</a></code>(8). The lvm2-activation-generator implements the <code>Generators Specification</code> as referenced in <code><a href="/docs/linux/man/1-systemd/">systemd</a></code>(1). </p>
