<p>bpfc &#8211; a Berkeley Packet Filter assembler and compiler </p>
<h2>Synopsis</h2>
<p><code>bpfc</code> { [<i>options</i>] | [<i>source-file</i>] } </p>
<h2>Description</h2>
<p>bpfc is a small Berkeley Packet Filter assembler and compiler which is able to translate BPF assembler-like mnemonics into a numerical or C-like format, that can be read by tools such as netsniff-ng, iptables (xt_bpf) and many others. BPF is the one and only upstream filtering construct that is used in combination with <a href="/docs/linux/man/7-packet/">packet</a>(7) sockets, but also seccomp-BPF for system call sandboxing. The Linux kernel and also BSD kernels implement &quot;virtual machine&quot; like constructs and JIT compilers that mimic a small register-based machine in BPF architecture and execute filter code that is, for example, composed by bpfc on a data buffer that is given by network packets. The purpose of this is to shift computation in time, so that the kernel can drop or truncate incoming packets as early as possible without having to push them to user space for further analysis first. Meanwhile, BPF constructs also find application in other areas such as in the communication between user and kernel space like system call sand-boxing. At the time of writing this man page, the only available BPF compiler is part of the <a href="/docs/linux/man/3-pcap/">pcap</a>(3) library and accessible through a high-level filter language that might be familiar to many people as tcpdump-like filters. However, it is quite often useful to bypass that compiler and write optimized code that cannot be produced by the <a href="/docs/linux/man/3-pcap/">pcap</a>(3) compiler, or is wrongly optimized, or is defective on purpose in order to debug test kernel code. Also, a reason to use bpfc could be to try out some new BPF extensions that are not supported by other compilers. Furthermore, bpfc can be useful to verify JIT compiler behavior or to find possible bugs that need to be fixed. bpfc is implemented with the help of <a href="/docs/linux/man/1-flex/">flex</a>(1) and <a href="/docs/linux/man/1-bison/">bison</a>(1), tokenizes the source file in the first stage and parses its content into an AST. In two code generation stages it emits target opcodes. bpfc furthermore supports Linux kernel BPF extensions. More about that can be found in the syntax section. The Linux kernel BPF JIT compiler is automatically turned on if detected by netsniff-ng. However, it can also be manually turned on through the command &#8221;echo &quot;1&quot; &gt; /proc/sys/net/core/bpf_jit_enable&#8221; (normal working mode) or &#8221;echo &quot;2&quot; &gt; /proc/sys/net/core/bpf_jit_enable&#8221; (debug mode where emitted opcodes of the image are printed to the kernel log). An architecture agnostic BPF JIT image disassembler can be found in the kernel source tree under &#8221;tools/net/bpf_jit_disasm.c&#8221; or within the netsniff-ng Git repository. </p>
<h2>Options</h2>
<h3>-i &lt;source-file/-&gt;, &#8211;input &lt;source-file/-&gt;</h3>
<p>Read BPF assembly instruction from an input file or from stdin.</p>
<h3>-p, &#8211;cpp</h3>
<p>Pass the bpf program through the C preprocessor before reading it in bpfc. This allows #define and #include directives (e.g. to include definitions from system headers) to be used in the bpf program.</p>
<h3>-f &lt;format&gt;, &#8211;format &lt;format&gt;</h3>
<p>Specify a different output format than the default that is netsniff-ng compatible. The &lt;format&gt; specifier can be: C, netsniff-ng, xt_bpf, tcpdump.</p>
<h3>-b, &#8211;bypass</h3>
<p>Bypass basic filter validation when emitting opcodes. This can be useful for explicitly creating malformed BPF expressions for injecting into the kernel, for example, for bug testing.</p>
<h3>-V, &#8211;verbose</h3>
<p>Be more verbose and display some bpfc debugging information.</p>
<h3>-d, &#8211;dump</h3>
<p>Dump all supported instructions to stdout.</p>
<h3>-v, &#8211;version</h3>
<p>Show version information and exit.</p>
<h3>-h, &#8211;help</h3>
<p>Show user help and exit.</p>

<p>&nbsp;<wbr>&nbsp;<wbr>1. Multi-line C-style comments:&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>/*&nbsp;<wbr>put comment here&nbsp;<wbr>*/<br />
&nbsp;<wbr>&nbsp;<wbr>2. Single-line ASM-style comments:&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>;&nbsp;<wbr>&nbsp;<wbr>put comment here </p>
<p> Used Abbreviations: </p>
<p>&nbsp;<wbr>&nbsp;<wbr>BHW: byte, half-word, or word</p>

<h2>Usage Example</h2>
<h3>bpfc fubar</h3>
<p>Compile the source file &#8221;fubar&#8221; into BPF opcodes. Opcodes will be directed to stdout.</p>
<h3>bpfc -f xt_bpf -b -p -i fubar, resp. iptables -A INPUT -m bpf &#8211;bytecode `bpfc -f xt_bpf -i fubar` -j LOG</h3>
<p>Compile the source file &#8221;fubar&#8221; into BPF opcodes, bypass basic filter validation and emit opcodes in netfilter&#8217;s xt_bpf readable format. Note that the source file &#8221;fubar&#8221; is first passed to the C preprocessor for textual replacements before handing over to the bpfc compiler.</p>
<h3>bpfc &#8211;</h3>
<p>Read bpfc instruction from stdin and emit opcodes to stdout.</p>
<h3>bpfc foo &gt; bar, resp. netsniff-ng -f bar &#8230;</h3>
<p>Compile filter instructions from file foo and redirect bpfc&#8217;s output into the file bar, that can then be read by <a href="/docs/linux/man/8-netsniff-ng/">netsniff-ng</a>(8) through option -f.</p>
<h3>bpfc -f tcpdump -i fubar</h3>
<p>Output opcodes from source file fubar in the same behavior as &#8221;tcpdump -ddd&#8221;.</p>
