<p>haproxy_selinux &#8211; Security Enhanced Linux Policy for the haproxy processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the haproxy processes via flexible mandatory access control. The haproxy processes execute with the haproxy_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep haproxy_t</code> </p>
<h2>Entrypoints</h2>
<p>The haproxy_t SELinux type can be entered via the <code>haproxy_exec_t</code> file type. </p>
<p> The default entrypoint paths for the haproxy_t domain are the following: </p>
<p> /usr/sbin/haproxy, /usr/sbin/haproxy-systemd-wrapper</p>

<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. haproxy policy is extremely flexible and has several booleans that allow you to manipulate the policy and run haproxy with the tightest access possible. </p>
<p> If you want to determine whether haproxy can connect to all TCP ports, you must turn on the haproxy_connect_any boolean. Disabled by default. </p>
<p> <code>setsebool -P haproxy_connect_any 1</code> </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to allow cluster administrative cluster domains memcheck-amd64- to use executable memory, you must turn on the cluster_use_execmem boolean. Disabled by default. </p>
<p> <code>setsebool -P cluster_use_execmem 1</code> </p>
<p> If you want to allow all daemons to write corefiles to /, you must turn on the daemons_dump_core boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_dump_core 1</code> </p>
<p> If you want to enable cluster mode for daemons, you must turn on the daemons_enable_cluster_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P daemons_enable_cluster_mode 1</code> </p>
<p> If you want to allow all daemons to use tcp wrappers, you must turn on the daemons_use_tcp_wrapper boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tcp_wrapper 1</code> </p>
<p> If you want to allow all daemons the ability to read/write terminals, you must turn on the daemons_use_tty boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tty 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Enabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code></p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux haproxy policy is very flexible allowing users to setup their haproxy processes in as secure a method as possible. </p>
<p> STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the haproxy, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t haproxy_var_run_t &#8216;/srv/myhaproxy_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/myhaproxy_content</code> </p>
<p> Note: SELinux often uses regular expressions to specify labels that match multiple files. </p>
<p> <i>The following file types are defined for haproxy:</i> </p>
<p> <code>haproxy_exec_t</code> </p>
<p> &#8211; Set files with the haproxy_exec_t type, if you want to transition an executable to the haproxy_t domain. </p>
<dl>
<dt>Paths:</p>
<dd>/usr/sbin/haproxy, /usr/sbin/haproxy-systemd-wrapper </p>
</dl>
<p> <code>haproxy_tmpfs_t</code> </p>
<p> &#8211; Set files with the haproxy_tmpfs_t type, if you want to store haproxy files on a tmpfs file system. </p>
<p> <code>haproxy_unit_file_t</code> </p>
<p> &#8211; Set files with the haproxy_unit_file_t type, if you want to treat the files as haproxy unit content. </p>
<p> <code>haproxy_var_lib_t</code> </p>
<p> &#8211; Set files with the haproxy_var_lib_t type, if you want to store the haproxy files under the /var/lib directory. </p>
<p> <code>haproxy_var_log_t</code> </p>
<p> &#8211; Set files with the haproxy_var_log_t type, if you want to treat the data as haproxy var log data, usually stored under the /var/log directory. </p>
<p> <code>haproxy_var_run_t</code> </p>
<p> &#8211; Set files with the haproxy_var_run_t type, if you want to store the haproxy files under the /run or /var/run directory. </p>
<dl>
<dt>Paths:</p>
<dd>/var/run/haproxy.stat.*, /var/run/haproxy.sock.*, /var/run/haproxy.pid </p>
</dl>
<p> Note: File context can be temporarily modified with the chcon command. If you want to permanently change the file context you need to use the <code>semanage fcontext</code> command. This will modify the SELinux labeling database. You will need to use <code>restorecon</code> to apply the labels.</p>
