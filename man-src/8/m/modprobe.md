<p>modprobe &#8211; Add and remove modules from the Linux Kernel</p>
<h2>Synopsis</h2>
<dl>
<dt> <code>modprobe</code> [<code>-v</code>] [<code>-V</code>] [<code>-C&nbsp;</code><i>config-file</i>] [<code>-n</code>] [<code>-i</code>] [<code>-q</code>] [<code>-b</code>] [<i>modulename</i>] [<i>module parameters</i>&#8230;]</p>
<dt> <code>modprobe</code> [-r] [<code>-v</code>] [<code>-n</code>] [<code>-i</code>] [<i>modulename</i>&#8230;]</p>
<dt> <code>modprobe</code> [-c]</p>
<dt> <code>modprobe</code> [&#8211;dump-modversions] [<i>filename</i>]</dl>
<h2>Description</h2>
<p><code>modprobe</code></p>
<dd>intelligently adds or removes a module from the Linux kernel: note that for convenience, there is no difference between _ and &#8211; in module names (automatic underscore conversion is performed). <code>modprobe</code> looks in the module directory /lib/modules/`uname -r` for all the modules and other files, except for the optional configuration files in the /etc/modprobe.d directory (see <code><a href="/docs/linux/man/5-modprobe-d/">modprobe.d</a></code>(5)). <code>modprobe</code> will also use module options specified on the kernel command line in the form of &lt;module&gt;.&lt;option&gt; and blacklists in the form of modprobe.blacklist=&lt;module&gt;. </p>
<p> Note that unlike in 2.4 series Linux kernels (which are not supported by this tool) this version of <code>modprobe</code> does not do anything to the module itself: the work of resolving symbols and understanding parameters is done inside the kernel. So module failure is sometimes accompanied by a kernel message: see <code><a href="/docs/linux/man/8-dmesg/">dmesg</a></code>(8). </p>
<p> <code>modprobe</code> expects an up-to-date modules.dep.bin file as generated by the corresponding <code>depmod</code> utility shipped along with <code>modprobe</code> (see <code><a href="/docs/linux/man/8-depmod/">depmod</a></code>(8)). This file lists what other modules each module needs (if any), and <code>modprobe</code> uses this to add or remove these dependencies automatically. </p>
<p> If any arguments are given after the <i>modulename</i>, they are passed to the kernel (in addition to any options listed in the configuration file).</p>
<h2>Options</h2>
<p><code>-a</code>, <code>&#8211;all</code></p>
<dl>
<dd>Insert all module names on the command line.</dl>
<p> <code>-b</code>, <code>&#8211;use-blacklist</code></p>
<dl>
<dd>This option causes <code>modprobe</code> to apply the <code>blacklist</code> commands in the configuration files (if any) to module names as well. It is usually used by <code><a href="/docs/linux/man/7-udev/">udev</a></code>(7).</dl>
<p> <code>-C</code>, <code>&#8211;config</code></p>
<dl>
<dd>This option overrides the default configuration directory (/etc/modprobe.d). </p>
<p> This option is passed through <code>install</code> or <code>remove</code> commands to other <code>modprobe</code> commands in the MODPROBE_OPTIONS environment variable.</dl>
<p> <code>-c</code>, <code>&#8211;showconfig</code></p>
<dl>
<dd>Dump out the effective configuration from the config directory and exit.</dl>
<p> <code>&#8211;dump-modversions</code></p>
<dl>
<dd>Print out a list of module versioning information required by a module. This option is commonly used by distributions in order to package up a Linux kernel module using module versioning deps.</dl>
<p> <code>-d</code>, <code>&#8211;dirname</code></p>
<dl>
<dd>Root directory for modules, / by default.</dl>
<p> <code>&#8211;first-time</code></p>
<dl>
<dd>Normally, <code>modprobe</code> will succeed (and do nothing) if told to insert a module which is already present or to remove a module which isn&#8217;t present. This is ideal for simple scripts; however, more complicated scripts often want to know whether <code>modprobe</code> really did something: this option makes modprobe fail in the case that it actually didn&#8217;t do anything.</dl>
<p> <code>&#8211;force-vermagic</code></p>
<dl>
<dd>Every module contains a small string containing important information, such as the kernel and compiler versions. If a module fails to load and the kernel complains that the &quot;version magic&quot; doesn&#8217;t match, you can use this option to remove it. Naturally, this check is there for your protection, so using this option is dangerous unless you know what you&#8217;re doing. </p>
<p> This applies to any modules inserted: both the module (or alias) on the command line and any modules on which it depends.</dl>
<p> <code>&#8211;force-modversion</code></p>
<dl>
<dd>When modules are compiled with CONFIG_MODVERSIONS set, a section detailing the versions of every interfaced used by (or supplied by) the module is created. If a module fails to load and the kernel complains that the module disagrees about a version of some interface, you can use &quot;&#8211;force-modversion&quot; to remove the version information altogether. Naturally, this check is there for your protection, so using this option is dangerous unless you know what you&#8217;re doing. </p>
<p> This applies any modules inserted: both the module (or alias) on the command line and any modules on which it depends.</dl>
<p> <code>-f</code>, <code>&#8211;force</code></p>
<dl>
<dd>Try to strip any versioning information from the module which might otherwise stop it from loading: this is the same as using both <code>&#8211;force-vermagic</code> and <code>&#8211;force-modversion</code>. Naturally, these checks are there for your protection, so using this option is dangerous unless you know what you are doing. </p>
<p> This applies to any modules inserted: both the module (or alias) on the command line and any modules it on which it depends.</dl>
<p> <code>-i</code>, <code>&#8211;ignore-install</code>, <code>&#8211;ignore-remove</code></p>
<dl>
<dd>This option causes <code>modprobe</code> to ignore <code>install</code> and <code>remove</code> commands in the configuration file (if any) for the module specified on the command line (any dependent modules are still subject to commands set for them in the configuration file). Both <code>install</code> and <code>remove</code> commands will currently be ignored when this option is used regardless of whether the request was more specifically made with only one or other (and not both) of <code>&#8211;ignore-install</code> or <code>&#8211;ignore-remove</code>. See <code><a href="/docs/linux/man/5-modprobe-d/">modprobe.d</a></code>(5).</dl>
<p> <code>-n</code>, <code>&#8211;dry-run</code>, <code>&#8211;show</code></p>
<dl>
<dd>This option does everything but actually insert or delete the modules (or run the install or remove commands). Combined with <code>-v</code>, it is useful for debugging problems. For historical reasons both <code>&#8211;dry-run</code> and <code>&#8211;show</code> actually mean the same thing and are interchangeable.</dl>
<p> <code>-q</code>, <code>&#8211;quiet</code></p>
<dl>
<dd>With this flag, <code>modprobe</code> won&#8217;t print an error message if you try to remove or insert a module it can&#8217;t find (and isn&#8217;t an alias or <code>install</code>/<code>remove</code> command). However, it will still return with a non-zero exit status. The kernel uses this to opportunistically probe for modules which might exist using request_module.</dl>
<p> <code>-R</code>, <code>&#8211;resolve-alias</code></p>
<dl>
<dd>Print all module names matching an alias. This can be useful for debugging module alias problems.</dl>
<p> <code>-r</code>, <code>&#8211;remove</code></p>
<dl>
<dd>This option causes <code>modprobe</code> to remove rather than insert a module. If the modules it depends on are also unused, <code>modprobe</code> will try to remove them too. Unlike insertion, more than one module can be specified on the command line (it does not make sense to specify module parameters when removing modules). </p>
<p> There is usually no reason to remove modules, but some buggy modules require it. Your distribution kernel may not have been built to support removal of modules at all.</dl>
<p> <code>-S</code>, <code>&#8211;set-version</code></p>
<dl>
<dd>Set the kernel version, rather than using <code><a href="/docs/linux/man/2-uname/">uname</a></code>(2) to decide on the kernel version (which dictates where to find the modules).</dl>
<p> <code>&#8211;show-depends</code></p>
<dl>
<dd>List the dependencies of a module (or alias), including the module itself. This produces a (possibly empty) set of module filenames, one per line, each starting with &quot;insmod&quot; and is typically used by distributions to determine which modules to include when generating initrd/initramfs images. <code>Install</code> commands which apply are shown prefixed by &quot;install&quot;. It does not run any of the install commands. Note that <code><a href="/docs/linux/man/8-modinfo/">modinfo</a></code>(8) can be used to extract dependencies of a module from the module itself, but knows nothing of aliases or install commands.</dl>
<p> <code>-s</code>, <code>&#8211;syslog</code></p>
<dl>
<dd>This option causes any error messages to go through the syslog mechanism (as LOG_DAEMON with level LOG_NOTICE) rather than to standard error. This is also automatically enabled when stderr is unavailable. </p>
<p> This option is passed through <code>install</code> or <code>remove</code> commands to other <code>modprobe</code> commands in the MODPROBE_OPTIONS environment variable.</dl>
<p> <code>-V</code>, <code>&#8211;version</code></p>
<dl>
<dd>Show version of program and exit.</dl>
<p> <code>-v</code>, <code>&#8211;verbose</code></p>
<dl>
<dd>Print messages about what the program is doing. Usually <code>modprobe</code> only prints messages if something goes wrong. </p>
<p> This option is passed through <code>install</code> or <code>remove</code> commands to other <code>modprobe</code> commands in the MODPROBE_OPTIONS environment variable.</dl>
<h2>Environment</h2>
<p>The MODPROBE_OPTIONS environment variable can also be used to pass arguments to <code>modprobe</code>.</p>
