<p>mozilla_plugin_selinux &#8211; Security Enhanced Linux Policy for the mozilla_plugin processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the mozilla_plugin processes via flexible mandatory access control. The mozilla_plugin processes execute with the mozilla_plugin_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep mozilla_plugin_t</code> </p>
<h2>Entrypoints</h2>
<p>The mozilla_plugin_t SELinux type can be entered via the <code>mozilla_plugin_exec_t</code> file type. </p>
<p> The default entrypoint paths for the mozilla_plugin_t domain are the following: </p>
<p> /usr/lib/xulrunner[^/]*/plugin-container, /usr/lib/nspluginwrapper/npviewer.bin, /usr/bin/nspluginscan, /usr/bin/nspluginviewer, /usr/libexec/WebKitPluginProcess, /usr/lib/firefox/plugin-container</p>
<h2>Process Types</h2>
<p>SELinux defines process types (domains) for each process running on the system </p>
<p> You can see the context of a process using the <code>-Z</code> option to <code>psP Policy governs the access confined processes have to files. SELinux mozilla_plugin policy is very flexible allowing users to setup their mozilla_plugin processes in as secure a method as possible. </p>
<p> The following process types are defined for mozilla_plugin: </p>

<p> Note: <code>semanage permissive -a mozilla_plugin_t</code> can be used to make the process type mozilla_plugin_t permissive. SELinux does not deny access to permissive process types, but the AVC (SELinux denials) messages are still generated.</p>
<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. mozilla_plugin policy is extremely flexible and has several booleans that allow you to manipulate the policy and run mozilla_plugin with the tightest access possible. </p>
<p> If you want to allow mozilla plugin domain to bind unreserved tcp/udp ports, you must turn on the mozilla_plugin_bind_unreserved_ports boolean. Disabled by default. </p>
<p> <code>setsebool -P mozilla_plugin_bind_unreserved_ports 1</code> </p>
<p> If you want to allow mozilla plugin domain to connect to the network using TCP, you must turn on the mozilla_plugin_can_network_connect boolean. Disabled by default. </p>
<p> <code>setsebool -P mozilla_plugin_can_network_connect 1</code> </p>
<p> If you want to allow mozilla plugin to use Bluejeans, you must turn on the mozilla_plugin_use_bluejeans boolean. Disabled by default. </p>
<p> <code>setsebool -P mozilla_plugin_use_bluejeans 1</code> </p>
<p> If you want to allow mozilla plugin to support GPS, you must turn on the mozilla_plugin_use_gps boolean. Disabled by default. </p>
<p> <code>setsebool -P mozilla_plugin_use_gps 1</code> </p>
<p> If you want to allow mozilla plugin to support spice protocols, you must turn on the mozilla_plugin_use_spice boolean. Disabled by default. </p>
<p> <code>setsebool -P mozilla_plugin_use_spice 1</code> </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Disabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code> </p>
<p> If you want to allow regular users direct dri device access, you must turn on the selinuxuser_direct_dri_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P selinuxuser_direct_dri_enabled 1</code> </p>
<p> If you want to allow all unconfined executables to use libraries requiring text relocation that are not labeled textrel_shlib_t, you must turn on the selinuxuser_execmod boolean. Enabled by default. </p>
<p> <code>setsebool -P selinuxuser_execmod 1</code> </p>
<p> If you want to allow unconfined users to transition to the Mozilla plugin domain when running xulrunner plugin-container, you must turn on the unconfined_mozilla_plugin_transition boolean. Enabled by default. </p>
<p> <code>setsebool -P unconfined_mozilla_plugin_transition 1</code> </p>

<p> <code>setsebool -P use_ecryptfs_home_dirs 1</code> </p>

<p> <code>setsebool -P use_fusefs_home_dirs 1</code> </p>

<p> <code>setsebool -P use_nfs_home_dirs 1</code> </p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux mozilla_plugin policy is very flexible allowing users to setup their mozilla_plugin processes in as secure a method as possible. </p>
<p> STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the mozilla_plugin, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t mozilla_plugin_tmpfs_t &#8216;/srv/mymozilla_plugin_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/mymozilla_plugin_content</code> </p>
<p> Note: SELinux often uses regular expressions to specify labels that match multiple files. </p>
<p> <i>The following file types are defined for mozilla_plugin:</i> </p>
<p> <code>mozilla_plugin_config_exec_t</code> </p>
<p> &#8211; Set files with the mozilla_plugin_config_exec_t type, if you want to transition an executable to the mozilla_plugin_config_t domain. </p>
<p> <code>mozilla_plugin_exec_t</code> </p>
<p> &#8211; Set files with the mozilla_plugin_exec_t type, if you want to transition an executable to the mozilla_plugin_t domain. </p>

<dd>/usr/lib/xulrunner[^/]*/plugin-container, /usr/lib/nspluginwrapper/npviewer.bin, /usr/bin/nspluginscan, /usr/bin/nspluginviewer, /usr/libexec/WebKitPluginProcess, /usr/lib/firefox/plugin-container </p>

<p> <code>mozilla_plugin_rw_t</code> </p>

<p> <code>mozilla_plugin_tmp_t</code> </p>
