<p>xdm_selinux &#8211; Security Enhanced Linux Policy for the xdm processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the xdm processes via flexible mandatory access control. The xdm processes execute with the xdm_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep xdm_t</code> </p>
<h2>Entrypoints</h2>
<p>The xdm_t SELinux type can be entered via the <code>xdm_exec_t</code> file type. </p>
<p> The default entrypoint paths for the xdm_t domain are the following: </p>
<p> /usr/s?bin/<a href="/docs/linux/man/3-gdm/">gdm</a>(3)?, /usr/s?bin/lightdm*, /usr/s?bin/[mxgkw]dm, /usr/s?bin/gdm-binary, /usr/s?bin/lxdm(-binary)?, /usr/X11R6/bin/[xgkw]dm, /usr/bin/razor-lightdm-.*, /usr/bin/sddm, /usr/bin/slim, /usr/bin/gpe-dm, /opt/kde3/bin/kdm, /usr/sbin/mdm-binary, /usr/bin/sddm-greeter, /etc/rc.d/init.d/x11-common</p>
<h2>Process Types</h2>
<p>SELinux defines process types (domains) for each process running on the system </p>
<p> You can see the context of a process using the <code>-Z</code> option to <code>psP Policy governs the access confined processes have to files. SELinux xdm policy is very flexible allowing users to setup their xdm processes in as secure a method as possible. </p>
<p> The following process types are defined for xdm: </p>
<p> xdm_t, xdm_unconfined_t</code> </p>
<p> Note: <code>semanage permissive -a xdm_t</code> can be used to make the process type xdm_t permissive. SELinux does not deny access to permissive process types, but the AVC (SELinux denials) messages are still generated.</p>
<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. xdm policy is extremely flexible and has several booleans that allow you to manipulate the policy and run xdm with the tightest access possible. </p>
<p> If you want to allows xdm_t to bind on vnc_port_t(5910), you must turn on the xdm_bind_vnc_tcp_port boolean. Disabled by default. </p>
<p> <code>setsebool -P xdm_bind_vnc_tcp_port 1</code> </p>
<p> If you want to allow the graphical login program to execute bootloader, you must turn on the xdm_exec_bootloader boolean. Disabled by default. </p>
<p> <code>setsebool -P xdm_exec_bootloader 1</code> </p>
<p> If you want to allow the graphical login program to login directly as sysadm_r:sysadm_t, you must turn on the xdm_sysadm_login boolean. Disabled by default. </p>
<p> <code>setsebool -P xdm_sysadm_login 1</code> </p>
<p> If you want to allow the graphical login program to create files in HOME dirs as xdm_home_t, you must turn on the xdm_write_home boolean. Enabled by default. </p>
<p> <code>setsebool -P xdm_write_home 1</code> </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to allow users to login using a radius server, you must turn on the authlogin_radius boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_radius 1</code> </p>
<p> If you want to allow users to login using a yubikey OTP server or challenge response mode, you must turn on the authlogin_yubikey boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_yubikey 1</code> </p>
<p> If you want to allow all daemons the ability to read/write terminals, you must turn on the daemons_use_tty boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tty 1</code> </p>
<p> If you want to deny user domains applications to map a memory region as both executable and writable, this is dangerous and the executable should be reported in bugzilla, you must turn on the deny_execmem boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_execmem 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Disabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code> </p>
<p> If you want to enable polyinstantiated directory support, you must turn on the polyinstantiation_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P polyinstantiation_enabled 1</code> </p>
<p> If you want to allow unconfined executables to make their stack executable. This should never, ever be necessary. Probably indicates a badly coded executable, but could indicate an attack. This executable should be reported in bugzilla, you must turn on the selinuxuser_execstack boolean. Enabled by default. </p>
<p> <code>setsebool -P selinuxuser_execstack 1</code> </p>
<p> If you want to support ecryptfs home directories, you must turn on the use_ecryptfs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_ecryptfs_home_dirs 1</code> </p>
<p> If you want to support fusefs home directories, you must turn on the use_fusefs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_fusefs_home_dirs 1</code> </p>
<p> If you want to support NFS home directories, you must turn on the use_nfs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_nfs_home_dirs 1</code> </p>
<p> If you want to support SAMBA home directories, you must turn on the use_samba_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_samba_home_dirs 1</code> </p>
<p> If you want to support X userspace object manager, you must turn on the xserver_object_manager boolean. Enabled by default. </p>
<p> <code>setsebool -P xserver_object_manager 1</code></p>
<h2>Port Types</h2>
<p>SELinux defines port types to represent TCP and UDP ports. </p>

<p> Policy governs the access confined processes have to these ports. SELinux xdm policy is very flexible allowing users to setup their xdm processes in as secure a method as possible. </p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux xdm policy is very flexible allowing users to setup their xdm processes in as secure a method as possible. </p>
<p> EQUIVALENCE DIRECTORIES</code> </p>
<p> xdm policy stores data with multiple different file context types under the /var/run/<a href="/docs/linux/man/3-gdm/">gdm</a>(3)? directory.
