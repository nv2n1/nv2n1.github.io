<p>xfs_metadump &#8211; copy XFS filesystem metadata to a file</p>
<h2>Synopsis</h2>
<p><code>xfs_metadump</code> [ <code>-aefFgow</code> ] [ <code>-m</code> <i>max_extents</i> ] ] [ <code>-l</code> <i>logdev</i> ] <i>source</i> <i>target</i><br />
 <code>xfs_metadump -V</code></p>
<h2>Description</h2>
<p><code>xfs_metadump</code> is a debugging tool that copies the metadata from an XFS filesystem to a file. The <i>source</i> argument must be the pathname of the device or file containing the XFS filesystem and the <i>target</i> argument specifies the destination file name. If <i>target</i> is -, then the output is sent to stdout. This allows the output to be redirected to another program such as a compression application. <code>xfs_metadump</code> may only be used to copy unmounted filesystems, or read-only mounted filesystems. <code>xfs_metadump</code> does not alter the source filesystem in any way. The <i>target</i> image is a contiguous (non-sparse) file containing all the filesystem&#8217;s metadata and indexes to where the blocks were copied from. By default, <code>xfs_metadump</code> obfuscates most file (regular file, directory and symbolic link) names and extended attribute names to allow the dumps to be sent without revealing confidential information. Extended attribute values are zeroed and no data is copied. The only exceptions are file or attribute names that are 4 or less characters in length. Also file names that span extents (this can only occur with the <code><a href="/docs/linux/man/8-mkfs-xfs/">mkfs.xfs</a></code>(8) options where <code>-n</code> <i>size</i> &gt; <code>-b</code> <i>size</i>) are not obfuscated. Names between 5 and 8 characters in length inclusively are partially obfuscated. <code>xfs_metadump</code> should not be used for any purposes other than for debugging and reporting filesystem problems. The most common usage scenario for this tool is when <code><a href="/docs/linux/man/8-xfs_repair/">xfs_repair</a></code>(8) fails to repair a filesystem and a metadump image can be sent for analysis. The file generated by <code>xfs_metadump</code> can be restored to filesystem image (minus the data) using the <code><a href="/docs/linux/man/8-xfs_mdrestore/">xfs_mdrestore</a></code>(8) tool. </p>
<h2>Options</h2>
<dl>
<dt><code>-a</code></p>
<dd>Copies entire metadata blocks. Normally, <code>xfs_metadump</code> will zero any stale bytes interspersed with in-use metadata. Use this option to copy full metadata blocks, to provide more debugging information for a corrupted filesystem. Note that the extra data will be unobfuscated.</p>
<dt><code>-e</code></p>
<dd>Stops the dump on a read error. Normally, it will ignore read errors and copy all the metadata that is accessible.</p>
<dt><code>-f</code></p>
<dd>Specifies that the filesystem image to be processed is stored in a regular file (see the <code>mkfs.xfs -d</code> file option). This can also happen if an image copy of a filesystem has been made into an ordinary file with <code><a href="/docs/linux/man/8-xfs_copy/">xfs_copy</a></code>(8).</p>
<dt><code>-F</code></p>
<dd>Specifies that we want to continue even if the superblock magic is not correct. If the source is truly not an XFS filesystem, the resulting image will be useless, and xfs_metadump may crash.</p>
<dt><code>-g</code></p>
<dd>Shows dump progress. This is sent to stdout if the <i>target</i> is a file or to stderr if the <i>target</i> is stdout.</p>
<dt><code>-l</code><i> logdev</i></p>
<dd>For filesystems which use an external log, this specifies the device where the external log resides. The external log is not copied, only internal logs are copied.</p>
<dt><code>-m</code></p>
<dd>Set the maximum size of an allowed metadata extent. Extremely large metadata extents are likely to be corrupt, and will be skipped if they exceed this value. The default size is 1000 blocks.</p>
<dt><code>-o</code></p>
<dd>Disables obfuscation of file names and extended attributes.</p>
<dt><code>-w</code></p>
<dd>Prints warnings of inconsistent metadata encountered to stderr. Bad metadata is still copied.</p>
<dt><code>-V</code></p>
<dd>Prints the version number and exits.</dl>
<h2>Diagnostics</h2>
<p><code>xfs_metadump</code> returns an exit code of 0 if all readable metadata is successfully copied or 1 if a write error occurs or a read error occurs and the <code>-e</code> option used.</p>
<h2>Notes</h2>
<p>As <code>xfs_metadump</code> copies metadata only, it does not matter if the <i>source</i> filesystem has a realtime section or not. If the filesystem has an external log, it is not copied. Internal logs are copied and any outstanding log transactions are not obfuscated if they contain names. </p>
<p> <code>xfs_metadump</code> is a shell wrapper around the <code><a href="/docs/linux/man/8-xfs_db/">xfs_db</a></code>(8) <code>metadump</code> command.</p>
