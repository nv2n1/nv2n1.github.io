<p>nfsd_selinux &#8211; Security Enhanced Linux Policy for the nfsd processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the nfsd processes via flexible mandatory access control. The nfsd processes execute with the nfsd_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep nfsd_t</code> </p>
<h2>Entrypoints</h2>
<p>The nfsd_t SELinux type can be entered via the <code>nfsd_exec_t</code> file type. </p>
<p> The default entrypoint paths for the nfsd_t domain are the following: </p>
<p> /usr/sbin/rpc.nfsd, /usr/sbin/rpc.mountd</p>

<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. nfsd policy is extremely flexible and has several booleans that allow you to manipulate the policy and run nfsd with the tightest access possible. </p>
<p> If you want to allow any files/directories to be exported read/only via NFS, you must turn on the nfs_export_all_ro boolean. Enabled by default. </p>
<p> <code>setsebool -P nfs_export_all_ro 1</code> </p>
<p> If you want to allow any files/directories to be exported read/write via NFS, you must turn on the nfs_export_all_rw boolean. Enabled by default. </p>
<p> <code>setsebool -P nfs_export_all_rw 1</code> </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to allow all daemons to write corefiles to /, you must turn on the daemons_dump_core boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_dump_core 1</code> </p>
<p> If you want to enable cluster mode for daemons, you must turn on the daemons_enable_cluster_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P daemons_enable_cluster_mode 1</code> </p>
<p> If you want to allow all daemons to use tcp wrappers, you must turn on the daemons_use_tcp_wrapper boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tcp_wrapper 1</code> </p>
<p> If you want to allow all daemons the ability to read/write terminals, you must turn on the daemons_use_tty boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tty 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Disabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code></p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux nfsd policy is very flexible allowing users to setup their nfsd processes in as secure a method as possible. </p>
<p> STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the nfsd, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t nfsd_unit_file_t &#8216;/srv/mynfsd_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/mynfsd_content</code> </p>

<p> <i>The following file types are defined for nfsd:</i> </p>
<p> <code>nfsd_exec_t</code> </p>
<p> &#8211; Set files with the nfsd_exec_t type, if you want to transition an executable to the nfsd_t domain. </p>
<dl>
<dt>Paths:</p>
<dd>/usr/sbin/rpc.nfsd, /usr/sbin/rpc.mountd </p>
</dl>
<p> <code>nfsd_fs_t</code> </p>
<p> &#8211; Set files with the nfsd_fs_t type, if you want to treat the files as nfsd fs data. </p>
<p> <code>nfsd_initrc_exec_t</code> </p>
<p> &#8211; Set files with the nfsd_initrc_exec_t type, if you want to transition an executable to the nfsd_initrc_t domain. </p>
<p> <code>nfsd_unit_file_t</code> </p>
<p> &#8211; Set files with the nfsd_unit_file_t type, if you want to treat the files as nfsd unit content. </p>
<p> Note: File context can be temporarily modified with the chcon command. If you want to permanently change the file context you need to use the <code>semanage fcontext</code> command. This will modify the SELinux labeling database. You will need to use <code>restorecon</code> to apply the labels.</p>
<h2>Sharing Files</h2>
<p>If you want to share files with multiple domains (Apache, FTP, rsync, Samba), you can set a file context of public_content_t and public_content_rw_t. These context allow any of the above domains to read the content. If you want a particular domain to write to the public_content_rw_t domain, you must set the appropriate boolean.</p>
<dl>
<dt>Allow nfsd servers to read the /var/nfsd directory by adding the public_content_t file type to the directory and by restoring the file type.</p>
<dd></dl>
<p> <code>semanage fcontext -a -t public_content_t &quot;/var/nfsd(/.*)?&quot;</code><br />
 <code>restorecon -F -R -v /var/nfsd</code></p>
<dl>
<dt>Allow nfsd servers to read and write /var/nfsd/incoming by adding the public_content_rw_t type to the directory and by restoring the file type. You also need to turn on the nfsd_anon_write boolean.</p>
<dd></dl>
<p> <code>semanage fcontext -a -t public_content_rw_t &quot;/var/nfsd/incoming(/.*)?&quot;</code><br />
 <code>restorecon -F -R -v /var/nfsd/incoming</code><br />
 <code>setsebool -P nfsd_anon_write 1</code> </p>
<p> If you want to allow nfs servers to modify public files used for public file transfer services. Files/Directories must be labeled public_content_rw_t., you must turn on the nfsd_anon_write boolean. </p>
<p> <code>setsebool -P nfsd_anon_write 1</code></p>
