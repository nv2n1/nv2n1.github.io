<p>fxotune &#8211; automatically tune DAHDI FXO channels</p>
<h2>Synopsis</h2>
<p><code>fxotune -i </code> <i>[options]</i> &#8211; detect mode </p>
<p> <code>fxotune -d</code> <i>[ options ]</i> &#8211; dump mode </p>
<p> <code>fxotune -s</code> &#8211; Startup mode</p>
<h2>
<h2>Description</h2>
</h2>
<p><code>fxotune </code> is a script that fine-tune parameters of the FXO modules of the card. It has three modes of operation: <i>Detect mode (-i):</i> it detects and tunes all the available FXO channels. It writes settings to a configuration file (/etc/fxotune.conf) from which it can be loaded (e.g: at startup) using -s . <i>Dump mode (-d):</i> Runs detection on a single DAHDI channel, and just dumps waveforms to <code>fxotune_dump.vals</code> is generated in the current directory. <i>Startup mode (-s):</i> fxotune just reads the settings from fxotune.conf into the FXO modules. You are advised to run fxotune on all FXO ports you have that support it and that are connected. Note that the tunning is affected by e.g. the physical parameters of the connection, and thus if it has been radically changed, you may need to re-run fxotune. This program only works for the Digium TDM400P/800P/2400P cards and compatible and the Xorcom Astribank devices. Other cards (notably X100P cards and clones) do not have the hardware to support such tuning. The tuning process needs a clear line to do the tuning. In order to do that, it runs in cycles of the following: sets the line off-hook, dials a dial string (which should set the PSTN provider waiting for the next digit), and then starts tuning. It has a limited ammount of time for tuning before the PSTN gives up and gives a busy tone. So after a while it hangs up and starts a new cycle. <code>fxotune</code> has two operation modes: tune (-i) and set (-s). In the tune mode it generates /etc/fxotune.conf, and in the set mode it merely applies the parameters from fxotune.conf to device&#8217;s ports. </p>
<h2>Options</h2>
<p>The following options below except -v (verbose) affect only the detection process and hence apply only to the <i>detect</i> and <i>dump</i> modes. </p>
<p> In addition, to maintain compatibility with older versions of fxotune, if in detect or dump mode there is a parameter with option before it, it is considered to be the <i>dialstring</i> parameter (-n). </p>
<p> <code>-b</code> <i>startdev</i></p>
<dl>
<dd>Start tuning from dahdi channel num. <i> startdev</i>: skip all previous channels. By default starting from channel 1. </p>
<p> In dump mode (-d) this is the single channel that will be tested.</dl>
<p> <code>-e</code> <i>stopdev</i></p>
<dl>
<dd>Tune only up to dahdi channel num. <i> stopdev</i>: skip all previous channels. By default stopping at channel 252. </p>
<p> In dump mode (-d) this parameter is ignored.</dl>
<p> <code>-l</code> <i>delay-to-silence</i></p>
<dl>
<dd>Time in seconds to wait after dialing the dial-string to get a clear line. The default is 0. before</dl>
<p> <code>-m</code> <i>silence-good-for</i></p>
<dl>
<dd>Time in seconds which states how long the PSTN will wait after we dialed the dial-string until it starts giving a busy tone. You can test this by connecting an analog phone to the line and dialing. </p>
<p> The default is 18 (18 seconds).</dl>
<p> <code>-n</code> <i>dial-string</i></p>
<dl>
<dd>Digits to dial to the PSTN in order to get it stop its dialtone and waiting for the next digit. </p>
<p> The default is &quot;4&quot; (sending just the digit 4). It should work in most cases. Again, this can be tested by connecting a phone to the PSTN line and dialing the dial-string.</dl>
<p> <code>-t</code> <i>detect-type</i></p>
<dl>
<dd>This option allows using the older detection method used by fxotune of Zaptel 1.2. use <code>-t 1</code> for that older method. whereas <code>-t 2</code> (the default) uses the current method. </p>
<p> This option only applies to detect mode (-i).</dl>
<p> <code>-v[vvvv]</code></p>
<dl>
<dd>Sets debugging on. The more v-s, the higher debug level. </p>
<p> Note that: -vv -v will actually set debug level to 1 instead of 3.</dl>
<p> <code>-w</code> <i>wave-form</i></p>
<dl>
<dd>The default: -1, for multitone waveform. Alternatively: a frequency of a single tone. </p>
<p> This option only applies to dump mode (-d).</dl>
<h2>Examples</h2>
<dl>
<dd>fxotune -i 9</dl>
<p> if you need to dial 9 for an external line. If you always get a line, you can simply use any digit. <code>-s</code></p>
<dl>
<dd>Load settings from the last test. Used at startup.</dl>
<h2>Files</h2>
<p><i>/etc/fxotune.conf</i></p>
<dl>
<dd>The configuration file generated by fxotune in detect mode and from which configuration is loaded when <code>-s</code> is used. </p>
</dl>
<h2>Notes</h2>
<p>Running fxotune takes approximately a minute per port. If you wish to only run fxotune for several ports, you can use the options -b and -e to set a specific range of ports. Another useful trick is to actually keep asterisk running, and only &quot;destroy&quot; the dahdi channels you wish to tune (dahdi destroy channel NNN): other channels will be used by Asterisk, and hence skipped. This can be useful if you have many FXO ports that are not connected. <code>fxotune</code> writes immediately to <code>/etc/fxotune.conf</code> so if you stop it half-way, you may get a half-configured system. If you have already tuned your FXO channels and wish to test-run fxotune again, you are advised to backup /etc/fxotune.conf . The default for -m is 18 seconds. This asusmes that you get a clear line for at least 18 seconds. It is advised that you test that timeout earlier by connecting a phone to the FXO line, dialing 4 (or whatever dial string you put with -n) and see how much time of silence you have. If you connect your device to a PSTN provider that is not in the US, there is a similar operation you should apply before even getting to fxotune: setting the opermode. The opermode sets a number of country-specific parameters. For the Digium analog cards this is set through the kernel module parameter &#8216;opermode&#8217; . For the Xorcom Astribank this is set through the variable &#8216;opermode&#8217; in /etc/dahdi/xpp.conf . For valid values of this parameter, see /usr/share/asterisk/init_fxo_modes (FIXME: this has changed and will change. Tzafrir). </p>
