<p>kernel-install &#8211; Add and remove kernel and initramfs images to and from /boot</p>
<h2>Synopsis</h2>
<dl>
<dt> <code>kernel-install</code> COMMAND [OPTIONS&#8230;] <i>KERNEL-VERSION</i> <i>KERNEL-IMAGE</i> [<i>INITRD-FILE</i>&#8230;]</dl>
<h2>Description</h2>
<p><code>kernel-install</code></p>
<dd>is used to install and remove kernel and initramfs images to and from the boot loader partition, referred to as <i>$BOOT</i> here. It will usually be one of /boot/, /efi/, or /boot/efi/, see below. </p>
<p> <code>kernel-install</code> will execute the files located in the directory /usr/lib/kernel/install.d/ and the local administration directory /etc/kernel/install.d/. All files are collectively sorted and executed in lexical order, regardless of the directory in which they live. However, files with identical filenames replace each other. Files in /etc/kernel/install.d/ take precedence over files with the same name in /usr/lib/kernel/install.d/. This can be used to override a system-supplied executables with a local file if needed; a symbolic link in /etc/kernel/install.d/ with the same name as an executable in /usr/lib/kernel/install.d/, pointing to /dev/null, disables the executable entirely. Executables must have the extension &quot;.install&quot;; other extensions are ignored. </p>
<p> An executable should return <code>0</code> on success. It may also return <code>77</code> to cause the whole operation to terminate (executables later in lexical order will be skipped).</p>
<h2>Commands</h2>
<p>The following commands are understood: </p>
<p> <code>add </code><i>KERNEL-VERSION</i><i>KERNEL-IMAGE</i><code> [</code><i>INITRD-FILE</i><code> &#8230;]</code></p>
<dl>
<dd>This command expects a kernel version string and a path to a kernel image file as arguments. <code>kernel-install</code> calls the executables from /usr/lib/kernel/install.d/*.install and /etc/kernel/install.d/*.install with the following arguments: </p>
<dl>
<dd>
<pre>add <i>KERNEL-VERSION</i> $BOOT/<i>MACHINE-ID</i>/<i>KERNEL-VERSION</i>/ <i>KERNEL-IMAGE</i> [<i>INITRD-FILE</i> ...]</pre>
</dl>
<p> Three default plugins execute the following operations in this case: </p>
<dl>
<dd>&bull; 00-entry-directory.install creates the directory $BOOT/<i>MACHINE-ID</i>/<i>KERNEL-VERSION</i>/ if $BOOT/<i>MACHINE-ID</i>/ already exists.</dl>
<dl>
<dd>&bull; 50-depmod.install runs <code><a href="/docs/linux/man/8-depmod/">depmod</a></code>(8) for the <i>KERNEL-VERSION</i>.</dl>
<dl>
<dd>&bull; 90-loaderentry.install copies <i>KERNEL-IMAGE</i> to $BOOT/<i>MACHINE-ID</i>/<i>KERNEL-VERSION</i>/linux. If an <i>INITRD-FILE</i> is provided, it also copies <i>INITRD-FILE</i> to $BOOT/<i>MACHINE-ID</i>/<i>KERNEL_VERSION</i>/<i>INITRD-FILE</i>. It also creates a boot loader entry according to the m[blue]<code>Boot Loader Specification</code>m[]<font SIZE="-2">[1]</font> in $BOOT/loader/entries/<i>MACHINE-ID</i>&#8211;<i>KERNEL-VERSION</i>.conf. The title of the entry is the <i>PRETTY_NAME</i> parameter specified in /etc/os-release or /usr/lib/os-release (if the former is missing), or &quot;Linux <i>KERNEL-VERSION</i>&quot;, if unset. </p>
<p> If the entry directory $BOOT/<i>MACHINE-ID</i>/<i>KERNEL-VERSION</i>/ does not exist, this plugin does nothing.</dl>
</dl>
<p> <code>remove </code><i>KERNEL-VERSION</i></p>
<dl>
<dd>This command expects a kernel version string as single argument. This calls executables from /usr/lib/kernel/install.d/*.install and /etc/kernel/install.d/*.install with the following arguments: </p>
<dl>
<dd>
<pre>remove <i>KERNEL-VERSION</i> $BOOT/<i>MACHINE-ID</i>/<i>KERNEL-VERSION</i>/</pre>
</dl>
<p> Afterwards, <code>kernel-install</code> removes the directory $BOOT/<i>MACHINE-ID</i>/<i>KERNEL-VERSION</i>/ and its contents. </p>
<p> Two default plugins execute the following operations in this case: </p>
<dl>
<dd>&bull; 50-depmod.install removes the files generated by <code>depmod</code> for this kernel again.</dl>
<dl>
<dd>&bull; 90-loaderentry.install removes the file $BOOT/loader/entries/<i>MACHINE-ID</i>&#8211;<i>KERNEL-VERSION</i>.conf.</dl>
</dl>
<h2>The Fi$Bootfr Partition</h2>
<p>The partition where the kernels and m[blue]<code>Boot Loader Specification</code>m[]<font SIZE="-2">[1]</font> snippets are located is called <i>$BOOT</i>. <code>kernel-install</code> determines the location of this partition by checking /efi/, /boot/, and /boot/efi/ in turn. The first location where $BOOT/loader/entries/ or $BOOT/$MACHINE_ID/ exists is used.</p>
<h2>Options</h2>
<p>The following options are understood: </p>
<p> <code>-v</code>, <code>&#8211;verbose</code></p>
<dl>
<dd>Output additional information about operations being performed.</dl>
<p> <code>-h</code>, <code>&#8211;help</code></p>
<dl>
<dd>Print a short help text and exit.</dl>
<h2>Environment Variables</h2>
<p>If <code>&#8211;verbose</code> is used, <i>$KERNEL_INSTALL_VERBOSE=1</i> will be set for the plugins. They may output additional logs in this case.</p>
<h2>Exit Status</h2>
<p>If every executable returns 0 or 77, 0 is returned, and a non-zero failure code otherwise.</p>
<h2>Files</h2>
<p>/usr/lib/kernel/install.d/*.install /etc/kernel/install.d/*.install</p>
<dl>
<dd>Drop-in files which are executed by kernel-install.</dl>
<p> /etc/kernel/cmdline /proc/cmdline</p>
<dl>
<dd>Read by 90-loaderentry.install. The content of the file /etc/kernel/cmdline specifies the kernel command line to use. If that file does not exist, /proc/cmdline is used.</dl>
<p> /etc/kernel/tries</p>
<dl>
<dd>Read by 90-loaderentry.install. If this file exists a numeric value is read from it and the naming of the generated entry file is slightly altered to include it as $BOOT/loader/entries/<i>MACHINE-ID</i>&#8211;<i>KERNEL-VERSION</i>+<i>TRIES</i>.conf. This is useful for boot loaders such as <code><a href="/docs/linux/man/7-systemd-boot/">systemd-boot</a></code>(7) which implement boot attempt counting with a counter embedded in the entry file name.</dl>
<p> /etc/machine-id</p>
<dl>
<dd>The content of this file specifies the machine identification <i>MACHINE-ID</i>. If it cannot read /etc/machine-id, kernel-install will use &quot;Linux&quot; as the machine ID instead.</dl>
<p> /etc/os-release /usr/lib/os-release</p>
<dl>
<dd>The content of the file specifies the operating system title <i>PRETTY_NAME</i>.</dl>
