<p>ksplice-apply &#8211; Apply an on-disk Ksplice update to the running kernel</p>
<h2>Synopsis</h2>
<p><code>ksplice-apply</code> [<i></i><font SIZE="-1"><i>OPTIONS</i></font><i></i>] {<i></i><font SIZE="-1"><i>UPDATE_TARBALL</i></font><i></i> | <i></i><font SIZE="-1"><i>UPDATE_TREE</i></font><i></i>}</p>
<h2>Description</h2>
<p><code>ksplice-apply</code> takes as input a Ksplice update, as generated by <i><a href="/docs/linux/man/8-ksplice-create/">ksplice-create</a></i>(8), and it applies the update to the running binary kernel. The update may be supplied in the form of a tarball or an unpacked tree. </p>
<p> The update is required to have been generated for the running kernel&#8217;s version.</p>
<h2>Options</h2>
<dl>
<dt><code>&#8211;debug</code></p>
<dd>Applies the update with debugging output enabled. Recommended only for debugging.</p>
<dt><code>&#8211;debugfile=</code><i>filename</i></p>
<dd>Sets the location where debugging output should be saved. Implies &#8211;debug.</p>
<dt><code>&#8211;partial</code></p>
<dd>Applies the update only to those modules which are loaded. Any modules patched by the update that are not loaded are ignored (without this option, Ksplice aborts if any modules patched by the update are not loaded).</p>
<dt><code>&#8211;raw-errors</code></p>
<dd>Print only raw error information designed to be machine-readable on standard error (standard output is still intended to be human-readable). If <code>ksplice-apply</code> fails due to an error from the Ksplice kernel modules, the first line on standard error will be a Ksplice <code>abort code</code> (see the Ksplice source code for documentation on these codes). Further lines will vary depending on the abort code. If <code>ksplice-apply</code> fails for any other reason, it will output the line <tt>&quot;OTHER
&quot;</tt>, followed by a human-readable failure message, to standard error.</dl>
