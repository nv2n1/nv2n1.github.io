<p>kbuildsycoca5 &#8211; Rebuilds the KService desktop file system configuration cache.</p>
<h2>Synopsis</h2>
<dl>
<dt> <code>kbuildsycoca5</code> [<i>OPTIONS</i>&#8230;]</dl>
<h2>Description</h2>
<p><code>kbuildsycoca5</code></p>
<dd>builds binary cache of the data stored in .desktop and MIME type .xml files that the KService framework uses to find plugins, applications and other services. </p>
<p> The KService library uses this database to efficiently provide the information requested of it. </p>
<p> Users do not normally need to run this application directly; KService will run it if necessary, when any of the files whose data is cached are changed.</p>
<h2>Options</h2>
<p><code>&#8211;global</code></p>
<dl>
<dd>Ignores any user-set files (in <i>XDG_DATA_HOME</i>). This is currently only supported on Unix systems.</dl>
<p> <code>&#8211;noincremental</code></p>
<dl>
<dd>Rather than using the existing cache and only updating the information that has changed or been added, start with an empty cache. Ignored if <code>&#8211;global</code> is set.</dl>
<p> <code>&#8211;nosignal</code></p>
<dl>
<dd>Ordinarily, <code>kbuildsyscoca5</code> sends a signal over D-Bus once the cache is updated to all the applications that use KService so that they are always working with the latest information. This option suppresses that behaviour.</dl>
<p> <code>&#8211;menutest</code></p>
<dl>
<dd>Test the generation of the application menu database. Does not actually build the cache.</dl>
<p> <code>&#8211;testmode</code></p>
<dl>
<dd>Use the QStandardPaths &quot;test mode&quot; to avoid interfering with user data. This is intended for use with unit tests.</dl>
<p> <code>&#8211;track </code><i>menu-id</i></p>
<dl>
<dd>Track a menu ID for debugging.</dl>
<p> <code>&#8211;author</code></p>
<dl>
<dd>Show author information.</dl>
<p> <code>&#8211;license</code></p>
<dl>
<dd>Show license information.</dl>
<p> <code>-h, &#8211;help</code></p>
<dl>
<dd>Show a brief help text.</dl>
<p> <code>-v , &#8211;version</code></p>
<dl>
<dd>Show version information.</dl>
<h2>Files</h2>
<p><i>cachedir</i>/ksycoca5_[lang]_[sha1-of-dirs]</p>
<dl>
<dd>The KService cache generated by <code>kbuildsycoca5</code>. On Unix systems, <i>cachedir</i> is typically <code>XDG_CONFIG_HOME</code></dl>
