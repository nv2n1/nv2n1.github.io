<p>cracklib-format, cracklib-packer, cracklib-unpacker &#8211; cracklib dictionary utilities</p>
<h2>Synopsis</h2>
<p><code>cracklib-format</code> <i>file</i> <i>&#8230;</i> </p>
<p> <code>cracklib-packer</code> <i>cracklib_dictpath</i> </p>
<p> <code>cracklib-unpacker</code> <i>cracklib_dictpath</i></p>
<h2>Description</h2>
<p><code>cracklib-format</code> takes a list of text files each containing a list of words, one per line, It lowercases all words, removes control characters, and sorts the lists. It outputs the cleaned up list to standard output. The text files may be optionally compressed with <code><a href="/docs/linux/man/1-gzip/">gzip</a></code>(1). If you supply massive amounts of text to <code>cracklib-format</code> you must have enough free space available for use by the <code><a href="/docs/linux/man/1-sort/">sort</a></code>(1) command. If you do not have 20Mb free in /var/tmp (or whatever temporary area your <code><a href="/docs/linux/man/1-sort/">sort</a></code>(1) command uses), have a look at the <code>/usr/sbin/cracklib-format</code> program which is a <code><a href="/docs/linux/man/1-sh/">sh</a></code>(1) program. You can usually tweak the <code><a href="/docs/linux/man/1-sort/">sort</a></code>(1) command to use any large area of disk you desire, by use of the <code>-T</code> option. <code>cracklib-format</code> has a hook for this. <code>cracklib-packer</code> reads from standard input a list of sorted and cleaned words and creates a database in the directory and prefix given by the command line argument <code>cracklib_dictpath.</code> Three files are created with the suffixes of .hwm, .pwd, and .pwi. These three files are in the format that the <code><a href="/docs/linux/man/3-fascistcheck/">FascistCheck</a></code>(3) subroutine, <code><a href="/docs/linux/man/8-cracklib-unpacker/">cracklib-unpacker</a></code>(8), and <code><a href="/docs/linux/man/8-cracklib-check/">cracklib-check</a></code>(8), utilities understand. The number of words read and written are printed on <code><a href="/docs/linux/man/3-stdout/">stdout</a></code>(3). <code>cracklib-unpacker</code> reads from the database in the directory and prefix given by the command line argument <code>cracklib_dictpath</code> and outputs on standard output the list of words that make up the database. The database is in a binary format generated by the utilities <code><a href="/docs/linux/man/8-cracklib-format/">cracklib-format</a></code>(8) and <code><a href="/docs/linux/man/8-cracklib-packer/">cracklib-packer</a></code>(8). On a Debian system the database is located in the directory /var/cache/cracklib/cracklib_dict and is generated daily with the program /etc/cron.daily/cracklib. The location is also defined in the header file <code>crack.h</code> using the constant <code>CRACKLIB_DICTPATH</code> though none of the subroutines in the cracklib libraries have this location hardcoded into their implementations. </p>
<h2>Files</h2>
<dl>
<dt><i>/var/cache/cracklib/cracklib_dict.[hwm|pwd|pwi]</i></p>
<dd>cracklib dictionary database files used by utilities.</p>
<dt><i>/etc/cron.daily/cracklib</i></p>
<dd>cracklib daily cron program to rebuild the cracklib dictionary database.</p>
<dt><i>/etc/cracklib/cracklib.conf</i></p>
<dd>cracklib configuration file used by the cracklib daily cron program to rebuild the cracklib dictionary database.</p>
<dt><i>/usr/include/crack.h</i></p>
<dd>cracklib header file defining the subroutine <code><a href="/docs/linux/man/3-fascistcheck/">FascistCheck</a>(3)</code> and the constant <code>CRACKLIB_DICTPATH</code> used to compile in the location of the cracklib dictionary database for these utilities.</p>
<dt><i>/usr/sbin/cracklib-format</i></p>
<dd>cracklib shell script to create initial list of words for dictionary database.</dl>
