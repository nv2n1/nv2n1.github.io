<p><code>cups-browsed </code>&#8211; A daemon for browsing the Bonjour broadcasts of shared, remote CUPS printers</p>
<h2>Synopsis</h2>
<pre><code>cups-browsed</code> [<code>-v</code> | <code>-d</code> | <code>--debug</code>] [<code>-c</code> <i>config-file</i>]
[<code>-o</code> <i>option</i><code>=</code><i>value</i>] [<code>-o</code> '<i>config file line</i>'] ...
[<code>--autoshutdown=</code><i>mode</i>] [<code>--autoshutdown-timeout=</code><i>timeout</i>]
[<code>-h</code> | <code>--help</code> | <code>--version</code>]</pre>
<h2>Description</h2>
<p><code>cups-browsed</code> has four independently switchable functions:</p>
<dl>
<dt>1.</p>
<dd>Browse Bonjour broadcasts of remote printers and create/remove local raw queues pointing to these printers.</p>
<dt>2.</p>
<dd>Browse CUPS broadcasts of remote printers and create/remove local raw queues pointing to these printers.</p>
<dt>3.</p>
<dd>Browse an LDAP server for printers and create/remove local raw queues pointing to these printers.</p>
<dt>4.</p>
<dd>Broadcast local queues with the CUPS protocol.</dl>
<p> Note that 2. and 4. are only to allow communication with legacy CUPS servers (1.5.x or older) on the remote machine(s). The standard method to broadcast for shared/network printers to broadcast their presence is Bonjour. The CUPS broadcasting/browsing protocol is deprecated. cups-browsed can be run permanently (from system boot to shutdown) or on-demand (for example to save resources on mobile devices). For running it on-demand an auto-shutdown feature can be activated to let cups-browsed terminate when it does not have queues any more to take care of. </p>
<h2>Options</h2>
<dl>
<dt><code>-v</code>, <code>-d</code>, <code>&#8211;debug</code></p>
<dd>Debug mode, verbose logging to stderr</p>
<dt><code>-l</code>, <code>&#8211;logfile</code></p>
<dd>Debug logging into /var/log/cups/cups-browsed_log file.</p>
<dt><code>-c</code> <i>config-file</i></p>
<dd>Uses the alternative configuration file <i>config-file</i> instead of the standard one.</p>
<dt><code>-o</code> <i>option</i><code>=</code><i>value</i><code>, -o</code> &#8216;<i>config file line</i>&#8216;</p>
<dd>Supply configuration options via the command line. You can supply any line which also could be put into the configuration file, but note that due to the spaces the line has to be put into quotes, or for a simple key/value pair the space between key and value can get replaced by &#8216;=&#8217;. If command-line-supplied configuration settings are contradicting with the ones in the configuration file, the ones in the configuration file will get used.</p>
<dt><code>&#8211;autoshutdown=mode</code></p>
<dd>Auto shutdown mode, <code>mode</code> is <code>off</code> for no auto shutdown, <code>on</code> for auto shutdown being active, and <code>avahi</code> for control by the avahi-daemon being run on-demand, getting auto-shutdown turned off while avahi-daemon is present and on when avahi-daemon is shut down.</p>
<dt><code>&#8211;autoshutdown-on=inactivity-type</code></p>
<dd>What cups-browsed considers as inactivity for auto-shutdown. <code>inactivity-type</code> set to <code>no-queues</code> (the default) means that auto-shutdown is initiated if there are no queues generated by cups-browsed any more, <code>no-jobs</code> means that auto-shutdown will get initiated if all queues generated by cups-browsed are without jobs.</p>
<dt><code>&#8211;autoshutdown-timeout=timeout</code></p>
<dd><code>timeout</code> tells after how many seconds cups-browsed should shut down if it has no local queues set up for any discovered remote printer any more or jobs on these. Default is 30 seconds. 0 means immediate shutdown.</p>
<dt><code>-h, &#8211;help, &#8211;version</code></p>
<dd>Display usage and version info and do not start the daemon.</dl>
<h2>Files</h2>
<p>/etc/cups/cups-browsed.conf</p>
<h2>Signals</h2>
<p><i>SIGINT, SIGTERM</i>: cups-browsed will shutdown. </p>
<p> <i>SIGUSR1</i>: Switches cups-browsed into permanent mode (no auto shutdown). </p>
<p> <i>SIGUSR2</i>: Switches cups-browsed into auto shutdown mode.</p>
<h2>Notes</h2>
<p>Please take references to cups 1.6.x to include newer versions. Similarly, cups 1.5.x is intended to encompass older versions too. </p>
<p> In environments with only cups 1.6.x servers and clients (plus <code>cups-browsed</code> on either server or client or both) the function described in 1. enables the automatic discovery of remote queues and their display in printing dialogues of applications and with command line tools. </p>
<p> The facility provided by 3. allows printers that are registered in an LDAP server to be added as local queues. CUPS servers 1.5.x are able to automatically register printers in LDAP. The facility provided by <code>cups-browsed</code> allows a filter string to further limit the printers that are browsed from LDAP. </p>
<p> The facility provided by 4. means that servers running cups 1.6.x plus <code>cups-browsed</code> can broadcast their local queues so that clients with cups 1.5.x get these queues automatically available. The outcome of 2. is that clients running cups 1.6.x plus <code>cups-browsed</code> can use the CUPS broadcasts from servers with cups 1.5.x. As with browsing of Bonjour broadcasts, the created local raw queues are available to applications and command line tools. </p>
