<p>setup-ds.pl &#8211; Set up an instance of Directory Server</p>
<h2>Synopsis</h2>
<p><code>setup-ds.pl</code> [<i>&#8211;options</i>] <i>&#8212; </i>[<i>args</i>]</p>
<h2>Description</h2>
<p>Set up a Directory Server instance. Creates the configuration files for an instance of Directory Server based on a few parameters like the hostname, port number, and directory manager information. Can be run in interactive mode with different levels of verbosity, or in silent mode with parameters supplied in a .inf format file or on the command line. </p>
<h2>Options</h2>
<p>A summary of options is included below:</p>
<dl>
<dt><code>&#8211;help</code></p>
<dd>This message</p>
<dt><code>&#8211;version</code></p>
<dd>Print the version and exit</p>
<dt><code>&#8211;debug</code></p>
<dd>Turn on debugging</p>
<dt><code>&#8211;silent</code></p>
<dd>Use silent setup &#8211; no user input</p>
<dt><code>&#8211;file</code>=<i>name</i></p>
<dd>Use the file &#8216;name&#8217; in .inf format to supply the default answers</p>
<dt><code>&#8211;keepcache</code></p>
<dd>Do not delete the temporary .inf file generated by this program</p>
<dt><code>&#8211;logfile</code></p>
<dd>Log setup messages to this file &#8211; otherwise, a temp file will be used</p>
<dt><code>&#8211;update</code></p>
<dd>Update existing installations &#8211; add/update schema files, add/change configuration, add new instance scripts, etc. You must run setup-ds.pl -u after upgrading your packages. You will usually have to restart your servers in order for all of the changes to take effect (e.g. adding/changing plug-in configuration), so schedule this when you can afford a little downtime.</p>
<dt><code>&#8211;continue</code></p>
<dd>(Update only) Keep going even if errors occur. You will usually not need to use this option unless your installation is broken and you need to force it to update in order to fix it.</dl>
<p> For all options, you can also use the short name e.g. <code>-h</code>, <code>-d</code>, etc. For the <code>-d</code> argument, specifying it more than once will increase the debug level e.g. <code>-ddddd</code> </p>
<p> args: You can supply default .inf data in this format:</p>
<dl>
<dd>section.param=value</dl>
<p> e.g.</p>
<dl>
<dd>General.FullMachineName=foo.example.com</dl>
<p> or</p>
<dl>
<dd>&quot;slapd.Suffix=dc=example, dc=com&quot;</dl>
<p> Values passed in this manner will override values in an .inf file given with the <code>-f</code> argument.</p>
<h2>Updates</h2>
<p>The update process (setup-ds.pl -u) can work in one of two modes: </p>
<p> <code>Online</code>: Configuration changes are made to the running directory servers using LDAP. The operations must be performed as an administrative user. You must provide the name and password, for each instance if there is more than one instance of directory server. Some changes (e.g. plug-ins) may require a directory server restart to take effect. The update script will notify you if a restart is required. </p>
<p> <code>Offline</code>: The changes are made to the server configuration files. The servers <code>MUST FIRST BE SHUTDOWN BY YOU</code>. The script will not shutdown the servers for you. <code>You MUST</code> shutdown the servers in order to use this mode. A username and password are not required to use Offline mode. If the servers are not shutdown, <code>CHANGES WILL BE LOST</code>. </p>
<p> To summarize: </p>
<p> Online &#8211; servers remain running &#8211; you must provide admin name and password for each server &#8211; servers may need to be restarted </p>
<p> Offline &#8211; servers <code>must be shutdown</code> &#8211; no username or password required</p>
