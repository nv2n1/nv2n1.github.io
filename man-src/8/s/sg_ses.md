<p>sg_ses &#8211; access a SCSI Enclosure Services (SES) device</p>
<h2>Synopsis</h2>
<p><code>sg_ses</code> [<i>&#8211;byte1=B1</i>] [<i>&#8211;clear=STR</i>] [<i>&#8211;control</i>] [<i>&#8211;data=H,H&#8230;</i>] [<i>&#8211;descriptor=DN</i>] [<i>&#8211;enumerate</i>] [<i>&#8211;filter</i>] [<i>&#8211;get=STR</i>] [<i>&#8211;help</i>] [<i>&#8211;hex</i>] [<i>&#8211;index=IIA</i> | <i>&#8211;index=TIA,II</i>] [<i>&#8211;inner-hex</i>] [<i>&#8211;join</i>] [<i>&#8211;list</i>] [<i>&#8211;nickname=SEN</i>] [<i>&#8211;nickid=SEID</i>] [<i>&#8211;page=PG</i>] [<i>&#8211;raw</i>] [<i>&#8211;set=STR</i>] [<i>&#8211;status</i>] [<i>&#8211;verbose</i>] [<i>&#8211;version</i>] <i>DEVICE</i></p>
<h2>Description</h2>
<p>Fetches management information from a SCSI Enclosure Service (SES) device. This utility can also modify the state of a SES device. The <i>DEVICE</i> should be a SES device which may be a dedicated enclosure services processor in which case an INQUIRY response&#8217;s Peripheral Device Type is 13 [0xd]. Alternatively it may be attached to another type of SCSI device (e.g. a disk) in which case the EncServ bit is set in its INQUIRY response. </p>
<p> If no options are given (i.e. only the <i>DEVICE</i> argument is given) then the names of all diagnostic pages supported are listed. Most, but not necessarily all, of the named diagnostic pages are defined in the SES standards and drafts. The most recent reference for this utility is the draft SCSI Enclosure Services 3 document T10/2149-D Revision 6 at <a rel="nofollow" href="http://www.t10.org">http://www.t10.org</a> . Existing standards for SES and SES-2 are ANSI INCITS 305-1998 and ANSI INCITS 448-2008 respectively. </p>
<p> Changing the state of an enclosure (e.g. requesting the &quot;ident&quot; (locate) LED to flash on a disk carrier in an array) is typically done using a read-modify-write cycle. See the section on CHANGING STATE below. </p>
<p> There is a web page discussing this utility at <a rel="nofollow" href="http://sg.danny.cz/sg/sg_ses.html">http://sg.danny.cz/sg/sg_ses.html</a> . </p>
<p> In the following sections &quot;page&quot; refers to a diagnostic page, either fetched with a SCSI RECEIVE DIAGNOSTIC RESULTS command or sent to the <i>DEVICE</i> with a SCSI SEND DIAGNOSTIC command.</p>
<h2>Options</h2>
<p>Arguments to long options are mandatory for short options as well. The options are arranged in alphabetical order based on the long option name.</p>
<dl>
<dt><code>-b</code>, <code>&#8211;byte1</code>=<i>B1</i></p>
<dd>some modifiable pages may need byte 1 (i.e. the second byte) set. In the Enclosure Control page, byte 1 contains the INFO, NON-CRIT, CRIT and UNRECOV bits. In the Subenclosure String Out, Subenclosure Nickname Control and Download Microcode Control pages, byte 1 is the Subenclosure identifier. Active when the <i>&#8211;control</i> and <i>&#8211;data=H,H&#8230;</i> options are used and the default value is 0. If the <i>&#8211;clear=STR</i> or <i>&#8211;set=STR</i> option is used then the value read from byte 1 is written back to byte 1. <i>B1</i> is in decimal unless it is prefixed by &#8216;0x&#8217; or &#8216;0X&#8217; (or has a trailing &#8216;h&#8217; or &#8216;H&#8217;).</p>
<dt><code>-C</code>, <code>&#8211;clear</code>=<i>STR</i></p>
<dd>Used to clear an element field in the Enclosure Control or Threshold Out page. Must be used together with a <i>&#8211;descriptor=DN</i> or <i>&#8211;index=&#8230;</i> option to specify which element is to be changed. The Enclosure Control page is assumed if the <i>&#8211;page=PG</i> option is not given. See the STR FORMAT section below.</p>
<dt><code>-c</code>, <code>&#8211;control</code></p>
<dd>will send control information to the <i>DEVICE</i> via a SCSI SEND DIAGNOSTIC command. Cannot give both this option and <i>&#8211;status</i>. The Enclosure Control, String Out, Threshold Out, Array Control (obsolete in SES-2), Subenclosure String Out, Subenclosure Nickname Control and Download Microcode pages can be set currently. This option is assumed if either the <i>&#8211;clear=STR</i> or <i>&#8211;set=STR</i> option is given.</p>
<dt><code>-d</code>, <code>&#8211;data</code>=<i>H,H&#8230;</i></p>
<dd>permits a string of comma separated (ASCII) hex bytes to be specified (limit 1024). A (single) space separated string of hex bytes is also allowed but the list needs to be in quotes. This option allows the parameters to a control page to be specified. The string given should not include the first 4 bytes (i.e. page code and length).</p>
<dt><code>-d</code>, <code>&#8211;data</code>=-</p>
<dd>reads a data string from stdin, limit 1024 bytes. stdin may provide ASCII hex as a comma separated list (i.e. as with the <i>&#8211;data=H,H&#8230;</i> option). Additionally spaces, tabs and line feeds are permitted as separators from stdin . Stops reading stdin when an EOF is detected.</p>
<dt><code>-D</code>, <code>&#8211;descriptor</code>=<i>DN</i></p>
<dd>where <i>DN</i> is a descriptor name (string) as found in the Element Descriptor page. If that page is supported then <i>DN</i> may be an alternative for <i>TIA,II</i> (in the <i>&#8211;index=TIA,II</i> option). If the descriptor name contains a space then <i>DN</i> needs to be surrounded by quotes (single or double) or the space escaped (e.g. preceded by a backslash). Some elements (e.g. overall elements) may not have descriptor names. Useful with the <i>&#8211;clear=STR</i>, <i>&#8211;get=STR</i> and <i>&#8211;set=STR</i> options. If no other options are given then the <i>&#8211;join</i> option is assumed.</p>
<dt><code>-e</code>, <code>&#8211;enumerate</code></p>
<dd>enumerate all known page names and SES elements when this option is given once. If <i>&#8211;enumerate</i> is given twice, then the recognised acronyms for the <i>&#8211;clear=STR</i>, <i>&#8211;get=STR</i> and <i>&#8211;set=STR</i> options are listed. The utility exits after listing this information (so most other options and <i>DEVICE</i> are ignored).</p>
<dt><code>-f</code>, <code>&#8211;filter</code></p>
<dd>cuts down on the amount of output from the Enclosure Status page and the Additional Element Status page. When this option is given, any line which has all its binary flags cleared (i.e. 0) is filtered out (i.e. ignored). If a line has some other value on it (e.g. a temperature) then it is output. The <i>&#8211;filter</i> option is also useful for reducing the amount of output generated by the <i>&#8211;join</i> option.</p>
<dt><code>-G</code>, <code>&#8211;get</code>=<i>STR</i></p>
<dd>Used to read a field in a status element. Must be used together with a <i>&#8211;descriptor=DN</i> or <i>&#8211;index=&#8230;</i> option to specify which element is to be read. By default the Enclosure Status page is read, the only other pages that can be read are the Threshold In and Additional Element Status pages. If a value is found it is output in decimal to stdout (by default) or in hexadecimal preceded by &quot;0x&quot; if the <i>&#8211;hex</i> option is also given. See the STR FORMAT section below.</p>
<dt><code>-h</code>, <code>&#8211;help</code></p>
<dd>output the usage message then exit.</p>
<dt><code>-H</code>, <code>&#8211;hex</code></p>
<dd>If the <i>&#8211;get=STR</i> option is given then output the value found (if any) in hexadecimal, with a leading &quot;0x&quot;. Otherwise output the response in hexadecimal. Ignored with some options (e.g. <i>&#8211;join</i>).</p>
<dt><code>-I</code>, <code>&#8211;index</code>=<i>IIA</i></p>
<dd>where <i>IIA</i> is either an individual index (II) or an Element type abbreviation (A). See the INDEXES section below. If the <i>&#8211;page=PG</i> option is not given then the Enclosure Status (or Control) page is assumed. May be used with the <i>&#8211;join</i> option or one of the <i>&#8211;clear=STR</i>, <i>&#8211;get=STR</i> or <i>&#8211;set=STR</i> options. To enumerate the available Element type abbreviations use the <i>&#8211;enumerate</i> option.</p>
<dt><code>-I</code>, <code>&#8211;index</code>=<i>TIA,II</i></p>
<dd>where <i>TIA,II</i> is an type header index (TI) or Element type abbreviation (A) followed by an individual index (II). See the INDEXES section below. If the <i>&#8211;page=PG</i> option is not given then the Enclosure Status (or Control) page is assumed. May be used with the <i>&#8211;join</i> option or one of the <i>&#8211;clear=STR</i>, <i>&#8211;get=STR</i> or <i>&#8211;set=STR</i> options. To enumerate the available Element type abbreviations use the <i>&#8211;enumerate</i> option.</p>
<dt><code>-i</code>, <code>&#8211;inner-hex</code></p>
<dd>the outer levels of a status page are decoded and printed out but the innermost level (e.g. the Element Status Descriptor) is output in hex. Also active with the Additional Element Status and Threshold In pages. Can be used with <i>&#8211;index=&#8230;</i> and/or <i>&#8211;join</i> options.</p>
<dt><code>-j</code>, <code>&#8211;join</code></p>
<dd>group elements from the Element Descriptor, Enclosure Status and Additional Element Status pages. If this option is given twice then elements from the Threshold In page are also grouped. The order is dictated by the Configuration page. All elements are output unless the <i>&#8211;index=</i> or <i>&#8211;descriptor=DN</i> option is given, in which case only the matching element is output. The <i>&#8211;filter</i> option can be added to reduce the amount of output generated by the option. See the INDEXES section below.</p>
<dt><code>-l</code>, <code>&#8211;list</code></p>
<dd>This option is equivalent to <i>&#8211;enumerate</i>. See that option.</p>
<dt><code>-n</code>, <code>&#8211;nickname</code>=<i>SEN</i></p>
<dd>where <i>SEN</i> is the new Subenclosure Nickname. Only the first 32 characters (bytes) of <i>SEN</i> are used, if more are given they are ignored. See the SETTING SUBENCLOSURE NICKNAME section below.</p>
<dt><code>-N</code>, <code>&#8211;nickid</code>=<i>SEID</i></p>
<dd>where <i>SEID</i> is the Subenclosure identifier that the new Nickname (<i>SEN</i>) will be applied to. The default value is 0 which is the main enclosure.</p>
<dt><code>-p</code>, <code>&#8211;page</code>=<i>PG</i></p>
<dd>where <i>PG</i> is a page abbreviation or code (a number). If <i>PG</i> starts with a digit it is assumed to be in decimal unless prefixed by 0x for hex. Valid range is 0 to 255 (0x0 to 0xff) inclusive. Default is page &#8216;sdp&#8217; which is page_code 0 (i.e. &quot;Supported Diagnostic Pages&quot;) if no other options are given.</p>
<dt><code>-r</code>, <code>&#8211;raw</code></p>
<dd>outputs the chosen status page in ASCII hex in a format suitable for a later invocation using the <i>&#8211;data=</i> option. A page less its first 4 bytes (page code and length) is output. When used twice (e.g. <i>-rr</i>) the full page contents is output in binary to stdout.</p>
<dt><code>-S</code>, <code>&#8211;set</code>=<i>STR</i></p>
<dd>Used to set an element field in the Enclosure Control or Threshold Out page. Must be used together with a <i>&#8211;descriptor=DN</i> or <i>&#8211;index=&#8230;</i> option to specify which element is to be changed. The Enclosure Control page is assumed if the <i>&#8211;page=PG</i> option is not given. See the STR FORMAT section below.</p>
<dt><code>-s</code>, <code>&#8211;status</code></p>
<dd>will fetch page from the <i>DEVICE</i> via a SCSI RECEIVE DIAGNOSTIC RESULTS command. In the absence of other options that imply modifying a page (e.g. <i>&#8211;control</i> or <i>&#8211;set=STR</i>) then <i>&#8211;status</i> is assumed.</p>
<dt><code>-v</code>, <code>&#8211;verbose</code></p>
<dd>increase the level of verbosity, (i.e. debug output).</p>
<dt><code>-V</code>, <code>&#8211;version</code></p>
<dd>print the version string and then exit.</dl>
<h2>Indexes</h2>
<p>An enclosure can have information about its disk and tape drives plus other supporting components like power supplies spread across several pages. Addressing a specific element (overall or individual) is complicated. </p>
<p> The Configuration page is key: it contains a list of &quot;type headers&quot;, each of which contains an Element type (e.g. Array Device Slot), a Subenclosure identifier (0 for the primary enclosure) and a &quot;Number of possible elements&quot;. Corresponding to each type header, the Enclosure Status page has one &quot;overall&quot; element plus &quot;Number of possible elements&quot; individual elements all of which have the given Element type. For some Element types the &quot;Number of possible elements&quot; will be 0 so the Enclosure Status page has only one &quot;overall&quot; element corresponding to that type header. The Element Descriptor page and the Threshold (In and Out) pages follow the same pattern as the Enclosure Status page. </p>
<p> The Additional Element Status page is a bit more complicated. It has entries for &quot;Number of possible elements&quot; of certain Element types. It does not have entries corresponding to the &quot;overall&quot; elements. To make the correspondence a little clearer each descriptor in this page optionally contains an &quot;Element Index Present&quot; (EIP) indicator. If EIP is set then each element&#8217;s &quot;Element Index&quot; field refers to the position of the corresponding element in the Enclosure Status page. </p>
<p> Addressing a single overall element or a single individual element is done with two indexes: TI and II. Both are origin 0. TI=0 corresponds to the first type header entry which must be a Device Slot or Array Device Slot Element type (according to the SES-2 standard). To address the corresponding overall instance, II is set to -1, otherwise II can be set to the individual instance index. As an alternative to the type header index (TI), an Element type abbreviation (A) optionally followed by a number (e.g. &quot;ps&quot; refers to the first Power Supply Element type; &quot;ps1&quot; refers to the second) can be given. </p>
<p> One of two command lines variants can be used to specify indexes: <i>&#8211;index=TIA,II</i> where <i>TIA</i> is either an type header index (TI) or an Element type abbreviation (A) (e.g. &quot;ps&quot; or &quot;ps1&quot;). <i>II</i> is either an individual index or &quot;-1&quot; to specify the overall element. The second variant is <i>&#8211;index=IIA</i> where <i>IIA</i> is either an individual index (II) or an Element type abbreviation (A). When <i>IIA</i> is an individual index then the option is equivalent to <i>&#8211;index=0,II</i>. When <i>IIA</i> is an Element type abbreviation then the option is equivalent to <i>&#8211;index=A,-1</i>. </p>
<p> To cope with vendor specific Element types (which should be in the range 128 to 255) the Element type can be given as a number with a leading underscore. For example these are equivalent: <i>&#8211;index=arr</i> and <i>&#8211;index=_23</i> since the Array Device Slot Element type value is 23. Also <i>&#8211;index=ps1</i> and <i>&#8211;index=_2_1</i> are equivalent. </p>
<p> Another example: if the first type header in the Configuration page has Array Device Slot Element type then <i>&#8211;index=0,-1</i> is equivalent to <i>&#8211;index=arr</i>. Also <i>&#8211;index=arr,3</i> is equivalent to <i>&#8211;index=3</i>. </p>
<p> Note that if the Element Descriptor page is available then the <i>&#8211;descriptor=DN</i> option may be an alternative to the <i>&#8211;index=&#8230;</i> option.</p>
<h2>Str Format</h2>
<p>The <i>STR</i> operands of the <i>&#8211;clear=STR</i>, <i>&#8211;get=STR</i> and <i>&#8211;set=STR</i> options all have the same structure. There are two forms: </p>
<p>&lt;acronym&gt;[=&lt;value&gt;] </p>
<p>&lt;start_byte&gt;:&lt;start_bit&gt;[:&lt;num_bits&gt;][=&lt;value&gt;] </p>
<p> The &lt;acronym&gt; is one of a list of common fields (e.g. &quot;ident&quot; and &quot;fault&quot;) that the utility converts internally into the second form. The &lt;start_byte&gt; is usually in the range 0 to 3, the &lt;start_bit&gt; must be in the range 0 to 7 and the &lt;num_bits&gt; must be in the range 1 to 64 (default 1). The number of bits are read in the left to right sense of the element tables shown in the various SES draft documents. For example the 8 bits of byte 2 would be represented as 2:7:8 with the most significant bit being 2:7 and the least sugnificant bit being 2:0 . </p>
<p> The &lt;value&gt; is optional but is ignored if provided to <i>&#8211;get=STR</i>. For <i>&#8211;set=STR</i> the default &lt;value&gt; is 1 while for <i>&#8211;clear=STR</i> the default value is 0 . </p>
<p> The supported list of &lt;acronym&gt;s can be viewed by using the <i>&#8211;enumerate</i> option twice (or &quot;-ee&quot;).</p>
<h2>Changing State</h2>
<p>This utility has various techniques for changing the state of a SES device. As noted above this is typically a read-modify-write type operation. Most modifiable pages have a &quot;status&quot; (or &quot;in&quot;) page that can be read, and a corresponding &quot;control&quot; (or &quot;out&quot;) page that can be written back to change the state of the enclosure. </p>
<p> The lower level technique provided by this utility involves outputting a &quot;status&quot; page in hex with <i>&#8211;raw</i>. Then a text editor can be used to edit the hex (note: to change an Enclosure Control descriptor the SELECT bit needs to be set). Next the control page data can fed back with the <i>&#8211;data=H,H&#8230;</i> option together with the <i>&#8211;control</i> option; the <i>&#8211;byte1=B1</i> option may need to be given as well. </p>
<p> Changes to the Enclosure Control page (and the Threshold Out page) can be done at a higher level. This involves choosing a page (the default in this case is the Enclosure Control page). Next choose an individual or overall element index (or name it with its Element Descriptor string). Then give the element&#8217;s name (e.g. &quot;ident&quot; for RQST IDENT) or its position within that element (e.g. in an Array Device Slot Control element RQST IDENT is byte 2, bit 1 and 1 bit long (&quot;2:1:1&quot;)). Finally a value can be given, if not the value for <i>&#8211;set=STR</i> defaults to 1 and for <i>&#8211;clear=STR</i> defaults to 0.</p>
<h2>Setting Subenclosure Nickname</h2>
<p>The format of the Subenclosure Nickname control page is different from its corresponding status page. The status page reports all Subenclosure Nicknames (and Subenclosure identifier 0 is the main enclosure) while the control page allows only one of them to be changed. Therefore using the <code>&#8211;data</code> option technique to change a Subenclosure nickname is difficult (but still possible). </p>
<p> To simplify changing a Subenclosure nickname the <i>&#8211;nickname=SEN</i> and <i>&#8211;nickid=SEID</i> options have been added. If the <i>SEN</i> string contains spaces or other punctuation, it should be quoted: surrounded by single or double quotes (or the offending characters escaped). If the <i>&#8211;nickid=SEID</i> is not given then a Subenclosure identifier of 0 is assumed. As a guard the <i>&#8211;control</i> option must also be given. If the <i>&#8211;page=PG</i> option is not given then <i>&#8211;page=snic</i> is assumed. </p>
<p> When <i>&#8211;nickname=SEN</i> is given then the Subenclosure Nickname Status page is read to obtain the Generation Code field. That Generation Code together with no more than 32 bytes from the Nickname (<i>SEN</i>) and the Subenclosure Identifier (<i>SEID</i>) are written to the Subenclosure Nickname Control page. </p>
<p> There is an example of changing a nickname in the EXAMPLES section below.</p>
<h2>Notes</h2>
<p>This utility can be used to fetch arbitrary (i.e. non SES) diagnostic pages (using the SCSI READ DIAGNOSTIC command). To this end the <i>&#8211;page=PG</i> and <i>&#8211;hex</i> options would be appropriate. Arbitrary diagnostic pages can be sent to a device with the sg_senddiag utility. </p>
<p> The most troublesome part of the join operation is associating Additional Element Status descriptors correctly. At least one SES device vendor has misinterpreted the SES-2 standard with its &quot;element index&quot; field. The code in this utility interprets the &quot;element index&quot; field as per the SES-2 standard and if that yields an inappropriate Element type, adjusts its indexing to follow that vendor&#8217;s misinterpretation. </p>
<p> In draft SES-3 revision 5 the &quot;Door Lock&quot; element name was changed to the &quot;Door&quot; (and an OPEN field was added to the status element). As a consequence the former &#8216;dl&#8217; element type abbreviation has been changed to &#8216;do&#8217;. </p>
<p> There is a related command set called SAF-TE (SCSI attached fault-tolerant enclosure) for enclosure (including RAID) status and control. SCSI devices that support SAF-TE report &quot;Processor&quot; peripheral device type (0x3) in their INQUIRY response. See the sg_safte utility in this package or safte-monitor on the Internet.</p>
<h2>Examples</h2>
<p>These examples use Linux device names. For suitable device names in other supported Operating Systems see the <a href="/docs/linux/man/8-sg3_utils/">sg3_utils</a>(8) man page. To view the supported pages:<br />
sg_ses&nbsp;<wbr>/dev/bsg/6:0:2:0 To view the Configuration page: </p>
<pre><code>sg_ses --page=cf /dev/bsg/6:0:2:0</code></pre>
<p> To view the Enclosure Status page: sg_ses &#8211;page=es /dev/bsg/6:0:2:0 To get the (attached) SAS address of that device (which is held in the Additional Element Sense page (page 10)) printed on hex:<br />
sg_ses -p aes -D ArrayDevice07 -G at_sas_addr -H&nbsp;<wbr>/dev/sg3 To collate the information in the Enclosure Status, Element Descriptor and Additional Element Status pages the <i>&#8211;join</i> option can be used:<br />
sg_ses &#8211;join&nbsp;<wbr>/dev/sg3 This will produce a lot of output. To filter out lines that don&#8217;t contain much information add the <i>&#8211;filter</i> option:<br />
sg_ses &#8211;join &#8211;filter&nbsp;<wbr>/dev/sg3 Fields in the various elements of the Enclosure Control and Threshold pages can be changed with the <i>&#8211;clear=STR</i> and <i>&#8211;set=STR</i> options. [All modifiable pages can be changed with the <i>&#8211;raw</i> and <i>&#8211;data=H,H&#8230;</i> options.] The following example looks at making the &quot;ident&quot; LED (also called &quot;locate&quot;) flash on &quot;ArrayDevice07&quot; which is a disk (or more precisely the carrier drawer the disk is in): sg_ses &#8211;index=7 &#8211;set=2:1:1 /dev/sg3 If the Element Descriptor diagnostic page shows that &quot;ArrayDevice07&quot; is the descriptor name associated with element index 7 then this invocation is equivalent to the previous one: sg_ses &#8211;descriptor=ArrayDevice07 &#8211;set=2:1:1 /dev/sg3 Further the byte 2, bit 1 (for 1 bit) field in the Array Device Slot Control element is RQST IDENT for asking a disk carrier to flash a LED so it can be located. In this case &quot;ident&quot; (or &quot;locate&quot;) is accepted as an acronym for that field: sg_ses &#8211;descriptor=ArrayDevice07 &#8211;set=ident /dev/sg3 To stop that LED flashing: sg_ses &#8211;descriptor=ArrayDevice07 &#8211;clear=ident /dev/sg3 Now for an example of a more general but lower level technique for changing a modifiable diagnostic page. The String (In and Out) diagnostics page is relatively simple (compared with the Enclosure Status/Control page). However the use of this lower level technique is awkward involving three steps: read, modify then write. First check the current String (In) page contents: sg_ses &#8211;page=str /dev/bsg/6:0:2:0 Now the &quot;read&quot; step. The following command will send the contents of the String page (from byte 4 onwards) to stdout. The output will be in ASCII hex with pairs of hex digits representing a byte, 16 pairs per line, space separated. The redirection puts stdout in a file called &quot;t&quot;: sg_ses &#8211;page=str &#8211;raw /dev/bsg/6:0:2:0 &gt; t Then with the aid of the SES-3 document (in revision 3: section 6.1.6) use your favourite editor to change t. The changes can be sent to the device with: sg_ses &#8211;page=str &#8211;control &#8211;data=- /dev/bsg/6:0:2:0 &lt; t If the above is successful, the String page should have been changed. To check try: sg_ses &#8211;page=str /dev/bsg/6:0:2:0 To change the nickname on the main enclosure: </p>
<pre><code>sg_ses --nickname='1st enclosure' --control /dev/bsg/6:0:2:0</code></pre>
<h2>Exit Status</h2>
<p>The exit status of sg_ses is 0 when it is successful. Otherwise see the <a href="/docs/linux/man/8-sg3_utils/">sg3_utils</a>(8) man page.</p>
