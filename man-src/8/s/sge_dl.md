<p>dl &#8211; setting xxQS_NAME_Sxx debug tracing information</p>
<h2>Synopsis</h2>
<p><code>source $SGE_ROOT/util/dl.sh</code><br />
 <code>dl</code> <i>level</i></p>
<h2>Description</h2>
<p>The <i>dl</i> shell script alias is obtained by sourcing one of the scripts <i>$SGE_ROOT/util/dl.sh</i> or <i>$SGE_ROOT/util/dl.csh</i>, for Bourne and C shell respectively. It provides a convenient way to set up the environment to produce certain xxQS_NAME_Sxx debugging information. It is mostly useful for maintainers, but may occasionally be useful to users diagnosing problems. (In that case it probably indicates a need for extra user-level messages logged in the spool area or elsewhere, which should be improved.) </p>
<p> The <i>level</i> argument specifies the printing of debugging output by the xxQS_NAME_Sxx components as described below, or 0 to turn off debugging output and reset the other environment variables concerned. When tracing is on, output goes to the stderr stream. <code>dl</code> also sets (or, with argument 0, resets) the <code>SGE_ND</code> environment variable to make daemon programs run in the foreground rather than actually daemonizing, and also <code>SGE_ENABLE_COREDUMP</code>, which enables core dumps from daemons which change user or group. The trace output is most often used for debugging daemons; some is available from client programs but is typically less useful.</p>
<h3>Debugging levels</h3>
<p>Debugging is specified in terms of &quot;layers&quot;, describing particular components of the system, such as libraries, indexed by a number:</p>
<dl>
<dt>TOP (0)</p>
<dd>General information;</p>
<dt>CULL (1)</p>
<dd>List-processing (not used consistently);</p>
<dt>BASIS (2)</p>
<dd>Apparently intended for low-level routines, such as string processing, but used quite generally;</p>
<dt>GUI (3)</p>
<dd>Operations in the <i>qmon</i> graphical client;</p>
<dt>GDI (6)</p>
<dd>Grid Engine Database Interface for dealing with &quot;objects&quot; maintained by the qmaster process;</p>
<dt>PACK (7)</p>
<dd>Packing and unpacking network data.</dl>
<p> The other indices are unused. </p>
<p> There are also different &quot;classes&quot; which determine the type/amount of information printed, again indexed by a number:</p>
<dl>
<dt>TRACE (1)</p>
<dd>Tracing function enter/exit (generated by DENTER, DEXIT etc. macros);</p>
<dt>INFOPRINT (2)</p>
<dd>General information (generated by DPRINTF);</p>
<dt>TIMING (16)</p>
<dd>Time taken by execd to start a job;</p>
<dt>LOCK (32)</p>
<dd>Locking/mutex information.</dl>
<p> Other classes are defined, but currently unused. For those and unused layers, see the source file <i>libs/uti/sge_rmon_monitoring_level.h</i>. </p>
