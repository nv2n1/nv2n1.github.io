<p>sanlock_selinux &#8211; Security Enhanced Linux Policy for the sanlock processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the sanlock processes via flexible mandatory access control. The sanlock processes execute with the sanlock_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep sanlock_t</code> </p>
<h2>Entrypoints</h2>
<p>The sanlock_t SELinux type can be entered via the <code>sanlock_exec_t</code> file type. </p>
<p> The default entrypoint paths for the sanlock_t domain are the following: </p>
<p> /usr/sbin/sanlock</p>

<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. sanlock policy is extremely flexible and has several booleans that allow you to manipulate the policy and run sanlock with the tightest access possible. </p>
<p> If you want to allow sanlock to read/write fuse files, you must turn on the sanlock_use_fusefs boolean. Disabled by default. </p>
<p> <code>setsebool -P sanlock_use_fusefs 1</code> </p>
<p> If you want to allow sanlock to manage nfs files, you must turn on the sanlock_use_nfs boolean. Disabled by default. </p>
<p> <code>setsebool -P sanlock_use_nfs 1</code> </p>
<p> If you want to allow sanlock to manage cifs files, you must turn on the sanlock_use_samba boolean. Disabled by default. </p>
<p> <code>setsebool -P sanlock_use_samba 1</code> </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to allow all daemons to write corefiles to /, you must turn on the daemons_dump_core boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_dump_core 1</code> </p>
<p> If you want to enable cluster mode for daemons, you must turn on the daemons_enable_cluster_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P daemons_enable_cluster_mode 1</code> </p>

<p> <code>setsebool -P daemons_use_tcp_wrapper 1</code> </p>

<p> <code>setsebool -P daemons_use_tty 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>

<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux sanlock policy is very flexible allowing users to setup their sanlock processes in as secure a method as possible. </p>
<p> STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the sanlock, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t sanlock_var_run_t &#8216;/srv/mysanlock_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/mysanlock_content</code> </p>
<p> Note: SELinux often uses regular expressions to specify labels that match multiple files. </p>
<p> <i>The following file types are defined for sanlock:</i> </p>
<p> <code>sanlock_conf_t</code> </p>
<p> &#8211; Set files with the sanlock_conf_t type, if you want to treat the files as sanlock configuration data, usually stored under the /etc directory. </p>
<p> <code>sanlock_exec_t</code> </p>
<p> &#8211; Set files with the sanlock_exec_t type, if you want to transition an executable to the sanlock_t domain. </p>
<p> <code>sanlock_initrc_exec_t</code> </p>
<p> &#8211; Set files with the sanlock_initrc_exec_t type, if you want to transition an executable to the sanlock_initrc_t domain. </p>
<p> <code>sanlock_log_t</code> </p>
<p> &#8211; Set files with the sanlock_log_t type, if you want to treat the data as sanlock log data, usually stored under the /var/log directory. </p>
<p> <code>sanlock_unit_file_t</code> </p>
<p> &#8211; Set files with the sanlock_unit_file_t type, if you want to treat the files as sanlock unit content. </p>
<p> <code>sanlock_var_run_t</code> </p>
<p> &#8211; Set files with the sanlock_var_run_t type, if you want to store the sanlock files under the /run or /var/run directory. </p>
