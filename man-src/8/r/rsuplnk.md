<p>rsuplnk &#8211; User entry into the ROSE network.</p>
<h2>Synopsis</h2>
<p><code>rsuplnk [-q] &lt;port&gt;</code></p>
<h2>Description</h2>
<p>The <code>rsuplnk</code> program allows a user to gain entry into the ROSE network using the standard pseudo-digipeating method. Recent Linux kernels are aware of this form of operation and the <code>ax25d</code> program can listen for such connections. The normal mode of operation of a ROSE switch is to have one ROSE address (ie port) per physical AX.25 port. Therefore ROSE users coming in on a given AX.25 port will appear as if they come from the associated ROSE port. This is the reason for the need for a ROSE port as an argument. </p>
<p> To use <code>rsuplnk</code> you need an entry in <code>ax25d.conf</code> to listen for incoming connections. In the example below, I will be listening for ROSE connections on my AX.25 port 144 using the callsign KE4GAJ-10 and the ROSE port associated with the AX.25 port is rs144. </p>
<p> #<br />
 [KE4GAJ-10* VIA 144]<br />
 NOCALL * * * * * * L<br />
 default * * * * * * &#8211; root /usr/sbin/rsuplnk rsuplnk rs144<br />
 # </p>
<p> There would typically be one <code>rsuplnk</code> per user access AX.25 port. The associated program for exiting a ROSE network is <code>rsdwnlnk.</code> </p>
<p> All errors generated by <code>rsuplnk</code> are written to the system debug log file.</p>
<h2>Options</h2>
<dl>
<dt><code>-q</code></p>
<dd>Supresses the messages generated by <code>rsuplnk</code> when making the connection.</dl>
<h2>Files</h2>
<p>/etc/ax25/rsports</p>
