<p>register-ds-admin.pl &#8211; Registers Directory Server instances with an Admin Server</p>
<h2>Synopsis</h2>
<p><code>register-ds-admin.pl</code> [<i>&#8211;options</i>] <i>&#8212; </i>[<i>args</i>]</p>
<h2>Description</h2>
<p>Registers existing Directory Server instances with an existing Admin Server. This command does the set up necessary for the use of the Console to manage the Directory Server instances you are registering. You can register local Directory Server instances with a local Configuration Directory Server/Admin Server. You can also create an Admin Server and register standalone instances with it. You can register remote Directory Server instances to the local Admin Server, as well as register local Directory Server instances with a remote Admin Server &#8211; this allows a single Console/Admin Server to manage all the Directory Servers in your network. Use this command with the <code>&#8211;update</code> option after an upgrade to refresh<br />
&nbsp;<wbr>the server information&nbsp;<wbr>(version, build number, etc.)&nbsp;<wbr>in the Console. Can be run in interactive mode with different levels of verbosity, or in silent mode with parameters supplied in a .inf format file or on the command line. </p>
<h2>Options</h2>
<p>A summary of options is included below:</p>
<dl>
<dt><code>&#8211;help</code></p>
<dd>This message</p>
<dt><code>&#8211;version</code></p>
<dd>Print the version and exit</p>
<dt><code>&#8211;debug</code></p>
<dd>Turn on debugging</p>
<dt><code>&#8211;silent</code></p>
<dd>Use silent setup &#8211; no user input</p>
<dt><code>&#8211;file</code>=<i>name</i></p>
<dd>Use the file &#8216;name&#8217; in .inf format to supply the default answers</p>
<dt><code>&#8211;keepcache</code></p>
<dd>Do not delete the temporary .inf file generated by this program</p>
<dt><code>&#8211;logfile</code></p>
<dd>Log setup messages to this file &#8211; otherwise, a temp file will be used</p>
<dt><code>&#8211;update</code></p>
<dd>Update an existing installation (e.g. after upgrading packages)</p>
<dt><code>&#8211;continue</code></p>
<dd>(update only) keep going despite errors (also &#8211;force)</dl>
<p> For all options, you can also use the short name e.g. <code>-h</code>, <code>-d</code>, etc. For the <code>-d</code> argument, specifying it more than once will increase the debug level e.g. <code>-ddddd</code> </p>
<p> args: You can supply default .inf data in this format:</p>
<dl>
<dd>section.param=value</dl>
<p> e.g.</p>
<dl>
<dd>General.FullMachineName=foo.example.com</dl>
<p> or</p>
<dl>
<dd>&quot;slapd.Suffix=dc=example,dc=com&quot;</dl>
<p> Values passed in this manner will override values in an .inf file given with the <code>-f</code> argument.</p>
<h2>Silent Mode (.inf file)</h2>
<p>The .inf file use three directives depending on what you want to do: [General], [admin], and [register]. The [admin] section is only needed if an Admin Server needs to be installed on the local system. </p>
<p> Here is an example of creating an Admin Server, and turning a standalone Directory Server instance into a configuration instance. In this case we need the [General], [admin], and [register] directives</p>
<dl>
<dd>[General]<br />
 FullMachineName= localhost.localdomain<br />
 SuiteSpotUserID= dirsrv<br />
 SuiteSpotGroup= dirsrv<br />
 AdminDomain= redhat.com<br />
 ConfigDirectoryAdminID= admin<br />
 ConfigDirectoryAdminPwd= admin<br />
 ConfigDirectoryLdapURL= <a href="ldap://localhost.localdomain:389/o=NetscapeRoot">ldap://localhost.localdomain:389/o=NetscapeRoot</a> </p>
<p> [admin]<br />
 Port= 9830<br />
 ServerIpAddress= 127.0.0.1<br />
 ServerAdminID= admin<br />
 ServerAdminPwd= password </p>
<p> [register]<br />
 configinst= slapd-localhost::cn=directory manager::password </p>
</dl>
<p> Here is an example of an .inf file that registers two local Directory Server instances (slapi-replica, slapd-instance2) with the local Configuration Directory Server (slapd-localhost).</p>
<dl>
<dd>[General]<br />
 FullMachineName= localhost.localdomain<br />
 SuiteSpotUserID= dirsrv<br />
 SuiteSpotGroup= dirsrv<br />
 AdminDomain= redhat.com<br />
 ConfigDirectoryAdminID= admin<br />
 ConfigDirectoryAdminPwd= admin<br />
 ConfigDirectoryLdapURL= <a href="ldap://localhost.localdomain:389/o=NetscapeRoot">ldap://localhost.localdomain:389/o=NetscapeRoot</a> </p>
<p> [register]<br />
 configinst= slapd-localhost::cn=directory manager::password<br />
 localinst= slapd-instance2::cn=directory manager::password<br />
 localinst= slapd-replica::cn=directory manager::password </p>
</dl>
<p> This example will add the slapd-replica instance to the local configuration server. Then this server&#8217;s configuration to added to the remote configuration server on ldap.redhat.com</p>
<dl>
<dd>[General]<br />
 FullMachineName= localhost.localdomain<br />
 SuiteSpotUserID= dirsrv<br />
 SuiteSpotGroup= dirsrv<br />
 AdminDomain= redhat.com<br />
 ConfigDirectoryAdminID= admin<br />
 ConfigDirectoryAdminPwd= admin<br />
 ConfigDirectoryLdapURL= <a href="ldap://localhost.localdomain:389/o=NetscapeRoot">ldap://localhost.localdomain:389/o=NetscapeRoot</a> </p>
<p> [register]<br />
 configinst= slapd-localhost::cn=directory manager::password<br />
 localinst= slapd-replica::cn=directory manager::password<br />
 localcertdir= /etc/dirsrv/slapd-localhost<br />
 remotehost= ldap.redhat.com<br />
 remoteport= 636<br />
 remotebinddn= cn=directory manager<br />
 remotebindpw= password<br />
 admindomain= redhat.com<br />
 admindn= uid=admin,ou=Administrators,ou=TopologyManagement,o=NetscapeRoot<br />
 adminpw= password<br />
 destination= remote
</dl>
<p> The <code>[register]</code> directive parameter descriptions:</p>
<dl>
<dt><code>configinst</code> = INSTANCE::BIND_DN::PASSWORD</p>
<dd>
<dd><i>INSTANCE</i> = The server where the existing configuration exists, or the server where you want to add the configuration to. The value takes the form of slapd-INSTANCE.<br />
 <i>BIND_DN</i> = The root DN, usually &#8220;cn=directory manager&#8221;, for the local configuration server.<br />
 <i>PASSWORD</i> = the root DN password.</p>
<dt><code>localinst</code> = INSTANCE::BIND_DN::PASSWORD</p>
<dd>
<dd>The parameters are the same as &#8216;configinst&#8217;. This argument is required for local registerations. </p>
<dt><code>remotehost</code> = The FQDN of the remote server. This is either the rmeote server we</p>
<dd>registering with, or the remote server that is being registered with the local configuration server.</p>
<dt><code>remoteport</code> = The port of the remote server.</p>
<dd>
<dt><code>localcertdir</code> = The directory of the certificate database files (e.g. cert8.db, key3.db). This optional parameter is only used if connecting to the remote server over SSL.</p>
<dd>
<dt><code>remotebinddn</code> = The bind DN, preferrably the root DN, to connect to the remote server.</p>
<dd>
<dt><code>remotebinddn</code> = The password for the remotebinddn entry.</p>
<dd>
<dt><code>admindomain</code> = This is the Admin Domain for the server that is being registered. If registering the local server to the remote server, it would be the domain from the local server. If registering a remote server to the local configuration server, it would be the Admin Domain from the remote server.</p>
<dd>
<dt><code>admindn</code> = The local administrator DN for o=netscaperoot</p>
<dd>
<dt><code>adminpw</code> = The local administrator password.</p>
<dd>
<dt><code>destination</code> = <code>local</code>, or <code>remote</code></p>
<dd>
<dd><i>local</i> = Registers the remote server with the local configuration server.<br />
 <i>remote</i> = Registers the local server with the remote configuration server.</dl>
