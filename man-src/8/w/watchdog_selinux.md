<p>watchdog_selinux &#8211; Security Enhanced Linux Policy for the watchdog processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the watchdog processes via flexible mandatory access control. The watchdog processes execute with the watchdog_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep watchdog_t</code> </p>
<h2>Entrypoints</h2>
<p>The watchdog_t SELinux type can be entered via the <code>watchdog_exec_t</code> file type. </p>
<p> The default entrypoint paths for the watchdog_t domain are the following: </p>
<p> /usr/sbin/watchdog</p>

<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. watchdog policy is extremely flexible and has several booleans that allow you to manipulate the policy and run watchdog with the tightest access possible. </p>
<p> If you want to allow all daemons to write corefiles to /, you must turn on the daemons_dump_core boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_dump_core 1</code> </p>
<p> If you want to enable cluster mode for daemons, you must turn on the daemons_enable_cluster_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P daemons_enable_cluster_mode 1</code> </p>
<p> If you want to allow all daemons to use tcp wrappers, you must turn on the daemons_use_tcp_wrapper boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tcp_wrapper 1</code> </p>
<p> If you want to allow all daemons the ability to read/write terminals, you must turn on the daemons_use_tty boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tty 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Disabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code></p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux watchdog policy is very flexible allowing users to setup their watchdog processes in as secure a method as possible. </p>
<p> STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the watchdog, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t watchdog_var_run_t &#8216;/srv/mywatchdog_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/mywatchdog_content</code> </p>
<p> Note: SELinux often uses regular expressions to specify labels that match multiple files. </p>
<p> <i>The following file types are defined for watchdog:</i> </p>
<p> <code>watchdog_cache_t</code> </p>
<p> &#8211; Set files with the watchdog_cache_t type, if you want to store the files under the /var/cache directory. </p>
<p> <code>watchdog_exec_t</code> </p>
<p> &#8211; Set files with the watchdog_exec_t type, if you want to transition an executable to the watchdog_t domain. </p>
<p> <code>watchdog_initrc_exec_t</code> </p>
<p> &#8211; Set files with the watchdog_initrc_exec_t type, if you want to transition an executable to the watchdog_initrc_t domain. </p>
<p> <code>watchdog_log_t</code> </p>
<p> &#8211; Set files with the watchdog_log_t type, if you want to treat the data as watchdog log data, usually stored under the /var/log directory. </p>
<p> <code>watchdog_unconfined_exec_t</code> </p>
<p> &#8211; Set files with the watchdog_unconfined_exec_t type, if you want to transition an executable to the watchdog_unconfined_t domain. </p>

<p> Note: File context can be temporarily modified with the chcon command. If you want to permanently change the file context you need to use the <code>semanage fcontext</code> command.
