<p>error &#8211; Postfix error/retry mail delivery agent</p>
<h2>Synopsis</h2>
<pre><code>error</code> [generic Postfix daemon options]</pre>
<h2>Description</h2>
<p>The Postfix <code><a href="/docs/linux/man/8-error/">error</a></code>(8) delivery agent processes delivery requests from the queue manager. Each request specifies a queue file, a sender address, the reason for non-delivery (specified as the next-hop destination), and recipient information. The reason may be prefixed with an RFC 3463-compatible detail code; if none is specified a default 4.0.0 or 5.0.0 code is used instead. This program expects to be run from the <code><a href="/docs/linux/man/8-master/">master</a></code>(8) process manager. </p>
<p> Depending on the service name in master.cf, <code>error</code> or <code>retry</code>, the server bounces or defers all recipients in the delivery request using the &quot;next-hop&quot; information as the reason for non-delivery. The <code>retry</code> service name is supported as of Postfix 2.4. </p>
<p> Delivery status reports are sent to the <code><a href="/docs/linux/man/8-bounce/">bounce</a></code>(8), <code><a href="/docs/linux/man/8-defer/">defer</a></code>(8) or <code><a href="/docs/linux/man/8-trace/">trace</a></code>(8) daemon as appropriate.</p>
<h2>Security</h2>
<p>The <code><a href="/docs/linux/man/8-error/">error</a></code>(8) mailer is not security-sensitive. It does not talk to the network, and can be run chrooted at fixed low privilege.</p>
<h2>Standards</h2>
<pre>RFC 3463 (Enhanced Status Codes)</pre>
<h2>Diagnostics</h2>
<p>Problems and transactions are logged to <code><a href="/docs/linux/man/8-syslogd/">syslogd</a></code>(8). </p>
<p> Depending on the setting of the <code>notify_classes</code> parameter, the postmaster is notified of bounces and of other trouble.</p>
<h2>Configuration Parameters</h2>
<p>Changes to <code>main.cf</code> are picked up automatically as <code><a href="/docs/linux/man/8-error/">error</a></code>(8) processes run for only a limited amount of time. Use the command &quot;<code>postfix reload</code>&quot; to speed up a change. </p>
<p> The text below provides only a parameter summary. See <code><a href="/docs/linux/man/5-postconf/">postconf</a></code>(5) for more details including examples.</p>
<dl>
<dt><code>2bounce_notice_recipient (postmaster)</code></p>
<dd>The recipient of undeliverable mail that cannot be returned to the sender.</p>
<dt><code>bounce_notice_recipient (postmaster)</code></p>
<dd>The recipient of postmaster notifications with the message headers of mail that Postfix did not deliver and of SMTP conversation transcripts of mail that Postfix did not receive.</p>
<dt><code>config_directory (see &#8216;postconf -d&#8217; output)</code></p>
<dd>The default location of the Postfix main.cf and master.cf configuration files.</p>
<dt><code>daemon_timeout (18000s)</code></p>
<dd>How much time a Postfix daemon process may take to handle a request before it is terminated by a built-in watchdog timer.</p>
<dt><code>delay_logging_resolution_limit (2)</code></p>
<dd>The maximal number of digits after the decimal point when logging sub-second delay values.</p>
<dt><code>double_bounce_sender (double-bounce)</code></p>
<dd>The sender address of postmaster notifications that are generated by the mail system.</p>
<dt><code>ipc_timeout (3600s)</code></p>
<dd>The time limit for sending or receiving information over an internal communication channel.</p>
<dt><code>max_idle (100s)</code></p>
<dd>The maximum amount of time that an idle Postfix daemon process waits for an incoming connection before terminating voluntarily.</p>
<dt><code>max_use (100)</code></p>
<dd>The maximal number of incoming connections that a Postfix daemon process will service before terminating voluntarily.</p>
<dt><code>notify_classes (resource, software)</code></p>
<dd>The list of error classes that are reported to the postmaster.</p>
<dt><code>process_id (read-only)</code></p>
<dd>The process ID of a Postfix command or daemon process.</p>
<dt><code>process_name (read-only)</code></p>
<dd>The process name of a Postfix command or daemon process.</p>
<dt><code>queue_directory (see &#8216;postconf -d&#8217; output)</code></p>
<dd>The location of the Postfix top-level queue directory.</p>
<dt><code>syslog_facility (mail)</code></p>
<dd>The syslog facility of Postfix logging.</p>
<dt><code>syslog_name (see &#8216;postconf -d&#8217; output)</code></p>
<dd>The mail system name that is prepended to the process name in syslog records, so that &quot;smtpd&quot; becomes, for example, &quot;postfix/smtpd&quot;.</dl>
