<p>dnsmasq_selinux &#8211; Security Enhanced Linux Policy for the dnsmasq processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the dnsmasq processes via flexible mandatory access control. The dnsmasq processes execute with the dnsmasq_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep dnsmasq_t</code> </p>
<h2>Entrypoints</h2>
<p>The dnsmasq_t SELinux type can be entered via the <code>dnsmasq_exec_t</code> file type. </p>
<p> The default entrypoint paths for the dnsmasq_t domain are the following: </p>
<p> /usr/sbin/dnsmasq</p>
<h2>Process Types</h2>
<p>SELinux defines process types (domains) for each process running on the system </p>

<p> Note: <code>semanage permissive -a dnsmasq_t</code> can be used to make the process type dnsmasq_t permissive. SELinux does not deny access to permissive process types, but the AVC (SELinux denials) messages are still generated.</p>
<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. dnsmasq policy is extremely flexible and has several booleans that allow you to manipulate the policy and run dnsmasq with the tightest access possible. </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to allow all daemons to write corefiles to /, you must turn on the daemons_dump_core boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_dump_core 1</code> </p>
<p> If you want to enable cluster mode for daemons, you must turn on the daemons_enable_cluster_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P daemons_enable_cluster_mode 1</code> </p>
<p> If you want to allow all daemons to use tcp wrappers, you must turn on the daemons_use_tcp_wrapper boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tcp_wrapper 1</code> </p>
<p> If you want to allow all daemons the ability to read/write terminals, you must turn on the daemons_use_tty boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tty 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Disabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code></p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux dnsmasq policy is very flexible allowing users to setup their dnsmasq processes in as secure a method as possible. </p>
<p> STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the dnsmasq, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t dnsmasq_var_run_t &#8216;/srv/mydnsmasq_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/mydnsmasq_content</code> </p>
<p> Note: SELinux often uses regular expressions to specify labels that match multiple files. </p>
<p> <i>The following file types are defined for dnsmasq:</i> </p>
<p> <code>dnsmasq_etc_t</code> </p>
<p> &#8211; Set files with the dnsmasq_etc_t type, if you want to store dnsmasq files in the /etc directories. </p>
<dl>
<dt>Paths:</p>
<dd>/etc/dnsmasq.d(/.*)?, /etc/dnsmasq.conf </p>
</dl>
<p> <code>dnsmasq_exec_t</code> </p>
<p> &#8211; Set files with the dnsmasq_exec_t type, if you want to transition an executable to the dnsmasq_t domain. </p>
<p> <code>dnsmasq_initrc_exec_t</code> </p>
<p> &#8211; Set files with the dnsmasq_initrc_exec_t type, if you want to transition an executable to the dnsmasq_initrc_t domain. </p>
<p> <code>dnsmasq_lease_t</code> </p>
<p> &#8211; Set files with the dnsmasq_lease_t type, if you want to treat the files as dnsmasq lease data. </p>
<dl>
<dt>Paths:</p>
<dd>/var/lib/dnsmasq(/.*)?, /var/lib/misc/dnsmasq.leases </p>
</dl>
<p> <code>dnsmasq_unit_file_t</code> </p>
<p> &#8211; Set files with the dnsmasq_unit_file_t type, if you want to treat the files as dnsmasq unit content. </p>
<p> <code>dnsmasq_var_log_t</code> </p>
<p> &#8211; Set files with the dnsmasq_var_log_t type, if you want to treat the data as dnsmasq var log data, usually stored under the /var/log directory. </p>
<p> <code>dnsmasq_var_run_t</code> </p>
<p> &#8211; Set files with the dnsmasq_var_run_t type, if you want to store the dnsmasq files under the /run or /var/run directory. </p>
<dl>
<dt>Paths:</p>
<dd>/var/run/dnsmasq.*, /var/run/libvirt/network(/.*)? </p>
</dl>
<p> Note: File context can be temporarily modified with the chcon command. If you want to permanently change the file context you need to use the <code>semanage fcontext</code> command. This will modify the SELinux labeling database. You will need to use <code>restorecon</code> to apply the labels.</p>
