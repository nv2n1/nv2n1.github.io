<p>dnssec-importkey &#8211; Import DNSKEY records from external systems so they can be managed.</p>
<h2>Synopsis</h2>
<dl>
<dt> <code>dnssec-importkey</code> [<code>-K&nbsp;<wbr></code><i>directory</i>] [<code>-L&nbsp;<wbr></code><i>ttl</i>] [<code>-P&nbsp;<wbr></code><i>date/offset</i>] [<code>-D&nbsp;<wbr></code><i>date/offset</i>] [<code>-h</code>] [<code>-v&nbsp;<wbr></code><i>level</i>] [<code>-V</code>] {<code>keyfile</code>}</p>
<dt> <code>dnssec-importkey</code> {<code>-f&nbsp;<wbr></code><i>filename</i>} [<code>-K&nbsp;<wbr></code><i>directory</i>] [<code>-L&nbsp;<wbr></code><i>ttl</i>] [<code>-P&nbsp;<wbr></code><i>date/offset</i>] [<code>-D&nbsp;<wbr></code><i>date/offset</i>] [<code>-h</code>] [<code>-v&nbsp;<wbr></code><i>level</i>] [<code>-V</code>] [<code>dnsname</code>]</dl>
<h2>Description</h2>
<p><code>dnssec-importkey</code></p>
<dd>reads a public DNSKEY record and generates a pair of .key/.private files. The DNSKEY record may be read from an existing .key file, in which case a corresponding .private file will be generated, or it may be read from any other file or from the standard input, in which case both .key and .private files will be generated. </p>
<p> The newly-created .private file does <i>not</i> contain private key data, and cannot be used for signing. However, having a .private file makes it possible to set publication (<code>-P</code>) and deletion (<code>-D</code>) times for the key, which means the public key can be added to and removed from the DNSKEY RRset on schedule even if the true private key is stored offline.</p>
<h2>Options</h2>
<p>-f <i>filename</i></p>
<dl>
<dd>Zone file mode: instead of a public keyfile name, the argument is the DNS domain name of a zone master file, which can be read from <code>file</code>. If the domain name is the same as <code>file</code>, then it may be omitted. </p>
<p> If <code>file</code> is set to &quot;-&quot;, then the zone data is read from the standard input.</dl>
<p> -K <i>directory</i></p>
<dl>
<dd>Sets the directory in which the key files are to reside.</dl>
<p> -L <i>ttl</i></p>
<dl>
<dd>Sets the default TTL to use for this key when it is converted into a DNSKEY RR. If the key is imported into a zone, this is the TTL that will be used for it, unless there was already a DNSKEY RRset in place, in which case the existing TTL would take precedence. Setting the default TTL to 0 or none removes it.</dl>
<p> -h</p>
<dl>
<dd>Emit usage message and exit.</dl>
<p> -v <i>level</i></p>
<dl>
<dd>Sets the debugging level.</dl>
<p> -V</p>
<dl>
<dd>Prints version information.</dl>
<h2>Timing Options</h2>
<p>Dates can be expressed in the format YYYYMMDD or YYYYMMDDHHMMSS. If the argument begins with a &#8216;+&#8217; or &#8216;-&#8216;, it is interpreted as an offset from the present time. For convenience, if such an offset is followed by one of the suffixes &#8216;y&#8217;, &#8216;mo&#8217;, &#8216;w&#8217;, &#8216;d&#8217;, &#8216;h&#8217;, or &#8216;mi&#8217;, then the offset is computed in years (defined as 365 24-hour days, ignoring leap years), months (defined as 30 24-hour days), weeks, days, hours, or minutes, respectively. Without a suffix, the offset is computed in seconds. To explicitly prevent a date from being set, use &#8216;none&#8217; or &#8216;never&#8217;. </p>
<p> -P <i>date/offset</i></p>
<dl>
<dd>Sets the date on which a key is to be published to the zone. After that date, the key will be included in the zone but will not be used to sign it.</dl>
<p> -D <i>date/offset</i></p>
<dl>
<dd>Sets the date on which the key is to be deleted. After that date, the key will no longer be included in the zone. (It may remain in the key repository, however.)</dl>
<h2>Files</h2>
<p>A keyfile can be designed by the key identification <i>Knnnn.+aaa+iiiii</i> or the full file name <i>Knnnn.+aaa+iiiii.key</i> as generated by <a href="/docs/linux/man/8-dnssec-keygen/">dnssec-keygen</a>(8).</p>
