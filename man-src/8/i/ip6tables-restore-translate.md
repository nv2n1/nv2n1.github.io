<p>iptables-translate &#8212; translation tool to migrate from iptables to nftables </p>
<p> ip6tables-translate &#8212; translation tool to migrate from ip6tables to nftables</p>
<h2>Description</h2>
<p>There is a set of tools to help the system administrator translate a given ruleset from <code><a href="/docs/linux/man/8-iptables/">iptables</a>(8)</code> and <code><a href="/docs/linux/man/8-ip6tables/">ip6tables</a>(8)</code> to <code><a href="/docs/linux/man/8-nftables/">nftables</a>(8)</code>. The available commands are:</p>
<dl>
<dt>&bull;</p>
<dd>iptables-translate</p>
<dt>&bull;</p>
<dd>iptables-restore-translate</p>
<dt>&bull;</p>
<dd>ip6tables-translate</p>
<dt>&bull;</p>
<dd>ip6tables-restore-translate </p>
<h2>Usage</h2>
<p>They take as input the original <code><a href="/docs/linux/man/8-iptables/">iptables</a>(8)</code>/<code><a href="/docs/linux/man/8-ip6tables/">ip6tables</a>(8)</code> syntax and output the native <code><a href="/docs/linux/man/8-nftables/">nftables</a>(8)</code> syntax. </p>
<p> The <code>iptables-restore-translate</code> tool reads a ruleset in the syntax produced by <code><a href="/docs/linux/man/8-iptables-save/">iptables-save</a>(8)</code>. Likewise, the <code>ip6tables-restore-translate</code> tool reads one produced by <code><a href="/docs/linux/man/8-ip6tables-save/">ip6tables-save</a>(8)</code>. No ruleset modifications occur, these tools are text converters only. </p>
<p> The <code>iptables-translate</code> reads a command line as if it was entered to <code><a href="/docs/linux/man/8-iptables/">iptables</a>(8)</code>, and <code>ip6tables-translate</code> reads a command like as if it was entered to <code><a href="/docs/linux/man/8-ip6tables/">ip6tables</a>(8)</code>.</p>
<h2>Examples</h2>
<p>Basic operation examples. Single command translation: </p>
<pre>root [at] machine:~# iptables-translate -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT
nft add rule ip filter INPUT tcp dport 22 ct state new counter accept
root [at] machine:~# ip6tables-translate -A FORWARD -i eth0 -o eth3 -p udp -m multiport --dports 111,222 -j ACCEPT
nft add rule ip6 filter FORWARD iifname eth0 oifname eth3 meta l4proto udp udp dport { 111,222} counter accept</pre>
<p>Whole ruleset translation: </p>
<pre>root [at] machine:~# iptables-save &gt; save.txt
root [at] machine:~# cat save.txt
# Generated by iptables-save v1.6.0 on Sat Dec 24 14:26:40 2016
*filter
:INPUT ACCEPT [5166:1752111]
:FORWARD ACCEPT [0:0]
:OUTPUT ACCEPT [5058:628693]
-A FORWARD -p tcp -m tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT
COMMIT
# Completed on Sat Dec 24 14:26:40 2016
root [at] machine:~# iptables-restore-translate -f save.txt
# Translated by iptables-restore-translate v1.6.0 on Sat Dec 24 14:26:59 2016
add table ip filter
add chain ip filter INPUT { type filter hook input priority 0; }
add chain ip filter FORWARD { type filter hook forward priority 0; }
add chain ip filter OUTPUT { type filter hook output priority 0; }
add rule ip filter FORWARD tcp dport 22 ct state new counter accept
root [at] machine:~# iptables-restore-translate -f save.txt &gt; ruleset.nft
root [at] machine:~# nft -f ruleset.nft
root [at] machine:~# nft list ruleset
table ip filter {
 chain INPUT {
 type filter hook input priority 0; policy accept;
 }
 chain FORWARD {
 type filter hook forward priority 0; policy accept;
 tcp dport ssh ct state new counter packets 0 bytes 0 accept
 }
 chain OUTPUT {
 type filter hook output priority 0; policy accept;
 }
}</pre>
<h2>Limitations</h2>
<p>Some (few) extensions may be not supported (or fully-supported) for whatever reason (for example, they were considered obsolete, or we didn&#8217;t have the time to work on them). </p>
<p> There are no translations available for <code><a href="/docs/linux/man/8-ebtables/">ebtables</a>(8)</code> and <code><a href="/docs/linux/man/8-arptables/">arptables</a>(8)</code>. </p>
<p> To get up-to-date information about this, please head to <code><a rel="nofollow" href="https://wiki.nftables.org/">https://wiki.nftables.org/</a></code>.</p>
