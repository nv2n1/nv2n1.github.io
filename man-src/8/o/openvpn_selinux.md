<p>openvpn_selinux &#8211; Security Enhanced Linux Policy for the openvpn processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the openvpn processes via flexible mandatory access control. The openvpn processes execute with the openvpn_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep openvpn_t</code> </p>
<h2>Entrypoints</h2>
<p>The openvpn_t SELinux type can be entered via the <code>openvpn_exec_t</code> file type. </p>
<p> The default entrypoint paths for the openvpn_t domain are the following: </p>
<p> /usr/sbin/openvpn</p>
<h2>Process Types</h2>
<p>SELinux defines process types (domains) for each process running on the system </p>
<p> You can see the context of a process using the <code>-Z</code> option to <code>psP Policy governs the access confined processes have to files. SELinux openvpn policy is very flexible allowing users to setup their openvpn processes in as secure a method as possible. </p>
<p> The following process types are defined for openvpn: </p>
<p> openvpn_t, openvpn_unconfined_script_t</code> </p>
<p> Note: <code>semanage permissive -a openvpn_t</code> can be used to make the process type openvpn_t permissive. SELinux does not deny access to permissive process types, but the AVC (SELinux denials) messages are still generated.</p>
<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. openvpn policy is extremely flexible and has several booleans that allow you to manipulate the policy and run openvpn with the tightest access possible. </p>
<p> If you want to determine whether openvpn can connect to the TCP network, you must turn on the openvpn_can_network_connect boolean. Enabled by default. </p>
<p> <code>setsebool -P openvpn_can_network_connect 1</code> </p>
<p> If you want to determine whether openvpn can read generic user home content files, you must turn on the openvpn_enable_homedirs boolean. Disabled by default. </p>
<p> <code>setsebool -P openvpn_enable_homedirs 1</code> </p>
<p> If you want to allow openvpn to run unconfined scripts, you must turn on the openvpn_run_unconfined boolean. Disabled by default. </p>
<p> <code>setsebool -P openvpn_run_unconfined 1</code> </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to allow all daemons to write corefiles to /, you must turn on the daemons_dump_core boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_dump_core 1</code> </p>
<p> If you want to enable cluster mode for daemons, you must turn on the daemons_enable_cluster_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P daemons_enable_cluster_mode 1</code> </p>
<p> If you want to allow all daemons to use tcp wrappers, you must turn on the daemons_use_tcp_wrapper boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tcp_wrapper 1</code> </p>
<p> If you want to allow all daemons the ability to read/write terminals, you must turn on the daemons_use_tty boolean. Disabled by default. </p>
<p> <code>setsebool -P daemons_use_tty 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Disabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code> </p>
<p> If you want to support ecryptfs home directories, you must turn on the use_ecryptfs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_ecryptfs_home_dirs 1</code> </p>
<p> If you want to support NFS home directories, you must turn on the use_nfs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_nfs_home_dirs 1</code> </p>
<p> If you want to support SAMBA home directories, you must turn on the use_samba_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_samba_home_dirs 1</code></p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux openvpn policy is very flexible allowing users to setup their openvpn processes in as secure a method as possible. </p>
<p> EQUIVALENCE DIRECTORIES</code> </p>
<p> openvpn policy stores data with multiple different file context types under the /var/run/openvpn directory. If you would like to store the data in a different directory you can use the semanage command to create an equivalence mapping. If you wanted to store this data under the /srv dirctory you would execute the following command: </p>
<p> <code>semanage fcontext -a -e /var/run/openvpn /srv/openvpn</code><br />
 <code>restorecon -R -v /srv/openvpn</code> </p>
<p> <code>STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the openvpn, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t openvpn_var_run_t &#8216;/srv/myopenvpn_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/myopenvpn_content</code> </p>
<p> Note: SELinux often uses regular expressions to specify labels that match multiple files. </p>
<p> <i>The following file types are defined for openvpn:</i> </p>
<p> <code>openvpn_etc_rw_t</code> </p>
<p> &#8211; Set files with the openvpn_etc_rw_t type, if you want to treat the files as openvpn etc read/write content. </p>
<p> <code>openvpn_etc_t</code> </p>
<p> &#8211; Set files with the openvpn_etc_t type, if you want to store openvpn files in the /etc directories. </p>
<p> <code>openvpn_exec_t</code> </p>
<p> &#8211; Set files with the openvpn_exec_t type, if you want to transition an executable to the openvpn_t domain. </p>
<p> <code>openvpn_initrc_exec_t</code> </p>
<p> &#8211; Set files with the openvpn_initrc_exec_t type, if you want to transition an executable to the openvpn_initrc_t domain. </p>

<h2>Commands</h2>
<p><code>semanage fcontext</code> can also be used to manipulate default file context mappings. </p>

<p> <code>semanage module</code> can also be used to enable/disable/install/remove policy modules. </p>
<p> <code>semanage port</code> can also be used to manipulate the port definitions </p>
<p> <code>semanage boolean</code> can also be used to manipulate the booleans </p>
