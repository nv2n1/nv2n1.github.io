<p><code>puppet-module</code> &#8211; Creates, installs and searches for modules on the Puppet Forge.</p>
<h2>Synopsis</h2>
<p>puppet module <i>action</i> [&#8211;environment production ] [&#8211;modulepath $confdir/modules:/usr/share/puppet/modules ]</p>
<h2>Description</h2>
<p>This subcommand can find, install, and manage modules from the Puppet Forge, a repository of user-contributed Puppet code. It can also generate empty modules, and prepare locally developed modules for release on the Forge.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument, although it may or may not be relevant to the present action. For example, <code>server</code> and <code>run_mode</code> are valid configuration parameters, so you can specify <code>&#8211;server &lt;servername&gt;</code>, or <code>&#8211;run_mode &lt;runmode&gt;</code> as an argument. </p>
<p> See the configuration file documentation at <i><a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a></i> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet with <code>&#8211;genconfig</code>.</p>
<dl>
<dt>&#8211;render-as FORMAT</p>
<dd>The format in which to render output. The most common formats are <code>json</code>, <code>s</code> (string), <code>yaml</code>, and <code>console</code>, but other options such as <code>dot</code> are sometimes available.</p>
<dt>&#8211;verbose</p>
<dd>Whether to log verbosely.</p>
<dt>&#8211;debug</p>
<dd>Whether to log debug information.</p>
<dt>&#8211;environment production</p>
<dd>The environment Puppet is running in. For clients (e.g., <code>puppet agent</code>) this determines the environment itself, which is used to find modules and much more. For servers (i.e., <code>puppet master</code>) this provides the default environment for nodes we know nothing about.</p>
<dt>&#8211;modulepath $confdir/modules:/usr/share/puppet/modules</p>
<dd>The search path for modules, as a list of directories separated by the system path separator character. (The POSIX path separator is &#8216;:&#8217;, and the Windows path separator is &#8216;;&#8217;.)</dl>
<h2>Actions</h2>
<dl>
<dt><code>build</code> &#8211; Build a module release package.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module build [<i>path</i>]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Prepares a local module for release on the Puppet Forge by building a ready-to-upload archive file.</p>
<dd>This action uses the Modulefile in the module directory to set metadata used by the Forge. See <i><a rel="nofollow" href="http://links.puppetlabs.com/modulefile">http://links.puppetlabs.com/modulefile</a></i> for more about writing modulefiles.</p>
<dd>After being built, the release archive file can be found in the module&#8217;s <code>pkg</code> directory.</p>
<dd><code>RETURNS</code></p>
<dd>Pathname object representing the path to the release archive.</p>
<dt><code>changes</code> &#8211; Show modified files of an installed module.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module changes <i>path</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Shows any files in a module that have been modified since it was installed. This action compares the files on disk to the md5 checksums included in the module&#8217;s metadata.</p>
<dd><code>RETURNS</code></p>
<dd>Array of strings representing paths of modified files.</p>
<dt><code>generate</code> &#8211; Generate boilerplate for a new module.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module generate <i>name</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Generates boilerplate for a new module by creating the directory structure and files recommended for the Puppet community&#8217;s best practices.</p>
<dd>A module may need additional directories beyond this boilerplate if it provides plugins, files, or templates.</p>
<dd><code>RETURNS</code></p>
<dd>Array of Pathname objects representing paths of generated files.</p>
<dt><code>install</code> &#8211; Install a module from the Puppet Forge or a release archive.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module install [&#8211;force | -f] [&#8211;target-dir DIR | -i DIR] [&#8211;ignore-dependencies] [&#8211;version VER | -v VER] <i>name</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Installs a module from the Puppet Forge or from a release archive file.</p>
<dd>The specified module will be installed into the directory specified with the <code>&#8211;target-dir</code> option, which defaults to /Users/josh/.puppet/modules.</p>
<dd><code>OPTIONS</code> <i>&#8211;force</i> | <i>-f</i> &#8211; Force overwrite of existing module, if any.</p>
<dd><i>&#8211;ignore-dependencies</i> &#8211; Do not attempt to install dependencies.</p>
<dd><i>&#8211;target-dir DIR</i> | <i>-i DIR</i> &#8211; The directory into which modules are installed; defaults to the first directory in the modulepath.</p>
<dd>Specifying this option will change the installation directory, and will use the existing modulepath when checking for dependencies. If you wish to check a different set of directories for dependencies, you must also use the <code>&#8211;environment</code> or <code>&#8211;modulepath</code> options.</p>
<dd><i>&#8211;version VER</i> | <i>-v VER</i> &#8211; Module version to install; can be an exact version or a requirement string, eg &#8216;&gt;= 1.0.3&#8217;. Defaults to latest version.</p>
<dd><code>RETURNS</code></p>
<dd>Pathname object representing the path to the installed module.</p>
<dt><code>list</code> &#8211; List installed modules</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module list [&#8211;tree]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Lists the installed puppet modules. By default, this action scans the modulepath from puppet.conf&#8217;s <code>[main]</code> block; use the &#8211;modulepath option to change which directories are scanned.</p>
<dd>The output of this action includes information from the module&#8217;s metadata, including version numbers and unmet module dependencies.</p>
<dd><code>OPTIONS</code> <i>&#8211;tree</i> &#8211; Whether to show dependencies as a tree view</p>
<dd><code>RETURNS</code></p>
<dd>hash of paths to module objects</p>
<dt><code>search</code> &#8211; Search the Puppet Forge for a module.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module search <i>search_term</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Searches a repository for modules whose names, descriptions, or keywords match the provided search term.</p>
<dd><code>RETURNS</code></p>
<dd>Array of module metadata hashes</p>
<dt><code>uninstall</code> &#8211; Uninstall a puppet module.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module uninstall [&#8211;force | -f] [&#8211;version=] <i>name</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Uninstalls a puppet module from the modulepath (or a specific target directory).</p>
<dd><code>OPTIONS</code> <i>&#8211;force</i> | <i>-f</i> &#8211; Force the uninstall of an installed module even if there are local changes or the possibility of causing broken dependencies.</p>
<dd><i>&#8211;version=</i> &#8211; The version of the module to uninstall. When using this option, a module matching the specified version must be installed or else an error is raised.</p>
<dd><code>RETURNS</code></p>
<dd>Hash of module objects representing uninstalled modules and related errors.</p>
<dt><code>upgrade</code> &#8211; Upgrade a puppet module.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet module upgrade [&#8211;force | -f] [&#8211;ignore-dependencies] [&#8211;version=] <i>name</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Upgrades a puppet module.</p>
<dd><code>OPTIONS</code> <i>&#8211;force</i> | <i>-f</i> &#8211; Force the upgrade of an installed module even if there are local changes or the possibility of causing broken dependencies.</p>
<dd><i>&#8211;ignore-dependencies</i> &#8211; Do not attempt to install dependencies</p>
<dd><i>&#8211;version=</i> &#8211; The version of the module to upgrade to.</p>
<dd><code>RETURNS</code></p>
<dd>Hash</dl>
<h2>Examples</h2>
<p><code>build</code> </p>
<p> Build a module release: </p>
<p> $ puppet module build puppetlabs-apache notice: Building /Users/kelseyhightower/puppetlabs-apache for release Module built: /Users/kelseyhightower/puppetlabs-apache/pkg/puppetlabs-apache-0.0.1.tar.gz </p>
<p> Build the module in the current working directory: </p>
<p> $ cd /Users/kelseyhightower/puppetlabs-apache $ puppet module build notice: Building /Users/kelseyhightower/puppetlabs-apache for release Module built: /Users/kelseyhightower/puppetlabs-apache/pkg/puppetlabs-apache-0.0.1.tar.gz </p>
<p> <code>changes</code> </p>
<p> Show modified files of an installed module: </p>
<p> $ puppet module changes /etc/puppet/modules/vcsrepo/ warning: 1 files modified lib/puppet/provider/vcsrepo.rb </p>
<p> <code>generate</code> </p>
<p> Generate a new module in the current directory: </p>
<p> $ puppet module generate puppetlabs-ssh notice: Generating module at /Users/kelseyhightower/puppetlabs-ssh puppetlabs-ssh puppetlabs-ssh/tests puppetlabs-ssh/tests/init.pp puppetlabs-ssh/spec puppetlabs-ssh/spec/spec_helper.rb puppetlabs-ssh/spec/spec.opts puppetlabs-ssh/README puppetlabs-ssh/Modulefile puppetlabs-ssh/metadata.json puppetlabs-ssh/manifests puppetlabs-ssh/manifests/init.pp </p>
<p> <code>install</code> </p>
<p> Install a module: </p>
<p> $ puppet module install puppetlabs-vcsrepo Preparing to install into /etc/puppet/modules &#8230; Downloading from <a rel="nofollow" href="http://forge.puppetlabs.com">http://forge.puppetlabs.com</a> &#8230; Installing &#8212; do not interrupt &#8230; /etc/puppet/modules └── puppetlabs-vcsrepo (v0.0.4) </p>
<p> Install a module to a specific environment: </p>
<p> $ puppet module install puppetlabs-vcsrepo &#8211;environment development Preparing to install into /etc/puppet/environments/development/modules &#8230; Downloading from <a rel="nofollow" href="http://forge.puppetlabs.com">http://forge.puppetlabs.com</a> &#8230; Installing &#8212; do not interrupt &#8230; /etc/puppet/environments/development/modules └── puppetlabs-vcsrepo (v0.0.4) </p>
<p> Install a specific module version: </p>
<p> $ puppet module install puppetlabs-vcsrepo -v 0.0.4 Preparing to install into /etc/puppet/modules &#8230; Downloading from <a rel="nofollow" href="http://forge.puppetlabs.com">http://forge.puppetlabs.com</a> &#8230; Installing &#8212; do not interrupt &#8230; /etc/puppet/modules └── puppetlabs-vcsrepo (v0.0.4) </p>
<p> Install a module into a specific directory: </p>
<p> $ puppet module install puppetlabs-vcsrepo &#8211;target-dir=/usr/share/puppet/modules Preparing to install into /usr/share/puppet/modules &#8230; Downloading from <a rel="nofollow" href="http://forge.puppetlabs.com">http://forge.puppetlabs.com</a> &#8230; Installing &#8212; do not interrupt &#8230; /usr/share/puppet/modules └── puppetlabs-vcsrepo (v0.0.4) </p>
<p> Install a module into a specific directory and check for dependencies in other directories: </p>
<p> $ puppet module install puppetlabs-vcsrepo &#8211;target-dir=/usr/share/puppet/modules &#8211;modulepath /etc/puppet/modules Preparing to install into /usr/share/puppet/modules &#8230; Downloading from <a rel="nofollow" href="http://forge.puppetlabs.com">http://forge.puppetlabs.com</a> &#8230; Installing &#8212; do not interrupt &#8230; /usr/share/puppet/modules └── puppetlabs-vcsrepo (v0.0.4) </p>
<p> Install a module from a release archive: </p>
<p> $ puppet module install puppetlabs-vcsrepo-0.0.4.tar.gz Preparing to install into /etc/puppet/modules &#8230; Downloading from <a rel="nofollow" href="http://forge.puppetlabs.com">http://forge.puppetlabs.com</a> &#8230; Installing &#8212; do not interrupt &#8230; /etc/puppet/modules └── puppetlabs-vcsrepo (v0.0.4) </p>
<p> Install a module from a release archive and ignore dependencies: </p>
<p> $ puppet module install puppetlabs-vcsrepo-0.0.4.tar.gz &#8211;ignore-dependencies Preparing to install into /etc/puppet/modules &#8230; Installing &#8212; do not interrupt &#8230; /etc/puppet/modules └── puppetlabs-vcsrepo (v0.0.4) </p>
<p> <code>list</code> </p>
<p> List installed modules: </p>
<p> $ puppet module list /etc/puppet/modules ├── bodepd-create_resources (v0.0.1) ├── puppetlabs-bacula (v0.0.2) ├── puppetlabs-mysql (v0.0.1) ├── puppetlabs-sqlite (v0.0.1) └── puppetlabs-stdlib (v2.2.1) /usr/share/puppet/modules (no modules installed) </p>
<p> List installed modules in a tree view: </p>
<p> $ puppet module list &#8211;tree /etc/puppet/modules └─┬ puppetlabs-bacula (v0.0.2)</p>
<dl>
<dd>
<pre>├── puppetlabs-stdlib (v2.2.1)
├─┬ puppetlabs-mysql (v0.0.1)
│ └── bodepd-create_resources (v0.0.1)
└── puppetlabs-sqlite (v0.0.1)</pre>
<dd></dl>
<p> /usr/share/puppet/modules (no modules installed) </p>
<p> List installed modules from a specified environment: </p>
<p> $ puppet module list &#8211;environment production /etc/puppet/modules ├── bodepd-create_resources (v0.0.1) ├── puppetlabs-bacula (v0.0.2) ├── puppetlabs-mysql (v0.0.1) ├── puppetlabs-sqlite (v0.0.1) └── puppetlabs-stdlib (v2.2.1) /usr/share/puppet/modules (no modules installed) </p>
<p> List installed modules from a specified modulepath: </p>
<p> $ puppet module list &#8211;modulepath /usr/share/puppet/modules /usr/share/puppet/modules (no modules installed) </p>
<p> <code>search</code> </p>
<p> Search the Puppet Forge for a module: </p>
<p> $ puppet module search puppetlabs NAME DESCRIPTION AUTHOR KEYWORDS bacula This is a generic Apache module @puppetlabs backups </p>
<p> <code>uninstall</code> </p>
<p> Uninstall a module: </p>
<p> $ puppet module uninstall puppetlabs-ssh Removed /etc/puppet/modules/ssh (v1.0.0) </p>
<p> Uninstall a module from a specific directory: </p>
<p> $ puppet module uninstall puppetlabs-ssh &#8211;modulepath /usr/share/puppet/modules Removed /usr/share/puppet/modules/ssh (v1.0.0) </p>
<p> Uninstall a module from a specific environment: </p>
<p> $ puppet module uninstall puppetlabs-ssh &#8211;environment development Removed /etc/puppet/environments/development/modules/ssh (v1.0.0) </p>
<p> Uninstall a specific version of a module: </p>
<p> $ puppet module uninstall puppetlabs-ssh &#8211;version 2.0.0 Removed /etc/puppet/modules/ssh (v2.0.0) </p>
<p> <code>upgrade</code> </p>
<p> upgrade an installed module to the latest version </p>
<p> $ puppet module upgrade puppetlabs-apache /etc/puppet/modules └── puppetlabs-apache (v1.0.0 -&gt; v2.4.0) </p>
<p> upgrade an installed module to a specific version </p>
<p> $ puppet module upgrade puppetlabs-apache &#8211;version 2.1.0 /etc/puppet/modules └── puppetlabs-apache (v1.0.0 -&gt; v2.1.0) </p>
<p> upgrade an installed module for a specific environment </p>
<p> $ puppet module upgrade puppetlabs-apache &#8211;environment test /usr/share/puppet/environments/test/modules └── puppetlabs-apache (v1.0.0 -&gt; v2.4.0)</p>
