<p><code>puppet-certificate</code> &#8211; Provide access to the CA for certificate management.</p>
<h2>Synopsis</h2>
<p>puppet certificate <i>action</i> [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i></p>
<h2>Description</h2>
<p>This subcommand interacts with a local or remote Puppet certificate authority. Currently, its behavior is not a full superset of <code>puppet cert</code>; specifically, it is unable to mimic puppet cert&#8217;s &quot;clean&quot; option, and its &quot;generate&quot; action submits a CSR rather than creating a signed certificate.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument, although it may or may not be relevant to the present action. For example, <code>server</code> and <code>run_mode</code> are valid configuration parameters, so you can specify <code>&#8211;server &lt;servername&gt;</code>, or <code>&#8211;run_mode &lt;runmode&gt;</code> as an argument. </p>
<p> See the configuration file documentation at <i><a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a></i> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet with <code>&#8211;genconfig</code>.</p>
<dl>
<dt>&#8211;render-as FORMAT</p>
<dd>The format in which to render output. The most common formats are <code>json</code>, <code>s</code> (string), <code>yaml</code>, and <code>console</code>, but other options such as <code>dot</code> are sometimes available.</p>
<dt>&#8211;verbose</p>
<dd>Whether to log verbosely.</p>
<dt>&#8211;debug</p>
<dd>Whether to log debug information.</p>
<dt>&#8211;ca-location LOCATION</p>
<dd>Whether to act on the local certificate authority or one provided by a remote puppet master. Allowed values are &#8216;local&#8217; and &#8216;remote.&#8217;</p>
<dd>This option is required.</p>
<dt>&#8211;extra HASH</p>
<dd>A terminus can take additional arguments to refine the operation, which are passed as an arbitrary hash to the back-end. Anything passed as the extra value is just send direct to the back-end.</p>
<dt>&#8211;terminus TERMINUS</p>
<dd>Indirector faces expose indirected subsystems of Puppet. These subsystems are each able to retrieve and alter a specific type of data (with the familiar actions of <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code>) from an arbitrary number of pluggable backends. In Puppet parlance, these backends are called terminuses.</p>
<dd>Almost all indirected subsystems have a <code>rest</code> terminus that interacts with the puppet master&#8217;s data. Most of them have additional terminuses for various local data models, which are in turn used by the indirected subsystem on the puppet master whenever it receives a remote request.</p>
<dd>The terminus for an action is often determined by context, but occasionally needs to be set explicitly. See the &quot;Notes&quot; section of this face&#8217;s manpage for more details.</dl>
<h2>Actions</h2>
<dl>
<dt><code>destroy</code> &#8211; Delete a certificate.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate destroy [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i> <i>host</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Deletes a certificate. This action currently only works on the local CA.</p>
<dd><code>RETURNS</code></p>
<dd>Nothing.</p>
<dt><code>find</code> &#8211; Retrieve a certificate.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate find [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i> <i>host</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Retrieve a certificate.</p>
<dd><code>RETURNS</code></p>
<dd>An x509 SSL certificate.</p>
<dd>Note that this action has a side effect of caching a copy of the certificate in Puppet&#8217;s <code>ssldir</code>.</p>
<dt><code>generate</code> &#8211; Generate a new certificate signing request.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate generate [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i> [&#8211;dns-alt-names NAMES] <i>host</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Generates and submits a certificate signing request (CSR) for the specified host. This CSR will then have to be signed by a user with the proper authorization on the certificate authority.</p>
<dd>Puppet agent usually handles CSR submission automatically. This action is primarily useful for requesting certificates for individual users and external applications.</p>
<dd><code>OPTIONS</code> <i>&#8211;dns-alt-names NAMES</i> &#8211; The comma-separated list of alternative DNS names to use for the local host. When the node generates a CSR for itself, these are added to the request as the desired <code>subjectAltName</code> in the certificate: additional DNS labels that the certificate is also valid answering as. This is generally required if you use a non-hostname <code>certname</code>, or if you want to use <code>puppet kick</code> or <code>puppet resource -H</code> and the primary certname does not match the DNS name you use to communicate with the host. This is unnecessary for agents, unless you intend to use them as a server for <code>puppet kick</code> or remote <code>puppet resource</code> management. It is rarely necessary for servers; it is usually helpful only if you need to have a pool of multiple load balanced masters, or for the same master to respond on two physically separate networks under different names.</p>
<dd><code>RETURNS</code></p>
<dd>Nothing.</p>
<dt><code>info</code> &#8211; Print the default terminus class for this face.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate info [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Prints the default terminus class for this subcommand. Note that different run modes may have different default termini; when in doubt, specify the run mode with the &#8216;&#8211;run_mode&#8217; option.</p>
<dt><code>list</code> &#8211; List all certificate signing requests.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate list [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>List all certificate signing requests.</p>
<dd><code>RETURNS</code></p>
<dd>An array of #inspect output from CSR objects. This output is currently messy, but does contain the names of nodes requesting certificates. This action returns #inspect strings even when used from the Ruby API.</p>
<dt><code>save</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate save [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i> <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</p>
<dt><code>search</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate search [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i> <i>query</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</p>
<dt><code>sign</code> &#8211; Sign a certificate signing request for HOST.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet certificate sign [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>&#8211;ca-location LOCATION</i> [&#8211;[no-]allow-dns-alt-names] <i>host</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Sign a certificate signing request for HOST.</p>
<dd><code>OPTIONS</code> <i>&#8211;[no-]allow-dns-alt-names</i> &#8211; Whether or not to accept DNS alt names in the certificate request</p>
<dd><code>RETURNS</code></p>
<dd>A string that appears to be (but isn&#8217;t) an x509 certificate.</dl>
<h2>Examples</h2>
<p><code>generate</code> </p>
<p> Request a certificate for &quot;somenode&quot; from the site&#8217;s CA: </p>
<p> $ puppet certificate generate somenode.puppetlabs.lan &#8211;ca-location remote </p>
<p> <code>sign</code> </p>
<p> Sign somenode.puppetlabs.lan&#8217;s certificate: </p>
<p> $ puppet certificate sign somenode.puppetlabs.lan &#8211;ca-location remote</p>
<h2>Notes</h2>
<p>This subcommand is an indirector face, which exposes <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code> actions for an indirected subsystem of Puppet. Valid termini for this face include:</p>
<dl>
<dt>&bull;</p>
<dd><code>ca</code></p>
<dt>&bull;</p>
<dd><code>disabled_ca</code></p>
<dt>&bull;</p>
<dd><code>file</code></p>
<dt>&bull;</p>
<dd><code>rest</code></p>
<dd></dl>
