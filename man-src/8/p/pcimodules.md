<p>pcimodules &#8211; List kernel driver modules available for all currently plugged in PCI devices</p>
<h2>Synopsis</h2>
<p><code>pcimodules</code> [<code>&#8211;class</code>class_id<code>]</code> [<code>&#8211;classmask</code>mask<code>]</code> [<code>&#8211;help</code>]</p>
<h2>Description</h2>
<p><code>pcimodules</code> lists all driver modules for all currently plugged in PCI devices. <code>pcimodules</code> should be run at boot time, and whenever a PCI device is &quot;hot plugged&quot; into the system. This can be done by the following Bourne shell syntax:</p>
<dl>
<dd><tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;</tt>for module in $(pcimodules) ; do</p>
<dd><tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;</tt><tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;</tt>modprobe -s &quot;$module&quot;</p>
<dd><tt>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;</tt>done
</dl>
<p> When a PCI device is removed from the system, the Linux kernel will decrement a usage count on PCI driver module. If this count drops to zero (i.e., there are no PCI drivers), then the <code>modprobe -r</code> process that is normally configured to run from cron every few minutes will eventually remove the unneeded module. </p>
<p> The &#8211;class and &#8211;classmask arguments can be used to limit the search to certain classes of PCI devices. This is useful, for example, to generate a list of ethernet card drivers to be loaded when the kernel has indicated that it is trying to resolve an unknown network interface. </p>
<p> Modules are listed in the order in which the PCI devices are physically arranged so that the computer owner can arrange things like having scsi device 0 be on a controller that is not alphabetically the first scsi controller.</p>
<h2>Options</h2>
<dl>
<dt><code>&#8211;class class &#8211;classmask mask</code></p>
<dd></dl>
<p> &#8211;class and &#8211;classmask limit the search to PCI cards in particular classes. These arguments are always used together. The arguments to &#8211;class and &#8211;classmask can be given as hexadecimal numbers by prefixing a leading &quot;0x&quot;. Note that the classes used by pcimodules are in &quot;Linux&quot; format, meaning the class value that you see with lspci would be shifted left eight bits, with the new low eight bits programming interface ID. An examples of how to use class and classmask is provided below. <code>&#8211;help, -h</code> Print a help message and exit.</p>
<h2>Examples</h2>
<dl>
<dt>pcimodules</p>
<dd>lists all modules corresponding to currently plugged in PCI devices.</p>
<dt>pcimodules &#8211;class 0x20000 &#8211;classmask 0xffff00</p>
<dd>lists all modules corresponding to currently plugged in ethernet PCI devices.</dl>
<h2>Files</h2>
<dl>
<dt><code>/lib/modules/&lt;kernel-version&gt;/modules.pcimap</code></p>
<dd>This file is automatically generated by <code>depmod,</code> and used by <code>pcimodules</code> to determine which modules correspond to which PCI ID&#8217;s.</p>
<dt><code>/proc/bus/pci</code></p>
<dd>An interface to PCI bus configuration space provided by the post-2.1.82 Linux kernels. Contains per-bus subdirectories with per-card config space files and a <i>devices</i> file containing a list of all PCI devices. </p>
</dl>
