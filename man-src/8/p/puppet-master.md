<p><code>puppet-master</code> &#8211; The puppet master daemon</p>
<h2>Synopsis</h2>
<p>The central puppet server. Functions as a certificate authority by default.</p>
<h2>Usage</h2>
<p>puppet master [-D|&#8211;daemonize|&#8211;no-daemonize] [-d|&#8211;debug] [-h|&#8211;help] [-l|&#8211;logdest <i>file</i>|console|syslog] [-v|&#8211;verbose] [-V|&#8211;version] [&#8211;compile <i>node-name</i>]</p>
<h2>Description</h2>
<p>This command starts an instance of puppet master, running as a daemon and using Ruby&#8217;s built-in Webrick webserver. Puppet master can also be managed by other application servers; when this is the case, this executable is not used.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument. For example, &#8216;ssldir&#8217; is a valid configuration parameter, so you can specify &#8216;&#8211;ssldir <i>directory</i>&#8216; as an argument. </p>
<p> See the configuration file documentation at <a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet master with &#8216;&#8211;genconfig&#8217;.</p>
<dl>
<dt>&#8211;daemonize</p>
<dd>Send the process into the background. This is the default.</p>
<dt>&#8211;no-daemonize</p>
<dd>Do not send the process into the background.</p>
<dt>&#8211;debug</p>
<dd>Enable full debugging.</p>
<dt>&#8211;help</p>
<dd>Print this help message.</p>
<dt>&#8211;logdest</p>
<dd>Where to send messages. Choose between syslog, the console, and a log file. Defaults to sending messages to syslog, or the console if debugging or verbosity is enabled.</p>
<dt>&#8211;verbose</p>
<dd>Enable verbosity.</p>
<dt>&#8211;version</p>
<dd>Print the puppet version number and exit.</p>
<dt>&#8211;compile</p>
<dd>Compile a catalogue and output it in JSON from the puppet master. Uses facts contained in the $vardir/yaml/ directory to compile the catalog.</dl>
<h2>Example</h2>
<p>puppet master</p>
<h2>Diagnostics</h2>
<p>When running as a standalone daemon, puppet master accepts the following signals:</p>
<dl>
<dt>SIGHUP</p>
<dd>Restart the puppet master server.</p>
<dt>SIGINT and SIGTERM</p>
<dd>Shut down the puppet master server.</p>
<dt>SIGUSR2</p>
<dd>Close file descriptors for log files and reopen them. Used with logrotate.</dl>
