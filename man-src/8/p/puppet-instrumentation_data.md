<p><code>puppet-instrumentation_data</code> &#8211; Manage instrumentation listener accumulated data.</p>
<h2>Synopsis</h2>
<p>puppet instrumentation_data <i>action</i> [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<h2>Description</h2>
<p>This subcommand allows to retrieve the various listener data.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument, although it may or may not be relevant to the present action. For example, <code>server</code> and <code>run_mode</code> are valid configuration parameters, so you can specify <code>&#8211;server &lt;servername&gt;</code>, or <code>&#8211;run_mode &lt;runmode&gt;</code> as an argument. </p>
<p> See the configuration file documentation at <i><a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a></i> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet with <code>&#8211;genconfig</code>.</p>
<dl>
<dt>&#8211;render-as FORMAT</p>
<dd>The format in which to render output. The most common formats are <code>json</code>, <code>s</code> (string), <code>yaml</code>, and <code>console</code>, but other options such as <code>dot</code> are sometimes available.</p>
<dt>&#8211;verbose</p>
<dd>Whether to log verbosely.</p>
<dt>&#8211;debug</p>
<dd>Whether to log debug information.</p>
<dt>&#8211;extra HASH</p>
<dd>A terminus can take additional arguments to refine the operation, which are passed as an arbitrary hash to the back-end. Anything passed as the extra value is just send direct to the back-end.</p>
<dt>&#8211;terminus TERMINUS</p>
<dd>Indirector faces expose indirected subsystems of Puppet. These subsystems are each able to retrieve and alter a specific type of data (with the familiar actions of <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code>) from an arbitrary number of pluggable backends. In Puppet parlance, these backends are called terminuses.</p>
<dd>Almost all indirected subsystems have a <code>rest</code> terminus that interacts with the puppet master&#8217;s data. Most of them have additional terminuses for various local data models, which are in turn used by the indirected subsystem on the puppet master whenever it receives a remote request.</p>
<dd>The terminus for an action is often determined by context, but occasionally needs to be set explicitly. See the &quot;Notes&quot; section of this face&#8217;s manpage for more details.</dl>
<h2>Actions</h2>
<dl>
<dt><code>destroy</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet instrumentation_data destroy [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</p>
<dt><code>find</code> &#8211; Retrieve listener data.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet instrumentation_data find [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Retrieve listener data.</p>
<dd><code>RETURNS</code></p>
<dd>The data of an instrumentation listener</p>
<dt><code>info</code> &#8211; Print the default terminus class for this face.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet instrumentation_data info [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Prints the default terminus class for this subcommand. Note that different run modes may have different default termini; when in doubt, specify the run mode with the &#8216;&#8211;run_mode&#8217; option.</p>
<dt><code>save</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet instrumentation_data save [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>API only: create or overwrite an object. As the Faces framework does not currently accept data from STDIN, save actions cannot currently be invoked from the command line.</p>
<dt><code>search</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet instrumentation_data search [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>query</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</dl>
<h2>Examples</h2>
<p><code>find</code> </p>
<p> Retrieve listener data: </p>
<p> $ puppet instrumentation_data find performance &#8211;terminus rest</p>
<h2>Notes</h2>
<p>This subcommand is an indirector face, which exposes <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code> actions for an indirected subsystem of Puppet. Valid termini for this face include:</p>
<dl>
<dt>&bull;</p>
<dd><code>local</code></p>
<dt>&bull;</p>
<dd><code>rest</code></p>
<dd></dl>
