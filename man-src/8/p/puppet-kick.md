<p><code>puppet-kick</code> &#8211; Remotely control puppet agent</p>
<h2>Synopsis</h2>
<p>Trigger a puppet agent run on a set of hosts.</p>
<h2>Usage</h2>
<p>puppet kick [-a|&#8211;all] [-c|&#8211;class <i>class</i>] [-d|&#8211;debug] [-f|&#8211;foreground] [-h|&#8211;help] [&#8211;host <i>host</i>] [&#8211;no-fqdn] [&#8211;ignoreschedules] [-t|&#8211;tag <i>tag</i>] [&#8211;test] [-p|&#8211;ping] <i>host</i> [<i>host</i> [&#8230;]]</p>
<h2>Description</h2>
<p>This script can be used to connect to a set of machines running &#8216;puppet agent&#8217; and trigger them to run their configurations. The most common usage would be to specify a class of hosts and a set of tags, and &#8216;puppet kick&#8217; would look up in LDAP all of the hosts matching that class, then connect to each host and trigger a run of all of the objects with the specified tags. </p>
<p> If you are not storing your host configurations in LDAP, you can specify hosts manually. </p>
<p> You will most likely have to run &#8216;puppet kick&#8217; as root to get access to the SSL certificates. </p>
<p> &#8216;puppet kick&#8217; reads &#8216;puppet master&#8221;s configuration file, so that it can copy things like LDAP settings.</p>
<h2>Usage Notes</h2>
<p>Puppet kick needs the puppet agent on the target machine to be running as a daemon, be configured to listen for incoming network connections, and have an appropriate security configuration. </p>
<p> The specific changes required are:</p>
<dl>
<dt>&bull;</p>
<dd>Set <code>listen = true</code> in the agent&#8217;s <code>puppet.conf</code> file (or <code>&#8211;listen</code> on the command line)</p>
<dt>&bull;</p>
<dd>Configure the node&#8217;s firewall to allow incoming connections on port 8139</p>
<dt>&bull;</p>
<dd>Insert the following stanza at the top of the node&#8217;s <code>auth.conf</code> file:</p>
<dd>
<pre> # Allow puppet kick access
 path /run
 method save
 auth any
 allow workstation.example.com</pre>
<dd>
<dd></dl>
<p> This example would allow the machine <code>workstation.example.com</code> to trigger a Puppet run; adjust the &quot;allow&quot; directive to suit your site. You may also use <code>allow *</code> to allow anyone to trigger a Puppet run, but that makes it possible to interfere with your site by triggering excessive Puppet runs. </p>
<p> See <code><a rel="nofollow" href="http://docs.puppetlabs.com/guides/rest_auth_conf.html">http://docs.puppetlabs.com/guides/rest_auth_conf.html</a></code> for more details about security settings.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument. For example, &#8216;ssldir&#8217; is a valid configuration parameter, so you can specify &#8216;&#8211;ssldir <i>directory</i>&#8216; as an argument. </p>
<p> See the configuration file documentation at <a rel="nofollow" href="http://docs.puppetlabs.com/references/latest/configuration.html">http://docs.puppetlabs.com/references/latest/configuration.html</a> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet master with &#8216;&#8211;genconfig&#8217;.</p>
<dl>
<dt>&#8211;all</p>
<dd>Connect to all available hosts. Requires LDAP support at this point.</p>
<dt>&#8211;class</p>
<dd>Specify a class of machines to which to connect. This only works if you have LDAP configured, at the moment.</p>
<dt>&#8211;debug</p>
<dd>Enable full debugging.</p>
<dt>&#8211;foreground</p>
<dd>Run each configuration in the foreground; that is, when connecting to a host, do not return until the host has finished its run. The default is false.</p>
<dt>&#8211;help</p>
<dd>Print this help message</p>
<dt>&#8211;host</p>
<dd>A specific host to which to connect. This flag can be specified more than once.</p>
<dt>&#8211;ignoreschedules</p>
<dd>Whether the client should ignore schedules when running its configuration. This can be used to force the client to perform work it would not normally perform so soon. The default is false.</p>
<dt>&#8211;parallel</p>
<dd>How parallel to make the connections. Parallelization is provided by forking for each client to which to connect. The default is 1, meaning serial execution.</p>
<dt>&#8211;puppetport</p>
<dd>Use the specified TCP port to connect to agents. Defaults to 8139.</p>
<dt>&#8211;tag</p>
<dd>Specify a tag for selecting the objects to apply. Does not work with the &#8211;test option.</p>
<dt>&#8211;test</p>
<dd>Print the hosts you would connect to but do not actually connect. This option requires LDAP support at this point.</p>
<dt>&#8211;ping</p>
<dd>Do an ICMP echo against the target host. Skip hosts that don&#8217;t respond to ping.</dl>
<h2>Example</h2>
<pre>$ sudo puppet kick -p 10 -t remotefile -t webserver host1 host2</pre>
