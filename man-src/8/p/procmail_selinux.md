<p>procmail_selinux &#8211; Security Enhanced Linux Policy for the procmail processes</p>
<h2>Description</h2>
<p>Security-Enhanced Linux secures the procmail processes via flexible mandatory access control. The procmail processes execute with the procmail_t SELinux type. You can check if you have these processes running by executing the <code>ps</code> command with the <code>-Z</code> qualifier. For example: <code>ps -eZ | grep procmail_t</code> </p>
<h2>Entrypoints</h2>
<p>The procmail_t SELinux type can be entered via the <code>procmail_exec_t</code> file type. </p>
<p> The default entrypoint paths for the procmail_t domain are the following: </p>
<p> /usr/bin/procmail</p>

<h2>Booleans</h2>
<p>SELinux policy is customizable based on least access required. procmail policy is extremely flexible and has several booleans that allow you to manipulate the policy and run procmail with the tightest access possible. </p>
<p> If you want to allow users to resolve user passwd entries directly from ldap rather then using a sssd server, you must turn on the authlogin_nsswitch_use_ldap boolean. Disabled by default. </p>
<p> <code>setsebool -P authlogin_nsswitch_use_ldap 1</code> </p>
<p> If you want to deny any process from ptracing or debugging any other processes, you must turn on the deny_ptrace boolean. Enabled by default. </p>
<p> <code>setsebool -P deny_ptrace 1</code> </p>
<p> If you want to allow all domains to use other domains file descriptors, you must turn on the domain_fd_use boolean. Enabled by default. </p>
<p> <code>setsebool -P domain_fd_use 1</code> </p>
<p> If you want to allow all domains to have the kernel load modules, you must turn on the domain_kernel_load_modules boolean. Disabled by default. </p>
<p> <code>setsebool -P domain_kernel_load_modules 1</code> </p>
<p> If you want to allow all domains to execute in fips_mode, you must turn on the fips_mode boolean. Enabled by default. </p>
<p> <code>setsebool -P fips_mode 1</code> </p>
<p> If you want to enable reading of urandom for all domains, you must turn on the global_ssp boolean. Disabled by default. </p>
<p> <code>setsebool -P global_ssp 1</code> </p>
<p> If you want to allow confined applications to run with kerberos, you must turn on the kerberos_enabled boolean. Enabled by default. </p>
<p> <code>setsebool -P kerberos_enabled 1</code> </p>
<p> If you want to allow system to run with NIS, you must turn on the nis_enabled boolean. Disabled by default. </p>
<p> <code>setsebool -P nis_enabled 1</code> </p>
<p> If you want to allow confined applications to use nscd shared memory, you must turn on the nscd_use_shm boolean. Disabled by default. </p>
<p> <code>setsebool -P nscd_use_shm 1</code> </p>
<p> If you want to support ecryptfs home directories, you must turn on the use_ecryptfs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_ecryptfs_home_dirs 1</code> </p>
<p> If you want to support fusefs home directories, you must turn on the use_fusefs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_fusefs_home_dirs 1</code> </p>
<p> If you want to support NFS home directories, you must turn on the use_nfs_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_nfs_home_dirs 1</code> </p>
<p> If you want to support SAMBA home directories, you must turn on the use_samba_home_dirs boolean. Disabled by default. </p>
<p> <code>setsebool -P use_samba_home_dirs 1</code></p>

<h2>File Contexts</h2>
<p>SELinux requires files to have an extended attribute to define the file type. </p>
<p> You can see the context of a file using the <code>-Z</code> option to <code>lsP Policy governs the access confined processes have to these files. SELinux procmail policy is very flexible allowing users to setup their procmail processes in as secure a method as possible. </p>
<p> EQUIVALENCE DIRECTORIES</code> </p>
<p> procmail policy stores data with multiple different file context types under the /var/log/procmail directory. If you would like to store the data in a different directory you can use the semanage command to create an equivalence mapping. If you wanted to store this data under the /srv dirctory you would execute the following command: </p>
<p> <code>semanage fcontext -a -e /var/log/procmail /srv/procmail</code><br />
 <code>restorecon -R -v /srv/procmail</code> </p>
<p> <code>STANDARD FILE CONTEXT</code> </p>
<p> SELinux defines the file context types for the procmail, if you wanted to store files with these types in a diffent paths, you need to execute the semanage command to sepecify alternate labeling and then use restorecon to put the labels on disk. </p>
<p> <code>semanage fcontext -a -t procmail_tmp_t &#8216;/srv/myprocmail_content(/.*)?&#8217;</code><br />
 <code>restorecon -R -v /srv/myprocmail_content</code> </p>
<p> Note: SELinux often uses regular expressions to specify labels that match multiple files. </p>
<p> <i>The following file types are defined for procmail:</i> </p>
<p> <code>procmail_exec_t</code> </p>
<p> &#8211; Set files with the procmail_exec_t type, if you want to transition an executable to the procmail_t domain. </p>
<p> <code>procmail_home_t</code> </p>
<p> &#8211; Set files with the procmail_home_t type, if you want to store procmail files in the users home directory. </p>
<dl>
<dt>Paths:</p>
<dd>/root/.procmailrc, /home/[^/]+/.procmailrc </p>
</dl>
<p> <code>procmail_log_t</code> </p>
<p> &#8211; Set files with the procmail_log_t type, if you want to treat the data as procmail log data, usually stored under the /var/log directory. </p>
<dl>
<dt>Paths:</p>
<dd>/var/log/procmail(/.*)?, /var/log/procmail.log.* </p>
</dl>
<p> <code>procmail_tmp_t</code> </p>
<p> &#8211; Set files with the procmail_tmp_t type, if you want to store procmail temporary files in the /tmp directories. </p>
<p> Note: File context can be temporarily modified with the chcon command. If you want to permanently change the file context you need to use the <code>semanage fcontext</code> command. This will modify the SELinux labeling database. You will need to use <code>restorecon</code> to apply the labels.</p>
