<p><code>puppet-node</code> &#8211; View and manage node definitions.</p>
<h2>Synopsis</h2>
<p>puppet node <i>action</i> [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<h2>Description</h2>
<p>This subcommand interacts with node objects, which are used by Puppet to build a catalog. A node object consists of the node&#8217;s facts, environment, node parameters (exposed in the parser as top-scope variables), and classes.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument, although it may or may not be relevant to the present action. For example, <code>server</code> and <code>run_mode</code> are valid configuration parameters, so you can specify <code>&#8211;server &lt;servername&gt;</code>, or <code>&#8211;run_mode &lt;runmode&gt;</code> as an argument. </p>
<p> See the configuration file documentation at <i><a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a></i> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet with <code>&#8211;genconfig</code>.</p>
<dl>
<dt>&#8211;render-as FORMAT</p>
<dd>The format in which to render output. The most common formats are <code>json</code>, <code>s</code> (string), <code>yaml</code>, and <code>console</code>, but other options such as <code>dot</code> are sometimes available.</p>
<dt>&#8211;verbose</p>
<dd>Whether to log verbosely.</p>
<dt>&#8211;debug</p>
<dd>Whether to log debug information.</p>
<dt>&#8211;extra HASH</p>
<dd>A terminus can take additional arguments to refine the operation, which are passed as an arbitrary hash to the back-end. Anything passed as the extra value is just send direct to the back-end.</p>
<dt>&#8211;terminus TERMINUS</p>
<dd>Indirector faces expose indirected subsystems of Puppet. These subsystems are each able to retrieve and alter a specific type of data (with the familiar actions of <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code>) from an arbitrary number of pluggable backends. In Puppet parlance, these backends are called terminuses.</p>
<dd>Almost all indirected subsystems have a <code>rest</code> terminus that interacts with the puppet master&#8217;s data. Most of them have additional terminuses for various local data models, which are in turn used by the indirected subsystem on the puppet master whenever it receives a remote request.</p>
<dd>The terminus for an action is often determined by context, but occasionally needs to be set explicitly. See the &quot;Notes&quot; section of this face&#8217;s manpage for more details.</dl>
<h2>Actions</h2>
<dl>
<dt><code>clean</code> &#8211; Clean up everything a puppetmaster knows about a node.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet node clean [&#8211;terminus TERMINUS] [&#8211;extra HASH] [&#8211;[no-]unexport] <i>host1</i> [<i>host2</i> &#8230;]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Clean up everything a puppet master knows about a node, including certificates and storeconfigs data.</p>
<dd>The full list of info cleaned by this action is:</p>
<dd><i>Signed certificates</i> &#8211; ($vardir/ssl/ca/signed/node.domain.pem)</p>
<dd><i>Cached facts</i> &#8211; ($vardir/yaml/facts/node.domain.yaml)</p>
<dd><i>Cached node objects</i> &#8211; ($vardir/yaml/node/node.domain.yaml)</p>
<dd><i>Reports</i> &#8211; ($vardir/reports/node.domain)</p>
<dd><i>Stored configs</i> &#8211; (in database) The clean action can either remove all data from a host in your storeconfigs database, or, with the <i>&#8211;unexport</i> option, turn every exported resource supporting ensure to absent so that any other host that collected those resources can remove them. Without unexporting, a removed node&#8217;s exported resources become unmanaged by Puppet, and may linger as cruft unless you are purging that resource type.</p>
<dd><code>OPTIONS</code> <i>&#8211;[no-]unexport</i> &#8211; Whether to remove this node&#8217;s exported resources from other nodes</p>
<dt><code>destroy</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet node destroy [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</p>
<dt><code>find</code> &#8211; Retrieve a node object.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet node find [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>host</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Retrieve a node object.</p>
<dd><code>RETURNS</code></p>
<dd>A hash containing the node&#8217;s <code>classes</code>, <code>environment</code>, <code>expiration</code>, <code>name</code>, <code>parameters</code> (its facts, combined with any ENC-set parameters), and <code>time</code>. When used from the Ruby API: a Puppet::Node object.</p>
<dd>RENDERING ISSUES: Rendering as string and json are currently broken; node objects can only be rendered as yaml.</p>
<dt><code>info</code> &#8211; Print the default terminus class for this face.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet node info [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Prints the default terminus class for this subcommand. Note that different run modes may have different default termini; when in doubt, specify the run mode with the &#8216;&#8211;run_mode&#8217; option.</p>
<dt><code>save</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet node save [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</p>
<dt><code>search</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet node search [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>query</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</dl>
<h2>Examples</h2>
<p><code>find</code> </p>
<p> Retrieve an &quot;empty&quot; (no classes, no ENC-imposed parameters, and an environment of &quot;production&quot;) node: </p>
<p> $ puppet node find somenode.puppetlabs.lan &#8211;terminus plain &#8211;render-as yaml </p>
<p> Retrieve a node using the puppet master&#8217;s configured ENC: </p>
<p> $ puppet node find somenode.puppetlabs.lan &#8211;terminus exec &#8211;run_mode master &#8211;render-as yaml </p>
<p> Retrieve the same node from the puppet master: </p>
<p> $ puppet node find somenode.puppetlabs.lan &#8211;terminus rest &#8211;render-as yaml</p>
<h2>Notes</h2>
<p>This subcommand is an indirector face, which exposes <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code> actions for an indirected subsystem of Puppet. Valid termini for this face include:</p>

<dd><code>active_record</code></p>

<dd><code>exec</code></p>
<dt>&bull;</p>
<dd><code>ldap</code></p>
<dt>&bull;</p>
<dd><code>memory</code></p>

<dd><code>rest</code></p>
<dt>&bull;</p>
<dd><code>store_configs</code></p>
<dt>&bull;</p>
<dd><code>write_only_yaml</code></p>
