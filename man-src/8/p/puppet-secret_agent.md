<p><code>puppet-secret_agent</code> &#8211; Mimics puppet agent.</p>
<h2>Synopsis</h2>
<p>puppet secret_agent <i>action</i></p>
<h2>Description</h2>
<p>This subcommand currently functions as a proof of concept, demonstrating how the Faces API exposes Puppet&#8217;s internal systems to application logic; compare the actual code for puppet agent. It will eventually replace puppet agent entirely, and can provide a template for users who wish to implement agent-like functionality with non-standard application logic.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument, although it may or may not be relevant to the present action. For example, <code>server</code> and <code>run_mode</code> are valid configuration parameters, so you can specify <code>&#8211;server &lt;servername&gt;</code>, or <code>&#8211;run_mode &lt;runmode&gt;</code> as an argument. </p>
<p> See the configuration file documentation at <i><a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a></i> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet with <code>&#8211;genconfig</code>.</p>
<dl>
<dt>&#8211;render-as FORMAT</p>
<dd>The format in which to render output. The most common formats are <code>json</code>, <code>s</code> (string), <code>yaml</code>, and <code>console</code>, but other options such as <code>dot</code> are sometimes available.</p>
<dt>&#8211;verbose</p>
<dd>Whether to log verbosely.</p>
<dt>&#8211;debug</p>
<dd>Whether to log debug information.</dl>
<h2>Actions</h2>
<dl>
<dt><code>synchronize</code> &#8211; Run secret_agent once.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet secret_agent</p>
<dd><code>DESCRIPTION</code></p>
<dd>Mimics a single run of puppet agent. This action does not currently daemonize, but can download plugins, submit facts, retrieve and apply a catalog, and submit a report to the puppet master.</p>
<dd><code>RETURNS</code></p>
<dd>Verbose logging from the completed run. When used from the Ruby API: returns a Puppet::Transaction::Report object.</p>
<dd><code>NOTES</code></p>
<dd>This action requires that the puppet master&#8217;s <code>auth.conf</code> file allow save access to the <code>facts</code> REST terminus. Puppet agent does not use this facility, and it is turned off by default. See <i><a rel="nofollow" href="http://docs.puppetlabs.com/guides/rest_auth_conf.html">http://docs.puppetlabs.com/guides/rest_auth_conf.html</a></i> for more details.</dl>
<h2>Examples</h2>
<p><code>synchronize</code> </p>
<p> Trigger a Puppet run with the configured puppet master: </p>
<p> $ puppet secret_agent</p>
