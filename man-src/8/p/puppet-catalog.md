<p><code>puppet-catalog</code> &#8211; Compile, save, view, and convert catalogs.</p>
<h2>Synopsis</h2>
<p>puppet catalog <i>action</i> [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<h2>Description</h2>
<p>This subcommand deals with catalogs, which are compiled per-node artifacts generated from a set of Puppet manifests. By default, it interacts with the compiling subsystem and compiles a catalog using the default manifest and <code>certname</code>, but you can change the source of the catalog with the <code>&#8211;terminus</code> option. You can also choose to print any catalog in &#8216;dot&#8217; format (for easy graph viewing with OmniGraffle or Graphviz) with &#8216;&#8211;render-as dot&#8217;.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument, although it may or may not be relevant to the present action. For example, <code>server</code> and <code>run_mode</code> are valid configuration parameters, so you can specify <code>&#8211;server &lt;servername&gt;</code>, or <code>&#8211;run_mode &lt;runmode&gt;</code> as an argument. </p>
<p> See the configuration file documentation at <i><a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a></i> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet with <code>&#8211;genconfig</code>.</p>
<dl>
<dt>&#8211;render-as FORMAT</p>
<dd>The format in which to render output. The most common formats are <code>json</code>, <code>s</code> (string), <code>yaml</code>, and <code>console</code>, but other options such as <code>dot</code> are sometimes available.</p>
<dt>&#8211;verbose</p>
<dd>Whether to log verbosely.</p>
<dt>&#8211;debug</p>
<dd>Whether to log debug information.</p>
<dt>&#8211;extra HASH</p>
<dd>A terminus can take additional arguments to refine the operation, which are passed as an arbitrary hash to the back-end. Anything passed as the extra value is just send direct to the back-end.</p>
<dt>&#8211;terminus TERMINUS</p>
<dd>Indirector faces expose indirected subsystems of Puppet. These subsystems are each able to retrieve and alter a specific type of data (with the familiar actions of <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code>) from an arbitrary number of pluggable backends. In Puppet parlance, these backends are called terminuses.</p>
<dd>Almost all indirected subsystems have a <code>rest</code> terminus that interacts with the puppet master&#8217;s data. Most of them have additional terminuses for various local data models, which are in turn used by the indirected subsystem on the puppet master whenever it receives a remote request.</p>
<dd>The terminus for an action is often determined by context, but occasionally needs to be set explicitly. See the &quot;Notes&quot; section of this face&#8217;s manpage for more details.</dl>
<h2>Actions</h2>
<dl>
<dt><code>apply</code> &#8211; Find and apply a catalog.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog apply [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Finds and applies a catalog. This action takes no arguments, but the source of the catalog can be managed with the <code>&#8211;terminus</code> option.</p>
<dd><code>RETURNS</code></p>
<dd>Nothing. When used from the Ruby API, returns a Puppet::Transaction::Report object.</p>
<dt><code>destroy</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog destroy [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</p>
<dt><code>download</code> &#8211; Download this node&#8217;s catalog from the puppet master server.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog download [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Retrieves a catalog from the puppet master and saves it to the local yaml cache. This action always contacts the puppet master and will ignore alternate termini.</p>
<dd>The saved catalog can be used in any subsequent catalog action by specifying &#8216;&#8211;terminus yaml&#8217; for that action.</p>
<dd><code>RETURNS</code></p>
<dd>Nothing.</p>
<dd><code>NOTES</code></p>
<dd>When used from the Ruby API, this action has a side effect of leaving Puppet::Resource::Catalog.indirection.terminus_class set to yaml. The terminus must be explicitly re-set for subsequent catalog actions.</p>
<dt><code>find</code> &#8211; Retrieve the catalog for a node.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog find [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>certname</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Retrieve the catalog for a node.</p>
<dd><code>RETURNS</code></p>
<dd>A serialized catalog. When used from the Ruby API, returns a Puppet::Resource::Catalog object.</p>
<dt><code>info</code> &#8211; Print the default terminus class for this face.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog info [&#8211;terminus TERMINUS] [&#8211;extra HASH]</p>
<dd><code>DESCRIPTION</code></p>
<dd>Prints the default terminus class for this subcommand. Note that different run modes may have different default termini; when in doubt, specify the run mode with the &#8216;&#8211;run_mode&#8217; option.</p>
<dt><code>save</code> &#8211; API only: create or overwrite an object.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog save [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>key</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>API only: create or overwrite an object. As the Faces framework does not currently accept data from STDIN, save actions cannot currently be invoked from the command line.</p>
<dt><code>search</code> &#8211; Invalid for this subcommand.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog search [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>query</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Invalid for this subcommand.</p>
<dt><code>select</code> &#8211; Retrieve a catalog and filter it for resources of a given type.</p>
<dd><code>SYNOPSIS</code></p>
<dd>puppet catalog select [&#8211;terminus TERMINUS] [&#8211;extra HASH] <i>host</i> <i>resource_type</i></p>
<dd><code>DESCRIPTION</code></p>
<dd>Retrieves a catalog for the specified host, then searches it for all resources of the requested type.</p>
<dd><code>RETURNS</code></p>
<dd>A list of resource references (&quot;Type[title]&quot;). When used from the API, returns an array of Puppet::Resource objects excised from a catalog.</p>
<dd><code>NOTES</code></p>
<dd>By default, this action will retrieve a catalog from Puppet&#8217;s compiler subsystem; you must call the action with <code>&#8211;terminus rest</code> if you wish to retrieve a catalog from the puppet master.</p>
<dd>FORMATTING ISSUES: This action cannot currently render useful yaml; instead, it returns an entire catalog. Use json instead.</dl>
<h2>Examples</h2>
<p><code>apply</code> </p>
<p> Apply the locally cached catalog: </p>
<p> $ puppet catalog apply &#8211;terminus yaml </p>
<p> Retrieve a catalog from the master and apply it, in one step: </p>
<p> $ puppet catalog apply &#8211;terminus rest </p>
<p> From <code>secret_agent.rb</code> (API example):</p>
<dl>
<dd>
<pre># ...
Puppet::Face[:catalog, '0.0.1'].download
# (Termini are singletons; catalog.download has a side effect of
# setting the catalog terminus to yaml)
report = Puppet::Face[:catalog, '0.0.1'].apply
# ...</pre>
<dd></dl>
<p> <code>download</code> </p>
<p> Retrieve and store a catalog: </p>
<p> $ puppet catalog download </p>
<p> From <code>secret_agent.rb</code> (API example):</p>
<dl>
<dd>
<pre>Puppet::Face[:plugin, '0.0.1'].download
Puppet::Face[:facts, '0.0.1'].upload
Puppet::Face[:catalog, '0.0.1'].download
# ...</pre>
<dd></dl>
<p> <code>select</code> </p>
<p> Ask the puppet master for a list of managed file resources for a node: </p>
<p> $ puppet catalog select &#8211;terminus rest somenode.magpie.lan file</p>
<h2>Notes</h2>
<p>This subcommand is an indirector face, which exposes <code>find</code>, <code>search</code>, <code>save</code>, and <code>destroy</code> actions for an indirected subsystem of Puppet. Valid termini for this face include:</p>
<dl>
<dt>&bull;</p>
<dd><code>active_record</code></p>
<dt>&bull;</p>
<dd><code>compiler</code></p>
<dt>&bull;</p>
<dd><code>json</code></p>
<dt>&bull;</p>
<dd><code>queue</code></p>
<dt>&bull;</p>
<dd><code>rest</code></p>
<dt>&bull;</p>
<dd><code>static_compiler</code></p>
<dt>&bull;</p>
<dd><code>store_configs</code></p>
<dt>&bull;</p>
<dd><code>yaml</code></p>
<dd></dl>
