<p><code>puppet-cert</code> &#8211; Manage certificates and requests</p>
<h2>Synopsis</h2>
<p>Standalone certificate authority. Capable of generating certificates, but mostly used for signing certificate requests from puppet clients.</p>
<h2>Usage</h2>
<p>puppet cert <i>action</i> [-h|&#8211;help] [-V|&#8211;version] [-d|&#8211;debug] [-v|&#8211;verbose] [&#8211;digest <i>digest</i>] [<i>host</i>]</p>
<h2>Description</h2>
<p>Because the puppet master service defaults to not signing client certificate requests, this script is available for signing outstanding requests. It can be used to list outstanding requests and then either sign them individually or sign all of them.</p>
<h2>Actions</h2>
<p>Every action except &#8216;list&#8217; and &#8216;generate&#8217; requires a hostname to act on, unless the &#8216;&#8211;all&#8217; option is set.</p>
<dl>
<dt>clean</p>
<dd>Revoke a host&#8217;s certificate (if applicable) and remove all files related to that host from puppet cert&#8217;s storage. This is useful when rebuilding hosts, since new certificate signing requests will only be honored if puppet cert does not have a copy of a signed certificate for that host. If &#8216;&#8211;all&#8217; is specified then all host certificates, both signed and unsigned, will be removed.</p>
<dt>fingerprint</p>
<dd>Print the DIGEST (defaults to the signing algorithm) fingerprint of a host&#8217;s certificate.</p>
<dt>generate</p>
<dd>Generate a certificate for a named client. A certificate/keypair will be generated for each client named on the command line.</p>
<dt>list</p>
<dd>List outstanding certificate requests. If &#8216;&#8211;all&#8217; is specified, signed certificates are also listed, prefixed by &#8216;+&#8217;, and revoked or invalid certificates are prefixed by &#8216;-&#8216; (the verification outcome is printed in parenthesis).</p>
<dt>print</p>
<dd>Print the full-text version of a host&#8217;s certificate.</p>
<dt>revoke</p>
<dd>Revoke the certificate of a client. The certificate can be specified either by its serial number (given as a hexadecimal number prefixed by &#8216;0x&#8217;) or by its hostname. The certificate is revoked by adding it to the Certificate Revocation List given by the &#8216;cacrl&#8217; configuration option. Note that the puppet master needs to be restarted after revoking certificates.</p>
<dt>sign</p>
<dd>Sign an outstanding certificate request.</p>
<dt>verify</p>
<dd>Verify the named certificate against the local CA certificate.</dl>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument. For example, &#8216;ssldir&#8217; is a valid configuration parameter, so you can specify &#8216;&#8211;ssldir <i>directory</i>&#8216; as an argument. </p>
<p> See the configuration file documentation at <a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet cert with &#8216;&#8211;genconfig&#8217;.</p>
<dl>
<dt>&#8211;all</p>
<dd>Operate on all items. Currently only makes sense with the &#8216;sign&#8217;, &#8216;clean&#8217;, &#8216;list&#8217;, and &#8216;fingerprint&#8217; actions.</p>
<dt>&#8211;digest</p>
<dd>Set the digest for fingerprinting (defaults to the the digest used when signing the cert). Valid values depends on your openssl and openssl ruby extension version.</p>
<dt>&#8211;debug</p>
<dd>Enable full debugging.</p>
<dt>&#8211;help</p>
<dd>Print this help message</p>
<dt>&#8211;verbose</p>
<dd>Enable verbosity.</p>
<dt>&#8211;version</p>
<dd>Print the puppet version number and exit.</dl>
<h2>Example</h2>
<pre>$ puppet cert list
culain.madstop.com
$ puppet cert sign culain.madstop.com</pre>
