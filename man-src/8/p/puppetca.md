<h2>Synopsis</h2>
<p>Stand-alone certificate authority. Capable of generating certificates but mostly meant for signing certificate requests from puppet clients.</p>
<h2>Usage</h2>
<dl>
<dt><code>puppetca [-h|&#8211;help] [-V|&#8211;version] [-d|&#8211;debug] [-v|&#8211;verbose]</code></p>
<dd>[-g|&#8211;generate] [-l|&#8211;list] [-s|&#8211;sign] [-r|&#8211;revoke] [-p|&#8211;print] [-c|&#8211;clean] [&#8211;verify] [host]</dl>
<h2>Description</h2>
<p>Because the puppetmasterd daemon defaults to not signing client certificate requests, this script is available for signing outstanding requests. It can be used to list outstanding requests and then either sign them individually or sign all of them.</p>
<h2>Options</h2>
<p>Note that any configuration parameter thataqs valid in the configuration file is also a valid long argument. For example, aqssldiraq is a valid configuration parameter, so you can specify aq&#8211;ssldir &lt;directory&gt;aq as an argument. </p>
<p> See the configuration file documentation at <i><a rel="nofollow" href="http://puppetlabs.com/projects/puppet/reference/configref.html">http://puppetlabs.com/projects/puppet/reference/configref.html</a></i> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppetca with aq&#8211;genconfigaq.</p>
<dl>
<dt><code>all: Operate on all items. Currently only makes sense with</code></p>
<dd>aq&#8211;signaq, aq&#8211;cleanaq, or aq&#8211;listaq.</p>
<dt><code>clean: Remove all files related to a host from puppetcaaqs storage.</code></p>
<dd>This is useful when rebuilding hosts, since new certificate signing requests will only be honored if puppetca does not have a copy of a signed certificate for that host. The certificate of the host remains valid. If aq&#8211;allaq is specified then all host certificates, both signed and unsigned, will be removed. </p>
<p> debug: Enable full debugging.</p>
<dt><code>generate: Generate a certificate for a named client. A</code></p>
<dd>certificate/keypair will be generated for each client named on the command line. </p>
<p> help: Print this help message</p>
<dt><code>list: List outstanding certificate requests. If aq&#8211;allaq is</code></p>
<dd>specified, signed certificates are also listed, prefixed by aq+aq, and revoked or invalid certificates are prefixed by aq-aq (the verification outcome is printed in parenthesis). </p>
<p> print: Print the full-text version of a hostaqs certificate.</p>
<dt><code>revoke: Revoke the certificate of a client. The certificate can be</code></p>
<dd>specified either by its serial number, given as a decimal number or a hexadecimal number prefixed by aq0xaq, or by its hostname. The certificate is revoked by adding it to the Certificate Revocation List given by the aqcacrlaq config parameter. Note that the puppetmasterd needs to be restarted after revoking certificates.</p>
<dt><code>sign: Sign an outstanding certificate request. Unless aq&#8211;allaq is</code></p>
<dd>specified, hosts must be listed after all flags. </p>
<p> verbose: Enable verbosity. </p>
<p> version: Print the puppet version number and exit. </p>
<p> verify: Verify the named certificate against the local CA certificate.</dl>
<h2>Example</h2>
<p>$ puppetca -l culain.madstop.com $ puppetca -s culain.madstop.com</p>
