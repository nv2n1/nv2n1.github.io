<p><code>puppet-resource</code> &#8211; The resource abstraction layer shell</p>
<h2>Synopsis</h2>
<p>Uses the Puppet RAL to directly interact with the system.</p>
<h2>Usage</h2>
<p>puppet resource [-h|&#8211;help] [-d|&#8211;debug] [-v|&#8211;verbose] [-e|&#8211;edit] [-H|&#8211;host <i>host</i>] [-p|&#8211;param <i>parameter</i>] [-t|&#8211;types] <i>type</i> [<i>name</i>] [<i>attribute</i>=<i>value</i> &#8230;]</p>
<h2>Description</h2>
<p>This command provides simple facilities for converting current system state into Puppet code, along with some ability to modify the current state using Puppet&#8217;s RAL. </p>
<p> By default, you must at least provide a type to list, in which case puppet resource will tell you everything it knows about all resources of that type. You can optionally specify an instance name, and puppet resource will only describe that single instance. </p>
<p> If given a type, a name, and a series of <i>attribute</i>=<i>value</i> pairs, puppet resource will modify the state of the specified resource. Alternately, if given a type, a name, and the &#8216;&#8211;edit&#8217; flag, puppet resource will write its output to a file, open that file in an editor, and then apply the saved file as a Puppet transaction.</p>
<h2>Options</h2>
<p>Note that any configuration parameter that&#8217;s valid in the configuration file is also a valid long argument. For example, &#8216;ssldir&#8217; is a valid configuration parameter, so you can specify &#8216;&#8211;ssldir <i>directory</i>&#8216; as an argument. </p>
<p> See the configuration file documentation at <a rel="nofollow" href="http://docs.puppetlabs.com/references/stable/configuration.html">http://docs.puppetlabs.com/references/stable/configuration.html</a> for the full list of acceptable parameters. A commented list of all configuration options can also be generated by running puppet with &#8216;&#8211;genconfig&#8217;.</p>
<dl>
<dt>&#8211;debug</p>
<dd>Enable full debugging.</p>
<dt>&#8211;edit</p>
<dd>Write the results of the query to a file, open the file in an editor, and read the file back in as an executable Puppet manifest.</p>
<dt>&#8211;host</p>
<dd>When specified, connect to the resource server on the named host and retrieve the list of resouces of the type specified.</p>
<dt>&#8211;help</p>
<dd>Print this help message.</p>
<dt>&#8211;param</p>
<dd>Add more parameters to be outputted from queries.</p>
<dt>&#8211;types</p>
<dd>List all available types.</p>
<dt>&#8211;verbose</p>
<dd>Print extra information.</dl>
<h2>Example</h2>
<p>This example uses <code>puppet resource</code> to return a Puppet configuration for the user <code>luke</code>:</p>
<dl>
<dd>
<pre>$ puppet resource user luke
user { 'luke':
 home =&gt; '/home/luke',
 uid =&gt; '100',
 ensure =&gt; 'present',
 comment =&gt; 'Luke Kanies,,,',
 gid =&gt; '1000',
 shell =&gt; '/bin/bash',
 groups =&gt; ['sysadmin','audio','video','puppet']
}</pre>
<dd></dl>
