<p>arpwatch &#8211; keep track of ethernet/ip address pairings</p>
<h2>Synopsis</h2>
<p><code>arpwatch</code> [ <code>-dNp</code> ] [ <code>-f</code> <i>datafile</i> ] [ <code>-i</code> <i>interface</i> ] </p>
<p> &nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr>&nbsp;<wbr> [ <code>-n</code> <i>net</i>[/<i>width</i> ]] [ <code>-r</code> <i>file</i> ] [ <code>-u</code> <i>username</i> ] [ <code>-e</code> <i>username</i> ] [ <code>-s</code> <i>username</i> ]</p>
<h2>Description</h2>
<p><code>Arpwatch</code> keeps track for ethernet/ip address pairings. It syslogs activity and reports certain changes via email. <code>Arpwatch</code> uses <code><a href="/docs/linux/man/3-pcap/">pcap</a></code>(3) to listen for arp packets on a local ethernet interface. The <code>-d</code> flag is used enable debugging. This also inhibits forking into the background and emailing the reports. Instead, they are sent to <i>stderr</i>. The <code>-p</code> flag disables promiscuous mode. The <code>-f</code> flag is used to set the ethernet/ip address database filename. The default is <i>arp.dat</i>. The <code>-i</code> flag is used to override the default interface. The <code>-n</code> flag specifies additional local networks. This can be useful to avoid &quot;bogon&quot; warnings when there is more than one network running on the same wire. If the optional <i>width</i> is not specified, the default netmask for the network&#8217;s class is used. The <code>-N</code> flag disables reporting any bogons. The <code>-r</code> flag is used to specify a savefile (perhaps created by <code><a href="/docs/linux/man/1-tcpdump/">tcpdump</a></code>(1) or <code><a href="/docs/linux/man/1-pcapture/">pcapture</a></code>(1)) to read from instead of reading from the network. In this case, <code>arpwatch</code> does not fork. If <code>-u </code> flag is used, <code>arpwatch</code> drops root privileges and changes user ID to <i>username</i> and group ID to that of the primary group of <i>username</i>. This is recommended for security reasons. If the <code>-e </code> flag is used, <code>arpwatch</code> sends e-mail messages to <i>username</i> rather than the default (root). If a single `-&#8216; character is given for the username, sending of e-mail is suppressed, but logging via syslog is still done as usual. (This can be useful during initial runs, to collect data without being flooded with messages about new stations.) If the <code>-s </code> flag is used, <code>arpwatch</code> sends e-mail messages with <i>username</i> as the return address, rather than the default (root). Note that an empty <i>arp.dat</i> file must be created before the first time you run <code>arpwatch</code>. Also, the default directory (where arp.dat is stored) must be owned by <i>username</i> if <code>-u</code> flag is used. </p>
<h2>Report Messages</h2>
<p>Here&#8217;s a quick list of the report messages generated by <code><a href="/docs/linux/man/1-arpwatch/">arpwatch</a></code>(1) (and <code><a href="/docs/linux/man/1-arpsnmp/">arpsnmp</a></code>(1)):</p>
<dl>
<dt><code>new activity</code></p>
<dd>This ethernet/ip address pair has been used for the first time six months or more.</p>
<dt><code>new station</code></p>
<dd>The ethernet address has not been seen before.</p>
<dt><code>flip flop</code></p>
<dd>The ethernet address has changed from the most recently seen address to the second most recently seen address. (If either the old or new ethernet address is a DECnet address and it is less than 24 hours, the email version of the report is suppressed.)</p>
<dt><code>changed ethernet address</code></p>
<dd>The host switched to a new ethernet address.</dl>
<h2>Syslog Messages</h2>
<p>Here are some of the syslog messages; note that messages that are reported are also sysloged.</p>
<dl>
<dt><code>ethernet broadcast</code></p>
<dd>The mac ethernet address of the host is a broadcast address.</p>
<dt><code>ip broadcast</code></p>
<dd>The ip address of the host is a broadcast address.</p>
<dt><code>bogon</code></p>
<dd>The source ip address is not local to the local subnet.</p>
<dt><code>ethernet broadcast</code></p>
<dd>The source mac or arp ethernet address was all ones or all zeros.</p>
<dt><code>ethernet mismatch</code></p>
<dd>The source mac ethernet address didn&#8217;t match the address inside the arp packet.</p>
<dt><code>reused old ethernet address</code></p>
<dd>The ethernet address has changed from the most recently seen address to the third (or greater) least recently seen address. (This is similar to a flip flop.)</p>
<dt><code>suppressed DECnet flip flop</code></p>
<dd>A &quot;flip flop&quot; report was suppressed because one of the two addresses was a DECnet address.</dl>
<h2>Files</h2>
<pre>/var/lib/arpwatch - default directory
arp.dat - ethernet/ip address database
ethercodes.dat - vendor ethernet block list</pre>
