<p>automount2amd &#8211; converts old Sun automount maps to Amd maps</p>
<h2>Synopsis</h2>
<p><code>automount2amd</code> <i>auto.map</i></p>
<h2>Description</h2>
<p><code>automount2amd</code> is used to convert an old Sun automount maps named <i>auto.map</i> to an Amd map. This perl script will use the following /default entry </p>
<pre> type:=nfs;opts:=rw,grpid,nosuid,utimeout=600</pre>
<p>If you wish to override that, define the <code>$DEFAULTS</code> environment variable, or modify the script. If you wish to generate Amd maps using the <i>hostd</i> (host domain) Amd map syntax, then define the environment variable <code>$DOMAIN</code> or modify the script. </p>
<h2>Example</h2>
<p>Say you have the Sun automount file auto.foo, with these two lines: </p>
<pre> home earth:/home
 moon -ro,intr server:/proj/images</pre>
<p>Running </p>
<pre> automount2amd auto.foo &gt; amd.foo</pre>
<p>will produce the Amd map <i>amd.foo</i> with this content: </p>
<pre># generated by automount2amd on Sat Aug 14 17:59:32 US/Eastern 1999
/defaults \
 type:=nfs;opts:=rw,grpid,nosuid,utimeout=600
home host==earth;type:=link;fs:=/home \
 rhost:=earth;rfs:=/home
moon -addopts:=ro,intr \
 host==server;type:=link;fs:=/proj/images \
 rhost:=server;rfs:=/proj/images</pre>
<h2>Bugs</h2>
<p><i>automount2amd</i> does not understand newer Sun Automount map syntax, those used by autofs.</p>
