<p>mh-mime &#8211; Overview of <i></p>
<p><a href="/docs/linux/man/7-nmh/">nmh</a></i>(7) MIME message composition and display</p>
<h2>Description</h2>
<p>The acronym MIME stands for Multipurpose Internet Mail Extensions, the format of Internet messages used to send multi-media content. The <code>nmh</code> command suite has support for the display and composition of MIME messages, but currently MIME support is not completely integrated into all tools. This document provides an overview as to which tools support MIME message display, storage, and composition.</p>
<h3>Local Character Set Conversion</h3>
<p>All of the <code>nmh</code> commands convert non-native character sets to the local character set, as specified by the operating system locale settings. See <i><a href="/docs/linux/man/1-locale/">locale</a></i>(1) for more details on the environment variables used to set the local character set. Character set conversion will only take place if <code>nmh</code> was built with <i><a href="/docs/linux/man/3-iconv/">iconv</a></i>(3) support. See the <i><a href="/docs/linux/man/1-mhparam/">mhparam</a></i>(1) man page for how determine whether your <code>nmh</code> installation includes <i><a href="/docs/linux/man/3-iconv/">iconv</a></i>(3) support. </p>
<p> Depending on the source and target character set, it may not be possible to convert all characters to the local character set. In this case a substitution character will be used for the characters that cannot be converted.</p>
<h3>Message Display</h3>
<p>The default format used by <i><a href="/docs/linux/man/1-scan/">scan</a></i>(1) will automatically decode MIME-encoded headers. If you have a custom <code>scan</code> format, see the examples provided with the <code>nmh</code> distribution (found in the &#8220;<i>/etc/nmh</i>&#8221; directory) and <i><a href="/docs/linux/man/5-mh-format/">mh-format</a></i>(5) for details on how to make sure your MIME headers are properly decoded. </p>
<p> By default, if <code>show</code> detects that it is reading a MIME message it will invoke <i><a href="/docs/linux/man/1-mhshow/">mhshow</a></i>(1). The default behavior of <code>mhshow</code> is to only display text parts that are not marked as attachments. See <i><a href="/docs/linux/man/1-mhshow/">mhshow</a></i>(1) for details on how to control what <code>mhshow</code> will display.</p>
<h3>Message Interrogation and Storage</h3>
<p>The <i><a href="/docs/linux/man/1-mhlist/">mhlist</a></i>(1) command will display a listing of the MIME parts contained within a message. That information can be used in conjunction with the <code>mhstore</code> command to save individual parts or content types of a message. See <i><a href="/docs/linux/man/1-mhlist/">mhlist</a></i>(1) and <i><a href="/docs/linux/man/1-mhstore/">mhstore</a></i>(1) for more details on how these commands work.</p>
<h3>Message Composition and Reply</h3>
<p>All messages sent by <i><a href="/docs/linux/man/1-send/">send</a></i>(1) will automatically be processed by <i><a href="/docs/linux/man/1-mhbuild/">mhbuild</a></i>(1) before being passed to <i><a href="/docs/linux/man/1-post/">post</a></i>(1) for message submission. <code>Mhbuild</code> will use the locale settings to mark text content with the appropriate character set and apply any necessary encoding. If you wish to include text in your message using a character set that does not match your locale, you will need to specify the character set using a <code>mhbuild</code> directive; see <i><a href="/docs/linux/man/1-mhbuild/">mhbuild</a></i>(1) for more information. </p>
<p> For attaching files or composing other non-text content, there are two options: the attach system and <code>mhbuild</code> directives. </p>
<p> The attach system is best suited for content where one or more files are being attached to a message. You can use the attach system by either using the <code>attach</code> command at the &#8220;What now?&#8221; prompt, or by inserting an &#8220;Attach:&#8221; header in the message draft containing the name of the file you wish to attach to the message (it should be noted all that the <code>attach</code> command does is place an &#8220;Attach&#8221; header in the message draft). <code>Mhbuild</code> will then automatically include the specified file(s) in the outgoing message. See <i><a href="/docs/linux/man/1-send/">send</a></i>(1) for details on how <code>mhbuild</code> determines the proper content type of attached files. </p>
<p> The other method of composing MIME messages is to use <code>mhbuild</code> directives. This allows exact control over the contents and format of the MIME message, but has a more complicated syntax. <i><a href="/docs/linux/man/1-mhbuild/">mhbuild</a></i>(1) contains details on the directive syntax and examples of directives for different media types. It is important to note that when using <code>mhbuild</code> directives the user must run <code>mhbuild</code> outside of <code>send</code> to have it process directives; when being run by <code>send</code>, <code>mhbuild</code> is configured to not process directives so normal user text is not mistaken for a directive. When using directives a user typically uses the <code>mime</code> command at the &#8220;What now?&#8221; prompt to process them. </p>
<p> When replying to messages using <i><a href="/docs/linux/man/1-repl/">repl</a></i>(1) the traditional MH method of including the original text in the reply does not interoperate with MIME messages. As of this writing there is no native solution for addressing this issue, but the contrib directory (<i>/usr/share/doc/nmh-1.6/contrib</i>) contains a Perl program called <code>replyfilter</code> which will decode text parts and present them in an appropriate manner to be included in a message reply. See the comments at the top of <code>replyfilter</code> for instructions on how to configure <code>nmh</code> to work with it.</p>
<h3>Message Rewrite</h3>
<p>The <i><a href="/docs/linux/man/1-mhfixmsg/">mhfixmsg</a></i>(1) command can apply various transformations to MIME messages, including decoding of text parts, converting the character set of text parts, and insertion of text/plain parts to correspond to text parts of other subtypes. <code>mhfixmsg</code> can also repair defects in MIME messages, such as mismatched top-level boundary indicators and invalid Content-Transfer-Encoding values.</p>
