<p>remote-filesystems &#8211; event signalling that remote filesystems have been mounted</p>
<h2>Synopsis</h2>
<p><code>local-filesystems</code> [<i>ENV</i>]&#8230;</p>
<h2>Description</h2>
<p>The <code>remote-filesystems</code> event is generated by the <code><a href="/docs/linux/man/8-mountall/">mountall</a></code>(8) daemon after it has mounted all remote filesystems listed in <code><a href="/docs/linux/man/5-fstab/">fstab</a></code>(5). <code><a href="/docs/linux/man/8-mountall/">mountall</a></code>(8) emits this event as an informational signal, services and tasks started or stopped by this event will do so in parallel with other activity. </p>
<p> This event is typically used by services that must be started to manage remote filesystems. When it occurs, local filesystems such as <i>/usr</i> may not be mounted. For most normal services the <code><a href="/docs/linux/man/7-filesystem/">filesystem</a></code>(7) event is sufficient. </p>
<p> This event will never occur before the <code><a href="/docs/linux/man/7-virtual-filesystems/">virtual-filesystems</a></code>(7) event.</p>
<h2>Example</h2>
<p>A service that wishes to be running once remote filesystems are mounted might use: </p>
<dl>
<dd>
<pre>start on remote-filesystems</pre>
</dl>
