<p>time &#8211; overview of time and timers</p>
<h2>Description</h2>
<h3>Real time and process time</h3>
<p><i>Real time</i> is defined as time measured from some fixed point, either from a standard point in the past (see the description of the Epoch and calendar time below), or from some point (e.g., the start) in the life of a process (<i>elapsed time</i>). </p>
<p> <i>Process time</i> is defined as the amount of CPU time used by a process. This is sometimes divided into <i>user</i> and <i>system</i> components. User CPU time is the time spent executing code in user mode. System CPU time is the time spent by the kernel executing in system mode on behalf of the process (e.g., executing system calls). The <code><a href="/docs/linux/man/1-time/">time</a></code>(1) command can be used to determine the amount of CPU time consumed during the execution of a program. A program can determine the amount of CPU time it has consumed using <code><a href="/docs/linux/man/2-times/">times</a></code>(2), <code><a href="/docs/linux/man/2-getrusage/">getrusage</a></code>(2), or <code><a href="/docs/linux/man/3-clock/">clock</a></code>(3).</p>
<h3>The hardware clock</h3>
<p>Most computers have a (battery-powered) hardware clock which the kernel reads at boot time in order to initialize the software clock. For further details, see <code><a href="/docs/linux/man/4-rtc/">rtc</a></code>(4) and <code><a href="/docs/linux/man/8-hwclock/">hwclock</a></code>(8).</p>
<h3>The software clock, HZ, and jiffies</h3>
<p>The accuracy of various system calls that set timeouts, (e.g., <code><a href="/docs/linux/man/2-select/">select</a></code>(2), <code><a href="/docs/linux/man/2-sigtimedwait/">sigtimedwait</a></code>(2)) and measure CPU time (e.g., <code><a href="/docs/linux/man/2-getrusage/">getrusage</a></code>(2)) is limited by the resolution of the <i>software clock</i>, a clock maintained by the kernel which measures time in <i>jiffies</i>. The size of a jiffy is determined by the value of the kernel constant <i>HZ</i>. </p>
<p> The value of <i>HZ</i> varies across kernel versions and hardware platforms. On i386 the situation is as follows: on kernels up to and including 2.4.x, HZ was 100, giving a jiffy value of 0.01 seconds; starting with 2.6.0, HZ was raised to 1000, giving a jiffy of 0.001 seconds. Since kernel 2.6.13, the HZ value is a kernel configuration parameter and can be 100, 250 (the default) or 1000, yielding a jiffies value of, respectively, 0.01, 0.004, or 0.001 seconds. Since kernel 2.6.20, a further frequency is available: 300, a number that divides evenly for the common video frame rates (PAL, 25 HZ; NTSC, 30 HZ). </p>
<p> The <code><a href="/docs/linux/man/2-times/">times</a></code>(2) system call is a special case. It reports times with a granularity defined by the kernel constant <i>USER_HZ</i>. User-space applications can determine the value of this constant using <i>sysconf(_SC_CLK_TCK)</i>.</p>
<h3>System and process clocks; time namespaces</h3>
<p>The kernel supports a range of clocks that measure various kinds of elapsed and virtual (i.e., consumed CPU) time. These clocks are described in <code><a href="/docs/linux/man/2-clock_gettime/">clock_gettime</a></code>(2). A few of the clocks are settable using <code><a href="/docs/linux/man/2-clock_settime/">clock_settime</a></code>(2). The values of certain clocks are virtualized by time namespaces; see <code><a href="/docs/linux/man/7-time_namespaces/">time_namespaces</a></code>(7).</p>
<h3>High-resolution timers</h3>
<p>Before Linux 2.6.21, the accuracy of timer and sleep system calls (see below) was also limited by the size of the jiffy. </p>
<p> Since Linux 2.6.21, Linux supports high-resolution timers (HRTs), optionally configurable via <code>CONFIG_HIGH_RES_TIMERS</code>. On a system that supports HRTs, the accuracy of sleep and timer system calls is no longer constrained by the jiffy, but instead can be as accurate as the hardware allows (microsecond accuracy is typical of modern hardware). You can determine whether high-resolution timers are supported by checking the resolution returned by a call to <code><a href="/docs/linux/man/2-clock_getres/">clock_getres</a></code>(2) or looking at the &quot;resolution&quot; entries in <i>/proc/timer_list</i>. </p>
<p> HRTs are not supported on all hardware architectures. (Support is provided on x86, arm, and powerpc, among others.)</p>
<h3>The Epoch</h3>
<p>UNIX systems represent time in seconds since the <i>Epoch</i>, 1970-01-01 00:00:00 +0000 (UTC). </p>
<p> A program can determine the <i>calendar time</i> via the <code><a href="/docs/linux/man/2-clock_gettime/">clock_gettime</a></code>(2) <code>CLOCK_REALTIME</code> clock, which returns time (in seconds and nanoseconds) that have elapsed since the Epoch; <code><a href="/docs/linux/man/2-time/">time</a></code>(2) provides similar information, but only with accuracy to the nearest second. The system time can be changed using <code><a href="/docs/linux/man/2-clock_settime/">clock_settime</a></code>(2).</p>
<h3>Broken-down time</h3>
<p>Certain library functions use a structure of type <i>tm</i> to represent <i>broken-down time</i>, which stores time value separated out into distinct components (year, month, day, hour, minute, second, etc.). This structure is described in <code><a href="/docs/linux/man/3-ctime/">ctime</a></code>(3), which also describes functions that convert between calendar time and broken-down time. Functions for converting between broken-down time and printable string representations of the time are described in <code><a href="/docs/linux/man/3-ctime/">ctime</a></code>(3), <code><a href="/docs/linux/man/3-strftime/">strftime</a></code>(3), and <code><a href="/docs/linux/man/3-strptime/">strptime</a></code>(3).</p>
<h3>Sleeping and setting timers</h3>
<p>Various system calls and functions allow a program to sleep (suspend execution) for a specified period of time; see <code><a href="/docs/linux/man/2-nanosleep/">nanosleep</a></code>(2), <code><a href="/docs/linux/man/2-clock_nanosleep/">clock_nanosleep</a></code>(2), and <code><a href="/docs/linux/man/3-sleep/">sleep</a></code>(3). </p>
<p> Various system calls allow a process to set a timer that expires at some point in the future, and optionally at repeated intervals; see <code><a href="/docs/linux/man/2-alarm/">alarm</a></code>(2), <code><a href="/docs/linux/man/2-getitimer/">getitimer</a></code>(2), <code><a href="/docs/linux/man/2-timerfd_create/">timerfd_create</a></code>(2), and <code><a href="/docs/linux/man/2-timer_create/">timer_create</a></code>(2).</p>
<h3>Timer slack</h3>
<p>Since Linux 2.6.28, it is possible to control the &quot;timer slack&quot; value for a thread. The timer slack is the length of time by which the kernel may delay the wake-up of certain system calls that block with a timeout. Permitting this delay allows the kernel to coalesce wake-up events, thus possibly reducing the number of system wake-ups and saving power. For more details, see the description of <code>PR_SET_TIMERSLACK</code> in <code><a href="/docs/linux/man/2-prctl/">prctl</a></code>(2).</p>
