<p>startup &#8211; event signalling system startup</p>
<h2>Synopsis</h2>
<p><code>startup</code> [<i>ENV</i>]&#8230;</p>
<h2>Description</h2>
<p>The <code>startup</code> event is generated by the Upstart <code><a href="/docs/linux/man/8-init/">init</a></code>(8) daemon after it has completed its own initialisation and is the signal that the rest of the system may be started. </p>
<p> Typically this will involve checking and mounting the partitions and drives that form the filesystem, loading drivers for connected devices and starting the X windowing system or other login environment. </p>
<p> In the default Upstart configuration, the primary task run on the <code>startup</code> event is the <i>/etc/init/rc-sysinit.conf</i> job responsible for generating the System V compatible <code><a href="/docs/linux/man/7-runlevel/">runlevel</a></code>(7) event. See that page for a more detailed explanation of this process. </p>
<p> This event is emitted when running both as pid 1 and as a Session Init. </p>
<p> Paradoxically there is currently no corresponding Upstart-native event signifying that the system is to be shutdown, only the System V compatible <code>runlevel 0</code> and <code>runlevel 6</code> events provide this functionality. However, when running as a Session Init, the <code>session-end</code> event performs this function.</p>

<p>A service with no other dependencies run on startup might use: </p>

</dl>
