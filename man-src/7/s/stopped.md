<p>stopped &#8211; event signalling that a job has stopped</p>
<h2>Synopsis</h2>
<p><code>stopped</code> <code>JOB</code>=<i>JOB</i> <code>INSTANCE</code>=<i>INSTANCE</i> <code>RESULT</code>=<i>RESULT</i> <i></i>[<code>PROCESS</code>=<i>PROCESS</i>] <i></i>[<code>EXIT_STATUS</code>=<i>STATUS</i>] <i></i>[<code>EXIT_SIGNAL</code>=<i>SIGNAL</i>] [<i>ENV</i>]&#8230;</p>
<h2>Description</h2>
<p>The <code>stopped</code> event is generated by the Upstart <code><a href="/docs/linux/man/8-init/">init</a></code>(8) daemon when an instance of a job has stopped. The <code>JOB</code> environment variable contains the job name, and the <code>INSTANCE</code> environment variable contains the instance name which will be empty for single-instance jobs. </p>
<p> If the job was stopped normally, the <code>RESULT</code> environment variable will be <i>ok</i>, otherwise if the job was stopped because it has failed it will be <i>failed</i>. </p>
<p> When the job has failed, the process that failed will be given in the <code>PROCESS</code> environment variable. This may be <i>pre-start</i>, <i>post-start</i>, <i>main</i>, <i>pre-stop</i> or <i>post-stop</i>; it may also be the special value <i>respawn</i> to indicate that the job was stopped because it hit the respawn limit. </p>
<p> Finally in the case of a failed job, one of either <code>EXIT_STATUS</code> or <code>EXIT_SIGNAL</code> may be given to indicate the cause of the stop. Either <code>EXIT_STATUS</code> will contain the exit status code of the process, or <code>EXIT_SIGNAL</code> will contain the name of the signal that the process received. The <code>normal exit</code> job configuration stanza can be used to prevent particular exit status values or signals resulting in a failed job, see <code><a href="/docs/linux/man/5-init/">init</a></code>(5) for more information. </p>
<p> If neither <code>EXIT_STATUS</code> or <code>EXIT_SIGNAL</code> is given for a failed process, it is because the process failed to spawn (for example, file not found). See the system logs for the error. </p>
<p> <code><a href="/docs/linux/man/8-init/">init</a></code>(8) emits this event as an informational signal, services and tasks started or stopped by this event will do so in parallel with other activity. It is typically combined with the <code><a href="/docs/linux/man/7-starting/">starting</a></code>(7) event by services when inserting themselves as a dependency. </p>
<p> Job configuration files may use the <code>export</code> stanza to export environment variables from their own environment into the <code>stopped</code> event. See <code><a href="/docs/linux/man/5-init/">init</a></code>(5) for more details.</p>
<h2>Example</h2>
<p>A service that wishes to be running whenever another service would be running, started before and stopped after it, might use: </p>
<dl>
<dd>
<pre>start on starting apache
stop on stopped apache</pre>
</dl>
<p> A task that must be run after another task or service has been stopped might use: </p>
<dl>
<dd>
<pre>start on stopped postgresql</pre>
</dl>
