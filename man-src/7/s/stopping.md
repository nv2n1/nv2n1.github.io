<p>stopping &#8211; event signalling that a job is stopping</p>
<h2>Synopsis</h2>
<p><code>stopping</code> <code>JOB</code>=<i>JOB</i> <code>INSTANCE</code>=<i>INSTANCE</i> <code>RESULT</code>=<i>RESULT</i> <i></i>[<code>PROCESS</code>=<i>PROCESS</i>] <i></i>[<code>EXIT_STATUS</code>=<i>STATUS</i>] <i></i>[<code>EXIT_SIGNAL</code>=<i>SIGNAL</i>] [<i>ENV</i>]&#8230;</p>
<h2>Description</h2>
<p>The <code>stopping</code> event is generated by the Upstart <code><a href="/docs/linux/man/8-init/">init</a></code>(8) daemon when an instance of a job begins stopping. The <code>JOB</code> environment variable contains the job name, and the <code>INSTANCE</code> environment variable contains the instance name which will be empty for single-instance jobs. </p>
<p> If the job is stopping normally, the <code>RESULT</code> environment variable will be <i>ok</i>, otherwise if the job is stopping because it has failed it will be <i>failed</i>. </p>
<p> When the job has failed, the process that failed will be given in the <code>PROCESS</code> environment variable. This may be <i>pre-start</i>, <i>post-start</i>, <i>main</i>, <i>pre-stop</i> or <i>post-stop</i>; it may also be the special value <i>respawn</i> to indicate that the job is stopping because it hit the respawn limit. </p>
<p> Finally in the case of a failed job, one of either <code>EXIT_STATUS</code> or <code>EXIT_SIGNAL</code> may be given to indicate the cause of the stop. Either <code>EXIT_STATUS</code> will contain the exit status code of the process, or <code>EXIT_SIGNAL</code> will contain the name of the signal that the process received. The <code>normal exit</code> job configuration stanza can be used to prevent particular exit status values or signals resulting in a failed job, see <code><a href="/docs/linux/man/5-init/">init</a></code>(5) for more information. </p>
<p> If neither <code>EXIT_STATUS</code> or <code>EXIT_SIGNAL</code> is given for a failed process, it is because the process failed to spawn (for example, file not found). See the system logs for the error. </p>
<p> <code><a href="/docs/linux/man/8-init/">init</a></code>(8) will wait for all services started by this event to be running, all tasks started by this event to have finished and all jobs stopped by this event to be stopped before allowing the job to continue stopping. </p>
<p> This allows jobs to depend on other jobs, safely stopping themselves before their dependency goes away. This event is typically combined with the <code><a href="/docs/linux/man/7-started/">started</a></code>(7) event by services. </p>
<p> Job configuration files may use the <code>export</code> stanza to export environment variables from their own environment into the <code>stopping</code> event. See <code><a href="/docs/linux/man/5-init/">init</a></code>(5) for more details.</p>
<h2>Example</h2>
<p>A service that wishes to depend on another service might use: </p>
<dl>
<dd>
<pre>start on started apache
stop on stopping apache</pre>
</dl>
<p> A task that must be run before another task or service is stopped might use: </p>
<dl>
<dd>
<pre>start on stopping postgresql RESULT=ok</pre>
</dl>
