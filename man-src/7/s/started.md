<p>started &#8211; event signalling that a job is running</p>
<h2>Synopsis</h2>
<p><code>started</code> <code>JOB</code>=<i>JOB</i> <code>INSTANCE</code>=<i>INSTANCE</i> [<i>ENV</i>]&#8230;</p>
<h2>Description</h2>
<p>The <code>started</code> event is generated by the Upstart <code><a href="/docs/linux/man/8-init/">init</a></code>(8) daemon when an instance of a job has finished starting and is now running. The <code>JOB</code> environment variable contains the job name, and the <code>INSTANCE</code> environment variable contains the instance name which will be empty for single-instance jobs. </p>
<p> <code><a href="/docs/linux/man/8-init/">init</a></code>(8) emits this event as an informational signal, services and tasks started or stopped by this event will do so in parallel with other activity. It is typically combined with the <code><a href="/docs/linux/man/7-stopping/">stopping</a></code>(7) event by services declaring a dependency. </p>
<p> Job configuration files may use the <code>export</code> stanza to export environment variables from their own environment into the <code>started</code> event. See <code><a href="/docs/linux/man/5-init/">init</a></code>(5) for more details.</p>
<h2>Example</h2>
<p>A service that wishes to depend on another service might use: </p>
<dl>
<dd>
<pre>start on started apache
stop on stopping apache</pre>
</dl>
<p> A task that must be run after another task or service has been started might use: </p>
<dl>
<dd>
<pre>start on started postgresql</pre>
</dl>
