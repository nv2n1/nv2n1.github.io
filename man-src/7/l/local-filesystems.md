<p>local-filesystems &#8211; event signalling that local filesystems have been mounted</p>
<h2>Synopsis</h2>
<p><code>local-filesystems</code> [<i>ENV</i>]&#8230;</p>
<h2>Description</h2>
<p>The <code>local-filesystems</code> event is generated by the <code><a href="/docs/linux/man/8-mountall/">mountall</a></code>(8) daemon after it has mounted all local filesystems listed in <code><a href="/docs/linux/man/5-fstab/">fstab</a></code>(5). <code><a href="/docs/linux/man/8-mountall/">mountall</a></code>(8) emits this event as an informational signal, services and tasks started or stopped by this event will do so in parallel with other activity. </p>
<p> This event is typically used by services that must be started in order for remote filesystems, if any, to be activated. Remember that some users may not consider it wrong to place <i>/usr</i> on a remote filesystem. For most normal services the <code><a href="/docs/linux/man/7-filesystem/">filesystem</a></code>(7) event is sufficient. </p>
<p> This event will never occur before the <code><a href="/docs/linux/man/7-virtual-filesystems/">virtual-filesystems</a></code>(7) event.</p>
<h2>Example</h2>
<p>A service that wishes to be running once local filesystems are mounted might use: </p>
<dl>
<dd>
<pre>start on local-filesystems</pre>
</dl>
