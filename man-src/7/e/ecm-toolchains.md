<p>ecm-toolchains &#8211; ECM Toolchains Reference</p>
<h2>Introduction</h2>
<p>Extra CMake Modules (ECM) provides some toolchain modules. Unlike normal modules, these are not included directly in projects, but specified with the <code>CMAKE_TOOLCHAIN_FILE</code> cache variable on the commandline.</p>
<h2>All Modules</h2>
<h3>AndroidToolchain</h3>
<p>Enable easy compilation of cmake projects on Android. </p>
<p> By using this android toolchain, the projects will be set up to compile the specified project targeting an Android platform, depending on its input. Furthermore, if desired, an APK can be directly generated by using the <i>androiddeployqt</i> tool. </p>
<p> <code>NOTE:</code> This module requires CMake 3.1. </p>
<p> Since 1.7.0.</p>
<h3>Usage</h3>
<p>To use this file, you need to set the <code>CMAKE_TOOLCHAIN_FILE</code> to point to <code>AndroidToolchain.cmake</code> on the command line: </p>
<pre>cmake -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/AndroidToolchain.cmake</pre>
<p>You will also need to provide the locations of the Android NDK and SDK. This can be done on the commandline or with environment variables; in either case the variable names are:</p>
<dl>
<dt><code>ANDROID_NDK</code></p>
<dd>The NSK root path.</p>
<dt><code>ANDROID_SDK_ROOT</code></p>
<dd>The SDK root path. </p>
<p> Additional options are specified as cache variables (eg: on the command line):</p>
<dt><code>ANDROID_ARCHITECTURE</code></p>
<dd>The architecture to compile for. Default: <code>arm</code>.</p>
<dt><code>ANDROID_TOOLCHAIN</code></p>
<dd>The toolchain to use. See the <code>toolchains</code> directory of the NDK. Default: <code>arm-linux-androideabi</code>.</p>
<dt><code>ANDROID_ABI</code></p>
<dd>The ABI to use. See the <code>sources/cxx-stl/gnu-libstdc++/*/libs</code> directories in the NDK. Default: <code>armeabi-v7a</code>.</p>
<dt><code>ANDROID_GCC_VERSION</code></p>
<dd>The GCC version to use. Default: <code>4.9</code>.</p>
<dt><code>ANDROID_API_LEVEL</code></p>
<dd>The <i>API level</i> to require. Default: <code>14</code>.</p>
<dt><code>ANDROID_SDK_BUILD_TOOLS_REVISION</code></p>
<dd>The build tools version to use. Default: <code>21.1.1</code>. </p>
<p> For integrating other libraries which are not part of the Android toolchain, like Qt5, and installed to a separate prefix on the host system, the install prefixes of those libraries would be passed as alternative roots as list via <code>ECM_ADDITIONAL_FIND_ROOT_PATH</code>. Since 5.30.0. </p>
<p> For example, for integrating a Qt5 for Android with armv7 target present at <code>/opt/android/Qt5/5.7/android_armv7</code> and some other libraries installed to the prefix <code>/opt/android/foo</code>, you would use: </p>
<pre>cmake \
 -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/AndroidToolchain.cmake \
 -DECM_ADDITIONAL_FIND_ROOT_PATH=&quot;/opt/android/Qt5/5.7/android_armv7;/opt/android/foo&quot;</pre>
<p>If your project uses <code>find_package()</code> to locate build tools on the host system, make sure to pass <code>CMAKE_FIND_ROOT_PATH_BOTH</code> or <code>NO_CMAKE_FIND_ROOT_PATH</code> as argument in the call. See the <code>find_package()</code> documentation for more details.</dl>
<h3>Deploying Qt Applications</h3>
<p>After building the application, you will need to generate an APK that can be deployed to an Android device. This module integrates androiddeployqt support to help with this for Qt-based projects. To enable this, set the <code>QTANDROID_EXPORTED_TARGET</code> variable to the target you wish to export as an APK, as well as <code>ANDROID_APK_DIR</code> to a directory containing some basic information. This will create a <code>create-apk-&lt;target&gt;</code> target that will generate the APK file. See the <i>Qt on Android deployment documentation</i> for more information. </p>
<p> For example, you could do: </p>
<pre>cmake \
 -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/AndroidToolchain.cmake \
 -DQTANDROID_EXPORTED_TARGET=myapp \
 -DANDROID_APK_DIR=myapp-apk
make
make create-apk-myapp</pre>
<p>The APK would then be found in <code>myapp_build_apk/bin</code> in the build directory. </p>
<p> The create-apk-myapp target will be able to take an ARGS parameter with further arguments for androiddeployqt. For example, one can use: </p>
<pre>make create-apk-myapp ARGS=&quot;--install&quot;</pre>
<p>To install the apk to test. To generate a signed apk, one can do it with the following syntax: </p>
<pre>make create-apk-myapp ARGS=&quot;--sign ~/my.keystore alias_name&quot;</pre>
<p>See Android documentation on how to create a keystore to use</p>
