<h2 class="name">NAME</h2>
<p> rt_sigqueueinfo, rt_tgsigqueueinfo &#8211; queue a signal and data </p>
<h2>SYNOPSIS</h2>
<pre><code>
int rt_sigqueueinfo(pid_t tgid, int sig, siginfo_t *info);
int rt_tgsigqueueinfo(pid_t tgid, pid_t tid, int sig,
                      siginfo_t *info);
</code></pre>
<p> <i>Note</i>: There are no glibc wrappers for these system calls; see NOTES.</p>
<h2>DESCRIPTION</h2>
<p> The <code>rt_sigqueueinfo</code>() and <code>rt_tgsigqueueinfo</code>() system calls are the low-level interfaces used to send a signal plus data to a process or thread. The receiver of the signal can obtain the accompanying data by establishing a signal handler with the <code><a href="/docs/linux/man/2-sigaction/">sigaction</a></code>(2) <code>SA_SIGINFO</code> flag. </p>
<p> These system calls are not intended for direct application use; they are provided to allow the implementation of <code><a href="/docs/linux/man/3-sigqueue/">sigqueue</a></code>(3) and <code><a href="/docs/linux/man/3-pthread_sigqueue/">pthread_sigqueue</a></code>(3). </p>
<p> The <code>rt_sigqueueinfo</code>() system call sends the signal <i>sig</i> to the thread group with the ID <i>tgid</i>. (The term &quot;thread group&quot; is synonymous with &quot;process&quot;, and <i>tid</i> corresponds to the traditional UNIX process ID.) The signal will be delivered to an arbitrary member of the thread group (i.e., one of the threads that is not currently blocking the signal). </p>
<p> The <i>info</i> argument specifies the data to accompany the signal. This argument is a pointer to a structure of type <i>siginfo_t</i>, described in <code><a href="/docs/linux/man/2-sigaction/">sigaction</a></code>(2) (and defined by including <i>&lt;sigaction.h&gt;</i>). The caller should set the following fields in this structure:</p>
<dl>
<dt><i>si_code</i></p>
<dd> This should be one of the <code>SI_*</code> codes in the Linux kernel source file <i>include/asm-generic/siginfo.h</i>. If the signal is being sent to any process other than the caller itself, the following restrictions apply:</p>
<dl>
<dt>
<dd>
<dl>
<dt>*</p>
<dd> The code can&#8217;t be a value greater than or equal to zero. In particular, it can&#8217;t be <code>SI_USER</code>, which is used by the kernel to indicate a signal sent by <code><a href="/docs/linux/man/2-kill/">kill</a></code>(2), and nor can it be <code>SI_KERNEL</code>, which is used to indicate a signal generated by the kernel.</p>
<dt>*</p>
<dd> The code can&#8217;t (since Linux 2.6.39) be <code>SI_TKILL</code>, which is used by the kernel to indicate a signal sent using <code><a href="/docs/linux/man/2-tgkill/">tgkill</a></code>(2).</dl>
</dl>
<dt><i>si_pid</i></p>
<dd> This should be set to a process ID, typically the process ID of the sender.</p>
<dt><i>si_uid</i></p>
<dd> This should be set to a user ID, typically the real user ID of the sender.</p>
<dt><i>si_value</i></p>
<dd> This field contains the user data to accompany the signal. For more information, see the description of the last (<i>union sigval</i>) argument of <code><a href="/docs/linux/man/3-sigqueue/">sigqueue</a></code>(3).</dl>
<p> Internally, the kernel sets the <i>si_signo</i> field to the value specified in <i>sig</i>, so that the receiver of the signal can also obtain the signal number via that field. </p>
<p> The <code>rt_tgsigqueueinfo</code>() system call is like <code>rt_sigqueueinfo</code>(), but sends the signal and data to the single thread specified by the combination of <i>tgid</i>, a thread group ID, and <i>tid</i>, a thread in that thread group.</p>
<h2>RETURN VALUE</h2>
<p> On success, these system calls return 0. On error, they return -1 and <i>errno</i> is set to indicate the error.</p>
<h2>ERRORS</h2>
<dl>
<dt><code>EAGAIN</code></p>
<dd> The limit of signals which may be queued has been reached. (See <code><a href="/docs/linux/man/7-signal/">signal</a></code>(7) for further information.)</p>
<dt><code>EINVAL</code></p>
<dd> <i>sig</i>, <i>tgid</i>, or <i>tid</i> was invalid.</p>
<dt><code>EPERM</code></p>
<dd> The caller does not have permission to send the signal to the target. For the required permissions, see <code><a href="/docs/linux/man/2-kill/">kill</a></code>(2).</p>
<dt><code>EPERM</code></p>
<dd> <i>tgid</i> specifies a process other than the caller and <i>info-&gt;si_code</i> is invalid.</p>
<dt><code>ESRCH</code></p>
<dd> <code>rt_sigqueueinfo</code>(): No thread group matching <i>tgid</i> was found.</dl>
<p> <code>rt_tgsigqueinfo</code>(): No thread matching <i>tgid</i> and <i>tid</i> was found.</p>
<h2>VERSIONS</h2>
<p> The <code>rt_sigqueueinfo</code>() system call was added to Linux in version 2.2. The <code>rt_tgsigqueueinfo</code>() system call was added to Linux in version 2.6.31.</p>
<h2>CONFORMING TO</h2>
<p> These system calls are Linux-specific.</p>
<h2>NOTES</h2>
<p> Since these system calls are not intended for application use, there are no glibc wrapper functions; use <code><a href="/docs/linux/man/2-syscall/">syscall</a></code>(2) in the unlikely case that you want to call them directly. </p>
<p> As with <code><a href="/docs/linux/man/2-kill/">kill</a></code>(2), the null signal (0) can be used to check if the specified process or thread exists.</p>
