<h2 class="name">NAME</h2>
<p> sigprocmask, rt_sigprocmask &#8211; examine and change blocked signals </p>
<h2>SYNOPSIS</h2>
<p> <code>#include &lt;signal.h&gt;</code> </p>
<pre><code>
/* Prototype for the glibc wrapper function */
int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);
/* Prototype for the underlying system call */
int rt_sigprocmask(int how, const kernel_sigset_t *set,
                   kernel_sigset_t *oldset, size_t sigsetsize);
/* Prototype for the legacy system call (deprecated) */
int sigprocmask(int how, const old_kernel_sigset_t *set,
                old_kernel_sigset_t *oldset);
</code></pre>
<p> Feature Test Macro Requirements for glibc (see <code><a href="/docs/linux/man/7-feature_test_macros/">feature_test_macros</a></code>(7)): </p>
<p> <code>sigprocmask</code>(): _POSIX_C_SOURCE</p>
<h2>DESCRIPTION</h2>
<p> <code>sigprocmask</code>() is used to fetch and/or change the signal mask of the calling thread. The signal mask is the set of signals whose delivery is currently blocked for the caller (see also <code><a href="/docs/linux/man/7-signal/">signal</a></code>(7) for more details). </p>
<p> The behavior of the call is dependent on the value of <i>how</i>, as follows.</p>
<dl>
<dt><code>SIG_BLOCK</code></p>
<dd> The set of blocked signals is the union of the current set and the <i>set</i> argument.</p>
<dt><code>SIG_UNBLOCK</code></p>
<dd> The signals in <i>set</i> are removed from the current set of blocked signals. It is permissible to attempt to unblock a signal which is not blocked.</p>
<dt><code>SIG_SETMASK</code></p>
<dd> The set of blocked signals is set to the argument <i>set</i>.</dl>
<p> If <i>oldset</i> is non-NULL, the previous value of the signal mask is stored in <i>oldset</i>. </p>
<p> If <i>set</i> is NULL, then the signal mask is unchanged (i.e., <i>how</i> is ignored), but the current value of the signal mask is nevertheless returned in <i>oldset</i> (if it is not NULL). </p>
<p> A set of functions for modifying and inspecting variables of type <i>sigset_t</i> (&quot;signal sets&quot;) is described in <code><a href="/docs/linux/man/3-sigsetops/">sigsetops</a></code>(3). </p>
<p> The use of <code>sigprocmask</code>() is unspecified in a multithreaded process; see <code><a href="/docs/linux/man/3-pthread_sigmask/">pthread_sigmask</a></code>(3).</p>
<h2>RETURN VALUE</h2>
<p> <code>sigprocmask</code>() returns 0 on success and -1 on error. In the event of an error, <i>errno</i> is set to indicate the cause.</p>
<h2>ERRORS</h2>
<dl>
<dt><code>EFAULT</code></p>
<dd> The <i>set</i> or <i>oldset</i> argument points outside the process&#8217;s allocated address space.</p>
<dt><code>EINVAL</code></p>
<dd> Either the value specified in <i>how</i> was invalid or the kernel does not support the size passed in <i>sigsetsize.</i></dl>
<h2>CONFORMING TO</h2>
<p> POSIX.1-2001, POSIX.1-2008.</p>
<h2>NOTES</h2>
<p> It is not possible to block <code>SIGKILL</code> or <code>SIGSTOP</code>. Attempts to do so are silently ignored. </p>
<p> Each of the threads in a process has its own signal mask. </p>
<p> A child created via <code><a href="/docs/linux/man/2-fork/">fork</a></code>(2) inherits a copy of its parent&#8217;s signal mask; the signal mask is preserved across <code><a href="/docs/linux/man/2-execve/">execve</a></code>(2). </p>
<p> If <code>SIGBUS</code>, <code>SIGFPE</code>, <code>SIGILL</code>, or <code>SIGSEGV</code> are generated while they are blocked, the result is undefined, unless the signal was generated by <code><a href="/docs/linux/man/2-kill/">kill</a></code>(2), <code><a href="/docs/linux/man/3-sigqueue/">sigqueue</a></code>(3), or <code><a href="/docs/linux/man/3-raise/">raise</a></code>(3). </p>
<p> See <code><a href="/docs/linux/man/3-sigsetops/">sigsetops</a></code>(3) for details on manipulating signal sets. </p>
<p> Note that it is permissible (although not very useful) to specify both <i>set</i> and <i>oldset</i> as NULL.</p>
<h3>C library/kernel differences</h3>
<p> The kernel&#8217;s definition of <i>sigset_t</i> differs in size from that used by the C library. In this manual page, the former is referred to as <i>kernel_sigset_t</i> (it is nevertheless named <i>sigset_t</i> in the kernel sources). </p>
<p> The glibc wrapper function for <code>sigprocmask</code>() silently ignores attempts to block the two real-time signals that are used internally by the NPTL threading implementation. See <code><a href="/docs/linux/man/7-nptl/">nptl</a></code>(7) for details. </p>
<p> The original Linux system call was named <code>sigprocmask</code>(). However, with the addition of real-time signals in Linux 2.2, the fixed-size, 32-bit <i>sigset_t</i> (referred to as <i>old_kernel_sigset_t</i> in this manual page) type supported by that system call was no longer fit for purpose. Consequently, a new system call, <code>rt_sigprocmask</code>(), was added to support an enlarged <i>sigset_t</i> type (referred to as <i>kernel_sigset_t</i> in this manual page). The new system call takes a fourth argument, <i>size_t sigsetsize</i>, which specifies the size in bytes of the signal sets in <i>set</i> and <i>oldset</i>. This argument is currently required to have a fixed architecture specific value (equal to <i>sizeof(kernel_sigset_t)</i>). </p>
<p> The glibc <code>sigprocmask</code>() wrapper function hides these details from us, transparently calling <code>rt_sigprocmask</code>() when the kernel provides it.</p>
