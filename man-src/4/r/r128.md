<p>r128 &#8211; ATI Rage 128 video driver</p>

<h2>Description</h2>
<p><code>r128</code> is an Xorg driver for ATI Rage 128 based video cards. It contains full support for 8, 15, 16 and 24 bit pixel depths, hardware acceleration of drawing primitives, hardware cursor, video modes up to 1800&#215;1440 @ 70Hz, doublescan modes (e.g., 320&#215;200 and 320&#215;240), gamma correction at all pixel depths, a fully programming dot clock and robust text mode restoration for VT switching. Dualhead is supported on M3/M4 mobile chips.</p>
<h2>Supported Hardware</h2>
<p>The <code>r128</code> driver supports all ATI Rage 128 based video cards including the Rage Fury AGP 32MB, the XPERT 128 AGP 16MB and the XPERT 99 AGP 8MB.</p>
<h2>Configuration Details</h2>
<p>Please refer to <a href="/docs/linux/man/5-xorg-conf/">xorg.conf</a>(5) for general configuration details. This section only covers configuration details specific to this driver. </p>
<p> The driver auto-detects all device information necessary to initialize the card. However, if you have problems with auto-detection, you can specify: </p>
<dl>
<dd>VideoRam &#8211; in kilobytes<br />
 MemBase &#8211; physical address of the linear framebuffer<br />
 IOBase &#8211; physical address of the MMIO registers<br />
 ChipID &#8211; PCI DEVICE ID</dl>
<p> In addition, the following driver <code>Options</code> are supported:</p>
<dl>
<dt><code>Option &#34;SWcursor&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Selects software cursor. The default is <code>off.</code></p>
<dt><code>Option &#34;NoAccel&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Enables or disables all hardware acceleration. The default is to <code>enable</code> hardware acceleration.</p>
<dt><code>Option &#34;EnablePageFlip&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Enable page flipping for 3D acceleration. This will increase performance but not work correctly in some rare cases, hence the default is <code>off.</code></p>
<dt><code>Option &#34;RenderAccel&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Enables or disables hardware Render acceleration. It is only supported when using EXA acceleration and DRI. The default is to <code>enable</code> Render acceleration.</p>
<dt><code>Option &#34;AccelMethod&#34; &#34;</code><i>string</i><code>&#34;</code></p>
<dd>Chooses between available acceleration architectures. Valid options are <code>XAA</code> and <code>EXA.</code> XAA is the traditional acceleration architecture and support for it is very stable. EXA is a newer acceleration architecture with better performance for the Render and Composite extensions. The default is <code>XAA.</code></p>
<dt><code>Option &#34;Dac6Bit&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Enables or disables the use of 6 bits per color component when in 8 bpp mode (emulates VGA mode). By default, all 8 bits per color component are used. The default is <code>off.</code></p>
<dt><code>Option &#34;VideoKey&#34; &#34;</code><i>integer</i><code>&#34;</code></p>
<dd>This overrides the default pixel value for the YUV video overlay key. The default value is <code>undefined.</code></p>
<dt><code>Option &#34;Display&#34; &#34;</code><i>string</i><code>&#34;</code></p>
<dd>Select display mode for devices which support flat panels. Supported modes are: </p>
<p> <code>&#34;FP&#34;</code> &#8211; use flat panel; </p>
<p> <code>&#34;CRT&#34;</code> &#8211; use cathode ray tube; </p>
<p> <code>&#34;Mirror&#34;</code> &#8211; use both FP and CRT; </p>
<p> <code>&#34;BIOS&#34;</code> &#8211; use mode as configured in the BIOS. </p>
<p> The default is <code>FP.</code> </p>
</dl>
<p> The following <code>Options</code> are mostly important for non-x86 architectures:</p>
<dl>
<dt><code>Option &#34;ProgramFPRegs&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Enable or disable programming of the flat panel registers. Beware that this may damage your panel, so use this <code>at your own risk.</code> The default depends on the device.</p>
<dt><code>Option &#34;PanelWidth&#34; &#34;</code><i>integer</i><code>&#34;</code></p>
<dd>
<dt><code>Option &#34;PanelHeight&#34; &#34;</code><i>integer</i><code>&#34;</code></p>
<dd>Override the flat panel dimensions in pixels. They are used to program the flat panel registers and normally determined using the video card BIOS. If the wrong dimensions are used, the system may hang.</p>
<dt><code>Option &#34;UseFBDev&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Enable or disable use of an OS-specific framebuffer device interface (which is not supported on all OSs). See <a href="/docs/linux/man/4-fbdevhw/">fbdevhw</a>(4) for further information. Default: <code>on</code> for PowerPC, <code>off</code> for other architectures.</p>
<dt><code>Option &#34;DMAForXv&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Try or don&#8217;t try to use DMA for Xv image transfers. This will reduce CPU usage when playing big videos like DVDs, but may cause instabilities. Default: off. </p>
</dl>
<p> The following additional <code>Options</code> are supported:</p>
<dl>
<dt><code>Option &#34;ShowCache&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Enable or disable viewing offscreen cache memory. A development debug option. Default: off.</p>
<dt><code>Option &#34;VGAAccess&#34; &#34;</code><i>boolean</i><code>&#34;</code></p>
<dd>Tell the driver if it can do legacy VGA IOs to the card. This is necessary for properly resuming consoles when in VGA text mode, but shouldn&#8217;t be if the console is using radeonfb or some other graphic mode driver. Some platforms like PowerPC have issues with those, and they aren&#8217;t necessary unless you have a real text mode in console. The default is <code>off</code> on PowerPC and SPARC and <code>on</code> on other architectures. </p>
</dl>
<p> <code>Dualhead Note: </code> The video BIOS on some laptops interacts strangely with dualhead. This can result in flickering and problems changing modes on crtc2. If you experience these problems try toggling your laptop&#8217;s video output switch (e.g., fn-f7, etc.) prior to starting X or switch to another VT and back.</p>
